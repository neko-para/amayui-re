# enter-load.txt —— **模板**：进入 Eushully-chan Room 的**装载帧**（⛔ 本轮不跑、不产出读数）
#
# ★★ 读之前先看这两句：
#   ① 现在跑它**量不到装载帧** —— 窗口里还缺"点进房间"的那几个动作（见下面的 ⛔），
#      跑出来的只会是 TITLE 空转。⛔ 别把它的读数写进任何表。
#   ② 它依赖另一张单的窗口定义：
#      REQ-01M6XVZ8AXJNG492WA2QAMTA35 —— enter 窗 = [整帧 hash `0x94CB…`] → [hash `0x96E5…`]
#      （那是**像素**判据；exit 窗 = [「戻る」rect 均值命中] → [hash `0x94CB…`]）。
#
# 为什么这里只能用 `at insn` 近似：`--input-script` 的触发单位是闭集合
#   frame / guest_ms / insn / wall_ms / marker ⇒ 整帧 hash / rect 均值命中**都不是**其中任何一种。
#   ⇒ 下面的 insn 边界只是"量级锚"，只在**同一 build 内**成立（measurement.md M-11）；
#     换构建 / 换 --native-overrides 档都要重新标定。
#
# 量级从哪来（⛔ 不是猜）：OBS-20261108-01 —— 进入房间的过渡帧 **75.9M 条 / 4.89–5.59 s**。
#   ⇒ 窗口 = 那 75.9M 条的那一帧本身（两个打点把它夹住）。
#
# ⛔ 故意没写的东西：那次"点进房间"的 click（坐标 / hold）。它属于上面那张单的窗口定义
#   （窗口里**必须有**那一次交互，否则窗口不成立），抄错一个坐标就是假窗口 —— 请从那张单 / 它
#   留档的脚本里取，⛔ 不要在这里编。
#
# 将来怎么跑（脚本补齐 + 窗口定义落地之后）：
#   pnpm tools lift bench apps/emulator-lift/scripts/bench/enter-load.txt --n 5 --label enter-load
#   · A/B 两侧必须同一个 appdata（进入房间会写存档 / 设定）；
#   · ⚠ 装载帧的墙钟里有约 2.7–3.0 s 属于 guest+interp 之外（shim+host 地板，见
#     REQ-01M6XVZC086PFXJRWE5AASRJ8G 的地板算式）⇒ 这条工况的 ms/百万条**不能**和 idle 混表
#     当作"解释器变快了"。

at insn 180000000       # ← 待换：进入动作之前的稳态（现在取 TITLE 稳态 250M 之前的余量）
wait 0 insn             # ← 打点 1（窗起点）

# ⛔ 这里应该是"点进房间"的那一次 click（坐标 / hold 见 REQ-01M6XVZ8AXJNG492WA2QAMTA35 的窗口定义）

after 75900000 insn     # ← OBS-20261108-01：过渡帧 75.9M 条
wait 0 insn             # ← 打点 2（窗终点 ≈ 房间第一帧）
quit

# tools/ui-bake/recipes/SO001.json 的说明书

> ★ 本仓约定：**JSON 是不透明数据** —— 字段 / 枚举 / 不变量 / 操作**只看控制脚本的自描述**
> （`pnpm tools ui-bake describe`）。这里只写"它是什么 + 这张图的非显然口径 + 指向"，
> **不复述 schema，也不抄参数取值**（取值真源就是这份 JSON 自己）。

## 它是什么

**SO001 这一张图的改图配方**：把旧仓那次手工改图的**全部操作**落成数据 ——
① `clean` 段（怎么把日文原图抹成无文字的干净底图）；② `text` 段（在干净底图上叠什么中文、放在哪）。
一条命令即可从**原始游戏件**重放出 `corpus/assets/ui-images/SO001-4.png`。

* 生效版是第 **4** 版；这张图**有汉化改动**。
* 本图的合成口径是 `text.compose = "canvas"`：干净底图作 `<img id="bg">` 贴进页面 + 整画布截图（旧仓那条口径，会把 Chrome 的 premultiply 往返烙进底图）。
* 这张图**改了什么、为什么这么改**：见本 JSON 的 `_doc` / `note` / 各步的 `_note`
  （那是本图知识的唯一落点，不要搬到别处去）。

## 非显然的口径

1. **清理是半开区间**（与旧仓 `clean_fill.py` 的 `range()` 逐字对齐）：列填充填
   `[x0+keepL, x1-keepR+1)`。改成闭区间会多/少一列像素。
2. **合成口径不许猜**：三种值各有归属（见上）。把 canvas 口径的图改成 `over-base`
   会差十万级通道数（Chrome 的 premultiply 往返是生效版的一部分）。
3. **文字层的 `lineHeight` 是定位的一部分**：它等于旧仓那层的行高（不是块高）；
   字形的垂直位置由"行盒 + `top`"共同决定。
4. `pos` 是**该层盒子**的左上角（= 旧仓 CSS 的 `left/top`），不一定是按钮格的左上角
   —— 旧仓有些块把文字盒另算了（见本 JSON 的 `pos` 与 `_note`）。

## 怎么查

```bash
pnpm tools ui-bake describe            # ★ 字段 / 不变量 / 命令（schema 的唯一真源）
pnpm tools ui-bake plan SO001         # 执行计划：clean 有哪些步、文字有哪些层（不渲染）
pnpm tools ui-bake lint SO001         # 本配方过守卫？（红 = 退出码 1）
pnpm tools ui-bake run  SO001         # 重放到 .tmp/ui-bake/（干净底图 / 文字层 / 成品 / AGF / 生成的 HTML）
pnpm tools ui-bake verify SO001       # ★ 判据：与 corpus/assets/ui-images/SO001-4.png 逐像素对照
```

## 怎么改

* **改这张图**（坐标 / 文案 / 样式 / 清理参数）：直接改这份 JSON 的对应字段，然后
  `pnpm tools ui-bake verify SO001` **必须回 0**（`逐通道不等 0`）。
  中间产物在 `.tmp/ui-bake/`，可用 Python + Pillow 定位差异。
* **改完要落回入库件**：`pnpm tools ui-bake apply SO001 --write`
  （缺省 dry-run；写前会打印"与现有效版是否相同"的警告）。
* **改原始件的清理方式**（例如"旧仓其实是先置透明再填充"）：那属于"重建原始件"的范畴，
  改 `clean` 段并在 `_note` 里写明依据，**不要为凑数字在别处将就**。
* 字段 / 不变量的**真源**是 `pnpm tools ui-bake describe`；本文件不复述。

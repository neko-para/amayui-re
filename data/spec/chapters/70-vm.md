## 执行与时间

本章规定**指令流怎样被驱动**：一次迭代做几件事、什么条件下才执行指令、等待怎样结束、时间从哪里来。
单条指令改了哪些引擎数据属于各指令族章；操作数的读法属于「数据池」。

### 一次迭代做哪些事

<!-- rule: CORE-VM-LOOP -->

主循环的每次迭代按固定顺序走：先在**迭代头**按节流决定是否泵一次宿主消息（一次泵 = 在泵点排空当前消息队列；请求序列见「启动期的平台请求」的事件入口，本条只规定节流）；随后**读一次系统毫秒时钟**；再在条件允许时把这次读数交付给**两个声音子系统（音效 / 语音）**各一次；最后过门——**服务状态选择字里的一个位**，或者**执行一条指令**。场景的窗也在门之前推进（见「场景计时窗」）。泵消息与"服务一位 / 执行一条"可以在同一次迭代里都发生；服务一位与执行指令互斥。

- 时间推进**不在**门后的分支里：它排在门之前，不占"一件事"的名额。
- 第三步有一个开关：引擎处于**暂停**状态且等待位为 1 时整段跳过；暂停是引擎的一个状态，本版只规定它在时间交付与场景推进上的作用，不规定何时进入 / 离开。
- 本迭代内所有子系统共用同一个时钟读数。
- 回消息是宿主相关的行为；本版只登记它存在与节流，泵的请求序列（窥视 / 取一条 / 翻译 / 派发 / 退出消息）见「启动期的平台请求」的事件入口，本条不重复。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 本迭代的"现在" | 迭代头的一次时钟读数（毫秒） |
| 本迭代做了哪件事 | 消息泵（可以没有）、一个状态位或一条指令（后两者至多其一） |
| 时间是否交付 | 每迭代一次（交给声音）；引擎暂停且等待位为 1 时整段跳过 |

**成立条件**

- 一次迭代**至多**执行一条指令；没有"一帧执行 N 条"的规则。
- 回消息可以有节流，不是每次迭代都做；泵完仍继续本迭代的其余步骤。
- ★ "每迭代读一次时钟"不等于"窗一定推进"：只有"有窗"位为 1 的条目才参与推进（见「场景计时窗」）。

### 门：状态选择字整字为 0 才执行

<!-- rule: CORE-VM-GATE -->

**一条指令只在状态选择字整字为 0 时执行**。整字非 0 时，本迭代不派发指令：只服务其中一个位，然后回到迭代头——时钟读数与时间交付排在门之前。

- 判据是**整字**比较，不是逐位与：任意一个位被置起都会挡住派发。
- 这就是"某条指令看起来没有执行、只有时间在走"的唯一机制。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 门开着 | 状态选择字 = 0 |
| 门关着 | 状态选择字 ≠ 0（等多久由位的服务分支决定） |

**成立条件**

- 位由谁置、服务分支做什么、何时清，见各指令条目与「位是待服务标记，清不清由服务分支决定」。

### 位是待服务标记，清不清由服务分支决定

<!-- rule: CORE-VM-STATE -->

状态选择字的每一位表示"有一件引擎级工作待做"。迭代服务**其中一个**命中的位，只服务那一件（位号顺序、以及多个位同时置起时先服务谁，**本版不规定**）；清位由该位的服务分支决定：清掉，下个迭代门就打开；没清，下个迭代继续服务同一位（表现为门持续关着）。

- 等待位就是这样：场景还有动画时，服务分支**不清**它，门一直关着（见「等待（opcode 0x21c）」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 有 N 件待做 | 状态选择字里的 N 个位；每迭代服务至多 1 个，清位与否由服务分支决定 |

**成立条件**

- 本版只规定**等待位**的服务语义（见「等待（opcode 0x21c）」）；其余位只登记存在，不解释含义。

### 时钟：宿主毫秒时钟，没有固定帧率

<!-- rule: CORE-TIMING-CLOCK -->

引擎**没有**固定帧率、也没有固定步长：每次迭代读一次宿主的系统毫秒时钟，两次读数之差就是这一步推进的时间。

- 场景另存两个时间戳：当前读数与上一次读数（后者在每次推进前被前者覆盖）。
- 时间单位是毫秒，宽度 32 位（会回绕），比较按无符号。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 本步的现在 | 迭代头的时钟读数（毫秒） |
| 场景的上一步 | 场景的"上一次读数" |

**成立条件**

- 实现可以用固定步长**离散化**时钟（那是仿真参数，不是引擎常量）；规范只规定"时间从宿主来、单位毫秒"。
- 睡眠只影响这一步实际过了多久，不改变时间单位。

### 场景计时窗与"有动画"

<!-- rule: CORE-TIMING-WINDOW -->

场景里每个可绘制条目（绘制项 / 网格）可以有一个**颜色渐变窗**：延迟、持续时间、起点、终色、"有窗"位；插值用的"起色"就是该项的**当前颜色**字段，窗不另存起色。

- **起点为 0 是"未盖章"哨兵**：第一次被推进时才盖上当时的场景时钟。
- **推进时机**：只有"有窗"位为 1 的条目才被推进；场景的窗在门之前推进（见「一次迭代做哪些事」），推进用场景时钟：本迭代的读数先写进场景（场景另存上一次读数），窗的"盖章 / 插值 / 到期"在场景推进里发生。
- **暂停时**：暂停且等待位为 0 ⇒ 场景推进整段不跑；暂停且等待位为 1 ⇒ 暂停不再挡它（否则等待会永远等不到头）。
- **持续时间为 0 不推进**：持续时间 ≤ 0（从未排窗，或已到期——到期那一步把它清 0）⇒ 这一趟不盖章、不插值、不置"有动画"。
- 若"现在"落在 `起点 + 延迟 + 持续时间` 之内 ⇒ 置"场景有动画"（个别绘制项另带一个引擎级屏蔽标记，置起时不置；该标记的含义本版不规定）；
  过了延迟之后按 `(现在 − 起点 − 延迟) / 持续时间` 在**当前颜色**与终色之间插值。
- 到期 ⇒ 清延迟与持续时间、**当前颜色 ← 终色**、终色 ← "无颜色"，并清该项的"有窗"位；绘制项与网格都如此。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某项的窗是否还开着 | 该项的"有窗"位与起止字段 |
| 场景还有动画 | 场景的"有动画"标记（场景推进在推进各项之前清、窗命中时置） |

**成立条件**

- 等待位的放行看的是**场景的"有动画"标记**（同一次迭代里、门之前的场景推进有没有置它），不是"表里还有没有未到期的窗"。
- 标记的清除与重置都发生在同一个迭代里、门服务等待位之前：场景推进先清标记，窗命中时再置；等待位读的是此刻的标记，不另存"上一次迭代"的副本。

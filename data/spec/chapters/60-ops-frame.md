## 帧类指令

本章 12 条规则 / 12 个 opcode。

这一族改变**指令指针 / 帧**：同脚本的调用、返回、条件跳转，以及脚本级切换（换脚本、结束当前脚本、重置重装）。
★ 帧这个**结构本身**（容量 / 当前帧选择 / 父帧链）的合同在「帧与调用」章；本节只写各条指令的效果。

### 条件跳转：opcode 0xa0

<!-- rule: CORE-OPS-FRAME-JUMP-A0 -->

`0xa0` 有三个操作数：**第 1 个是条件**，另外两个是**两条分支各自的目标位置**。

- 条件**非 0** ⇒ 用**第 2 个**作目标；
- 条件**等于 0** ⇒ 用**第 3 个**作目标；
- 目标等于 **−1** ⇒ **不跳**（本条原地落下，分派器照常推进到下一条）；
- 否则指令指针 ← 代码区起点 + 4 × 目标，且长度槽清 0（不自动推进）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 按条件选一条分支 | 指令指针 ← 代码区起点 + 4 × 命中那一支的目标位置 |

**成立条件**

- 只读「该走的那一支」的操作数：另一支的操作数**不被访问**（类型不支持时也不会因此失败）。
- −1 是「不跳」，**不是**「跳到 −4」，也不是「退出」。
- 目标就是位置（与调用/返回同一口径）；跳转后分派器不许再加一次长度。

### 调用（opcode 0x8f）

<!-- rule: CORE-OPS-FRAME-CALL -->

`0x8f` 有一个操作数：读成**位置**。然后：

1. 把**本指令之后那条指令的位置**压进本帧的返回栈（= 本指令位置 + 1 + 2 × 操作数个数；本指令的操作数个数是 1，所以就是 +3）；
2. 指令指针 ← 代码区起点 + 4 × 位置；
3. "操作数个数"槽清 0 ⇒ 分派器**不再**自动前进。

例外（哨兵）：操作数等于 **−1**（32 位全 1）时，撤销第 1 步的压栈、**不跳转**；该路径**不写长度槽**（它保持 `2 × 1 + 1 = 3`），分派器照常前进到下一条。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 返回地址被记住 | 本帧返回栈顶 ← 下一条指令的位置 |
| 执行转到子程序 | 指令指针 ← 代码区起点 + 4 × 位置 |

**成立条件**

- 压进去的是**下一条**的位置，不是本条的位置：压成本条会原地死循环。★ 唯一的有意例外是 `0x100` 的按键派发：它压**当前位置**、靠扫描游标前进终止（见「输入」）。
- 控制转移之后分派器**不许**再加一次长度：引擎把"操作数个数"槽清 0 就是这个意思（若不清，每次调用都会多走一条指令）。
- 哨兵 −1 的效果是"什么都不做"，**不是**"跳到负位置"，也不是"立刻返回"。
- 返回栈每帧一份（容量属机器细节，本规范不规定）；栈满时的行为尚未观察。

### 返回（opcode 0x5）

<!-- rule: CORE-OPS-FRAME-RET -->

`0x5` 没有操作数。它先把"操作数个数"槽写成 **1**、把本帧返回栈的栈顶指针减一，然后弹出栈顶的位置：

- 位置等于 **−1** ⇒ **不跳转**：长度槽留在 1，分派器只前进 4 字节（等于"这条返回指令原地落下"）；
- 否则：指令指针 ← 代码区起点 + 4 × 位置，并把"操作数个数"槽清 0（不再自动前进）。

此外，真正跳转的那条路径上，引擎还会从**另一个引擎级栈**里弹出一个值写进一个引擎级槽位。那个栈里存的是什么、那个槽位给谁用，都**没有观察**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 回到调用点 | 指令指针 ← 代码区起点 + 4 × 弹出的位置 |
| 返回栈变浅 | 本帧返回栈顶指针 −1 |

**成立条件**

- 返回**不换帧**：帧号、局部池、代码区都不变（与"换帧"是两件事）。
- 返回点是**绝对位置**（压进去时已经算好），不是"相对当前指令的偏移"，所以返回不能直接由 `调用` 的位置推出。
- 栈空时的引擎后续没有观察（栈顶指针会越界）：本版**不**把它写成合同（本版不规定）。
- 那个引擎级栈的弹出**没有**建模 —— 它的用途未定（本版不规定）。

### 换脚本：opcode 0x3

<!-- rule: CORE-OPS-FRAME-CALL-SCRIPT -->

`0x3` 有一个操作数：读成**统一文件 id**，把那个脚本装进来执行。执行前它做三件事：

1. 把**父脚本挂起**：记住父脚本的代码区、指令指针与帧记录；父帧的位置字段写上**本条指令自己的位置**（dword 序号，不是 +3），父帧的**长度槽写成 3**（本指令固定 1 个操作数 ⇒ `2 × 1 + 1`）。★ 这两步都在**深度检查之前**：即使随后因深度超限报错，父帧的位置与长度槽也已经被写过。★ 这里写下的「调用点位置」与 `0x71` 写的「文本请求位置」是**同一帧记录里相邻的两个不同字段，互不复用**（数值算式相同，⛔ 不许共用一个字段）。
2. 帧号 +1，给子脚本一个**新的帧记录**（局部池**重新分配**、不继承父池）；子帧的父帧号 ← 调用时的帧号，长度槽 ← 0。
3. 子脚本的指令指针 = 子代码区起点（dword 0）。

返回点**不存在任何"下一条"的槽里**：父帧的指令指针停在调用点，子脚本结束后由父帧自己的长度槽推进到下一条（见 0x2）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 父脚本被挂起 | 父脚本的代码区 / 指令指针 / 帧记录进栈 |
| 子脚本开始执行 | 帧号 +1、新的帧记录（新池）、指令指针 ← 子代码区起点 |

**成立条件**

- 当前帧号 = 39 时再换脚本就报错（判据是**当前帧号**，不是已占的槽数；上限与报错文本见「帧与调用」的帧栈规则）。
- 局部池**不继承**：父池里的值在子脚本里读不到，反之亦然。
- 装载失败按失败点分：**id 非法 / 打不开** ⇒ **当前帧号已经变成子槽、不恢复**，抛**显示消息型异常（类别 7：可重试 / 忽略）**；**头坏 / 装载器返回 0** ⇒ 退出型异常，不重试。⛔ 不要写成“任何装载失败都已恢复、一律退出”。

### 结束当前脚本：opcode 0x2

<!-- rule: CORE-OPS-FRAME-EXIT -->

`0x2` 没有操作数、也**不写长度槽** —— 长度槽取 `2 × argc + 1` 只是**直线指令**的规则；控制转移指令各自规定，本条不写。它按**当前帧记录的父帧号**分三支。

- 父帧号 **≥ 0** ⇒ 子脚本结束，控制权还给父脚本：**当前帧号改成那个父帧号**（不是"弹出栈顶"），父帧的指令指针**仍是调用点**，由父帧自己的长度槽推进到下一条；
- 父帧号 = **−1** ⇒ **整个执行结束**；另有两个特殊负值用于存档 / 读档（它们的行为不在本版）；其余负值 ⇒ 错误。

★ **释放是有条件的**：只有「父帧号 + 1 == 当前帧号」时才**释放**当前帧槽（帧缓冲与各数组）；否则只切帧号、不释放 —— 那会在帧数组里留下**空槽**（"换帧"造成）。**空槽**的判据是：该帧没有装载脚本，即它的代码区起点为 0。切完之后从父帧号起**向下（帧号递减）**跳过空槽，直到落在一个非空槽上；帧号降到 0 以下仍为空 ⇒ 错误。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 子脚本结束 | 当前脚本换回父脚本（帧号 / 指令指针 / 帧记录都回到挂起时） |
| 紧邻上层返回 | 当前帧槽被释放（父帧号 + 1 == 当前帧号 时） |
| 根脚本结束 | 执行结束（不再取指） |

**成立条件**

- 它**不写指令指针**：返回后的"下一条"是父帧长度槽的算术结果，不是存下来的返回地址。
- 返回时还把父帧的**位置字段**写成 **−1**（返回记号）；长度槽不动。
- 根帧结束时是"整个执行结束"，不是"返回给谁"。

### 装载帧：opcode 0x6

<!-- rule: CORE-OPS-FRAME-LOAD-FRAME -->

`0x6` 有两个操作数：**第 1 个是统一文件 id**，**第 2 个是目标帧号**（槽号）。它把那个脚本装进**目标槽**，**不切换当前帧**、也不开始执行目标帧——装完仍回到原来那一帧继续跑。

1. 长度槽 ← **5**（= 2 × 2 + 1）；
2. 装载前置不成立 ⇒ 抛**退出型异常**，**什么都不装**（前置见「成立条件」）；
3. 目标帧号 **≥ 40** ⇒ 报错（文本「ファイルの階層が深すぎます．最大は%dです．」，`%d` = 40），抛**显示消息型异常**，**不装载**；
4. 装载：按该 id **打开文件、读头**；然后**释放**目标槽原有的帧（代码区与各数组）；再写新记录——**统一文件 id**、**代码区**（分配缓冲、读入内容）、**父帧号 ← 装载时正在执行的帧号**、**返回栈清空**；该帧的两格**本地块进入目标**（主 / 副，见「登记本地块的两个进入目标」）被写成 **−1**，表示这一帧没有登记进入目标；
5. **成功装载后：当前帧号恢复成装载前的值**：装载期间只是临时指向目标槽。因此这条指令对**正在执行的那一帧**没有可见影响——它的指令指针、局部池、返回栈都不动。

例外：装载失败按失败点分：**id 非法 / 打不开** ⇒ **当前帧号停在目标槽、不恢复**，抛**显示消息型异常（类别 7：可重试 / 忽略）**；**头坏 / 装载器返回 0** ⇒ 退出型异常，不重试。★ 失败点决定目标槽剩下什么：**打开之前**就失败 ⇒ 原内容还在；**打开之后**失败 ⇒ 原内容已被释放。本版不对"失败后目标槽里剩下什么"作更强的断言。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 目标槽上出现一份新的帧记录 | 帧区里目标槽的记录被整体替换 |
| 正在执行的帧不变 | 当前帧号装载前后相同 |

**成立条件**

- 目标槽**不需要**是空的：里面原有的帧会被丢弃并重建——与「换脚本」占用「父帧号 + 1」那个槽同形。
- 上限按**帧号**判（≥ 40 报错），与"已经占了几个槽"无关；**负帧号没有判据**（本版只规定 0..39）。
- ★ **三条路径的当前帧号要分开读**：成功 ⇒ 恢复成装载前的值；**id 非法 / 打不开** ⇒ **停在目标槽、不恢复**（可重试 / 忽略）；**头坏 / 返回 0** ⇒ 恢复并走退出型异常。**深度检查失败**（目标帧号 ≥ 40）⇒ 退出型异常（类别 1），**只能终止**，不按三支处理。
- 前置条件只有一条**可观察的**：一条**宿主回调没有请求中止**。其余内部不变量（解码密钥非 0、编码零点与它满足的循环移位关系）**不作为本条 0x6 的装载前置写进正文**：它们要么在正常启动后恒真，要么是纯实现内部断言，不是"给定脚本，引擎做什么"的合同。前置不满足 ⇒ 抛**退出型异常**，发生在装载任何东西**之前**。
- 装载**不执行**新脚本：要让目标帧跑起来必须再「换帧」。
- 被清成 −1 的两格是本地块的两个进入目标（见「登记本地块的两个进入目标」），不是"位置表"之外的第三种东西；−1 是"未登记"哨兵，不是"跳到负位置"。

### 换帧：opcode 0x8

<!-- rule: CORE-OPS-FRAME-CALL-FRAME -->

`0x8` 有一个操作数：**目标帧号**。它把**当前帧**切到那个**已经装载的**帧，并从那一帧的**开头**执行。

1. 当前帧（调用者）的长度槽 ← **3**（= 2 × 1 + 1）；
2. 记住调用者的帧号，**当前帧号 ← 目标帧号**；
3. 目标帧**没有装载脚本**（代码区起点为 0）⇒ 报错（文本「この階層にはファイルが読み込まれていません．Depth=%d」，`%d` = 目标帧号），**当前帧号恢复成调用者**，抛**显示消息型异常**；不执行任何东西；
4. 否则写目标帧的三格：**父帧号 ← 调用者帧号**、**指令指针 ← 目标帧的代码区起点**、**长度槽 ← 0**（分派器不自动推进，这条指令之后执行的是目标帧的第一条）；
5. 调用者的指令指针**不动**（仍停在 `0x8` 上）：目标帧结束时回到调用者，由调用者自己的长度槽 3 推进到下一条。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 执行转到另一个已装载的帧 | 当前帧号 ← 目标帧号 |
| 目标帧把调用者记成"谁切进来的" | 目标帧的父帧号 ← 调用者帧号 |
| 目标帧从头开始 | 目标帧的指令指针 ← 它的代码区起点 |

**成立条件**

- 目标帧必须**已经装载**（由「装载帧」装过，或本来就在那个槽上）：否则报错，且当前帧号恢复成调用者。★ 调用者的长度槽在第 1 步就写了（早于这项检查）——报错路径上它已经是 3。
- 切帧**只改那三格**：目标帧的代码区、局部池、返回栈、标志位都不动。★ 返回栈**不清**——再次切回同一帧时它仍是上次离开时的样子。重入一个**未被释放**的槽时，下一次 `0x5` 会弹出**上次离开时未弹出的返回点**；若计数为 0，则读到相邻数组（**未定义行为**，本版不规定）。
- 目标帧的父帧号被**改写**成调用者 ⇒ 它之后「结束当前脚本」回到哪一帧，由**最后一次切到它的那一帧**决定，与它当初被谁装载无关。
- 与「换脚本」的区别：`0x3` 往**新**槽建帧（槽号 = 父帧号 + 1、新的局部池）；`0x8` 复用**已有**槽，不新建池、不改变槽的数量与位置。
- 目标帧号 = 当前帧号时没有特判：等于"本帧从头再跑一遍，并把父帧号写成自己"。★ 这一支**是未定义行为**（与 `0x2` 组合会形成"切回自己再扫描"的循环，没有可复刻的语义）：实现必须把它记为诊断，⛔ 不许自行规定"到哪一帧为止"。
- 帧号 ≥ 40 时引擎不设范围检查（直接按帧号取记录），其后果没有观察 ⇒ 本版只规定 0..39；≥ 40 是**未定义行为**（按项目口径记诊断）。

### 重置并重装根脚本：opcode 0x9

<!-- rule: CORE-OPS-FRAME-EXIT-SCRIPT -->

`0x9` 没有操作数。它**不是返回**：它丢掉**全部**帧（所有挂起的脚本一起丢）、复位引擎级状态，然后以**统一文件 id 0** 重新装载根脚本，从它的 dword 0 开始执行。已挂机器站点的复位项：40 个帧槽全部释放、帧号回 0、**父帧号回 −1**（根帧的哨兵）、**状态选择字**归 0、**整型池**每格写同一个初值、**浮点池**清 0、**show-logo 标志** ← 0（见「引擎级标量与事件」的 `0x130`）；**字符串池**的清空只到观察级（未逐条挂站点）；**三个引用族全局池是否复位，本版不规定**（原因：没有逐条取证）；其余复位入口（各子系统自己的重置）本版也不逐项建模（本版不规定）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 整个脚本栈被丢弃 | 帧栈清空、帧号回 0 |
| 回到根脚本开头 | 装载统一文件 id 0，指令指针 ← 0 |

**成立条件**

- 调用者**永远拿不回控制权**：`0x9` 之后的执行属于新装的根脚本。
- 与 `0x2` 的分叉判据是**作用域**：`0x2` 看父帧号（帧作用域），`0x9` 是全局重置（无判据、无返回）。
- 它的领域名（"退出脚本"）与真实可达性**仍未定**（本版不规定）：本作发行数据里它出现在各脚本共有的前导块中，不能据此说它是"文件末尾结束指令"。

### 无条件跳转：opcode 0x8c

<!-- rule: CORE-OPS-FRAME-JUMP-8C -->

`0x8c` 有一个操作数，读成**位置**。它先把本帧的**推进格数**写成 **3**（= 2 × 1 + 1），**然后**才读操作数 —— 所以操作数读失败时，推进格数已经是 3。

- 位置等于 **−1**（32 位全 1）⇒ **不跳**：推进格数留在 3，分派器照常前进到下一条；
- 否则：指令指针 ← 代码区起点 + 4 × 位置，并把推进格数清 **0**（分派器不再自动前进）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 执行转到另一位置 | 指令指针 ← 代码区起点 + 4 × 位置 |
| 不跳 | 指令指针不变；推进格数 = 3 |

**成立条件**

- **−1 是「不跳」**，不是「跳到 0」，也不是「退出」：与 `0xa0` 的两条分支各自带的 −1 哨兵同形（见「条件跳转」）。
- 推进格数写在**读操作数之前**，这是可观察的：操作数类型异常时它已经是 3（已写下的引擎数据保留、不回滚）。
- 目标**不做范围检查**：合法位置是代码区内的位置，越界没有观察 ⇒ 本版只规定合法位置（越界按未定义行为记诊断）。
- 与 `0xa0` 的区别：本条**没有条件、只有一条目标**，不读条件；`0xa0` 的推进格数写入时点见其条目（本版不在此重复）。

### 登记本地块的两个进入目标：opcode 0x7b

<!-- rule: CORE-OPS-FRAME-LOCAL-SET-7B -->

`0x7b` 有两个操作数。推进格数 ← **5**（= 2 × 2 + 1，**先写格数、再读操作数**），然后：

1. 读整型(第 1 个) → 本帧的**主进入目标**格；
2. 读整型(第 2 个) → 本帧的**副进入目标**格。

- 两条格子**各自按帧索引**：换帧后读到的是另一帧的两格，且两格**不是同一条格**。
- 两格存的是**位置**（不是字节地址；消费方要乘 4 再加代码区起点）。
- 本条只写这两格：不改状态选择字、不改指令指针、不改池、不写返回值。
- **初值与重置**：两格**每帧各一格**，初值 **−1**；帧被装载、或帧被释放（结束脚本 / 重置的释放路径）时都重置成 −1。⇒ 新帧上两格都读作"未登记"，与"上一次在这个槽上登记过的目标"无关。
- **消费方的二选一**：读取方是「进入本地块」(`0x199`) —— 按**存档字第 26 位**选格（为 0 用**主**格，非 0 用**副**格）；被选中的那格是 −1 ⇒ 本次**什么都不做**。引擎内部还有三条同形的"进入"路径读同样的两格（不经过 opcode）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 本帧的本地块主进入目标 | ← 读整型(第 1 个) |
| 本帧的本地块副进入目标 | ← 读整型(第 2 个) |

**成立条件**

- 读序固定：第 1 个 → 第 2 个。
- 两格的**值域是位置**（消费方乘 4 再加代码区起点），所以 −1 只能是哨兵：把它当位置用会指到代码区之前，规范不规定该结果（未定义行为）。
- ⛔ 两格不许合并成一格：它们是两条独立的按帧格，消费方按"一个开关"二选一（那个开关不在本条）。
- −1 是「未登记」哨兵（见上一条"初值与重置"）；本条只把读到的整数写进去，不把 −1 归一成别的数。

### 结束本地块：opcode 0x7c

<!-- rule: CORE-OPS-FRAME-LOCAL-RET-7C -->

`0x7c` **没有操作数**，而且**不先写推进格数**。它按三步走：

1. **身份判据**：引擎里有一个**存档字**。它的**第 25 位**为 0 ⇒ 推进格数 ← **1**，抛**显示消息型异常**（"不在本地块里"）；为 1 ⇒ 继续。让这一位置起的是「进入本地块」(`0x199`) 的两种形态（首次进入整字覆盖、已在块内读-改-写）。
2. **深度判据**：**本帧记录里的身份编号**必须等于**引擎的入块深度**；不等 ⇒ 抛**显示消息型异常**（消息里是这两个编号各自解析出的**名字**），**这一支不写推进格数**。
   - **写者**是「进入本地块」(`0x199`) 的**首次进入**形态（把本帧记录里的身份编号抄进引擎的入块深度）；它的**已在块内**形态**不写**这一格 ⇒ 嵌套进入不改变本判据（比较的仍是外层进入时的值）。
   - **这里的"身份编号"就是该帧所跑脚本文件的统一文件 id**（高 8 位 = 区号、低 24 位 = 该份索引里的条目下标）。它由**帧装载**从"用来打开这个脚本文件的同一个整数"抄进帧记录；对 `0x3`（call-script）就是它的**第 1 个操作数**。异常消息里两个编号各自被解析成**该 id 在索引里登记的名字**。
   - ⇒ **"深度"这个词只来自消息串**；机器侧它是"**这一帧跑的是哪一份脚本文件**"的身份比较，⛔ 不是调用计数、不是嵌套层数、也不是帧槽号。可观察后果：只要当前帧被换成另一份脚本文件（而引擎格还留着旧身份），`0x7c` 就抛；同一份文件内的嵌套进入不改变它。
3. **返回**：
   - 指令指针 ← 代码区起点 + 4 × **存档位置**；
   - 推进格数 ← **0**；
   - 状态选择字 ← 存档字 **& ~第 25 位**（第 26 位若被置起则**保留**）⇒ 成功退出后第 26 位**会带着 1 回来**，这是可观察的。
   - 存档字 ← **0**；
   - 再清四格；这四格的领域身份本版**不规定**（见残差）；
   - 若一格"待处理"标记非 0 ⇒ 清 0，并在两个游标**相差 1** 时调用一个引擎例程；该例程做什么本版**不规定**（见残差）。

- 存档字与返回点由「进入本地块」(`0x199`) 的**首次进入**形态写下（返回点 = 本条之后的那一格）；入块深度也由它写。该条已成篇（见「进入本地块」），所以本条的输入在本版**可由规范自身构造**。
- **不换帧**：帧号、局部池、代码区都不变；返回点是**绝对位置**，与 `0x5` 的返回栈**不是同一套**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 离开本地块 | 状态选择字 ← 存档字 & ~第 25 位（**整字覆盖**，不是只清一位）；存档字 ← 0 |
| 回到进入点之后 | 指令指针 ← 代码区起点 + 4 × 存档位置；推进格数 = 0 |
| 四格被清 | 两对"值 / −1"（身份未取证） |
| 失败（第 25 位 = 0） | 推进格数 = 1；显示消息型异常 |

**成立条件**

- **第 25 位是“在本地块里”的判据**；第 26 位**不参与**判据，而且在返回后**保留**下来（所以返回后**状态选择字**可能仍然非 0，门还关着 —— 那一支由第 26 位的服务分支负责）。
- 两条失败路径**不一样**：第 1 步写推进格数 1；第 2 步**不写**（保持原值）—— 异常由主循环的保护区按「异常的处置」三支处理；推进量取当前帧的推进格数槽（第 1 步已写 1，第 2 步保持原值）。
- 清位是**读-改-写**：⛔ 不许把**状态选择字**整字写 0（第 26 位会一起丢）。
- 存档字清 0 之后，本条**不能再执行一次**（第二次会命中第 1 步的失败路径）。

### 进入本地块（opcode 0x199）

<!-- rule: CORE-OPS-STATE-199 -->

`0x199` 没有操作数。它把执行位置交给**本地块的两个进入目标**之一，并记下"回来时要用的状态"。

设 `save` = 引擎的**存档字**，`state` = 引擎的**状态选择字**，`word` = **输入字**，
`main` / `sub` = 当前帧的两个**本地块进入目标**（`-1` = 未登记），`here` = 本条指令自身的位置。

1. 推进格数 ← **1**（= 2 × 0 + 1）；这一写发生在**任何判断之前**。
2. `word` ← 0，**无条件执行** —— 包括下面两条"什么都不做"的路径。
3. 分支开关是 `save` 的**第 26 位**。

**第 26 位 = 0（首次进入形态）**

- `main = -1` ⇒ **什么都不做**：推进格数留在 1、执行位置不动、`save` / `state` / 返回点 / 入块深度都不动。
- 否则依次：推进格数 ← **0**；`state` **整字**搬进 `save` 并置第 25、26 位，同时 `state` ← 0；
  **返回点 ← `here` + 1**；**入块深度 ← 本帧记录里的身份编号**；执行位置 ← 代码区起点 + 4 × `main`。
  ★ 这一形态**不读** `save` 的原值。

**第 26 位 = 1（已在块内形态）**

- `sub = -1` ⇒ 什么都不做（同上）。
- 否则：推进格数 ← **0**；`save` ← `(save & ~第26位) | 第25位`（读-改-写，保留第 25 位与其余所有位）；
  执行位置 ← 代码区起点 + 4 × `sub`。
  ★ **不写**返回点、**不写**入块深度、**不动** `state`：保留**外层**记录的三样状态。

- 本条**没有返回值**（分派器处理体返回后只读推进格数并据此前进）；**不产生异常**（不读操作数、不查表、不做范围检查）。
- **尾段没有动画、没有标脏动作**；除上面列出的格之外不改任何引擎数据；**不切换当前帧号**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 这次进入用哪个进入目标 | 存档字第 26 位：0 → 主进入目标；1 → 副进入目标 |
| 回来时从哪继续 | 返回点 ← 本条指令之后的那一格（仅首次进入形态写） |
| 进入前要保住的状态 | 状态选择字整字搬进存档字（并置第 25、26 位），状态选择字清 0（仅首次进入形态） |
| 回来时校验什么 | 入块深度 ← 进入时本帧记录里的身份编号（仅首次进入形态写） |
| 没有登记进入目标时 | 只有推进格数 1 与输入字清 0 |

**成立条件**

- 两个进入目标存的是**位置**（dword 下标），不是字节地址；本条与所有消费者一律按"代码区起点 + 4 × 位置"换算。
- 两种形态都读 `save` 第 26 位，但只有首次进入整字覆盖 `save`；已在块内是读-改-写。两者都让第 25 位置起（「退出本地块」的身份判据要求）。
- 首次进入形态**不读** `save` 原值（它本来应当是"上次退出时清成 0"）。
- 输入字被清 0 与"有没有进入"无关：没登记进入目标时也清。
- 两条"什么都不做"的路径**不是"不写推进格数"**：推进格数已是 1 ⇒ 未登记时这条指令退化成一条空指令（除清输入字）。
- 本条**不判断门位**；它只**写**状态选择字（清 0）与输入字（清 0）。

**可证伪**

- 两个进入目标都未登记时执行：推进格数必须是 **1**、执行位置落到下一条、`save` / `state` / 返回点 / 入块深度都不变，而**输入字必须被清 0**。
- `0x199` 之后紧跟一条 `0x7c` 且目标指向以 `0x7c` 结尾的代码：`0x7c` **不得抛深度异常**，并回到 `0x199` 的下一条。
- 在 `state` 里置一个可观察位 → 进入 → 退出：该位必须仍在。
- 构造第 26 位 = 1 的第二次进入（副目标已登记）：退出后必须回到**第一次**进入时记下的返回点。
- 第 25 位为 0 时执行不得产生"不在本地块里"异常（那属于 `0x7c`）；执行前后当前帧号必须相同。

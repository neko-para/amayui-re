## 纹理族

本章 8 条规则 / 7 个 opcode。

本章各条指令操作两类**键空间不同**的引擎数据：

- **按纹理 id**（`0x1f8` / `0x1f9` / `0x1fa`）：共享对象槽、纹理记录、纹理槽与释放守卫。id 是纹理槽表的键，不是绘制键。
- **按绘制键**（`0x1f7` / `0x1fb`）：绘制项表（= 对象记录表）、网格表与**两张辅助表**。绘制键与纹理 id **不是**同一个编号空间；`0x1fb` 同时带一个绘制键和一个纹理 id，二者不能互借。

底层图像的解码按「AGF 图像」的规则进行；把解码后的像素写进平台表面是**外部请求**；绘制项由谁、在什么时候画出来，不在本章（见「渲染请求边界」；颜色键命中后的像素写入是引擎行为，见「加载纹理像素」；其余表现边界本版不覆盖）。

★ 本章各条给出的**读取顺序**也是操作数类型异常的抛出顺序；异常前已经写入的引擎数据不回滚（清理规则见各条）。

### 状态模型

- **共享对象槽**：引擎按整数 id 索引的一格，纹理族与影片族共用。格子里装一个对象引用；纹理族的三条写指令都会**先清这一格**。
- **纹理记录**：按纹理 id 索引。字段是**来源文件**（`-1` = 无来源）、**颜色键**、**空白创建标记**与**释放守卫**。★ 空白创建是**独立的写入历史位**，不是"来源文件 == -1"的派生谓词。
- **颜色键**：一个 **32 位**值，上传期用来判定**哪些像素命中**。命中判据随**目标表面的位宽**分档：
  在 **32 位表面**上，判据是 **32 位 ARGB 全值相等**（A 参与），`0` = **无键**；
  在 **16 位表面**上，键与像素按**目标格式的位段**装配后再比较，仍属残差。
  所以 32 位路径上 `0xFF000000`（不透明黑）与 `0`（无键）是**两个不同的键**：前者命中不透明黑像素，后者只可能命中完全透明的黑像素
  （即对不透明像素相当于"没有键"）。颜色键的归一化与命名只在 `0x1f9` 一处定义。
- **纹理槽**：按纹理 id 索引的一格，装一个**纹理对象**；没有对象就是空槽。对象有种类（普通 / 分割）、逻辑尺寸与可查询的表面。
- **绘制项表（= 对象记录表）**：按绘制键索引；另有**网格表**与**两张辅助表**共用同一键空间。另有一张同键空间的表不参与本章的删除或写入（`0x1f7` 不碰它）。
- **范围与越界**：纹理 id 的容量分两档：`0x1f8` 那组**直接按下标访问、不做范围检查**；`0x208` / `0x20b` 以 **999** 为上界并走错误通道。`0x20d` 把 `< 1000` 当纹理槽、`>= 1000` 当后缓冲；⛔ 不要把 `0x20d` 的分支阈值当成已取证的容量。绘制项表、网格表与两张辅助表的键是任意整数，容量与越界后果本版不规定，也**不做范围检查**；⛔ 不要把纹理 id 的阈值套到绘制键上。
- **空槽 ≠ 空白纹理**：`0x1fa` 释放后纹理槽里**没有对象**；`0x1f8` 的空白创建才留下一个空白对象。前者没有纹理对象，后者也只是"没有来源文件"，不保证像素被清零。两者不是同一种状态。
- **绘制项只引用纹理，不携带像素缓冲**：绘制项按纹理 id 引用另一张表；绘制项表里没有像素。`0x1f7` 只删除四张表里的键；另一张同键空间的表不动。绘制项与纹理槽在消费时如何组合，本版未成篇（见残差）。

### 按键拆离：opcode 0x1f7

<!-- rule: CORE-OPS-TEXTURE-DETACH -->

`0x1f7` 有两个操作数：**第 2 个是个数**、**第 1 个是绘制键**。读取顺序是 **第 2 个 → 第 1 个**；类型异常在读到该操作数时抛出，已发生的删除不回滚。

- **个数 ≤ 1**：把该绘制键从四张表（绘制项表、网格表与两张辅助表）里删除。
- **个数 > 1**：按**左闭右开**区间 `[键, 键 + 个数)` 删除四张表里的条目。
- 四张表里的条目在删除时释放它自己的内嵌对象 / 缓冲（绘制项表没有可释放的内嵌对象；有内嵌对象 / 缓冲的是网格表与辅助表的条目）；单键与区间两条路径都释放，**区间路径的释放顺序本版不规定**。另一张同键空间的表不动。
- 只要四张表里有任意一张真的删掉了东西 ⇒ 场景被标成"脏"；没有删掉 ⇒ 脏标记不动。
- 本条没有外部请求；它不碰纹理记录、纹理槽或共享对象槽。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个绘制键在四张表里都不存在 | 四张表都查不到该键 |
| 场景被标脏 | 场景的脏标记 ← 1（至少一张表删掉了条目） |
| 纹理记录 / 纹理槽 / 共享对象槽 | **不变** |

**成立条件**

- 区间是左闭右开；负数个数也走"≤ 1"的单键路径。
- 键不存在时该表**静默跳过**，不报错、不代替建默认项。
- 键是绘制键，**不是纹理 id**：本条不释放任何纹理。

### 创建纹理：opcode 0x1f8

<!-- rule: CORE-OPS-TEXTURE-CREATE -->

`0x1f8` 有四个操作数：**1 = 纹理 id**、**2 = 宽**、**3 = 高**、**4 = 种类**。读取顺序是 **1 → 4 → 3 → 2 → 1**；1 先读一次、清共享对象槽，最后再读一次用于建对象。

- 先清**共享对象槽**里该 id 的对象（非空则释放、置空）。
- 把该 id 的**纹理记录**写成"没有来源文件、空白创建"：来源文件 = 无，空白创建标记 = 1；**颜色键与记录里的其它字段保持原值**，释放守卫也不动。
- 清**纹理槽**里该 id 的旧对象；按种类新建一个对象写回该槽：种类 = 3 ⇒ 分割纹理，其它 ⇒ 普通纹理。
- 宽 / 高 / 种类交给对象向底层请求创建（**外部请求**）。创建成功 ⇒ 对象的逻辑尺寸 = 宽 × 高；创建失败 ⇒ 对象仍留在槽里，但它的尺寸 / 可用性未定义（实现必须诊断；后续取表面可能失败，⛔ 不要把"槽里有对象"当成"纹理可用"）。
- 本条**不上传像素**，也不保证新表面被清零：空白纹理的像素内容未定义。
- 底层创建失败 ⇒ 错误文本写进**错误通道**（术语见「总览与约定」）并上报；**不抛异常**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理记录 | 来源文件 = 无；空白创建 = 1；颜色键 / 其它字段不变 |
| 该 id 的纹理槽 | 一个新对象（种类决定它是不是分割纹理）；成功时尺寸 = 宽 × 高，失败时尺寸未定义 |
| 共享对象槽 | 该 id 的槽被清空 |
| 错误通道 | 一次上报（仅底层创建失败时；文本内容不在本版） |

**成立条件**

- 编号**不做范围检查**；越界诊断见「状态模型」。
- 种类只有"等于 3 / 不等于 3"决定**类**；种类还会改变底层创建请求的参数（1 / 2 / 其它各有分支），那些参数不在本版。
- 本条的"空白"是**没有来源文件**，不是"像素被清零"。

### 设置纹理：opcode 0x1f9

<!-- rule: CORE-OPS-TEXTURE-SET -->

`0x1f9` 有三个操作数：**1 = 文件号**、**2 = 纹理 id**、**3 = 颜色键**。读取顺序是 **2 → 1 → 3 → 2**；清共享对象槽发生在读第 1 个之前，打开 / 锁定之后、解码之前才读第 3 个与第二次第 2 个。

- 先清**共享对象槽**里该 id 的对象（这一步在读文件**之前**）。
- 按**统一文件 id**（见「总览与约定」与「文件与脚本装载」）打开并锁定文件；文件号非法、打不开或锁定失败 ⇒ 抛**显示消息型异常**。此时纹理记录与纹理槽都保持原值。
- **颜色键归一化**：操作数**为负** ⇒ 键 = **0**（四段全 0）；否则键 = `0xFF000000 | (操作数 & 0xFFFFFF)`。
  ★ 非负的 0 归一化成 `0xFF000000` —— 那是**不透明黑**键；负数的 0 **不是**黑键，而是**无键**：
  在 **32 位表面**上，上传期的比较是 **32 位 ARGB 全值相等**（A / R / G / B 四段都参与，见「加载纹理像素」），
  值为 0 的键命中不了任何不透明像素；16 位表面的键按目标格式位段装配（残差）。
- 清**纹理槽**里该 id 的旧对象；按「加载纹理像素」解码并新建一张**普通纹理**；尺寸 = 解码图像的宽 × 高。
- **成功** ⇒ 纹理记录：来源文件 = 文件号、颜色键 = 归一化值、空白创建 = 0；纹理槽里是普通纹理对象。
- **解码失败** ⇒ 纹理槽为空（旧对象已在解码前清掉），纹理记录：来源文件 = 无；抛显示消息型异常。
- **上传失败** ⇒ 纹理槽里是已经创建出的普通纹理对象（**上传未完成**），纹理记录：来源文件 = 无；抛显示消息型异常。
- 关闭 / 解锁在成功与失败路径上都做；操作数 3 读取抛类型异常时是否也关闭 / 解锁，本版不规定（见残差）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理来自哪个文件 | 记录的来源文件 |
| 该 id 的颜色键 | 记录的颜色键（归一化后） |
| 该 id 的纹理槽 | 一个新对象；成功时普通纹理、尺寸 = 图像宽高 |
| 共享对象槽 | 该 id 的槽被清空 |
| 打开 / 锁定失败 | 记录与纹理槽**不动** |
| 读字节失败 | 本版不规定槽状态（见残差） |
| 解码失败 | 记录来源 = 无；纹理槽为空 |
| 上传失败 | 记录来源 = 无；纹理槽里留着未完成的普通纹理对象 |

**成立条件**

- 先释放共享对象槽、再打开文件 ⇒ 打开失败时共享对象槽已经是空的，但纹理记录 / 纹理槽未动。
- 解码失败与上传失败是**两种不同的槽状态**：前者空，后者留下对象。
- 失败分支只把记录的来源文件写成"无"，**不改颜色键与空白创建标记**。
- 本条**不**改绘制项、不置脏标记；最终显示 / 混合不在本版，颜色键作为上传参数的作用见「加载纹理像素」。
- 操作数 1 是文件号，不是纹理 id；操作数 2 才是纹理 id。

### 加载纹理像素：0x1f9 的请求

<!-- rule: CORE-OPS-TEXTURE-LOAD -->

`0x1f9` 在读完文件号、并打开 / 锁定之后（颜色键在打开 / 锁定之后、解码之前读入；见「设置纹理」的读序），按下面的顺序完成一次**同步**加载（本条返回前结束）：

1. **打开 / 锁定**：按统一文件 id 打开并锁定文件。文件号非法、打不开或锁定失败 ⇒ 本条失败，抛显示消息型异常；此时只清过共享对象槽，纹理记录与纹理槽保持原值。
2. **读字节**：取整份文件字节。读取失败 ⇒ 本条失败，抛显示消息型异常；此时纹理槽可能已清（装载器的清槽时点见残差），本版不把槽状态写成合同。
3. **清槽**：清纹理槽里该 id 的旧对象（解码之前）。
4. **解码**：按「AGF 图像」的读取规则解码成 **top-down RGBA8**（8 / 24 / 32bpp；调色板、ACIF alpha、bottom-up 与行宽都按该章）。文件头前两字节为 `BM` 的走 BMP 分支；该分支的容器、两段头与 24 位像素布局见「存档」章的 `FMT-SAVE-STH`（本作的四份 `.STH` 就是 BMP 样本）；1 / 4 / 8 位调色板展开与 32bpp 布局本版未成篇（见残差）。其它不能解码的字节 ⇒ 失败。
5. **建对象**：新建一张**普通纹理**；逻辑尺寸 = 解码图像的宽 × 高。文件来源不影响种类（`0x1f9` 不建分割纹理）。
6. **上传**（**外部请求**）：把按目标表面格式装配好的像素写进目标表面；归一化颜色键在**写入前**用于命中判定。
   **32 位表面**上的命中判据是 **32 位 ARGB 全值相等**（A / R / G / B 四段都参与）：键 0（无键）不会命中任何不透明像素；
   调色板路径与不带 alpha 的 24 位图像都会把 A 补成**目标格式的 A 满位**（32 位 = `0xFF`）再比较。
   **命中后的清零写的是目标，不是源**：命中 ⇒ **目标像素**的**四段全 0（全透明黑）**；**源解码缓冲只读、不被改写**。
   目标为 32 位时，32bpp 与 24bpp 源上参与比较的像素值都在写进目标表面之前装配成目标像素；8 位调色板源上清的是
   **转换后供上传的调色板条目**（该条目随后按像素写进目标表面），源调色板同样不动。**16 位表面**上的键 / 像素按**目标格式的位段**装配；
   命中同样使**目标像素值为 0**（四个分量全 0）。16 位的装配 / 量化见残差。
   表面格式由显示配置的纹理位深决定（16 / 32 位）；其它位深 ⇒ 上传失败。
7. **成功**：纹理记录写来源文件 / 颜色键 / 空白创建 = 0；纹理槽里是普通纹理对象，尺寸 = 图像宽高。

- 解码失败与上传失败的区别见「设置纹理」的状态表；两者都以显示消息型异常结束。
- 本条是**同步**的：不置等待位、不等到下一帧；请求返回后指令指针才推进。
- 本条不规定平台内部的像素通道顺序与混合；目标位宽的装配 / 量化本版未取证（见残差）。本条只规定"哪张图、多大、什么颜色键、命中像素在目标里被清成什么、哪个上传请求携带它"。

### 释放纹理：opcode 0x1fa

<!-- rule: CORE-OPS-TEXTURE-RELEASE -->

`0x1fa` 有一个操作数：**纹理 id**；**同一个操作数被读两次**。读取顺序是 **1 → 清共享对象槽 → 1**。

- 先清**共享对象槽**里该 id 的对象；这一步**不受释放守卫影响**。
- 若该 id 的**释放守卫**为 0：把纹理记录的**来源文件**写成"无"；清**纹理槽**里的对象（**外部请求**：释放平台纹理）。
- 释放守卫非 0 ⇒ 上面两步都**不做**（只清共享对象槽）。本作里（观察）守卫表没有写入点 ⇒ 观察上恒为 0。
- 本条**不改**颜色键与空白创建标记；不碰绘制项、不置脏标记、不改当前渲染目标。
- 释放后的纹理槽是**空槽**，不是空白纹理；`0x1fa` **不删除**引用该 id 的绘制项（`0x1f7` 才删除绘制项表里的键）。空槽与 `0x1f8` 的空白对象是两种状态。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理被释放 | 来源文件 = 无；纹理槽为空 |
| 释放被守卫挡住 | 来源文件与纹理槽都不变 |
| 共享对象槽 | 该 id 的槽被清空（两条路径都清） |

**成立条件**

- 不清"空白创建"标记，也不清颜色键。
- 纹理槽本来就是空 ⇒ 跳过释放，不报错。
- 释放一条纹理不等于把当前渲染目标复位；目标格可能继续指向已释放的槽（见残差）。

### 绘制纹理：opcode 0x1fb

<!-- rule: CORE-OPS-TEXTURE-DRAW -->

`0x1fb` 有八个操作数：**1 = 绘制键**、**2 = 纹理 id**、**3 / 4 = 四条边的 left / top**、**5 / 6 = 四条边的宽 / 高**、**7 / 8 = 两个整型转浮点**。读取顺序是 **6 → 4 → 5 → 3 → 4 → 3 → 7 → 8 → 2 → 1**。

- 四条边：右 = left + 宽、下 = top + 高。3 / 4 / 5 / 6 都按**整型**读出。
- 第 7、8 个操作数按**整型**读出，再转成浮点，写进绘制项的两个浮点位；第三个浮点格写 0。
- 绘制项按**绘制键**取；不存在 ⇒ 先建一个默认项再插入。绘制键与纹理 id 不是同一空间。
- 写入：置**记录首字的第 0 位**（“有效”位 —— 与 `0x202` 读的“已存在”位是**同一位**）、纹理 id、四条边、两个浮点位与 0；其它字段保持原值；场景标脏。★ 新默认项的**其余字段**按「场景对象」的默认记录初值。
- 此外，它还把**同一条场景记录**首字的第 0 位置 **1**（绘制项标志与场景对象编号**共用同一张记录表**；见「场景对象：写变换」的位 0 说明）。
- 本条**只入队**：没有外部请求，也不立即画。绘制项由渲染期的消费者读取；消费路径本版未成篇（见残差）。
- 本条**不检查**纹理 id 是否存在；检查发生在消费路径。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个绘制键对应的绘制项 | 绘制项表里该键的记录（缺则新建） |
| 该项用哪张纹理、哪四条边、哪两个浮点位 | 记录的纹理 id、四条边、两个浮点位 |
| 该项"已存在" | 记录标志字的第 0 位 ← 1 |
| 场景 | 脏标记 ← 1 |

**成立条件**

- 3 / 4 / 5 / 6 与 7 / 8 都是**整型**读取 ⇒ 若实参是浮点来源，小数部分会被截掉。
- 数值越界不检查；绘制键不存在是"建默认项"，不是错误。
- "有效"不是另一个字段：⛔ 不许为它单开一位 —— `0x202` 的门读的就是这一位。
- 本条不证明"纹理存在"；把不存在的纹理 id 写进绘制项是允许的，消费路径才可能报错 / 跳过（该路径未成篇）。


### 纹理：查询尺寸（opcode 0x208）

<!-- rule: CORE-OPS-TEXTURE-SIZE -->

读三个操作数：**纹理编号**（整数，第 1 个）、**宽**（第 2 个，**被写**）、**高**（第 3 个，**被写**）。

- 编号 **大于 999** ⇒ 向**错误通道**上报一条「编号非法」说明；两个输出都写 **0**（与 0x20b 同界；纹理族里“不做范围检查”只适用于 0x1f8 那组）。
- 编号在范围内、槽里有纹理对象 ⇒ 宽 / 高 ← 该纹理对象的尺寸；
- 编号在范围内、槽为空 ⇒ 两个输出都写 **0**（**不**上报）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某纹理的像素尺寸 | 第 2 / 3 个操作数（整数）← 纹理对象的宽 / 高；失败时 0 / 0 |
| 错误通道 | 一次上报（仅编号越界） |

**成立条件**

- 「越界」与「槽空」**不是同一失败**：一个上报，一个静默。
- 本条**不建**纹理、**不改**纹理槽、**不**置脏。
- 读序是 **1 → 写 2 → 写 3**。

### 纹理：矩形填充（opcode 0x20b）

<!-- rule: CORE-OPS-FILLTEXTURE -->

读七个操作数：**纹理编号**、**x**、**y**、**宽**、**高**、**透明度**、**颜色**（都按整数读）。

1. 以 (x, y) 为左上、宽 / 高为尺寸构造一个矩形；
2. **透明度夹取**：大于 255 ⇒ 按 255（本条**只有**上夹，没有下夹）；
3. **颜色变换**：`颜色 ← (颜色 & 0x00FFFFFF) | 0xFF000000` —— 低 24 位**原位不动**，最高字节置 **1**（源按 ARGB 解释）。
4. 按纹理编号定位**纹理记录**，把记录里「内容非文件装载」标志置 **1**（**先于**编号检查；该格与「空白创建」写的是同一格）；
5. 编号 **大于 999** ⇒ 错误通道上报（「编号非法」）；
6. 槽里没有纹理对象 ⇒ 错误通道上报（「纹理不存在」）；
7. 存在 ⇒ 把矩形**夹到该纹理对象自己的逻辑矩形**（创建时写成 `(0, 0, 宽, 高)`；不是表面实际尺寸）——左上取大、右下取小；夹完为空（左 ≥ 右 或 上 ≥ 下）⇒ **直接返回，不画也不报错**；
8. 否则把矩形、变换后的颜色、透明度交给该纹理的**填充入口**；入口唯一的失败源是加锁失败 ⇒ 错误通道上报（「加锁失败」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 纹理记录「内容非文件装载」 | 该记录的标志格 ← 1（与「空白创建」同一格；全语料无读点） |
| 某纹理上的一块矩形被填色 | 纹理的填充入口被调用（矩形 + 颜色 + 透明度） |
| 错误通道 | 一次上报（编号越界 / 槽空 / 加锁失败；空矩形**不**上报） |

**成立条件**

- 标志格在**编号检查之前**就写；但它**全语料没有读点**，所以“写没写”不是可观察合同；编号越界时这次写落在哪里属**未定义行为**（见残差），本版不规定。
- 颜色公式是**逐位合同**：低 24 位不重排、最高字节置 1。⛔ 不许写成“把三段重排”。
- 矩形夹到**对象自己的逻辑矩形**（创建时请求的宽 / 高），不是表面实际尺寸；夹取发生在调用填充入口之前。
- 透明度只有**上夹**（>255 ⇒ 255）；负数**不**夹到 0（按原值传下去）。
- 填充入口是**平台 / 渲染侧**的请求；像素结果本版不规定（见残差）。
- 编号上界 **999 与 0x208 相同**；纹理族里“不做范围检查”只适用于 0x1f8 那组（其 handler 直接索引），0x20b 是**先写后查**。
- 本条不改纹理内容以外的引擎数据（不改绘制项、不改场景脏标记——除非填充入口自己写）。

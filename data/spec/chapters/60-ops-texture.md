## 纹理族

本章 11 条规则 / 9 个 opcode。

本章各条指令操作两类**键空间不同**的引擎数据：

- **按纹理 id**（`0x1f8` / `0x1f9` / `0x1fa` / `0x216`）：共享对象槽、纹理记录、纹理槽、释放守卫与「槽 → 文件」绑定。id 是纹理槽表的键，不是绘制键。
- **按绘制键**（`0x1f7` / `0x1fb`）：绘制项表（= 对象记录表）、网格表与**两张辅助表**。绘制键与纹理 id **不是**同一个编号空间；`0x1fb` 同时带一个绘制键和一个纹理 id，二者不能互借。

底层图像的解码按「AGF 图像」的规则进行；把解码后的像素写进平台表面是**外部请求**；绘制项由谁、在什么时候画出来，不在本章（见「渲染请求边界」；颜色键命中后的像素写入是引擎行为，见「加载纹理像素」；其余表现边界本版不覆盖）。

★ 本章各条给出的**读取顺序**也是操作数类型异常的抛出顺序；异常前已经写入的引擎数据不回滚（清理规则见各条）。

### 状态模型

- **共享对象槽**：引擎按整数 id 索引的一格，纹理族与影片族共用。格子里装一个对象引用；纹理族的三条写指令都会**先清这一格**。
  ★ 它与「等待、影片与空操作」的「播影片」条所称的**对象表**是**同一张表**（同一批槽位、同一套编号：按整数 id 索引，每格装一个对象引用）；两章各自从自己的用途称呼它，⛔ 不是两张表。
- **纹理记录**：按纹理 id 索引，是一个由若干 32 位格组成的定长记录；**逐格排布与格数只在「存档」的纹理记录表条列出**（唯一落点，本条不复述、也不另立第二份格清单）。本条只用它的**角色名**说话：**来源文件**（`-1` = 无来源）、**颜色键**、**空白创建**、**恢复重建门**（读者 = 读档恢复）、**零读者标志**（只有写、没有读点）。★ 空白创建是**独立的写入历史位**，不是"来源文件 == -1"的派生谓词。★ **释放守卫不在这个记录里**：它是另一张按 id 索引的表（上面的「按纹理 id」那条与「状态模型」都按这个口径写）。
- **颜色键**：一个 **32 位**值，上传期用来判定**哪些像素命中**。命中判据随**目标表面的位宽**分档：
  在 **32 位表面**上，判据是 **32 位 ARGB 全值相等**（A 参与），`0` = **无键**；
  在 **16 位表面**上，判据与 32 位路径**同形**：键与像素各自按**目标格式的 4 位通道**装配后四段全等（A 参与；
  无 alpha 段的源把 A4 补成目标格式的满位 `0xF`）—— 装配、量化与命中后的清零见「加载纹理像素」。
  所以 32 位路径上 `0xFF000000`（不透明黑）与 `0`（无键）是**两个不同的键**：前者命中不透明黑像素，后者只可能命中完全透明的黑像素
  （即对不透明像素相当于"没有键"）。颜色键的归一化与命名只在 `0x1f9` 一处定义。
- **纹理槽**：按纹理 id 索引的一格，装一个**纹理对象**；没有对象就是空槽。对象有种类（普通 / 分割）、逻辑尺寸与可查询的表面。
- **绘制项表（= 对象记录表）**：按绘制键索引；另有**网格表**与**两张辅助表**共用同一键空间。另有一张**场景命令表**（键空间见「场景 / 颜色族」），不参与本章的删除或写入（`0x1f7` 不碰它）。
- **范围与越界**：纹理 id 的容量分两档：`0x1f8` 那组**直接按下标访问、不做范围检查**；`0x208` / `0x20b` 的合法集合是 **`0..999`**、不在其中一律走错误通道（按**无符号**比较 ⇒ 负数也算越界）。`0x20d` 把 `< 1000` 当纹理槽、`>= 1000` 当后缓冲；⛔ 不要把 `0x20d` 的分支阈值当成已取证的容量。绘制项表、网格表与两张辅助表的键是任意整数，容量与越界后果本版不规定，也**不做范围检查**；⛔ 不要把纹理 id 的阈值套到绘制键上。
- **空槽 ≠ 空白纹理**：`0x1fa` 释放后纹理槽里**没有对象**；`0x1f8` 的空白创建才留下一个空白对象。前者没有纹理对象，后者也只是"没有来源文件"，不保证像素被清零。两者不是同一种状态。
- 绘制项只引用纹理，不携带像素缓冲**：绘制项按纹理 id 引用另一张表；绘制项表里没有像素。`0x1f7` 只删除四张表里的键；另一张**场景命令表**不动。绘制项与纹理槽在消费时如何组合，见「绘制项的消费者」。

### 按键拆离：opcode 0x1f7

<!-- rule: CORE-OPS-TEXTURE-DETACH -->

`0x1f7` 有两个操作数：**第 2 个是个数**、**第 1 个是绘制键**。读取顺序是 **第 2 个 → 第 1 个**；类型异常在读到该操作数时抛出，已发生的删除不回滚。

- **个数 ≤ 1**：把该绘制键从四张表（绘制项表、网格表与两张辅助表）里删除。
- **个数 > 1**：按**左闭右开**区间 `[键, 键 + 个数)` 删除四张表里的条目。
- 四张表里的条目在删除时释放它自己的内嵌对象 / 缓冲：**网格表**条目有内嵌对象与三份缓冲；**绘制项表与两张辅助表**的条目**没有可释放资源**（见下「条目要不要逐条释放」；⛔ 不许把"网格表有"推成"辅助表也有"）；单键与区间两条路径都释放。另一张**场景命令表**不动。
- **固定表序**：一次删除按 **绘制项表 → 网格表 → 辅助表 A → 辅助表 B** 处理四张表；前一张表里没删到条目，也照样继续处理后一张。
- **网格表条目有自己的释放步**：先把条目里的内嵌对象交给**它自己的**释放入口（不是通用的"删一块内存"），再释放该条目自带的**三份缓冲**；这次删除涉及的全部网格条目**先释放完**，这一段键才从表里摘掉（"先释放、再摘键"）。
- **其余三张表没有这一步**：它们的条目不拥有可释放资源，随该表区间的移除**整块收回**，不存在"摘键之前的独立释放步"。
- **标脏分次发生**：哪张表真的删掉了条目，就在那一刻标脏；四张表各自置一次，⛔ 不是最后统一置一次。四张表都没删到 ⇒ 脏标记不动。
- 本条没有外部请求；它不碰纹理记录、纹理槽或共享对象槽。

**条目要不要逐条释放（合同）**

- 场景持有多张按编号索引的表。**只有网格表**的条目拥有需要单独释放的东西；**绘制项表与两张辅助表**的条目**不拥有任何可释放资源**。
- 这些条目**不是独立分配的**：条目与它在树里的结点在**同一块内存**里（结点 = 三个链接字 + 条目本体 + 一个着色 / 哨兵字节）。因此「释放一个条目」= 释放这一整块；⛔ 不需要、也**不允许**对条目内部任何一格单独释放。
- 于是三条路径对这些表做的是同一件事：**整表清空**、**摘一个键**、**按编号区间摘除** —— 三者都只摘结点；区间摘除在实现上就是「对区间内每个结点各摘一次」（整表清空见「场景对象表的清空」）。
- **对照（不许推广）**：网格表的条目里有**四个**引用（一份顶点缓冲对象 + 三份逐顶点数组），引擎对它们**逐格**释放：先把对象交给它**自己的**释放接口，再释放三份缓冲，每格释放前先判非 0（空引用跳过）、每格释放后归空；最后才摘结点。⇒ 引擎不是「从不逐字段释放」，而是「**只有网格表**那样」。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个绘制键在四张表里都不存在 | 四张表都查不到该键 |
| 场景被标脏 | 场景的脏标记 ← 1（至少一张表删掉了条目） |
| 纹理记录 / 纹理槽 / 共享对象槽 | **不变** |

**成立条件**

- 区间是左闭右开；负数个数也走"≤ 1"的单键路径。
- 键不存在时该表**静默跳过**，不报错、不代替建默认项。
- 键是绘制键，**不是纹理 id**：本条不释放任何纹理。
- 条目与表结点同块内存是**合同**：⛔ 不许实现成"先摘结点、再按条目字段逐个释放"（那会越过条目边界读写已收回的结点）。

**可证伪**

- 建一条辅助表条目、改它任意一格、再摘键 ⇒ 释放动作必须恰好 **1** 次（整块）；出现按字段的第二次释放 ⇒ 把辅助表当成了网格表。
- 把网格表条目四个引用之一置空再删除 ⇒ 对那一格的释放必须被**跳过**；仍然释放 ⇒ 少了判空（对照：两张辅助表一次判空都没有）。
- 按区间删除一段含 N 条辅助表条目 ⇒ 释放次数必须是 **N**（每结点一次），不是 3N、也不是 N × 格子数。
- 摘一个**不存在**的键 ⇒ 一次释放都不许发生；发生了 ⇒ 把"先查后摘"写成了"直接摘"。
- 清空之后再按任一编号取条目 ⇒ 必须一条都取不到（表是空的）；还取得到 ⇒ 清空漏了收尾。

### 创建纹理：opcode 0x1f8

<!-- rule: CORE-OPS-TEXTURE-CREATE -->

`0x1f8` 有四个操作数：**1 = 纹理 id**、**2 = 宽**、**3 = 高**、**4 = 种类**。读取顺序是 **1 → 4 → 3 → 2 → 1**；1 先读一次、清共享对象槽，最后再读一次用于建对象。

- 先清**共享对象槽**里该 id 的对象（非空则释放、置空）。
- 把该 id 的**纹理记录**写成"没有来源文件、空白创建"：来源文件 = 无，空白创建标记 = 1；**颜色键与记录里的其它字段保持原值**，释放守卫也不动。
- 清**纹理槽**里该 id 的旧对象；按种类新建一个对象写回该槽：种类 = 3 ⇒ 分割纹理，其它 ⇒ 普通纹理。
- 宽 / 高 / 种类交给对象向底层请求创建（**外部请求**）。创建成功 ⇒ 对象的逻辑尺寸 = 宽 × 高；创建失败 ⇒ 对象仍留在槽里，但它的尺寸 / 可用性未定义（实现必须诊断；后续取表面可能失败，⛔ 不要把"槽里有对象"当成"纹理可用"）。
- 本条**不上传像素**，也不保证新表面被清零：空白纹理的像素内容未定义。
- 底层创建失败 ⇒ 错误文本写进**错误通道**（术语见「总览与约定」）并上报；**不抛异常**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理记录（0x216 读来源文件） | 来源文件 = 无（-1）；空白创建 = 1；颜色键 / 其它字段不变 |
| 该 id 的纹理槽 | 一个新对象（种类决定它是不是分割纹理）；成功时尺寸 = 宽 × 高，失败时尺寸未定义 |
| 共享对象槽 | 该 id 的槽被清空 |
| 错误通道 | 一次上报（仅底层创建失败时；文本内容不在本版） |

**成立条件**

- 编号**不做范围检查**；越界诊断见「状态模型」。
- 种类只有"等于 3 / 不等于 3"决定**类**；种类还会改变底层创建请求的参数（1 / 2 / 其它各有分支），那些参数不在本版。
- 本条的"空白"是**没有来源文件**，不是"像素被清零"。

### 设置纹理：opcode 0x1f9

<!-- rule: CORE-OPS-TEXTURE-SET -->

`0x1f9` 有三个操作数：**1 = 文件号**、**2 = 纹理 id**、**3 = 颜色键**。读取顺序是 **2 → 1 → 3 → 2**：清**共享对象槽**在读第 1 个之前；**打开 / 锁定之后**才读第 3 个；第二次读第 2 个仍在**清纹理槽之前** —— **清纹理槽**是装载的第一步，发生在读完第 3 个与第二次第 2 个之后。⇒ 第 3 个操作数读取抛类型异常时**纹理槽里还是旧对象**（清槽还没发生），纹理记录也没被写过。

- 先清**共享对象槽**里该 id 的对象（这一步在读文件**之前**）。
- 按**统一文件 id**（见「总览与约定」与「文件与脚本装载」）打开并锁定文件；文件号非法、打不开或锁定失败 ⇒ 抛**显示消息型异常**。此时纹理记录与纹理槽都保持原值。
- **颜色键归一化**：操作数**为负** ⇒ 键 = **0**（四段全 0）；否则键 = `0xFF000000 | (操作数 & 0xFFFFFF)`。
  ★ 非负的 0 归一化成 `0xFF000000` —— 那是**不透明黑**键；负数的 0 **不是**黑键，而是**无键**：
  在 **32 位表面**上，上传期的比较是 **32 位 ARGB 全值相等**（A / R / G / B 四段都参与，见「加载纹理像素」），
  值为 0 的键命中不了任何不透明像素；16 位表面的键按目标格式的 **4 位通道**装配（见「加载纹理像素」）。
- 清**纹理槽**里该 id 的旧对象；按「加载纹理像素」解码并新建一张**普通纹理**；尺寸 = 解码图像的宽 × 高。
- **成功** ⇒ 纹理记录：来源文件 = 文件号、颜色键 = 归一化值、空白创建 = 0；纹理槽里是普通纹理对象。
- **读字节 / 文件头失败** ⇒ 与解码失败同态：纹理槽为空、纹理记录来源文件 = 无；抛显示消息型异常（装载器在读取任何字节之前就清掉该槽并释放旧对象）。
- **解码失败** ⇒ 纹理槽为空（旧对象已在解码前清掉），纹理记录：来源文件 = 无；抛显示消息型异常。
- **上传失败** ⇒ 纹理槽里是已经创建出的普通纹理对象（**上传未完成**），纹理记录：来源文件 = 无；抛显示消息型异常。
- 关闭 / 解锁发生在**装载返回之后**的两条路径上（成功 / 失败）：失败这一条覆盖**读字节 / 文件头失败、解码失败、上传失败**三种（三者是同一个失败返回，都走过同一次关闭 / 解锁）。只有**操作数 3 读取抛类型异常**时不关闭 / 不解锁：异常在读该操作数处直接抛出，本条没有清理动作，文件保持打开 / 加锁（此时**清纹理槽还没发生**，槽里仍是旧对象）。
- 抛出后的处置见「异常的处置」：显示消息型异常按**重试 / 忽略 / 终止**分流；选择**忽略**时执行位置按当前帧的推进格数前进。已写入的引擎数据（共享对象槽）**不回滚**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理来自哪个文件（0x216 读） | 成功 = 文件号；打开 / 锁定失败 = 旧值；解码 / 上传失败 = -1 |
| 该 id 的颜色键 | 记录的颜色键（归一化后） |
| 该 id 的纹理槽 | 一个新对象；成功时普通纹理、尺寸 = 图像宽高 |
| 共享对象槽 | 该 id 的槽被清空 |
| 打开 / 锁定失败 | 记录与纹理槽**不动** |
| 读字节失败 | 与解码失败相同：记录来源 = 无；纹理槽为空 |
| 解码失败 | 记录来源 = 无；纹理槽为空 |
| 上传失败 | 记录来源 = 无；纹理槽里留着未完成的普通纹理对象 |

**成立条件**

- 先释放共享对象槽、再打开文件 ⇒ 打开失败时共享对象槽已经是空的，但纹理记录 / 纹理槽未动。
- 解码失败与上传失败是**两种不同的槽状态**：前者空，后者留下对象。
- 失败分支只把记录的来源文件写成"无"，**不改颜色键与空白创建标记**。
- **颜色键记录格、空白创建标记与「零读者标志」都没有读出点**（"没有读者"这件事的证明与明确舍弃见 `RES-TEX-RECORD-READERS` 与「场景」章的 `RES-SCENE-TABLE-FLAGS-READERS`）；引擎不按它们做分支；它们只作为纹理记录的一部分被**整块拷贝**（层清理时的快照复制与存档例程的影像复制）。⇒ `来源文件 = 无` 与这些格的**任意组合**都不改变引擎行为，也不互相派生（`0x216` 只读来源文件格；上传用的是本次归一化后的键参数，不是记录里的旧键）。★ 五格里唯一的**读出点**是**来源文件格**（`0x216`）与**恢复重建门**（读档恢复）；⛔ 不许把这句写成"整条记录没有读者"。
- 本条**不**改绘制项、不置脏标记；最终显示 / 混合不在本版，颜色键作为上传参数的作用见「加载纹理像素」。
- 操作数 1 是文件号，不是纹理 id；操作数 2 才是纹理 id。

### 加载纹理像素：0x1f9 的请求

<!-- rule: CORE-OPS-TEXTURE-LOAD -->

`0x1f9` 在读完文件号、并打开 / 锁定之后（颜色键在打开 / 锁定之后、**清纹理槽之前**读入；见「设置纹理」的读序），按下面的顺序完成一次**同步**加载（本条返回前结束）：

1. **打开 / 锁定**：按统一文件 id 打开并锁定文件。文件号非法、打不开或锁定失败 ⇒ 本条失败，抛显示消息型异常；此时只清过共享对象槽，纹理记录与纹理槽保持原值。
2. **读颜色键**（第 3 个操作数）：按「设置纹理」归一化（负数 ⇒ `0`；否则 `0xFF000000 | (值 & 0xFFFFFF)`）。★ 这一步**在清纹理槽之前**：读它抛类型异常 ⇒ 本条不开始 —— 纹理槽里仍是**旧对象**（共享对象槽在第 1 步之前已经清过，那是唯一已发生的改变），纹理记录也没被写过。
3. **清槽**：清纹理槽里该 id 的旧对象并释放它 —— 这一步发生在**读任何字节之前**（所以后面任何装载失败都留下空槽）。
4. **读字节 / 文件头**：取整份文件字节。读取失败 ⇒ 本条失败，抛显示消息型异常；此时纹理槽已为空（见上一步），纹理记录来源文件 = 无。
5. **解码**：按「AGF 图像」的读取规则解码成 **top-down RGBA8**（8 / 24 / 32bpp；调色板、ACIF alpha、bottom-up 与行宽都按该章）。文件头前两字节为 `BM` 的走 BMP 分支（BMP 的**文件容器与两段头的写入**见「存档」的缩略图条；**写入侧**的容器不算解码合同）。
   BMP 分支的**位深集合是 1 / 4 / 8 / 24 / 32 位**；其它位深 ⇒ 解码失败。低位深按下面的条件合同展开：
   - **调色板**：按 **4 字节条目**读入（B / G / R / 不使用字节）；条目数取文件头的**使用颜色数**，为 0 时按位深取默认 **2 / 16 / 256**。
   - **像素行**按 **32 位对齐的行跨距**读入：行跨距 = ⌈宽 × 位深 ÷ 32⌉ × 4 字节；行尾填充字节丢弃。
   - **BMP 分支的行序**：文件里的像素数据**自下而上**存放 —— 引擎从最后一行开始、每行向上取一行，写成**自上而下**。
   - **索引展开**：1 位 = 每字节 **8 个**像素、**最高位先**；4 位 = 每字节 **2 个**像素、**高 4 位先**；8 位 = 每字节 1 个索引。
   - **直接色**：24 位 = 每像素 3 字节（B / G / R）；32 位 = 每像素 4 字节（B / G / R / A）。
   其它不能解码的字节 ⇒ 失败。
6. **建对象**：新建一张**普通纹理**；逻辑尺寸 = 解码图像的宽 × 高。文件来源不影响种类（`0x1f9` 不建分割纹理）。
7. **上传**（**外部请求**）：把按目标表面格式装配好的像素写进目标表面；归一化颜色键在**写入前**用于命中判定。
   **目标表面的格式**取自显示配置 `display:TextureBit`：每一次**成功建立**图形设备时读一次、存进显示状态，此后不再重读（建立失败时上一次的值保持不变）。
   三档：**16 ⇒ A4R4G4B4**（每通道 4 位）、**32 ⇒ A8R8G8B8**（每通道 8 位）、**其它任何整数 ⇒ 上传失败**。
   ★ 该键在引擎里**必然有值**：配置库**构造**时（早于图形设备建立）就把内建默认值 **32** 写进去，玩家文件只能覆盖它、不会让它消失 ⇒ 「缺键」在引擎自身的流程里**不可达**；而"显式写 0"与"缺键读出的 0"在判据上**同值**，都落进第三档（上传失败）。缺键时**读作什么**由「配置」章的读取器合同规定（读作 0，并在读到时提示一次）；本条**不**为它另立缺省。⛔ 不许把本档写成"缺键 ⇒ 32"，也⛔ 不许写成"非 16 一律按 32"。
   ★ **那个"只能覆盖、不会消失"由顺序决定，不是靠约定**：装载玩家文件是**配置库自己的一个入口**，只能在库构造完成之后被调用 ⇒ 构造期的写入一定先落库，玩家文件里的同名键随后**覆盖**它（键存在 ⇒ 覆盖；键缺失 ⇒ 构造期的值留下）。⇒ 本条的"必然有值"**不是**"引擎强制 32"：玩家把该键写成 24 就必须真的走 24（上传失败）。
   目标字的装配：**B 在最低段**，依次 G、R、A（32 位目标 = `A<<24 | R<<16 | G<<8 | B`）。
   **16 位目标的量化 = 取每个源通道的高 4 位**（右移 4、截断；不舍入、不抖动）：16 位像素 = `A4<<12 | R4<<8 | G4<<4 | B4`。
   **32 位表面**上的命中判据是 **32 位 ARGB 全值相等**（A / R / G / B 四段都参与）：键 0（无键）不会命中任何不透明像素；
   调色板路径与不带 alpha 的 24 位图像都会把 A 补成**目标格式的 A 满位**（32 位 = `0xFF`；16 位 = `0xF`）再比较。
   **16 位表面**的命中判据与 32 位同形：键与像素各自按同一套 **4 位装配**后四段全等（A 参与）；无 alpha 段的源把 A4 补成 `0xF`。
   调色板条目按同一套转换：条目的 B / G / R 取源调色板条目的对应字节（16 位目标再取高 4 位），A 恒补满位；命中即把这条**转换后**的条目清 0。
   **命中后的清零写的是目标，不是源**：命中 ⇒ **目标像素**的**四段全 0（全透明黑）**；**源解码缓冲只读、不被改写**。
   目标为 32 位时，32bpp 与 24bpp 源上参与比较的像素值都在写进目标表面之前装配成目标像素；8 位调色板源上清的是
   **转换后供上传的调色板条目**（该条目随后按像素写进目标表面），源调色板同样不动。
8. **成功**：纹理记录写来源文件 / 颜色键 / 空白创建 = 0；纹理槽里是普通纹理对象，尺寸 = 图像宽高。

- 失败分档见「设置纹理」的状态表：**读字节 / 文件头失败与解码失败同态**（槽空、来源 = 无），上传失败留下未完成的对象；三者都以显示消息型异常结束。
- 本条是**同步**的：不置等待位、不等到下一帧；请求返回后指令指针才推进。
- 本条不规定平台内部的像素通道顺序与混合；本条只规定"哪张图、多大、什么颜色键、命中像素在目标里被清成什么、哪个上传请求携带它"。

### 释放纹理：opcode 0x1fa

<!-- rule: CORE-OPS-TEXTURE-RELEASE -->

`0x1fa` 有一个操作数：**纹理 id**；**同一个操作数被读两次**。读取顺序是 **1 → 清共享对象槽 → 1**。

- 先清**共享对象槽**里该 id 的对象；这一步**不受释放守卫影响**。
- 若该 id 的**释放守卫**为 0：把纹理记录的**来源文件**写成"无"；清**纹理槽**里的对象（**外部请求**：释放平台纹理）。
- 释放守卫非 0 ⇒ 上面两步都**不做**（只清共享对象槽）。本作里（观察）守卫表没有写入点，观察上恒为 0；写者未定见 `RES-TEX-GUARD-WRITER`。
- 本条**不改**颜色键与空白创建标记；不碰绘制项、不置脏标记、不改当前渲染目标。
- 释放后的纹理槽是**空槽**，不是空白纹理；`0x1fa` **不删除**引用该 id 的绘制项（`0x1f7` 才删除绘制项表里的键）。空槽与 `0x1f8` 的空白对象是两种状态。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理被释放（0x216 读来源文件） | 释放守卫为 0 ⇒ 来源文件 = 无（-1）、纹理槽为空；守卫非 0 ⇒ 来源文件与纹理槽都不变 |
| 共享对象槽 | 该 id 的槽被清空（两条路径都清） |

**成立条件**

- 不清"空白创建"标记，也不清颜色键。
- 纹理槽本来就是空 ⇒ 跳过释放，不报错。
- 释放一条纹理不等于把当前渲染目标复位；目标格可能继续指向已释放的槽（见残差）。

### 绘制纹理：opcode 0x1fb

<!-- rule: CORE-OPS-TEXTURE-DRAW -->

`0x1fb` 有八个操作数：**1 = 绘制键**、**2 = 纹理 id**、**3 / 4 = 四条边的 left / top**、**5 / 6 = 四条边的宽 / 高**、**7 / 8 = 两个整型转浮点**。读取顺序是 **6 → 4 → 5 → 3 → 4 → 3 → 7 → 8 → 2 → 1**。

- 四条边：右 = left + 宽、下 = top + 高。3 / 4 / 5 / 6 都按**整型**读出。
- 第 7、8 个操作数按**整型**读出，再转成浮点，写进绘制项的两个浮点位；第三个浮点格写 0。
- 绘制项按**绘制键**取；不存在 ⇒ 先建一个默认项再插入。绘制键与纹理 id 不是同一空间。
- 写入：置**记录首字的第 0 位**（“有效”位 —— 与 `0x202` 读的“已存在”位是**同一位**）、纹理 id、四条边、两个浮点位与 0；其它字段保持原值；场景标脏。★ 新默认项的**其余字段**按「场景对象」的默认记录初值。
- 此外，它还把**同一条场景记录**首字的第 0 位置 **1**（绘制项标志与场景对象编号**共用同一张记录表**；见「场景对象：写变换」的位 0 说明）。
- 本条**只入队**：没有外部请求，也不立即画。绘制项由渲染期的消费者读取；消费路径见「绘制项的消费者」。
- ★ 渲染步末尾的**呈现请求不读**绘制项表、也不读纹理槽表（见「帧步进」的「渲染步（合同边界）」）：两张表在遍历阶段已消费完，呈现只是把已经画好的内容交给平台。
- 本条**不检查**纹理 id 是否存在；检查发生在消费路径。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个绘制键对应的绘制项 | 绘制项表里该键的记录（缺则新建） |
| 该项用哪张纹理、哪四条边、哪两个浮点位 | 记录的纹理 id、四条边、两个浮点位 |
| 该项"已存在" | 记录标志字的第 0 位 ← 1 |
| 场景 | 脏标记 ← 1 |

**成立条件**

- 3 / 4 / 5 / 6 与 7 / 8 都是**整型**读取 ⇒ 若实参是浮点来源，小数部分会被截掉。
- 数值越界不检查；绘制键不存在是"建默认项"，不是错误。
- **绘制键是记录表的整数键**：它与**场景对象编号**共用同一张记录表（同一把键 ⇒ 同一条记录，不是两条，也**不是**插入次序），与**纹理 id** 不是同一空间。它的语义全部由使用处给出：定位记录、决定帧内绘制次序（键升序）、可被「键区间」引用（额外变换）、可被拆离删除。⛔ 不许给它另起一个身份（"图层号 / 渲染组 / 批次的序号"），也⛔ 不许按纹理 id 排序。
- **第 7、8 个操作数是三维位置的 x / y 分量**（第三分量由本条写 0），它们的唯一作用是**平移画到的位置**：既不改变画出的尺寸，也不改采样区。位置在到达绘制入口之前已经过「绘制项的消费者」那几步加工（裁剪补偿 / 档位缩放与取整 / 场景偏移 / 相加）；入口收到的是**加工后**的三元组，入口不再二次缩放。
- **默认项就是共享记录表的默认记录**：标志 0、矩形空、三个位置分量 0、变换为单位阵、其余按默认；本条随后只写它自己那几个字段（有效位、纹理引用、四条边、两个位置分量与第三分量 0）。★ 绘制项**没有**专属字段、也**没有**专属初值表：⛔ 不许为绘制项另立一套默认值 ——"新建的默认项"与"场景对象新建时的默认记录"**逐字段相同**。
- "有效"不是另一个字段：⛔ 不许为它单开一位 —— `0x202` 的门读的就是这一位。
- 本条不证明"纹理存在"；把不存在的纹理 id 写进绘制项是允许的，消费路径才可能报错 / 跳过（后果见「绘制项的消费者」）。


### 绘制项的消费者：一帧里怎么把绘制项画出来

<!-- rule: CORE-OPS-TEXTURE-DRAW-CONSUMER -->

渲染步会**访问**绘制项表里的条目；访问顺序由「绘制顺序」那条规则决定（键序 + 命令档 + 平键序）。本条只规定**每个被访问的条目如何决定"发不发绘制请求"**，不规定像素。

1. **有效位门**：条目首字的**第 0 位**（写绘制项那条指令置的"有效"位）为 0 ⇒ **不画、不报错**。除 `0x1fb` / `0x23b` 外，其余写入方（直接设当前颜色、附加组族…）**都不置这一位**；它们建出的条目在消费侧一律不可见。
2. **本轮已消费门**：条目首字的**第 16 位**为 1 ⇒ 本轮**不再画它**（场景命令档已经画过 / 占位）；收尾扫描访问过条目后**一律**把这一位清 0（不论画没画）——所以它只在**当轮**有效，不是持久状态。
3. **纹理解析**：按条目记的**纹理 id** 找纹理槽。
   - 槽里**没有对象** ⇒ 向**错误通道**上报一条「绘制源纹理尚未创建」的说明（**带纹理 id**），然后**跳过**（不发出绘制请求）。空槽**不建**纹理、**不改**条目。
   - 纹理编号**不做范围检查**：纹理槽恰好 **1000 格**；编号落在 `[0, 1000)` 之外时，读到的是渲染对象的**其它状态格**（不是纹理对象）。读到 0 ⇒ 走"空槽"那一档（上报 + 跳过）；读到非 0 ⇒ 被当作纹理对象使用（本版不规定后果：可能崩、可能画出垃圾）。⇒ **越界不会以"编号非法"被拒绝**：同族的**设目标 / 填充 / 查询尺寸**入口另有 999 上界（**创建与取对象**不检查；设目标在编号 ≥ 1000 时切到后缓冲），消费路径没有；也**不**把"越界"与"空槽"合成同一个失败。
   - 越界读到非 0 时，引擎**把那一格的值当成对象指针**：取它的第一格当虚表、调虚表的第 6 项（把当前绘制目标对象作第 1 个实参）——即**经由任意值的一次间接调用**。值的来源是渲染对象的邻格（目标对象引用 / 目标编号 / 计数 / 标志格），是否可执行取决于那一格指向什么。**后果本版不规定**，但"以该值作对象、经其虚表调用"是规定的。
   - 纹理编号 `[20, 30)` 那一档**由脚本给出**（引擎只按编号区间判档）；引擎以常量自建的纹理编号（36 / 37 / 38）不落在该区间。⇒ 正文只写**编号区间**，⛔ 不许给它起"屏幕 / 特效 / 相机纹理"这类名字。
   - **38**：引擎**自建**的离屏绘制目标（虚拟全屏类型 = 1 时按显示记录自己的宽 / 高建出；"目标是后缓冲"时切到它、画完切回）。消费路径里"目标编号 = 38"的档位读的是这个目标。
   - **39**：引擎**不建**、也**从不**把它设成目标（只有"目标编号 = 39"的档位读）。它能出现只有一种途径：脚本自己建了 39 号纹理并把目标设成它。⛔ 不许把 38 / 39 合成一个"保留档"。
   - 本节说的**显示模式**格 = 显示记录里的**虚拟全屏类型**（配置 `display:VirtualFullScreenType` 的当前值；虚拟全屏关时为 0）。⛔ 不许写成"相机模式"：它来自配置，不是场景状态。
4. **渲染目标**：当前**没有渲染目标** ⇒ 上报一条「绘制目标尚未创建」的说明并**跳过**。
   **源与目标可以是同一个纹理对象**：本条**不比较、不跳过**（引擎里没有"源 == 目标"的判断）；自引用的后果属平台（本版不规定，见残差）。
4.1 **源矩形窗口**：条目可以带一个**源矩形窗口**（由「场景对象：一对整数 + 附加组三个整数（opcode 0x239）」排上）：延迟、持续时间、**步进总数**、**每行步数**、一个**开关字**，外加一个与颜色窗**共用**的窗起点。
   - **门**：条目的"有窗"位为 0 ⇒ 整段不跑（也**不**标脏）。位为 1 且窗起点为 0 ⇒ 本步盖章（起点 ← 本步场景时钟）；盖章对所有子窗（颜色 / 变换 / 源矩形）**共用一次**。
   - **持续时间 ≤ 0** ⇒ **不插值**（没有进度可言），也**不改矩形、不标脏**；窗起点仍在第一次推进时盖章（见上一条）。
   - **三档**（`现在` = 本步场景时钟，按 32 位**无符号**比较，**按此顺序判**）：`现在 ≥ 起点 + 延迟 + 持续时间` 或场景的「强制完成」位为 1 ⇒ **到期**；否则 `现在 ≤ 起点 + 延迟` ⇒ **延迟内**；其余 ⇒ **推进中**。★ 相等（`现在 == 终点`）**即已到期**（与「场景计时窗」同一口径）；注意它与等待指令的消息等待计时器（`现在 > 起点 + 时长`，相等仍算窗内）**不是同一个比较**。⚠ 与「场景计时窗」的差别**只在参数**：这里用**源矩形窗自己**的延迟 / 持续时间（窗起点与颜色窗共用），**符号性一样，都是无符号**。
   - **推进中的偏移**（图集按行扫）：`步序号 = ⌊(现在 − 起点 − 延迟) × 步进总数 ÷ 持续时间⌋`（**无符号**除法，整数截断）；`Δx = 宽 × (步序号 mod 每行步数)`、`Δy = 高 × (步序号 ÷ 每行步数)`（**有符号**除法；宽 / 高是条目四条边的差）。四条边**同时**平移 `(Δx, Δy)` ⇒ 宽 / 高不变。
     ★ 步序号随时间**连续取整**，不存在"跨步事件"；**本支**不比较上一步序号（另一条**同形**链见残差 `RES-TEX-STEP-INDEX-COMPARE`，**归属未定**）。
   - **延迟内**：开关字第 1 位 = 1 ⇒ 矩形原样；= 0 ⇒ 矩形**塌成空**（右 ← 左、下 ← 上）。
   - **到期**：先把延迟与持续时间清 0；开关字第 0 位 = 1 ⇒ 矩形 = 基准 + **末帧**偏移（`步序号 = 步进总数 − 1`，同样的 mod / div）；= 0 ⇒ 矩形**塌成空**。
   - **回写**：只有**到期那一档**把结果写回条目的四条边；推进中 / 延迟内只改**本帧实参**。⇒ 从下一帧起"条目的四条边"就是上一次窗口的末帧矩形（或空矩形）；本条**不重置**它（重置它的只有「纹理：写绘制项」那条）。
   - **脏 / 有动画**：只要"有窗"位为 1 且本步走到这一段，就**逐帧**标脏；"有动画"再受条目的**屏蔽标记**约束。
   - **清位 / 清起点由「场景计时窗」的推进执行**（它管共享的"有窗"位）；本条**不自己清**这个位。
   - **没有检查**：每行步数为 0 且持续时间 > 0 时的整数除零后果本版不规定（不夹取、不跳过）。

**第 6 条（附加组派生）**的边界：它**不**改"有窗"位、**不**比较上一步序号、**不**额外标脏；它与 4.1 改的是同一份矩形实参，**4.1 先、附加组后**；只有 4.1 的到期帧把矩形落表。

5. **裁剪**：把条目的四条边（**先**经过 4.1 的源矩形窗口，**再**经过第 6 条的附加组步进）夹进**纹理对象自己的逻辑矩形**（创建纹理时请求的宽 / 高；不是表面实际尺寸）——左 / 上取大、右 / 下取小。夹完为空（左 ≥ 右 或 上 ≥ 下）⇒ **静默跳过**：不画、**不上报**。
5.1 **位置档位**：条目的**两个浮点位**（外加一个恒为 0 的第三格）作为**一个三维实参**交给绘制入口；绘制入口的另一个三维实参在本路径**恒为空**。这个实参按下面四步加工（顺序固定）：
   1. **裁剪补偿**：源矩形被**左**裁掉多少，位置的 x 就加回多少；被**上**裁掉多少，y 就加回多少；被右 / 下裁**不补**。第三格不参与补偿。
   2. **缩放 + 取整**：纹理编号落在 **`[20, 30)`** 那一档 ⇒ 位置的 x / y **各乘场景缩放，再按半上取整**（`floor(值 × 缩放 + 0.5)`）；其它编号**不缩放、不取整**。★ 这一档**只由纹理编号决定**，与绘制目标编号无关。
   3. **场景偏移**：由**显示适配参数**提供两个整数偏移（视口原点；见「显示适配」），按下面两档之一取"**整数原样**"或"**整数 ÷ 场景缩放**"：
      - 绘制目标是**后缓冲**（编号 -1）或保留编号 **38**：显示模式 = 1 且目标是后缓冲 ⇒ 偏移 = **(0, 0)**；否则纹理编号在 `[20, 30)` ⇒ 偏移 = **整数原样**；否则 ⇒ 偏移 = **整数 ÷ 场景缩放**。
      - 其它目标（编号 ≥ 0 且 ≠ 38）：纹理编号在 `[20, 30)` ⇒ 偏移 = **(0, 0)**；否则 ⇒ 偏移 = **整数 ÷ 场景缩放**。
   4. **相加**：位置的 x / y 各加对应偏移；第三格不加。
   - **固定分辨率模式**生效时：缩放按 **1**、偏移按 **0**（但第 2 步的**取整照做** —— 取整与"是否真的缩放"不是同一个开关）。
   - 同一组档位还决定这一步的**变换**（门是**互斥**的，每笔最多乘一张）：场景视图矩阵只在"**屏幕形态 = 占满屏** 且（目标编号 < 0 **或** = 39）且纹理编号**不在** `[20, 30)`"时乘入；**逆**场景缩放矩阵只在"**屏幕形态 = 占满屏** 且目标编号 ≥ 0 且 ≠ 39 且纹理编号**在** `[20, 30)`"时乘入。⛔ 不要把视图矩阵的门写成"目标编号 ≥ 0 且 ≠ 39"（那是反的：目标 38 与纹理目标不乘）。这两个矩阵由**显示适配参数**派生（见「显示适配」）；矩阵内容见该条。
   - ⛔ 不许把第 2 步写成"位置 × 1/缩放"：位置乘的是**缩放本身**，矩阵里乘的才是**逆缩放**。⛔ 不许把取整写成"四舍五入"。
6. **附加组派生**：条目的第 **2 位**（由「附加组」那族写入方置 1）为 1 ⇒ 再走一次**附加组派生**。它**不是**第二次绘制，**不发**第二个绘制请求；它改的是主绘制的**输入**。执行次序：**源矩形步进在裁剪（第 5 条）之前**；颜色 / 变换的修改在裁剪之后、请求（第 7 条）之前：
   - 把**本步颜色**按附加组**自己的**周期（起点戳 + 周期的三角波）朝附加组终色**逐字节混合**，结果写回**同一个**本步颜色出参；
   - 把附加组的变换通道乘进**本步变换**，并把"本步变换有效"**强制为 1**；
   - 把附加组的**步进量**加到**源矩形的四条边上**（左右同加、上下同加 ⇒ 换成同一张图里的另一个子矩形）。标脏**不是**这条独有的：**只要条目的"有窗"位为 1，本步的派生就逐帧标脏**（4.1 也标）；附加组这里**不额外**标脏、也**不**比较上一步序号。
   主绘制**仍然只发一次**，收到的是被改过之后的矩形 / 位置 / 颜色。附加组的时间基准与主窗**不同**（各自起点戳、各自周期），⛔ 不许合并成一个窗。
6.1 **场景自身变换（额外变换）**：场景对象上有一对整数给出的**键区间**（起点 + 计数）。条目的绘制键落在该区间内时，在**主绘制之前**把一份"场景自身记录的变换矩阵"乘进**本步变换**，并把"本步变换有效"置 1；命令档可以多传一个**「跳过」**标志来抑制这一步。
   - 该区间的**唯一脚本写入者**是一条指令（`0x229`），它同时设置**场景自身记录的三元平移**；场景默认值重置把它清成 `(0, 0)`，存档载入会把两个整数读回来。
   - 那份矩阵由**场景自身记录**派生，且只有当**计数非 0** 时才派生。
   - **命令档的判据是"命令覆盖区间的起点键是否落在区间内"**（不是逐条判）：落在内 ⇒ 传"跳过" ⇒ 该命令画的条目**一个都不乘**；不落在 ⇒ 不传 ⇒ 逐条按键判。⚠ 这是引擎的既有行为（区间起点在窗外、而区间跨进窗内时，窗内条目照旧乘），实现必须照此，⛔ 不许"为了自洽"改成逐条判。收尾扫描**总是**不跳过。

7. **请求**：把**裁剪后的源矩形**、上面 5.1 加工过的**三维位置实参**、**本步变换**与**本步颜色**交给该纹理的**绘制入口**。命令档还可以多传一个**「跳过额外变换」**标志（收尾扫描总传"不跳过"；标志的来源见「场景命令记录族」）。本步颜色是一个 32 位值：**默认是不透明白**，位布局就是「场景 / 颜色族」的**共用口径**（位 31–24 = 透明度，位 23–16 = 红，15–8 = 绿，7–0 = 蓝），⛔ 不是"另一套位段"；它由「场景计时窗」的派生规则得出（无窗 / 延迟内 / **持续时间 ≤ 0**（不插值）/ 未推进 ⇒ 当前颜色；推进中 ⇒ 插值色；到期 ⇒ 终色）。★ 那五档里「持续时间 ≤ 0」**最先判**：那种窗整段不走到期收尾，所以"到期 ⇒ 终色"只在**持续时间 > 0** 时成立（见「场景计时窗」）。**派生结果只写进"本步颜色"这一个出参格**，不写进记录的当前颜色格：推进中的**插值色不落表**；唯一写当前颜色格的是窗口**到期那一步**（当前颜色 ← 终色、终色 ← 无颜色、延迟与持续时间清 0）。本条随后把**整份记录副本拷回表**，所以"到期"这一步的写入是**持久**的。绘制入口返回**失败** ⇒ 上报一条「绘制失败」说明（**带纹理 id**）并**跳过**；返回成功 ⇒ 正常结束。
8. 本条**不建纹理、不改纹理槽**；条目字段只允许这些写入：第 16 位清 0、**4.1 的到期帧写回源矩形**、「附加组派生」的矩形成分只在实参上（不落表）、窗**到期**写回当前颜色 / 终色 / 延迟 / 持续时间（然后整份副本拷回表）。它**不删除条目**；条目的删除是「拆离」那条的事。

**成立条件**

- **"槽里没有对象"与"条目无效"是两条不同的跳过**：前者上报、后者静默；⛔ 不许把两者合成一个"画不出来"分支。
- **夹空是静默的**：它既不是错误，也不建占位物。⛔ 不许为"没有可见像素"补一个占位块。
- 裁剪用**纹理对象自己的逻辑矩形**，⛔ 不是表面实际尺寸、也不是"不裁剪"。
- 第 0 位是**唯一**的"可画"判据（它与 `0x202` 的门同一位）；⛔ 不许另立"已创建 / 有内容"的位。
- 颜色是**本步派生色**：窗进行中改当前颜色会改下一帧的派生色，但**当前颜色字段本身不被本条回写**。
- 透明度是颜色的一部分，⛔ 不许把它写成另一个操作数 / 另一个字段。
- 像素（混合、滤镜、最终像素）属平台 ⛔ 不在本条；本条只规定"哪张纹理、哪块源矩形、画到哪、用什么颜色"。
- 错误文本的**内容**本版不规定，但必须**仍然上报**且**带纹理 id**（否则无法从日志定位坏条目）。
- 位置取整是**半上取整**（乘之后 +0.5 再取 floor）；场景偏移在取整**之后**才加。
- 场景偏移的"原样 / ÷ 缩放"两档按**绘制目标编号**分；纹理编号只决定 `[20, 30)` 那一档。
- 越界纹理编号**不被夹取**，也不会变成"编号非法"；自引用**不跳过**。
- 位 2 只多一次**派生**，⛔ 不许写成"多画一次"；颜色混合是**逐字节整数**（截断）。
- ★ 条目的四条边是**纹理里的一个子矩形**，不是屏幕上的目标矩形：它同时是**采样区**与**画出来的跨度**（1 : 1 像素对应）。⇒ 跨度小于纹理尺寸时，画的是**纹理的一块**（⛔ 不是把整张纹理压进去）；跨度超出纹理时，超出部分被**夹掉**并补偿进位置（⛔ 不是缩放）。
- **改变画出的尺寸只有两条途径**：本步变换（含场景视图 / 逆缩放矩阵）与位置平移；⛔ 纹理尺寸**只**参与夹取，不参与缩放 —— "四条边与纹理尺寸不一致"的唯一后果是**夹**（超出）或**取子块**（小于）。

**可证伪**

- 建一条绘制项，纹理 id 指向**空纹理槽**：若画面上出现任何东西（占位块 / 旧内容 / 其它纹理），或错误通道里没有一条带该 id 的说明 ⇒ 本条错。
- 把绘制项的矩形设成**完全落在纹理逻辑矩形之外**：若错误通道出现说明、或绘制入口被调用 ⇒ 本条错。
- 用**不置第 0 位**的写入方建条目：若它被画出 ⇒ 本条错。
- 把条目的当前颜色设成**全透明**：若绘制入口收到的颜色不是全透明 ⇒ 颜色参与合同错。
- 让同一条目在**同一帧**被命令档画过：若收尾扫描又画了它一次 ⇒ 第 16 位合同错。
- 纹理编号设成 **1000**（越界）再画：**本版不判**画出来的结果（越界后果是明确舍弃的未定义行为）；这一句只判**消费路径没有范围检查** —— 若引擎以"编号非法"拒绝、经错误通道上报并跳过 ⇒ 本条错（999 上界属于**设目标 / 填充 / 查询尺寸**那组入口，不在消费路径上）。
- 把绘制项**画进它自己**（目标 = 该纹理）：若引擎侧出现"跳过"（不调绘制入口、也不报失败）⇒ 本条错。
- 窗口**推进中**画一次（时钟不推进）：若记录的当前颜色格已经等于插值色 ⇒ 本条错。
- 纹理编号 20..29、位置 1.4、场景缩放 2 ⇒ 若绘制入口收到的 x 不是 3 ⇒ 本条错；位置 1.4、编号 5、缩放 2 ⇒ 若 x 被改成 3 或 2.8 ⇒ 本条错。
- 位 2 = 1 且其它字段不变：若绘制入口被调用**两次** ⇒ 本条错；若源矩形 / 颜色 / 变换三者都没变 ⇒ 本条错。

**残差**

- `RES-TEX-DRAW-CONSUMER-OOB`（**discarded**，明确舍弃）：消费路径**不做范围检查**、越界格读到的不是纹理对象，引擎还会把那一格的值当**对象指针**用（经它的虚表第 6 项调用）—— 后果取决于宿主的相邻格内容与那个值指向什么，属**未定义行为**。引擎侧**已写进正文**的只有"不检查、读到 0 走空槽上报、读到非 0 当对象用、且不把越界合进'编号非法'"这几条；**被舍弃**的是越界之后的表现。⇒ 实现必须在编号落在 `[0, 1000)` 之外时**显式记诊断 / 失败**，⛔ 不复刻相邻格、⛔ 不要为它补一条"越界错误"合同。
- `RES-TEX-DRAW-CONSUMER-SELFTARGET`（**discarded**，明确舍弃）：引擎**不比较**源与目标、**不跳过**（源对象与目标对象是同一次绘制调用的两个实参，调用前没有相等比较），所以自引用在引擎侧是**合法输入**；画出来是什么、成不成，由平台绘制入口的返回码决定（返回 0 ⇒ 按"绘制失败"上报并跳过）。⇒ 这条**已写进正文**（第 4 条与"成立条件"）；**被舍弃**的只是平台侧的像素结果与成败判断：⛔ 不许另加"源 == 目标"的检查把它挡掉。
- `RES-TEX-STEP-INDEX-COMPARE`（unknown）：4.1 写"引擎不比较上一步序号"，但另有一条**同形**的窗推进把"按上一时刻算出的步序号"与当前步序号比较后置「有动画」⇒ 两者必有一处要改：该段属于另一条规则（网格侧 / 附加组侧），或 4.1 的"不比较"写得过宽。**归属未定。**下一步：读那条链的调用方与它推进哪张表，确认是不是源矩形窗；是 ⇒ 改 4.1；不是 ⇒ 另立一条并让 4.1 明确指向它。

**编号 `[20, 30)` = 文本层画布带（仅场景绘制模式 = 1）**：文本 / 消息子系统按**文本层号 i** 自建编号 `20 + i` 的离屏画布，层槽共 10 格 ⇒ 编号恰好落满 20..29。★ 建画布这一步**只在场景绘制模式 = 1 时发生**；模式 ≠ 1 时该层走**旧式精灵表面**（另一张对象表里的对象、只共用编号，**不建纹理画布、不碰纹理槽**，见「ADV 文本层」的范围项）。画布内容由 CPU 写入；随后（**仅当场景绘制模式 = 1**）引擎按**每个已揭示的字符格一条**入队绘制项 —— ⛔ **不是**"整张画布一条"：键 = 该层的**键基数 + 字符序号**，目标纹理 = 这个编号，源矩形 = 该字符的布局字符格 × 字体缩放，位置 = 层左 / 上 + 字符格左上；条目数量受该层**键区间的数量门**约束（揭示游标 < 键数量才建；数量 = 0 ⇒ 一条都不建）。逐字条目的完整规则见「ADV 文本层」。画布按适配比**预缩放**（尺寸 = 层矩形 × 适配比；**取整与位置同一套 —— 半上取整**，见「文本层：矩形、原点、清空与画布」）；消费路径把位置乘同一个比 + 半上取整折进同一适配坐标，纹理目标上用逆缩放矩阵抵回去（只写算术合同，不写引擎动机）。

**画布与脚本纹理撞号（仅画布路径，即场景绘制模式 = 1）**：编号 `20 + i` 就是**普通的纹理槽编号** —— 画布不是独立对象，也不比别的槽更受保护。脚本用 `0x1f8` 给同一编号建纹理会**替换**画布对象（后写覆盖先写），而 `0x70` 后重建画布也会**替换**脚本纹理；两者走的是同一条创建路径，因此 `0x70` 建画布时也把该编号的纹理记录写成"无来源文件 / 空白创建"。替换后文本层的逐字绘制条目仍按该编号取纹理 ⇒ 画的是**留在槽里的那个对象**的像素（源矩形仍是字符格），画布像素本身不再存在。⛔ 不许把画布实现成"与纹理槽无关的第二份缓冲"。★ 这一整段只谈**画布路径**：场景绘制模式 ≠ 1 时 `0x70` **不经过**这条创建路径 ⇒ 它既不建 / 不替换该编号的纹理记录，也不占用脚本纹理那一槽（旧式精灵表面是另一张表里的对象）—— 在这条路径上说"`0x70` 会把该编号的纹理记录写成空白"就是错的。

### 纹理：查询尺寸（opcode 0x208）

<!-- rule: CORE-OPS-TEXTURE-SIZE -->

读三个操作数：**纹理编号**（整数，第 1 个）、**宽**（第 2 个，**被写**）、**高**（第 3 个，**被写**）。

- 编号**不在 `0..999`** ⇒ 向**错误通道**上报一条「编号非法」说明；两个输出都写 **0**（与 0x20b 同界；纹理族里“不做范围检查”只适用于 0x1f8 那组）。
  ★ **判据是"不在 `0..999`"，不是"大于 999"**：比较按**无符号**做 ⇒ **负数也落进这一支**（它不是"下界未定义"，而是与 1000 以上走同一条上报路径）；⛔ 不许实现成「只判上界、负数放过去」。
- 编号在范围内、槽里有纹理对象 ⇒ 宽 / 高 ← 该纹理对象的尺寸；
- 编号在范围内、槽为空 ⇒ 两个输出都写 **0**（**不**上报）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某纹理的像素尺寸 | 第 2 / 3 个操作数（整数）← 纹理对象的宽 / 高；失败时 0 / 0 |
| 错误通道 | 一次上报（仅编号越界） |

**成立条件**

- 「越界」与「槽空」**不是同一失败**：一个上报，一个静默。
- 本条**不建**纹理、**不改**纹理槽、**不**置脏。
- 读序是 **1 → 写 2 → 写 3**。

### 纹理：读槽→文件绑定（opcode 0x216）

<!-- rule: CORE-OPS-TEXTURE-SLOT-IMGID -->

`0x216` 有两个操作数：**目标**（写）、**槽号**（读）。

- 槽号在 `0..999`：目标 ← 该槽**纹理记录的来源文件格**（不是独立的第二张表）。记录表在场景初始化时把 1000 条来源文件都写 -1；初始化后未再写入的槽读回 **-1**。
- `0..999` 读的是**活动表**，不是**存档快照**（快照的**唯一合同内读者**是**存档写出**；读档写的是**活动表**）。这一对表（活动表 + 快照）的身份、发布点、存档取哪一块、活动表的全部写者，集中写在「列表与文本子系统」的「请求文本层」条 —— 本节只说本条读到的是哪一块。
- **读档恢复**逐项重建活动表的来源文件（同 `0x1f9` 的装载路径）；`0x216` 读到的是恢复后的活动表。
- 槽号越界（负数 / ≥1000）不在本版合同内：引擎的索引没有范围比较，`1000..1999` 落进的是**快照那一块**（这是**越界观察**，不是合同 —— 快照的**合同内**读者只有存档写出，本条的 `0..999` 支从不读它；越界后果见残差）。
- 推进格数 = 5；不写其它脚本变量、不置门位、**不切换当前帧**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某槽的纹理来自哪个文件 | 目标 ← 该槽纹理记录的来源文件；无 = -1 |
| 槽号越界 | 本版不规定（残差） |

**成立条件**

- **写者**：`0x1f8` 空白创建 ⇒ -1；`0x1f9` 成功 ⇒ 文件号，打开 / 锁定失败 ⇒ 旧值，读字节 / 解码 / 上传失败 ⇒ -1（见「设置纹理」的失败分档）；`0x1fa` 释放守卫为 0 ⇒ -1，非 0 ⇒ 不变；`0x23d` 在释放守卫为 0 时对槽 42..999 ⇒ -1，0..41 不变；**存档恢复**逐项重建活动表（读档把这一段**按项取出**，在「恢复重建门已置且来源文件号 ≥ 0」时重建纹理对象并**写回活动表**、不写快照；合同见「存档」的纹理记录表条，装载路径见「加载纹理像素」）；本条读到恢复后的活动表。
- 绑定表是**槽号索引**，不是绘制键；`0x216` 不写它，只读。
- 读序是 **2 → 1**（先读槽号，再写目标）。

**残差**

- `RES-216-OUT-OF-RANGE`（unknown）：`1000..1999` 读到的是**快照那一块**（不是活动表）；`>=2000` 越出这两块、后果不在本版合同内。本版只规定 `0..999`，实现应响亮失败 / 记诊断，不复刻布局。

### 纹理：矩形填充（opcode 0x20b）

<!-- rule: CORE-OPS-FILLTEXTURE -->

读七个操作数：**纹理编号**、**x**、**y**、**宽**、**高**、**透明度**、**颜色**（都按整数读）。

1. 以 (x, y) 为左上、宽 / 高为尺寸构造一个矩形；
2. **透明度夹取**：大于 255 ⇒ 按 255（本条**只有**上夹，没有下夹）；
3. **颜色变换**：`颜色 ← (颜色 & 0x00FFFFFF) | 0xFF000000` —— 低 24 位**原位不动**，最高字节置 **1**（源按 ARGB 解释）。
4. 按纹理编号定位**纹理记录**，把记录里「内容非文件装载」标志置 **1**（**先于**编号检查；该格与「空白创建」写的是同一格）；
5. 编号**不在 `0..999`** ⇒ 错误通道上报（「编号非法」；判据按**无符号**比较 ⇒ **负数与 1000 以上同一条支**，⛔ 不是"只判上界"）；
6. 槽里没有纹理对象 ⇒ 错误通道上报（「纹理不存在」）；
7. 存在 ⇒ 把矩形**夹到该纹理对象自己的逻辑矩形**（创建时写成 `(0, 0, 宽, 高)`；不是表面实际尺寸）——左上取大、右下取小；夹完为空（左 ≥ 右 或 上 ≥ 下）⇒ **直接返回，不画也不报错**；
8. 否则把矩形、变换后的颜色、透明度交给该纹理的**填充入口**；入口唯一的失败源是加锁失败 ⇒ 错误通道上报（「加锁失败」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 纹理记录「内容非文件装载」 | 该记录的标志格 ← 1（与「空白创建」同一格；全语料无读点） |
| 某纹理上的一块矩形被填色 | 纹理的填充入口被调用（矩形 + 颜色 + 透明度） |
| 错误通道 | 一次上报（编号越界 / 槽空 / 加锁失败；空矩形**不**上报） |

**成立条件**

- 标志格在**编号检查之前**就写；但它**全语料没有读点**，所以“写没写”不是可观察合同；编号越界时这次写落在哪里属**未定义行为**（见残差），本版不规定。
- 颜色公式是**逐位合同**：低 24 位不重排、最高字节置 1。⛔ 不许写成“把三段重排”。
- 矩形夹到**对象自己的逻辑矩形**（创建时请求的宽 / 高），不是表面实际尺寸；夹取发生在调用填充入口之前。
- 透明度只有**上夹**（>255 ⇒ 255）；负数**不**夹到 0（按原值传下去）。
- 填充入口是**平台 / 渲染侧**的请求；像素结果本版不规定（见残差）。
- 编号判据 **`0..999` 之外一律上报**（按**无符号**比较：负数与 1000 以上同一条支），与 `0x208` 同一界；纹理族里“不做范围检查”只适用于 0x1f8 那组（其 handler 直接索引），0x20b 是**先写后查**。
- 本条不改纹理内容以外的引擎数据（不改绘制项、不改场景脏标记——除非填充入口自己写）。

### 纹理缩放拷贝：opcode 0x32

<!-- rule: CORE-OPS-TEXTURE-STRETCH-32 -->

`0x32` 有十个操作数，推进格数 = **21**。

- 第 1 个 = **源**纹理 id、第 2 个 = **目标**纹理 id。
- 第 3..6 个 = **源矩形**（x / y / 宽 / 高），第 7..10 个 = **目标矩形**（x / y / 宽 / 高）；矩形在引擎里折成 `(x, y, x+宽, y+高)`。
- 读序：先 **3 → 4 → 5 → 6 → 7 → 8 → 9 → 10**（预算矩形），再按绘制模式分叉：
  - 模式 = 0：读 **1** 再读 **2**，把两段矩形交给**平台的位块传送**（像素效果属平台边界，不进本版）；
  - 模式 ≠ 0：读 **2** 再读 **1**，走引擎自带的软件缩放（下面两条公式）。
- 源或目标纹理**不存在** ⇒ 只**记一条错误**、直接返回（**不抛**）；矩形各自夹进对应纹理的尺寸，
  目标矩形还要按比例回推到源矩形（比例 = 源跨度 ÷ 目标跨度）。
- **不写**纹理宽 / 高 / 缩放比：矩形与比例都只活在这次调用的栈上。

**像素公式（模式 ≠ 0）**

分类按**两轴一起**判，判定顺序是**先试放大、再试缩小**：

- **放大**（两轴都 源跨度 ≤ 目标跨度）：**双线性**。目标像素 `(u, v)` 的采样坐标
  `sx = u · 源跨宽 ÷ 目标宽`、`sy = v · 源跨高 ÷ 目标高`；整数部分截断、小数部分记作 `fx / fy`；
  整数索引夹到 `源跨 − 1`（越界取边界）；每通道
  `p = (1−fy)·((1−fx)·p00 + fx·p10) + fy·((1−fx)·p01 + fx·p11)`，
  再 `+0.5` 后截断、夹到 0..255。
- **缩小**（两轴都 源跨度 ≥ 目标跨度，且**两轴不全相等**）：**面积加权平均**。目标像素 `(u, v)` 覆盖的源区间
  `[u·比例, (u+1)·比例)`（两个轴各一份），按区间重叠面积给每个源像素加权，除以权重和，再 `+0.5` 截断。
- **等跨度**：只有一轴相等时由另一轴定：另一轴放大 ⇒ 放大，另一轴缩小 ⇒ 缩小。
  两轴跨度**都**相等时，放大与缩小两条公式都退化成逐像素原样拷贝，像素不可区分 ⇒ 本版不区分（引擎实际先命中放大支）。
  ⛔ 不要只写 ≤ / ≥ 让两边同时成立而不给这条 tie-break。
- **一边放一边缩**（一轴放大、一轴缩小）：引擎分**两趟**——**先放大到临时介面、再缩小到目标**；
  两趟合起来的等价公式与中间取整本版不规定（残差 `RES-TEX-STRETCH-MIXED`）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 目标纹理的内容 | 源矩形按**双线性**（放大）或**面积加权平均**（缩小）落到目标矩形；模式 0 时由平台位块传送决定 |
| 失败 | 引擎错误记录一条（无异常） |

**成立条件**

- **源在前、目标在后**（第 1 = 拷贝源、第 2 = 拷贝先）；⛔ 反了就画到源上。
- 两个矩形**各自夹取**（源夹源、目标夹目标）：⛔ 不要用一个矩形夹两次。
- 失败是**静默**（错误通道），⛔ 不是抛异常。
- ⛔ **不是最近邻**：放大取四邻域加权、缩小取面积平均；写成"取 `(u·比例, v·比例)` 处那一个像素"就错。

**可证伪**

- 4×4 源（红 = x·10、绿 = y·10、蓝 = 50、α = 255）放大到目标矩形 (0,0,8,8)：目标 (1,1) 必须是
  `(5,5,50,255)`（四邻域均值），(2,0) 必须是源 (1,0) = `(10,0,50,255)`，(7,7) 必须是源 (3,3) = `(30,30,50,255)`。
  若 (1,1) = 源 (0,0)（最近邻）⇒ 本条错。
- 8×8 源（红 = x·10、绿 = y·10）缩到 (0,0,4,4)：目标 (0,0) 的红必须是 `5`（2×2 块均值），
  是 `0`（抽点）⇒ 本条错。
- 跨度**一轴相等、一轴缩小**（8×8 源，同上配色 → 目标矩形 (0,0,8,4)）：必须走**面积平均**，目标 (0,0) 的绿必须是
  `5`（源第 0、1 行的均值）；是 `0`（"宽 ≤ 目标宽"就当成放大 ⇒ 双线性只取第 0 行）⇒ 等跨度 tie-break 写错。
  ⛔ 两轴**都**相等的用例证伪不了它：两条公式都退化成逐像素原样拷贝，别拿它当证据。
- 源 100×100、源矩形 (0,0,200,200)：实际用到的源矩形必须被夹到 100×100。
- 目标纹理不存在：**不得抛异常**，只记一条错误。

## 纹理族

本章 10 条规则 / 8 个 opcode。

本章各条指令操作两类**键空间不同**的引擎数据：

- **按纹理 id**（`0x1f8` / `0x1f9` / `0x1fa` / `0x216`）：共享对象槽、纹理记录、纹理槽、释放守卫与「槽 → 文件」绑定。id 是纹理槽表的键，不是绘制键。
- **按绘制键**（`0x1f7` / `0x1fb`）：绘制项表（= 对象记录表）、网格表与**两张辅助表**。绘制键与纹理 id **不是**同一个编号空间；`0x1fb` 同时带一个绘制键和一个纹理 id，二者不能互借。

底层图像的解码按「AGF 图像」的规则进行；把解码后的像素写进平台表面是**外部请求**；绘制项由谁、在什么时候画出来，不在本章（见「渲染请求边界」；颜色键命中后的像素写入是引擎行为，见「加载纹理像素」；其余表现边界本版不覆盖）。

★ 本章各条给出的**读取顺序**也是操作数类型异常的抛出顺序；异常前已经写入的引擎数据不回滚（清理规则见各条）。

### 状态模型

- **共享对象槽**：引擎按整数 id 索引的一格，纹理族与影片族共用。格子里装一个对象引用；纹理族的三条写指令都会**先清这一格**。
- **纹理记录**：按纹理 id 索引。字段是**来源文件**（`-1` = 无来源）、**颜色键**、**空白创建标记**与**释放守卫**。★ 空白创建是**独立的写入历史位**，不是"来源文件 == -1"的派生谓词。
- **颜色键**：一个 **32 位**值，上传期用来判定**哪些像素命中**。命中判据随**目标表面的位宽**分档：
  在 **32 位表面**上，判据是 **32 位 ARGB 全值相等**（A 参与），`0` = **无键**；
  在 **16 位表面**上，键与像素按**目标格式的位段**装配后再比较，仍属残差。
  所以 32 位路径上 `0xFF000000`（不透明黑）与 `0`（无键）是**两个不同的键**：前者命中不透明黑像素，后者只可能命中完全透明的黑像素
  （即对不透明像素相当于"没有键"）。颜色键的归一化与命名只在 `0x1f9` 一处定义。
- **纹理槽**：按纹理 id 索引的一格，装一个**纹理对象**；没有对象就是空槽。对象有种类（普通 / 分割）、逻辑尺寸与可查询的表面。
- **绘制项表（= 对象记录表）**：按绘制键索引；另有**网格表**与**两张辅助表**共用同一键空间。另有一张**场景命令表**（键空间见「场景 / 颜色族」），不参与本章的删除或写入（`0x1f7` 不碰它）。
- **范围与越界**：纹理 id 的容量分两档：`0x1f8` 那组**直接按下标访问、不做范围检查**；`0x208` / `0x20b` 以 **999** 为上界并走错误通道。`0x20d` 把 `< 1000` 当纹理槽、`>= 1000` 当后缓冲；⛔ 不要把 `0x20d` 的分支阈值当成已取证的容量。绘制项表、网格表与两张辅助表的键是任意整数，容量与越界后果本版不规定，也**不做范围检查**；⛔ 不要把纹理 id 的阈值套到绘制键上。
- **空槽 ≠ 空白纹理**：`0x1fa` 释放后纹理槽里**没有对象**；`0x1f8` 的空白创建才留下一个空白对象。前者没有纹理对象，后者也只是"没有来源文件"，不保证像素被清零。两者不是同一种状态。
- 绘制项只引用纹理，不携带像素缓冲**：绘制项按纹理 id 引用另一张表；绘制项表里没有像素。`0x1f7` 只删除四张表里的键；另一张**场景命令表**不动。绘制项与纹理槽在消费时如何组合，见「绘制项的消费者」。

### 按键拆离：opcode 0x1f7

<!-- rule: CORE-OPS-TEXTURE-DETACH -->

`0x1f7` 有两个操作数：**第 2 个是个数**、**第 1 个是绘制键**。读取顺序是 **第 2 个 → 第 1 个**；类型异常在读到该操作数时抛出，已发生的删除不回滚。

- **个数 ≤ 1**：把该绘制键从四张表（绘制项表、网格表与两张辅助表）里删除。
- **个数 > 1**：按**左闭右开**区间 `[键, 键 + 个数)` 删除四张表里的条目。
- 四张表里的条目在删除时释放它自己的内嵌对象 / 缓冲（绘制项表没有可释放的内嵌对象；有内嵌对象 / 缓冲的是网格表与辅助表的条目）；单键与区间两条路径都释放，**区间路径的释放顺序本版不规定**。另一张**场景命令表**不动。
- 只要四张表里有任意一张真的删掉了东西 ⇒ 场景被标成"脏"；没有删掉 ⇒ 脏标记不动。
- 本条没有外部请求；它不碰纹理记录、纹理槽或共享对象槽。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个绘制键在四张表里都不存在 | 四张表都查不到该键 |
| 场景被标脏 | 场景的脏标记 ← 1（至少一张表删掉了条目） |
| 纹理记录 / 纹理槽 / 共享对象槽 | **不变** |

**成立条件**

- 区间是左闭右开；负数个数也走"≤ 1"的单键路径。
- 键不存在时该表**静默跳过**，不报错、不代替建默认项。
- 键是绘制键，**不是纹理 id**：本条不释放任何纹理。

### 创建纹理：opcode 0x1f8

<!-- rule: CORE-OPS-TEXTURE-CREATE -->

`0x1f8` 有四个操作数：**1 = 纹理 id**、**2 = 宽**、**3 = 高**、**4 = 种类**。读取顺序是 **1 → 4 → 3 → 2 → 1**；1 先读一次、清共享对象槽，最后再读一次用于建对象。

- 先清**共享对象槽**里该 id 的对象（非空则释放、置空）。
- 把该 id 的**纹理记录**写成"没有来源文件、空白创建"：来源文件 = 无，空白创建标记 = 1；**颜色键与记录里的其它字段保持原值**，释放守卫也不动。
- 清**纹理槽**里该 id 的旧对象；按种类新建一个对象写回该槽：种类 = 3 ⇒ 分割纹理，其它 ⇒ 普通纹理。
- 宽 / 高 / 种类交给对象向底层请求创建（**外部请求**）。创建成功 ⇒ 对象的逻辑尺寸 = 宽 × 高；创建失败 ⇒ 对象仍留在槽里，但它的尺寸 / 可用性未定义（实现必须诊断；后续取表面可能失败，⛔ 不要把"槽里有对象"当成"纹理可用"）。
- 本条**不上传像素**，也不保证新表面被清零：空白纹理的像素内容未定义。
- 底层创建失败 ⇒ 错误文本写进**错误通道**（术语见「总览与约定」）并上报；**不抛异常**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理记录（0x216 读来源文件） | 来源文件 = 无（-1）；空白创建 = 1；颜色键 / 其它字段不变 |
| 该 id 的纹理槽 | 一个新对象（种类决定它是不是分割纹理）；成功时尺寸 = 宽 × 高，失败时尺寸未定义 |
| 共享对象槽 | 该 id 的槽被清空 |
| 错误通道 | 一次上报（仅底层创建失败时；文本内容不在本版） |

**成立条件**

- 编号**不做范围检查**；越界诊断见「状态模型」。
- 种类只有"等于 3 / 不等于 3"决定**类**；种类还会改变底层创建请求的参数（1 / 2 / 其它各有分支），那些参数不在本版。
- 本条的"空白"是**没有来源文件**，不是"像素被清零"。

### 设置纹理：opcode 0x1f9

<!-- rule: CORE-OPS-TEXTURE-SET -->

`0x1f9` 有三个操作数：**1 = 文件号**、**2 = 纹理 id**、**3 = 颜色键**。读取顺序是 **2 → 1 → 3 → 2**；清共享对象槽发生在读第 1 个之前，打开 / 锁定之后、解码之前才读第 3 个与第二次第 2 个。

- 先清**共享对象槽**里该 id 的对象（这一步在读文件**之前**）。
- 按**统一文件 id**（见「总览与约定」与「文件与脚本装载」）打开并锁定文件；文件号非法、打不开或锁定失败 ⇒ 抛**显示消息型异常**。此时纹理记录与纹理槽都保持原值。
- **颜色键归一化**：操作数**为负** ⇒ 键 = **0**（四段全 0）；否则键 = `0xFF000000 | (操作数 & 0xFFFFFF)`。
  ★ 非负的 0 归一化成 `0xFF000000` —— 那是**不透明黑**键；负数的 0 **不是**黑键，而是**无键**：
  在 **32 位表面**上，上传期的比较是 **32 位 ARGB 全值相等**（A / R / G / B 四段都参与，见「加载纹理像素」），
  值为 0 的键命中不了任何不透明像素；16 位表面的键按目标格式位段装配（残差）。
- 清**纹理槽**里该 id 的旧对象；按「加载纹理像素」解码并新建一张**普通纹理**；尺寸 = 解码图像的宽 × 高。
- **成功** ⇒ 纹理记录：来源文件 = 文件号、颜色键 = 归一化值、空白创建 = 0；纹理槽里是普通纹理对象。
- **解码失败** ⇒ 纹理槽为空（旧对象已在解码前清掉），纹理记录：来源文件 = 无；抛显示消息型异常。
- **上传失败** ⇒ 纹理槽里是已经创建出的普通纹理对象（**上传未完成**），纹理记录：来源文件 = 无；抛显示消息型异常。
- 关闭 / 解锁在成功与失败路径上都做；操作数 3 读取抛类型异常时是否也关闭 / 解锁，本版不规定（见残差）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理来自哪个文件（0x216 读） | 成功 = 文件号；打开 / 锁定失败 = 旧值；解码 / 上传失败 = -1 |
| 该 id 的颜色键 | 记录的颜色键（归一化后） |
| 该 id 的纹理槽 | 一个新对象；成功时普通纹理、尺寸 = 图像宽高 |
| 共享对象槽 | 该 id 的槽被清空 |
| 打开 / 锁定失败 | 记录与纹理槽**不动** |
| 读字节失败 | 本版不规定槽状态（见残差） |
| 解码失败 | 记录来源 = 无；纹理槽为空 |
| 上传失败 | 记录来源 = 无；纹理槽里留着未完成的普通纹理对象 |

**成立条件**

- 先释放共享对象槽、再打开文件 ⇒ 打开失败时共享对象槽已经是空的，但纹理记录 / 纹理槽未动。
- 解码失败与上传失败是**两种不同的槽状态**：前者空，后者留下对象。
- 失败分支只把记录的来源文件写成"无"，**不改颜色键与空白创建标记**。
- 本条**不**改绘制项、不置脏标记；最终显示 / 混合不在本版，颜色键作为上传参数的作用见「加载纹理像素」。
- 操作数 1 是文件号，不是纹理 id；操作数 2 才是纹理 id。

### 加载纹理像素：0x1f9 的请求

<!-- rule: CORE-OPS-TEXTURE-LOAD -->

`0x1f9` 在读完文件号、并打开 / 锁定之后（颜色键在打开 / 锁定之后、解码之前读入；见「设置纹理」的读序），按下面的顺序完成一次**同步**加载（本条返回前结束）：

1. **打开 / 锁定**：按统一文件 id 打开并锁定文件。文件号非法、打不开或锁定失败 ⇒ 本条失败，抛显示消息型异常；此时只清过共享对象槽，纹理记录与纹理槽保持原值。
2. **读字节**：取整份文件字节。读取失败 ⇒ 本条失败，抛显示消息型异常；此时纹理槽可能已清（装载器的清槽时点见残差），本版不把槽状态写成合同。
3. **清槽**：清纹理槽里该 id 的旧对象（解码之前）。
4. **解码**：按「AGF 图像」的读取规则解码成 **top-down RGBA8**（8 / 24 / 32bpp；调色板、ACIF alpha、bottom-up 与行宽都按该章）。文件头前两字节为 `BM` 的走 BMP 分支；该分支的容器、两段头与 24 位像素布局见「存档」章的 `FMT-SAVE-STH`（本作的四份 `.STH` 就是 BMP 样本）；BMP 分支的 1 / 4 / 8 位调色板展开与 32bpp 布局本版未成篇（见残差）。其它不能解码的字节 ⇒ 失败。
5. **建对象**：新建一张**普通纹理**；逻辑尺寸 = 解码图像的宽 × 高。文件来源不影响种类（`0x1f9` 不建分割纹理）。
6. **上传**（**外部请求**）：把按目标表面格式装配好的像素写进目标表面；归一化颜色键在**写入前**用于命中判定。
   **32 位表面**上的命中判据是 **32 位 ARGB 全值相等**（A / R / G / B 四段都参与）：键 0（无键）不会命中任何不透明像素；
   调色板路径与不带 alpha 的 24 位图像都会把 A 补成**目标格式的 A 满位**（32 位 = `0xFF`）再比较。
   **命中后的清零写的是目标，不是源**：命中 ⇒ **目标像素**的**四段全 0（全透明黑）**；**源解码缓冲只读、不被改写**。
   目标为 32 位时，32bpp 与 24bpp 源上参与比较的像素值都在写进目标表面之前装配成目标像素；8 位调色板源上清的是
   **转换后供上传的调色板条目**（该条目随后按像素写进目标表面），源调色板同样不动。**16 位表面**上的键 / 像素按**目标格式的位段**装配；
   命中同样使**目标像素值为 0**（四个分量全 0）。16 位的装配 / 量化见残差。
   表面格式由显示配置的纹理位深决定（16 / 32 位）；其它位深 ⇒ 上传失败。
7. **成功**：纹理记录写来源文件 / 颜色键 / 空白创建 = 0；纹理槽里是普通纹理对象，尺寸 = 图像宽高。

- 解码失败与上传失败的区别见「设置纹理」的状态表；两者都以显示消息型异常结束。
- 本条是**同步**的：不置等待位、不等到下一帧；请求返回后指令指针才推进。
- 本条不规定平台内部的像素通道顺序与混合；目标位宽的装配 / 量化本版未取证（见残差）。本条只规定"哪张图、多大、什么颜色键、命中像素在目标里被清成什么、哪个上传请求携带它"。

### 释放纹理：opcode 0x1fa

<!-- rule: CORE-OPS-TEXTURE-RELEASE -->

`0x1fa` 有一个操作数：**纹理 id**；**同一个操作数被读两次**。读取顺序是 **1 → 清共享对象槽 → 1**。

- 先清**共享对象槽**里该 id 的对象；这一步**不受释放守卫影响**。
- 若该 id 的**释放守卫**为 0：把纹理记录的**来源文件**写成"无"；清**纹理槽**里的对象（**外部请求**：释放平台纹理）。
- 释放守卫非 0 ⇒ 上面两步都**不做**（只清共享对象槽）。本作里（观察）守卫表没有写入点，观察上恒为 0；写者未定见 `RES-TEX-GUARD-WRITER`。
- 本条**不改**颜色键与空白创建标记；不碰绘制项、不置脏标记、不改当前渲染目标。
- 释放后的纹理槽是**空槽**，不是空白纹理；`0x1fa` **不删除**引用该 id 的绘制项（`0x1f7` 才删除绘制项表里的键）。空槽与 `0x1f8` 的空白对象是两种状态。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理被释放（0x216 读来源文件） | 释放守卫为 0 ⇒ 来源文件 = 无（-1）、纹理槽为空；守卫非 0 ⇒ 来源文件与纹理槽都不变 |
| 共享对象槽 | 该 id 的槽被清空（两条路径都清） |

**成立条件**

- 不清"空白创建"标记，也不清颜色键。
- 纹理槽本来就是空 ⇒ 跳过释放，不报错。
- 释放一条纹理不等于把当前渲染目标复位；目标格可能继续指向已释放的槽（见残差）。

### 绘制纹理：opcode 0x1fb

<!-- rule: CORE-OPS-TEXTURE-DRAW -->

`0x1fb` 有八个操作数：**1 = 绘制键**、**2 = 纹理 id**、**3 / 4 = 四条边的 left / top**、**5 / 6 = 四条边的宽 / 高**、**7 / 8 = 两个整型转浮点**。读取顺序是 **6 → 4 → 5 → 3 → 4 → 3 → 7 → 8 → 2 → 1**。

- 四条边：右 = left + 宽、下 = top + 高。3 / 4 / 5 / 6 都按**整型**读出。
- 第 7、8 个操作数按**整型**读出，再转成浮点，写进绘制项的两个浮点位；第三个浮点格写 0。
- 绘制项按**绘制键**取；不存在 ⇒ 先建一个默认项再插入。绘制键与纹理 id 不是同一空间。
- 写入：置**记录首字的第 0 位**（“有效”位 —— 与 `0x202` 读的“已存在”位是**同一位**）、纹理 id、四条边、两个浮点位与 0；其它字段保持原值；场景标脏。★ 新默认项的**其余字段**按「场景对象」的默认记录初值。
- 此外，它还把**同一条场景记录**首字的第 0 位置 **1**（绘制项标志与场景对象编号**共用同一张记录表**；见「场景对象：写变换」的位 0 说明）。
- 本条**只入队**：没有外部请求，也不立即画。绘制项由渲染期的消费者读取；消费路径见「绘制项的消费者」。
- 本条**不检查**纹理 id 是否存在；检查发生在消费路径。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个绘制键对应的绘制项 | 绘制项表里该键的记录（缺则新建） |
| 该项用哪张纹理、哪四条边、哪两个浮点位 | 记录的纹理 id、四条边、两个浮点位 |
| 该项"已存在" | 记录标志字的第 0 位 ← 1 |
| 场景 | 脏标记 ← 1 |

**成立条件**

- 3 / 4 / 5 / 6 与 7 / 8 都是**整型**读取 ⇒ 若实参是浮点来源，小数部分会被截掉。
- 数值越界不检查；绘制键不存在是"建默认项"，不是错误。
- "有效"不是另一个字段：⛔ 不许为它单开一位 —— `0x202` 的门读的就是这一位。
- 本条不证明"纹理存在"；把不存在的纹理 id 写进绘制项是允许的，消费路径才可能报错 / 跳过（后果见「绘制项的消费者」）。


### 绘制项的消费者：一帧里怎么把绘制项画出来

<!-- rule: CORE-OPS-TEXTURE-DRAW-CONSUMER -->

渲染步会**访问**绘制项表里的条目；访问顺序由「绘制顺序」那条规则决定（键序 + 命令档 + 平键序）。本条只规定**每个被访问的条目如何决定"发不发绘制请求"**，不规定像素。

1. **有效位门**：条目首字的**第 0 位**（写绘制项那条指令置的"有效"位）为 0 ⇒ **不画、不报错**。除 `0x1fb` / `0x23b` 外，其余写入方（直接设当前颜色、附加组族…）**都不置这一位**；它们建出的条目在消费侧一律不可见。
2. **本轮已消费门**：条目首字的**第 16 位**为 1 ⇒ 本轮**不再画它**（场景命令档已经画过 / 占位）；收尾扫描访问过条目后**一律**把这一位清 0（不论画没画）——所以它只在**当轮**有效，不是持久状态。
3. **纹理解析**：按条目记的**纹理 id** 找纹理槽。
   - 槽里**没有对象** ⇒ 向**错误通道**上报一条「绘制源纹理尚未创建」的说明（**带纹理 id**），然后**跳过**（不发出绘制请求）。空槽**不建**纹理、**不改**条目。
   - 纹理编号**不做范围检查**：纹理槽恰好 **1000 格**；编号落在 `[0, 1000)` 之外时，读到的是渲染对象的**其它状态格**（不是纹理对象）。读到 0 ⇒ 走"空槽"那一档（上报 + 跳过）；读到非 0 ⇒ 被当作纹理对象使用（本版不规定后果：可能崩、可能画出垃圾）。⇒ **越界不会以"编号非法"被拒绝**：同族的**设目标 / 填充 / 查询尺寸**入口另有 999 上界（**创建与取对象**不检查；设目标在编号 ≥ 1000 时切到后缓冲），消费路径没有；也**不**把"越界"与"空槽"合成同一个失败。
   - 越界读到非 0 时，引擎**把那一格的值当成对象指针**：取它的第一格当虚表、调虚表的第 6 项（把当前绘制目标对象作第 1 个实参）——即**经由任意值的一次间接调用**。值的来源是渲染对象的邻格（目标对象引用 / 目标编号 / 计数 / 标志格），是否可执行取决于那一格指向什么。**后果本版不规定**，但"以该值作对象、经其虚表调用"是规定的。
   - 纹理编号 `[20, 30)` 那一档**由脚本给出**（引擎只按编号区间判档）；引擎以常量自建的纹理编号（36 / 37 / 38）不落在该区间。⇒ 正文只写**编号区间**，⛔ 不许给它起"屏幕 / 特效 / 相机纹理"这类名字。
   - **38**：引擎**自建**的离屏绘制目标（虚拟全屏类型 = 1 时按显示记录自己的宽 / 高建出；"目标是后缓冲"时切到它、画完切回）。消费路径里"目标编号 = 38"的档位读的是这个目标。
   - **39**：引擎**不建**、也**从不**把它设成目标（只有"目标编号 = 39"的档位读）。它能出现只有一种途径：脚本自己建了 39 号纹理并把目标设成它。⛔ 不许把 38 / 39 合成一个"保留档"。
   - 本节说的**显示模式**格 = 显示记录里的**虚拟全屏类型**（配置 `display:VirtualFullScreenType` 的当前值；虚拟全屏关时为 0）。⛔ 不许写成"相机模式"：它来自配置，不是场景状态。
4. **渲染目标**：当前**没有渲染目标** ⇒ 上报一条「绘制目标尚未创建」的说明并**跳过**。
   **源与目标可以是同一个纹理对象**：本条**不比较、不跳过**（引擎里没有"源 == 目标"的判断）；自引用的后果属平台（本版不规定，见残差）。
4.1 **源矩形窗口**：条目可以带一个**源矩形窗口**（由「场景对象：一对整数 + 附加组三个整数（opcode 0x239）」排上）：延迟、持续时间、**步进总数**、**每行步数**、一个**开关字**，外加一个与颜色窗**共用**的窗起点。
   - **门**：条目的"有窗"位为 0 ⇒ 整段不跑（也**不**标脏）。位为 1 且窗起点为 0 ⇒ 本步盖章（起点 ← 本步场景时钟）；盖章对所有子窗（颜色 / 变换 / 源矩形）**共用一次**。
   - **持续时间 ≤ 0** ⇒ 这一趟什么都不做（不盖章、不改矩形、不标脏）。
   - **三档**（`现在` = 本步场景时钟，按 32 位无符号比较）：`现在 > 起点 + 延迟 + 持续时间` 或场景的"强制完成"档为 1 ⇒ **到期**；`现在 ≤ 起点 + 延迟` ⇒ **延迟内**；其余 ⇒ **推进中**。★ 相等（`现在 == 终点`）算**窗内**（与「场景计时窗」同一口径）。
   - **推进中的偏移**（图集按行扫）：`步序号 = ⌊(现在 − 起点 − 延迟) × 步进总数 ÷ 持续时间⌋`（**无符号**除法，整数截断）；`Δx = 宽 × (步序号 mod 每行步数)`、`Δy = 高 × (步序号 ÷ 每行步数)`（**有符号**除法；宽 / 高是条目四条边的差）。四条边**同时**平移 `(Δx, Δy)` ⇒ 宽 / 高不变。
     ★ 步序号随时间**连续取整**，不存在"跨步事件"；引擎不比较上一步序号。
   - **延迟内**：开关字第 1 位 = 1 ⇒ 矩形原样；= 0 ⇒ 矩形**塌成空**（右 ← 左、下 ← 上）。
   - **到期**：先把延迟与持续时间清 0；开关字第 0 位 = 1 ⇒ 矩形 = 基准 + **末帧**偏移（`步序号 = 步进总数 − 1`，同样的 mod / div）；= 0 ⇒ 矩形**塌成空**。
   - **回写**：只有**到期那一档**把结果写回条目的四条边；推进中 / 延迟内只改**本帧实参**。⇒ 从下一帧起"条目的四条边"就是上一次窗口的末帧矩形（或空矩形）；本条**不重置**它（重置它的只有「纹理：写绘制项」那条）。
   - **脏 / 有动画**：只要"有窗"位为 1 且本步走到这一段，就**逐帧**标脏；"有动画"再受条目的**屏蔽标记**约束。
   - **清位 / 清起点由「场景计时窗」的推进执行**（它管共享的"有窗"位）；本条**不自己清**这个位。
   - **没有检查**：每行步数为 0 且持续时间 > 0 时的整数除零后果本版不规定（不夹取、不跳过）。

**第 6 条（附加组派生）**的边界：它**不**改"有窗"位、**不**比较上一步序号、**不**额外标脏；它与 4.1 改的是同一份矩形实参，**4.1 先、附加组后**；只有 4.1 的到期帧把矩形落表。

5. **裁剪**：把条目的四条边（**先**经过 4.1 的源矩形窗口，**再**经过第 6 条的附加组步进）夹进**纹理对象自己的逻辑矩形**（创建纹理时请求的宽 / 高；不是表面实际尺寸）——左 / 上取大、右 / 下取小。夹完为空（左 ≥ 右 或 上 ≥ 下）⇒ **静默跳过**：不画、**不上报**。
5.1 **位置档位**：条目的**两个浮点位**（外加一个恒为 0 的第三格）作为**一个三维实参**交给绘制入口；绘制入口的另一个三维实参在本路径**恒为空**。这个实参按下面四步加工（顺序固定）：
   1. **裁剪补偿**：源矩形被**左**裁掉多少，位置的 x 就加回多少；被**上**裁掉多少，y 就加回多少；被右 / 下裁**不补**。第三格不参与补偿。
   2. **缩放 + 取整**：纹理编号落在 **`[20, 30)`** 那一档 ⇒ 位置的 x / y **各乘场景缩放，再按半上取整**（`floor(值 × 缩放 + 0.5)`）；其它编号**不缩放、不取整**。★ 这一档**只由纹理编号决定**，与绘制目标编号无关。
   3. **场景偏移**：由**显示适配参数**提供两个整数偏移（视口原点；见「显示适配」），按下面两档之一取"**整数原样**"或"**整数 ÷ 场景缩放**"：
      - 绘制目标是**后缓冲**（编号 -1）或保留编号 **38**：显示模式 = 1 且目标是后缓冲 ⇒ 偏移 = **(0, 0)**；否则纹理编号在 `[20, 30)` ⇒ 偏移 = **整数原样**；否则 ⇒ 偏移 = **整数 ÷ 场景缩放**。
      - 其它目标（编号 ≥ 0 且 ≠ 38）：纹理编号在 `[20, 30)` ⇒ 偏移 = **(0, 0)**；否则 ⇒ 偏移 = **整数 ÷ 场景缩放**。
   4. **相加**：位置的 x / y 各加对应偏移；第三格不加。
   - **固定分辨率模式**生效时：缩放按 **1**、偏移按 **0**（但第 2 步的**取整照做** —— 取整与"是否真的缩放"不是同一个开关）。
   - 同一组档位还决定这一步的**变换**（门是**互斥**的，每笔最多乘一张）：场景视图矩阵只在"**屏幕形态 = 占满屏** 且（目标编号 < 0 **或** = 39）且纹理编号**不在** `[20, 30)`"时乘入；**逆**场景缩放矩阵只在"**屏幕形态 = 占满屏** 且目标编号 ≥ 0 且 ≠ 39 且纹理编号**在** `[20, 30)`"时乘入。⛔ 不要把视图矩阵的门写成"目标编号 ≥ 0 且 ≠ 39"（那是反的：目标 38 与纹理目标不乘）。这两个矩阵由**显示适配参数**派生（见「显示适配」）；矩阵内容见该条。
   - ⛔ 不许把第 2 步写成"位置 × 1/缩放"：位置乘的是**缩放本身**，矩阵里乘的才是**逆缩放**。⛔ 不许把取整写成"四舍五入"。
6. **附加组派生**：条目的第 **2 位**（由「附加组」那族写入方置 1）为 1 ⇒ 再走一次**附加组派生**。它**不是**第二次绘制，**不发**第二个绘制请求；它改的是主绘制的**输入**。执行次序：**源矩形步进在裁剪（第 5 条）之前**；颜色 / 变换的修改在裁剪之后、请求（第 7 条）之前：
   - 把**本步颜色**按附加组**自己的**周期（起点戳 + 周期的三角波）朝附加组终色**逐字节混合**，结果写回**同一个**本步颜色出参；
   - 把附加组的变换通道乘进**本步变换**，并把"本步变换有效"**强制为 1**；
   - 把附加组的**步进量**加到**源矩形的四条边上**（左右同加、上下同加 ⇒ 换成同一张图里的另一个子矩形）。标脏**不是**这条独有的：**只要条目的"有窗"位为 1，本步的派生就逐帧标脏**（4.1 也标）；附加组这里**不额外**标脏、也**不**比较上一步序号。
   主绘制**仍然只发一次**，收到的是被改过之后的矩形 / 位置 / 颜色。附加组的时间基准与主窗**不同**（各自起点戳、各自周期），⛔ 不许合并成一个窗。
6.1 **场景自身变换（额外变换）**：场景对象上有一对整数给出的**键区间**（起点 + 计数）。条目的绘制键落在该区间内时，在**主绘制之前**把一份"场景自身记录的变换矩阵"乘进**本步变换**，并把"本步变换有效"置 1；命令档可以多传一个**「跳过」**标志来抑制这一步。
   - 该区间的**唯一脚本写入者**是一条指令（`0x229`），它同时设置**场景自身记录的三元平移**；场景默认值重置把它清成 `(0, 0)`，存档载入会把两个整数读回来。
   - 那份矩阵由**场景自身记录**派生，且只有当**计数非 0** 时才派生。
   - **命令档的判据是"命令覆盖区间的起点键是否落在区间内"**（不是逐条判）：落在内 ⇒ 传"跳过" ⇒ 该命令画的条目**一个都不乘**；不落在 ⇒ 不传 ⇒ 逐条按键判。⚠ 这是引擎的既有行为（区间起点在窗外、而区间跨进窗内时，窗内条目照旧乘），实现必须照此，⛔ 不许"为了自洽"改成逐条判。收尾扫描**总是**不跳过。

7. **请求**：把**裁剪后的源矩形**、上面 5.1 加工过的**三维位置实参**、**本步变换**与**本步颜色**交给该纹理的**绘制入口**。命令档还可以多传一个**「跳过额外变换」**标志（收尾扫描总传"不跳过"；标志的来源见「场景命令记录族」）。本步颜色是一个 32 位值：**默认是不透明白**，透明度是它的一部分（位段属机器细节）；它由「场景计时窗」的四档派生规则得出（无窗 / 延迟内 / 未推进 ⇒ 当前颜色；推进中 ⇒ 插值色；到期 ⇒ 终色）。**派生结果只写进"本步颜色"这一个出参格**，不写进记录的当前颜色格：推进中的**插值色不落表**；唯一写当前颜色格的是窗口**到期那一步**（当前颜色 ← 终色、终色 ← 无颜色、延迟与持续时间清 0）。本条随后把**整份记录副本拷回表**，所以"到期"这一步的写入是**持久**的。绘制入口返回**失败** ⇒ 上报一条「绘制失败」说明（**带纹理 id**）并**跳过**；返回成功 ⇒ 正常结束。
8. 本条**不建纹理、不改纹理槽**；条目字段只允许这些写入：第 16 位清 0、**4.1 的到期帧写回源矩形**、「附加组派生」的矩形成分只在实参上（不落表）、窗**到期**写回当前颜色 / 终色 / 延迟 / 持续时间（然后整份副本拷回表）。它**不删除条目**；条目的删除是「拆离」那条的事。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个绘制项本帧被画出 | 该纹理的绘制入口收到：渲染目标、裁剪后的源矩形、目标位置、本步变换、本步颜色，以及（命令档才有的）「跳过额外变换」标志 |
| 本步变换 | 单位阵起步，"有效"默认 0；附加组派生可乘入并强制"有效 = 1" |
| 某个绘制项本帧被跳过 | 有效位为 0 / 第 16 位为 1 / 源矩形夹空 / 纹理槽为空 / 无渲染目标 / 绘制入口失败 |
| 条目本帧的位置实参 | 两个浮点格 + 第三格，经裁剪补偿 / 档位缩放取整 / 场景偏移后交给绘制入口 |
| 条目本帧的源矩形 | 四条边，可能已被**附加组派生**步进过，再夹到纹理逻辑矩形 |
| 错误通道 | 至多一次上报（源纹理缺失 / 无渲染目标 / 绘制失败三种之一；夹空**不**上报） |
| 「本轮已消费」 | 被访问的条目第 16 位 ← 0（不论是否画出） |

**成立条件**

- **"槽里没有对象"与"条目无效"是两条不同的跳过**：前者上报、后者静默；⛔ 不许把两者合成一个"画不出来"分支。
- **夹空是静默的**：它既不是错误，也不建占位物。⛔ 不许为"没有可见像素"补一个占位块。
- 裁剪用**纹理对象自己的逻辑矩形**，⛔ 不是表面实际尺寸、也不是"不裁剪"。
- 第 0 位是**唯一**的"可画"判据（它与 `0x202` 的门同一位）；⛔ 不许另立"已创建 / 有内容"的位。
- 颜色是**本步派生色**：窗进行中改当前颜色会改下一帧的派生色，但**当前颜色字段本身不被本条回写**。
- 透明度是颜色的一部分，⛔ 不许把它写成另一个操作数 / 另一个字段。
- 像素（混合、滤镜、最终像素）属平台 ⛔ 不在本条；本条只规定"哪张纹理、哪块源矩形、画到哪、用什么颜色"。
- 错误文本的**内容**本版不规定，但必须**仍然上报**且**带纹理 id**（否则无法从日志定位坏条目）。
- 位置取整是**半上取整**（乘之后 +0.5 再取 floor）；场景偏移在取整**之后**才加。
- 场景偏移的"原样 / ÷ 缩放"两档按**绘制目标编号**分；纹理编号只决定 `[20, 30)` 那一档。
- 越界纹理编号**不被夹取**，也不会变成"编号非法"；自引用**不跳过**。
- 位 2 只多一次**派生**，⛔ 不许写成"多画一次"；颜色混合是**逐字节整数**（截断）。

**可证伪**

- 建一条绘制项，纹理 id 指向**空纹理槽**：若画面上出现任何东西（占位块 / 旧内容 / 其它纹理），或错误通道里没有一条带该 id 的说明 ⇒ 本条错。
- 把绘制项的矩形设成**完全落在纹理逻辑矩形之外**：若错误通道出现说明、或绘制入口被调用 ⇒ 本条错。
- 用**不置第 0 位**的写入方建条目：若它被画出 ⇒ 本条错。
- 把条目的当前颜色设成**全透明**：若绘制入口收到的颜色不是全透明 ⇒ 颜色参与合同错。
- 让同一条目在**同一帧**被命令档画过：若收尾扫描又画了它一次 ⇒ 第 16 位合同错。
- 纹理编号设成 **1000**（越界）再画：若错误通道出现"编号非法"、或条目被静默丢弃 ⇒ 本条错。
- 把绘制项**画进它自己**（目标 = 该纹理）：若引擎侧出现"跳过"（不调绘制入口、也不报失败）⇒ 本条错。
- 窗口**推进中**画一次（时钟不推进）：若记录的当前颜色格已经等于插值色 ⇒ 本条错。
- 纹理编号 20..29、位置 1.4、场景缩放 2 ⇒ 若绘制入口收到的 x 不是 3 ⇒ 本条错；位置 1.4、编号 5、缩放 2 ⇒ 若 x 被改成 3 或 2.8 ⇒ 本条错。
- 位 2 = 1 且其它字段不变：若绘制入口被调用**两次** ⇒ 本条错；若源矩形 / 颜色 / 变换三者都没变 ⇒ 本条错。

**残差**

- `RES-TEX-DRAW-CONSUMER-OOB`（unknown）：纹理槽表 1000 格、消费路径不检查；越界读到渲染对象相邻状态（读到 0 走空槽上报，非 0 当纹理对象用）。下一步：**真机采样**越界编号（如 1000）看是否崩 / 画垃圾；以及目标编号 38 / 39 的语义。
- `RES-TEX-DRAW-CONSUMER-SELFTARGET`（unknown）：引擎不比较源与目标、不跳过；自引用的成败在平台（返回失败则走上报）。下一步：真机 / 采样一次自引用绘制，记录平台返回码与画面。
- `RES-TEX-LAYER-CANVAS-COLLIDE`（unknown）：脚本可以给同号纹理（20..29）建自己的画布，与文本层画布撞号；运行期谁覆盖谁未取证。层号越界属文本系，不进本章。

**编号 `[20, 30)` = 文本层画布带**：文本 / 消息子系统按**文本层号 i** 自建编号 `20 + i` 的离屏画布，层槽共 10 格 ⇒ 编号恰好落满 20..29。画布内容由 CPU 写入，随后以同一编号**入队一条绘制项**，走的正是本节这条消费路径。画布按适配比**预缩放**（尺寸 = 层矩形 × 适配比；**取整与位置同一套 —— 半上取整**，见「文本层画布」）；消费路径把位置乘同一个比 + 半上取整折进同一适配坐标，纹理目标上用逆缩放矩阵抵回去（只写算术合同，不写引擎动机）。

### 纹理：查询尺寸（opcode 0x208）

<!-- rule: CORE-OPS-TEXTURE-SIZE -->

读三个操作数：**纹理编号**（整数，第 1 个）、**宽**（第 2 个，**被写**）、**高**（第 3 个，**被写**）。

- 编号 **大于 999** ⇒ 向**错误通道**上报一条「编号非法」说明；两个输出都写 **0**（与 0x20b 同界；纹理族里“不做范围检查”只适用于 0x1f8 那组）。
- 编号在范围内、槽里有纹理对象 ⇒ 宽 / 高 ← 该纹理对象的尺寸；
- 编号在范围内、槽为空 ⇒ 两个输出都写 **0**（**不**上报）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某纹理的像素尺寸 | 第 2 / 3 个操作数（整数）← 纹理对象的宽 / 高；失败时 0 / 0 |
| 错误通道 | 一次上报（仅编号越界） |

**成立条件**

- 「越界」与「槽空」**不是同一失败**：一个上报，一个静默。
- 本条**不建**纹理、**不改**纹理槽、**不**置脏。
- 读序是 **1 → 写 2 → 写 3**。

### 纹理：读槽→文件绑定（opcode 0x216）

<!-- rule: CORE-OPS-TEXTURE-SLOT-IMGID -->

`0x216` 有两个操作数：**目标**（写）、**槽号**（读）。

- 槽号在 `0..999`：目标 ← 该槽**纹理记录的来源文件格**（不是独立的第二张表）。记录表在场景初始化时把 1000 条来源文件都写 -1；初始化后未再写入的槽读回 **-1**。
- `0..999` 读的是**活动表**，不是存档快照；快照与活动表的差别见「场景 / 颜色族」的 1000 项表。
- **读档恢复**逐项重建活动表的来源文件（同 `0x1f9` 的装载路径）；`0x216` 读到的是恢复后的活动表。
- 槽号越界（负数 / ≥1000）不在本版合同内；引擎的索引没有范围比较，`1000..1999` 会落到紧邻的**快照表**（见残差）。
- 推进格数 = 5；不写其它脚本变量、不置门位、**不切换当前帧**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某槽的纹理来自哪个文件 | 目标 ← 该槽纹理记录的来源文件；无 = -1 |
| 槽号越界 | 本版不规定（残差） |

**成立条件**

- **写者**：`0x1f8` 空白创建 ⇒ -1；`0x1f9` 成功 ⇒ 文件号，打开 / 锁定失败 ⇒ 旧值，解码 / 上传失败 ⇒ -1（读字节失败 / 操作数 3 异常见 `0x1f9` 残差）；`0x1fa` 释放守卫为 0 ⇒ -1，非 0 ⇒ 不变；`0x23d` 在释放守卫为 0 时对槽 42..999 ⇒ -1，0..41 不变；**存档恢复**逐项重建活动表（见「存档」与 `0x1f9` 的装载路径）；本条读到恢复后的活动表。
- 绑定表是**槽号索引**，不是绘制键；`0x216` 不写它，只读。
- 读序是 **2 → 1**（先读槽号，再写目标）。

**残差**

- `RES-216-OUT-OF-RANGE`（unknown）：`1000..1999` 会读到紧邻的快照表（不是活动表）；`>=2000` 继续落到后续内存。本版只规定 `0..999`，实现应响亮失败 / 记诊断，不复刻布局。
- `RES-216-SAVE-RESTORE`（unknown）：存档恢复写的是快照，是否 / 何时同步到活动表未取证。

### 纹理：矩形填充（opcode 0x20b）

<!-- rule: CORE-OPS-FILLTEXTURE -->

读七个操作数：**纹理编号**、**x**、**y**、**宽**、**高**、**透明度**、**颜色**（都按整数读）。

1. 以 (x, y) 为左上、宽 / 高为尺寸构造一个矩形；
2. **透明度夹取**：大于 255 ⇒ 按 255（本条**只有**上夹，没有下夹）；
3. **颜色变换**：`颜色 ← (颜色 & 0x00FFFFFF) | 0xFF000000` —— 低 24 位**原位不动**，最高字节置 **1**（源按 ARGB 解释）。
4. 按纹理编号定位**纹理记录**，把记录里「内容非文件装载」标志置 **1**（**先于**编号检查；该格与「空白创建」写的是同一格）；
5. 编号 **大于 999** ⇒ 错误通道上报（「编号非法」）；
6. 槽里没有纹理对象 ⇒ 错误通道上报（「纹理不存在」）；
7. 存在 ⇒ 把矩形**夹到该纹理对象自己的逻辑矩形**（创建时写成 `(0, 0, 宽, 高)`；不是表面实际尺寸）——左上取大、右下取小；夹完为空（左 ≥ 右 或 上 ≥ 下）⇒ **直接返回，不画也不报错**；
8. 否则把矩形、变换后的颜色、透明度交给该纹理的**填充入口**；入口唯一的失败源是加锁失败 ⇒ 错误通道上报（「加锁失败」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 纹理记录「内容非文件装载」 | 该记录的标志格 ← 1（与「空白创建」同一格；全语料无读点） |
| 某纹理上的一块矩形被填色 | 纹理的填充入口被调用（矩形 + 颜色 + 透明度） |
| 错误通道 | 一次上报（编号越界 / 槽空 / 加锁失败；空矩形**不**上报） |

**成立条件**

- 标志格在**编号检查之前**就写；但它**全语料没有读点**，所以“写没写”不是可观察合同；编号越界时这次写落在哪里属**未定义行为**（见残差），本版不规定。
- 颜色公式是**逐位合同**：低 24 位不重排、最高字节置 1。⛔ 不许写成“把三段重排”。
- 矩形夹到**对象自己的逻辑矩形**（创建时请求的宽 / 高），不是表面实际尺寸；夹取发生在调用填充入口之前。
- 透明度只有**上夹**（>255 ⇒ 255）；负数**不**夹到 0（按原值传下去）。
- 填充入口是**平台 / 渲染侧**的请求；像素结果本版不规定（见残差）。
- 编号上界 **999 与 0x208 相同**；纹理族里“不做范围检查”只适用于 0x1f8 那组（其 handler 直接索引），0x20b 是**先写后查**。
- 本条不改纹理内容以外的引擎数据（不改绘制项、不改场景脏标记——除非填充入口自己写）。

## 纹理族

本章 5 条规则 / 5 个 opcode。

这五条操作的是场景里的**纹理对象**与**绘制项**：按一个整数编号取记录，按槽建/换/释放纹理对象。
它们都只改引擎数据；底层图像的解码、上传与呈现属于外部模块。

### 拆离纹理：opcode 0x1f7

<!-- rule: CORE-OPS-TEXTURE-DETACH -->

`0x1f7` 有两个操作数：**第 2 个是个数**、**第 1 个是键**；读取顺序是**先第 2 个、后第 1 个**。

- **个数 ≤ 1**：把该键从场景的四张键表（绘制项表与三张辅助表）里删除。
- **个数 > 1**：按**左闭右开**区间 `[键, 键 + 个数)` 删除四张表里的条目；条目内嵌的对象与缓冲一并释放。
- 只要四张表里有任意一张真的删掉了东西 ⇒ 场景被标成"脏"；没有删掉 ⇒ 脏标记不动。
- 本条没有外部请求。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个键在四张表里都不存在 | 四张表都查不到该键 |
| 场景被标脏 | 场景的脏标记 ← 1（至少一张表删掉了条目） |

**成立条件**

- 区间是左闭右开；负数个数也走"≤ 1"的单键路径。
- 键不存在时该表**静默跳过**，不报错、不代替建默认项。

### 创建纹理：opcode 0x1f8

<!-- rule: CORE-OPS-TEXTURE-CREATE -->

`0x1f8` 有四个操作数：**1 = 纹理 id**、**2 = 宽**、**3 = 高**、**4 = 种类**；读取顺序是 **1 → 4 → 3 → 2 → 1**。

- 先清**引擎级对象槽**里该 id 的对象（非空则释放、置空）。
- 把该 id 的**纹理记录**重置为"没有来源文件、空白创建"：来源文件 = 无，空白创建标记 = 1。
- 清**纹理槽**里该 id 的旧对象；按种类新建一个对象写回该槽：种类 = 3 ⇒ 分割纹理，其它 ⇒ 普通纹理。
- 宽 / 高 / 种类交给对象向底层请求创建（**外部请求**）。
- 底层创建失败 ⇒ 错误文本写进**错误通道**（术语见「总览与约定」）并上报；**不抛异常**，本对象**仍留在槽里**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理记录 | 来源文件 = 无；空白创建 = 1 |
| 该 id 的纹理槽 | 一个新对象（种类决定它是不是分割纹理） |
| 引擎级对象槽 | 该 id 的槽被清空 |
| 错误通道 | 一次上报（仅底层创建失败时；文本内容不在本版） |

**成立条件**

- 编号**不做范围检查**。
- 种类只有"等于 3 / 不等于 3"两个分支，不是枚举。

### 设置纹理：opcode 0x1f9

<!-- rule: CORE-OPS-TEXTURE-SET -->

`0x1f9` 有三个操作数：**1 = 文件号**、**2 = 纹理 id**、**3 = 颜色键**；读取顺序是 **2 → 1 → 3 → 2**。

- 先清**引擎级对象槽**里该 id 的对象（这一步在读文件**之前**）。
- 按文件号打开并加锁（**外部请求**）；文件号非法、或加锁失败 ⇒ 抛**显示消息型异常**。
- 颜色键归一化：负数 ⇒ 0；非负 ⇒ **不透明黑**与操作数的按位或。★ 颜色字段的**位段划分**与「不透明黑」的具体数值都属机器细节，**本版不规定**（原因：没有逐字取证，写出的颜色键因此不唯一；本版也不断言哪几位是颜色、哪几位是 alpha）。
- 清**纹理槽**里该 id 的旧对象；解码图像、新建普通纹理对象、上传像素（后三者是**外部请求**）。
- **成功** ⇒ 纹理记录：来源文件 = 文件号、颜色键 = 归一化值、空白创建 = 0。
- **失败** ⇒ 纹理记录：来源文件 = 无；关闭文件后抛**显示消息型异常**。
- 关闭 / 解锁在两条路径上都做。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理来自哪个文件 | 记录的来源文件 |
| 该 id 的颜色键 | 记录的颜色键（归一化后） |
| 该 id 的纹理槽 | 一个新对象 |

**成立条件**

- 先释放对象槽、再打开文件 ⇒ 失败路径上对象槽已经是空的。
- 失败分支只把记录的来源文件写成"无"，不改颜色键与空白创建。
- **显示消息型异常**（定义见「异常与错误通道」）：本条的两处失败（打开 / 加锁、解码）都抛它；抛出即中止本条，清理在抛出前已经做，已经写下的引擎数据**保留、不回滚**。主循环捕获它之后怎样处置（显示、重试、结束）属于「执行与时间」，本版不规定。

### 释放纹理：opcode 0x1fa

<!-- rule: CORE-OPS-TEXTURE-RELEASE -->

`0x1fa` 有一个操作数：**纹理 id**；**同一个操作数被读两次**。

- 先清**引擎级对象槽**里该 id 的对象。
- 若该 id 的**释放守卫**为 0：把纹理记录的**来源文件**写成"无"；清**纹理槽**里的对象。
- 释放守卫非 0 ⇒ 上面两步都**不做**（只清引擎级对象槽）。本作里（观察）守卫表没有写入点 ⇒ 观察上恒为 0。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该 id 的纹理被释放 | 来源文件 = 无；纹理槽为空 |
| 释放被守卫挡住 | 来源文件与纹理槽都不变 |

**成立条件**

- 不清"空白创建"标记。
- 纹理槽本来就是空 ⇒ 跳过释放，不报错。

### 绘制纹理：opcode 0x1fb

<!-- rule: CORE-OPS-TEXTURE-DRAW -->

`0x1fb` 有八个操作数：**1 = 绘制键**、**2 = 纹理 id**、**3 / 4 = 矩形 x / y**、**5 / 6 = 宽 / 高**、**7 / 8 = 两个数值**。
读取顺序是 **6 → 4 → 5 → 3 → 4 → 3 → 7 → 8 → 2 → 1**。

- 矩形存成**四条边**：右 = x + 宽、下 = y + 高；**不是宽高本身**。
- 第 7、8 个操作数按**整型**读出，再转成浮点，写进绘制项的两个位置；第三个位置写 0。
- 绘制项按**绘制键**取；不存在 ⇒ 先建一个默认项再插入。
- 写入：置**绘制项标志字的第 0 位**（"有效"位 —— 与 `0x202` 读的"已存在"位是**同一位**）、纹理 id、矩形四条边、两个浮点与 0；场景标脏。
- 本条没有外部请求；**不检查纹理 id 是否存在**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个绘制键对应的绘制项 | 绘制项表里该键的记录（缺则新建） |
| 该项用哪张纹理、画在哪个矩形 | 记录的纹理 id 与四条边 |
| 两个数值 | 记录里的两个浮点位（第三个位 = 0） |
| 该项"已存在" | 记录标志字的第 0 位 ← 1 |

**成立条件**

- 两个数值来自**整型**读取 ⇒ 若实参是浮点来源，小数部分会被截掉。
- 数值越界不检查；绘制键不存在是"建默认项"，不是错误。
- "有效"不是另一个字段：⛔ 不许为它单开一位 —— `0x202` 的门读的就是这一位。

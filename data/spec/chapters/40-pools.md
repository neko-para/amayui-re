## 数据池

**池**是一组可按整数下标访问的**槽**。引擎有两类池：

- **全局池**：属于引擎，跨脚本存在；
- **局部池**：属于**当前帧**，随帧切换。

本规范把数据池作为一个完整主题：**族、下标、访问原语、值表示、容量**都在本章。脚本怎样编码操作数见「脚本与执行」；`type` / `raw` 的字节布局属于脚本二进制协议，本章只规定它们的运行期含义。

### 操作数类型标签

操作数由**类型标签**与 **raw** 组成。类型标签决定访问哪个池、按哪种值语义解释；raw 是下标或立即值。

| 标签 | 含义 | 本版规定 |
|---|---|---|
| 0 | 立即值 | 是（见「立即值与内联字符串」） |
| 1 | 浮点立即值 | 是（见「立即值与内联字符串」） |
| 2 | 内联字符串 | 是（见「立即值与内联字符串」） |
| 3–8 | 全局池族（见下表） | 是 |
| 9–14 | 局部池族（见下表） | 是 |
| 0x8003 / 0x8005 / 0x8009 / 0x800B | 容器句柄 | 是（见「容器句柄：类型标签 0x8003 / 0x8009」与「字符串容器句柄：类型标签 0x8005 / 0x800B」） |

上表的"是"表示该标签的访问语义在本版规定内；容器对象本身的其余语义（其余字段的用途、哪些操作用容器、注册表的消费者）不在本版。

每个池有一个**族**。族的名字同时描述槽里装什么、以及读写时如何解释：

| 族的类别 | 族 | 槽里装什么 |
|---|---|---|
| 值族 | 整型 | 一个整数值（以编码位模式存储，见「整数值的编码」） |
| 值族 | 浮点 | 一个 32 位浮点数 |
| 值族 | 字符串 | 一条定长字符串记录（见「字符串记录」） |
| 引用族 | 整型引用 / 浮点引用 / 字符串引用 | 一个**地址**；目标是相应值族的槽或记录 |
| 引用族 | 指针 / 浮点指针 / 字符串指针 | 一个**地址**；目标是相应值族的槽或记录 |

全局池与局部池各有一套族。类型标签与池族一一对应：

| 类型标签 | 池 | 族 | 类别 |
|---|---|---|---|
| 3 | 全局 | 整型 | 值族 |
| 4 | 全局 | 浮点 | 值族 |
| 5 | 全局 | 字符串 | 值族 |
| 6 | 全局 | 整型引用 | 引用族 |
| 7 | 全局 | 浮点引用 | 引用族 |
| 8 | 全局 | 字符串引用 | 引用族 |
| 9 | 局部 | 整型 | 值族 |
| 10 | 局部 | 浮点 | 值族 |
| 11 | 局部 | 字符串 | 值族 |
| 12 | 局部 | 指针 | 引用族 |
| 13 | 局部 | 浮点指针 | 引用族 |
| 14 | 局部 | 字符串指针 | 引用族 |

**下标**由操作数的 raw 给出 —— 这是**池族 3–14** 的口径：raw 是池内下标，不是值；下标本身不过任何编解码。类型标签 0 / 1 / 2 的 raw **不是**池下标（分别是立即值、浮点位模式、文本偏移，见「立即值与内联字符串」）；容器句柄的 raw 是池下标，但落点是被那个句柄指的容器（见容器句柄两节）。

池的**容量**是运行期状态：**全局池在启动期**、**局部池在脚本装载时**按计数确定，本规范不把它写成常量。引擎对下标访问**没有边界检查**。

### 五种访问原语

| 原语 | 用途 | 结果 |
|---|---|---|
| 取址 | 只需要地址时 | 返回槽 / 记录的地址 |
| 读整型 | 按整型语义取值 | 32 位整数 |
| 读浮点 | 按浮点语义取值 | 64 位浮点数 |
| 写整型 | 把整型语义的值写回 | 无 |
| 写浮点 | 把浮点语义的值写回 | 无 |

同一类型标签在不同原语下可能有不同结果。例如字符串族在"读整型"时按十进制文本解析成整数，在"读浮点"时按十进制文本解析成浮点数（见「字符串记录」）。原语的选择由消费该操作数的指令决定。

### 五种访问原语的入口契约

<!-- rule: CORE-POOL-PRIMITIVE-ENTRY -->

五种访问原语是**取址、读整型、读浮点、写整型、写浮点**。每次调用给两件事：**这是第几个操作数**（从 1 开始数）与（写原语）**要写的值**。取址返回一个地址；读整型返回 32 位整数；读浮点返回 64 位浮点；写原语没有返回值。

原语**不消费操作数以外的指令状态**：同一个操作数、同一个池状态，结果只由类型标签与 raw 决定。

★ **两个宽度别混**：池内的浮点元素是 **32 位**；读浮原语把它转成 **64 位**返回。需要 32 位的调用点自己截断——这不是"池里存的是 64 位"，也不是"返回值是 32 位"。

原语每次调用还把"当前操作数在指令里的地址"写进一个引擎级槽（每个原语一个），同一个原语后续会从那个槽里回读 raw。

**适用条件**

- 操作数序号是**第几个**，不是字节偏移；一条指令里第一个操作数的序号是 1。
- 原语只在"已经知道类型标签"的前提下被调用；标签分派在函数入口自己做（见「类型标签的分派结构」）。
- 写原语的"要写的值"是 32 位整数或 32 位浮点；跨族写入要先转换（见「浮点值的表示与跨族转换」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 一条指令的第 k 个操作数 | 操作数记录数组的第 k−1 项 |
| 当前操作数地址缓存 | 每个原语一个引擎级槽（五个各一） |

### 类型标签的分派结构

<!-- rule: CORE-POOL-TAG-DISPATCH -->

原语按类型标签三分：

1. **标签小于 0x8003**：与一个小上界比较后直接查跳转表。不同原语有不同**表规模**与**起点**：
   取址从 3 起（12 项 ⇒ 3..14）、读整 / 读浮从 0 起（14 项 ⇒ 0..13）、写整从 3 起（10 项 ⇒ 3..12）、
   写浮从 3 起（11 项 ⇒ 3..13）。**表项可以指向 default 块**（读整 / 读浮的表项 8 就是），**超出上界的标签**走 `ja` 到 default。
2. **标签等于 0x8003**：独立分支（容器句柄，见「容器句柄」）。
3. **标签大于 0x8003**：再按具体值分：取址接受 `0x8005` / `0x8009` / `0x800B`；四个读写原语在 `0x8003` 之后只接受 `0x8009`；其余一律 default。

default 的行为是**抛**（类型异常）；"抛"是规范的可观察行为，不是实现选择。

**适用条件**

- 五张表的规模互不相等（12 / 14 / 14 / 10 / 11）——这是**实现结构**，不是可观察合同；
  合同是「支持集合与不支持的组合」那张接受集。
- 标签 0 / 1 / 2 不在取址与两个写原语的表里 ⇒ 它们在那三个原语里是 default（见「立即值与内联字符串」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 标签是否被某原语支持 | 该原语的分派结构是否给这个标签一个非 default 的目标 |

### 立即值与内联字符串：类型标签 0 / 1 / 2

<!-- rule: CORE-POOL-TAG-IMMEDIATE -->

这三个标签只在两个**读**原语里有语义；取址与两个写原语对它们是类型异常。它们**不碰任何池**：没有下标，也没有编解码。

- **0**：raw 就是值本身。读整得到 raw；读浮把 raw 当**有符号**整数再转成浮点。
- **1**：raw 的**位模式**就是一个 32 位 IEEE-754 浮点。读浮原样取出；读整把它**截断**成整数（向零）。
- **2**：raw 是一个**文本偏移**：文本在脚本缓冲里的第 raw 个 32 位字处。读整把文本按十进制解析成整数，读浮解析成浮点；文本**没有长度前缀**，以 NUL 结束。★ 脚本缓冲里存的是**逐字节取反**（每字节与 0xFF 异或）的字节：读的时候先取反回来，**取反后为 0 的那个字节**就是终止符（存储字节 `0xFF`）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 立即整数 / 立即浮点的值 | 操作数记录里的 raw 字（不落到任何池） |
| 内联文本 | 脚本缓冲第 raw 个 32 位字起的字节序列（逐字节取反；存储字节 `0xFF` 处终止） |

**成立条件**

- 三个标签只在"读"方向有定义；对它们取址或写入是类型异常（见「支持集合与不支持的组合」）。
- 标签 1 的读整是**截断**，不是四舍五入。
- 标签 2 的文本解析与字符串记录的文本解析是同一口径。

### 全局值族：类型标签 3 / 4 / 5

<!-- rule: SPC-POOL-GLOBAL-VALUE-FAMILIES -->

操作数类型标签 3 / 4 / 5 分别选择全局整型池、全局浮点池、全局字符串池。raw 是池内下标；取址结果是该槽（字符串族为该记录）的地址。

- 整型池的槽装**编码后的整数位模式**（见「整数值的编码」）；整型池的初值是**编码后的 0**。
- 浮点池的槽装 32 位浮点数；浮点不过编解码。
- 字符串池的一槽是一条定长字符串记录（见「字符串记录」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 全局整型池第 i 个值 | `operand(type 3, index i)` 经读整型原语解码后的整数 |
| 全局浮点池第 i 个值 | `operand(type 4, index i)` 经读浮点原语得到的 64 位浮点数（池内元素是 32 位） |
| 全局字符串池第 i 个字符串 | `operand(type 5, index i)` 指向的字符串记录 |

**成立条件**

- raw 是池内下标，不是值；下标不参与整型编解码。
- 池容量是运行期状态，本规范不假设上界（见「容量与分配」与「下标不做上界检查」）。
- 写整型 / 写浮点原语不接受类型标签 5（字符串族），见「支持集合与不支持的组合」。

### 全局引用族：类型标签 6 / 7 / 8

<!-- rule: SPC-POOL-GLOBAL-REF-FAMILIES -->

类型标签 6 / 7 / 8 是全局池的**引用族**：槽里装的是一个地址，不是值本身。

- 取址原语取槽，得到地址；
- 读原语再解引用一次，才得到目标值（整型、浮点、字符串各按目标族解释）；
- 写原语把目标地址取出来，再写到目标处。

因此"池里那一槽"与"值所在处"是两层。指针槽本身不参与编解码：取址原语直接返回槽内容；解引用出来的整数值仍按「整数值的编码」解码。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 引用第 i 槽指向的整数值 | `cell(type 6, i)` → 解引用 → 解码 |
| 引用第 i 槽指向的浮点值 | `cell(type 7, i)` → 解引用 → 32 位浮点数 |

★ 类型标签 8（全局字符串引用）**只有取址**：读整型 / 读浮点原语对它落缺省（抛"操作数类型异常"），写原语也不接受它。
它不是"读出来再解引用成字符串"：字符串引用的**读取不在支持集合里**（抛异常），本版因此不给它读语义。

**成立条件**

- 指针槽本身不参与编解码；取址原语直接返回槽内容（一个地址）。
- 解引用出来的整数值仍按「整数值的编码」解码。
- 指针目标的生命周期与有效性不在本版范围；本规范不假设目标已被初始化。

### 局部池：类型标签 9..14

<!-- rule: SPC-POOL-LOCAL-FAMILIES -->

类型标签 9..14 对应当前帧的六个局部池：整型、浮点、字符串、指针、浮点指针、字符串指针。取址原语先按当前帧定位局部池，再按 raw 下标取槽。

- 整型族的槽装编码位模式；初值是**编码后的 0**（读出来是 0，但位模式不是 0）。
- 浮点族是裸 32 位浮点数。
- 字符串族是一槽一条定长字符串记录。
- 指针族（12 / 13 / 14）的槽装地址；**取址**原语三个都接受。读 / 写只在「支持集合与不支持的组合」里接受：12 读、写都可；13 可读、只可写浮；14 只有取址。被接受时，读 / 写都要经过一次解引用；指针槽本身不解码，解码发生在解引用出来的目标上。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 局部整型变量 i 的值 | `operand(type 9, i)` → 当前帧整型池第 i 槽 → 解码 |
| 局部浮点变量 i 的值 | `operand(type 10, i)` → 当前帧浮点池第 i 槽 |
| 局部字符串变量 i | `operand(type 11, i)` → 当前帧字符串池第 i 条记录 |
| 局部指针 i 指向的整数值 | `operand(type 12, i)` → 取槽（地址）→ 解引用 → 解码 |

**成立条件**

- 局部池按当前帧选择；跨帧访问不在本版范围。
- 整型族的初值是编码后的零。
- 字符串记录的**字段布局与容量字段的宽度**不是本规范的内容；**记录宽度 28 字节**与内联阈值 16 是合同（见「字符串记录」「数组地址算术」）。

### 支持集合与不支持的组合

<!-- rule: SPC-OPERAND-UNSUPPORTED-THROW -->

每个原语只接受一部分类型标签。**接受** = 不抛异常（不等于本版规定了它的值语义）：

| 原语 | 接受（不抛） | 明确不支持（抛） |
|---|---|---|
| 取址 | 3–14；`0x8003` / `0x8005` / `0x8009` / `0x800B` | 0–2；其余句柄与 15 以上 |
| 读整型 | 0–7、9–13；`0x8003`；`0x8009` | 8、14；`0x8005`；`0x800B`；其余 |
| 读浮点 | 0–7、9–13；`0x8003`；`0x8009` | 8、14；`0x8005`；`0x800B`；其余 |
| 写整型 | 3、4、6、7、9、10、12；`0x8003`；`0x8009` | 0–2、5、8、11、13、14；`0x8005`；`0x800B`；其余 |
| 写浮点 | 3、4、6、7、9、10、12、13；`0x8003`；`0x8009` | 0–2、5、8、11、14；`0x8005`；`0x800B`；其余 |

- **0–2**（立即值 / 浮点立即值 / 内联字符串）只被**读**原语接受；它们的**值语义**见「立即值与内联字符串」，本表只登记"哪个原语接受它"。
- **句柄**：`0x8003` 与 `0x8009` 被五个原语全部接受；`0x8005` / `0x800B` 只在**取址**里被接受，四个值原语对它们抛异常。

不支持的组合**必须响亮地失败**：引擎抛出一个"操作数类型异常"。它不是返回 0，也不是静默跳过；实现不得替引擎编一个值。

**成立条件**

- "不支持"是规范的可观察行为（抛异常），不是本项目的实现选择。
- 句柄的**语义**见「容器句柄：类型标签 0x8003 / 0x8009」与「字符串容器句柄：类型标签 0x8005 / 0x800B」；本表只规定"哪个原语接受它"。
- 句柄由独立分支处理，不经过上面五张分派表的 case。

### 容器句柄：类型标签 0x8003 / 0x8009

<!-- rule: CORE-POOL-HANDLE-INT -->

`0x8003`（全局）与 `0x8009`（局部）是**整型池的容器句柄**：池槽里装的是一个**容器对象指针**（与整型值一样编码存放），不是值本身。

- **取址**：解码槽得到容器指针；解码后的槽值为 0（尚未登记容器）时**懒分配**一个容器对象（初始化为空容器），把"编码后的指针"写回槽，并把这个槽号登记进一张引擎级注册表；返回容器指针。
- **读**（两个读原语）：解码槽得到容器；元素个数 = （尾指针 − 头指针）/ 4；**个数为 0 或解码后的槽值为 0 时返回 0**（读浮返回 0.0）；否则返回**第一个元素**（整型元素要再解码）。
- **写**（两个写原语）：解码后为 0 时同样懒分配；元素个数为 0 ⇒ **追加**一个元素；不为 0 ⇒ **覆写第一个元素**。写原语没有元素下标参数，写路径因此不比较元素下标；覆写分支上有一个"元素个数为 0"的检查（由头尾指针差算出个数），但进入该分支的前提就是个数非 0，所以没有可观察的越界异常。
- `0x8005` / `0x800B` 在这个机制里不存在：四个读写原语对它们都是类型异常。

**成立条件**

- “容器”在这里是可观察的最小结构：头指针 + 尾指针（元素为 32 位整数）与**容量**。
- 元素的值按整数编码存放（写要编码，读要解码）。
- 读 / 写只在"第一个元素"上工作：**这两个访问原语没有元素下标参数**。按索引访问容器另有一条路径（`0x32f`，见「转发型指令」的「把索引交给容器入口」）；它作用的是不是**这里**这个容器对象，本版未取证，不作断言。
- **两种下标不是一回事**：池下标不做上界检查（越界是未定义行为）；容器元素**没有可写的下标**——写原语只作用于第一个元素（容器为空则追加），因此容器内不存在可观察的元素下标检查。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| `0x8003` 的容器 | 全局整型池第 i 槽 → 解码 → 容器对象 |
| `0x8009` 的容器 | 当前帧整型池第 i 槽 → 解码 → 容器对象 |
| 容器注册表 | 引擎级的容器表（登记的是池槽号） |

### 字符串容器句柄：类型标签 0x8005 / 0x800B

<!-- rule: CORE-POOL-HANDLE-STRING -->

`0x8005`（全局）/ `0x800B`（局部）是**字符串池的容器句柄**：容器指针以**十进制文本**存在字符串记录里。

- **取址**（唯一有定义的原语）：若记录的长度字段（已用字节数，见「字符串记录」）为 0（空串）⇒ 分配一个容器对象，把它的指针用十进制文本写进这条记录（走记录级文本写入路径）；然后按内联 / 间接判别取出文本，**按十进制解析成整数**，这个整数就是"容器地址"。
- 两个读原语与两个写原语对 `0x8005` / `0x800B` 都是**类型异常**。

**成立条件**

- 这条机制的"地址"是**文本**：任何能改写该字符串槽的路径都会改变句柄（这是可观察的耦合，规范必须说清）。
- 容器对象本身的语义见「容器句柄：类型标签 0x8003 / 0x8009」。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| `0x8005` 的容器指针 | 全局字符串池第 i 条记录的文本 → 十进制解析 |
| `0x800B` 的容器指针 | 当前帧字符串池第 i 条记录的文本 → 十进制解析 |

### 整数值的编码

<!-- rule: SPC-VALUE-INT-ENCODED -->

整型族（全局整型池、局部整型池，以及引用族解引用后得到的整数）在内存里不是原值，而是**编码后的位模式**。

设 `key` 是引擎的运行期状态（见下）。`rol32` / `ror32` 是 32 位循环左移 / 循环右移。对 32 位值：

- **解码**：`DEC(x) = ror32(rol32(x, 11) XOR key, 25)`
- **编码**：`ENC(v) = rol32(ror32(v, 7) XOR key, 21)`

两者互为逆运算。读整型原语在取出位模式后做一次解码；写整型原语在写入前做一次编码。

`key` 由引擎在**实例初始化时生成一次**（在首次填充或访问任何整型池之前），每个引擎实例一份，生成时保证非 0；此后直到进程结束不再改变，池的所有读写路径都读同一个值。它是引擎内部状态，正常运行下不来自脚本、配置、玩家文件或宿主启动参数；实现不得要求使用者提供它，也不得为它设置任何默认定值（0 与非 0 固定值都不行）。未注入时必须现场生成。

为可复现的位模式对照，测试设施可以注入一个显式非 0 值；该注入不属于引擎输入面，正常运行路径不得读取它。

整型池的初值是 `ENC(0)`（即"编码后的零"），不是位模式 0。因此"未初始化 = 0"是错的；只是解码后看起来是 0。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 整型池里的原值 | `DEC(槽中的位模式, key)` |
| 写进整型池的位模式 | `ENC(原值, key)` |

**成立条件**

- 本规则覆盖所有读写整型值的路径，包括引用族解引用之后。
- 浮点族、字符串记录与指针槽本身不走这条。

### 浮点值的表示与跨族转换

<!-- rule: CORE-POOL-FLOAT-VALUE -->

浮点族（全局浮点池、局部浮点池，以及浮点引用 / 浮点指针解引用之后）的槽里直接装 32 位 IEEE-754 浮点数，**不过编解码**。读浮得到该数（读原语返回 64 位浮点，值相同）；写浮直接写入。

跨族时按下面的口径转换（都是**引擎自己**的行为，不是实现的自由）：

- **整数 → 浮点**：有符号整数转 32 位浮点（写整型到浮点族）。
- **浮点 → 整数**：**向零截断**（写浮点到整型族、读整型从浮点族、读整型从立即浮点都是这条）。
- **整型族 → 浮点**：先解码，再把有符号整数转浮点（读浮从整型池、从整型引用）。

**适用条件**

- 截断不是四舍五入，也不是"饱和"；超出整数范围的值不属于本版范围。
- 32 位浮点的逐位表示（NaN / 非规格化数）不进本规范正文（属平台 / 硬件行为）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 浮点池第 i 个值 | 浮点族槽里的 32 位浮点 |
| 跨族读写的值 | 先按上表转换，再按目标族编码（若目标是整型） |

### 字符串记录

<!-- rule: SPC-POOL-STRING-SSO -->

全局字符串池与局部字符串池的每一槽是一条**定长字符串记录**；一条记录在池里的**步长是 28 字节**（本版规定的元素宽度；池下标与配置键换算都用它。记录内部字段的布局不在本版）。
记录里有两个必须区分的字段：**容量**（数据区能容纳的字节数）与**长度**（已用字节数，不含结尾 NUL）。读取与写入都把容量与内联阈值 **16** 比较（16 是**本版规定的常量**，不是从记录字段派生的）：

- 容量小于 **16** 时，字符串字节内联在记录自己的缓冲区里；
- 否则，记录里放一个指针，文本在指针指向处。

取址原语返回这条记录的地址。读值原语按**目标语义**解释记录中的文本：

- 读整型：按十进制文本解析成整数（C 语言 `atoi` 的语义）；
- 读浮点：按十进制文本解析成浮点数（C 语言 `atof` 的语义）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 第 i 条字符串记录 | 字符串池的第 i 槽 |
| 字符串作为整数被读取 | 按容量字段判内联/间接得到文本 → `atoi` |
| 字符串作为浮点数被读取 | 同上 → `atof` |

**成立条件**

- 记录的**字段的存储布局与容量字段的宽度**不是本规范的内容；**记录宽度 28 字节**与内联阈值 16 是合同（见「数组地址算术」与上文）；本规范另外只规定容量 / 长度两个字段的用途、"容量与阈值比较、内联/间接判别、按文本解析"。
- 字符串族的写原语不走类型标签 5 / 11（见「支持集合与不支持的组合」）；字符串记录的文本写入走另一条记录级路径（见「字符串记录的写入」），那条路径不经过操作数类型标签。
- 整型读 / 浮点读是把字符串当**十进制文本**解析，不是把记录里的字节当数。

### 字符串记录的写入

<!-- rule: CORE-POOL-STRING-WRITE -->

引擎有一个**记录级写入原语**：给定"记录地址 + 源字节 + 长度"，它：

1. 读记录的容量字段；容量够就原地写，不够就**扩容**（新容量由引擎选；旧文本是否保留由扩容实现决定）；
2. 把源字节拷进数据区（内联区或堆上，按容量与阈值决定）；
3. 更新长度字段，并在文本末尾写 NUL。

源与本记录的缓冲区**重叠**时走另一条路径（先按重叠量调整再搬），不是直接拷贝。

**适用条件**

- 这条是**文本层**的写入，不经过操作数类型标签（标签 5 / 11 的写仍是类型异常）。
- 长度是**字节数**，不是字符数。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 一条字符串记录被赋新文本 | 记录级写入原语（记录, 源, 长度） |
| 文本变长超过内联阈值 | 容量比较失败 → 扩容 → 数据区换成堆指针 |

### 容量与分配

<!-- rule: SPC-POOL-CAPACITY-AND-UB -->

池的容量在**装载时**确定，是运行期状态：**全局池在启动期**（初始化文件装载时）、**局部池在脚本装载时**分配。本规范不把任何容量写成常量。

- **全局池**：**6 个计数槽**由**启动期**从引擎初始化文件的头部读入（初始化文件是启动时装载的元数据文件，**不是脚本头**；与脚本头里决定局部池的六个整数不是同一份）。**只有第 1 个已确证**；其余 5 个各对应哪个池，**本版不规定**（原因：没有逐条取证）。每个池按"对应的计数 + 一个**随机余量** + 1"分配，此后不随脚本装载变化。
- **局部池**：每帧 **6 个计数槽**（脚本头的 6 个整数搬进帧记录，见「脚本与执行」的「固定区」）；**只有第 1 个已确证**是局部整型池的计数，其余 5 个与其余 5 个局部池的对应关系**本版不规定**（原因：没有逐条取证）。每个局部池按"该帧对应的计数 + 1"分配；基址写进帧记录。
- 整型族分配后**逐格**填"编码后的零"；其它族不保证初值，本规范不假设未写过的槽读出来是什么。

**成立条件**

- "随机余量"是**内存分配行为**，不是语义容量：它既不扩大可寻址的合法下标，也不改变"越界是未定义"（见「下标不做上界检查」）。
- 容量与计数在装载时确定；本规范只声明口径，不复述具体数值。
- 全局池的"两份缓冲"是另一条规则（见「全局池的两份缓冲与翻页」）：它改的是**选择**，不改容量。

### 全局池的两份缓冲与翻页（opcode 0x6d）

<!-- rule: SPC-POOL-MEMFLIP -->

六个全局池族（整型、浮点、字符串、整型引用、浮点引用、字符串引用）各有一组**缓冲**。运行期的访问（取址、读、写）落在**当前选中的那一组**上。

- **组数由配置决定**：引擎在启动期（装载初始化文件、分配全局池时）查一次配置命名键 `set:EnableMemFlip`（「内存翻页」，整数键）。该键缺失或为 0 ⇒ 每个族只有**一组**缓冲；非 0 ⇒ 每个族**两组**：一组主缓冲、一组备用缓冲。两组各自独立分配、各自带自己的分配余量；两组按同一套初值口径填充（整型族逐格写"编码后的零"，其余族按各自的分配方式）。
- **翻页指令 `0x6d`**（无操作数）把六个族的主 / 备选择**整体对调**：
  - 执行时同一个配置键为 0 或缺失 ⇒ 抛**显示消息型异常**（消息「memflipは現在使用不可になっています．」），六个选择**不变**；
  - 非 0 ⇒ 对调。对调**只改选择**：不搬动数据、不重新分配、不改变任何计数、不改变元素宽度。
- **判定的先后**：本条先把推进格数写成 1，**然后**才查配置 ⇒ 异常路径上推进格数已经是 1（与"直进指令"的 `2 × 0 + 1` 数值相同，但写入**先于**读键，所以异常时它已是定值）。
- **初始选择**：在任何 `0x6d` 之前，六个族都选**主缓冲**；`0x6d` 执行一次后选备用组，两次后回到主组。
- **两份缓冲互不影响**：写进主缓冲某个槽的值，在翻页之后读不到（读到的是备用缓冲在同一位置的值 —— 整型族是分配时填的编码零、其余族未定义，或更早写进那一组的值）；翻页两次回到原选择，原先写下的值仍在。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个族当前用哪一组缓冲 | 该族的一个"当前组"状态量（主 / 备二选一） |
| 某个池某个下标的值 | **当前选中那一组**里该槽的内容 |
| 翻页 | 六个"当前组"状态量**同时**翻转 |
| 备用缓冲是否存在 | 启动期由配置键决定（缺失或 0 ⇒ 不存在） |

**成立条件**

- 翻页**不改变**池下标空间、容量口径与元素宽度：六个族的计数与元素宽度都不随翻页变化（见「容量与分配」「数组地址算术」）。
- 两组的地址都是运行期状态，本规范不写数值，也不规定两组的先后 / 相对位置。
- 配置键为 0 或缺失时**备用缓冲不存在**（不是"存在但为空"）：此后任何翻页尝试都在查键之后**立刻抛异常**，所以在同一次运行且该键未被改写的期间，「翻到一组不存在的缓冲」**不可达**。
- 这个异常是**显示消息型**（与「装载帧」「换帧」的报错同类），不是静默跳过、不是返回 0。
- ★ **同一个键被读两次、时机不同**：一次在启动期（决定分配几组），一次在翻页指令执行时（决定放不放行）。若该键在两者之间被改写，就会出现"指令认为可用、而备用缓冲从未分配"的状态 —— 本版把这种状态归为**未定义行为**（成因是配置在运行期被改写，属程序侧行为）；实现不得用"翻页时再补分配"来掩盖它。
- 本条**不规定**发行数据到底把该配置键置成什么（那是游戏数据，不是引擎合同）；两条分支都是可实现的合同。
- **本作发行数据的事实**（不是引擎合同）：索引尾部的默认表把该键**显式**置为 `0` ⇒ 本作的每个族只有一组缓冲，翻页指令在发行数据下**恒走"不可用"的异常支**。替换发行数据（置非 0）后引擎按本条的"非 0"分支走 —— 两种都在合同内。

**可证伪**

1. 若在一次运行里翻页之后仍能读到翻页前写进池的槽值（同族同下标），且不存在"只有一组缓冲"的其它解释 ⇒ 本条错（"两份独立缓冲 + 只换选择"不成立）。
2. 若配置键为 0 时执行翻页指令**没有**抛异常、而是静默不动作（或反而换了选择）⇒ 本条错。
3. 若翻页之后容量 / 越界判据发生变化（同一个越界下标在翻页前 UB、翻页后"合法"）⇒ 本条错。

### 数组地址算术

<!-- rule: CORE-POOL-ADDRESS-ARITH -->

池里一个**元素**的地址由一条算术关系给出：**地址 = 池基址 + 元素宽度 × 下标**。

元素宽度按族的类别固定：

| 族的类别 | 族 | 元素宽度 |
|---|---|---|
| 值族 | 整型 / 浮点 | 4 字节 |
| 值族 | 字符串 | 28 字节（字符串记录的步长） |
| 引用族 | 整型引用 / 浮点引用 / 字符串引用 | 4 字节（槽里装一个地址） |
| 引用族 | 指针 / 浮点指针 / 字符串指针 | 4 字节（槽里装一个地址） |

**指针槽不编解码**：引用族与指针族的槽只存一个地址 —— 读它得到地址，写它写入地址；编解码只发生在解引用之后的目标槽（见「整数值的编码」）。

同一条地址关系可以用三种方式观察，规范只保证这三种：

- **取址—解引用往返**：对同一个元素取址，再按得到的地址访问，仍是同一格；
- **地址差**：同一族内两个下标算出的地址之差 = 下标之差 × 元素宽度；
- **配置键换算**：引用槽里的地址减去**它所指向的值族**的全局池基址、再除以**该值族**的元素宽度（整型 4 / 字符串 28），得到该值族的槽下标（见「配置」的「脚本访问」）。

**地址的数值本身不规定。** 基址取什么值、池在地址空间里谁先谁后、窗口怎样排布，都是**实现选择**。实现不得让绝对地址以别的方式变成可观察的语义：例如把两个无关指针的大小比较、或把地址当整数打印出来，都不构成本规范规定的行为。

**越界与未对齐是未定义行为。** 下标越出池的实际容量、或地址不在该族元素的边界上时，本规范不规定结果；实现可以记诊断或**响亮失败**，但 ⛔ 不许 clamp 到池内、也不许补 0 后继续。配置键换算的输入不落在它所指向的值族的全局池内时同样是未定义行为（见「配置」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 第 i 个元素的地址 | 池基址 + 元素宽度 × i |
| 引用 / 指针槽里存的东西 | 一个地址（不再编解码） |

**成立条件**

- 元素宽度是**族的属性**，不是调用点的选择：同一个下标在不同族的池里指向不同宽度的元素。
- 引用 / 指针族的槽宽是 4 字节；槽里的地址指向**目标值族**的元素，那一侧的地址关系用同一个式子、按目标族的基址与元素宽度换算。
- 字符串族的 28 字节是**记录步长**；记录内部字段的布局不在本版（见「字符串记录」）。
- 池基址是运行期状态（见「容量与分配」），本规范不把它写成常量。
- 本条与「下标不做上界检查」互补：本条给出关系，那条说明引擎不检查这个关系的输入。

### 下标不做上界检查

<!-- rule: CORE-POOL-INDEX-UNCHECKED -->

池的下标访问**没有边界检查**：五个访问原语的函数体里不出现任何池计数槽，地址由"基址 + 下标 × 元素宽"直接算出。

- 越界访问是**未定义行为**，不是可复刻的语义；实现必须把它记成诊断，而不是替引擎 clamp 或补 0。
- 这条**只针对池**：引擎标量表（见「引擎级状态」）有自己的检查，不要把两者混起来。
- "未初始化 ≠ 0"：整型族初值是编码后的零；其它族按各自的分配方式，本规范不假设。

**成立条件**

- 判据是机械的：五个原语的实现里**从不读池的计数槽**（计数只在装载期用于分配）。
- 本版**没有**任何一次真机越界观测；这条结论只来自代码结构。

### 容器句柄的四个类型标签

<!-- rule: CORE-CONTAINERS-HANDLE-TAGS -->

操作数类型标签 `0x8003` / `0x8009` / `0x8005` / `0x800B` 是**容器句柄**：

| 标签 | 池 | 容器种类 |
|---|---|---|
| `0x8003` | 全局整型池 | 整型容器 |
| `0x8009` | 当前帧的局部整型池 | 整型容器 |
| `0x8005` | 全局字符串池 | 字符串容器 |
| `0x800B` | 当前帧的局部字符串池 | 字符串容器 |

- 句柄标签的低字节就是它所解释的**值族标签**（`0x8003`↔3、`0x8009`↔9、`0x8005`↔5、`0x800B`↔11）。raw 仍是该值族池的下标；句柄**不引入新的下标空间**。
- 五个访问原语对句柄的接受集：**取址**接受全部四个；**读整型 / 读浮点 / 写整型 / 写浮点**只接受 `0x8003` 与 `0x8009`，对 `0x8005` / `0x800B` 抛类型异常。
- 分派顺序：标签小于 `0x8003` 走跳转表（池族 3–14）；等于 `0x8003` 走 `0x8003` 专支。大于 `0x8003` 时两种形态：
  - **取址**依次比较 `0x8005` / `0x8009` / `0x800B`，其余值（含 `0x8004`、`0x8006`–`0x8008`、`0x800A`、`0x800C` 及以上）落缺省并抛类型异常；
  - **四个值原语**只比较 `0x8009`；`0x8005` / `0x800B` 与其余大于 `0x8003` 的值一起落缺省（所以它们对这两个标签抛异常）。
- 浮点族（4 / 10）与引用 / 指针族（6–8、12–14）**没有**句柄标签。

**成立条件**

- 同一 raw 指向同一个池槽；值族访问与句柄访问是**同一存储的两种解释**，不是两份存储。
- 句柄标签只在操作数原语内被解释；哪些脚本 / 指令使用句柄属于程序（游戏数据）。
- 类型异常那条（缺省分支）由「支持集合与不支持的组合」规定，本条只声明句柄标签落在哪个分支，不重复规定异常。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| `0x8003` / `0x8009` 的容器引用 | 对应整型池第 raw 槽里的编码值；解码后是容器引用 |
| `0x8005` / `0x800B` 的容器引用 | 对应字符串池第 raw 条记录的文本；按十进制解析后是容器引用 |
| 标签属于句柄 | 原语入口在跳转表之外给出的专支 |

### 容器句柄的懒分配与登记

<!-- rule: CORE-CONTAINERS-LAZY-ALLOC -->

- **空句柄**：整型句柄在槽解码为 0 时为空；字符串句柄在记录的长度（已用字节数）为 0 时为空。
- **创建点（五个访问原语内）**：取址、写整型、写浮点。两个读原语**从不创建**。另有一条字符串赋值路径也会创建字符串容器（归文本系统，见残差）；这不改变"读原语从不创建"。
- **创建**：分配一个空容器（元素区首 = 元素区末 = 0、容量 = 0）；整型句柄把容器引用按整型编码写回槽；字符串句柄把容器引用写成十进制文本，经记录级文本写入写进记录，记录长度变为该文本的长度。
- **登记**：创建后，把一条 **（池槽号，容器引用）** 追加到该句柄的登记表。全局句柄的登记表属于引擎；局部句柄的登记表属于当前帧。登记**只发生在创建时**。
- **登记表不参与访问**：五个原语取容器时只看槽里的值或文本，不查登记表，也不做"是否已登记"的校验。
- **重复登记**：同一槽被重新置空后再次作为句柄访问（整型：用值族写入整数 0；字符串：记录长度变为 0），会再创建一个容器并追加一条新登记。没有去重、没有冲突检查、没有"已有容器就复用"的查找 —— 创建的前提就是槽为空。
- **生命周期**：容器创建后一直存活到引擎拆卸 / 帧拆卸；登记表按创建顺序增长，没有数量上限、没有淘汰。拆卸时逐条释放容器及其元素区，然后清空登记表。
- **可见性**：字符串句柄的十进制文本就是容器引用本身（脚本可见、可复制、可改写）；整型句柄的引用按整型编码存放 ⇒ 用**同一槽的值族**读会解码出该引用（脚本可见、可作为整数复制），用值族写会把它改成任意整数（见「容器句柄的失败路径」）。两种句柄的引用都不是"引擎私有、脚本碰不到"的。
- **覆盖不释放**：用值族写入覆盖一个仍被登记的句柄槽，不会释放原容器；该容器仍在登记表里可达，直到拆卸才释放。之后再以句柄访问该槽时，槽里的新值被当作容器引用（见「容器句柄的失败路径」）。

**成立条件**

- 容器引用的数值本身不规定（地址是运行期状态）。
- 登记表的元素是"槽号 + 引用"，不是元素级索引；登记不改变容器内容。
- 登记表的容量增长策略是实现细节，本规范不规定；只规定"只增不减、无上限、拆卸时清空"。
- 局部句柄的登记表随当前帧选择：每个帧各一份，跨帧不共享。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| `0x8003` / `0x8009` 的容器引用 | 对应整型池槽里编码后的容器引用 |
| `0x8005` / `0x800B` 的容器引用 | 对应字符串记录文本十进制解析出的整数 |
| 已创建容器 | 登记表里一条（池槽号，容器引用） |
| 容器的空 / 满 | 元素区首 / 元素区末 / 容量三个状态量（布局属机器细节） |

### 容器句柄的失败路径

<!-- rule: CORE-CONTAINERS-FAILURE -->

本条规定**句柄路径自己的**失败行为。类型标签不在支持集时抛类型异常那条属于「支持集合与不支持的组合」，本条不重复。

- **空读不是失败**：槽为空或容器为空时，读返回 0（读浮点 0.0）。
- **引用不校验**：整型句柄只要槽解码非 0 就当作容器引用解引用；不检查它是否由引擎创建、是否在登记表里、是否对齐。把普通整数写进句柄槽后再当句柄用是**未定义行为**。
- **字符串句柄的文本不校验**：文本按十进制解析（与字符串记录的整数读同一口径）；非数字文本得 0，不报错、不重建。文本长度非 0 就不会触发创建。文本可被脚本改写 ⇒ 句柄可被伪造 / 别名化；登记表里仍记着创建时的引用，两者可以不一致。
- **分配失败（防御分支）**：若容器分配返回空引用，创建路径仍会把"空引用"写回槽（整型：编码后的 0；字符串：文本 `"0"`），并登记该槽，然后取址返回空引用。写原语随后把空引用当容器解引用（未定义行为）；读原语返回 0。**没有**在分配失败时抛异常。分配器在正常语义下是否可返回空，本版未观察。
- **没有结构校验**：首 / 末指针被外部改写时，元素个数与元素地址照算；没有"容器已损坏"的检查。

**成立条件**

- 失败路径的可观察性受"分配器是否返回空"限制；本版只有代码结构证据，没有真机观测。
- 非数字文本按 C 的十进制解析口径（前导空白 / 符号 / 前缀数字），不额外校验、不报错。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 句柄槽里的"引用"实际不是容器 | 该值被直接当容器解引用（未定义行为） |
| 字符串句柄文本不是数字 | 解析结果为 0，不触发创建 |
| 分配返回空 | 槽写回"空引用"、仍登记、取址返回空 |

### 容器句柄的元素

<!-- rule: CORE-CONTAINERS-ELEMENT -->

- **整型容器**：元素是 32 位整数，按整型编码存放；元素步长 4 字节；元素个数 =（元素区末 − 元素区首）/ 4；第 i 个元素的地址 = 元素区首 + 4 × i。
- **读**（读整型 / 读浮点）：若槽为空或元素个数为 0，返回 0（读浮点返回 0.0）；否则返回**第 0 个元素**（读整型要先解码；读浮点先解码再转成浮点）。
- **写**（写整型 / 写浮点）：若槽为空，先创建（见「容器句柄的懒分配与登记」）；元素个数为 0 时在元素区末**追加**一个元素；个数非 0 时**覆写第 0 个元素**。写入值先变成整数（写浮点的值按跨族转换**向零截断**），再编码成整型位模式。
- 五个访问原语**没有元素下标参数** ⇒ 本机制里不存在可表达的元素越界。写路径里那条"个数为 0 就抛越界"的检查在进入该分支时元素个数必非 0，因此**不可达**，不构成可观察异常。（池下标越界仍按「下标不做上界检查」为未定义行为，那是另一条。）
- 容器**没有“当前元素”游标**：容器只有元素区首 / 元素区末 / 容量三个状态量（布局属机器细节；与「容器句柄：类型标签 0x8003 / 0x8009」的“头 / 尾 / 容量”同义）；读写的“第一个”就是元素区首那个。
- **字符串容器**：元素是字符串记录，步长 28 字节；元素个数 =（元素区末 − 元素区首）/ 28。五个访问原语**不寻址**字符串容器的元素（只能取址）；元素级写入由字符串赋值路径完成（该路径也会创建 / 登记字符串容器；归文本系统，见残差）。
- 本版没有发现一条属于本机制的“按任意下标访问容器元素”的入口；`0x32f` 的接收者容器是不是同一个对象未取证，不合并。

**成立条件**

- 元素宽度是容器种类的属性（整型 4 字节 / 字符串 28 字节），不是调用点选择。
- 容器容量是运行期状态，本规范不写成常量。
- 空元素区时读写都走"返回 0 / 追加"；没有"读到未初始化元素"的可观察路径（个数由首末差算出）。
- 字符串记录的字段布局不是本条内容；28 字节是记录步长（合同见「字符串记录」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 整型容器第 i 个元素 | 元素区首 + 4 × i 处的编码整数 |
| 字符串容器第 i 个元素 | 元素区首 + 28 × i 处的字符串记录 |
| 元素个数 | （元素区末 − 元素区首）/ 元素宽度 |

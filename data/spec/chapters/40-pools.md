## 数据池

**池**是一组可按整数下标访问的**槽**。引擎有两类池：

- **全局池**：属于引擎，跨脚本存在；
- **局部池**：属于**当前帧**，随帧切换。

本规范把数据池作为一个完整主题：**族、下标、访问原语、值表示、容量**都在本章。脚本怎样编码操作数见「脚本与执行」；`type` / `raw` 的字节布局属于脚本二进制协议，本章只规定它们的运行期含义。

### 操作数类型标签

操作数由**类型标签**与 **raw** 组成。类型标签决定访问哪个池、按哪种值语义解释；raw 是下标或立即值。

| 标签 | 含义 | 本版规定 |
|---|---|---|
| 0 | 立即值 | 是（见「立即值与内联字符串」） |
| 1 | 浮点立即值 | 是（见「立即值与内联字符串」） |
| 2 | 内联字符串 | 是（见「立即值与内联字符串」） |
| 3–8 | 全局池族（见下表） | 是 |
| 9–14 | 局部池族（见下表） | 是 |
| 0x8003 / 0x8005 / 0x8009 / 0x800B | 容器句柄 | 否（只登记存在） |

"本版不规定"意味着：实现者知道这些标签存在，但本版不对其读值 / 写值语义作任何断言；它们不属于支持集合规则。

每个池有一个**族**。族的名字同时描述槽里装什么、以及读写时如何解释：

| 族的类别 | 族 | 槽里装什么 |
|---|---|---|
| 值族 | 整型 | 一个整数值（以编码位模式存储，见「整数值的编码」） |
| 值族 | 浮点 | 一个 32 位浮点数 |
| 值族 | 字符串 | 一条定长字符串记录（见「字符串记录」） |
| 引用族 | 整型引用 / 浮点引用 / 字符串引用 | 一个**地址**；目标是相应值族的槽或记录 |
| 引用族 | 指针 / 浮点指针 / 字符串指针 | 一个**地址**；目标是相应值族的槽或记录 |

全局池与局部池各有一套族。类型标签与池族一一对应：

| 类型标签 | 池 | 族 | 类别 |
|---|---|---|---|
| 3 | 全局 | 整型 | 值族 |
| 4 | 全局 | 浮点 | 值族 |
| 5 | 全局 | 字符串 | 值族 |
| 6 | 全局 | 整型引用 | 引用族 |
| 7 | 全局 | 浮点引用 | 引用族 |
| 8 | 全局 | 字符串引用 | 引用族 |
| 9 | 局部 | 整型 | 值族 |
| 10 | 局部 | 浮点 | 值族 |
| 11 | 局部 | 字符串 | 值族 |
| 12 | 局部 | 指针 | 引用族 |
| 13 | 局部 | 浮点指针 | 引用族 |
| 14 | 局部 | 字符串指针 | 引用族 |

**下标**由操作数的 raw 给出。raw 是下标，不是值；下标本身不过任何编解码。

池的**容量**是运行期状态：它在脚本装载时确定，本规范不把它写成常量。引擎对下标访问**没有边界检查**。

### 五种访问原语

| 原语 | 用途 | 结果 |
|---|---|---|
| 取址 | 只需要地址时 | 返回槽 / 记录的地址 |
| 读整型 | 按整型语义取值 | 32 位整数 |
| 读浮点 | 按浮点语义取值 | 32 位浮点数 |
| 写整型 | 把整型语义的值写回 | 无 |
| 写浮点 | 把浮点语义的值写回 | 无 |

同一类型标签在不同原语下可能有不同结果。例如字符串族在"读整型"时按十进制文本解析成整数，在"读浮点"时按十进制文本解析成浮点数（见「字符串记录」）。原语的选择由消费该操作数的指令决定。

### 五种访问原语的入口契约

<!-- rule: CORE-POOL-PRIMITIVE-ENTRY -->

五种访问原语是**取址、读整型、读浮点、写整型、写浮点**。每次调用给两件事：**这是第几个操作数**（从 1 开始数）与（写原语）**要写的值**。取址返回一个地址；读整型返回 32 位整数；读浮点返回 64 位浮点；写原语没有返回值。

原语**不消费操作数以外的指令状态**：同一个操作数、同一个池状态，结果只由类型标签与 raw 决定。

原语每次调用还把"当前操作数在指令里的地址"写进一个引擎级槽（每个原语一个），同一个原语后续会从那个槽里回读 raw。

**适用条件**

- 操作数序号是**第几个**，不是字节偏移；一条指令里第一个操作数的序号是 1。
- 原语只在"已经知道类型标签"的前提下被调用；标签分派在函数入口自己做（见「类型标签的分派结构」）。
- 写原语的"要写的值"是 32 位整数或 32 位浮点；跨族写入要先转换（见「浮点值的表示与跨族转换」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 一条指令的第 k 个操作数 | 操作数记录数组的第 k−1 项（每项 8 字节） |
| 当前操作数地址缓存 | 每个原语一个引擎级槽（五个各一） |

### 类型标签的分派结构

<!-- rule: CORE-POOL-TAG-DISPATCH -->

原语按类型标签三分：

1. **标签小于 0x8003**：与一个小上界比较后直接查跳转表。不同原语有不同**表规模**与**起点**：
   取址从 3 起（12 项 ⇒ 3..14）、读整 / 读浮从 0 起（14 项 ⇒ 0..13）、写整从 3 起（10 项 ⇒ 3..12）、
   写浮从 3 起（11 项 ⇒ 3..13）。**表里缺席的标签与超出上界的标签走 default**。
2. **标签等于 0x8003**：独立分支（容器句柄，见「容器句柄」）。
3. **标签大于 0x8003**：再按具体值分：取址接受 `0x8005` / `0x8009` / `0x800B`；四个读写原语在 `0x8003` 之后只接受 `0x8009`；其余一律 default。

default 的行为是**抛**（类型异常）；"抛"是规范的可观察行为，不是实现选择。

**适用条件**

- 五张表的规模互不相等（12 / 14 / 14 / 10 / 11），⛔ 不许用"一张表"代表全部。
- 标签 0 / 1 / 2 不在取址与两个写原语的表里 ⇒ 它们在那三个原语里是 default（见「立即值与内联字符串」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 标签是否被某原语支持 | 该原语的分派结构是否给这个标签一个非 default 的目标 |

### 立即值与内联字符串：类型标签 0 / 1 / 2

<!-- rule: CORE-POOL-TAG-IMMEDIATE -->

这三个标签只在两个**读**原语里有语义；取址与两个写原语对它们是类型异常。它们**不碰任何池**：没有下标，也没有编解码。

- **0**：raw 就是值本身。读整得到 raw；读浮把 raw 当**有符号**整数再转成浮点。
- **1**：raw 的**位模式**就是一个 32 位 IEEE-754 浮点。读浮原样取出；读整把它**截断**成整数（向零）。
- **2**：raw 是一个**文本偏移**：文本在脚本缓冲里的第 raw 个 32 位字处。读整把文本按十进制解析成整数，读浮解析成浮点；文本**没有长度前缀**，以 NUL 结束。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 立即整数 / 立即浮点的值 | 操作数记录里的 raw 字（不落到任何池） |
| 内联文本 | 脚本缓冲偏移 `4 × raw` 处的字节序列 |

**成立条件**

- 三个标签只在"读"方向有定义；对它们取址或写入是类型异常（见「支持集合与不支持的组合」）。
- 标签 1 的读整是**截断**，不是四舍五入。
- 标签 2 的文本解析与字符串记录的文本解析是同一口径。

### 全局值族：类型标签 3 / 4 / 5

<!-- rule: SPC-POOL-GLOBAL-VALUE-FAMILIES -->

操作数类型标签 3 / 4 / 5 分别选择全局整型池、全局浮点池、全局字符串池。raw 是池内下标；取址结果是该槽（字符串族为该记录）的地址。

- 整型池的槽装**编码后的整数位模式**（见「整数值的编码」）；整型池的初值是**编码后的 0**。
- 浮点池的槽装 32 位浮点数；浮点不过编解码。
- 字符串池的一槽是一条定长字符串记录（见「字符串记录」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 全局整型池第 i 个值 | `operand(type 3, index i)` 经读整型原语解码后的整数 |
| 全局浮点池第 i 个值 | `operand(type 4, index i)` 经读浮点原语得到的 32 位浮点数 |
| 全局字符串池第 i 个字符串 | `operand(type 5, index i)` 指向的字符串记录 |

**成立条件**

- raw 是池内下标，不是值；下标不参与整型编解码。
- 池容量是运行期状态，本规范不假设上界（见「容量与越界」）。
- 写整型 / 写浮点原语不接受类型标签 5（字符串族），见「不支持的组合」。

### 全局引用族：类型标签 6 / 7 / 8

<!-- rule: SPC-POOL-GLOBAL-REF-FAMILIES -->

类型标签 6 / 7 / 8 是全局池的**引用族**：槽里装的是一个地址，不是值本身。

- 取址原语取槽，得到地址；
- 读原语再解引用一次，才得到目标值（整型、浮点、字符串各按目标族解释）；
- 写原语把目标地址取出来，再写到目标处。

因此"池里那一槽"与"值所在处"是两层。指针槽本身不参与编解码：取址原语直接返回槽内容；解引用出来的整数值仍按「整数值的编码」解码。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 引用第 i 槽指向的整数值 | `cell(type 6, i)` → 解引用 → 解码 |
| 引用第 i 槽指向的浮点值 | `cell(type 7, i)` → 解引用 → 32 位浮点数 |

★ 类型标签 8（全局字符串引用）**只有取址**：读整型 / 读浮点原语对它落缺省（抛"操作数类型异常"），写原语也不接受它。
它不是"读出来再解引用成字符串"——本版**不规定**字符串引用的读语义。

**成立条件**

- 指针槽本身不参与编解码；取址原语直接返回槽内容（一个地址）。
- 解引用出来的整数值仍按「整数值的编码」解码。
- 指针目标的生命周期与有效性不在本版范围；本规范不假设目标已被初始化。

### 局部池：类型标签 9..14

<!-- rule: SPC-POOL-LOCAL-FAMILIES -->

类型标签 9..14 对应当前帧的六个局部池：整型、浮点、字符串、指针、浮点指针、字符串指针。取址原语先按当前帧定位局部池，再按 raw 下标取槽。

- 整型族的槽装编码位模式；初值是**编码后的 0**（读出来是 0，但位模式不是 0）。
- 浮点族是裸 32 位浮点数。
- 字符串族是一槽一条定长字符串记录。
- 指针族（12 / 13 / 14）的槽装地址；读 / 写都要经过一次解引用。指针槽本身不解码，解码发生在解引用出来的目标上。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 局部整型变量 i 的值 | `operand(type 9, i)` → 当前帧整型池第 i 槽 → 解码 |
| 局部浮点变量 i 的值 | `operand(type 10, i)` → 当前帧浮点池第 i 槽 |
| 局部字符串变量 i | `operand(type 11, i)` → 当前帧字符串池第 i 条记录 |
| 局部指针 i 指向的整数值 | `operand(type 12, i)` → 取槽（地址）→ 解引用 → 解码 |

**成立条件**

- 局部池按当前帧选择；跨帧访问不在本版范围。
- 整型族的初值是编码后的零。
- 字符串记录的具体宽度与字段布局不是本规范的内容；本规范只使用"一条记录"这一抽象。

### 支持集合与不支持的组合

<!-- rule: SPC-OPERAND-UNSUPPORTED-THROW -->

每个原语只接受一部分类型标签。**接受** = 不抛异常（不等于本版规定了它的值语义）：

| 原语 | 接受（不抛） | 明确不支持（抛） |
|---|---|---|
| 取址 | 3–14；`0x8003` / `0x8005` / `0x8009` / `0x800B` | 0–2；其余句柄与 15 以上 |
| 读整型 | 0–13；`0x8003`；`0x8009` | 8、14；`0x8005`；`0x800B`；其余 |
| 读浮点 | 0–13；`0x8003`；`0x8009` | 8、14；`0x8005`；`0x800B`；其余 |
| 写整型 | 3、4、6、7、9、10、12；`0x8003`；`0x8009` | 0–2、5、8、11、13、14；`0x8005`；`0x800B`；其余 |
| 写浮点 | 3、4、6、7、9、10、12、13；`0x8003`；`0x8009` | 0–2、5、8、11、14；`0x8005`；`0x800B`；其余 |

- **0–2**（立即值 / 浮点立即值 / 内联字符串）只被**读**原语接受；本版只登记"接受"，**不规定**它们的值语义。
- **句柄**：`0x8003` 与 `0x8009` 被五个原语全部接受；`0x8005` / `0x800B` 只在**取址**里被接受，四个值原语对它们抛异常。

不支持的组合**必须响亮地失败**：引擎抛出一个"操作数类型异常"。它不是返回 0，也不是静默跳过；实现不得替引擎编一个值。

**成立条件**

- "不支持"是规范的可观察行为（抛异常），不是本项目的实现选择。
- 句柄的**语义**见「容器句柄：0x8003 / 0x8009」与「字符串容器句柄：0x8005 / 0x800B」；本表只规定"哪个原语接受它"。
- 句柄由独立分支处理，不经过上面五张分派表的 case。

### 容器句柄：类型标签 0x8003 / 0x8009

<!-- rule: CORE-POOL-HANDLE-INT -->

`0x8003`（全局）与 `0x8009`（局部）是**整型池的容器句柄**：池槽里装的是一个**容器对象指针**（与整型值一样编码存放），不是值本身。

- **取址**：解码槽得到容器指针；槽内容为 0（未初始化）时**懒分配**一个容器对象（三个 32 位字清零），把"编码后的指针"写回槽，并把这个槽号登记进一张引擎级注册表；返回容器指针。
- **读**（两个读原语）：解码槽得到容器；元素个数 = （尾指针 − 头指针）/ 4；**个数为 0 或槽为 0 时返回 0**（读浮返回 0.0）；否则返回**第一个元素**（整型元素要再解码）。
- **写**（两个写原语）：槽为 0 时同样懒分配；元素个数为 0 ⇒ **追加**一个元素；不为 0 ⇒ **覆写第一个元素**；非空路径上的下标检查会抛"容器下标越界"。
- `0x8005` / `0x800B` 在这个机制里不存在：四个读写原语对它们都是类型异常。

**成立条件**

- "容器"在这里是可观察的最小结构：头指针 + 尾指针（元素按 4 字节步进）与一个用途未定的第三字。
- 元素的值按整数编码存放（写要编码，读要解码）。
- 读 / 写只在"第一个元素"上工作；其它元素只能由未来的容器机制访问。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| `0x8003` 的容器 | 全局整型池第 i 槽 → 解码 → 容器对象 |
| `0x8009` 的容器 | 当前帧整型池第 i 槽 → 解码 → 容器对象 |
| 容器注册表 | 引擎级的容器表（登记的是池槽号） |

### 字符串容器句柄：类型标签 0x8005 / 0x800B

<!-- rule: CORE-POOL-HANDLE-STRING -->

`0x8005`（全局）/ `0x800B`（局部）是**字符串池的容器句柄**：容器指针以**十进制文本**存在字符串记录里。

- **取址**（唯一有定义的原语）：若记录的长度字段为 0（空串）⇒ 分配一个容器对象，把它的指针用十进制文本写进这条记录（走记录级文本写入路径）；然后按内联 / 间接判别取出文本，**按十进制解析成整数**，这个整数就是"容器地址"。
- 两个读原语与两个写原语对 `0x8005` / `0x800B` 都是**类型异常**。

**成立条件**

- 这条机制的"地址"是**文本**：任何能改写该字符串槽的路径都会改变句柄（这是可观察的耦合，规范必须说清）。
- 容器对象本身的语义见「容器句柄：0x8003 / 0x8009」。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| `0x8005` 的容器指针 | 全局字符串池第 i 条记录的文本 → 十进制解析 |
| `0x800B` 的容器指针 | 当前帧字符串池第 i 条记录的文本 → 十进制解析 |

### 整数值的编码

<!-- rule: SPC-VALUE-INT-ENCODED -->

整型族（全局整型池、局部整型池，以及引用族解引用后得到的整数）在内存里不是原值，而是**编码后的位模式**。

设 `key` 是引擎的运行期状态（见下）。`rol32` / `ror32` 是 32 位循环左移 / 循环右移。对 32 位值：

- **解码**：`DEC(x) = ror32(rol32(x, 11) XOR key, 25)`
- **编码**：`ENC(v) = rol32(ror32(v, 7) XOR key, 21)`

两者互为逆运算。读整型原语在取出位模式后做一次解码；写整型原语在写入前做一次编码。

`key` 由引擎在启动期写入，每个进程一份；它不是常量。实现必须把 `key` 参数化，**不得**提供默认值（用 0 当默认会把"不知道 key"伪装成"key 是 0"）。

整型池的初值是 `ENC(0)`（即"编码后的零"），不是位模式 0。因此"未初始化 = 0"是错的；只是解码后看起来是 0。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 整型池里的原值 | `DEC(槽中的位模式, key)` |
| 写进整型池的位模式 | `ENC(原值, key)` |

**成立条件**

- 本规则覆盖所有读写整型值的路径，包括引用族解引用之后。
- 浮点族、字符串记录与指针槽本身不走这条。

### 浮点值的表示与跨族转换

<!-- rule: CORE-POOL-FLOAT-VALUE -->

浮点族（全局浮点池、局部浮点池，以及浮点引用 / 浮点指针解引用之后）的槽里直接装 32 位 IEEE-754 浮点数，**不过编解码**。读浮得到该数（读原语返回 64 位浮点，值相同）；写浮直接写入。

跨族时按下面的口径转换（都是**引擎自己**的行为，不是实现的自由）：

- **整数 → 浮点**：有符号整数转 32 位浮点（写整型到浮点族）。
- **浮点 → 整数**：**向零截断**（写浮点到整型族、读整型从浮点族、读整型从立即浮点都是这条）。
- **整型族 → 浮点**：先解码，再把有符号整数转浮点（读浮从整型池、从整型引用）。

**适用条件**

- 截断不是四舍五入，也不是"饱和"；超出整数范围的值不属于本版范围。
- 32 位浮点的逐位表示（NaN / 非规格化数）不进本规范正文（属平台 / 硬件行为）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 浮点池第 i 个值 | 浮点族槽里的 32 位浮点 |
| 跨族读写的值 | 先按上表转换，再按目标族编码（若目标是整型） |

### 字符串记录

<!-- rule: SPC-POOL-STRING-SSO -->

全局字符串池与局部字符串池的每一槽是一条**定长字符串记录**。记录里有一个容量字段，读取时把它与内联阈值比较：

- 容量小于 **16** 时，字符串字节内联在记录自己的缓冲区里；
- 否则，记录里放一个指针，文本在指针指向处。

取址原语返回这条记录的地址。读值原语按**目标语义**解释记录中的文本：

- 读整型：按十进制文本解析成整数（C 语言 `atoi` 的语义）；
- 读浮点：按十进制文本解析成浮点数（C 语言 `atof` 的语义）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 第 i 条字符串记录 | 字符串池的第 i 槽 |
| 字符串作为整数被读取 | 按容量字段判内联/间接得到文本 → `atoi` |
| 字符串作为浮点数被读取 | 同上 → `atof` |

**成立条件**

- 记录的具体宽度与字段布局不是本规范的内容；本规范只规定"容量与阈值比较、内联/间接判别、按文本解析"。
- 字符串族的写原语不走类型标签 5 / 11（见「不支持的组合」）；字符串写入另有路径，不在本版范围。
- 整型读 / 浮点读是把字符串当**十进制文本**解析，不是把记录里的字节当数。

### 字符串记录的写入

<!-- rule: CORE-POOL-STRING-WRITE -->

引擎有一个**记录级写入原语**：给定"记录地址 + 源字节 + 长度"，它：

1. 读记录的容量字段；容量够就原地写，不够就**扩容**（新容量由引擎选；旧文本是否保留由扩容实现决定）；
2. 把源字节拷进数据区（内联区或堆上，按容量与阈值决定）；
3. 更新长度字段，并在文本末尾写 NUL。

源与本记录的缓冲区**重叠**时走另一条路径（先按重叠量调整再搬），不是直接拷贝。

**适用条件**

- 这条是**文本层**的写入，不经过操作数类型标签（标签 5 / 11 的写仍是类型异常）。
- 长度是**字节数**，不是字符数。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 一条字符串记录被赋新文本 | 记录级写入原语（记录, 源, 长度） |
| 文本变长超过内联阈值 | 容量比较失败 → 扩容 → 数据区换成堆指针 |

### 容量与分配

<!-- rule: SPC-POOL-CAPACITY-AND-UB -->

池的大小在脚本装载时按计数分配，是运行期状态。本规范不把任何容量写成常量。

- **全局池**：六个计数（值族 3 + 引用族 3）由装载期从脚本元数据拷进引擎槽；每个池按"计数 + 一个**随机余量** + 1"分配。
- **局部池**：每帧 6 个计数槽，按"该帧计数 + 1"分配；基址写进帧记录。
- 整型族分配后**逐格**填"编码后的零"；其它族不保证初值，本规范不假设未写过的槽读出来是什么。

**成立条件**

- "随机余量"是**内存分配行为**，不是语义容量：它既不扩大可寻址的合法下标，也不改变"越界是未定义"（见「下标不做上界检查」）。
- 容量与计数在装载时确定；本规范只声明口径，不复述具体数值。
- 池有第二份"另一半"缓冲（memflip），本版不写它的触发条件。

### 下标不做上界检查

<!-- rule: CORE-POOL-INDEX-UNCHECKED -->

池的下标访问**没有边界检查**：五个访问原语的函数体里不出现任何池计数槽，地址由"基址 + 下标 × 元素宽"直接算出。

- 越界访问是**未定义行为**，不是可复刻的语义；实现必须把它记成诊断，而不是替引擎 clamp 或补 0。
- 这条**只针对池**：引擎标量表（见「引擎级状态」）有自己的检查，不要把两者混起来。
- "未初始化 ≠ 0"：整型族初值是编码后的零；其它族按各自的分配方式，本规范不假设。

**成立条件**

- 判据是机械的：五个原语的函数体（`proc near` 到 `endp`）里，12 个池计数槽出现 **0** 次。
- 本版**没有**任何一次真机越界观测；这条结论只来自代码结构。

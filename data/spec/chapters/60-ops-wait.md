## 等待、输入、影片与空操作

本章 5 条规则 / 5 个 opcode。

## 等待与输入（opcode 0x21c / 0x101）

### 等待（opcode 0x21c）

<!-- rule: CORE-OPS-WAIT -->

`0x21c` 没有操作数。它只做两件事：把当前帧的**推进格数**写成 1（= `2 × 0 + 1`），并**置起等待位** —— 等待位是状态选择字的**第 10 位**（位号从 0 起数）。

- 阻塞**不发生在处理器体内**：置位后门立刻关上，之后由门的服务分支决定何时放行（见「执行与时间」）。
- 本条不读操作数、不写别的引擎状态。
- 等待位（第 10 位）与 `0x71` 置的第 27 位**不是同一位**：⛔ 不许把"置位后门关上"的机制实现成一条共用位。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 脚本在等待 | 状态选择字的第 10 位 = 1 |
| 本条指令的长度 | 当前帧的推进格数 ← 1 |

**成立条件**

- 实现不许在处理器里循环 / 睡眠等待；那是把门的语义搬进一条指令。
- 本版只建模"场景不再有动画"这一条放行条件；服务分支另有一路判定（身份未取证，**本版不规定**）。点击跳过不在本版。

### 采样输入并丢弃（opcode 0x101）

<!-- rule: CORE-OPS-WAIT-POLL-INPUT -->

`0x101` 没有操作数。已观察到的形态是：按固定顺序做四件事：

1. 采样一次输入到引擎的输入字（**外部请求**；采样本身不在本版范围）；
2. 清状态选择字里的**一个位** —— 位号未取证，**本版不规定**；
3. 把输入字写成 0（**丢弃**这次采样）；
4. 两个引擎级标量：**A ← 1**、**B ← 0**（A、B 是两条不同的格；它们的领域身份未取证，本版不规定）。

★ **这条指令对引擎数据的完整效果本版不规定**（原因：被清的是哪一位没有取证，而那是本条唯一作用于状态选择字的效果）。本版只登记上面四步的形态与它们之间的次序。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 输入已被丢弃 | 输入字 = 0 |
| 某位被清 | 状态选择字里对应位 = 0（位号本版不规定） |
| 两个标量 | A ← 1、B ← 0 |

**成立条件**

- 顺序固定：采样 → 清位 → 清输入字 → 写两个标量（后三步不许调换）。
- 采样结果除"写进输入字再清零"外没有其它消费。
- A 与 B 的**领域身份**未取证：本版只规定"两条不同的格、一条写 1、一条写 0"，不规定它们各自被谁读。

## 外部请求

### 播影片（opcode 0x20f）

<!-- rule: CORE-OPS-MOVIE -->

`0x20f` 有三个操作数：**1 = 资源 id**、**2 = 对象表槽号**、**3 = 选项字**；读取顺序是 **2 → 1 → 1 → 3**。资源 id 使用《总览与约定》的**统一文件 id**；影片字节从该 id 对应的文件取。

- 按第 2 个操作数查**对象表**（0..999）；该槽为空 ⇒ 新建一个影片对象放进去；同槽已有影片对象 ⇒ **不重建**，只改配置与启动。
- 用第 1 个操作数取文件名并初始化播放后端（**外部请求**）；后端初始化失败 ⇒ 抛**显示消息型异常**，已建对象留在槽里。
- **纹理绑定**：按**同一个槽号**索引的**纹理槽表**里的一项；它与对象表里的影片对象**不是同一个东西**（对象表空只是建对象，纹理槽空则抛异常）。本条**只读**它，不建立、也不清除；播放期间该槽被 `0x1f8` / `0x1f9` / `0x1fa` 重建或释放时，影片绑定是否还有效本版不规定（见残差）。
- **绑定门**：纹理槽为空 ⇒ 抛**显示消息型异常**；不会继续打开 / 配置。
- 次序固定：建对象（仅当槽空）→ 初始化播放后端 → **绑定门** → 取文件并配置播放后端 → 读选项字 → 应用音轨类别 / 音量 → 启动 → 置影片位。
- **失败**：后端初始化 / 取文件打开失败、或绑定为空 ⇒ **已建的影片对象留在对象表里**，影片位**尚未**置，启动不做。**打开成功后的配置返回值不被检查**：配置返回 0 仍会启动并置位；若后端没有可用流，可能在下一迭代立即收尾。
- 第 3 个操作数是**选项字**：第 0 位 = 循环；`(选项字 & 3) == 2` ⇒ 收尾时**不发出**“填纹理”请求；其余位（含音频类别）的位段与语义未完全取证，本版只登记“对象音量被配置”，不规定键位与合成公式，也不把“可跳过”当成合同。
- 最后**置起影片位**，并把“有活动对象”写 1。
- 处理器体内**不等待**：建对象、配置、启动之后立即返回；阻塞由**门之前的影片对象表服务**与门上的影片位服务共同维持（见「执行与时间」的「影片对象表的服务」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个槽上有影片在播 | 对象表该槽非空、对象已启动 |
| 影片占用主循环 | 影片位 = 1（由门上的影片位服务维持；循环分支保持置起） |
| 有活动对象 | “有活动对象”标记 = 1（仅成功启动后写 1；失败残留对象不参与服务） |

**成立条件**

- 影片时长、解码、声音呈现都属于外部模块；本条只规定请求 / 对象状态 / 选项字分流。
- 本版**不要求**实现音频输出；忽略音频不得改变影片位、对象生命周期或阻塞。
- 资源 id 的统一性只到“取文件”为止；文件名 / 容器识别属外部模块。
- 失败残留对象没有“已启动”；本版规定它不进入播完判据、也不维持影片位（避免从未播放的对象把门永久关住）。这是本版对未取证失败路径的**显式边界**，见残差。

## 空操作

### 注释（opcode 0x1a7）

<!-- rule: CORE-OPS-NOOP-COMMENT -->

`0x1a7` 带**一个**操作数，但**不读它**：处理器只写"操作数个数"槽（3 = 2×1+1），然后返回。

- 不读操作数 ⇒ 即使载荷的类型标签不受支持，也**不抛异常**。
- 不写任何池、标量或场景状态。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 无 | 只有分派协议的操作数个数槽 |

**成立条件**

- 这条的合同是"**什么都不做**"：把它实现成 no-op 不是偷懒，而是规范结论。
- 操作数载荷（注释文本）只存在于指令流里，不进入任何状态。

### 未使用（opcode 0x1a8）

<!-- rule: CORE-OPS-NOOP-DEV -->

`0x1a8` **没有**操作数：处理器只写"操作数个数"槽（1 = 2×0+1），然后返回。

- 不读操作数、不写任何引擎状态。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 无 | 只有分派协议的操作数个数槽 |

**成立条件**

- 与 `0x1a7` 的区别只在操作数个数（一条带载荷、一条不带）；语义都是 no-op。

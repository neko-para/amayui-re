## 等待、影片与空操作

本章规则数以 `pnpm tools spec chapters` 现查。

### 等待（opcode 0x21c）

<!-- rule: CORE-OPS-WAIT -->

`0x21c` 没有操作数。它只做两件事：把当前帧的**推进格数**写成 1（= `2 × 0 + 1`），并**置起等待位** —— 等待位是状态选择字的**第 10 位**（位号从 0 起数）。

- 阻塞**不发生在处理器体内**：置位后门立刻关上，之后由门的服务分支决定何时放行（见「执行与时间」）。
- 本条不读操作数、不写别的引擎状态。
- 等待位（第 10 位）与 `0x71` 置的第 27 位**不是同一位**：⛔ 不许把"置位后门关上"的机制实现成一条共用位。

**残差**

- `CORE-OPS-WAIT-TIMER`（unknown）：消息子系统里那个决定放行的**计时器**由谁、按什么步长递减未取证；
  本版用"待画格 / 打字态"近似；因此"窗口淡入期间点击无效"这类现象**不**在本版的合同里。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 脚本在等待 | 状态选择字的第 10 位 = 1 |
| 本条指令的长度 | 当前帧的推进格数 ← 1 |

**成立条件**

- 实现不许在处理器里循环 / 睡眠等待；那是把门的语义搬进一条指令。
- **放行条件有两路**（都在门的服务分支里，且**都不看颜色窗**）：
  - **自然放行**：**消息 / 文本子系统没有未完成的工作**，**且** 场景里没有处于"推进中"状态的对象
    （判据 = 对象状态字的第 2 位为 1、第 0 位为 0）。颜色插值、窗口淡入**不**在这条判据里。
  - **输入跳过**：配置项 `system:EffectSkipOnClick` 非 0、消息子系统的某一个标志位为 0、
    且输入字的**第 4 位**命中。★ 这一路采样的是**确认键**（默认 Enter），**不是鼠标左键**：
    鼠标左键在本条的任何一路里都不构成放行。
- **颜色窗不在放行条件里**：把"场景里还有带 duration 的窗"当放行条件，会让每一句的窗口淡入
  （实测 1800 ms）把脚本卡住数秒，期间点击完全无效。
- 本版对"消息子系统没工作"的落点是「没有待画格、且不在打字态」；`0x0B5B4` 那个计时器的
  精确计数方式未取证（残差 `CORE-OPS-WAIT-TIMER`）。

## 外部请求

### 播影片（opcode 0x20f）

<!-- rule: CORE-OPS-MOVIE -->

`0x20f` 有三个操作数：**1 = 资源 id**、**2 = 对象表槽号**、**3 = 选项字**；读取顺序是 **2 → 1 → 1 → 3**。资源 id 使用《总览与约定》的**统一文件 id**；影片字节从该 id 对应的文件取。

- 按第 2 个操作数查**对象表**（0..999）；该槽为空 ⇒ 新建一个影片对象放进去；同槽已有影片对象 ⇒ **不重建**，只改配置与启动。
- 用第 1 个操作数取文件名并初始化播放后端（**外部请求**）；后端初始化失败 ⇒ 抛**显示消息型异常**，已建对象留在槽里。
- **纹理绑定**：按**同一个槽号**索引的**纹理槽表**里的一项；它与对象表里的影片对象**不是同一个东西**（对象表空只是建对象，纹理槽空则抛异常）。本条**只读**它，不建立、也不清除；播放期间该槽被 `0x1f8` / `0x1f9` / `0x1fa` 重建或释放时，影片绑定是否还有效本版不规定（见残差）。
- **绑定门**：纹理槽为空 ⇒ 抛**显示消息型异常**；不会继续打开 / 配置。
- 次序固定：建对象（仅当槽空）→ 初始化播放后端 → **绑定门** → 取文件并配置播放后端 → 读选项字 → 应用音轨类别 / 音量 → 启动 → 置影片位。
- **失败**：后端初始化 / 取文件打开失败、或绑定为空 ⇒ **已建的影片对象留在对象表里**，影片位**尚未**置，启动不做。**打开成功后的配置返回值不被检查**：配置返回 0 仍会启动并置位；若后端没有可用流，可能在下一迭代立即收尾。
- 第 3 个操作数是**选项字**：第 0 位 = 循环；`(选项字 & 3) == 2` ⇒ 收尾时**不发出**“填纹理”请求；其余位（含音频类别）的位段与语义未完全取证，本版只登记“对象音量被配置”，不规定键位与合成公式，也不把“可跳过”当成合同。
- 最后**置起影片位**，并把“有活动对象”写 1。
- 处理器体内**不等待**：建对象、配置、启动之后立即返回；阻塞由**门之前的影片对象表服务**与门上的影片位服务共同维持（见「执行与时间」的「影片对象表的服务」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个槽上有影片在播 | 对象表该槽非空、对象已启动 |
| 影片占用主循环 | 影片位 = 1（由门上的影片位服务维持；循环分支保持置起） |
| 有活动对象 | “有活动对象”标记 = 1（仅成功启动后写 1；失败残留对象不参与服务） |

**成立条件**

- 影片时长、解码、声音呈现都属于外部模块；本条只规定请求 / 对象状态 / 选项字分流。
- 本版**不要求**实现音频输出；忽略音频不得改变影片位、对象生命周期或阻塞。
- 资源 id 的统一性只到“取文件”为止；文件名 / 容器识别属外部模块。
- 失败残留对象没有“已启动”；本版规定它不进入播完判据、也不维持影片位（避免从未播放的对象把门永久关住）。这是本版对未取证失败路径的**显式边界**，见残差。

## 空操作

### 退出清理：影片 / 场景槽（opcode 0x23d）

<!-- rule: CORE-OPS-MOVIE-CLEAR-23D -->

`0x23d` 没有操作数。

- 遍历槽号 **42..999**：槽里若有影片对象，关闭 / 释放该对象并清空槽（外部释放请求）。槽号与 `0x20f` 的对象表槽号同一套；槽里不是影片对象 ⇒ 跳过。
- 对每个 42..999 的槽，若该槽的**释放守卫为 0**，把纹理记录的**来源文件格**写 **-1**（`0x216` 可观察；无论槽里有没有影片对象），并释放该槽的纹理槽对象（槽 ← 空；纹理记录保留）；守卫非 0 ⇒ 只跳过这两项（影片对象仍然清）。0..41 不变。**不删除纹理记录 / 绘制项 / 网格**。
- 不写脚本变量、不置门位、**不切换当前帧**；推进格数 = 1；没有返回值。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 槽 42..999 的影片对象被清掉 | 这些槽的影片对象 ← 空 |
| 槽 0..41 的影片对象 | **不变** |
| 槽 42..999 的纹理记录来源文件格 | 释放守卫为 0 ⇒ -1；守卫非 0 ⇒ 不变（槽 0..41 不变） |
| 该槽的纹理槽对象 | 释放守卫为 0 ⇒ 槽 ← 空；守卫非 0 ⇒ 不变 |
| 场景脏标记 | 清掉至少一个**影片对象** ⇒ 1；没清掉 ⇒ 不变 |
| 场景"有动画"标记 | **不变** |

**成立条件**

- 范围是**左闭右开**的槽号 `[42, 1000)`；槽 41 不在范围内；对象表只到 999。
- 只要真的清掉至少一个影片对象 ⇒ 场景标脏；没有清掉 ⇒ 脏标记不动。
- 它清影片对象、来源文件格与纹理槽对象，**不删纹理记录 / 绘制项 / 网格**。
- 空槽 / 非影片对象静默跳过，不报错。

**残差**

- `RES-23D-IMAGE-OBJECT`（omitted）：纹理槽对象（图像对象）的**内部资源**释放不建模；纹理槽清空与来源文件 -1 是合同，由守卫固定。
- 释放守卫的写者问题与 `0x1fa` 共用 `RES-TEX-GUARD-WRITER`（unknown）：只有读点，没有写者，观察上恒 0。

### 注释（opcode 0x1a7）

<!-- rule: CORE-OPS-NOOP-COMMENT -->

`0x1a7` 带**一个**操作数，但**不读它**：处理器只写"操作数个数"槽（3 = 2×1+1），然后返回。

- 不读操作数 ⇒ 即使载荷的类型标签不受支持，也**不抛异常**。
- 不写任何池、标量或场景状态。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 无 | 只有分派协议的操作数个数槽 |

**成立条件**

- 这条的合同是"**什么都不做**"：把它实现成 no-op 不是偷懒，而是规范结论。
- 操作数载荷（注释文本）只存在于指令流里，不进入任何状态。

### 未使用（opcode 0x1a8）

<!-- rule: CORE-OPS-NOOP-DEV -->

`0x1a8` **没有**操作数：处理器只写"操作数个数"槽（1 = 2×0+1），然后返回。

- 不读操作数、不写任何引擎状态。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 无 | 只有分派协议的操作数个数槽 |

**成立条件**

- 与 `0x1a7` 的区别只在操作数个数（一条带载荷、一条不带）；语义都是 no-op。

### 睡眠：opcode 0x0c8

<!-- rule: CORE-OPS-SLEEP-C8 -->

`0x0c8` 有一个操作数。推进格数 ← **3**（= 2 × 1 + 1），然后按三步：

1. **前置**：宿主库解析出的一个入口指针存在且**返回非 0** ⇒ 抛**退出型异常**（码 0），不睡。前置失败路径**不改**推进格数（它已经写了 3）。同一组前置里还有解码密钥 / 编码零点两个不变量；它们属机器细节，本版不在正文规定（见残差）。
2. 状态选择字**第 27 位**（位号从 0 起数）为 1 ⇒ 除推进格数外**什么都不做**。★ 在「执行与时间」的门模型下，位非 0 时本条不会被派发 ⇒ 这一支是**防御性分支**，本版不把它当可观察路径。
3. 否则读整型(第 1 个) = **n**：
   - **n ≥ 10**：置状态选择字**第 0 位**；把 n 交给**引擎计时器对象**（时长 = n）。本条**不阻塞** —— 门由第 0 位关住，放行由那一位的服务分支决定。
   - **n < 10**：**在处理器体内**请求宿主睡眠 n 毫秒（**阻塞**）。这一支不置任何位。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 长睡眠（n ≥ 10） | 状态选择字第 0 位 = 1；计时器 ← n |
| 短睡眠（n < 10） | 处理器内阻塞 n 毫秒；状态字不变 |
| 跳过（第 27 位为 1） | 只有推进格数 |
| 前置失败 | 退出型异常；引擎数据不变 |

**成立条件**

- 判据是 **n ≥ 10**（含 10），不是 n > 10。
- **第 27 位不是等待位**（等待位是第 10 位）：第 27 位就是本版所说的「跳过位」，`0x88` 在值为 0 时清它（见「引擎级标量」的成对写）。
- 短睡眠搬进了处理器体：⛔ 不许把它改成"置位 + 门"（那样短睡眠会变成一次迭代，而不是一次 n 毫秒的阻塞）。
- ⛔ **短睡眠不得变成 no-op**：实现可以用虚拟时钟代替真实阻塞，但必须让**时间前进 n 毫秒**、并保持次序（同一次迭代内不得提前执行下一条指令）。把 `sleep 1` 当作"什么都不做"会让轮询循环以 CPU 全速空转，属于违反本条，不是仿真参数。
- 负值**没有范围检查**：n < 10 这一支把值交给宿主睡眠（按无符号解释 ⇒ 极长阻塞）。这是可观察行为，不是"夹到 0"。
- 前置的三格里，那个入口指针是**宿主库**解析出来的（平台边界）；本版只规定"存在且返回非 0 时中止"，不规定它问的是什么。

### 读系统毫秒时钟：opcode 0x0d0

<!-- rule: CORE-OPS-CLOCK-D0 -->

`0x0d0` 有一个操作数。推进格数 ← **3**（= 2 × 1 + 1）；读一次宿主的系统毫秒时钟；把读数经**写整型**写进第 1 个操作数。

- 本条请求**一次**时钟读数；它是否与主循环迭代头那次读数是同一次，本版不规定（见残差）。
- 单位毫秒、宽度 32 位、会回绕（与「时钟」一章同口径）。
- 不归一、不夹取；除第 1 个操作数与操作数访问原语的缓存外，不改其它引擎状态。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 第 1 个操作数 = "现在" | ← 本处理器自己的一次毫秒读数 |

**成立条件**

- 值经过**写整型**原语（要编码）：落点的接受集就是「数据池」写整型原语的接受集；不受支持的类型 ⇒ 操作数类型异常。
- ⛔ 不许把它实现成"读一个常量"；是否复用迭代头读数属未定（见残差）。
- 回绕比较由**读它的人**负责（本条只给 32 位读数）。

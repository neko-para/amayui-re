## 配置

配置是引擎级、跨帧持久的键值库：启动时建立，脚本与设置界面在运行期读写它，可被写回玩家文件。

它有三个来源，优先级从低到高：**发行默认表**（随索引文件携带）、**玩家配置文件**（分段文本）、**运行期写入**（脚本与设置界面）。后两者按同一个键覆盖前者。

配置的**值**只有两类：整数与字符串。字符串是不透明字节串，不是 Unicode 文本；非 ASCII 字节按原样保存，整数转换只认十进制前缀。

### 配置库

<!-- rule: CORE-CONFIG-STORE -->

引擎持有一份**键 → 值**的配置库。键是 ASCII 名，值分整数、字符串与字符串列表三类；同一个键只有一种类型，类型由引擎的固定词表决定。

- 读一个不存在的整数键 ⇒ **0**；读一个不存在的字符串键 ⇒ **空串**。读取不创建键，也不改变库。
- 写一个键会创建它（若不存在）或覆盖它（若存在）；写入不改变其它键。列表键没有“覆盖单个元素”的操作，只有追加。
- 库是**跨帧**的：帧结束、脚本切换、场景切换都不清空它。
- 库里的键名按**字节精确**匹配；大小写不敏感只发生在“把输入里的名字匹配到固定词表”这一步，匹配完成后存的是词表里的规范名。
- 库里的命名空间是键名的一部分（例如窗口尺寸与开关分别落在不同前缀下），不同命名空间的同名后缀是**不同的键**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 配置库 | 键 → （整数 \| 字节串 \| 字节串列表）的表 |

**成立条件**

- 整数键与字符串键**不互相转换**：往整数键写字符串不是“自动解析”，往字符串键写整数不是“自动格式化”；这是词表在装载期决定的，不是运行期按值猜的。
- 读缺失键给默认值，不等于“把默认值写进库”：读之后该键仍然不存在。

### 发行默认表

<!-- rule: CORE-CONFIG-DEFAULTS -->

索引文件的目录之后**可以**带一段发行默认表。定位方式：

1. 目录之后第一个 32 位标记：它只表示“两个计数数组在不在”。≤ 0 ⇒ 不读数组；> 0 ⇒ 接着读两个计数数组。
2. 两个计数数组：第一个是元素数 + 若干 32 位整数，第二个同形。它们**不属于配置库**，引擎把它们读进别处；配置装载只负责跳过。
3. 数组之后（或第一个标记 ≤ 0 时直接）是第二个 32 位标记；标记 ≤ 0 ⇒ 没有默认表，停止。
4. 标记之后是一个 32 位条目数 N，随后 N 对以 NUL 结尾的 **（键, 值）**。键是 ASCII 大写名，值是字节串。

条目**按文件顺序**处理，且处理前先把列表键清空：

- 键按固定词表匹配（大小写不敏感）。词表外的键 ⇒ **装载失败**：引擎停止解析并向调用者返回失败；⛔ 不是静默忽略。
- 整数键：值按 C 的十进制整数前缀转换 —— 可带正负号，遇到第一个非数字字节停止，没有数字 ⇒ 0。
- 字符串键：值的字节原样进库（不做代码页转换、不做大小写折叠）。
- 列表键：同名的多次出现**按顺序追加**，不是覆盖；后出现的条目不会清掉先出现的条目。
- 复合键：`SAVEVERSION` 的数值 V 拆成主版本 `V / 100` 与次版本 `V % 100` 两个整数键；`NOSETMUSIC` 非零时还派生一个音乐开关键，值为 `V - 1`（V 为 0 时不派生）；`WHEELKEYUP` / `WHEELKEYDOWN` 还各派生一个消息滚动键；`ENABLEANTIFONT` 还派生一个菜单开关，值相同。
- 归一化：`FORCESCREEN` 先归一成 0 / 1 再进库（非 0 ⇒ 1）。
- 接受但忽略：`OUTERFRAMEMODE` 在词表里，但**不产生任何键**，也不算错误。
- 平台条件：`ENABLEANTIFONT` 请求启用、而宿主报告字体平滑不可用时，引擎把它改为 0，再写进库。
- 收尾修补：默认表全部处理完后，若“菜单保存开关”为 0、主版本为 1、次版本为 0，则把主 / 次版本改为 1 / 10。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 发行默认表 | 索引尾部的一段长度标记 + 条目数 + （键, 字节串）序列 |
| 默认值 | 条目按上述规则转换后写进配置库 |

**成立条件**

- 条目数 N 是**条目对**的个数，不是字节数；字符串区前面的长度标记只做非零校验，引擎不拿它当循环上界。
- 未知键是**装载期**的失败，不是运行期读不到：失败发生在配置库建立之前。
- 词表里的“宽度 / 高度 / 位深 / 窗口坐标 / 开关”都只是整数键；它们的取值范围与含义由使用它们的引擎阶段决定，本规则不把它们 clamp 到某个范围。

### 玩家配置文件

<!-- rule: CORE-CONFIG-PLAYER -->

玩家配置是一份**可选**的分段文本文件，本作的文件名是 `SYS4REG.INI`。它是覆盖层：只有文件里出现的条目才覆盖发行默认。

**位置**由宿主与配置共同决定：

- 宿主给出一个配置根：`USEAPPDATAFOLDER` 为真 ⇒ 用户配置目录；为假 ⇒ 安装目录。用户配置目录的取法属于宿主边界；本规则只规定“配置根由宿主给出”。
- 配置根之后拼上 `REGFILEPATH` 键的值（相对路径），再拼文件名。
- 读文件之前，引擎按需创建目录；文件本身**不创建** —— 文件不存在是正常状态，表示“全部用发行默认”。

**文本格式**（按行读）：

- 只按 LF 分行；行缓冲有上限，超长行会被切开（不是错误）。
- 一行的**原始首字节**是 `[` ⇒ 这一段是段头：取 `[` 与随后的 `]` 之间的文本为当前段名。首字节不是 `[` 的行一律按 `键=值` 解析。
- `键=值`：在**第一个** `=` 处切开；键与值都先去掉首尾的 0x00–0x20 字节（空格、制表、CR、LF），再各剥掉一层成对的双引号。没有 `=` 的行仍然会被登记成“空键、空值”的条目。
- 没有注释符：`;` / `#` 没有特殊含义；带 `=` 的注释行会成为普通条目。
- 段名与键名都按**字节精确**保存与匹配：不折叠大小写。词表外的段 / 键**忽略**（不是错误）。
- 文件里的条目以 `段名 + 反斜杠 + 键名` 进入玩家层，再按固定词表映射到配置库的键。缺某个键 ⇒ 该键保留发行默认；同一个键出现多次 ⇒ 以**最后一次**的值为准。
- 值的类型由词表决定：整数键按十进制前缀转换，字符串键保留原字节。
- 条件键：`VirtualFullScreenType` 只在 `VirtualFullScreen` 非 0 时读取；`UseAntiFont` / `AntiFontLevel` 只在启用抗锯齿字体时读取。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 玩家配置层 | （段名 \ 键名）→ 字节串 |
| 覆盖结果 | 配置库里对应键的值被替换，其余键不变 |

**成立条件**

- “文件不存在”与“文件存在但为空”都合法，且都得到同一结果：默认值原样保留。
- 段名、键名的匹配是**字节精确**的：大小写不同的条目会被当成词表外条目而忽略，不会“宽容地”命中。
- 文件层只覆盖词表里登记过的键；脚本写进库里的运行期键不在词表内，因此不会被文件覆盖。

### 保存

<!-- rule: CORE-CONFIG-PERSIST -->

保存把配置库里**可持久化**的键写成一份新的分段文本：文件以覆盖方式打开（不存在则创建，存在则截断），目录按需创建。

- **段顺序固定**：`display`、`sound`、`message`、`system`。段内键顺序也固定（由词表顺序决定，不按字母序）。
- 段头只在段名与上一条不同时写出：`[段名]` + CR LF。每个条目一行 `键=值` + CR LF。行结束符是 CR LF 两字节；文件没有额外的头、注释或空行。
- 整数写十进制文本（不补零）；字符串写原字节，不做转义、不加引号。
- 只有词表里的**可持久键**被写出。发行默认表里有、但不在可持久词表里的键（例如菜单类、窗口位置类、`SCREENX` / `SCREENY`）**不落盘**；脚本写进库的类型码键也不落盘；`debug` 段的键只读不写。
- 个别键是**条件写出**的：`VirtualFullScreenType` 只在 `VirtualFullScreen` 非 0 时出现；`UseAntiFont` / `AntiFontLevel` 只在启用抗锯齿字体时出现。
- 装载本身**不写文件**：文件只在保存时创建。保存是整体重写，不是逐键合并。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 持久化配置 | 四个段的有序条目 |
| 文件 | `[段]` + `键=值` 行序列，CR LF 结尾 |

**成立条件**

- 重写是整体替换：文件里原有的、词表外的行会被丢弃。
- 保存不改变内存里的配置库。
- 保存由哪个宿主路径触发（设置提交、退出、其它）不在本规则内；本规则只规定“保存被调用时写出什么”。

### 脚本访问

<!-- rule: CORE-CONFIG-SCRIPT -->

四条指令读写配置库：`0x1a3 load-int`、`0x1a2 save-int`、`0x1aa load-string`、`0x1a9 save-string`。四条都只有一个操作数，它既是**键的来源**，也是**读写的目标**。

**键不是操作数里的值**，而是 `（类型码, 表下标）` 拼成的 12 字节键：

- 整数侧的类型码是 3；字符串侧的类型码是 5。
- 表下标由操作数经「取表下标」原语得到：全局值族（类型 3 / 5）的操作数 ⇒ 它自带的池下标；引用族（类型 6 / 8）与局部引用族（类型 12 / 14）⇒ 被引用格在池内的下标。
- 键的文本形式是类型码字节 + 8 位十六进制下标（不足 8 位左补 0）。

四条的行为：

- `load-int`：查整数键。命中 ⇒ 取出槽里的整数；未命中 ⇒ 0。**无论命中与否，结果都写回第 1 个操作数**。
- `save-int`：把第 1 个操作数的整数值写进整数键。
- `load-string`：查字符串键。命中 ⇒ 取出字节串；未命中 ⇒ **静态空串**（不是 0）。结果写回第 1 个操作数。
- `save-string`：把第 1 个操作数的文本值写进字符串键。

**类型约束**（不满足 ⇒ 抛“指令类型异常”，不是静默跳过）：

- 整数两条的键原语只接受**全局整型池、全局整型引用、局部整型引用**三类操作数。
- 字符串两条的键原语只接受**全局字符串池、全局字符串引用、局部字符串引用**三类操作数。
- 字符串两条写回目标时还接受带宽度标记的字符串操作数；其余类型同样抛异常。

**成立条件**

- 键与操作数当时的值无关：同一个槽位上的值变了，键不变。
- 脚本写入的键**不持久化**：它们不在可持久词表里，保存时不会被写出。
- `load-int` / `load-string` 的写回是**无条件**的：未命中时也会把 0 / 空串写回目标，覆盖目标原来的值。

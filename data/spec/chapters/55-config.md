## 配置

配置是引擎级、跨帧持久的键值存储：启动时建立，设置界面与脚本在运行期读写它，命名键可被写回玩家文件。

**命名键**有三个来源，优先级从低到高：**发行默认表**（随索引文件携带）、**玩家配置文件**（分段文本）、**运行期写入**（设置界面与存档恢复）。后两者按同一个键覆盖前者。**脚本键**只由脚本的四条读写指令产生（见「脚本访问」），不参与这三段来源。

配置的**值**有三类：整数、字符串与字符串列表。字符串是不透明字节串，不是 Unicode 文本；非 ASCII 字节按原样保存，整数转换只认十进制前缀。

键名与类型的完整清单是**伴随数据** `format/config-keys.json`；正文不逐键抄写，只规定库与三段来源的行为。

### 配置库

<!-- rule: CORE-CONFIG-STORE -->

引擎有**两张**键 → 值的表，用同一套查找 / 插入实现，但**是不同的实例**：

- **命名键表**：键是 ASCII 名，带前缀（如 `set:` / `message:` / `sound:`）；类型由固定词表决定。玩家文件与保存用它。
- **脚本键表**：键是 `(类型码, 池下标)` 拼成的 **9 字节串**（见「脚本访问」）；脚本的四条读写指令用它。

两张表**互不可见**：本版不假设它们之间有任何同步。值分整数、字符串与字符串列表三类；同一个键只有一种类型。

- 读一个不存在的整数键 ⇒ **0**；读一个不存在的字符串键 ⇒ **空串**。读取不创建键，也不改变表。
- 写一个键会创建它（若不存在）或覆盖它（若存在）；写入不改变其它键。列表键没有"覆盖单个元素"的操作，只有追加。
- 两张表都是**跨帧**的：帧结束、脚本切换、场景切换都不清空它们。
- 键名按**字节精确**匹配；大小写不敏感只发生在"把输入里的名字匹配到固定词表"这一步，匹配完成后存的是词表里的规范名。
- 命名键的**前缀是键名的一部分**（例如窗口尺寸与开关分别落在不同前缀下），不同前缀的同名后缀是**不同的键**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 命名键表 | 键 → （整数 \| 字节串 \| 字节串列表）的表（ASCII 名） |
| 脚本键表 | 键 → （整数 \| 字节串）的表（9 字节二进制键） |

**成立条件**

- 整数键与字符串键**不互相转换**：往整数键写字符串不是“自动解析”，往字符串键写整数不是“自动格式化”；这是词表在装载期决定的，不是运行期按值猜的。
- 读缺失键给默认值，不等于“把默认值写进库”：读之后该键仍然不存在。

### 发行默认表

<!-- rule: CORE-CONFIG-DEFAULTS -->

索引文件的目录之后**可以**带一段发行默认表。定位方式：

1. 目录之后第一个 32 位标记：它只表示“两个计数数组在不在”。≤ 0 ⇒ 不读数组；> 0 ⇒ 接着读两个计数数组。
2. 两个计数数组：第一个是元素数 + 若干 32 位整数，第二个同形。它们**不属于配置库**，引擎把它们读进别处；配置装载只负责跳过。
3. 数组之后（或第一个标记 ≤ 0 时直接）是第二个 32 位标记；标记 ≤ 0 ⇒ 没有默认表，停止。
4. 标记之后是一个 32 位条目数 N，随后 N 对以 NUL 结尾的 **（键, 值）**。键是 ASCII 大写名，值是字节串。

条目**按文件顺序**处理，且**整表处理前一次性**清空列表键（不是逐条清）：

- 键按固定词表匹配（大小写不敏感）。词表外的键 ⇒ **装载失败**：引擎停止解析并向调用者返回失败；⛔ 不是静默忽略。
- 整数键：值按 C 的十进制整数前缀转换 —— 可带正负号，遇到第一个非数字字节停止，没有数字 ⇒ 0。
- 字符串键：值的字节原样进库（不做代码页转换、不做大小写折叠）。
- 列表键：同名的多次出现**按顺序追加**，不是覆盖；后出现的条目不会清掉先出现的条目。
- 复合键：`SAVEVERSION` 的数值 V 拆成主版本 `V / 100` 与次版本 `V % 100` 两个整数键；`NOSETMUSIC` 非零时还派生一个音乐开关键，值为**该键的值减 1**（该键为 0 时不派生）；`WHEELKEYUP` / `WHEELKEYDOWN` 还各派生一个消息滚动键；`ENABLEANTIFONT` 还派生菜单开关键 `set:Menu_UseAntiFont`，值等于**平台条件改写之后**的最终值。
- 归一化：`FORCESCREEN` 先归一成 0 / 1 再进库（非 0 ⇒ 1）。
- 接受但忽略：`OUTERFRAMEMODE` 在词表里，但**不产生任何键**，也不算错误。
- 平台条件：`ENABLEANTIFONT` 的值恰为 1、而宿主报告字体平滑不可用时，引擎把它改为 0，再写进库；派生写在这次改写之后，用的是改写后的值。值不是 1 时不做这项改写。
- 收尾修补：默认表全部处理完后，若配置库里的 `set:Menu_Save` 为 0、**主版本键**为 1、**次版本键**为 0（两者由词表 `SAVEVERSION` 的 `saveVersionSplit` 定义），则写回主版本键 = 1、次版本键 = 10（两个都是普通整数值）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 发行默认表 | 索引尾部的第二个存在标记 + 条目数 + （键, 字节串）序列 |
| 默认值 | 条目按上述规则转换后写进配置库 |

**成立条件**

- 条目数 N 是**条目对**的个数，不是字节数。
- 未知键是**装载期**的失败，不是运行期读不到：失败发生在配置库建立之前。
- 词表里的“宽度 / 高度 / 位深 / 窗口坐标 / 开关”都只是整数键；它们的取值范围与含义由使用它们的引擎阶段决定，本规则不把它们 clamp 到某个范围。

### 玩家配置文件

<!-- rule: CORE-CONFIG-PLAYER -->

玩家配置是一份**可选**的分段文本文件，本作的文件名是 `SYS4REG.INI`。它是覆盖层：只有文件里出现的条目才覆盖发行默认。

**位置**由宿主与配置共同决定：

- 宿主给出一个配置根：`USEAPPDATAFOLDER` 为真 ⇒ 用户配置目录；为假 ⇒ 安装目录。用户配置目录的取法属于宿主边界；本规则只规定“配置根由宿主给出”。
- 配置根之后拼上 `REGFILEPATH` 键的值（相对路径），再拼文件名。
- 读文件之前，引擎按需创建目录；文件本身**不创建** —— 文件不存在是正常状态，表示“全部用发行默认”。

**文本格式**（按行读）：

- 只按 LF 分行。**一行最多 255 字节**（实现用固定行缓冲，容量不属于合同）：遇到 LF 提前结束；读满 255 字节而未见 LF ⇒ 这 255 字节先作为一行交出，剩余字节（含紧随的 LF）作为下一行继续解析（不是错误）。
- 一行的**原始首字节**是 `[` ⇒ 这一段是段头：取 `[` 与随后的 `]` 之间的文本为当前段名。首字节不是 `[` 的行一律按 `键=值` 解析。
- `键=值`：在**第一个** `=` 处切开；键与值都先去掉首尾的 0x00–0x20 字节（空格、制表、CR、LF），再各剥掉一层成对的双引号。没有 `=` 的行仍然会被登记成“空键、空值”的条目。
- 没有注释符：`;` / `#` 没有特殊含义；带 `=` 的注释行会成为普通条目。
- 段名与键名都按**字节精确**匹配词表；匹配成功后存的是词表里的规范名。词表外的段 / 键**忽略**（不是错误）。
- 文件里的条目以 `段名 + 反斜杠 + 键名` 进入玩家层，再按固定词表映射到配置库的键。缺某个键 ⇒ 该键保留发行默认；同一个键出现多次 ⇒ 以**最后一次**的值为准。
- 值的类型由词表决定：整数键按十进制前缀转换，字符串键保留原字节。
- 条件键：`VirtualFullScreenType` 只在 `VirtualFullScreen` 非 0 时读取；`UseAntiFont` / `AntiFontLevel` 只在启用抗锯齿字体时读取。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 玩家配置层 | （段名 \ 键名）→ 字节串 |
| 覆盖结果 | 配置库里对应键的值被替换，其余键不变 |

**成立条件**

- “文件不存在”与“文件存在但为空”都合法，且都得到同一结果：默认值原样保留。
- 段名与键名都按字节精确匹配词表（存的是词表规范名）。匹配失败的条目被忽略，不会“宽容地”入库。
- 文件层只覆盖词表里登记过的**命名键**；脚本写进脚本键表的键不在词表内，因此不会被文件覆盖。

### 保存

<!-- rule: CORE-CONFIG-PERSIST -->

保存把配置库里**可持久化**的键写成一份新的分段文本：文件以覆盖方式打开（不存在则创建，存在则截断），目录按需创建。

- **段顺序固定**：`display`、`sound`、`message`、`system`。段内键顺序也固定（由词表顺序决定，不按字母序）。
- 段头只在段名与上一条不同时写出：`[段名]` + CR LF。每个条目一行 `键=值` + CR LF。行结束符是 CR LF 两字节；文件没有额外的头、注释或空行。
- 整数写十进制文本（不补零）；字符串写原字节，不做转义、不加引号。
- 只有词表里的**可持久键**被写出。发行默认表里有、但不在可持久词表里的键（例如菜单类、窗口位置类、`SCREENX` / `SCREENY`）**不落盘**；脚本写进库的类型码键也不落盘；`debug` 段的键只读不写。
- 个别键是**条件写出**的：`VirtualFullScreenType` 只在 `VirtualFullScreen` 非 0 时出现；`UseAntiFont` / `AntiFontLevel` 只在启用抗锯齿字体时出现。
- 装载本身**不写文件**：文件只在保存时创建。保存是整体重写，不是逐键合并。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 持久化配置 | 四个段的有序条目 |
| 文件 | `[段]` + `键=值` 行序列，CR LF 结尾 |

**成立条件**

- 重写是整体替换：文件里原有的、词表外的行会被丢弃。
- 保存不改变内存里的配置库。
- 保存由哪个宿主路径触发（设置提交、退出、其它）不在本规则内；本规则只规定“保存被调用时写出什么”。

### 脚本访问

<!-- rule: CORE-CONFIG-SCRIPT -->

四条指令读写配置库：`0x1a3 load-int`、`0x1a2 save-int`、`0x1aa load-string`、`0x1a9 save-string`。四条都只有一个操作数，它既是**键的来源**，也是**读写的目标**。

**键不是操作数里的值**，而是由**键类型码**与**键下标**拼成的 **9 字节串**：

- 第 1 字节是键类型码的**原字节**（整数侧 3、字符串侧 5 —— 不是 ASCII 数字）；
- 后 8 字节是键下标的 **8 位小写十六进制**（左补 0，无 `0x` 前缀）；串以 NUL 结束（键内容 9 字节，缓冲里另有终止符）；
- 键下标由操作数的访问方式决定：
  - 值族（类型 3 / 5）⇒ 操作数自带的池下标；
  - 引用族 / 指针族（类型 6 / 8 / 12 / 14）⇒ 取引用槽里的**地址**，减去**该族全局池的起点**，再除以该族元素宽度（整型族 4 字节、字符串族 28 字节）。换算结果是键下标；引用槽自身的下标不参与。地址的数值本身不规定，只用地址差。
- 键里**没有池的标识**：键只由地址换算值决定。因此全局值池第 i 槽与「指向该槽的指针」生成同一个键；指向局部池的指针得到的是以全局池起点为基准的地址序号，**不等于**局部池下标（局部池与全局池的基址不同）。
- 实现内部给键一块 **12 字节**的缓冲，但**键内容只有 9 字节**：比较用这 9 字节，并额外要求两侧长度相等（构造侧长度都是 9）；缓冲里多出来的字节不参与。

四条的行为：

- `load-int`：查整数键。命中 ⇒ 取出槽里的整数；未命中 ⇒ 0。**无论命中与否，结果都写回第 1 个操作数**。
- `save-int`：把第 1 个操作数的整数值写进整数键。
- `load-string`：查字符串键。命中 ⇒ 取出字节串；未命中 ⇒ **静态空串**（不是 0）。结果写回第 1 个操作数。
- `save-string`：把第 1 个操作数的文本值写进字符串键。

**类型约束**（不满足 ⇒ 抛「操作数类型异常」，与「数据池」的同一异常；不是静默跳过）：

- 整数两条的键原语只接受**全局整型池、全局整型引用、局部整型指针**三类操作数。
- 字符串两条的键原语只接受**全局字符串池、全局字符串引用、局部字符串指针**三类操作数。
- 上述三类以外的类型（例如局部值族 9–11、浮点族 4 / 7 / 13、四个容器句柄）都在构造键时抛「操作数类型异常」。`load-string` 的键与写回目标是同一个操作数，因此可写回的类型也限于上面三类。

**成立条件**

- 值族的键只由类型标签与 raw 决定，槽里的值变化不改变键；引用族 / 指针族的键只由**引用槽里的地址**决定：改写该槽的地址会改变键，改写目标格里的值不会改变键。
- 脚本键落在**脚本键表**里，与命名键表不是同一张表：脚本读不到命名键，命名键的装载 / 保存也不碰脚本键。
- 脚本写入的键**不持久化**：它们不在可持久词表里，保存时不会被写出。
- `load-int` / `load-string` 的写回是**无条件**的：未命中时也会把 0 / 空串写回目标，覆盖目标原来的值。

## 配置

配置是引擎级、跨帧持久的键值存储：启动时建立，设置界面与脚本在运行期读写它，命名键可被写回玩家文件。

**命名键**有三个来源，优先级从低到高：**发行默认表**（随索引文件携带）、**玩家配置文件**（分段文本）、**运行期写入**（设置界面、存档恢复，以及脚本的专用写入口 —— 见「脚本访问」）。后两者按同一个键覆盖前者。**脚本键**只由脚本的四条读写指令产生（见「脚本访问」），不参与这三段来源。

配置的**值**有三类：整数、字符串与字符串列表。字符串是不透明字节串，不是 Unicode 文本；非 ASCII 字节按原样保存，整数转换只认十进制前缀。

键名与类型的完整清单是**伴随数据** `format/config-keys.json`；正文不逐键抄写，只规定库与三段来源的行为。

### 配置库

<!-- rule: CORE-CONFIG-STORE -->

引擎有**两张**键 → 值的表，用同一套查找 / 插入实现，但**是不同的实例**：

- **命名键表**：键是 ASCII 名，带前缀（如 `set:` / `message:` / `sound:`）；词表内的键类型由固定词表决定；运行期写入还可创建词表外的键（见下）。玩家文件与保存用它。
- **脚本键表**：键是 `(类型码, 键下标)` 拼成的 **9 字节串**（键下标的定义见「脚本访问」）；脚本的四条读写指令用它。

两张表**互不可见**：本版不假设它们之间有任何同步。值分整数、字符串与字符串列表三类；同一个键只有一种类型。

- 读一个不存在的整数键 ⇒ **0**；读一个不存在的字符串键 ⇒ **空串**。读取不创建键，也不改变表。
- 写一个**标量键**会创建它（若不存在）或覆盖它（若存在）；写入不改变其它键。**列表键**的写不是覆盖：它只有**追加**一个元素这一种写法（同名的多次出现按顺序追加，见「发行默认表」）。
- 两张表都是**跨帧**的：帧结束、脚本切换、场景切换都不清空它们。
- 键名按**字节精确**匹配。**只有索引默认表（`SYS4INI.BIN` 尾部）的键名**在匹配固定词表时折叠大小写（引擎用大小写不敏感比较）；**玩家文件**的段名 / 键名按**字节精确**匹配（见「玩家文件」），匹配完成后存的是词表里的规范名。
- 命名键的**前缀是键名的一部分**（例如窗口尺寸与开关分别落在不同前缀下），不同前缀的同名后缀是**不同的键**。
- **运行期写入可以创建词表外的命名键**：脚本的专用写入口按整数 / 字符串写入，引擎自己也可按整数写（例如窗口位置）。类型由写入方给出，之后按该类型读；读缺失仍是 0 / 空串。这类键不参与玩家文件装载与保存，除非它在可持久词表里。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 命名键表 | 键 → （整数 \| 字节串 \| 字节串列表）的表（ASCII 名） |
| 脚本键表 | 键 → （整数 \| 字节串）的表（9 字节二进制键） |

**成立条件**

- 整数键与字符串键**不互相转换**：往整数键写字符串不是“自动解析”，往字符串键写整数不是“自动格式化”；这是词表在装载期决定的，不是运行期按值猜的。
- 读缺失键给默认值，不等于“把默认值写进库”：读之后该键仍然不存在。

### 发行默认表

<!-- rule: CORE-CONFIG-DEFAULTS -->

索引文件的目录之后**可以**带一段发行默认表。定位方式：

1. 目录之后第一个 32 位标记：它只表示"两个计数数组在不在"，判据是**符号**（`> 0` ⇒ 有数组；`≤ 0` ⇒ 跳过这 4 字节、不读数组）。★ 标记的数值本身**不被读**：它不当长度、不当计数。
2. 两个计数数组（仅在标记 1 > 0 时存在）：每个数组 = **32 位元素数** + 该数目的 32 位整数。它们**不属于配置库**，引擎把它们读进别处（用途**本版不规定**）；配置装载只负责按元素数跳过。
3. 数组之后（或标记 1 ≤ 0 时直接）是第二个 32 位标记：同样只按**符号**判存在（`> 0` ⇒ 有默认表；`≤ 0` ⇒ 没有默认表，停止）。★ 它的数值**不是**条目数、也不参与边界。
4. 第二个标记之后是一个**独立的 32 位条目数 N**，随后 N 对以 NUL 结尾的 **（键, 值）**。键是 ASCII 大写名，值是字节串。

★ 三个数各自独立读出、独立使用：**标记 1 / 标记 2 只判存在**，**N** 与**两个数组的元素数**才是计数 —— ⛔ 不许把标记的数值当长度复用。

条目**按文件顺序**处理，且**整表处理前一次性**清空列表键（不是逐条清）：

- 键按固定词表匹配（大小写不敏感）。词表外的键 ⇒ **装载失败**：引擎停止解析并向调用者返回失败；⛔ 不是静默忽略。
- 整数键：值按 C 的十进制整数前缀转换 —— 可带正负号，遇到第一个非数字字节停止，没有数字 ⇒ 0。
- 字符串键：值的字节原样进库（不做代码页转换、不做大小写折叠）。
- 列表键：同名的多次出现**按顺序追加**，不是覆盖；后出现的条目不会清掉先出现的条目。
- 复合键：`SAVEVERSION` 的数值 V 拆成主版本 `V / 100` 与次版本 `V % 100` 两个整数键；`NOSETMUSIC` 非零时还派生一个音乐开关键，值为**该键的值减 1**（该键为 0 时不派生）；`WHEELKEYUP` / `WHEELKEYDOWN` 还各派生一个消息滚动键；`ENABLEANTIFONT` 还派生菜单开关键 `set:Menu_UseAntiFont`，值等于**平台条件改写之后**的最终值。
- 归一化：`FORCESCREEN` 先归一成 0 / 1 再进库（非 0 ⇒ 1）。
- 接受但忽略：`OUTERFRAMEMODE` 在词表里，但**不产生任何键**，也不算错误。
- 平台条件：`ENABLEANTIFONT` 的值恰为 1、而宿主报告字体平滑不可用时，引擎把它改为 0，再写进库；派生写在这次改写之后，用的是改写后的值。值不是 1 时不做这项改写。
- 收尾修补：默认表全部处理完后，若配置库里的 `set:Menu_Save` 为 0、**主版本键**为 1、**次版本键**为 0（两者由词表 `SAVEVERSION` 的 `saveVersionSplit` 定义），则写回主版本键 = 1、次版本键 = 10（两个都是普通整数值）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 发行默认表 | 索引尾部的第二个存在标记 + 其后的条目数 + （键, 字节串）序列 |
| 默认值 | 条目按上述规则转换后写进配置库 |

**成立条件**

- 条目数 N 是**条目对**的个数，不是字节数；它与第二个标记**没有关系**（标记只判"有没有"）。
- 两个标记的数值在整份二进制里只被拿来与 0 比较（判符号），**没有第二处读法** ⇒ "第二个标记的正数值有边界含义"不成立。
- 两个计数数组各自带元素数，且各自是独立的数组（不是一个数组的两段）。
- 未知键是**装载期**的失败，不是运行期读不到：失败发生在配置库建立之前。
- 词表里的“宽度 / 高度 / 位深 / 窗口坐标 / 开关”都只是整数键；它们的取值范围与含义由使用它们的引擎阶段决定，本规则不把它们 clamp 到某个范围。
- 两个计数数组的**用途**（引擎读进别处之后被谁消费）**本版不规定**（原因：没有取证）。

### 玩家配置文件

<!-- rule: CORE-CONFIG-PLAYER -->

玩家配置是一份**可选**的分段文本文件，本作的文件名是 `SYS4REG.INI`。它是覆盖层：只有文件里出现的条目才覆盖发行默认。

**位置**由宿主与配置共同决定：

- 宿主给出一个配置根：`USEAPPDATAFOLDER` 为真 ⇒ 用户配置目录；为假 ⇒ 安装目录。用户配置目录的取法属于宿主边界；本规则只规定“配置根由宿主给出”。
- 配置根之后拼上 `REGFILEPATH` 键的值（相对路径），再拼文件名。
- 读文件之前，引擎按需创建目录；文件本身**不创建** —— 文件不存在是正常状态，表示“全部用发行默认”。
- ★ 这两个键（`USEAPPDATAFOLDER` / `REGFILEPATH`）**本身从哪一层读出**（发行默认 / 上一份玩家文件 / 宿主）本版不规定；实现不得把"配置根"与"键的来源"混成同一层（否则会自指）。

**文本格式**（按行读）：

- 只按 LF 分行。**一行最多 255 字节**（硬上限，本版规定的常量）：读到 LF 就结束这一行（LF 留在行里，随后由字段裁剪去掉）；读满 255 字节还没见到 LF ⇒ 这 255 字节先作为一行交出，剩余字节（含紧随的 LF）作为下一行继续解析（不是错误）。★ **文件末尾没有 LF 结尾的残行被丢弃**（不算一行）；只有“读满 255 字节”的那一块例外 —— 它即使没有 LF 也会被交出。
- 行按 C 字符串度量：行内出现 0x00 ⇒ 就在那里截断，其后的字节不参与解析。
- 一行的**原始首字节**是 `[` ⇒ 这一段是段头：取**第一个** `[` 与**最后一个** `]` 之间的文本为当前段名（没有 `]` 就取到行尾）；段头本身不产生条目。★ 找这两个括号时，**命中落在双字节字符内部不算** —— 双字节字符的后继字节区间与 `[` / `]` 的字节值重叠，某个字符的第二个字节可能就是 `]`，它是字符的一半、不是结束括号。这个判定是**局部**的：只看命中字节与相邻一字节（该字节的前一字节是不是前导字节），**不按行首重新配对**（连续两个前导字节时，后一个前导字节仍会让紧跟的 `]` 被算作字符内部）。首字节不是 `[` 的行一律按下面的字段切分解析。
- 其余行按**顶层** `=` 切成字段：**键 = 第 0 字段**（第 1 个顶层 `=` 之前；没有顶层 `=` 时是整行），**值 = 第 1 字段**（第 1 个与第 2 个顶层 `=` 之间；只有一个顶层 `=` 时到行尾；没有顶层 `=` 时是空串）。★ 因此值在**第二个**顶层 `=` 处截断，再往后的字节不参与解析。
- **顶层** = 既不在双引号之内、也不在括号之内：`"` 每出现一次就把“在引号内”翻转（在某个 `=` 之前出现奇数次 ⇒ 这个 `=` 在引号内），`(` 使括号深度 +1、`)` 使深度 −1，深度非 0 的 `=` 都不是分隔符。★ 推论：像 `"键=值` 这样引号**未配对**的行，`=` 不是顶层分隔符，于是整行落到“没有顶层 `=`”的分支（键 = 整行、值 = 空串）。
- 段名、键、值都要先**裁剪**：去掉首尾连续的 0x00–0x20 字节（`0x20` 也去掉、`0x21` 以上不去掉；行内的 0x00 会先按上一条把整行截断，所以实际被裁掉的是 0x01–0x20），再剥掉**一层**双引号（判据 = 裁剪后的首字节与末字节都是 `"`；只按端点判、没有长度下限）：只剥一层、不循环，引号**内部**的空格保留。★ 剥引号有门槛：只有字段在开引号**之前**至少有一个被裁掉的字节时才剥；字段的第 0 个字节就是 `"` 时引号原样留下（`键="值"` 的值是 `"值"`，`键= "值" ` 的值才是 `值`）。
- 没有注释符：`;` / `#` 没有特殊含义。带 `=` 的注释行成为普通条目；**不带 `=` 的非空行**成为“键 = 整行（裁剪后）、值 = 空串”的条目（匹配不到词表就被忽略）；空行 ⇒ 空键、空值。
- 段名与键名都按**字节精确**匹配词表；匹配成功后存的是词表里的规范名。词表外的段 / 键**忽略**（不是错误）。
- 文件里的条目以 `段名 + 反斜杠 + 键名` 进入玩家层，再按固定词表映射到配置库的键。缺某个键 ⇒ 该键保留发行默认；同一个键出现多次 ⇒ 以**最后一次**的值为准。
- 值的类型由词表决定：整数键按十进制前缀转换，字符串键保留原字节。
- 条件键：`VirtualFullScreenType` 只在 `VirtualFullScreen` 非 0 时读取；`UseAntiFont` / `AntiFontLevel` 只在启用抗锯齿字体时读取。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 玩家配置层 | （段名 \ 键名）→ 字节串 |
| 覆盖结果 | 配置库里对应键的值被替换，其余键不变 |

**成立条件**

- “文件不存在”与“文件存在但为空”都合法，且都得到同一结果：默认值原样保留。
- 段名与键名都按字节精确匹配词表（存的是词表规范名）。匹配失败的条目被忽略，不会“宽容地”入库。
- 文件层只覆盖词表里登记过的**命名键**；脚本写进脚本键表的键不在词表内，因此不会被文件覆盖。

### 保存

<!-- rule: CORE-CONFIG-PERSIST -->

保存把配置库里**可持久化**的键写成一份新的分段文本：文件以覆盖方式打开（不存在则创建，存在则截断），目录按需创建。

- **段顺序固定**：`display`、`sound`、`message`、`system`。段内键顺序也固定（由词表顺序决定，不按字母序）。
- 段头只在段名与上一条不同时写出：`[段名]` + CR LF。每个条目一行 `键=值` + CR LF。行结束符是 CR LF 两字节；文件没有额外的头、注释或空行。
- 整数写十进制文本（不补零）；字符串写原字节，不做转义、不加引号。
- 只有词表里的**可持久键**被写出。发行默认表里有、但不在可持久词表里的键（例如菜单类、窗口位置类、`SCREENX` / `SCREENY`）**不落盘**；脚本写进库的类型码键也不落盘；`debug` 段的键只读不写。
- 个别键是**条件写出**的：`VirtualFullScreenType` 只在 `VirtualFullScreen` 非 0 时出现；`UseAntiFont` / `AntiFontLevel` 只在启用抗锯齿字体时出现。
- 装载本身**不写文件**：文件只在保存时创建。保存是整体重写，不是逐键合并。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 持久化配置 | 四个段的有序条目 |
| 文件 | `[段]` + `键=值` 行序列，CR LF 结尾 |

**成立条件**

- 重写是整体替换：文件里原有的、词表外的行会被丢弃。
- 保存不改变内存里的配置库。
- 保存由哪个宿主路径触发（设置提交、退出、其它）不在本规则内；本规则只规定“保存被调用时写出什么”。

### 脚本访问：opcode 0x1a2 / 0x1a3 / 0x1a9 / 0x1aa

<!-- rule: CORE-CONFIG-SCRIPT -->

四条指令读写配置库：`0x1a3 load-int`、`0x1a2 save-int`、`0x1aa load-string`、`0x1a9 save-string`。四条都只有一个操作数：它是**键的来源**；`load-int` / `load-string` 还把结果**写回**这个操作数，`save-int` / `save-string` 只把它的值读出来写进键（**不**写回操作数）。

**键不是操作数里的值**，而是由**键类型码**与**键下标**拼成的 **9 字节串**：

- 第 1 字节是键类型码的**原字节**（整数侧 3、字符串侧 5 —— 不是 ASCII 数字）；
- 后 8 字节是键下标的 **8 位小写十六进制**（左补 0，无 `0x` 前缀）；键内容共 **9 字节**，比较要求两侧长度相等（构造侧长度都是 9）。
- 键下标由操作数的访问方式决定：
  - 值族（类型 3 / 5）⇒ 操作数自带的池下标；
  - 引用族 / 指针族（类型 6 / 8 / 12 / 14）⇒ 取引用槽里的**地址**。**只有当地址落在该族全局池内时，键下标才有定义**：此时减去该族全局池的起点、再除以该族元素宽度（整型族 4 字节、字符串族 28 字节），结果**等于该全局池的槽下标**；引用槽自身的下标不参与。
- 键里**没有池的标识**：键只由上面换算出的下标决定。因此全局值池第 i 槽与「指向该槽的指针」生成同一个键。
- ★ **未定义行为**：引用槽里的地址**不落在该族全局池内**（例如指向当前帧的局部池，或任何别的位置）时，**键没有定义**（本版不规定）。引擎在这一步只做减法与除法、**没有范围检查**（逐字：键原语只做 `(地址 − 全局池起点) / 元素宽`），所以那里得到的是一个**取决于池分配布局**的数，不是槽的身份；实现必须把它当 UB——**响亮失败或记诊断**，⛔ 不许拿它去命中一个"有定义的键"。

四条的行为：

- `load-int`：查整数键。命中 ⇒ 取出槽里的整数；未命中 ⇒ 0。**无论命中与否，结果都写回第 1 个操作数**。
- `save-int`：把第 1 个操作数的整数值写进整数键。
- `load-string`：查字符串键。命中 ⇒ 取出字节串；未命中 ⇒ **静态空串**（不是 0）。结果写回第 1 个操作数。
- `save-string`：把第 1 个操作数的文本值写进字符串键。

**类型约束**（不满足 ⇒ 抛「操作数类型异常」，与「数据池」的同一异常；不是静默跳过）：

- 整数两条的键原语只接受**全局整型池、全局整型引用、局部整型指针**三类操作数。
- 字符串两条的键原语只接受**全局字符串池、全局字符串引用、局部字符串指针**三类操作数。
- 上述三类以外的类型（例如局部值族 9–11、浮点族 4 / 7 / 13、四个容器句柄）都在构造键时抛「操作数类型异常」。`load-string` 的键与写回目标是同一个操作数，因此可写回的类型也限于上面三类。

**成立条件**

- 值族的键只由类型标签与 raw 决定，槽里的值变化不改变键；引用族 / 指针族的键只由**引用槽里的地址**决定（**且该地址必须落在该族全局池内**，否则是上一条说的 UB）：改写该槽的地址会改变键，改写目标格里的值不会改变键。
- 脚本键落在**脚本键表**里，与命名键表不是同一张表：脚本的配置指令读不到命名键；命名键的装载 / 保存也不碰脚本键。
- 脚本另有一个**专用写入口**可以设置**运行期命名键**（见「转发型指令」的「设一个命名键」）。该键若在「保存」的可持久词表里，保存时按那张表写出；不在表里的键不写出。**下次启动是否读回同一个值本版不规定**（原因：命名键的读入口没有针对这条写入取证）。
- 脚本键（9 字节键）不在可持久词表里 ⇒ 保存时不会被写出（见「保存」）。
- `load-int` / `load-string` 的写回是**无条件**的：未命中时也会把 0 / 空串写回目标，覆盖目标原来的值。

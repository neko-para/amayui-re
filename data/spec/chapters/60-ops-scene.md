## 场景 / 颜色族

本章 5 条规则 / 5 个 opcode。

这五条给场景里**可绘制的东西**上色：绘制项（带矩形与颜色）与网格（带顶点缓冲与颜色）。
它们只改引擎数据；把颜色烘进顶点缓冲、以及在屏幕上画出来，属于外部模块。

三条共用口径：

- **颜色归一化**：透明度 > 255 ⇒ 按 255；透明度 < 0 ⇒ 取**现有颜色的透明度**；颜色 < 0 ⇒ 取**现有颜色**；其余情况用参数本身。
  ★ **位段与哨兵都属机器细节，本版不规定**：颜色值与透明度在 32 位颜色字段里各占哪几位、以及「无颜色」的具体数值，本版都不规定（因此本条不写位移公式）。⇒ 依赖「现有颜色 / 现有颜色的透明度 / 无颜色」的分支只到**形态**，写出的具体颜色值不唯一。
- **取记录**：按编号查表；查不到 ⇒ **先建一条默认记录**再继续。因此"什么都没做"对颜色可能成立，
  对表不成立（表里一定多了一条默认记录）。
- **起色就是当前颜色**：渐变窗不另存起色 —— 推进时插值读的起色就是该项的**当前颜色**字段（`0x203` / `0x322` 写的那一格）。因此排窗（`0x202` / `0x323`）只写终色；**窗进行中改当前颜色会改变起色**。

### 绘制项：排颜色渐变窗（opcode 0x202）

<!-- rule: CORE-OPS-SCENE-202 -->

读五个操作数：**编号**、**延迟**、**持续时间**、**透明度**、**颜色**。
延迟与持续时间的单位是**毫秒**；颜色从该项**现有颜色**渐变到归一化后的新颜色。

- 只有该项的"已存在"位（**绘制项标志字的第 0 位**，与 `0x1fb` 置的"有效"位是**同一位**）为 1 时才排窗：置"有窗"位（**第 1 位**）、把窗起点清成 0（未盖章）、写延迟 / 持续时间 / 终色，
  并把场景标脏、标成"有动画"。
- "已存在"位为 0（含刚建出的默认记录）⇒ **一个窗字段都不写**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某项的渐变窗 | 该项的延迟、持续时间、终色、"有窗"位、起点（0 = 未盖章） |
| 场景有动画 | 场景的"有动画"标记 ← 1 |

**成立条件**

- 起点 0 是"未盖章"哨兵，不是"从 0 毫秒起算"。
- "已存在"门只看该项自己的位；没有别的前置。
- "已存在"与"有窗"是**两个不同的位**（第 0 / 第 1 位）：⛔ 不许把这两个名字实现成同一位。

### 绘制项：直接设当前颜色（opcode 0x203）

<!-- rule: CORE-OPS-SCENE-203 -->

读四个操作数：**编号**、**一个整数**、**透明度**、**颜色**。按共用口径归一化后写进该项的**当前颜色**。

- **不排窗**：不碰延迟 / 持续时间 / "有窗"位；场景标脏。
- 第 2 个操作数写进记录里的一个整数位，**读者未找到**（本版只规定"写进去了"）。
- **没有"已存在"门**：编号不存在时照写（写进刚建出的默认记录）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某项的当前颜色 | 记录的当前颜色 ← 归一化值 |
| 第 2 个操作数 | 记录里的一个整数位 |

**成立条件**

- ⛔ 不许与 `0x202` 合并实现：一条排窗、一条只改当前颜色，字段集与门都不同。

### 网格：建 / 换（opcode 0x320）

<!-- rule: CORE-OPS-SCENE-320 -->

读**十个**操作数，顺序不是 1..10：**先第 9 个（顶点数）** → 第 5、6 个的**地址** → 第 7、8 个的**地址**
→ 按顶点数逐元素算出第三段 → 第 10 个 → 第 4、3、2 个的**地址** → **第 1 个（编号）**。

- **顶点数 ≤ 0** ⇒ 把错误文本「顶点数非法」写进**错误通道**（术语见「总览与约定」），**不建网格**。
- 第 2、3、4、5、6、7、8 个操作数都按**地址**读：各自指向一段逐顶点数组，**不是标量、也不做浮点读取**。
- 三个逐顶点数组（各"顶点数 × 4 字节"）的来源：
  - 第 1 个 ← 第 2 个操作数地址处的 n 个 32 位字**原样**拷贝；
  - 第 2 个 ← 第 3 个操作数地址处的 n 个 32 位字**原样**拷贝；
  - 第 3 个 ← 第 5、6 个地址处的两段逐元素合成：**(解码(第 5 段[i]) 的低 8 位) << 24 | (解码(第 6 段[i]) 的低 24 位)**；解码 = 「数据池」的整型解码。
- 第 4、7、8 个操作数地址处的数组交给**顶点缓冲对象**的装配；装配后的逐顶点布局属外部模块，本版不规定。
- 建 / 换该编号的网格：释放原有缓冲，建上述三个数组与一个顶点缓冲对象；置"已存在"位、写顶点数与第 10 个操作数。
- 若该网格的当前颜色**不是「无颜色」**⇒ 按当前颜色重烘顶点色；场景标脏。★ 「无颜色」的数值未取证 ⇒ **这个分支在什么条件下成立，本版不规定**（原因：`0x322` 等写入方可以写任意颜色，是否恰好等于哨兵值无从判断）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 顶点数 / 三个逐顶点数组 / 顶点缓冲对象 / 第 10 个操作数 | 网格记录的对应字段与缓冲 |
| "已存在"位 | 网格记录的位 0 |
| 错误通道 | 一次上报（文本 = 「顶点数非法」；仅当顶点数 ≤ 0） |

**成立条件**

- 这是"替换"不是"追加"：重复调用先释放旧缓冲。
- 编号**不做范围检查**；顶点数只有"≤ 0 / > 0"两分支，没有上限检查。

### 网格：直接设当前颜色（opcode 0x322）

<!-- rule: CORE-OPS-SCENE-322 -->

读四个操作数：**编号**、**一个整数**、**透明度**、**颜色**。

- 按共用口径归一化后写进网格的**当前颜色**，并**按当前颜色烘进顶点缓冲**（混合系数 0）；
  第 2 个操作数写进记录里的一个整数位（**读者未找到**）；场景标脏。
- **不排窗**；**没有"已存在"门**（编号不存在时写进刚建出的默认记录，默认当前颜色是"无颜色"）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 网格的当前颜色 | 记录的当前颜色 |
| 逐顶点颜色 | 顶点缓冲里的颜色 ← 当前颜色 |
| 第 2 个操作数 | 记录里的一个整数位 |

**成立条件**

- 第 2 个操作数不要当"透明度"或"编号"用：它写的是另一个整数位。

### 网格：排颜色渐变窗（opcode 0x323）

<!-- rule: CORE-OPS-SCENE-323 -->

读五个操作数：**编号**、**延迟**、**持续时间**、**透明度**、**颜色**。

- 与绘制项同形：置"有窗"位、把窗起点清成 0、写延迟 / 持续时间 / 终色；场景标脏。
- **没有"已存在"门**：编号不存在时会先建默认记录，然后**照常排窗**。
- 本条**不**直接置"场景有动画"（那由窗的推进决定）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 网格的渐变窗 | 记录的延迟、持续时间、终色、"有窗"位、起点 |

**成立条件**

- 与 `0x202` 的"已存在"门**不对称**：这是真实差异，不许抹平。

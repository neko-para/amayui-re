## 场景 / 颜色族

本章的规则逐条点名它覆盖的 opcode（见各小节标题）；未列出的 opcode 本版不作断言。

本章各条给场景里**可绘制的东西**上色：绘制项（带矩形与颜色）与网格（带顶点缓冲与颜色）。
它们只改引擎数据；顶点缓冲的**逐顶点布局 / 格式**、以及最终把画面呈现到屏幕，属于外部模块；**建顶点缓冲对象并把颜色写进缓冲是引擎数据**（`0x320` / `0x322` 与计时窗都会写）。
★ **场景里哪些对象被画、以什么顺序画是引擎行为，属于本规范的范围**：无命令记录与有命令记录时的顺序都见 `CORE-SCENE-DRAW-ORDER`；命令记录族的写侧见 `CORE-OPS-SCENE-COMMAND-RECORDS`。⛔ 不许因为"呈现交给平台"就把绘制顺序推给平台。

四条共用口径：

- **颜色归一化**：颜色是**一个 32 位 ARGB 值** —— **位 31–24 = 透明度（A）**，位 23–16 = 红，位 15–8 = 绿，位 7–0 = 蓝。参数里的**透明度**与**颜色**都按 **32 位有符号**整数读，结果的「透明度段」与「RGB 段」分别决定：
  - **透明度段**：透明度 > 255 ⇒ 取 255；0 ≤ 透明度 ≤ 255 ⇒ 取参数本身；透明度 < 0 ⇒ 取该项**当前颜色格的透明度段**（同一个 32 位字的位 31–24）。
  - **RGB 段**：颜色 < 0 ⇒ 取该项**当前颜色格的 RGB 段**（位 23–0）；颜色 ≥ 0 ⇒ 取**颜色参数的位 23–0**。
  - 归一化结果 = `(透明度段 << 24) | RGB 段`。
  - ★ **「颜色」这个参数的高 8 位（位 31–24）永不参与**：透明度只从「透明度」参数（或其兜底）来。⇒ 同一次调用里只改「颜色」参数的高 8 位，结果**一位都不变**（例：透明度 = 0、颜色 = `0x7F000000` ⇒ 结果是全 0，不是 `0x7F000000`）。★ 举例必须用**非负**实参：最高位为 1 的颜色实参（如 `0x8F000000`）按 32 位**有符号**是**负数** ⇒ 走「取现有颜色」那一支，不适用本例。
  - **归一化不按「当前颜色是不是无颜色」分支**：无颜色只是一个取值。四条写色规则写出的值只由「参数符号 + 现有颜色的取值」决定。
- **取记录**：按编号查表；查不到 ⇒ **先建一条默认记录**再继续。因此"什么都没做"对颜色可能成立，
  对表不成立（表里一定多了一条默认记录）。★ **「现有颜色」= 该项的「当前颜色格」**，不是终色格、不是别的格；按编号查不到的项读回「无颜色」—— 与建出来的默认记录的当前颜色同值，所以"编号不存在"与"编号存在但从没上过色"在归一化里**不可区分**（⛔ 不许实现成两种不同结果）。
- **起色就是当前颜色**：渐变窗不另存起色 —— 推进时插值读的起色就是该项的**当前颜色**字段（`0x203` / `0x322` 写的那一格）。因此排窗（`0x202` / `0x323`）只写终色；**窗进行中改当前颜色会改变起色**。
- **插值结果不写回当前颜色**：窗对当前颜色的唯一写入是**到期时 ← 终色**；窗进行中每一步的绘制色按「执行与时间」的「场景计时窗」派生，不写回当前颜色。网格只在被推进的那一步按派生色重烘顶点缓冲（详见该条；本节不重复）。

### 绘制顺序

<!-- rule: CORE-SCENE-DRAW-ORDER -->

**没有场景命令记录时**

一帧内没有**场景命令记录**时，引擎对**四张同键表**（辅助表 A、辅助表 B、网格、绘制项）做一次**收尾扫描**。★ **辅助表 A / 辅助表 B 是两张同形条目表的表身份暂用名**（A 是哪一张、B 是哪一张，按「CG 数字条」的「旧名对照」用删序定）；两者的**领域名本版未取证** —— 旧稿的「Live2D 模型条目表 / 3D 网格模型条目表」两个说法都没有绑定到可再校验的观察（见残差 `RES-SCENE-AUX-TABLES`），⛔ 不许把它们当已定事实、也⛔ 不许据此实现条目内容。
  ★ **两张辅助表的条目本版不给字段级语义**：能进正文的只有「它们是与网格 / 绘制项同键的条目、在同一次收尾扫描里按同一套**有效位 / 本轮已消费**判据参与」；条目值里其余字段的含义与读者**未取证**（见残差 `RES-SCENE-ENTRY-TABLE-FIELDS`），⛔ 不许据旧稿把它们实现成「模型实例（模型号 / 摆放 / 两色 / 混合档……）」。
  这次扫描按条目键**严格升序**发出绘制请求；**同键的平键序 = 辅助表 B → 辅助表 A → 网格 → 绘制项**（因此同键的绘制项在上层）。本版只给**绘制项 / 网格**的领域语义；辅助表 A / B 的条目语义未取证（见残差），但它们**在同一次扫描里**按上面的平键序参与。

- 条目的“键”是创建 / 改色时写进条目的那个编号（`0x1fb` / `0x320` 等条目的第 1 个操作数），不是表内插入次序。
- 本条只规定**引擎发出绘制请求的顺序**；D3D 内部的批次合并 / 光栅化 / 最终像素仍属平台，但“谁先谁后”不是平台的自由选择。
- 没有命令记录时命令档无动作，剩下的就是收尾扫描；四张同键表仍按同一条收尾扫描访问，**负键口径按表分**（见下）。
- **绘制项**画不画由「绘制项的消费者」决定；**网格 / 辅助表**按各自的第 0 位（有效）与第 16 位（本轮已消费）判据（辅助表 A / B 的语义见残差）。本小节只规定**谁先被访问**。

**有场景命令记录时（两档）**

一帧内有**场景命令记录**时，绘制分**两档**，先后不可交换：

1. **命令档**：按**命令键升序**逐条执行命令表里的记录。一条命令覆盖一段（有的种类是两段）**绘制键区间**；它把**自己覆盖区间内画出**的条目记成「本轮已消费」。（个别种类还会在区间之外画一趟；那一趟**不**记，见下。）
2. **收尾扫描**：命令档结束后，把**四张同键表**——**辅助表 A、辅助表 B、网格表、绘制项表**——合并，按键**严格升序**逐个访问。只有「有效位 = 1 且第 16 位 = 0」的条目才发出绘制请求；**同键的平键序固定为：辅助表 B → 辅助表 A → 网格 → 绘制项**。访问过的条目**一律**清掉第 16 位（不论是否发出）。

- **负键**：**网格 / 辅助表 B / 辅助表 A** 的负键条目按哨兵处理（不参与选择）。**绘制项是**比较链里的**最后候选**（不是最后发出），它的键**不做符号检查** ⇒ 负键绘制项是**最小键**，按严格升序**最先**发出。⛔ 不许把「负键不参与」写成不区分表的通则。
- 命令档画过的条目（第 16 位 = 1）在收尾扫描里**不会再画一次**；命令档没覆盖的条目在收尾扫描里按上面的顺序画。
- 种类 1 的第一帧路径还可能有「区间之下」那一趟（**不记**第 16 位）；它的触发条件见「场景命令记录族」的影片覆盖命令。**目的**：给离屏画布**垫底**（见下）。
- 第 16 位只在**当轮**有效：收尾扫描每访问一条就清一条。
- **命令档的覆盖范围只含三张表**（辅助表 B、网格、绘制项；按上表的平键序访问）：辅助表 A 的条目**不参与**命令档的覆盖，永远落到收尾扫描。
- 命令表为空时命令档无动作，剩下的就是"没有命令记录时"那条：键升序、同键网格先于绘制项。
- 命令档里**种类 1** 的「第一帧画 / 之后只标记」判据见「场景命令记录族」的"影片覆盖命令"；这里只规定它**先于**收尾扫描、并会置第 16 位。

**命令档的前置与出档（合同）**

- **空表无动作**：命令表为空 ⇒ 命令档**一个请求都不发、一个场景格都不写、也不切目标**。
- **每条命令的前置（次序固定）**：按命令键取记录 → 若记录的**时间戳为 0** ⇒ 写成**本帧场景时刻**（"盖章"；**本帧场景时刻 = 渲染步内直读场景时钟「现在」的活格**，不是迭代头快照）→ 用**第一段区间（区间 A）的起点**与**场景自身键窗**算出「跳过额外变换」（两段区间的种类也只用 A 的起点；整条命令**一个开关**）→ 按**种类**分派。
- **「本帧场景时刻」的可证伪判据**：同一迭代里先执行 `0x20c`、再进渲染步（区间忙标记为 0）⇒ 命令档盖章取到**覆盖后**的采样；若取到迭代头快照，本条错。
- **正常出档**：若当前目标 ≠ 进档时记下的目标 ⇒ **恢复**成进档目标（相同则不做）；标脏**不**由这一步读「有动画」决定 —— 它由**命令处理路径各自的请求**置起（出档的标脏条件见残差 `RES-SCENE-DIRTY-ON-EXIT`）。
- **中止路径**（种类 2 找不到同键绘制项）：清该命令的持续时间后**整档返回** —— 本帧其后的命令**一条都不执行**，且**不**做恢复目标 / 收尾。⛔ 不许实现成"跳过这一条继续"。它发生在**任何切目标之前**，所以不会留下悬空目标。

**命令表的生命周期（合同）**

- 渲染步在**收尾扫描之后**检查本帧的**「有动画」标记**（它与**脏**在同一处被清 0，但是**两个不同的标记**；这里判的是「本步还有没有东西在动」，不是脏）：为 **0** ⇒ 把**整张命令表清空**（不是"删掉已完成的那一条"）；为 1 ⇒ 保留。随后**无条件**把「强制完成」位清 0（不管本步有没有人读过它）。
- **「有动画」在这里回答的是"本步有没有东西在动"**：步首（与清**脏**同一处、前一条指令）把它清 0；本步的推进子步只要还在动就把它置起 —— 命令自己的计时没到终点（延迟内 / 推进中）、命令记录的持续时间非 0、命令进度还没走完、以及条目自己的窗还在延迟内 / 推进中。同一步里这些推进点**同时**把**脏**置 1；命令档**出口**再把"本标记 ∨ 强制完成"**或进「脏」**。⇒ 收尾读到的**只是本步**的值；⛔ 不许只让"计时窗"置它（指两者中的任何一个）。
- ★ 同一个标记还有**两个别处**：它是**等待谓词返回的那个值**（见「场景计时窗与"有动画"」），并且**脚本写入方**（排窗 / 写命令记录）也会把它置起 —— 那些置起发生在渲染步**之外**，活不到本步收尾，只影响等待（**仅当本步的渲染步被跳过时**）。
- ⇒ 一条命令要连续多帧执行，**必须**让**「有动画」**在这几帧里为真；若某一帧里没有任何命令 / 窗在推进（延迟内或推进中），**下一帧的命令表就是空的** —— 即使那一帧的**脏**为真（内容变更或命令档出口把它置起）。⛔ 不许把这句写成"必须有脏"：两者是**同处清零的两个不同标记**，收尾判的是前者。
- ⛔ 不许把命令表当"写进去就一直是脚本可观察的状态"（下一帧可能就空了）；**脚本指令 `0x224` 会整表清空命令记录**（唯一由脚本发起的清空点），此外就是本条的收尾按「本步还有没有动作」清空。

**「区间之下」的口径**

- 它是命令档在三张表上的一次**额外**扫描，**不是种类 1 独有**：

| 种类 | 何时跑 | 用哪一段 | 门 | 置「已消费」？ |
|---|---|---|---|---|
| 1 | **仅首帧** ∧ **绘制设备就绪** ∧ 着色器能力档 < 2 | 该条唯一的区间 | 有效 ∧ 未消费 | **否** |
| 2 | **每帧**的**每块画布**，且能力档 < 2 | 本块那一段（跳过另一段里的条目） | 有效 ∧ 未消费 | **否** |
| 0 | **每帧**的**每块画布**，且能力档 < 2 | 本块那一段（跳过另一段里的条目） | 有效 ∧ 未消费 | **否** |
| 3 | **不发生** | — | — | — |

- 它画的不是"覆盖区间的补充"，而是"键**小于**本段起点的那些条目"⇒ 落在它范围内的条目在**同一帧里**被画进**每块**画布、再由收尾扫描画一次（单画布种类共两次；双画布种类共三次）。
- **目的（已定）**：命令档每次用离屏画布前都先把它**清空**；**低档（默认路径）画布是不透明画布**、高档画布带透明度。画布随后被**整幅**使用（种类 1 = 整幅表面拷贝，种类 0/2 = 两块画布整幅合成）。⇒ 低档下"没画到"的区域是不透明底色，整幅导出会盖住底下内容，所以必须先把**本段起点之前的条目**垫进画布，让它成为"到本段末为止的完整画面"；高档下未画区域保持透明、让出底下内容 ⇒ 这一趟不需要。**同帧两次发射是后果不是目的**；不置已消费正是为了保住收尾扫描那一次。
- ⚠ 这里的门是**能力档这个代理**，不是"画布格式"本身（设备不支持时低档可能退回带透明度的格式，但仍会做这一趟）⇒ 措辞只写"低档（默认路径）画布是不透明画布"。
- 可证伪：能力档 = 2 时若仍出现"区间之下"的绘制 ⇒ 本条错；种类 3 + 能力档 < 2 若出现该趟 ⇒ 本条错；种类 2 的区间 A=[10,20)、B=[30,40)，键 35 的条目若进了画布 1 ⇒ "跳过另一段"错；键 5 的条目若在同一帧只被画一次（收尾扫描里没有）⇒ "不置已消费"错。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 一帧内绘制请求的发出顺序 | 先命令档（命令键升序），再收尾扫描（四表键升序、平键序 辅助B→辅助A→网格→绘制项） |
| 某条目本轮已被命令档画过 | 该条目首字第 16 位 ← 1（收尾扫描跳过） |
| 本轮结束 | 被访问条目的第 16 位 ← 0 |

**成立条件**

- 键升序是**严格升序**；同一张表内同键的第二次写入覆盖第一条，不并存。
- 键不因绘制而改变；绘制顺序不是插入次序、也不是创建次序。
- 第 0 位与第 16 位是**两个不同的位**：一个是"可画"，一个是"本轮已消费"。⛔ 不许合并、⛔ 不许把第 16 位当持久状态。
- 平键序是**合同**：同键时"辅助表 B → 辅助表 A → 网格 → 绘制项"（★ 这是按**表身份**与比较链核过的；⛔ 不要按表名 / 插入次序 / “链上第几个”去猜）；⛔ 不许按表名排序。
- 命令档**先于**收尾扫描；⛔ 不许把两者交错。
- 辅助表 A **不参与**命令档；⛔ 不许因为"四张表都在收尾扫描里"就把它也算进命令档的覆盖范围。
- **负键口径按表分**：网格 / 辅助 A / 辅助 B 的负键不参与；绘制项的负键**没有**这层过滤。⛔ 不许把旧版「负键不参与」原样套到绘制项上（那是本条的**纠错点**）。
- ⛔ 不许把“D3D 提交顺序”当成 D3D 的自由选择：引擎决定发出顺序，D3D 只执行。

**可证伪**

- 同键放一条网格与一条绘制项：若绘制项先发出（或网格压在上面）⇒ 平键序错。
- 绘制项键 50、网格键 10：若绘制项先发出 ⇒ 键序错。
- 改变表内插入次序但保持键不变：若绘制顺序跟着变 ⇒ 键序错。
- 一条命令覆盖键区间 `[10, 20)`，区间内有一条绘制项：若该绘制项在**收尾扫描**里又被发出一次（或它的请求先于命令档）⇒ 两档顺序错。
- 只放一条**辅助表 A** 的条目并让它落在某条命令的覆盖区间内：若它在命令档里被画（而不是收尾扫描）⇒「辅助 A 不参与命令档」错。
- 只放一条**负键绘制项**（三张非绘制项表 —— 网格 + 两张辅助表 —— 都空）：若它**没有**被发出 ⇒ 负键口径错。

**残差**

- 负键绘制项在"三张非绘制项表都无候选"时会被发出，这一行为本版由比较链读出；它在真机上**是否真的可见 / 与同键条目怎么叠放**属平台合成，见已登记的 `RES-SCENE-DRAW-STACK-SAMPLE`（采样步已含"放一条负键"）。
- `RES-SCENE-COMMAND-BELOW-RANGE-OMITTED-KIND3`（unknown）：种类 3 同样用低档不透明画布、同样先清空，却**没有**这一趟；两种解释未分：(a) 种类 3 的区间总是从表首起（区间之下恒空）；(b) 其离屏结果不被整幅使用。可测预测：低档下种类 3 未覆盖区域应呈"不透明底色"。
- `RES-SCENE-COMMAND-TABLE-LIFETIME`（unknown）："本步没有任何推进 ⇒ 整表清空"是**观察**（判据是**「有动画」**标记，不是**脏**）；为什么清（内存回收 / 脚本不可见的复位）、脚本能否观察，都未证。下一步：写一条到期命令 + 空帧，观察命令表与画面。
- `RES-SCENE-COMMAND-EFFECT-EQUIVALENCE`（unknown）：三个技法的内部组合已读（Fade 两档 / ZoomBlur / SlideBlur 的抽数与权重），但**效果路径与退路是否像素等价未证**（低档"同形"差量化 / 采样；高档不同形；种类 3 退路是 CPU 逐像素另一套）。下一步：截帧对比两路。
- `RES-SCENE-BLEND-TIER-VALUES`（unknown）：网格 / 绘制项的混合档由脚本实参给（`0x322` / `0x203` 的第 2 个操作数，默认 0）；脚本里各档的实际分布与档 2 的守卫字段语义未统计。下一步：统计发行脚本的档值分布；读档 2 的守卫字段。
- 同键网格 / 绘制项的真机叠放采样用于核对平键序，见已登记的 `RES-SCENE-DRAW-STACK-SAMPLE`（采样步已含"同键网格 + 绘制项"）。

### 场景命令记录族（opcode 0x223 / 0x24d / 0x24f / 0x250 / 0x251）

<!-- rule: CORE-OPS-SCENE-COMMAND-RECORDS -->

这五条都把一条**场景命令记录**写进**场景的命令表**。命令表与绘制项表、网格表、两张辅助表**不是同一张表**（它是第五张、按命令键有序的表）。

**共同规则**

- **第 1 个操作数 = 命令键**。按键取记录（不存在则建）；写入前**先把该键的旧记录删掉**再写 ⇒ 同一个键重复写是**替换**，不是追加。
- 记录首格 = **命令种类**，由写它的指令决定：`0x223` → 0、`0x24d` → 1、`0x24f` → 2、`0x250` / `0x251` → 3。
- 写成功后把场景标**脏**；`0x24d` 还置场景的「有动画」标记（与"脏"是**两个不同的格**）。
- 命令**不立即产生绘制请求**：它们写命令表；绘制由渲染步执行（见「绘制顺序」的"有场景命令记录时"）。**例外**：`0x223` / `0x250` / `0x251` 在写表**之前**可能先发一次建 / 换纹理请求（见各条）。
- 这些指令**没有脚本可观察的返回值**；记录里没有被本条写到的格保持默认值。

**种类 0（`0x223`，8 个操作数）：纹理覆盖命令**

- 操作数：2 = **纹理编号**；3 / 4 与 5 / 6 各是一段（**起点键、个数**）；7 = **延迟**、8 = **持续时间**。
- 若该纹理槽里没有对象、或对象的表面格式与当前显示格式不符 ⇒ 先向平台请求按该编号建 / 换纹理（**外部请求**）；请求**失败**的后果见下。
- 然后替换命令记录并写上述格。

**种类 1（`0x24d`，12 个操作数）：影片覆盖命令**

它把一条**已有的影片纹理**按一个目标矩形叠进画面，并**接管**一段绘制键区间 —— 区间内的条目改由命令档处理（画进**离屏目标**并记为「本轮已消费」），收尾扫描不再把它们直接画到主目标上。引擎自己的错误文本把这条命令的对象称作「影片」。

- **第 1 个操作数**是本命令的命令键，**同时**是一个**名字 id**（引擎用它在第 ② 步建播放后端）；它**不**写进记录。
- **第 2 个操作数**是一条**已经存在的**影片纹理的编号。★ **本条的次序是合同**，三步、顺序固定：**① 先按该编号在媒体对象表里选格**（格空 ⇒ 建一条播放类对象并放进格；格非空 ⇒ **保持原对象、不重建**，见「渲染请求边界」的「媒体对象表」）⇒ **② 只在 ① 真的建了新对象时，才让这条对象按第 1 个操作数查到的名字打开影片**（见下「打开影片（第 ② 步）」）⇒ **③ 再判纹理槽**：为空 ⇒ 引擎**抛出异常终止本条**（不是错误通道上报；此时**旧记录不动**，但**媒体对象表那一格保持已填的状态** —— 格空时就是刚建的那条对象，**不回收**）；非空 ⇒ 才删旧记录、写新记录。本条**不建纹理**。
  ★ **同一个编号也是媒体对象表的槽号**：⇒ 一个操作数同时选中**媒体对象表的一格**与**一张纹理**，⛔ 不许只做其中一件；**三件事的先后就是上面的次序**（先填媒体格、再打开影片、后判纹理槽），⛔ 不许把次序换掉 —— 换掉会让"纹理槽为空 ⇒ 抛出"这条路径少填一格、或留下一个与实现无关的媒体格状态。
- **第 10 个操作数**同样只是一个**名字 id**（用于 ③ 之后的「取文件并配置」），**不**写进记录。
- 记录里写下：种类 = 1；**时间戳格 = 0**；**延迟**（第 11 个操作数）与**持续时间**（第 12 个操作数）；**影片纹理编号**（第 2 个）；**覆盖区间的起点键**（第 3 个）与**个数**（第 4 个）；**目标矩形**的四边，由第 5、6 个操作数与「第 5 + 第 7」「第 6 + 第 8」组成（**宽高是加出来的，不是单独存的**）；以及一个取 0 / 1 的**标志**（第 9 个操作数）。
- **读的不对称（合同）**：种类 1 的绘制支**只读「持续时间」格** —— 影片结束后**该格非 0** ⇒ 置一次场景「有动画」然后把它清 0；「延迟」格在本条**没有观察到的读者**（本版不规定它对这个种类的意义）。⛔ 不许因为"种类 0 / 3 用这两格算进度"就给种类 1 也套上同样的推进公式。
- 记录里还有**两格不被本条写**；本条只保证"不写"，不保证它们的值。
- 写成功 ⇒ 场景标**脏**，并置场景的「有动画」（与「脏」是两个不同的格）。

**读序（合同）**

一条 12 个操作数的指令**不是**按 1..12 依次读的 —— **读序是合同**（可观察后果 = 抛在哪一步之后、哪些操作数还没被读）。「次序」一列是读的发生顺序，同一操作数可以出现两次：

| 次序 | 读的是 | 读来做什么 / 什么时候才读 |
|---|---|---|
| 1 | 第 2 个 | 选媒体对象表那一格（① 的判据） |
| 2 | 第 1 个 | **只在 ① 真的建了新对象时**：解析成名字，用来定通道并建播放后端（②） |
| 3 | 第 10 个 | ③ 通过（纹理槽非空）之后：解析成名字，**取文件并配置** |
| 4 | 第 11 个 | 写进对象的一格（本版未取证那一格的读者 / 用途） |
| 5 | 第 12 个 | 配置播放时长 / 速率（交给播放接口；**只在通道 0 上**发生，另一个通道上这一步不产生请求） |
| 6 | 第 7 个 | 遮罩的宽；也是目标矩形右边「= 第 5 + 第 7」里的第 7 |
| 7 | 第 8 个 | 遮罩的高；也是目标矩形下边「= 第 6 + 第 8」里的第 8 |
| 8 | 第 9 个 | 遮罩取值选择（= 1 ⇒ 填 0；≠ 1 ⇒ 填 255） |
| 9 | 第 5 个 | 目标矩形的左边 |
| 10 | 第 6 个 | 目标矩形的上边（第 6 个的**第二次**读） |
| 11 | 第 12 个 | 记录「持续时间」（第二次读） |
| 12 | 第 11 个 | 记录「延迟」（第二次读） |
| 13 | 第 9 个 | 记录「标志」（第二次读） |
| 14 | 第 4 个 | 记录「区间个数」 |
| 15 | 第 3 个 | 记录「区间起点键」 |
| 16 | 第 1 个 | 记录「命令键」（第二次读，**最后**一个） |

- **抛出点只有两处**（② 的后端建不起来、③ 的纹理槽为空），且都在**读完第 2 个（以及 ② 那一支的第 1 个）之后**、**第 10 个及以后之前** ⇒ 这两支抛出的那一刻，**第 3..12 个一个都还没读**（不会触发它们身上的操作数类型异常）；第 1 个在**媒体格本来就非空**时**没读**（② 整段跳过）。
- ③ 之后本条**自己不再抛**（它的两个抛出点都在 ③ 之前）：之后那 14 次读只喂各自的写入 / 请求，**不再有**「旧记录不动」这种早退。

**打开影片（第 ② 步）**

- **做的事**：把第 1 个操作数解析成一个**名字**（解析规则见下「名字的解析（合同）」），用这个名字的**格式标记**定下**通道**，再建立该通道的**播放后端**。⇒ **通道在同一个动作里定下**（判据 = 名字里有没有 `WMV` / `MP4`，见「渲染请求边界」的媒体对象；对象建立时通道是 0）。★ **名字本身不留在对象上**：引擎只从它取出通道，此后**不读回**它（⛔ 不许写成"对象记住了影片名"）。
- **它只发生在 ① 建了新对象的那一支**：格本来就非空 ⇒ ① 不动对象、② **整段跳过** —— 既不打开影片、也不改通道 ⇒ 那条旧对象的**通道保持原样**（对象上本来就没有存名字，所以也没有"换名字"这回事）；⇒「打开失败」这一支在**格非空时根本不可达**。
- **失败判据与后果**：这条对象报告「打不开」（**播放后端**建立失败；★ 名字在这一步只是被交给对象并定下通道，失败**不是**「影片文件读不到」）⇒ 引擎**抛出异常终止本条**（异常文本的意思 = 「影片初始化失败、无法播放影片」），**不是**错误通道上报。此时四处状态是：
  - **媒体对象表那一格**：**已填** —— 就是 ① 刚建的那条对象，**不回收**；它的**通道已经定下**（通道在后端建立之前就写进去了），只是后端没建起来；**影片文件 id 还没写**（那是 ③ 之后「取文件并配置」那一步的事）；
  - **命令记录**：**不动** —— 旧记录原样留着，不删也不写（写记录在全部三步之后）；
  - **场景「脏」**：**不置**；
  - **场景「有动画」**：**不置**。
- **与纹理槽那一支的关系**：**同为**「抛出异常终止本条」，**同**留下已填的媒体格、**同**不动命令记录、**同**不置「脏」/「有动画」；差别只有**触发条件**（打不开 vs 纹理槽为空）与**异常文本**。★ 两条**互不替代**：② 被跳过**不等于** ③ 也跳过 —— 格非空时 ② 不执行，但 ③ **照常判**。

**其后各步（与「播影片」对照）**

对照：`0x20f` 那条的次序是 **初始化后端 → 绑定门 → 取文件并配置 → 应用音轨类别 / 音量 → 启动 → 置影片位**（见「等待、影片与空操作」的「播影片」）。本条的对应关系逐项如下 —— 这**不是**同一条流水线：

- **有「初始化后端」**：第 ② 步，用第 1 个操作数的名字（通道由名字定）。
- **有「取文件并配置」**：第 ③ 步之后、写记录之前，用**第 10 个操作数**；它同时把这条影片**绑到那一格纹理**上。★ 这一步的**返回值不被检查**（配置失败 ⇒ 本条照样往下写记录）。
- **没有「启动播放」**：本条**不**发动播放。
- **没有「置影片位」**：本条**不**写影片位。⇒ 让门等它的是**谓词 B** 而不是影片位：这条对象的生效参数恒为 **6**（`(6 & 5) == 4`）⇒ 影片结束、对象被释放之前门**不放行**；叠画本身由命令档逐帧做。
- **取代「启动」的是「待办启动」**：本条把对象置成**待办启动** —— 待办标志置起、**待办参数 = 选项字，固定为 6**（⇒ 循环位 = 0、第 2 位置起；音轨类别也从**同一个固定值**取，**不读**脚本操作数）。真正的启动由**影片对象表服务**（每拍逐对象那趟，见「执行与时间」）在消费这个待办时发生 —— 那一支的读侧本版未成篇（见「等待、影片与空操作」的残差 `RES-WAIT-MOVIE-PENDING`）；另有两处也写同一组待办格，本版不展开它们。
- **另写一个引擎标记**：在「取文件并配置」之后、读第 12 个之前，它把引擎的「**有活动对象**」标记写 1（与 `0x20f` 在启动之后写的是**同一格**）。⇒ 这一格**不是**「有影片在播」的结论：种类 1 在**启动之前**就置它，而「执行与时间」的影片对象表服务在每趟收尾时按「还有没有**已启动**的影片」重算这一格 ⇒ 这个 1 只活到那一趟跑完（待办启动是否在同一趟里被消费，见残差 `RES-WAIT-MOVIE-PENDING`）。
- ★ 因此本条**没有**「按脚本给的选项字分流」这一维：种类 1 的影片恒按选项字 6 处置。⛔ 不许给它补一个"隐藏的第 13 个操作数"，也⛔ 不许把 `0x20f` 的启动 / 置位两步照搬进来。

**名字的解析（合同）**

- **没有"影片名表"这张专用表**：第 1 / 第 10 个操作数都是**名字 id**，由引擎的**名字库**解析 —— 与「播影片」那一族的资源 id **走同一个名字库、同一套编码**（同一个整数在几处指同一个名字；名字的**内容**是程序 / 游戏数据提供的，不是引擎行为）。★ 它与《总览与约定》的**统一文件 id** 是否同一空间，本版只钉到「同一个名字库」这一层（脚本 id 的解析路径不在本条）。
- **id 的两种形态**：高 8 位**非 0** ⇒ 高 8 位选一个**子表**、低 24 位是**该子表里的记录序号**；高 8 位为 **0** ⇒ **顶层表**里的记录序号（上限 = 该表自己的计数格）。⇒ 两种形态的解析结果都是**一条定长名字记录**，名字串取自这条记录。
- **越界（序号 ≥ 该表的计数）/ 负数 / 子表指针为空** ⇒ 解析结果是一段**字面量 `ERROR`**：解析**这一步**不抛、也不向错误通道上报，就把它当普通名字继续往下走（⇒ 通道按"没有 `WMV` / `MP4` 标记"判、后端仍会建立）；后续各步自己的失败处置见各步（例如「取文件并配置」的返回值不被检查）。
- **两个 id 各自独立、用途各一处**：第 1 个的**只**用于定通道 / 建后端（不写进记录、不留在对象上）；第 10 个的**只**用于「取文件并配置」（不写进记录，配置完就丢）。⛔ 不许把两者当成"同一份名字的两次使用"。

**第一帧画 / 之后只标记（判据与时机）**

- **判据字段 = 记录的「时间戳」格**。写记录时它被清 0。
- **时机在渲染步，不在写表时**：命令档每帧按命令键升序遍历到这条命令时，若时间戳为 0 ⇒ 把它写成**本帧的场景时刻**；随后把时间戳与**本帧场景时刻**比较：
  - **相等 ⇒ 第一帧**：把覆盖区间内的条目画出来（并记成「本轮已消费」），再把**本条记录里的影片纹理**用一次效果绘制叠上去（效果的选择属机器细节）；
  - **不等 ⇒ 之后**：只把覆盖区间内的条目记成「本轮已消费」，**一个绘制请求都不发**（包括影片纹理那次效果绘制）。
- 两路**都**会走同一段收尾（每帧一次）：若场景的「影片停止」标记为 1 ⇒ 结束该影片；影片对象已不存在 ⇒ 持续时间非 0 时置场景「有动画」、把**持续时间清 0**、并按下面的规则改该影片纹理的**逐像素遮罩**；影片对象还在 ⇒ 置场景「有动画」；最后把记录里的**目标矩形**交给该纹理对象。
- **第 9 个操作数 = 遮罩取值选择**：遮罩是"每像素 1 字节、按第 7 / 第 8 个操作数给出的宽 × 高分配"的一块缓冲。它**只在每帧尾段那次混合里使用**：混合的**源 = 离屏画布**、**目标 = 命令自己的纹理**；遮罩按像素乘**源像素的最高字节（透明度）**，**三个颜色通道逐位不变**。结果最高字节 ≈ `源高字节 × 系数 / 256`（截断）：系数 `0` ⇒ 高字节清零；系数 `255` **不是恒等**（`0xFF` 会变成 `0xFE`）。遮罩坐标以**目标矩形左上角**为原点、行距 = 矩形宽。两个时刻：
  - **命令写表时**：第 9 个操作数 ≠ 1 ⇒ 遮罩填 `255`；= 1 ⇒ 填 `0`。
  - **影片结束之后**（影片对象已不存在、持续时间刚被清 0）：第 9 个操作数 = 1 ⇒ 遮罩填 `255`；≠ 1 ⇒ 填 `0`。
  ⇒ 两次填充的取值**互为补**。⛔ 不许把两个时刻写成一个，也不许只写"填 255 / 0"而不写各自动的判据。
- ⇒ 「第一帧」不是"写记录的那一帧"，而是"**写记录之后第一次被命令档遍历到的帧**"。⛔ 不许把它实现成"记录被写入时就画"或"每帧都画"。
- **重写同一命令键 ⇒ 时间戳重新清 0**，于是下一次遍历又回到"第一帧"。
- **第一帧路径**里还**可能**有一趟「**覆盖区间之下**」的绘制（把键小于覆盖区间起点的条目按键序画一遍，且**不**记成已消费）：它**只随第一帧路径发生**（不是每帧），且还要同时满足 ① 绘制设备就绪；② 场景的**着色器能力档 < 2**（档 = 引擎按像素着色器版本取 0 / 1 / 2，可被显示配置覆盖；2 = 支持 PS 2.0）。满足时这些条目会被发**两次**（一次进离屏画布、一次由收尾扫描发到原目标）。**目的**：给低档的不透明离屏画布垫底（见「区间之下」的口径）。

**种类 2（`0x24f`，10 个操作数）：抹除命令**

它把**两段**绘制键区间各画进一块**引擎离屏画布**，再按一个**抹除图案**把它们合成到**命令自己的纹理**上。抹除发生的**矩形**不来自本命令的操作数，而来自**绘制项表**里与本命令**同键**的那条绘制项。

**操作数 → 记录**

| 操作数 | 写进记录的东西 |
|---|---|
| 1 | **命令键**（命令表的排序键）。它**同时**被记进记录里的一格，命令档用它去绘制项表里找"抹除矩形" |
| 2 | **纹理编号** = 命令自己的纹理（写表**之前**会先发一次建 / 换纹理请求，判据与种类 0 相同） |
| 3 / 4 | **区间 A** 的「起点键 / 个数」 |
| 5 / 6 | **区间 B** 的「起点键 / 个数」 |
| 7 | **类型 / 模式**（抹除图案的编号） |
| 8 | **分割幅**（图案被分成几道） |
| 9 / 10 | **延迟 / 持续时间** |

记录里另有：**时间戳**（写表时清 0）、**种类 = 2**。⛔ 不许把两个区间合成一个：区间 A 只喂第一块画布、区间 B 只喂第二块。

**先校验、后写表**（两条**顺序固定**、后果**不同**）：

- **分割幅 < 1** ⇒ 上报「分割幅が０以下です」，然后把**分割幅按 1**、**类型按 −1**、**延迟与持续时间清 0**，并**照常写记录**（⇒ 表里会留下一条类型 = −1 的命令）。★ 这一支**跳过**类型校验。
- **类型 / 模式 ∉ [0, 11]**（**两端闭、含负数**）⇒ 上报「タイプが不正です」并**一个字段都不写**（不建记录、不删旧记录）。⛔ **不许把负数放行**：负数与 > 11 走**同一个**错误支。
- 通过 ⇒ 替换命令记录（含类型 0..11 与分割幅），并置场景**脏**。本条**不**置「有动画」。
- **建 / 换纹理请求在两条校验之后**（分割幅 < 1 支跳过类型校验、但照常走到请求点）：校验失败（类型 ∉ [0,11]）⇒ **不发**请求、不写表；校验通过（含夹取后的那一支）⇒ 先发请求（判据同种类 0，返回值不看），再写表。

**类型 = −1 的副作用（合同）**：命令档每帧看到类型 < 0 的命令时，会把场景的**「强制完成」位**置 1（读取点见「显示适配」与「场景计时窗」；颜色窗的推进是**同一渲染步内部更早的子步**，它看不看得到本步置的 1 见「场景计时窗」的「强制完成」三条：**绘制项当帧看不到**，**网格按它在本步处理中的位置**）。这是"分割幅 < 1"那条错误记录的唯一可见后果，⛔ 不许让它静默。

**12 种抹除图案（条件表）**

- **每个图案单元两趟落笔**：先画布 36（区间 A）、后画布 37（区间 B），两笔的矩形**相接不重叠**、合起来盖住该单元。**12 种都用两块画布**。一族的一个"单元"是整幅抹除矩形（⇒ 2 趟）；二/三族的一个单元是**一条带**（⇒ 每条带 2 趟，共 `条带数 × 2` 趟）。
- 每笔除矩形外还带两个位置三元组：一个恒为抹除矩形左上角；另一个是该笔矩形左上角**加上视野偏移**（视野偏移 = **负的**视口原点 / 内容缩放；窗口态恒 0）。两者只影响落点，不影响矩形。⇒ 合成的落点只由这两个值决定，⛔ 不要在图案里再改一次符号。
- 混合与颜色 12 种完全一样（同一档混合、颜色末参全不透明）；⛔ 不许按模式区分 alpha / 混合。
- 输入只有五样：抹除矩形、分割幅 `S`、时间戳、延迟、持续时间（外加场景时刻）。`经过时间 = 现在 − (时间戳 + 延迟)`，`步长 = 持续时间 ÷ 步数`，`步序 = ⌊经过时间 ÷ 步长⌋`（不夹取）。
- **一族（0..3）整幅、按"道"跳**：`步数 = ⌊轴长/S⌋ + 2`，`让出量 = S × 步序`（0/2 用步序，1/3 用步序+1）；轴 = 宽（0/1）或高（2/3）；偶数从左/上、奇数从右/下。
  - 0：第 1 笔 `[左+让出, 上, 右, 下]`、第 2 笔 `[左, 上, 左+让出, 下]`；
  - 1：第 1 笔 `[左, 上, 右−让出, 下]`、第 2 笔 `[右−让出, 上, 右, 下]`；
  - 2：第 1 笔 `[左, 上+让出, 右, 下]`、第 2 笔 `[左, 上, 右, 上+让出]`；
  - 3：第 1 笔 `[左, 上, 右, 下−让出]`、第 2 笔 `[左, 下−让出, 右, 下]`。
- **二族（4..7）条带、同相、逐像素**：`条带数 = ⌊轴长/S⌋ + 1`、带宽 = S；`步长 = 持续时间 ÷ (S+1)`，步序单位是**像素**，`让出量 = clamp(步序, 0, S)`（**宽度**，不是位移）。
  - 4（左→右）：第 2 笔 `[带左, 上, 带左+让出量, 下]`、第 1 笔 `[带左+让出量, 上, 带右, 下]`；
  - 5（右→左）：第 2 笔 `[带右−让出量, 上, 带右, 下]`、第 1 笔 `[带左, 上, 带右−让出量, 下]`；
  - 6（上→下）：第 2 笔 `[左, 带上, 右, 带上+让出量]`、第 1 笔 `[左, 带上+让出量, 右, 带下]`；
  - 7（下→上）：第 2 笔 `[左, 带下−让出量, 右, 带下]`、第 1 笔 `[左, 带上, 右, 带下−让出量]`。
- **三族（8..11）条带、错相、逐像素**：`步长 = 持续时间 ÷ (S + 条带数)`；第 `i` 条带的 `让出量 = clamp(步序 − i, 0, S)`（**宽度**；第 i 带晚 i 个像素步），非正 ⇒ 第 2 笔宽 0（空）；方向与矩形公式同二族。
- **条带网格**（二/三族共用）：每条带宽都是 S；`余数 = 轴长 mod S`。4/8、6/10 的**最后一条带**贴矩形远边（第 0 带越出近边 `S−余数`）；5/9、7/11 的第 0 带贴远边、右/下缘越出 `S−余数`。⇒ 网格总覆盖 `S × 条带数 ≥ 轴长`，**多出量 = S − 余数**（余数 0 ⇒ 多出 S，即整整一条带在矩形外）；余数 0 时也多算一条带。
- **提前走完**：一族在约 `轴长/(轴长+2S)`、二族在 `S/(S+1)`、三族在 `(S+条带数−1)/(S+条带数)` 处就走满 ⇒ **到期 ≠ 动画走完**。
- `类型 < 0` 的命令落不到任何图案（一笔都不画），但「强制完成」副作用照做。
- **保持未定**：持续时间为 0 时步长为 0（除零）的后果；抹除矩形之外像素会被第二块画布覆盖的可见后果；两块画布的领域名；"晚 1 像素"的设计意图；空矩形 = 不画是绘制入口的性质（不是图案规则）。

**种类 3（`0x250` / `0x251`，10 / 12 个操作数）：模糊转场命令**

两条都是**同一种命令**，只有**变体格**不同：先把一段绘制键区间画进引擎的离屏目标，再按「**起值 → 终值**」的插值参数做一次模糊合成，合成结果落在**本条自己的纹理**上。

- 公共部分：
  - **第 1 个操作数 = 命令键**；**第 2 个操作数 = 纹理编号**（像种类 0 一样，写表**之前**会先发一次建 / 换纹理请求）；
  - **第 3 个 = 覆盖区间的起点键**、**第 4 个 = 个数**；
  - **延迟 / 持续时间**：`0x250` 取第 9 / 第 10 个操作数，`0x251` 取第 11 / 第 12 个操作数；
  - 记录里写下：种类 = 3、时间戳格 = 0、变体格（0 或 1）、纹理编号、区间起点与个数、延迟与持续时间，以及**若干对「起值 / 终值」格**；写成功 ⇒ 场景标脏（**不**置「有动画」——那由推进决定）。
- **变体 0（10 个操作数）= 「滑移模糊」**：插值的是**长度**（第 5 → 第 7）与**角度**（第 6 → 第 8）；另有两格被写成 **0**（本变体不用）。
- **变体 1（12 个操作数）= 「缩放模糊」**：插值的是**长度**（第 5 → 第 8）、**中心横向**（第 6 → 第 9）与**中心纵向**（第 7 → 第 10）；另有两格被写成 **0**（本变体不用）。
  - 中心两个值是**像素坐标**（合成时各除以该纹理的宽 / 高）。⛔ 不许把它们当已归一化的 0..1 系数。
- **时间戳**：写记录时清 0；命令档**首次**遍历到该记录时把它盖成**本帧场景时刻**（与种类 1 同一规则）。
- **推进**：已过时间 = 本帧场景时刻 − 时间戳 − 延迟；**进度 = 已过 / 持续时间**。
  - 进度**用尽**（或场景的「强制完成」位为 1）⇒ 直接用**终值**，并把**持续时间清 0**（动画到此为止）；
  - 进度**进行中** ⇒ 按进度在每对「起值 / 终值」之间**线性插值**，并置场景的「有动画」。
  - 进度**不夹取**：引擎只判"上界"，已过为负时按同一公式**外推**（会得到起值之外的值）。⛔ 不许实现成 clamp(0,1)。
  - ⇒ 变体格只选**哪一种模糊**（长度 + 角度 / 长度 + 中心），**不**改变"先画区间、再插值、再合成"这个次序。

**命令档对覆盖区间内的条目发什么绘制请求**

- 引擎按**条目键**取条目**自己的**记录并发请求：辅助表 B、网格、绘制项各一次。**网格 / 绘制项**用各自记录里的纹理 / 顶点；**辅助表 B** 也用**它自己那条记录**（它值里各字段的含义本版未取证，见残差 `RES-SCENE-ENTRY-TABLE-FIELDS`）。**命令记录里的纹理不用于这些条目**。
- **绘制项仍然走「绘制项的消费者」**（与收尾扫描同一个入口）；区别只有一处：命令档给它多传一个**「跳过额外变换」**标志，收尾扫描总是传"不跳过"。
- 每条画完**立刻**记成「本轮已消费」⇒ 收尾扫描不会再发一次。因此**种类 0 / 2 / 3** 的覆盖区间条目**每帧恰好一次**；**种类 1** 只在第一帧画，之后各帧**零请求**（但仍把条目记成「本轮已消费」）。
- **种类 2 的抹除矩形**：命令档按键去**绘制项表**找同键的那条绘制项，用它**自己的浮点位置与四条边**算出矩形；**找不到** ⇒ 把该命令的**持续时间清 0**，并**中止整趟命令档**（不是跳过这一条继续）。⛔ 不许把"缺条目"实现成 continue。
  - **矩形上的两个偏移量**：交给绘制之前，两个绘制**位置**分量各被减去一个偏移；偏移在**窗口态**恒 0；**占满屏态**按**显示适配的视口原点与内容缩放**算（「固定分辨率模式」下原点 = (0,0)、缩放 = 1 ⇒ 偏移也是 0）。"屏幕形态"= 引擎的屏幕形态档（来自配置 `display:ScreenMode` 是否非 0），场景里保存它的一份副本。⛔ 不许把偏移加到"抹除矩形的四条边"上（它减的是**绘制位置**）。★ 用途是"占满屏态下把屏幕坐标折回离屏画布的坐标"（画布 36/37 与屏幕同尺寸但不带那层变换）。★ 原点 / 缩放与位置的组合次序：**先加偏移（负的原点/缩放）、再按档决定是否乘缩放与取整**（见「显示适配」的折回段与 5.1）。
- **辅助表 A 不参与**：命令档没有它的发射入口（它永远落到收尾扫描）。
- 命令档把这些条目画进**离屏目标**：进命令档时记下当时的渲染目标，画之前切到离屏、画完**恢复**；因此收尾扫描画在原来的目标上。
- **命令自己的纹理**用在**另一类**请求上：命令档先把覆盖区间内的条目画进**引擎的离屏画布**（一个与屏幕同尺寸的内部画布纹理，不是脚本纹理），之后：
  - **种类 1**：把**离屏画布整幅**做一次**矩形表面拷贝**，目标 = **命令自己的纹理**（记录里的影片纹理编号）；然后**每一帧**尾段再按记录里的**目标矩形**做一次**逐像素遮罩混合**（遮罩见上）。
  - **种类 2**：同样有这条通道。它先把区间 A 画进**第一块离屏画布**、区间 B 画进**第二块**，然后按**类型**选出的图案把它们合成到**命令自己的纹理**上；图案与时间进度由**延迟 / 持续时间 / 时间戳 / 分割幅**决定。12 种图案的逐模式条件见下。
  - **种类 3**：把离屏画布按各自的图案 / 滤镜**画进或合成进**命令自己的纹理。
  - 两个技法名 `"SlideBlur"` / `"ZoomBlur"` 是**引擎内嵌的效果资源**（资源字节就是着色器源码），各 1 个 pass、只采样一张贴图、Clamp+Linear；归一化用**命令自己纹理**的宽高。
  - `"SlideBlur"`：沿角度方向的**对称 21 抽**（`i = −10..10`），第 `i` 抽的采样偏移 = `方向 × (i/10) × k`，`k = 长度 / max(宽,高) × 0.05`；权重 0.0476（和 ≈0.9996）。
  - `"ZoomBlur"`：朝中心的**单侧 10 抽**（`i = 0..9`），第 `i` 抽的采样偏移 = `normalize(方向) × (i/10) × (1/1024) × 长度 × |方向|`（`1/1024` 是硬编码），权重和 = 1。
  - **退路**（无效果接口 / 能力档不足）：CPU 锁表面逐像素模糊；它与技法路径是**两套实现**，⛔ 不许写"像素等价"。
  - **混合状态**：技法 pass 不声明混合 ⇒ 继承设备状态。命令档入口前**没有**任何混合写入 —— 渲染步之内与之外都成立：
    CG / 图像的全屏支路只写"中立对"（源 1 / 目标 0），文字与影片**没有**混合写点，Live2D 的写点被状态块原样还原且只在命令档之后。
  - **条目自己的混合档**：每个条目记录里有一格是**混合档**（网格取 `0x322` 的第 2 个操作数、绘制项取 `0x203` 的第 2 个操作数，默认 0）。
    网格发射器**总会**写"混合开"，再按档写因子（档 1 / 2 / 3 各一套；**其它值（含 0）⇒ 源透明度 / 一减源透明度**），画完复位成中立值。
    ⇒ **“网格条目不设混合”是错的**：它设混合，只是**档 0 不等于“不写因子”**。绘制项走另一条路径：档 0 ⇒ 不写任何因子，档非 0 才写。
    （混合开 / 源因子 = 1 / 目标因子 = 0 / 运算 = 加 ⇒ **覆盖式写入**）。⇒ 种类 0 出口 A、种类 3 技法、种类 3 CPU 退路进入时都是中立值；
    **只有种类 0 的默认退路不同**：它不写任何因子，但**无条件关掉 alpha 测试**，并在满足条件时写一次 (源=1,目标=0)。
  ⇒ **离屏画布本身从不出现在呈现侧**：它的内容必须由命令拷 / 画到"命令自己的纹理"上；**四个种类全体都有这条通道**（⛔ 不要再把种类 0 排除在外）。
  - **种类 0**：区间 A 画进**第一块画布**、区间 B 画进**第二块**，然后把**两块都合成到命令自己的纹理**上 —— 命令档把绘制目标切到该命令记录里的纹理编号，此后两块画布作为**两张源贴图**被整幅画在同一个矩形上（矩形 = 各块画布自己的宽 × 高、位置与 UV 全 0）。合成量只有一个**进度**（`∈ [0,1]`）：
    - 已到期或场景「强制完成」⇒ 1（并把该记录的**持续时间清 0**；此后只要场景时刻还在"时间戳 + 延迟"之后，判据一直落回"已到期" ⇒ 进度恒 1）；
    - 未开始（`现在 ≤ 时间戳 + 延迟`）⇒ 0（并置场景「有动画」）；否则 `(现在 − 时间戳 − 延迟) / 持续时间`。
    - **两条实现路径（同一出口，引擎按机器能力选）**：有渲染效果接口且着色器能力档 ≥ 1 ⇒ 以一张满屏四边形、在名为 `"Fade"` 的技法里把两块画布作为 `"Tex0" / "Tex1"`、把**进度**作为 `"Alpha"` 一次性合成。Fade 是**引擎内嵌资源**、1 个 pass、只有像素着色器、**不声明混合**；能力档 1 与 ≥2 用**不同版本**：低档四通道同式 `c0(1−α)+c1α`；高档颜色按 `clamp(c1.a×α/a_ret, 0, 1)` 加权，其中 `a_ret` 是该像素**源纹理的 alpha**（`a_ret = 0` 时是 0/0，见残差）；高档下 `c0` 那一半的权重未在源码里单独出现（由 `1 − c1 权重` 隐含）。否则（默认） ⇒ 先以**不透明白**整幅画第一块，再整幅画第二块，第二笔的**颜色实参** = `ARGB(round(进度 × 255), 255, 255, 255)`。⛔ 不许写"两条路径像素等价"（低档"同形"但差量化 / 采样 / 混合前提；高档不同形）。
    - ⛔ 不许把种类 0 写成"画进离屏画布即丢弃"、"留给别人来取"或"命令档结束时把画布呈现出去"；⛔ 也不许把两条路径写成"两次绘制"与"一次绘制"的**可见差异**断言（技法内部如何组合两张贴图本版不规定）。
    - **区间之下**：能力档 < 2 时，每块画布额外先画一趟"**区间之下**"（从表首到本段起点），且**跳过落在另一段区间里的条目**、**不**把条目记成「本轮已消费」；能力档 ≥ 2 时这一趟不发生。
  ★ 机器侧的两块画布就是纹理槽 **36 / 37**（覆盖条目按 `区间 A → 36`、`区间 B → 37` 分流）。"命令自己的纹理"由**脚本 / 绘制项**在之后送到呈现侧；命令档本身不把它送到呈现侧（种类 1 的"叠上去"是叠到纹理 / 画布，不是送呈现侧）。⛔ 不许实现成"命令档结束把离屏画布呈现出去"；⛔ 不许把种类 1 的那一次写成"用某编号画影片纹理"（该编号是**源画布**，方向是 **画布 → 影片纹理**）。
  - **种类 1 的时点**：矩形表面拷贝在**每个第一帧**的覆盖区间画完之后做一次；随后**每一帧**尾段做一次遮罩混合，**源 = 离屏画布、目标 = 命令自己的纹理**。命令档结束时恢复原渲染目标。

**种类 0 的建 / 换纹理请求失败**

- 请求在**写表之前**发出，是这条命令唯一的外部请求。
- 请求**失败**时：
  - **仍然写表**：旧记录照删、新记录照写、场景照标脏。⛔ 不许实现成"请求失败就跳过写表 / 保留旧记录"。
  - **会上报**：错误通道收到**一条**说明，带纹理编号；这条上报**不附脚本位置**（与绘制阶段的错误不同）。
  - 那条纹理槽里**仍然留下一个"建失败"的对象**（槽不是空的）⇒ 之后"槽是否为空"这个判据**不再**能识别它；是否重建由"**格式是否与当前显示格式相符**"决定。
- 另外：**格式相符时不发请求**（因此也不会产生这条失败上报）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某命令键上的命令 | 命令表里该键的一条记录（种类 + 该条自己的格；同键旧记录已被删） |
| 场景需要重绘 | 脏标记 ← 1 |
| 场景有动画 | 「有动画」标记 ← 1（种类 1 写表时；种类 3 由推进置位） |
| 错误通道 | 种类 2 的两条校验**各**最多上报一次；种类 0 的请求失败**另**上报一条（不带脚本位置） |
| 覆盖区间内的条目 | 命令档画一次并置「本轮已消费」；收尾扫描不再画 |

**成立条件**

- **同键是替换**：⛔ 不许把它实现成"命令列表追加两条"，否则同一键会执行两次。
- 种类 2 的两条校验**后果不同**：模式 > 11 在写表之前**直接返回**（表不变）；个数 < 1 则是**先报告、再把个数夹成 1 / 模式夹成 -1 后照写**。⛔ 不许把两条合并成一个"非法就拒绝"。
- 「脏」与「有动画」**两个格**：⛔ 不许合并；种类 1 写表时置「有动画」。
- 命令**不立即画**：⛔ 不许在这些 handler 里发**绘制**请求（建 / 换纹理请求是例外，且只发生在写表前）。
- 操作数 1 是**命令键**（命令表的排序键），不是绘制键；两者都是整数键，但作用域不同（命令档按操作数给出的绘制键区间去覆盖条目）。⛔ 不许把两者当同一套编号。
- 种类 1 的「第一帧」由**时间戳格**判，⛔ 不许用"记录刚被写"或"每帧都画"代替。
- 命令档对覆盖区间内的条目**每帧只画一次**（**种类 0 / 2 / 3**；种类 1 之后各帧零请求，见上）；⛔ 不许与收尾扫描各画一次。
- **记录的三档判据按 32 位有符号比较**：到期 / 延迟内 / 推进中 都由「时间戳 + 延迟 + 持续时间」与场景时刻、以及由它们算出的进度决定，这几处一律按 **32 位有符号**（与颜色窗 / 源矩形窗的**无符号** `≥` **不是同一个比较**）；⛔ 不许改成无符号、也不许把两族并成一句。
- **附加组派生不是第二次绘制**：它改的是主绘制的输入（见「绘制项的消费者」）。

**可证伪**

- 对同一个命令键连写两次（不同参数）：若命令表里留下两条、或渲染时执行了两次 ⇒ 本条错。
- 用种类 2 传 `类型 = 12`：若表里多了一条记录（或旧记录被删）⇒「先校验后写」错。
- 用种类 2 传 `分割幅 = 0`：若错误通道没有一条「分割幅」说明 ⇒ 错；若表里**没有**那条"类型 = -1、分割幅 = 1"的记录 ⇒ 也错。
- 写一条种类 1 命令 → 跑**两次**渲染步：若第二次仍然发出了覆盖区间内条目的绘制请求（或仍然发了影片纹理的效果绘制）⇒ 第一帧判据错。
- 把种类 1 的第 2 个操作数指向空纹理槽：若本条照常写记录（或走错误通道而不是抛出）⇒ 口径错。
- 让种类 1 的**打开影片**失败（第 2 个操作数指向空媒体格、名字指向打不开的影片）：若本条照常写记录、或走错误通道而不是抛出、或那一格被清空（新建的对象被回收）、或场景被标脏 / 置「有动画」⇒ 打开失败的后置状态写错。
- 先用同一个第 2 个操作数把媒体格填上（一次成功的打开），再**换第 1 个操作数**（另一个名字 id）写一条种类 1：若那条旧对象被重新打开、或换了通道 ⇒「② 只在格空时发生」写错；此时若整条被跳过、连纹理槽也不判 ⇒ 把 ② 的跳过当成了 ③ 的跳过。
- 覆盖区间内放一条绘制项（纹理 A），命令记录里的纹理写 B：若绘制请求带的是 B ⇒ 命令档请求口径错。
- 只放一条辅助表 A 的条目并落在覆盖区间内：若它在命令档里被画 ⇒「辅助 A 不参与」错。
- 让纹理建 / 换失败后执行一条种类 0 命令：若表里没有记录、场景没标脏，或错误通道没有那条带编号的说明 ⇒ 失败路径错。
- 用种类 1 与其它种类各写一条：若两者都置了「有动画」⇒ 标记合同错。

**残差**

- `RES-SCENE-COMMAND-WIPE-BOUNDARY`（unknown）：图案边界四件——持续时间为 0 的除零后果、抹除矩形之外像素被第二块画布覆盖的可见后果、两块画布的领域名、三族"晚 1 像素"的设计意图。图案本身的算式已全部落定。下一步：截帧 / 真机观察四件边界。
- `RES-SCENE-COMMAND-KIND0-ALPHA`（unknown）：种类 0 默认合成路径第二笔的颜色实参带"进度×255"的最高字节；它在呈现侧的可见后果（是否真的按 alpha 混合）未取证。下一步：读纹理对象绘制方法体的混合状态，或截帧对比进度 0 / 0.5 / 1。
- `RES-SCENE-COMMAND-KIND1-FLAG`（unknown）：第 9 个操作数 = 影片纹理遮罩的取值，两个时刻与互补关系、以及"只改最高字节"的算术已定；未定：**画面极性**（系数 255 / 0 在呈现侧是可见还是全透明）与播放期间谁还会改遮罩。下一步：截帧两个取值；读呈现侧混合状态。
- `RES-SCENE-COMMAND-TEXTURE-RETRY`（unknown）：纹理建 / 换失败后会不会重试（槽非空 + 格式不符 ⇒ 每次同编号写入都再发一次）。下一步：故障注入，连续两次同编号写入，数错误通道条数。

### 绘制项：排颜色渐变窗（opcode 0x202）

<!-- rule: CORE-OPS-SCENE-202 -->

读五个操作数：**编号**、**延迟**、**持续时间**、**透明度**、**颜色**。
延迟与持续时间的单位是**毫秒**；起色是该项**当前颜色字段在每一步的值**（排窗不改它）。

- **终色** = 归一化(透明度, 颜色) —— 透明度段从「透明度」操作数来（< 0 时取该项当前颜色的透明度段），RGB 段从「颜色」操作数来（< 0 时取该项当前颜色的 RGB 段）。⇒ 终色是**唯一值**，四种组合逐个写死：
  - 当前颜色是**无颜色**：`透明度 < 0 且 颜色 < 0` ⇒ 终色 = **无颜色**（不动点）；`透明度 < 0 且 颜色 ≥ 0` ⇒ 透明度段 = `0xFF`、RGB 段 = 颜色参数的位 23–0；`透明度 ≥ 0 且 颜色 < 0` ⇒ 透明度段 = 透明度、RGB 段 = `0xFFFFFF`；两者都 ≥ 0 ⇒ 两段各取参数。
  - 当前颜色是**别的值** X：`透明度 < 0` ⇒ 透明度段 = X 的位 31–24；`颜色 < 0` ⇒ RGB 段 = X 的位 23–0；两支都为负 ⇒ 终色**逐位等于 X**；两支都非负 ⇒ 终色与 X **无关**。
  - 本条**不做**「当前颜色是不是无颜色」的判断：无颜色在这里只是一个普通取值。
- 只有该项的“已存在”位（**记录首字的第 0 位**，与 `0x1fb` 置的“有效”位是**同一位**）为 1 时才排窗：置“有窗”位（**首字第 1 位**；与 `0x220` 的“已配置”是**同一位**）、把窗起点清成 0（未盖章）、写延迟 / 持续时间 / 终色，
  并把场景标脏、标成"有动画"。
- "已存在"位为 0（含刚建出的默认记录）⇒ **一个窗字段都不写**。

**「场景有动画」标记的读者（闭集，四处）**

「场景有动画」是**场景级**标记，不是某一项的字段。★ 它就是别处写的**「场景待处理标记」**、以及**「等待谓词的待处理闩」** —— **同一格、三个名字**（⛔ 不许实现成两格；本章用「有动画」）。它的读者是**闭集，四处**：

1. **等待谓词**：它的**返回值就是该标记**（窗内那一支直接返回 1），调用方据此知道「这一帧场景还在动」；谓词里还有一步：场景的**状态位字**（见「场景对象表的清空」；★ 它与脚本 `0x24e` 写的**主循环模式字**是**同一格**，两个字名指同一个字）第 16 位置位、且该标记为 0 ⇒ 把那个状态位字**整字清 0**（为 1 ⇒ 一位都不动）。
2. **命令档出口（渲染步之内）**：把该标记与**「强制完成」位**按位或；非 0 ⇒ 置**脏**（脏的读者是「帧步进」的**就绪判据** a 支）。★ 这一步**不产生**第三个「本帧有动作」中间标记：它写的就是**脏**。
3. **渲染步收尾**：本步的该标记为 0 ⇒ 把**场景命令表整表清空**（不是"删掉已完成的那一条"；标记非 0 ⇒ 保留）—— 同「绘制顺序」的「命令表的生命周期」。
   —— 第 2、3 条合起来给出一个反直觉但真实的次序：该标记在渲染步**开头就被清 0**，所以「收尾时它仍非 0」只可能来自**本步之内**被重新置起（推进子步与渲染后端会置它）；⛔ 不许把它理解成「上一帧留下的值」。
4. 它**不**决定：某一项画不画、绘制顺序、清屏、窗是否到期。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某项的渐变窗 | 该项的延迟、持续时间、终色、"有窗"位、起点（0 = 未盖章） |
| 场景有动画（= 本步「还在动」） | 场景的一个标记（多处置 1；渲染步开头清 0；复位清 0；收尾据它决定**清不清命令表**） |
| 场景需要重绘 | 脏标记 ← 1（命令档出口按「有动画 ∨ 强制完成」置起；读者是就绪判据 a 支） |

**成立条件**

- 起点 0 是"未盖章"哨兵，不是"从 0 毫秒起算"。
- "已存在"门只看该项自己的位；没有别的前置。
- "已存在"与"有窗"是**两个不同的位**（第 0 / 第 1 位）：⛔ 不许把这两个名字实现成同一位。
- **到期判据**（排窗只写字段，判决发生在窗被推进时）：`现在 ≥ 起点 + 延迟 + 持续时间` 那一刻该窗**即已到期（相等已到期）**；
  **未到期时**，延迟段（`现在 ≤ 起点 + 延迟`）**算窗内**。
  ⚠ 这与等待指令自己的消息等待计时器的 `现在 > 起点 + 时长` **不是同一个比较**（那条相等仍算窗内，见「等待、影片与空操作」）。
  ⛔ 不许把本条排出的窗实现成"相等仍算窗内"（那是把两种计时的边界混成了一个）。
- 「场景有动画」标记的读者是**闭集**（四处）：⛔ 不许再为它发明「每项自己有动画位」的第二套语义。
- 渲染步**开头清 0** 是合同（不是实现细节）：它使「收尾处标记非 0」成为「本步之内被重新置起」的**证据**。
- 置 1 的写者**多**（多个设值 / 排窗入口 + 渲染后端）：⛔ 不许把「谁置它」写成某一条指令专有。
- 「等待谓词读它」与「窗推进读它」是**两件事**：前者是本标记（经返回值），后者是窗自己的三格。
- ★ **本标记与「脏」是两个不同的格，方向只有一个**：命令档出口把「本标记 ∨ 强制完成」**或进脏**（不是把脏与它按位或）；⛔ 不许反过来把脏当成读者的输入。
- ★ 「场景待处理标记」/「等待谓词的待处理闩」**不是另一个格**：它们是本标记的别名（同处清 0、同处读）。⛔ 不许为它们另建一格、也⛔ 不许让两处各写各的。

**可证伪**

（三条都以**该项的「已存在」位 = 1** 为前提 —— 位为 0 时本条**一个窗字段都不写**；`0x203` 建的默认记录**不置**该位 ⇒ 先用会置它的写入方（`0x1fb`）建条目，否则三条都观测不到终色。）

- 把某项的当前颜色先写成 X（例如 RGB = `0x345678`、透明度 = 255），再以「透明度 = -1、颜色 = -1」排窗 ⇒ 终色必须**逐位等于 X**；若得到黑 / 不透明白 / RGB 被清零 ⇒ 归一化错。
- 以「透明度 = 256、颜色 = `0x00ABCDEF`」排窗 ⇒ 终色 = `0xFFABCDEF`；若透明度没被夹到 255 ⇒ 错。
- 以「透明度 = 0、颜色 = `0x7F000000`」排窗 ⇒ 终色 = `0x00000000`（**全 0**）；若得到 `0x7F000000` ⇒ 把「颜色」的高 8 位也算进透明度了。★ 这条只能用**非负**实参：`0x8F000000` 按 32 位有符号是负数 ⇒ RGB 段取现有颜色，得不出"全 0"。
- 把场景置成「有动画」（例如排一个窗）后只跑一次渲染步：该标记在该步**之内**必须为 0（步开头被清 0）；若步内仍为 1 ⇒「开头清 0」错。
- 让引擎在渲染步**之内**重新置起该标记（影片 / 命令记录那一支）⇒ 收尾那次「清空命令表」**必须不发生**；若仍然发生 ⇒ 收尾判据的方向反了。
- 在等待到期的同一帧把该标记置 1 ⇒ 状态位字的那一处待处理位**必须不被清**；若被清 ⇒ 等待谓词没读它。
- 只把**脏**置 1、本标记为 0 ⇒ 收尾**仍必须清空命令表**（脏不参与这条判据）；若保留 ⇒ 把脏当成了本标记。

### 绘制项：直接设当前颜色（opcode 0x203）

<!-- rule: CORE-OPS-SCENE-203 -->

读四个操作数：**编号**、**一个整数**、**透明度**、**颜色**。按共用口径归一化后写进该项的**当前颜色**。

- **写入值** = 归一化(透明度, 颜色)（逐段公式与四种组合见 `0x202` 的「终色」段）。写进的是**当前颜色格**，⛔ 不写终色、⛔ 不碰窗字段。
- 编号不存在时：读「现有颜色」得到的是**无颜色**，随后建出的默认记录的当前颜色**也是**无颜色 ⇒ 在「透明度 < 0 且 颜色 < 0」这一支上，对不存在的编号调用本条会把当前颜色写成**无颜色**（不是黑）。
- **不排窗**：不碰延迟 / 持续时间 / "有窗"位；场景标脏。
- 第 2 个操作数写进记录里的**一格独立整数**。本表消费者（排窗、设色、烘色、绘制请求、窗推进）**都不读它**，也没有「已存在」门拿它比较；它与该记录的**当前颜色格**、**终色格**、窗三格、变换矩阵的任何分量都**不同格**。
  ★「不参与」的强度见「成立条件」的**读者闭集**（值取址入口的调用方闭集内零读 + 三处同格读取的反例排除），不是「引擎永远不读」：该记录会被**整份复制**（见「场景对象：整份复制」）带走 ⇒ 复制后目标记录的同一格等于源记录的同一格（观察点是**实现侧插桩** —— 这一格自身没有脚本可读的消费者）。
  ⛔ 不许因为它没有语义读者就把它实现成「不写」或与相邻格合并 —— 整份复制会把这个差异暴露出来。
- **没有"已存在"门**：编号不存在时照写（写进刚建出的默认记录）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某项的当前颜色 | 记录的当前颜色 ← 归一化值 |
| 第 2 个操作数 | 记录里的**一格独立整数** ← 第 2 个操作数（默认记录初值 0；整份复制与**存档整块搬运**都会带走） |

这一格**随记录进入存档**：存档把整条记录按同一宽度整块搬出、读档按同宽搬回 ⇒ 存 → 改 → 读档后该格回到存档时的值。⛔ 不许实现成「不进存档的临时格」。

**成立条件**

- ⛔ 不许与 `0x202` 合并实现：一条排窗、一条只改当前颜色，字段集与门都不同。
- 第 2 个操作数那一格**只保真写**：⛔ 不许实现在「没有读者」的推论上（不写 / 合并到相邻格 / 建一条派生状态）—— 整份复制会把实现与引擎的差异暴露出来。
- ★ **「无读者」的强度（本版口径）**：这一格没有脚本可读的消费者，判据是**闭集**：① 本表自己的**值取址入口**及其**全部调用方**（本版 36 个）里没有任何一处读它 —— 同一偏移上另有三处读取，逐条归因后都是**对象行为表的槽位分派**（取一个槽号去分派，不是读记录字段），不算读者；② 全脚本语料里对**同一偏移**的访问形态（含按索引的形态）都扫过，除 ① 的写与那三处槽位分派之外，没有落在本表记录上的站点。
  ⇒ **存档整块搬运已证**（见上）；仍**不排除**「不经取址入口、直接遍历表结点并解引用值」的读者（本版只核了区间擦除与整份复制两个这样的入口），以及交给平台资源接口时的「整块带走」。这两者都**不**改变合同（该格照写），只影响「它有没有领域名」这一问。

**可证伪**

- 在**不存在的编号**上以「透明度 = 0、颜色 = `0x00123456`」调本条 ⇒ 当前颜色 = `0x00123456`（**不是** `0xFF123456`）；且表里多了一条默认记录。
- 在**不存在的编号**上以「透明度 = -1、颜色 = -1」调本条 ⇒ 当前颜色 = 无颜色（归一化在默认记录上是不动点）。
- 以「透明度 = 255、颜色 = `0xFFFFFFFE`」调本条 ⇒ 该实参按 32 位**有符号**是负数 ⇒ RGB 段走"取现有颜色"支（**不是**取 `0xFFFFFE`）；要写出 `0xFFFFFFFE` 的正确实参是「透明度 = 255、颜色 = `0x00FFFFFE`」。写出之后该当前颜色**不是**无颜色（见 `0x320`）。
- 把某项第 2 个操作数设成 X，再把该项复制到另一编号 ⇒ 目标记录的同一格必须为 X；若为 0 ⇒「会写」错。★ 这一条**不是**脚本可观察的（这一格没有本版可指认的读者）⇒ 观察点是**实现侧插桩**：复制完成后直接读目标记录的那一格。
- 以第 2 个操作数 = X 调本条后，若这一格的值改变了本表消费者的任何可观察结果（绘制请求的参数 / 排窗 / 颜色）⇒「不参与」错。

### 网格：建 / 换（opcode 0x320）

<!-- rule: CORE-OPS-SCENE-320 -->

读**十个**操作数，顺序不是 1..10：**先第 9 个（顶点数）** → 第 5、6 个的**地址** → 第 7、8 个的**地址**
→ 按顶点数逐元素算出第三段 → 第 10 个 → 第 4、3、2 个的**地址** → **第 1 个（编号）**。

- **顶点数 ≤ 0** ⇒ 把错误文本「顶点数非法」写进**错误通道**（术语见「总览与约定」），**不建网格**。
- 第 2、3、4、5、6、7、8 个操作数都按**地址**读：各自指向一段逐顶点数组（**每顶点 1 个 32 位字**，段长 = 顶点数个字），**不是标量、也不做浮点读取**。
- **网格记录自己保存的三张副本数组**（各"顶点数 × 4 字节"、每顶点 1 个字；拷贝发生在装配**之后**，它们**不是**装配的输入缓冲）的来源：
  - 第 1 张 ← 第 2 个操作数地址处的 n 个 32 位字**原样**拷贝；
  - 第 2 张 ← 第 3 个操作数地址处的 n 个 32 位字**原样**拷贝；
  - 第 3 张 ← 第 5、6 个地址处的两段逐元素合成：**(解码(第 5 段[i]) 的低 8 位) << 24 | (解码(第 6 段[i]) 的低 24 位)**；解码 = 「数据池」的整型解码。第 3 张就是「原逐顶点颜色」（重烘的基准，见「网格：直接设当前颜色」）。
- **装配输入不是三个段，而是九个逐顶点数组**（每段每顶点 1 个字；九段都按地址读，装配入口按固定次序收**九段 + 顶点数**）⇒ **哪一段喂哪一组分量（合同）**：

  | 顶点里的分量 | 来源段 |
  |---|---|
  | 位置第 1 / 2 / 3 个分量 | 第 2 / 3 / 4 个操作数地址处的数组（原样；前两个各减去同一个常量，第三个不减） |
  | 位置第 4 个分量 | 引擎自建的**常量（浮点 1.0）数组** —— ⛔ 不是任何脚本操作数 |
  | 色字 | 第 5、6 个操作数地址处的两段**合成出来的那张数组**（整字搬运） |
  | 第一套纹理坐标的两个分量 | u ← 第 7 个操作数地址处的数组、v ← 第 8 个 |
  | 第二套纹理坐标的两个分量 | **与第一套同两张数组**（u ← 第 7、v ← 第 8） |

  ⇒ 第 4 段只喂位置的第三个分量；第 5、6 段**只用来合成色字**（它们自己不被装配直接读）；第 7、8 段**各被读两次**（两套坐标共用同一对源段）。⛔ 不许把三个 n 字副本数组当成装配的输入（它们是装配之后才存进记录的拷贝，见上一条）。
- **装配后的逐顶点布局（合同）**：
  - 每个顶点 **36 字节 / 9 个 32 位分量**，与格式字的三个位段一致：**四分量位置**（前四个分量）、**一个 32 位色字**（第五个）、**两套纹理坐标**（各两个分量，后四个）。
  - **位置的第一个 / 第二个分量各减去同一个常量**（★ 这个常量**取值本版不规定**：它在「显示适配」里以「×0.5」的身份出现，但本版只规定"两个分量减的是**同一个量**，且第三个分量不减"；⛔ 不许把它写成"取整"，也⛔ 不许写成"加偏移"）；第三个分量取原值；第四个分量 = 上表的常量 1.0。
  - **色字按整字搬运**（不是浮点、不换算）；它就是「按当前颜色烘进顶点缓冲」改的那一格。
  - **每段源数组的每顶点步长是 1 个 32 位字**（每顶点从每个源段各取 1 个字）；一个顶点在装配后的缓冲里占 9 个 32 位字，其中位置占 4 个。⛔ 不许把"位置有四个分量"读成"每个源段的每顶点步长是四个字"。
  - 填充是**按每四个顶点一批**做的，余下的顶点逐个做；两批写出的字节同形（⛔ 不是两种布局）。
- 建 / 换该编号的网格：释放原有缓冲，建上述**三张副本数组**与一个顶点缓冲对象；置"已存在"位、写顶点数与第 10 个操作数。
- 建 / 换完成后：**若该网格的当前颜色不是「无颜色」⇒ 按当前颜色重烘顶点色**（重烘口径同 `0x322` 的「按当前颜色烘进顶点缓冲」）；当前颜色**是**「无颜色」⇒ **不重烘**（顶点缓冲保持装配出来的样子）。构建成功时，两种情况都**无条件**把场景标脏（构建失败 ⇒ 上面那些格一个都不写、也不标脏）。
  - 判据是**当前颜色格**与无颜色的**32 位整字相等**（无颜色 = 32 位全 1，即 `0xFFFFFFFF`；透明度参与）：`0xFFFFFFFE`（透明度 = `0xFF`、蓝 = `0xFE`）**不是**无颜色 ⇒ 会重烘。⛔ 不许只比低 24 位。
  - ⛔ 不许把这条门理解成"这一步不画"或"跳过整条 `0x320`"：它只影响**要不要额外烘一次**；三张副本数组、顶点缓冲对象、"已存在"位、顶点数、第 10 个操作数**照常写**。
  - ★ 两支写进缓冲的颜色分量**逐字节相同**（无颜色是乘法的单位元）⇒ 这条门在颜色分量上**没有可观察后果**；是否还有别处可观察（例如缓冲被锁的次数）不在本条。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 顶点数 / 三张副本数组 / 顶点缓冲对象 / 第 10 个操作数 | 网格记录的对应字段与缓冲 |
| "已存在"位 | 网格记录的位 0 |
| 错误通道 | 一次上报（文本 = 「顶点数非法」；仅当顶点数 ≤ 0） |

**成立条件**

- 这是"替换"不是"追加"：重复调用先释放旧缓冲。
- 编号**不做范围检查**；顶点数只有"≤ 0 / > 0"两分支，没有上限检查。

**可证伪**

- 网格当前颜色 = 无颜色（新建的网格就是）⇒ 调 `0x320` 后顶点缓冲的颜色分量 = 装配结果；若被清成 0 或变成不透明白常数 ⇒ 错（那说明"不重烘"被实现成了"清零"）。
- 先以「透明度 = 255、颜色 = `0x00FFFFFE`」把当前颜色写成 `0xFFFFFFFE`，再调 `0x320` ⇒ **必须**重烘（顶点色被乘一次 `0xFE`）；若也不重烘 ⇒ 判据只看了 RGB，透明度没参与。

### 网格：清空槽表（opcode 0x32b）

<!-- rule: CORE-OPS-SCENE-MESH-CLEAR-32B -->

`0x32b` 没有操作数。

- 遍历网格槽号 **0..999**：释放该槽的网格对象并清空槽。这里的「槽」是 `0x320` 记录的网格键；只清 `[0,1000)`。
- 不写脚本变量、不置门位、**不切换当前帧**；推进格数 = 1；没有返回值。
- 它**不碰**绘制项、纹理记录、两张辅助表或场景命令表；也不置 / 清场景的「有动画」标记。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 槽 0..999 的网格对象被清掉 | 这些槽的网格对象 ← 空 |
| 负键 / 槽 1000 及以上的网格对象 | **不变** |
| 绘制项 / 纹理 / 辅助表 / 命令表 | **不变** |
| 场景脏标记 | 清掉至少一个网格 ⇒ 1；没清掉 ⇒ 不变 |
| 场景"有动画"标记 | **不变** |

**成立条件**

- 范围是**左闭右开**的槽号 `[0, 1000)`；槽 1000 不在范围内。
- 空槽静默跳过，不报错。
- 只要真的清掉至少一个网格 ⇒ 场景标脏；没有清掉 ⇒ 脏标记不动。
- 网格对象内部的渲染资源释放未建模（见残差）。

**残差**

- `RES-32B-MESH-RESOURCE-RELEASE`（omitted）：网格对象内部的渲染资源逐项释放不建模；本版只规定脚本可见的槽表被清空。理由：释放链作用于网格对象内部资源；脚本可见的引擎数据是槽表，已由合同与守卫固定。下一步：若将来需要内部释放的可观察语义，按已定位的释放链补。

### 网格：直接设当前颜色（opcode 0x322）

<!-- rule: CORE-OPS-SCENE-322 -->

读四个操作数：**编号**、**一个整数**、**透明度**、**颜色**。

- 按共用口径归一化后写进网格的**当前颜色**（写入值 = 归一化(透明度, 颜色)，逐段公式与四种组合见 `0x202` 的「终色」段），并**按当前颜色烘进顶点缓冲**：
  - 烘色 = 把**当前颜色**当系数，与**该网格的原逐顶点颜色**逐字节相乘（每字节 `(原字节 × 当前字节) ÷ 255`，**向下取整**（整除），⛔ 不是四舍五入）后写进顶点缓冲的颜色分量：原字节 `1`、当前字节 `0x80` ⇒ `128 ÷ 255` = **0**；若得到 1 ⇒ 用了四舍五入。原逐顶点颜色是**不变量数组**，所以重复烘焙不累积；"混合系数 0"的含义是"这一步的色就是当前颜色本身"，**不是**"与缓冲里的旧值混合"。
  - 当前颜色是**无颜色**时，烘色结果与**原逐顶点颜色**逐字节相同（不染色）。☑ **字节级不跳过**：本条**无条件**烘焙（调用不因当前颜色取值而省掉），且写进缓冲的字节恒等于"乘出来"的字节（烘焙入口内部对「系数全 1」另有一支直拷，但两支写出的字节**逐字节相同**）—— 与 `0x320` 的重烘门**不对称**，⛔ 不许把门搬过来。
- 第 2 个操作数写进**网格记录**里的一格独立整数（**读者未找到**）；场景标脏。
  ★ 它**不是**该项的当前颜色格、**不是**顶点缓冲里的任何分量，也**不是**绘制项记录上的任何一格（网格记录与绘制项记录是**两张不同的表**）。
  与 `0x203` 同理：「不读」的强度见「成立条件」的**读者闭集**（15 个调用方的闭集内零读；同格另几处访问归因为「顶点数格」与「常数 36」）；该网格记录会被**整份复制**（见「场景对象：整份复制」，副本的顶点缓冲是新建的）带走 ⇒ 复制后目标记录的同一格等于源记录的同一格（观察点同样是**实现侧插桩**）。⛔ 不许实现成「不写」或与相邻格合并。
- 窗进行中本条写的烘色保留到下一次场景推进；下一次推进按该步派生色覆盖（若该步到期则覆盖为终色；派生色是无颜色 ⇒ 覆盖结果 = 原逐顶点颜色，与"没覆盖"逐字节相同）；窗不推进时保留。场景推进在门之前，所以同一迭代内本条的写入后发生（以门后写入为准）。
- **不排窗**；**没有“已存在”门**（编号不存在时写进刚建出的默认记录，默认当前颜色是**无颜色**）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 网格的当前颜色 | 记录的当前颜色 |
| 逐顶点颜色 | 顶点缓冲的颜色分量 ← 原逐顶点颜色 × 当前颜色（逐字节 ÷255）；当前颜色是无颜色时 = 原逐顶点颜色 |
| 第 2 个操作数 | **网格记录**里的一格独立整数 ← 第 2 个操作数（建表时初值未取证；整份复制时随记录带走） |

**成立条件**

- 第 2 个操作数不要当"透明度"或"编号"用：它写的是另一个整数位。
- ⛔ 不许把它与顶点色格、顶点数格、或绘制项记录上的同名偏移当成同一格 —— 三者在**不同的表 / 不同的记录**上。
- 这一格**只保真写**：⛔ 不许实现在「没有读者」的推论上（不写 / 合并到相邻格）。
- ★ **它不是顶点数**：把网格复制到另一个编号时，副本要**新建**逐顶点缓冲，缓冲的大小取自记录的**顶点数**那一格（每次复制按「顶点数 × 每顶点宽度」建一次），**不取**本条写的这一格。
  ⇒ 可证伪：拿一个顶点数为 N 的网格、先以第 2 个操作数 = M（M ≠ N）调本条、再把它复制到另一编号，若新缓冲的大小变成 M × 每顶点宽度 ⇒「不同格」写错（把这一格当成了顶点数）。
- ★ **读者闭集**：本条这一格没有脚本可读的消费者；判据是「本表取址入口及其全部调用方（本版 15 个）与全脚本语料里同一偏移的访问形态求交，只剩本条这一处写」；同一偏移上另有若干处访问，逐条归因后分别是**顶点数格**与**常数 36**（循环步长的伪装），都不是这一格。
  ⛔ 不许因为「没有领域名」就把它实现成不写、或与顶点数格合并。

**可证伪**

- 先以「透明度 = 255、颜色 = `0x00808080`」设当前颜色，再调本条 ⇒ 当前颜色 = `0xFF808080`，且逐顶点颜色的每个字节 = 原字节 × `0x80` ÷ 255（**不是**直接等于 `0x80808080`）；若顶点色被写成当前颜色原值 ⇒ "乘法"错。
- 以「透明度 = -1、颜色 = -1」在不存在的网格编号上调本条 ⇒ 当前颜色 = 无颜色，且逐顶点颜色与"从没调过本条"逐字节相同；若顶点色被清成 0 / 变成不透明白的常数 ⇒ "不染色"错。
- 先以「透明度 = 255、颜色 = `0x00FFFFFF`」调本条（结果 = 无颜色）后立即调 `0x320`：`0x320` **不得重烘**。★ 这一条**不是像素可观察的**（两支写进缓冲的颜色分量逐字节相同，见 `0x320` 的「成立条件」）⇒ 观察点是**实现侧插桩**：顶点缓冲的加锁 / 重烘次数不得增加；若观察到 `0x320` 也重烘 ⇒ 门的值判错（该值等于无颜色）。
- 以第 2 个操作数 = X 调本条后，把该网格复制到另一编号 ⇒ 目标网格的同一格必须为 X；若为 0 ⇒「会写」错。★ 这一条同样**不是**脚本可观察的（该格没有本版可指认的读者）⇒ 观察点是**实现侧插桩**：复制完成后直接读目标网格记录的那一格。
- 调完本条后读「建 / 换」写的那一格或顶点缓冲的颜色分量：若被改动 ⇒「不同格」错。

### 网格：排颜色渐变窗（opcode 0x323）

<!-- rule: CORE-OPS-SCENE-323 -->

读五个操作数：**编号**、**延迟**、**持续时间**、**透明度**、**颜色**。

- **终色** = 归一化(透明度, 颜色)（逐段公式与四种组合见 `0x202` 的「终色」段）；写进**终色格**，⛔ 不写当前颜色、⛔ 不烘焙。
- 窗的"起色"是该项**当前颜色格**（本条不改它）；当前颜色是**无颜色**时排出的窗在推进期按"无颜色 ↔ 终色"逐字节插值，到期后当前颜色 = 终色。
- 与绘制项同形：置"有窗"位、把窗起点清成 0、写延迟 / 持续时间 / 终色；场景标脏。
- **没有"已存在"门**：编号不存在时会先建默认记录，然后**照常排窗**。
- 本条**不**直接置"场景有动画"（那由窗的推进决定）。

| 领域状态 | 机器状态 |
|---|---|
| 网格的渐变窗 | 记录的延迟、持续时间、终色、"有窗"位、起点 |

**成立条件**

- 与 `0x202` 的"已存在"门**不对称**：这是真实差异，不许抹平。

**可证伪**

- 与 `0x202` 的三条同形（把"排窗"读成"排颜色窗"即可）。
- 在**不存在的网格编号**上以「透明度 = -1、颜色 = -1」排窗 ⇒ 终色 = 无颜色，且窗字段照常被写（本条没有"已存在"门）；若一个窗字段都没写 ⇒ 把 `0x202` 的门搬过来了。

### 场景对象的变换：opcode 0x1fd / 0x1ff / 0x1fe

<!-- rule: CORE-OPS-SCENE-TRANSFORM -->

三条都往**场景对象记录表**里的一条**记录**写一个**变换矩阵**。这张表是场景持有的**唯一**对象表（键 → 一条记录；记录与元素是同一个值）。共同部分：第 1 个操作数读成整数 = **对象键**；按键在表里找记录，**找不到就先建立**一条默认记录再写（不是跳过、不是崩溃）；写完把该记录的 **G3 配置格 ← 1**，并置场景的**脏**标记。

默认记录的初值（合同，用于定义“新建记录”的可观察状态）：首字为 **0**（位 0 / 位 1 都是 0）；第一 / 第二三元向量全 **0**；当前色 / 终色都是 **0xFFFFFFFF**；**八个 4×4 矩阵格（六个主格 + 附加组两格）的初值全部是单位矩阵**（每格 16 个分量逐个写出：对角四个 = 1、其余 12 个 = 0）⇒ 一条**从没有矩阵写者写过**的记录被绘制请求消费时，它的变换是「不变换」（⛔ 不是 0、⛔ 不是"上一条记录的残留"）；**任何写者写过之后**变换是唯一值（见「六个变换矩阵：各由谁写」的整份覆盖条）；轴 / 角为 0。

- `0x1fd`（**缩放**，4 个操作数）：第 2..4 个操作数读成浮点，**各除以 100**（即以**百分之一**为单位），写进**缩放矩阵**。
- `0x1ff`（**平移**，4 个操作数）：第 2..4 个读成浮点，**原值**写进**平移矩阵**。
- `0x1fe`（**旋转**，5 个操作数）：第 2..4 个 = 旋转轴 `x / y / z`，第 5 个 = **角度（度）**；引擎按 `π / 180` 换成弧度，写进**旋转矩阵**，并把**轴与角度**另存进记录自己的标量格（轴三格、角度一格）。

**六个变换矩阵：各由谁写**

绘制项记录里带**六个 4×4 变换矩阵**，按用途分三对（缩放 / 旋转 / 平移各两格），**每格只有一个主写者**（“① / ②”只表示同用途的两格，不表示先后）：

| 矩阵 | 主写者 | 副写者 | 语义 |
|---|---|---|---|
| 缩放① | `0x1fd` | `0x254` | 三个浮点各 ÷100（百分之一为单位） |
| 缩放② | `0x21e` | **无** | 同上；另置 G3 配置格；带「已存在」门 |
| 旋转① | `0x1fe` | `0x255` | 轴 + 角度（度 → 弧度）；轴 / 角度另存两份 |
| 旋转② | `0x21f` | **无** | 同上；带「已存在」门 |
| 平移① | `0x1ff` | `0x256` | 三个浮点原值 |
| 平移②（`0x220` 条称「第四个平移矩阵」） | `0x220` | **无** | 三个浮点原值；另写两个整数与一个标志 |

- ★ **副写者是真实的复用，不是重复登记**：`0x254` / `0x255` / `0x256` 分别**重写**上面第 1 / 3 / 5 个矩阵 —— 后写者**整份覆盖**该矩阵（不是叠加、不是部分改）。⛔ 不许把「主 / 副」实现成两个矩阵格。
- 第 2 / 4 / 6 个矩阵**没有**第二个矩阵写者：⛔ 不许因为「同族」就给它们也加一条写路径。★ 但它们**不是**独立的第二套变换：记录首字节的「修饰位」置起时，引擎在绘制前把**②整份拷回①**（缩放 / 旋转 / 平移各一次），再由当前的对位 / 附加组状态**重算①**，并把当次用到的一个标量写回②的**首分量** ⇒ **② 是①的「上一份值 / 备用值」**（见下「绘制时怎样合成最终世界变换」）。⛔ 因此「①的当前值」在某些路径上**不等于**脚本最后一次写进去的值。
- 除这六个之外，记录上还有**附加组的两个矩阵**（缩放 / 平移各一），由 `0x233` / `0x235` 写；它们**不在**这六个之列（⛔ 不许当成第 7 / 第 8 个主矩阵 —— 两者的门与配套格都不同）。
- ★ **每个矩阵写者都写一整份矩阵**（不是"只改三个分量、其余格保留"）：先把矩阵写成**单位矩阵**，再把该条自己点名的分量换掉 ——
  **缩放类**（`0x1fd` / `0x21e` / `0x233` / `0x254`）：对角三分量 ← 三个操作数（各 ÷100），其余格 = 单位阵的值；
  **平移类**（`0x1ff` / `0x220` / `0x235` / `0x256`）：平移分量 ← 三个操作数（原值），其余格 = 单位阵的值；
  **旋转类**（`0x1fe` / `0x21f` / `0x255`）：由轴 + 角度算出**整份**旋转矩阵（16 个分量全由这一条决定）。
  ⇒ 一条没点名的格 = **单位矩阵在该位置的值**（对角 1、其余 0），⛔ 不是「上一次的值」、也⛔ 不是「默认记录的初值」。这条与下面「副写者整份覆盖」同义。
- ★ **初值只在"从没有写者写过"时才被读到**：默认记录的**八个矩阵格**（六个主格 + 附加组两格）初值 = **单位矩阵**（见 `0x1fd` 条的默认记录段）；任何矩阵写者写完之后，**它写的那一格**的 16 个分量**全部**由写者决定。★ 反过来：`0x231` / `0x234` 只置附加组开关位、**不写任何矩阵** ⇒ 一条只被它们碰过（或从没被矩阵写者碰过）的记录，附加组那两格仍是**单位矩阵**（即「不变换」；⛔ 不是"残留上一条"，也⛔ 不是全 0）。
- ★ **八个矩阵格互不影响**：只写一格不会改动其它七格（⛔ 不许实现成"八格共享一份初值"）。

**绘制时怎样合成最终世界变换（合同）**

绘制一个条目时，引擎把**三对里各自①那一格**取出来，与一个现算的平移合成**最终世界变换**：

1. 取**缩放①**的**整份**副本 → 局部矩阵 A；
2. 取**旋转①**的**整份**副本 → 局部矩阵 B；
3. 取**平移①**的**整份**副本 → 局部矩阵 C；
4. 用记录里**三个纯量**（浮点，⛔ 不是任何矩阵格）按下面的「显示换算」得到两个偏移量与一个原样量，**三个分量各取反**后组成平移 → 局部矩阵 T。

   **形态**：`T = (−X, −Y, −Z)`，其中

   - `Z` = 第三个纯量（**原样**，不参与任何换算；⛔ 不许给它加偏移、也不许乘缩放）；
   - `X / Y` = 换算(第一个纯量, 第二个纯量)。

   **换算（三档；判据两格）**

   - 输入：一个**居中偏移对**（两个整数）、一个**缩放对**（两个浮点，横向 / 纵向）、一个**虚拟全屏类型**（0 / 1 / 2），以及记录的**种类格**。
   - **档 A** —— 虚拟全屏类型 ≠ 2：`X = 纯量① + 偏移x`、`Y = 纯量② + 偏移y`（偏移先由整数转浮点，**加**）。
   - **档 B** —— 类型 = 2 且种类格 ∈ {20 … 29}：`X = 纯量① × 缩放x + 偏移x`、`Y = 纯量② × 缩放y + 偏移y`（**先乘后加**）。
   - **档 C** —— 类型 = 2 且种类格 ∉ {20 … 29}：`X = 纯量① + 偏移x ÷ 缩放x`、`Y = 纯量② + 偏移y ÷ 缩放y`（**偏移先换算成浮点再除**；⛔ 不是「两个量都除」—— 纯量①本身不除）。
   - 横向 / 纵向各用自己那一格缩放（横向对第一个分量、纵向对第二个分量），⛔ 不许交叉。
   - 居中偏移对与缩放对由引擎按**渲染目标与显示档**算出（不是一张常量表；显示设置变化时重算，见「显示适配」）：无缩放的档里缩放对恒为 1.0；「用固定区域尺寸」开关置起时偏移对为 (0, 0) 且缩放对为 1.0 ⇒ 三档**同值**，换算退化成「原样」。

   **整段跳过**（不是把偏移当 0，而是连「档」都不进）：场景级一个「不做显示换算」开关置起时，或绘制目标**不是屏幕目标**时（对象被画进别的离屏目标），`X / Y / Z` 全取纯量原值，直接取反组 T。

   ★ **这一对缩放取哪一份（合同）**：它就是「显示适配」里那对 `s` —— **算式与三档分支的真源在「显示适配」**（分子 = 参考尺寸、分母 = 目标区域尺寸；横向用宽、纵向用高，不交叉），本条**只**规定「哪一档取哪一份、两个分量是否同值」，⛔ 不另立一套算式。分档：**虚拟全屏关**、或**类型 = 0**、或**固定分辨率档生效** ⇒ 两个分量恒 **1.0**；**类型 = 1** ⇒ 两个分量同值（取两个比值中**较小**者，该档下恒为 1.0）；**类型 = 2 且按比值适配** ⇒ 两个分量同值（取两个比值中**较小**者）；**类型 = 2 且不按比值适配** ⇒ 两个分量**各取自己那一格的比值** —— 这是**唯一**两分量不同的档；类型 ∉ {0,1,2} ⇒ 退化出口，两个分量保持旧值（本版不规定旧值）。
   ⇒ ⛔ 不许把「横向纵向各一」当成通则（只有一档如此）；⛔ 不许把「无缩放档恒 1.0」推广成「所有档恒 1.0」；⛔ 不许按「类型 = 1 时两分量各一」实现。
   ★ **这一对缩放不是「读鼠标位置」那条里的比例**（交叉引用：`60-ops-input` 的「坐标换算（结构面）」）：本条用的是渲染器上**缓存**的一对缩放值（无缩放档恒 1.0、由显示档变化触发重算）；那一条的**比例是每次查询现算的**、分子里含 **2 × 偏移**，且不读这对缓存值 ⇒ ⛔ 不许把两处实现成同一格，也⛔ 不许拿那一条的算式顶替「显示适配」里的这一对。**偏移对倒是同一对**（同一次「取两个显示偏移」的读取、同一个「用固定区域尺寸」开关）—— 两处允许共用的只有偏移，不是缩放。
5. 从**单位矩阵**开始，对**输出矩阵**连续**右乘**：`M ← M×A`、`M ← M×B`、`M ← M×C`、`M ← M×T`（次序即语义）。

- 三份副本都是**整份 16 分量**拿走：⛔ 不转置、不取逆、不挑分量。
- **输出矩阵**（合成结果）**不写回**记录：脚本能观察到的记录格变化只由「修饰路径」引起（见下条），⛔ 不是"把合成结果存回六格"。
- 三个局部矩阵的**来源格固定**：缩放取①、旋转取①、平移取① —— ⛔ 不许取②，也不许"两格取平均 / 相加"。
- **②格的作用**：记录首字节的「修饰位」为 **0** ⇒ **只跳过"②整份拷回① + 按当前状态重算①"这一对修饰**：第 1–3 步照取①的副本、第 4 步的 **T 照算**、第 5 步的四次右乘里 **T 照乘**（⇒ 此时记录**一格都不变**）；为 **1** ⇒ 引擎**先**把②整份拷回①（缩放 / 旋转 / 平移各一次），再按当前的对位 / 附加组状态**重算①**的那几格，并把当次用到的一个标量写回②的**首分量**，然后才取①的副本做第 5 步。
  ⇒ ② 的语义是**①的"上一份值 / 备用值"**，不是独立的第二套变换。⛔ 因此修饰位 = 1 时「①的当前值」**不等于**脚本最后一次写进去的值，而是"②回灌后重算的结果"；「②的首分量」也不再是它原来的值。
- 位闸只罩**修饰**、不罩 **T**：位为 0 时"②拷回① + 重算①"整体不发生，但第 4 步的 T 仍要现算、第 5 步仍要右乘它 —— ⛔ 不许把 T 一起跳过（那会把记录那三个纯量也一起丢掉），也⛔ 不许只跳过②的拷回、漏掉随之的重算。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 对象键 → 场景记录 | 对象键 → 场景对象记录表里的记录（缺失即按默认值建立） |
| 记录的缩放 / 平移 / 旋转 | 记录里的三个**不同**矩阵 |
| 记录需要重算 / 场景有改动 | 记录的 G3 配置格 + 场景的脏标记 |
| 一份记录的缩放 / 旋转 / 平移（各两份，用途不同） | 记录里六个 4×4 矩阵格（三对，每对两格） |
| 附加组的缩放 / 平移 | 另两个 4×4 矩阵格（不在六格之列） |
| 绘制期用的四个局部矩阵（A / B / C / T） | 绘制期临时算出的四块 4×4 暂存（不持久、不写回记录） |
| 最终世界变换 | 绘制期从单位矩阵起连续右乘得到的输出矩阵（**不写回**记录） |
| ②「上一份值 / 备用值」 | 记录里第 2 / 4 / 6 个矩阵格：修饰位置起时被**整份拷回**①，并收到一个标量写回 |
| 三个纯量（T 的原料） | 记录上三个浮点格（第一个 / 第二个参与换算，第三个原样取反） |
| 记录的种类格（决定档 B / 档 C） | 记录上的一个整数格：默认值建立时置 0；绘制路径会整格改写它；读档整块回填时收到存档里那一格的字节 |
| 居中偏移对 / 缩放对 | 渲染器上按显示档每帧现算的一对整数与一对浮点（不写回记录、不进存档） |

**成立条件**

- 三条的**单位不同**，这是语义不是仿真参数：缩放是百分数（÷100），旋转角度是**度**。⛔ 不许把 `0x1fd` 的三个值当「归一化系数」而省掉 ÷100；⛔ 不许把 `0x1fe` 的第 5 个当弧度。
- 三条的**落点互不相同**（缩放 / 平移 / 旋转各一个矩阵格）：⛔ 不许合并成一个「设置变换」的通用实现。
- 读序：`0x1fd` / `0x1ff` 是 op1 → op2 → op3 → op4；`0x1fe` 是 op1 → op2 → op3 → op4 → op5。读操作数本身无副作用，但次序是合同的一部分。
- **按需建立**是可观察的：键不存在时，读该键的后续指令看到的是一条**默认记录**，而不是「空」。
- 三条写的是**三个不同矩阵**；本节之外还有第四个平移矩阵由 `0x220` 写、`0x228` 读的是 `0x1ff` 写的那个平移矩阵（见各自条目）。
- 三条都不读第 1 个操作数以外的操作数两次；三条都不产生脚本可观察的返回值。
- 平台侧（矩阵怎么被图形设备用、像素结果）**不在本版**。
- 「一格一个主写者」是合同：两对缩放矩阵**不是**同一格（`0x1fd` 与 `0x21e` 的门、÷100 之外的效果都不同）。
- 副写者覆盖是**全矩阵覆盖**：副写者写完之后，该矩阵的 16 个分量**全部**来自副写者，不允许残留主写者的分量。
- **档划分的两层判据有先后**：先判「虚拟全屏类型 = 2」，**只有**在 = 2 时才判种类格；类型 ≠ 2 时种类格**不被读**。⛔ 不许把两个判据并成「或」。
- 种类格是**记录的**格（随记录走），虚拟全屏类型是**显示档**的格（全局）⇒ ⛔ 不许把两者存在同一处。
- 三个纯量是**纯量**，⛔ 不许从任何变换矩阵里取；它们也不因本条被写回。
- 换算是**浮点**运算：两个偏移在参与前先由整数转成浮点（档 B / C 的乘法 / 除法也是浮点）；⛔ 不许用整数四舍五入。
- 现算的平移**不写回**记录、不进存档；同一次绘制里只算一次。
- ★ 种类格是**记录上的一个可写整数格**：记录按默认值建立时它被置 **0**；文本 / 字形绘制路径会把它**整格改写**成调用方给的整数；从存档恢复整条记录时它会收到**存档里那一格的字节**。⇒「种类格恒 0」不是合同，但⛔ 也不许因为"有写者"就断言档 B 在发行数据上一定出现（那 25 个绘制调用点的实参能否落在 `[20, 29)` 未取证）。★ 因此本节**所有要摆布种类格的可证伪条件都标成白盒插桩**（正文后面条目里凡写"把种类格改成 20 / 19"的，**判据一律是白盒插桩**）。

**可证伪**

- 只调 `0x1fd` 设 X，再通过只读缩放②的效果观察 `0x21e` 那一格：必须**不变**；若变了 ⇒ 两格同格（合同错）。
- 先调 `0x1fd` 设 X，再调 `0x254` 设 Y ⇒ 观察到的缩放必须**整份**等于 Y（含非对角分量）；若残留 X 的分量 ⇒「整份覆盖」错。
- 只调 `0x254` ⇒ 若 `0x21e` 那一格也变 ⇒ 副写者归属错。
- 调 `0x233` / `0x235` ⇒ 六个主矩阵**一个都不许**变（附加组是另两格）。
- **合成**：只改**缩放②**、不动①、调一次绘制（记录首字节的修饰位 = 0）⇒ 最终矩阵必须**不变**；跟着变 ⇒ 用了②（来源格错）；若①被改成了②的值 ⇒ 回灌发生了（那是修饰位 = 1 的路径）。
- 把三对①各设成可区分的值（缩放 2 / 绕某轴 90° / 平移 (5, 0, 0)）后绘制一个在原点、单位大小的条目：最终位置必须是「先缩、再转、后移」的结果；若是「先移、再转、后缩」的结果 ⇒ 右乘次序错。
- 三个纯量的方向（修饰位 = 0）：把某一个纯量 +Δ、其它不动 ⇒ 最终平移的对应分量在**档 A / 档 C** 下变化 −Δ（取反后同量），在**档 B** 下变化 −k·Δ（k = 该方向的缩放）。⛔ 不许拿「各 −Δ」当三档通判据（档 B 里含乘法）；只钉「方向与进入 T 时的符号相反」。若某个分量朝**相反**方向动 ⇒ 该分量漏了取反；若三个分量都**不动** ⇒ T 没进合成。
- **（白盒插桩）**虚拟全屏类型 ≠ 2：把种类格改成 20 ⇒ `X / Y` 必须**一点不变**（类型闸在前）；变了 ⇒ 判据顺序错。
- **（白盒插桩）**类型 = 2、种类格 = 20、缩放对 = (2, 3)、两个纯量 = (10, 10)、偏移 = (4, 6) ⇒ 最终平移必须是 `(−24, −36, −纯量③)`（档 B：10×2+4 / 10×3+6）；若是 `(−12, −12, …)` ⇒ 走成了档 C（同组数下档 C 就是下一行那个值）。
- **（白盒插桩）**类型 = 2、种类格 = 19、同一组数 ⇒ 必须是 `(−12, −12, …)`（档 C：4÷2+10 / 6÷3+10）；若是 `(−24, −36, …)` ⇒ 把种类格的区间判反了。
- 只改第三个纯量、其它不动 ⇒ 最终矩阵的**第三个**平移分量必须跟着变、前两个**不变**；前两个也变了 ⇒ 把第三个纯量也送进了换算。
- 「用固定区域尺寸」开关置起 ⇒ 三档**必须同值**（偏移 0 / 缩放 1 使然）；三档仍不同 ⇒ 开关没有真的把偏移与缩放归零。
- 把对象画进一个**非屏幕**的离屏目标 ⇒ 换算整段不发生；仍出现偏移 ⇒ 整段跳过被写成了「偏移归零」。
- **（白盒插桩）**缩放对设成 (1, 1)、类型 = 2、种类格 = 20 ⇒ 结果必须与档 A 相同（乘 1）；不同 ⇒ 档 B 的乘法多做了别的。
- 修饰位 = 0 时：最终矩阵必须恰等于「单位矩阵 × ① × ① × ① × T」（三个①依次指缩放 / 旋转 / 平移那一格）；若仍出现「②回灌」的痕迹 ⇒ 位闸被绕开。
- 修饰位 = 0 时绘制后回读记录六格：必须与绘制前**逐字节相同**；变了 ⇒ 把合成结果写回了记录。
- 修饰位 = 1 时绘制后回读记录：①必须已是「②回灌后重算」的结果、②的**首分量**必须变；六格逐字节不变 ⇒ 修饰路径被绕开（总闸没接上）。
- **初值**：新建一条记录、不调任何矩阵指令、直接绘制 ⇒ 最终变换必须是「不变换」（缩放 1 / 旋转 0 / 平移 0）；缩放为 0 或平移为 1 个单位 ⇒ 初值不是单位阵。
- 新建记录后只读某格的效果（取该格的 2×2 左上块）⇒ 必须恰为 (1, 1)；任意一个对角分量为 0 ⇒ 该格初值错。
- 只调附加组开关位（`0x231` / `0x234`，不调任何矩阵写者）⇒ 附加组两格仍必须是「不变换」；变成「残留上一记录」或「全 0」⇒ 开关位与矩阵格被混为一格。
- 只写一格之后回读**其它七格** ⇒ 必须仍是单位阵；被连带改成 0 ⇒ 八格被实现成「共享一份初值」。
- ★ 种类格**可写**（前半句白盒）：用文本 / 字形绘制那条路径摆布一条已存在的记录之后回读该格 ⇒ 必须等于路径给的整数；仍为 0 ⇒ 把「整格写」实现成了「只置存在位」。反向：从一份该格为 20 的存档恢复后立刻绘制 ⇒ 必须走档 B；仍走档 C ⇒ 回填路径被绕开（存档字节没覆盖到这一格）。

### 场景对象表的清空：opcode 0x1f6

<!-- rule: CORE-OPS-SCENE-CLEAR -->

`0x1f6` **没有操作数**。它先把**指令长度字**写成 1（= 2 × 0 + 1，分派器据此推进），随后**控制转移到清理入口**（本条不返回）。

清理入口按**固定次序**做四段，**整条没有失败分支**（不上报错误通道、不返回错误码；四段与后面的标记清零都会走到）：

1. **清空对象记录表**（与绘制项共用同一张表）：记录**没有需要单独释放的东西**，整条记录的内存随表结点一起收回 ⇒ 这一步**没有逐条释放动作**。
2. **逐条释放网格记录**，每条按固定次序：先把该条自己的**顶点缓冲对象**交给它**自己的**释放接口（一次释放请求），随即收回它自带的**三份逐顶点数组**，并把这四个引用清空。★ **先对象、后三份数组**。条目里若还有**别的**引用，本条**不释放**它。
3. **收网格表的结点**（值随结点收回）。
4. **收两张辅助表的结点**：两张辅助表的条目**也没有逐条释放动作**（与第 1 步同形）—— 它们的条目与树结点**同块内存**、体内没有一格引用需要释放。⛔ 不许因为第 2 步的网格表是逐字段释放的，就给它们也加一遍（对照：只有网格表的条目带四个引用格）。

随后把**四个场景级标记**清 0（脏 + **强制完成位** + 另外两个；另外两个的身份本版不规定）—— 这四个是**无条件**的；「**有动画**」标记**不动**。
同一段里还有一个**场景级状态位字**（它**不是**那四个标记之一）：清理**看它的第 16 位** —— 置位 ⇒ **整字清 0**；未置 ⇒ **一位都不动**。★ 这个字**就是**「执行与时间」的**主循环模式字**（脚本 `0x24e` 写的那一个），也是「场景计时窗」的等待谓词里清的那个字 —— **同一格、三个名字**（⛔ 不许实现成两三格）；它唯一的整字写者是 `0x24e`，整字清 0 有**两处**判据（本清理入口与等待谓词），两处都只看第 16 位、都清**同一个整字**。⛔ 不许把它写成第五个「无条件清零的标记」，也⛔ 不许写成「只清第 16 位」。

这四张表以外的表**不在**清空范围：第五张**场景命令表**同样**不**被清空（命令记录跨"清场景"存活）。表本来就是空的时候走**同一个入口**，结果是**无动作**（不抛、不报错）。

**统一口径**：同一个清理入口也被**全局重置**使用 ⇒ 「清场景」与「重置」清的是**同一组四张表与同一组标记**（重置另外做的那些事属「帧类指令」的重置条目）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 场景里还有哪些对象 / 网格 / 辅助表条目 | 四张表清空（对象记录表与两张辅助表只回收结点；网格表逐条释放后再收结点） |
| 网格的顶点缓冲对象 / 三份逐顶点数组 | 该条目的四个引用：先释放对象、再收回三份数组，四个引用清空 |
| 两张辅助表的条目 | 只随结点收回，**没有**逐条释放 |
| 场景标记 | 四个标记 ← 0（无条件）；「有动画」标记**不动** |
| 场景级状态位字 | 第 16 位为 1 ⇒ 整字清 0；为 0 ⇒ 不变 |
| 本条的执行 | 先写指令长度字 1，再控制转移到清理入口 |

**成立条件**

- 这是**整表清空**，不是「删一个对象」：与 `0x1fd` / `0x1ff` / `0x1fe` 的「按需建立」是相反方向的两件事。
- 对象记录表**不逐记录调用释放入口**：⛔ 不许按「每个元素先走自己的释放入口」实现；网格表**是**逐条释放，两张辅助表**不是**。
- 网格条目的释放次序是合同（**对象在数组之前**）：⛔ 不许先收数组再请对象释放（那会让对象的释放接口读到已收回的数组）。
- 四个标记的零是**无条件**的；第五个状态位字是**条件**的 —— 两者不许合并成一句。
- 清理**不置脏**（脏在被清零的那四个之内）。
- `0x1f6` 的 1 是**通用指令长度字**，不是场景字段。
- 不读任何操作数 ⇒ 不会抛操作数类型异常。
- 清空范围是四张表 + 四个标记 + 一个条件清零的状态位字；「有动画」标记与第五张命令表都不在清空范围。

**可证伪**

- 一条网格记录同时有顶点缓冲对象与三份逐顶点数组：清场景之后，**对象必须先收到一次释放请求**、之后它的三份数组才被收回；若数组先被收回、或对象的释放接口在读数组 ⇒ 次序写错。
- 一张只有**辅助表**有条目、其余三张全空的场景：清场景之后这些条目的内存必须被收回（表清空），且**不得**出现任何"逐条释放"的可见动作；若观察到对辅助表条目逐个调用释放 ⇒ 把"只收结点"写成了"逐条释放"。
- 把场景的「有动画」标记置 1 后清场景：它必须**仍是 1**；若变 0 ⇒ 把「有动画」并进了那四个标记。
- 场景的第五个状态位字：第 16 位为 0 时清场景 ⇒ 该字**逐位不变**；为 1 时清场景 ⇒ 该字**整字变 0**。若两种情况下结果相同 ⇒ 条件判据写错。

### 场景对象：写变换（平移 + 平移窗 + 标志）（opcode 0x220）

<!-- rule: CORE-OPS-SCENE3D-SET-TRANSFORM -->

读六个操作数：**编号**（整数）、**两个整数**、**三个浮点**。读序是 **4 → 5 → 6 → 3 → 2 → 1**
（三个浮点先读，再读三个整数，编号最后）。

- 按编号取记录；不存在 ⇒ 先建默认记录（这一步**总会发生**）。
- 该记录的**「已存在」位**（记录首字的第 0 位）为 **0** ⇒ **只留下默认记录**，本条不再写任何东西。
- 该位为 **1** ⇒ 依次：
  1. 置记录首字的**第 1 位**——该位与 `0x202` 的「有窗」是**同一位**；置位后按「场景计时窗」的推进规则处理（位 1 的语义见残差 `RES-SCENE-BIT1-DUAL-ROLE`；插值的起值 / 终值见残差 `RES-SCENE3D-XFORM-WINDOW-VALUES`）；
  2. 四个**互异**的整数格依次写：`G0 ← 0`、`G1 ← 第 2 个操作数`、`G2 ← 第 3 个操作数`、`G3 ← 1`；
  3. 把**第四个平移矩阵**（与 `0x1ff` 写的那个平移矩阵不是同一个）的平移分量写成三个浮点操作数；
  4. 场景标**脏**，并置「场景有动画」。

本条写的四个整数格属于**记录的一组窗字段**：`G0` 是**窗起点**（与 `0x202` 的起点同格，0 = 未盖章），`G1` 是**平移窗的延迟**，`G2` 是**平移窗的持续时间**，`G3` 是给其它矩阵写者共用的**重算标志**。三档判据与「场景计时窗」相同（起点 + 延迟 + 持续时间；相等即到期），只是参数取本窗自己的两格。**持续时间 ≤ 0 只跳过推进**：排窗仍按步骤 3 / 4 写矩阵、标脏；推进时若持续时间 ≤ 0 ⇒ 不插值、也不因推进标脏。⛔ 不许把 `G1` / `G2` 写成"两个整数属性"——它们是时间量，单位与 `0x202` 的窗相同。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某场景对象的平移窗延迟 / 持续时间 | `G1` / `G2` ← 第 2 / 第 3 个操作数 |
| 某场景对象的第四个平移 | 第四个平移矩阵的平移分量 ← (第 4、5、6 个操作数) |
| 该记录已被本条配置 | 位 1 ← 1；`G0` ← 0；`G3` ← 1 |
| 场景需要重绘 / 有动画 | 脏标记 ← 1；「有动画」标记 ← 1（**两个不同的格**） |

**成立条件**

- **门在「建记录」之后**：位 0 为 0 时，默认记录已经被插进表里——这与「什么都不做」在表内容上不同。
- 位 0 与位 1 是**两个不同的位**：位 0 是「已存在」，位 1 是本条置的「已配置」。⛔ 不许实现成同一位。
- **位 0 的置 1 生产者**：本版只观察到 `0x1fb` 把它置 1；`0x217` / `0x219` / `0x220` 都**不写位 0**（`0x220` 只写位 1）⇒ 新建记录之后，本条与 `0x202` 的门看到的位 0 仍是 **0**（只建记录、不写字段）。
- 三个浮点写的是**第四个平移矩阵**，不是 `0x1ff` 的平移矩阵、也不是第一 / 第二三元向量。
- 四个整数格 `G0..G3` **互异**，且 `G0` 是「清 0」、`G3` 是「写 1」；`G0` 与 `0x202` 的窗起点同格，`G3` 与 `0x1fd/1ff/1fe` 及 `0x21e/21f` 写的 **G3 配置格**同格（不是首字的位 1）。
- **脏**与**有动画**是**两个不同的 32 位格**，⛔ 不许合并。
- 编号不检查；门只看记录自己的位。
- **读序**是合同的一部分：第 4 个操作数类型异常时，后五个都还没读。

### 场景对象：读本地矩阵的平移（opcode 0x228）

<!-- rule: CORE-OPS-SCENE3D-GET-LOCAL-TRANS -->

取五个操作数（**2 读 3 写**）：**结果标志**（第 1 个，**被写**）、**编号**（第 2 个，整数）、**三个浮点输出**（第 3、4、5 个，**被写**）。
读序是 **2 → 写 3 → 写 4 → 写 5 → 写 1**。

- 按编号**查**记录（不建记录）；记录不存在 ⇒ 第 1 个操作数写 **1**，三个浮点**不写**；
- 存在 ⇒ 分解 `0x1ff` 写的那个**平移矩阵**（不是 `0x220` 的第四个平移矩阵）；分解失败的条件本版**未取证**（见残差）——若发生，向**错误通道**上报一条说明（带编号），第 1 个操作数写 **1**，三个浮点不写；
- 分解成功 ⇒ 三个浮点输出 ← 分解出的**平移分量**，第 1 个操作数写 **0**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 读出某场景对象的本地平移 | 第 3 / 4 / 5 个操作数（浮点）← `0x1ff` 那个平移矩阵的平移分量 |
| 读取是否成功 | 第 1 个操作数（整数）← 0 成功 / 1 失败 |
| 错误通道 | 一次上报（仅「矩阵分解失败」；记录不存在**不**上报） |

**成立条件**

- 第 1 个操作数是**失败标志**（0 = 成功），⛔ 不是「是否有记录」的布尔值本身：记录不存在与分解失败**都**写 1。
- 记录不存在是**静默失败**；分解失败才上报错误通道，但**什么条件下会分解失败**本版未取证（见残差）。
- 读序是 **2 → 写 3 → 写 4 → 写 5 → 写 1**：标志是**最后**写的，所以三个浮点写失败（类型异常）时标志不会被写。
- 本条不改记录、不建记录、不置脏。

### 场景对象：批量属性 setter 族的取记录纪律（0x21e / 0x21f / 0x231 / 0x233 / 0x234 / 0x235 / 0x239）

<!-- rule: CORE-OPS-SCENE3D-RECORD-LOOKUP -->

这一族**每条**都以**第 1 个操作数**为**场景对象编号**，并做同一件前置：

> 按编号在**场景对象记录表**里取记录；**查不到就先建一条默认记录**（表里因此会多一条）。

随后各条把**其余操作数**写进**自己的一组字段**（逐条不同），并按各条自己的尾段处理场景标记。
**编号不做范围检查**；越界编号的后果本版不规定。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 按编号定位（必要时新建）场景对象记录 | 记录表里出现该编号的记录（默认记录或原有记录） |
| 各条自己的属性 | 该记录里各条自己的字段组（见各条残差） |

**成立条件**

- 这是**一族共享的前置**，不是“十条是同一实现”：字段组逐条不同，⛔ 不许把这一族压成一条 setter。
- 本族**不含** `0x21d` / `0x230` / `0x242`：`0x21d` 是整份复制、`0x230` 是清附加组、`0x242` 写两张表，三者各自单列。
- 「建默认记录」**先于**各条自己的门（若有）：即使该条随后什么都不写，表里也已经多了一条。
- 默认记录的初值（合同）：首字 **0**（位 0 / 位 1 都是 0）、两个三元向量全 **0**、当前色 / 终色 `0xFFFFFFFF`、轴 / 角 0；**八个 4×4 矩阵格（六个主格 + 附加组两格）的初值全部是单位矩阵**（与 `0x1fd` 条同一口径：每个矩阵写者都写整份矩阵，所以初值只在**该格从没有写者写过**的记录上才会被读到）。
- **位 0 的置 1 生产者**：本版只观察到 `0x1fb` 把它置 1；本族的 setter 与 `0x217` / `0x219` / `0x220` 都不写首字 ⇒ 新建记录之后位 0 仍是 0。⛔ 不许把「建了记录」当成「位 0 = 1」。
- 本族不含 `0x217` / `0x219` / `0x220`，也不含上面的 `0x21d` / `0x230` / `0x242`（它们各自单列；`0x220` 另有门，`0x217` / `0x219` 的读序见各自条目）。

### 场景的 1000 项表：写两项标志 / 全清（opcode 0x258 / 0x259）

<!-- rule: CORE-OPS-SCENE-TABLE-FLAGS -->

场景持有**两张平行的 1000 项记录表**（与上面的场景对象记录表**不是同一张表**），每项有若干 32 位字段。**这两张 = 纹理记录表（活动表）与它的存档快照**：活动表的写者、发布点（每次「请求文本层」）、存档取哪一块（**取快照** ⇒ 与活动表只在**来源文件格 / 颜色键 / 空白标记**这三类格上**差一拍**；标志两格与清零同时改两块，不差拍）、以及快照的**唯一合同内读者**，集中写在「列表与文本子系统」的「请求文本层」条；本节不重复。这两条只碰每项的**标志两格**（两张表都碰）。

**标志两格的身份（本版已定，⛔ 不许再写成"未取证"）**

- **第一格（`0x258` 的位 0 写的那一格）= 恢复重建门**：它的读者是**读档恢复** —— 逐项恢复时「**门 = 1 且来源文件格 ≥ 0**」才按来源文件格重新装载该槽的纹理，并把结果写回**活动表**（成功还清空白标记、失败在活动表里写 −1）。读档读的是**存档影像**里的这一格（写侧从快照整段搬过去的那份），⛔ 不是从活动表读；⇒ 它是**有读者的持久化字段**，不是死格。
- **第二格（`0x258` 的位 1 写的那一格）= 零读者标志**：全语料对它**只有写、没有任何读点**，领域角色本版**明确舍弃**（残差 `RES-SCENE-TABLE-FLAGS-READERS` 只覆盖这一格）。⛔ 不许把"第一格有读者"推成"两格都有读者"，也不⛔ 反过来说"两格都没有读者"。

- `0x258`（两个操作数：**编号**、**位掩码**）：
  - 读序 **2 → 1**；推进格数 = **5**；
  - 按编号定位两张表的同一项；
  - **第一格（恢复重建门）← 位掩码的第 0 位**（0 / 1）；
  - **第二格（零读者标志）← 位掩码的第 1 位**（0 / 1）；
  - 两张表写入**相同**的值；
  - **不做**编号范围检查（越界写属未定义行为，本版不规定后果）。
- `0x259`（无操作数）：
  - 推进格数 = **1**；
  - 把**两张表全部 1000 项**的这两格清 0；
  - 不碰其它字段。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某项的两个开关 | **活动表与快照**的同一项的两格 ← 位 0（恢复重建门）/ 位 1（零读者标志）（两张表同值） |
| 全清 | **活动表与快照**所有项的这两格 ← 0 |

**成立条件**

- 掩码**只取低两位**：第 2 位及以上不影响这两格；⛔ 不许把整个掩码存进去。
- 两张表**同值**：不是「一张表存位 0、另一张存位 1」，而是两张表都存**同一位对**。
- `0x258` 的编号**不做**范围检查；`0x259` 固定扫 **1000** 项。
- 编号**越界**不在本版合同内；本版只规定 `0..999`。
- 两条都**不**把场景标脏、**不**改每项的其它字段。
- 其它字段之一（每项的第一个 32 位格）由 `0x216` 读；标志两格与它**不是**同一格。
- **门那一格不是"纹理可用 / 有效"标志**：它只由这两条写、由读档恢复读；槽里有没有对象由纹理槽那张表决定（见「纹理」章的状态模型）。⛔ 不许实现成"门 = 1 才可画"。
- **两格的归宿不同**：第一格的身份与读者**已定**（读档重建判据），第二格**明确舍弃**（零读者）。⛔ 不许把两格合成一格，也⛔ 不许把"舍弃第二格"推成"第一格也没人读"。

**残差**

- `RES-SCENE-TABLE-FLAGS-READERS`（**已收窄**；`kind` 仍是 unknown，但只剩**第二格**）：**第一格**（恢复重建门）的读者**已找到** ="读档恢复逐项判「门 = 1 且来源文件格 ≥ 0」"，已经不是残差；**第二格**仍只有写、没有任何读点，它的领域角色与是否存在间接消费者未取证。⇒ 本版对第二格不规定任何行为差异（写进去的 0 / 1 都不改变可观察行为）。

### CG 参数记录（opcode 0x2da）

<!-- rule: CORE-OPS-CG-SET -->

读八个操作数：**CG 编号**（第 1 个，整数）+ **七个整数**（第 2..8 个），读序 **1 → 2 → 3 → … → 8**。

- 编号 **大于 10**（**按无符号**比）⇒ 向**错误通道**上报「CG 编号非法」，**一个字段都不写**（其余七个操作数**一次都不读**）；
- 编号 **0..9** ⇒ 把七个操作数**依次**写进该编号的 **CG 参数记录**的**七格**。这七格的领域身份由**消费方**（`0x23b` 的 CG 数字条）确定，
  依次是：**纹理槽（纹理 id）/ 条带左上 x / 条带左上 y / 单字宽 / 字高 / 字内空隙 / 字距**。
  写完后**不**置脏、**不**发请求、**不**建记录。
- 编号 **10** ⇒ 七个操作数**不落在这张记录表上**：它们落在**另一组七个格子**上 —— **脚本帧 0 到 6 各自的返回栈顶**（每帧一个；返回栈的容量、压栈与弹栈见「帧」章）。
  - 这七个值一写下去，帧 0..6 的**返回栈深度**就被直接改成给定的七个值；此后这些帧上的每次调用 / 返回都**从新深度继续**（调用把深度 +1、返回把深度 −1 并按深度取返回点）。
  - **反向也成立**：这些帧上的任何调用 / 返回，以及**帧复位**（把返回栈顶清 0）都会改掉这七格 —— 它们是**同一批格**，⛔ 不是「记录的一份副本」。
  - ⇒ 编号 10 **没有自己的记录**：「它的外观」就是**这七个帧的返回栈深度**。除落点外，其余写入行为与 0..9 相同。
- 七格的值**不做任何检查**（负数也照写）；编号**不从 1 开始**（0 合法）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某 CG（编号 0..9）的数字条外观 | 该编号记录的七格 ← 第 2..8 个操作数 |
| 编号 10 的「外观」 | **帧 0..6 各自的返回栈顶**（同一批格，双向改写） |
| 错误通道 | 一次上报（仅编号大于 10） |

**成立条件**

- 越界是**只上报、不写**（不是「写到一个默认记录」）；越界时后面的七个操作数**一次都不读**。
- 编号的合法集合是 **0..10**：判据是**无符号**的「> 10」—— ⛔ **不是有符号的「> 10」**、也⛔ **不是单独的「< 0」**；负数的无符号值远大于 10，**因此也落进越界这一支**（越界 = 只上报、不写）。
- 七格的**顺序**是合同：换序会让 `0x23b` 画出错位的数字条。
- 本条不做范围以外的夹取，也不建记录；编号 **0..9** 从未写过时消费方看到的**纹理槽为 0**（⇒ 视为**无效记录**），
  因为引擎复位时把这 **10 条记录**（每 7 格，共 **70 格**）整块清零。
  编号 **10** 的七格**不在**那一次清零的范围内：它们由**帧复位**（返回栈顶清 0）覆盖 ⇒ 刚复位时这七格也全为 0。
- 编号 10 与 0..9 的**唯一**区别是落点；⛔ 不许为编号 10 单建一条记录，也⛔ 不许把它当成「越界」。

**可证伪**

- 依次给编号 10 写 (7,5,5,6,7,1,2)，然后对帧 0 做一次调用：该帧的返回栈必须从深度 7 继续（新返回点写在第七格之后），返回时读到的必须是**原来第七格之后那个位置**；若返回点仍从深度 0 开始排 ⇒ 那七格不是返回栈顶。
- 刚复位（返回栈顶全 0）之后对编号 10 调 `0x23b`：必须报「CG 编号非法」（因为它的「纹理槽」是帧 0 的返回栈深度 = 0）；若照常画出一串数字 ⇒ 编号 10 有独立记录。
- 对编号 10 写七个值之后，只在帧 7 上做一次调用：七格必须**逐格不变**（帧 7 的栈顶是另一格）；若七格里有任何一格变了 ⇒ 编号 10 覆盖的帧范围写错。
- 依次用编号 **11** 与编号 **−1** 各执行一次 `0x2da`：两次都必须**恰一次**上报「CG 编号非法」，且**七个操作数一个都不读**（不建记录、不改任何格）；若编号 −1 被照写、或越界时仍读了第 2 个及以后的操作数 ⇒ 判据被写成了有符号比较、或越界支没在读完编号后立刻收手。

### CG 数字条：按数值画一串数字（opcode 0x23b）

<!-- rule: CORE-OPS-SCENE-CG-NUMBER-23B -->

读七个操作数：**起始绘制键**、**记录编号**、**数值**、**目标 x**、**目标 y**、**位数**、**标志**。
编号 **0..9** 的数字条外观来自 `0x2da` 登记的**七格记录**（纹理槽（纹理 id）/ 条带左上 x / 条带左上 y / 单字宽 / 字高 / 字内空隙 / 字距）。
建出的每一项都是一条**绘制项**（与 `0x1fb` 同一张绘制项表、同一套字段；只入队，不立即画）。

**先读记录编号并判有效性**：记录编号不在 `0..10` ⇒ 向**错误通道**上报「CG 编号非法」（与 `0x2da` 同一条文本），
本条到此为止：**其余六个操作数一次都不读、不删旧项、不建任何项**。
编号在 **0..9** 时，该编号记录的**纹理槽为 0** ⇒ 同样上报并到此为止（纹理槽 0 = 没登记过；复位把这 10 条记录整块清零，见 `0x2da`）。
编号 **10** 仍是合法编号（**按无符号比只排除 > 10 这一支**，负数因此也在内），但它的七格是**帧 0..6 的返回栈顶**，不是普通 CG 记录：
⇒ `0x2da` 的「纹理槽 0 ⇒ 无效」对它同样适用 —— 那个「纹理槽」是**帧 0 的返回栈深度**，所以帧 0 的返回栈为空（例如刚复位）时，编号 10 一律报「CG 编号非法」。

有效 ⇒ 按下列顺序执行（**读序是合同**：它的可观察后果是操作数类型异常的抛出顺序）：

1. 读**起始绘制键**（第 1 个）、**数值**（第 3 个）、**位数**（第 6 个，记作 `n`）、**标志**（第 7 个）；
2. **清旧项**：从**起始绘制键**起、长度 = `n`，把左闭右开区间里的旧条目从与「拆离」（`0x1f7`）**同一组四张**按键有序的表里删除：
   **绘制项表**、**网格表**，以及**两张同形的条目表** —— 一张由「按编号置存在位并写值」这一族指令写，另一张由另三条场景指令写；
   两张的条目都是同一形状的长记录。`0x1f7` 的 `个数 ≤ 1` 与 `个数 > 1` 删的是**同一组四张表**，
   只有**区间语义**来自 `个数 > 1`。删除语义与 `0x1f7` 相同（条目自己的**内嵌对象 / 缓冲一并释放**；删除顺序固定：
   **绘制项表 → 网格表 → 先那张条目表 → 后那张条目表**，只有**网格表**的条目在摘键之前先释放内嵌对象与它自己的三份缓冲，
   其余三张表没有字段级释放；**每张表**只要真的删到了条目就各标一次脏 —— 四张表 ⇒ **最多四次**，一条都没删到的表不标脏），见「按键拆离」。删到任何条目 ⇒ 场景标脏；
   ★ **场景命令表不在这四张之内**：它按**命令键**有序、与这四张同键但不同表；本清理**不碰命令记录** ⇒ 命令记录**不随**这次清理消失：
   四张表里落在键区间内的条目立刻不见，但同一键区间上的**命令记录仍然在**，下一次渲染步的命令档仍会遍历到它并照常执行
   （命令表的清除只发生在渲染步收尾按「本步还有没有动作」判定之后）。
   ★ **旧名对照（A / B 以本段为准）**：删除顺序是
    **绘制项表 → 网格表 → 辅助表 A → 辅助表 B** ⇒ 辅助表 **A** = 由**另三条场景指令**写的那张同形条目表（**删序第 3 张**）；
    辅助表 **B** = 由「按编号置存在位并写值」这一族指令写的条目表（**删序第 4 张**）。
    ★ **`0x21d` 的整份复制复制的是辅助表 B**（三张被复制的表里那张条目表就是它）。
    ⛔ 不许把「四张表」理解成含场景命令表。
3. 逐位建绘制项（见下）；每建出一项 ⇒ 场景标脏。建项顺序是**个位先、高位后**。

可观察的读序（**合同**）：**第 2 个（判有效性）→ 第 1 个 → 第 3 个 → 第 6 个 → 第 7 个 →（清旧项）→
每个被画出的位：第 4 个 → 第 5 个 → 建项**。**位数 ≤ 0 时第 4 / 5 个一次都不读**（因此它们也不会抛类型异常）。

**逐位规则**（`n` = 位数；`d` = 数值的十进制位数，至少 1）

- 第 `j` 位（`j = 0` 是个位，`j` 从 `0` 数到 `n - 1`）的数字 = **该位的截断余数**：取 `数值 ÷ 10^j` 的整数商（除法**向零截断**），再取「商 − (商 ÷ 10) × 10」。
  正数上这等于「商的个位」；**负数上它是 −1..−9 的负余数**（个位可能是 0），见下「数值为负」。
- 在字段内，第 `j` 位占从右数第 `j` 个槽（即从字段左边界数第 `n - 1 - j` 个槽）。
- **画哪些位**：个位（`j = 0`）**永远画**；`j > 0` 只有在「该位及更高位中存在非零数字」时才画（前导零抑制）。
  ★ **右对齐档**另有一条：标志的**第 0 位**置位 ⇒ 前导零抑制取消，`n` 个槽全画。
- **对齐**由标志决定，先判**第 1 位**、再判**第 2 位**：第 1 位置位 ⇒ **居中**；否则第 2 位置位 ⇒ **左对齐**；都不置 ⇒ **右对齐**。
  目标步长 = 单字宽 + 字距（可为负或 0）。
  - 右对齐：目标 x = **目标 x** + (`n - 1 - j`) × 目标步长；
  - 居中：目标 x = 右对齐位置 − `trunc((n - d) × 目标步长 / 2)`（向零截断）；
  - 左对齐：目标 x = 右对齐位置 − (`n - d`) × 目标步长。
  - 三种对齐的目标 y 都是**目标 y**；目标位置按**整数**算完再转成浮点（居中档也**不会**出现半个像素）。
- **源矩形**（在数字条纹理里）：**源格子步长 = 单字宽 + 字内空隙**；左 = 条带左上 x + 源格子步长 × 该位数字；
  上 = 条带左上 y；右 = 左 + 单字宽；下 = 上 + 字高。
- **建项**：绘制键从**起始绘制键**起、按建项顺序**连续**编号（被跳过的高位不占键）；每项写：纹理槽（记录第 1 格）、
  源矩形、目标位置（两个浮点）、第三个浮点 0，并置该项的**有效位**（与 `0x1fb` 的「有效 / 已存在」同一位）。

**数值为负**（位数与对齐都按上面的规则走，本条**不另设「符号」分支**）

- **十进制位数 `d`** 与正数同式计算：按**有符号、向零截断**的除法反复除 10，数到商为 0 为止（数值 0 时 `d = 1`）⇒ `d` 是**绝对值**的位数。
- **每一位的数字 = 该位的截断余数** ⇒ 负数的每一位是 **−1..−9**（个位可能是 0）；⛔ 不是「向下取整」的余数。
- 这个数字**不做绝对值**，而是**直接**乘进「源格子步长」⇒ 源矩形被推到条带**左侧** `|数字|` 个格子处
  （左边界 = 条带左上 x + 源格子步长 × 数字；右边界仍为「左 + 单字宽」；上下边界与数字无关）。
- **画哪些位**的判据同正数（个位永远画；其余位看「当前商是否为 0」）⇒ **画出的项数与绝对值相同**，但每一项取到的**字形不是该数字**。
- ⇒ 引擎**没有**「负号字形」，也**不取绝对值**：负数值画出来的是一串**取自数字条左侧**的字形。⛔ 不许补 `abs`、补负号、或把负数当成「不画」。

**位数 ≤ 0**

- **位数 = 0** ⇒ 清理区间为空（区间里一条旧条目都不删、也不标脏），一个位都不画，第 4 / 5 个操作数**一次都不读**。
- **位数 < 0** ⇒ 清理区间的**上界低于下界**。引擎只在「两端点各自定位到的位置**不同**、且起点**不在表的末尾**」时才真的进入区间擦除；一旦进入，擦除循环以「起点追上终点」为终止条件，而倒挂的两个端点**永远不会追上** ⇒ 循环会走过整张表、把表的**结束标记（哨兵结点）**也交给结点释放，随后继续读已释放的结点。
  ⇒ **这是未定义行为**：⛔ 不许把它实现成空操作、⛔ 不许静默把区间边界对调、⛔ 不许当成「只删下界之后的项」。**建议**实现拒绝或记诊断（例如中止 / 响亮失败）。清理之前已经写进去的推进格数不受影响。
- 三个对齐档对「位数 ≤ 0」是**同一个出口**（一个位都不画）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个绘制键上的数字 | 绘制项表里的条目（纹理 / 源矩形 / 目标位置） |
| 数字串占用的键区间 | 旧的 `[起始绘制键, 起始绘制键 + 位数)` 条目被删；新条目按建项顺序连续编号 |
| 场景需要重绘 | 脏标记 ← 1（删到旧条目或建出任一项） |
| 错误通道 | 一次上报（仅记录编号无效 / 0..9 的纹理槽为 0） |

**成立条件**

- **记录无效**与**位数 ≤ 0** 是两条**不同**的返回路径：前者上报错误通道且不删不建，后者静默返回（清理已按位数执行）。
- 读序的**可观察判据**只有两条：`位数 ≤ 0` ⇒ 第 4 / 5 个**一次都不读**（因此它们不会抛类型异常）；
  其余情况第 4 / 5 个**至少读一次**。读到非法类型时按上面的读序抛异常。
  ⛔ 不许把"读了几次"当判据 —— 纯读取不可观察，只有"读不读 / 读到时抛不抛"进合同。
- 记录编号的合法集合是 **0..10**，负数按越界处理。**0..9** 的编号还要求该记录的**纹理槽非 0**
  （`0x2da` 从 0 开始编号，所以 0 是合法编号；纹理槽 0 表示这条记录没登记过，复位把这 10 条记录整块清零）。
  编号 **10** 的七格是**帧 0..6 的返回栈顶**，不是普通 CG 记录：它的「纹理槽」= 帧 0 的返回栈深度
  ⇒「纹理槽 0 = 没登记过」对编号 10 同样成立（刚复位后编号 10 一律报「CG 编号非法」）；编号 10 的画法与 0..9 **完全相同**，只是七格参数来自那七个帧的返回栈深度。
- 清理长度用**第 6 个操作数的原值**，不是实际画出的位数：位数 4、只画出 2 位时，键区间的 4 个旧条目都会被删。
- 绘制键按**建项顺序**分配（个位先），所以数值的个位总是拿到起始键；⛔ 不许按从左到右的位置分配键。
- `0x2da` 的七格是**同一份**记录：改记录会改变之后所有 `0x23b` 的外观；⛔ 不许在本条里按操作数重建外观。
- 目标坐标与源矩形都是**整数**；步长可为负（字距为负时数字向左排）——这是合同，⛔ 不许夹到 0。
- 标志的高位（第 3 位及以上）不参与判定；同时置第 1、2 位时按**居中**处理。
- 数值的十进制位数可以**大于**位数（`d > n`）：本条只画低 `n` 位，但居中 / 左对齐用的 `d` 仍按**完整数值**的位数算（⛔ 不许把 `d` 夹到 `n`）；`n - d` 为负时按 `trunc`（向零截断）取整，目标位置**唯一**。
- 数值为负：每一位的数字是**负余数**、直接乘进源格子步长（不取绝对值、不画负号）；位数 < 0 的上界倒挂是**未定义行为**，位数 = 0 是空区间 —— 两者的处置见上面「数值为负」与「位数 ≤ 0」两段。

### 场景对象：整份复制（opcode 0x21d）

<!-- rule: CORE-OPS-SCENE3D-21D -->

读两个操作数，**两个都是编号**，读序 **第 2 个 → 第 1 个**：第 1 个是**源**，第 2 个是**目标**。按源编号在**三张**表里各查一次：**场景对象记录表**（与 `0x23b` 所说的「绘制项表」是**同一张表**）、**网格表**，以及**其中一张**条目表 —— 就是「按编号置存在位并写值」这一族指令写的那张；**另一张同形条目表**与**场景命令表**都**不参与**本复制。某表有源记录 ⇒ 把该表的记录**整份复制**到目标编号（对象记录整份；网格记录整份，但副本的**顶点缓冲新建**、**不**与源共享缓冲，新缓冲的内容 / 顶点色来源本版**不规定**；条目记录整份），目标记录不存在时先建默认记录再被覆盖；三张表**都没有**源记录 ⇒ 向**错误通道**上报一条含**源编号**的说明且**一张表都不改**（缓冲建立失败同样上报，且该表复制不完成）。复制成功后把场景标**脏**；**不**置「有动画」。
★ **「两张辅助表之一」这句话要按哪一张读**：两张同形条目表里**只有一张**参与复制 —— 就是**辅助表 B**（由「按编号置存在位并写值」这一族指令写的那张）；**辅助表 A 不参与**。⛔ 不许按「两张辅助表之一」的旧措辞去复制两张，也⛔ 不许把这里读成辅助表 A。

**成立条件**

- ⛔ 不是 setter：本条不把操作数写进字段，写进的是一份记录副本；⛔ 不许并进本族的「取记录 + 写字段」实现。
- 「按需建默认记录」只对**目标**编号、且只在**对应源记录存在**时发生；三张表的复制**互相独立**。
- 读序与「第 1 个是源」是合同；编号不做范围检查；源 = 目标时的后果本版不规定。

### 场景对象：一对整数与一个缩放矩阵（带「已存在」门）（opcode 0x21e）

<!-- rule: CORE-OPS-SCENE3D-21E -->

读六个操作数：**编号**（整数）+ **两个整数** + **三个浮点**；读序 **4 → 5 → 6 → 3 → 2 → 1**（三个浮点先读，编号最后）。按编号取记录（缺则先建默认记录）：**「已存在」位**为 0 ⇒ **一个字段都不写**（默认记录已建）；为 1 ⇒ 置**首字第 1 位**（与 `0x202` 的「有窗」同一位），把 **G3 配置格 ← 1**、把该记录的**窗起点**清 0、把两个整数写进**本条自己的两格**、把三个浮点**各 ÷100**（百分之一为单位）写进**本条自己的缩放矩阵**，随后把场景标**脏**并置「有动画」。

**成立条件**

- **÷100 是语义**（百分数），⛔ 不许当归一化系数省掉。
- 「已存在」门只看记录自己的位；位为 0 时**仍然建记录**，所以「什么都不写」在表内容上与「没调用」不同。
- ⛔ 不许与 `0x1fd` 合并：两条写的是**不同**的缩放矩阵。
- 置首字第 1 位即**进入窗机制**；窗字段（延迟 / 持续时间 / 终色）保持原值，推进见「场景计时窗」。⛔ 不许把「不写窗字段」写成「不排窗」。

### 场景对象：一对整数、轴角与一个旋转矩阵（带「已存在」门）（opcode 0x21f）

<!-- rule: CORE-OPS-SCENE3D-21F -->

读七个操作数：**编号**（整数）+ **两个整数** + **四个浮点**（轴 x / y / z + **角度（度）**）；读序 **4 → 5 → 6 → 7 → 3 → 2 → 1**。按编号取记录（缺则先建默认记录）：「已存在」位为 0 ⇒ **一个字段都不写**；为 1 ⇒ 置**首字第 1 位**、把 **G3 配置格 ← 1**、把**窗起点**清 0、把两个整数写进**本条自己的两格**、把四个浮点分别写进**本条自己的轴三格与角一格**，并按「度 → 弧度」（乘 π / 180）写进**本条自己的旋转矩阵**；场景标**脏**并置「有动画」。

**成立条件**

- **角度是度**，引擎内部按 π / 180 换弧度；⛔ 不许把第 7 个操作数当弧度。
- 轴与角**另存一份**（不是只进矩阵）：后续读到的是这两份格，不是从矩阵反解。
- ⛔ 不许与 `0x1fe` 合并：两条写的是**不同**的旋转矩阵与**不同**的轴角格。「已存在」门与读序同 `0x21e`。
- 置首字第 1 位即进入窗机制；窗字段保持原值，推进见「场景计时窗」。

### 场景对象：清附加组的开关位与六格（opcode 0x230）

<!-- rule: CORE-OPS-SCENE3D-230 -->

读一个操作数：**编号**。按编号取记录（缺则先建默认记录），随后把记录的**「附加组」开关位**清 0，并把该组存下的**六格**清 0：`0x231` 的**清格与第一个值格**、`0x232` 的**第一个值格**、`0x233` / `0x234` / `0x235` **各自的值格**（2 + 1 + 3 = 6）。⛔ 清的范围**不含** `0x231` 的后两个值格、`0x232` 的第二个值格、`0x233`..`0x235` 各自的清格与矩阵。本条**不**标脏、**不**置「有动画」、**不**碰首字第 1 位与第 0 位。

**成立条件**

- 这是**整组复位**：开关位与六格是**一次**动作，⛔ 不许只清开关位。
- 复位**不等于**回到默认记录：上列“不清”的格（`0x231` 后两个值格、`0x232` 第二格、233..235 的清格与矩阵）**保留**原值。
- **不标脏**：本条之后场景不会因它自己而重绘。⛔ 但「编号不存在 ⇒ 建默认记录」那一步会标脏，两件事分开写。无门：编号不存在时照清（清的是刚建出的默认记录，本来就是 0）。

### 场景对象：三个整数（置附加开关位）（opcode 0x231）

<!-- rule: CORE-OPS-SCENE3D-231 -->

读四个操作数（**编号** + 三个整数），读序 **4 → 3 → 2 → 1**。按编号取记录（缺则先建默认记录），**无门**：置记录的**「附加组」开关位（首字第 2 位）**、把附加组的**一个清格**清 0、把三个整数写进**附加组的三格**（其中后两格与 `0x239` 的第 4、5 个操作数**同格**）；场景标**脏**，**不**置「有动画」。

**成立条件**

- **无门**：编号不存在时先建默认记录，然后照写。
- 置的是**附加组开关位**，与**首字第 1 位**（有窗 / 已配置）**不同位**；⛔ 不许合并成同一个位。
- 与 `0x239` 的**两格重叠**是真实复用，⛔ 不许实现成两套独立格。本条**不**写 G3 配置格。

### 场景对象：一个整数与一个缩放矩阵（置附加开关位）（opcode 0x233）

<!-- rule: CORE-OPS-SCENE3D-233 -->

读五个操作数：**编号** + **一个整数** + **三个浮点**；读序 **3 → 4 → 5 → 2 → 1**（三个浮点先读）。按编号取记录（缺则先建默认记录），**无门**：置**附加组开关位**、清附加组的**一个清格**、把整数写进**附加组的值格**、把三个浮点**各 ÷100** 后写进**附加组的缩放矩阵**；场景标**脏**，**不**置「有动画」。

**成立条件**

- **÷100 是语义**（百分数），与 `0x21e` 同一约定；⛔ 不许省。
- ⛔ 不许与 `0x21e` 合并：矩阵不同（附加组 vs `0x21e` 那套），门也不同（无门 vs 有门）。
- 清格与值格是**两格**：⛔ 不许写成同一格。

### 场景对象：一个整数与三个浮点（置附加开关位）（opcode 0x234）

<!-- rule: CORE-OPS-SCENE3D-234 -->

读五个操作数：**编号** + **一个整数** + **三个浮点**；读序 **3 → 4 → 5 → 2 → 1**。按编号取记录（缺则先建默认记录），**无门**：置**附加组开关位**、清附加组的**一个清格**、把整数写进**附加组的值格**、把三个浮点**原值**写进**附加组的三个浮点格**；场景标**脏**，**不**置「有动画」。

**成立条件**

- 三个浮点**不除 100**（与 `0x233` 的缩放不同）：⛔ 不许按「同类」套用 ÷100。
- 写的是**三个独立浮点格**，不是矩阵；⛔ 不许把附加组当成一个 4×4 矩阵的局部。
- 其余同 `0x233`：无门、清格与值格两格分工、置附加开关位。

### 场景对象：一个整数与一个平移矩阵（置附加开关位）（opcode 0x235）

<!-- rule: CORE-OPS-SCENE3D-235 -->

读五个操作数：**编号** + **一个整数** + **三个浮点**；读序 **3 → 4 → 5 → 2 → 1**。按编号取记录（缺则先建默认记录），**无门**：置**附加组开关位**、清附加组的**一个清格**、把整数写进**附加组的值格**、把三个浮点**原值**写进**附加组的平移矩阵**；场景标**脏**，**不**置「有动画」。

**成立条件**

- 三个浮点写的是**平移矩阵**，⛔ 不是 `0x1ff` / `0x220` 的平移矩阵，也不是 `0x234` 的三个浮点格。
- 原值，不除 100。
- 其余同 `0x233`：无门、清格与值格两格分工、置附加开关位。

### 场景对象：一对整数 + 附加组三个整数（带「已存在」门）（opcode 0x239）

<!-- rule: CORE-OPS-SCENE3D-239 -->

读六个操作数（**编号** + 五个整数），读序 **6 → 5 → 4 → 3 → 2 → 1**。按编号取记录（缺则先建默认记录）：「已存在」位为 0 ⇒ **一个字段都不写**；为 1 ⇒ 置**首字第 1 位**、把**窗起点**清 0，并写**源矩形窗口**（见「绘制项的消费者」的 4.1）：第 2 / 3 个操作数 = **延迟 / 持续时间**；第 4 / 5 / 6 个 = **步进总数 / 每行步数 / 开关字**（后三者其中两格与 `0x231` 重叠）；场景标**脏**并置「有动画」。

**成立条件**

- ⛔ 本条**跨两组**：置的是首字第 1 位，写的三格却属附加组；不许按「一组 opcode 一组格」硬分。
- ⛔ **不写 G3 配置格**（`0x21e` / `0x21f` 都写）：这是真实差异，不许抹平。
- 「已存在」门与读序同 `0x21e`；位为 0 时仍然建记录。本条写的正是源矩形窗口自己的字段；窗起点清 0 后由派生盖章（见 4.1）。

### 场景对象：同一个整数写进两张表的记录（opcode 0x242）

<!-- rule: CORE-OPS-SCENE3D-242 -->

读两个操作数：**编号** + **一个整数**，读序 **2 → 1**。按编号在**场景对象记录表**取记录（缺则先建默认记录），把该整数写进该记录的一格；**同一个值**还要写进**另一张表**里同一编号的记录的一格（该表里不存在该编号时同样先建默认记录）。**两处写值本身**不置任何位、不清格、不标脏、不置「有动画」；⛔ 但「编号不存在 ⇒ 建默认记录」那一步**会**把场景标脏（见下），两件事分开写。

**成立条件**

- **两处写入、同一个值**：⛔ 不许只写一处；两处的键是**同一个编号**。
- 两张表**各自**按需建记录：一张表里没有该编号**不**影响另一张。
- **写值本身不标脏，但建默认记录会标脏**：本条的两处写值都不置脏 ⇒ 记录已存在时场景不因本条而重绘；
  ⛔ 但「编号不存在 ⇒ 建默认记录」那一步**会**把场景标脏 —— 它与 `0x1fb` / `0x230` 是**同一条**共享前置（「按编号取记录，缺则先建默认记录」），不是本条私有的效果，两件事分开写。
- **只有为「场景对象记录表」建默认记录才置脏**：为**另一张表**建默认记录**不**置脏 ⇒「第一张表已有该编号、第二张表没有」时，场景**不**因本条而变脏。
- **脏与「有动画」是两个状态**：建默认记录只置脏，⛔ 不置「有动画」；本条也不置位、不清格。

### 场景条目：按编号置存在位并写值（opcode 0x344）

<!-- rule: CORE-OPS-SCENE-ENTRY-344 -->

`0x344` 有两个操作数：**编号**、**值**；读取顺序是 **2 → 1**。

- 按编号在**场景条目表**取条目；不存在则先建一个默认条目。
- ★ **条目住在哪里**：「条目」不是一张**独立的数组**，而是**场景持有的那张按整数编号索引的表**里的一项；每项是一份**远大于两个字**的记录（本作样本里是数百字节）。⇒ 写一条 `0x344` 的效果**只**落在该编号对应的**那一项**上，⛔ 不许另建一张"条目数组"。
- ★ 条目的**值宽**是整份复制时的搬运单位：副本拿到的是一份**整份值的拷贝**（⛔ 不是只拷本条写的那两格）；值里其余格随复制带走。
- 该项的**首字第 0 位**置 1（**只置不清**）、**第二格** ← 操作数给的值；该项的**其余字段本条不动** —— 它们由别的条目 / 别的指令写同一项。
- 把该条目的**存在位**（**条目的首字第 0 位**）置 1（**只置不清**），并把**值**写进该条目的**第二格**（与首字不同字）。
- ★ **这张表是辅助表 B，不是绘制项表**：置的是该条目的存在位、写的是它的第二格；`0x1fb` / `0x1ff` 写的是绘制项表。
  两张表按**同一编号**各持一条记录、**互不影响**（写一张表**不**创建另一张表的记录）。
  两条「存在位」**位号相同**（都是各自记录的首字第 0 位）但**不是同一位**（不同的表、不同的首字）⇒ ⛔ 不许用「位号相同」推出「同一张表」，也⛔ 不许让一条指令的存在位去满足另一条的「已存在」判据。
- ★ **条目远不止这两个格**：同型的条目容器装的是数百字节的值，其字段语义**本版不规定**（见残差）。因此「置存在位」**不**蕴含「条目是空的」或「其它格是 0」。
- ★ 条目的**值格不是**绘制项 / 网格 / 列表项规则写的格：那些规则各用**自己的表**，条目表（辅助表 B）与它们各持一份；同一编号在不同表里可以有不同的值，**互不覆盖**。
  值格**没有本版可指认的消费者**；它唯一的可观察后果是：条目被**整份复制**时，副本的值格等于源的值格。
- 该条目表其余字段的内部语义**本版不展开**（见残差 `RES-SCENE-ENTRY-TABLE-FIELDS`）。
- 把场景的**脏标记**置 1。
- 推进格数 = 5；不改门位、不改当前帧、不写其它脚本变量。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个编号的条目存在 | 条目首字第 0 位 = 1（只置） |
| 条目上的值 | 条目第二个字 ← 第 2 个操作数 |
| 条目的其它字段 | 本版不规定（同型容器里是数百字节的值） |
| 场景需要重绘 | 脏标记 = 1 |

**成立条件**

- 读取顺序是 **2 → 1**：先读值、再读编号。
- 「建默认条目」与「置位 / 写值」是两步；条目已存在时**不重置**它的其它字段。
- 位只**置**不清：多次调用本条，首字的其它位**保持**（⛔ 不许整字覆盖成 1）。
- 值格与首字**不同字**；⛔ 不许把值写进首字。
- 条目表（辅助表 B）与绘制项表、网格表是**不同的表**（见上）：⛔ 不许用位号相同推出同表。
- 这条只改该条目与脏标记，不置「有动画」，也不排计时窗。

**可证伪**

- 对同一条目连调两次、两次第 2 个操作数不同 ⇒ 值格 = 后一次，且位字**只有**第 0 位被置（若位字变成恰为 1 ⇒ 整字覆盖错）。
- 对同一个编号先写本条、再用另一条只写**该项其它字段**的指令 ⇒ 首字第 0 位与第二格**必须**仍是本条留下的值（别的指令不能把它们清掉、也不能把整项覆盖成另一份记录）；若被清掉 ⇒ 「条目就是那张表的一项」写错（被实现成了另一张数组）。
- 只对某编号调本条（写条目表）⇒ 再用只读绘制项表的指令观察该编号：必须**仍是默认记录 / 不存在**（若已存在 ⇒ 两张表是同一张）。

### 显示适配：内容怎么放到当前显示尺寸上

<!-- rule: CORE-SCENE-DISPLAY-FIT -->

引擎在**图形初始化**与**显示设置改变**两个时刻，把一组**显示适配参数**算好放在渲染器上；绘制条目时按它取"缩放 / 偏移 / 视图矩阵"。这些参数**不是场景状态、不是脚本状态、不是存档状态**。

**输入**

- **后缓冲尺寸** `(BW, BH)`（屏幕像素）。
- **虚拟全屏是否开** `vfOn`：配置 `display:VirtualFullScreen` **非 0** 即开。
- **虚拟全屏类型** `T`：0 / 1 / 2（配置 `display:VirtualFullScreenType`；虚拟全屏关闭时不用）。
- **宽高比模式** `A`：配置 `display:AspectMode` 的当前值（0 = 按比值适配；非 0 = 画布直接取后缓冲）。
- **固定分辨率模式** `fixed`：配置 `display:ScreenMode` 的**生效值**（窗口态为真）；它不进公式，只在读取缩放 / 原点的取值器里短路成 `s=(1,1)`、`o=(0,0)`。
- **参考尺寸** `(refW, refH)`：虚拟全屏开 ⇒ 桌面尺寸与 `set:WinX/WinY` 逐分量取大；虚拟全屏关 ⇒ 全屏宽 / 高（经分辨率校验后的可用显示模式）。

**算术约定（缺一条就会差 1 像素）**

1. `trunc(x)` = 向零截断（⛔ 不是 floor、⛔ 不是四舍五入）。
2. `half(x) = trunc(x × 0.5)`（先乘 0.5 再截断）；只在原点里用。
3. 中间量按双精度算；`canvasW = trunc(canvasH × (1 / t))` 算的是 `1/t` 再乘（⛔ 不是 `canvasH / t`，边界上可能差 1 像素）。
4. 比较 `rH ≤ rW` **含等号**（相等算"高受限"）。

**主公式**

```text
fit(BW, BH, vfOn, T, A, refW, refH):
  if vfOn == 0:
    s = (1, 1)
    o = (trunc((canvasW - BW) / 2), trunc((canvasH - BH) / 2))   # canvas 为当前画布
    view = 单位阵（函数不写）
    return

  view = 单位阵
  if T ∉ {0, 1, 2}: return          # 退化出口：只写参考尺寸，原点/缩放保持旧值
  kx = refW / BW; ky = refH / BH
  if T == 0 or T == 1:
    if A == 0:
      t = refH / refW
      CH = trunc(BW * t); CW = BW
      if CH < BH: CH = BH; CW = trunc(BH * (1 / t))
    else: CW = BW; CH = BH
  else: CW = refW; CH = refH
  rW = CW / BW; rH = CH / BH
  if T == 0:
    s = (1, 1)
    if A == 0:
      if rH <= rW: ox = trunc((CW - BW*rH) * 0.5); oy = 0; vw = CW - 2*ox; vh = CH
      else:        ox = 0; oy = trunc((CH - BH*rW) * 0.5); vw = CW; vh = CH - 2*oy
    else: ox = 0; oy = 0; vw = CW; vh = BH
  elif T == 1:
    if A == 0:
      if rH <= rW: ox = trunc((CW - BW*rH)*0.5); oy = 0; vw = CW-2*ox; vh = CH; view = Scaling(ky, ky, 1); s = (rH, rH)
      else:        ox = 0; oy = trunc((CH - BH*rW)*0.5); vw = CW; vh = CH-2*oy; view = Scaling(kx, kx, 1); s = (rW, rW)
    else: ox = 0; oy = 0; vw = CW; vh = BH; view = Scaling(kx, ky, 1); s = (1, 1)
  else:  # T == 2
    if A == 0:
      if ky <= kx: ox = trunc((refW - BW*ky)*0.5); oy = 0; vw = refW-2*ox; vh = refH; view = Scaling(ky, ky, 1); s = (ky, ky)
      else:        ox = 0; oy = trunc((refH - BH*kx)*0.5); vw = refW; vh = refH-2*oy; view = Scaling(kx, kx, 1); s = (kx, kx)
    else: ox = 0; oy = 0; vw = refW; vh = refH; view = Scaling(kx, ky, 1); s = (kx, ky)
  # 写回：canvas=(CW,CH)、原点、视口、缩放、参考尺寸、view
```

**三条不变量（实现可作断言）**

- `T == 0` ⇒ 缩放恒 (1,1)、视图矩阵恒单位阵。
- `T == 1 且 A == 0` ⇒ 缩放恒 (1,1)（画布只会是"宽等于后缓冲宽"或"高等于后缓冲高"，分支正好取到恰为 1 的那个比值）。
- `A != 0` ⇒ 原点 (0,0)；`T == 0/1` 时画布高 = 后缓冲高。

**固定分辨率模式**：一个 0/1；它**不进上面的公式**，只在**读取缩放 / 原点**的取值器里短路成 `s=(1,1)`、`o=(0,0)`。

**两张矩阵**

- **场景视图矩阵**：上面的 `view`（只缩放、不平移；`vfOn == 0` 与 `T == 0` 时**不写**、保持调用方刚置的单位阵；`T ∉ {0,1,2}` 的退化出口也**不写**，保持旧值）。
- **逆缩放矩阵**：绘制入口现场构造 `Scaling(1/sx, 1/sy, 1)`，**右乘**进本笔矩阵；固定分辨率模式下 s=(1,1) ⇒ 这张矩阵退化成单位阵（**仍然乘一次**，数值无影响）。语义：`[20, 30)` 那一档的位置已经被乘过 s，这张矩阵把它抵回去。
- **乘入门（互斥，每一笔最多乘一张）**：设 `F` = 场景的屏幕形态副本（窗口态 1 / 占满屏态 0）、`D` = 绘制目标编号、`tex` = 纹理编号：
  - **场景视图矩阵** ⇐ `F == 0` **且**（`D < 0` **或** `D == 39`）**且** `tex ∉ [20, 30)`；
  - **逆缩放矩阵** ⇐ `F == 0` **且** `D ≥ 0` **且** `D != 39` **且** `tex ∈ [20, 30)`。
  - ⛔ 不许写成"目标编号 ≥ 0 且 ≠ 39 时乘视图矩阵" —— 那是**反的**：目标 38 与一切纹理目标**不乘**视图矩阵。
- **与「场景自身变换」(0x229) 的关系**：**不是同一个矩阵**。0x229 的矩阵由场景自身记录派生、按**键区间**门控，在消费者里先乘进本步变换；适配矩阵（视图或逆缩放）在**绘制入口最后右乘**。⇒ 装配顺序是"**0x229 在左、适配在右**"。

**折回画布坐标（占满屏态）**

- 交付绘制之前，两个**位置**分量各**加上一个偏移**：窗口态恒 0；占满屏态的偏移 = **负的**视口原点 / 内容缩放（等价于"位置 − 原点/缩放"；`T == 1` 且目标为后缓冲时偏移取 (0,0)）。
- 偏移作用在**位置**上、⛔ 不改矩形四边。
- 只有纹理编号 `[20, 30)` 那一档才把位置**乘缩放 + 半上取整**；其余档位置**不缩放、也不取整**（原样交给绘制）。

**成立条件**

- 这四类参数**没有**脚本写入者、也没有存档 / 场景资产写入者。⛔ 不许把它们建模成"场景相机对象"、⛔ 不许让脚本能直接写。
- "无相机 / 无缩放"应读成**固定分辨率模式生效**：缩放 = 1、偏移 = 0，但取整照做。
- 显示设置改变会**重算**这组参数并可能**重置设备**（离屏画布随之重建）。

**可证伪**

- 把显示配置改成"固定分辨率模式"后重开：若位置仍被乘了缩放 ⇒ 本规则错。
- 把窗口从全屏切到窗口化（触发重置设备）：若视口原点没有被重算 ⇒ 本规则错。
- 目标 = 38（画布）画一笔：若乘了视图矩阵（画面被缩放两次）⇒ 乘入门错。
- 目标 = 后缓冲、纹理编号 5 画一笔：若**没有**乘视图矩阵 ⇒ 乘入门错。
- 找一条写这四类参数的脚本指令：若存在 ⇒ 本规则"无脚本写入者"错。

### 场景自身变换与作用键区间（opcode 0x229）

<!-- rule: CORE-OPS-SCENE-SELF-TRANSFORM-229 -->

- 先把**场景自身的记录与状态重置**（场景自身记录恢复默认值；作用键区间清 `(0,0)`；场景标脏）。
- 第 1 个操作数 = 作用**键区间起点**，第 2 个 = **计数**（区间 = `[起点, 起点+计数)`）。
- 第 3 / 4 / 5 个操作数 = **三个浮点**，写进**场景自身记录**的平移三元组（X / Y / Z）。
- 推进格数 = **11**（写成在重置与读数之前）。
- 写成功 ⇒ 场景标脏。**没有脚本可观察的返回值。**

**成立条件**

- ⛔ 不许把它写成"设置场景相机"：它写的是**场景自身记录的平移** + 一个**作用键区间**（配合「绘制项的消费者」的额外变换条款）。
- ⛔ 不许把"重置"漏掉：这条指令**先清**场景自身状态，再写新值（因此它同时清掉上一次的作用区间）。
- **读序是 2 → 1 → 3 → 4 → 5**（先数、再起点，然后三个浮点）：多个非法操作数时，抛出的位置由这个次序决定。
- 两个整型的取用与三个浮点的取用走**不同的原语**：浮点槽收到整数操作数按数值转换（不抛），整数槽收到浮点按截断。
- 重置**早于**任何读数：读数抛出时区间已经是 `(0,0)`、平移已经清零，推进格数已经是 11。

**可证伪**

- 连写两条 `0x229`（不同键区间）：若第一条的区间残留 ⇒ "先重置"错。
- 用 `0x229` 设区间与平移后不画任何条目：若场景的"脏"没有置 1 ⇒ 尾段错。
- 用 `0x229` 设区间后删掉该指令重跑：若平移仍生效 ⇒ 本条错（它写的是场景自身记录，重跑会重置）。
- 设区间 `[5,6)` 与平移 X=2，画一条键 5 的绘制项：若它没有右移 2 像素 ⇒ 消费者的额外变换错；
  换成键 6 的条目若也右移 ⇒ 区间门槛错。
- 让第 2 个操作数类型非法：抛出后作用区间必须已是 `(0,0)`、推进格数必须是 11；区间保留旧值 ⇒ 写序错。

### 场景颜色：opcode 0x32d

<!-- rule: CORE-OPS-SCENE-COLOR-32D -->

`0x32d` 有两个操作数：**透明度**（第 1 个）、**RGB**（第 2 个，`0xRRGGBB`）。

- 推进格数 = **5**；读序 **1 → 2**。
- 透明度**大于 255 先夹到 255**；负透明度**不在本条夹**：打包时进高字节的是它的低 8 位（`-1` ⇒ `0xFF`），不是 0。
- 四个通道拼成**一个 32 位整数** `A<<24 | R<<16 | G<<8 | B`，作为一次「设场景颜色」请求的**唯一参数**交给渲染模块。
  引擎内部会把它拆成四个归一化浮点（R / G / B / A，各 = 字节 ÷ 255）再量化回字节，但这是**内部换算**，不是边界请求的形态。
- 请求**每次执行都发**（不是只在颜色变化时发）。
- 本条自己**不写场景记录、不写场景命令表、不标脏**；返回值不看、除操作数读取外不抛。
  请求落地时还会把打包色写进场景对象的一份状态格，并把它之后的像素后果留给消费方（见残差）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 场景颜色 | 一次「设颜色」请求：**一个 ARGB 整数**（`A<<24 | R<<16 | G<<8 | B`） |
| 透明度 | 大于 255 先夹到 255；负值不夹，打包时取低 8 位进高字节 |
| 场景记录 / 场景命令表 / 脏标记 | 都不变 |
| 场景对象里的一份打包色状态 | ← 请求的 ARGB（谁读、是否持久见残差） |

**成立条件**

- 夹取**只对透明度、且只有上界**：大于 255 夹到 255；负值不夹，打包时取它的低 8 位（`-1` ⇒ `0xFF`），不是 0；RGB 的三个字节原样取（`0xRRGGBB` 的高位忽略）。
- ⛔ **边界请求的参数是一个 32 位整数**，不是四个浮点。四浮点（R / G / B / A 各 ÷255）只是引擎内部的换算与量化路径；把"四浮点"写成请求参数形态 ⇒ 错。
- ⛔ 不要把它当成"场景混合"（那是另一条 `0x33f`：模式 + 透明度 + 颜色，逐像素乘进最终合成）。
  这条是**渲染模块的请求**，不写场景记录、不写命令表。
- 请求**每次执行都发**；去重需要额外状态，本条没有。

**残差**

- `RES-SCENE-COLOR-32D-CONSUMER`（unknown）：这次「设颜色」请求在渲染模块里怎么被使用（清屏色？全局乘？）、场景对象里那份打包色由谁读、是否持久，都未取证；本版只规定请求的参数与次数，不规定它之后的像素后果。

**可证伪**

- `0x32d 300 0xFFFFFF`：请求的 ARGB 必须是 **`0xFFFFFFFF`**（透明度夹到 255）；若是 `0x2CFFFFFF`（300 截成 44）⇒ 夹取错。
- `0x32d 128 0x123456`：请求的 ARGB 必须是 **`0x80123456`**；若边界上观测到**四个浮点**（而不是一个整数）⇒ 请求形态错。
- `0x32d -1 0x123456`：请求的 ARGB 必须是 **`0xFF123456`**（负值不夹、取低 8 位）；若是 `0x00123456`（把负值夹成 0）⇒ 夹取口径错。
  若在这四个内部浮点上看到次序不是 R / G / B / A ⇒ 内部换算次序错（但这不是边界参数）。
- 执行两次同一个颜色：请求必须发两次；只发一次 ⇒ 做了去重（本条没有去重）。
- 执行后场景的脏标记必须不变（之前为 0 则仍为 0）；变脏 ⇒ 多了标脏。

### 销毁网格槽表里的一个对象：opcode 0x32a

<!-- rule: CORE-OPS-SCENE-EFFECT-DESTROY-32A -->

`0x32a` 有一个操作数 = **槽号**，推进格数 = **3**。

- 按槽号取**网格槽表**（与 `0x32b` 全清的是**同一张表**）里的一格：存在 ⇒ 销毁它（对象释放、槽置空）；槽本来就空 ⇒ **什么都不做**。
- 槽号**不做范围检查**：本版只规定槽 `0..2`；表的容量是 **1000**（见残差），`3..999` 是表内未规定、⛔ 不按越界处理；`0..999` 之外才是未定义行为。
- 不写操作数、不报错、不标脏、不发渲染请求。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某网格槽有没有对象 | 存在 ⇒ 槽 ← 空；不存在 ⇒ 不变 |

**成立条件**

- "销毁"是**释放 + 置空**，不是"隐藏"：之后再按该槽取对象得到空。
- 重复销毁同一个槽是**幂等**的（第二次什么都不做），⛔ 不是错误。
- 这张网格槽表里对象的**创建者**是 `0x329`（按文件建对象）；对象类型与创建侧细节本版不规定（见残差）。

**残差**

- `RES-SCENE-EFFECT-OBJECT`（unknown）：这张网格槽表的**对象类型**未定；`0x329` 的建对象语义由 gap 的 `RES-GAP-329-MESH-OBJECT` 跟踪。本条只规定销毁的可见后果。⛔「三个槽的效果对象（雨 / 雪 / 雾）」是**没有绑定观察的旧说**，不许拿来实现。

**可证伪**

- 槽 0 有对象时执行：执行后必须取不到对象；还取得到 ⇒ "置空"漏了。
- 槽 0 空着时执行：不得报错、不得崩、不得改别的槽。

### 场景对象：按编号查一个整数值（opcode 0x215）

<!-- rule: CORE-OPS-SCENE-KEYED-215 -->

`0x215` 有两个操作数：**落点**（第 1）、**键**（第 2）。推进格数 = **5**；读序 **2 → 1**。

- 按**键**在**场景对象记录表**里查（与 `0x217` / `0x219` / `0x220` 的“查或建”是同一张表；记录由 `0x1fb` 建并写整数标签）。
  命中且该记录标志字的**第 0 位**为 1 ⇒ 落点 ← 记录的**整数值**；记录不存在、或第 0 位为 0 ⇒ 落点 ← **-1**。
- 不写第 2 个操作数、不建记录、不报错、不标脏、不置「有动画」。
- 写的是**整数**（不是指针）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某编号的记录值 | 落点 ← 值（命中且位 0 = 1） |
| 未命中 | 落点 ← -1 |

**成立条件**

- `-1` 是**两种未命中**的共同结果（记录不存在 / 位 0 = 0）⇒ ⛔ 不能用 -1 区分这两支。
- 查询**不建记录**（与 `0x217` / `0x219` / `0x220` 的"查不到先建"相反）。
- `0x218` 读**同一张表**但不查位 0（它只看记录在不在）；两条的有效性判据不同，⛔ 不许合并。
- 键不做范围检查。

**可证伪**

- 让表里有一条"位 0 = 1、值 = 7"的记录，查它：落点必须是 7；得 -1 ⇒ 位判反了。
- 同一条把位 0 清掉：必须得 -1；仍得 7 ⇒ 漏了门。
- 查一个不存在的键：必须得 -1，且表里**不许多出记录**。

### 清空一个按 key 的容器：opcode 0x224

<!-- rule: CORE-OPS-SCENE-CONTAINER-CLEAR-224 -->

`0x224` 无操作数，推进格数 = **1**：把**场景命令表**（一张按 key 的容器）清空（所有条目消失、计数归 0；**不**对条目值调用析构 —— 命令记录引用的纹理 / 影片对象由各自的表持有）。

- 不写操作数、不报错、不发请求、不标脏、不置「有动画」。
- 容器**为空**时同样是一趟空遍历（结果不变）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 场景命令表 | 所有条目销毁、计数 ← 0 |

**成立条件**

- 这是**销毁**不是"隐藏"：清空后容器里没有条目（不是"标记为无效"）。
- 这个容器**就是场景命令表**（`0x223` / `0x24d` / `0x24f` / `0x250` / `0x251` 五条命令记录指令写的第五张表）；`0x224` 是**唯一由脚本发起**的「整表清空命令记录」动作。它不释放命令记录引用的纹理 / 影片对象（清空只遍历结点 + 释放结点）。
- ⛔ 不许实现成"只把计数清 0 而不销毁条目"。

**可证伪**

- 容器里有 3 条时执行：执行后计数必须是 0、且逐条取都取不到。
- 空容器执行：不得报错、不得崩。

### 给一段键区间内的场景记录设平移矩阵与标志：opcode 0x256

<!-- rule: CORE-OPS-SCENE-RANGE-TRANSLATE-256 -->

`0x256` 有五个操作数：**键区间起点**、**个数**、**三个浮点**（x / y / z）。推进格数 = **11**；读序 **5 → 4 → 3 → 2 → 1**。

- 区间 = `[起点, 起点 + 个数)`。
- 对**表里已存在**的、键落在这个区间内的每一条场景记录：把该记录的 **G3 配置格 ← 1**，把它的**平移矩阵**按与 `0x1ff` 完全相同的方式重写（= 单位矩阵 + 平移分量 ← 第 3、4、5 个操作数），随后把场景**标脏**。
- 只改**已存在**的记录：本条**不建记录**，也不改表的大小。
- 个数 **= 0** ⇒ 区间为空 ⇒ **一条记录都不处理，也不标脏**（遍历在进入逐记录循环之前就结束）。
- 标脏**跟着"记录被遍历到"发生**：区间里一条已存在的记录都没有 ⇒ 本条**不**标脏。
- 推进格数 **11** 写在任何读数之前。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 区间内每条记录的平移 | 该记录的**平移矩阵** ← 单位矩阵 + 平移分量 (第 3、4、5 个操作数) |
| 区间内每条记录需要重算 | 该记录的 **G3 配置格** ← 1 |
| 场景需要重绘 | 脏标记 ← 1（**仅当至少一条记录被遍历到**） |

**成立条件**

- 门是**键在区间内**且**记录已存在**：⛔ 不是"按个数创建记录"。
- 标脏**只随记录发生**，⛔ 不是"末尾无条件标脏"：区间终点等于起点（个数 = 0）或区间里没有任何已存在记录时，本条**不**标脏。
- 三个浮点写的就是 `0x1ff` 写的那个**平移矩阵**（⛔ 不是 `0x220` 的第四个平移矩阵、也不是第一 / 第二三元向量）；写法也与 `0x1ff` 相同（整矩阵 = 单位矩阵 + 平移分量）。
- 那个**标志**就是 `0x1fd` / `0x1ff` / `0x1fe` / `0x220` 写的 **G3 配置格**（⛔ 不是另一个"独立整数格"，也不是记录首字的某一位）。
- 个数的下界**只有 `= 0`**：负数是**未定义行为**（区间终点落在起点之前，遍历不保证终止），本版不规定，⛔ 不许把"个数 ≤ 0 ⇒ 空区间"写成合同。
- 读序是合同的一部分：第 5 个操作数类型异常时，其余四个都还没读。

**残差**

- `RES-SCENE-RANGE-256-FIELDS`（unknown）：两个落点**已定名**（记录的 G3 配置格、与 `0x1ff` 同一个平移矩阵）；它们在本条**之外**还有哪些写者 / 读者未逐一排除。下一步：枚举这两个格的其余读写点。
- `RES-SCENE-RANGE-256-CONSUMER`（unknown）：这两个落点的**消费者**（谁按它们重算 / 谁按它们画）未取证；本版只规定"写成什么"，不规定"谁怎么用"。下一步：读绘制入口对这两个格的读取点。

**可证伪**

- 表里只有键 5 与 9 的记录，跑 `0x256(5, 1, 1,2,3)`：只有键 5 的记录被改（G3 配置格 = 1、平移 = (1,2,3)）；键 9 变了 ⇒ 区间判错。
- 跑 `0x256(5, 0, 9, 9, 9)`：一条记录都不改，且场景**不**标脏；标脏 ⇒ "标脏只随记录"那一条错。
- 区间里全是不存在的键（表里没有 100..102，跑 `0x256(100, 3, 1,2,3)`）：表的大小必须不变、且场景**不**标脏；多出记录 ⇒ 建了记录；标脏 ⇒ 把"标脏"写成了无条件。
- 对同一条记录先跑 `0x256(5, 1, 1,2,3)`，再用 `0x228` 读编号 5：必须是 (1,2,3)；读到旧值 ⇒ 没写到 `0x1ff` 那个矩阵。再让 `0x220` 写同一编号的第四个平移后重读 `0x228`：必须**仍是** (1,2,3)（`0x228` 读的不是第四个平移）；被 `0x220` 的值改掉 ⇒ 两个平移矩阵被合并成一个。
- 跑完之后该记录的 G3 配置格必须是 **1**；若置的是记录首字的某一位、或另一个整数格 ⇒ 标志格归属错。

### 场景对象：两条记录的交换 / 搬运（opcode 0x214）

<!-- rule: CORE-OPS-SCENE3D-214 -->

`0x214` 有两个操作数：**编号 A**（第 1）、**编号 B**（第 2）；推进格数 = **5**，读序 **2 → 1**。

它把两个编号上的**整条场景记录**做交换 / 搬运（两个编号**对称**，没有固定的“源 / 目标”方向）：

- 两个编号**都有**记录 ⇒ **交换**两条记录的载荷（A 的旧记录到 B、B 的旧记录到 A）。
- **只有一个**编号有记录 ⇒ 把这条记录**搬到**另一个编号：原编号消失，另一个编号得到整条记录。
- 两个编号**都没有**记录 ⇒ 不建记录，什么都不改。
- 三条出口都**标脏**；不写操作数、不报错、不置「有动画」。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 两个编号的记录互换 / 搬运 | 表里 A / B 两条记录的载荷按上面三种情形交换或搬移 |
| 场景需要重绘 | 脏标记 ← 1 |

**成立条件**

- 搬的是**整条记录**（记录里的绘制相关字段一起搬），⛔ 不是只搬某一半字段。
- 交换是**双向**的：只把 A 写成 B、B 保持原值 ⇒ 错。
- 两个编号都没有记录时**不建记录**，但仍要标脏。
- 标脏是**无条件**的（三条出口都标）；⛔ 不是“只在真的改了记录时才标”。
- 读序是合同：两个操作数都非法时，先读第 2 个。

**可证伪**

- A / B 都有记录且载荷不同：执行后 A 的载荷 = 原 B、B 的载荷 = 原 A；只变一边 ⇒ 少写一半。
- 只有 B 有记录：执行后 A 得到 B 的整条记录、B 消失；B 还在 ⇒ 没搬。
- 只有 A 有记录：执行后 B 得到 A 的整条记录、A 消失。
- 两个都没有：表大小不变，但脏标记必须置 1；没置 ⇒ 漏了无条件标脏。

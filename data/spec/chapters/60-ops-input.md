## 输入：键鼠 / 手柄 / 回调

本章规则数以 `pnpm tools spec chapters` 现查。

本章只规定**引擎侧的输入状态与脚本可见效果**。平台如何采样键盘、鼠标与手柄属于边界；本章不规定物理键与输入位号的映射，也不规定窗口消息的形态。

引擎把平台输入归约成一个 **32 位输入字**：位号 `0` 到 `31`，某位为 1 表示该编号的输入处于激活（按下）状态。脚本通过两条通路消费它（**只有脚本执行到本章的派发指令时才会派发**；等待期间门关，引擎不会自己泵）：

* **主动查询**：读光标位置、读按钮位图、取一条鼠标事件；
* **登记回调**：把「某个输入编号 / 定时器」绑定到当前脚本里的一个位置；当脚本执行到 `0xcd` / `0x100` 且条件满足时，引擎**把控制流当作一次脚本调用**交给那段脚本，回调返回后继续原来的指令流。

回调是**同一帧、同一局部池**里的脚本调用：回调对局部池的写，主循环随后可见。回调不是新的脚本、也不是新的帧。派发只发生在脚本执行到 `0xcd` / `0x100` 时；等待位 / 影片位挡住派发时，回调不会被泵。

### 输入字与键总数（opcode 0xfe / 0xff）

<!-- rule: CORE-INPUT-WORD -->

`0xfe` 有一个操作数：把它读成**键总数**，写进引擎的键总数格。

- 键总数接受 `0` 到 `31`（**无符号比较**：`32` 及以上都拒绝；`-1` 按无符号看是最大值，同样拒绝）⇒ 不满足时抛**显示消息型异常**，键总数与输入字都不变。
- 除键总数外，这条不改变任何引擎状态；推进格数 = 3。

`0xff` 没有操作数，按固定顺序做四件事：

1. 把**输入字**清成 0；
2. 向平台**请求一次输入采样**：平台把当前键 / 手柄状态按输入位号写进输入字（采样本身是外部请求，见残差）；
3. 把当前帧的**按键扫描游标**写成 0；
4. 把当前帧的**按键扫描上限**写成引擎的键总数。

- 推进格数 = 1。
- 这条不读操作数、不写脚本变量、不置门位、**不切换当前帧（帧号不变）**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前键总数 | 引擎的一个整数格（**初值本版不规定**，见残差） |
| 一次采样的结果 | 输入字（32 位） |
| 下一次按键派发从哪里开始 | 当前帧的扫描游标 |
| 扫描到哪里为止 | 当前帧的扫描上限 ← 键总数 |
| 采样 | 向平台发出一次请求 |

**成立条件**

- `0xfe` 的键总数**不是**输入字的宽度，也不是「已登记回调的个数」：它决定 `0x100` 的扫描范围与「没有按键时」使用哪一个表项（这一角色由 `0x100` 的读点支撑；其余读者见残差）。
- `0xff` 的次序固定：**先清、再采样、再重置游标与上限**。平台采样失败 / 没有设备时输入字保持 0。
- 输入字的写入路径已观察到 `0xff`（清后重采）、`0x101`（采样后清零）与平台采样；是否还有别的写点见残差。

### 采样输入并丢弃（opcode 0x101）

<!-- rule: CORE-OPS-WAIT-POLL-INPUT -->

`0x101` 没有操作数。已观察到的形态是：按固定顺序做四件事：

1. 采样一次输入到引擎的输入字（**外部请求**；采样本身不在本版范围）；
2. 清状态选择字的**第 27 位**（读-改-写：只清这一位，其它位保持原值）；
3. 把输入字写成 0（**丢弃**这次采样）；
4. 两个引擎级标量：**A ← 1**、**B ← 0**（A、B 是两条不同的格；它们的领域身份未取证，本版不规定）。

★ 第 27 位是**跨条目的一位**：`0x88` 在值为 0 时清它，`0x71` 在某个条件下置它，`0xcd` 在它置起时越过时间闸。⚠ 它与等待位（第 10 位）不是同一位；把它实现成"清等待位"会让 `0x101` 变成一次放行，而引擎这里只是清这一位。

★ **门模型下的可达性**：本规范的门是"整字为 0 才派发"；若第 27 位正是挡住派发的那一位，`0x101` 根本不会被派发 ⇒ 上面的清位是**防御性分支**。它何时可观察取决于门如何服务第 27 位（本版不规定，见残差）。本条仍把清位写成合同，是为了让"派发到它时"的引擎数据效果唯一。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 输入已被丢弃 | 输入字 = 0 |
| 第 27 位被清 | 状态选择字第 27 位 = 0（其它位不变） |
| 两个标量 | A ← 1、B ← 0 |

**成立条件**

- 顺序固定：采样 → 清第 27 位 → 清输入字 → 写两个标量（后三步不许调换）。
- 采样结果除"写进输入字再清零"外没有其它消费。
- A 与 B 的**领域身份**未取证：本版只规定"两条不同的格、一条写 1、一条写 0"，不规定它们各自被谁读。
- ⛔ 不许把第 27 位与等待位、影片位或睡眠位合并成一个"通用标志"。

### 输入回调的登记（opcode 0xcc / 0xfb）

<!-- rule: CORE-INPUT-CALLBACK-REGISTER -->

**按键回调（`0xfb`）** 有两个操作数：**键编号**、**脚本位置**。

- 键编号接受 `0` 到 `31`（**无符号比较**：`32` 及以上、`-1` 都拒绝）⇒ 抛**显示消息型异常**，不登记、不改任何引擎状态。
- 登记是**按当前帧**的：每个帧有一张「键编号 → 脚本位置」的表，初值全部是「未登记」。「没有按键」时使用**编号等于键总数**的表项；该表项是否已登记由脚本自己决定。
- 同一编号重复登记 ⇒ 后一次覆盖前一次。
- 推进格数 = 5；不改门位、不改输入字、**不切换当前帧（帧号不变）**。

**鼠标回调（`0xcc`）** 有两个操作数：**轮询间隔**、**脚本位置**。

- 间隔按毫秒读；`0` 会被写成 1。
- 登记时记下三样东西：脚本位置、**当前帧的调用深度**、**当前时刻**（作为「上次派发时刻」的初值）。
- 脚本位置为 `-1` 表示**取消登记**：下一次派发时什么都不做（但仍会消耗一次定时）。
- 推进格数 = 5；不改门位、不改输入字、**不切换当前帧（帧号不变）**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个按键编号绑定到哪段脚本 | 当前帧的按键回调表（键编号 0..31；「无按键」使用编号等于键总数的表项） |
| 鼠标回调绑定到哪段脚本 | 引擎的一格脚本位置 |
| 鼠标回调的轮询间隔 | 引擎的一格毫秒数（0 写成 1） |
| 鼠标回调的注册深度 | 登记时的当前帧调用深度 |
| 鼠标回调的上次派发时刻 | 引擎的一格时刻（登记时 = 当前时刻） |

**成立条件**

- 两张表不是同一张：按键回调按帧存，鼠标回调存引擎级一格。
- 「当前帧的调用层数」在本条只要求**登记与派发取同一个量**；它具体怎么算（根帧、`0x3` 子脚本、`0x8` 换帧）见残差。
- `0xfb` 的越界路径在写表**之前**返回；`0xcc` 没有范围检查（`-1` 是取消哨兵）。
- 登记本身不派发；派发只发生在 `0xcd` / `0x100`。

### 定时派发鼠标回调（opcode 0xcd）

<!-- rule: CORE-INPUT-MOUSE-CALLBACK-PUMP -->

`0xcd` 没有操作数。它按**时间闸**决定这次是否把控制流交给已登记的鼠标回调。

1. 推进格数先写成 1（缺省只前进一条指令）—— 本条是 `0xcd` 的处理体，自己写推进格数。
2. 读一次当前时刻。若「当前时刻 − 上次派发时刻」**小于**登记间隔，**并且**状态选择字的第 27 位不为 1 ⇒ 直接返回（只前进一条）。★ 在「执行与时间」的门模型下，第 27 位若正好是挡住派发的那一位，本条根本不会被派发 ⇒ 这一支只在门允许派发时有意义；「谁服务第 27 位、什么时候允许派发」见残差。
3. 否则把「上次派发时刻」更新为当前时刻，并**压入返回位置**：当前位置（dword 下标）的下一条（同一帧）。
4. 若登记的脚本位置是 `-1` ⇒ 撤销刚压入的返回位置，返回（只前进一条）。
5. 否则校验：**当前帧调用深度**必须等于**登记时的深度**；不等 ⇒ 抛**显示消息型异常**。
6. 校验通过 ⇒ 把当前帧的指令指针改到登记的脚本位置，推进格数写成 0（不再自动前进）。

- 这条**不读任何输入状态**、**不写任何脚本变量**；它只做时间判断与控制转移，**不切换当前帧（帧号不变）**。
- 它把控制流交给回调的方式与「同脚本调用」相同：压返回位置、跳到目标位置、由回调的返回指令回到下一条。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 距上次派发过了多久 | 当前时刻 − 上次派发时刻 |
| 这次是否派发 | 时间闸或第 27 位 |
| 回调返回后从哪里继续 | 当前帧的返回栈顶 ← 当前位置（dword 下标）+ 1 |
| 回调在哪个深度执行 | 当前帧调用深度（必须等于登记深度） |

**成立条件**

- 时间闸的判据是 **`elapsed >= interval`**（含等号），不是 `>`。
- 第 27 位与等待位（第 10 位）不是同一位；本版只规定「它置起时越过时间闸」这一观察，不规定它的领域含义（见残差）。
- 深度校验发生在**目标不是 −1** 时；失败是脚本层可见的显示消息型异常，不是静默跳过。
- 回调的返回位置是**下一条**指令；`0x100` 的按键派发不同（见下一条）。

### 派发按键回调（opcode 0x100）

<!-- rule: CORE-INPUT-KEY-DISPATCH -->

`0x100` 没有操作数。它按当前输入字与当前帧的扫描游标派发**一个**按键回调。

设 `limit` = 当前帧的扫描上限（由 `0xff` 写成键总数），`cursor` = 当前帧的扫描游标。

- **输入字为 0**：考虑**编号等于 `limit` 的表项**（「无按键」表项）。
  - 该表项未登记 ⇒ 只前进一条（推进格数 1）。
  - 该表项已登记 ⇒ 压入返回位置（**当前位置（dword 下标）+ 1**），把指令指针改到表项位置，推进格数 0。
- **输入字非 0**：从 `cursor` 起，在 `[cursor, limit)` 里找**第一个置位**的编号。
  - 找不到 ⇒ 只前进一条（推进格数 1）。
  - 找到 ⇒ 把扫描游标写成「找到的编号 + 1」；然后：
    - 该编号的表项已登记 ⇒ 压入返回位置（**当前位置（dword 下标）本身**，不是下一条），把指令指针改到表项位置，推进格数 0。
      ⇒ 回调返回后会**重新执行这条指令**，因为游标已经前进，于是派发下一个置位编号；如此逐个派发完全部置位。这是**有意的重派发**，终止靠游标前进。
    - 该编号的表项未登记 ⇒ 只前进一条（推进格数 1），并**放弃本轮剩余的置位**。

- 这条不写脚本变量、不置门位、**不切换当前帧（帧号不变）**；调用层数也不变。
- 扫描范围是**左闭右开**：包含 `cursor`，不包含 `limit`。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 这次派发哪一个按键 | 输入字里第一个置位编号 |
| 下一次从哪里继续 | 当前帧扫描游标 ← 找到的编号 + 1 |
| 无按键时派发哪一段 | 编号等于扫描上限的表项 |
| 回调返回后从哪里继续 | 输入字为 0 的表项 ⇒ 下一条；按键表项 ⇒ 当前位置（重新派发） |

**成立条件**

- **输入字为 0** 与**输入字非 0** 的返回位置**不同**：前者是「下一条」，后者是「当前位置」。这不是笔误：后者是逐个派发的迭代器。
- 未登记的表项会让本轮扫描提前结束（不是跳过它继续找下一个）。
- 回调是同一帧里的脚本调用；它写的局部池对主循环可见。
- 这条只派发**一个**回调；要派发全部，需要脚本反复执行它（引擎不在这里循环）。

### 取一条鼠标事件（opcode 0x2fc）

<!-- rule: CORE-INPUT-MOUSE-EVENT -->

`0x2fc` 有五个操作数：**结果**、**横坐标**、**纵坐标**、**事件标志**、**事件附加量**。

- 向平台**请求一条待处理鼠标事件**；请求本身是外部行为。
- **没有事件**：第 1 个操作数写 0；第 2 到第 5 个操作数**保持原值**（不写）。
- **有事件**：第 1 个操作数写 1；第 2 / 3 个写事件的客户区横 / 纵坐标；第 4 个写事件标志；第 5 个写事件的附加量。事件被消费（下一次请求拿到的是下一条）。
- 推进格数 = 11；不改门位、**不切换当前帧（帧号不变）**、不写其它脚本变量。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 队列里有没有鼠标事件 | 第 1 个操作数（1 / 0） |
| 事件位置 | 第 2 / 3 个操作数 |
| 事件标志与附加量 | 第 4 / 5 个操作数 |

**成立条件**

- **没有事件时不写坐标**：把坐标清 0 会把「没有事件」与「事件在原点」混为一谈。
- 坐标是**客户区**坐标；从屏幕坐标到客户区的映射属于平台边界，本章不规定。
- 事件标志与附加量的位段本版**不规定**（见残差）；实现只要求原样传递。

### 读光标位置（opcode 0x109）

<!-- rule: CORE-INPUT-MOUSE-POS -->

`0x109` 有两个操作数：**横坐标**、**纵坐标**。

- 向平台查询当前光标位置。
- **设备可用**：两个操作数分别写光标位置（经显示模式映射后的值；映射细节属机器/平台细节，本章不规定）。
- **设备不可用**（没有窗口 / 光标不在客户区）：两个操作数**都写 −100000**。
- 推进格数 = 5；不改门位、**不切换当前帧（帧号不变）**、不写其它脚本变量。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 光标在客户区的位置 | 第 1 / 2 个操作数 |
| 光标不可用 | 两个操作数 ← −100000 |

**成立条件**

- 「不可用」不是「不写」：两个操作数都会被写成哨兵 −100000。
- 第 1 个操作数是横坐标、第 2 个是纵坐标；读操作数本身的次序是 2 → 1（先取地址再按类型写），但对外语义是「写两个目标」。
- 显示模式变换（窗口 / 虚拟全屏）属引擎对平台坐标的再映射；本版不规定公式（见残差）。

### 读鼠标按钮位图（opcode 0x108）

<!-- rule: CORE-INPUT-MOUSE-BUTTON -->

`0x108` 有一个操作数：**按钮位图**。

- 向平台查询当前按下的鼠标按钮，写成位图。
- 位图至少包含左 / 右两个按钮各一位；**哪一位对应物理左 / 右键取决于平台的左右键交换设置**，属平台边界（本版不规定交换后的位号）。
- 设备不可用 ⇒ 写 0（不是保持旧值）。
- 推进格数 = 3；不改门位、**不切换当前帧（帧号不变）**、不写其它脚本变量。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前按下的鼠标按钮 | 第 1 个操作数（位 0 左 / 位 1 右） |
| 设备不可用 | 第 1 个操作数 ← 0 |

**成立条件**

- 除了左右键对应的两位，其它位本版不规定。
- 这条**不**返回「这一帧新按下的键」，只返回当前状态位图；边沿判定由脚本自己做（脚本保存上一次的位图）。

### 主循环模式字（opcode 0x24e）

<!-- rule: CORE-INPUT-MODE-WORD -->

`0x24e` 有一个操作数：把它原样写进引擎的**主循环模式字**。

- 推进格数 = 3；不改门位、**不切换当前帧（帧号不变）**、不写其它脚本变量。
- 模式字的**位 0** 被等待服务读取；它是否/如何影响「点击跳过」以及服务策略本版**不规定**（见残差）。
- 模式字的其它位本版不规定。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 模式字第 0 位 | 被等待服务读取（服务策略本版不规定） |
| 模式字其余位 | 本版不规定 |

**成立条件**

- 这条只写模式字，不采样输入、不消费输入事件、不清等待位。
- 位 0 的语义与等待服务的完整放行路径未取证；本版只登记「写入」与「等待服务会读它」两个观察。

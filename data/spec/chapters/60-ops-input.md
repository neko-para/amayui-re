## 输入：键鼠 / 手柄 / 回调 / 命中查找

本章的规则逐条点名它覆盖的 opcode（见各小节标题）；未列出的 opcode 本版不作断言。

本章只规定**引擎侧的输入状态与脚本可见效果**。平台如何采样键盘、鼠标与手柄的**原始状态**属于边界；本章不规定窗口消息的形态。**物理键 / 手柄按钮编号 → 输入位号**的对应由引擎的**映射表**决定（见「输入字与键总数」）：初值由引擎初始化写入，运行期只能由脚本的标量表指令（`0x107` / `0x10b` / `0xfd` / `0x10c`）改写；**配置不写这些表**（配置只决定手柄那一组参不参与采样，见「引擎级状态」的标量表）。

引擎有一个**输入可用标志**：启动时置 1；为 0 表示没有可用输入源。它为 0 时，查询类指令（`0x108` / `0x109` / `0x2fc`）按各自的“不可用”口径写结果（`0x108`/`0x109` 不发平台查询；`0x2fc` 返回“没有触点”）。

标志的**写入面是完整的**（不是"只在启动时置 1"）：引擎初始化与输入对象构造两处把它置 **1**；把它清 **0** 的路径至少有四条 —— ① **空闲计时器到期**（一段时间内既没按鼠标左右键、也没有别的活动）；② **进入菜单循环**；③ 一条**窗口消息**（其参数决定是否清）；④ 另一条窗口消息（消息号 0x12）。清 0 之后它**不会自己回到 1**，除非再走置 1 的路径。它只开关"是否向平台查询"，**不改已经写进脚本的值**（不清输入字、不清两个事件锁存字、不改键总数、不动回调表）。

引擎把平台输入归约成一个 **32 位输入字**：位号 `0` 到 `31`，某位为 1 表示该编号的输入处于激活（按下）状态。脚本通过两条通路消费它（**只有脚本执行到本章的派发指令时才会派发**；等待期间门关，引擎不会自己泵）：

* **主动查询**：读光标位置、读按钮位图、取一个触点、按脚本给的坐标做命中查找、读滚轮增量（`0x10d`；它**不查**输入可用标志，见「读滚轮增量并清零」）；
* **登记回调**：把「某个输入编号 / 定时器」绑定到当前脚本里的一个位置；当脚本执行到 `0xcd` / `0x100` / `0x104` 且条件满足时，引擎**把控制流当作一次脚本调用**交给那段脚本，回调返回后继续原来的指令流。

回调是**同一帧、同一局部池**里的脚本调用：回调对局部池的写，主循环随后可见。回调不是新的脚本、也不是新的帧。派发只发生在脚本执行到 `0xcd` / `0x100` / `0x104` 时；等待位 / 影片位挡住派发时，回调不会被泵。

### 输入字与键总数（opcode 0xfe / 0xff）

<!-- rule: CORE-INPUT-WORD -->

`0xfe` 有一个操作数：把它读成**键总数**，写进引擎的键总数格。

- 键总数接受 `0` 到 `31`（**无符号比较**：`32` 及以上都拒绝；`-1` 按无符号看是最大值，同样拒绝）⇒ 不满足时抛**显示消息型异常**，键总数与输入字都不变。
- **写这一格发生在范围检查之后**（不合格就一个字节都不写）；推进格数 = 3，而且它在范围检查**之前**就已写好 ⇒ 抛异常时推进格数仍是 3。
- 除键总数外，这条不改变任何引擎状态。

`0xff` 没有操作数，按固定顺序做四件事：

1. 把**输入字**清成 0；
2. 做一次**输入采样**：引擎按固定次序查平台的键 / 按钮状态，按映射表把命中的来源写成输入字的位（见「各来源的位号合成」）；
3. 把当前帧的**按键扫描游标**写成 0；
4. 把当前帧的**按键扫描上限**写成引擎的键总数。

- 推进格数 = 1。
- 这条不读操作数、不写脚本变量、不置门位、**不切换当前帧（帧号不变）**。
- 这次采样**不并入输入锁存**（见「输入锁存」）；会并入锁存的是引擎的「事件并入」采样（`0x101` 与 `0x72` 起播支走的就是这条）与主循环的输入处理。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前键总数 | 引擎的一个整数格（**构造时建立初值 7**；`0xfe` 覆盖） |
| 一次采样的结果 | 输入字（32 位） |
| 下一次按键派发从哪里开始 | 当前帧的扫描游标 |
| 扫描到哪里为止 | 当前帧的扫描上限 ← 键总数 |
| 采样 | 向平台发出**若干次**查询（键盘逐键、鼠标左右键、手柄按钮位图） |

**成立条件**

- `0xfe` 的键总数**不是**输入字的宽度，也不是「已登记回调的个数」：它决定 `0x100` 的扫描范围与「没有按键时」使用哪一个表项（这一角色由 `0x100` 的读点支撑）。
- `0xff` 的次序固定：**先清、再采样、再重置游标与上限**。平台采样失败 / 没有设备时输入字保持 0。
- **一次采样是引擎侧的合成**，不是平台直接给出输入字：引擎按固定次序查询**四个来源** —— 键盘、鼠标左右键、第一组手柄按钮、最近一次平台手势（它的编号经一张 8 格的表换成输入位号）—— 各来源按自己的映射表把命中写成输入字的位（见「各来源的位号合成」）。⇒ **采样源、次序与位号合成是引擎的决定，不是平台边界**。
- **三个来源受「输入可用标志」门控**：键盘、鼠标、手势在标志为 0 时**整段不做**（前两者不查询平台、手势来源不并入）；手柄来源**不看**这个标志，只看组头的按钮数（见「引擎级状态」的 `0x107`）。
- 输入字的写入路径已观察到 `0xff`（清后重采）、`0x101`（采样后清零）、`0x199`（进入本地块，**无条件**清 0）、`0x72`（起播时先做一次**事件并入**（并入挂起事件 + 摇杆边沿轮询一次）、再把整字清 0；跳过位已置时整段不做）与采样本身；本条不另外枚举写者。
- **键总数的写者只有两个**：引擎构造把它写成 **7**；`0xfe` 可以覆盖它。全语料里没有第三个写点；帧装载 / 重置不写它。
- **按键扫描上限有两个写者**：`0xff` 把它写成键总数；「按住派发按键回调」在掩码命中时把它**夹到找到的键号**（⇒ 它不总是等于键总数）。
- ★ **按键扫描上限没有引擎建立的初值**：引擎构造按点写若干单格、并按段清零几片存储，但**没有任何一段覆盖它所在的那一片**；对象本身由不清零的分配得到，`0xfc` / 帧装载 / 重置也都不碰它 ⇒ 在某个帧第一次执行 `0xff` 之前，这一格是**未定义的残留值**（可能极大、也可能 ≤ 0）。⛔ 不许把它当成 0，也⛔ 不许拿键总数兜底；第一次 `0xff` 之前执行 `0x104` 的后果见残差 `RES-INPUT-104-LIMIT-INIT`。
- ⇒ 在第一次执行 `0xfe` 之前，键总数是**已定义的 7**：`0x100` 的「无按键」表项下标、`0xff` 抄下的按帧上限都是 7。⛔ 不许再把它写成"未定义行为 / 实现兜底值"。
- 本条**不规定**发行数据是否都在使用按键扫描之前先执行"设置键总数"；那是游戏数据；不执行时初值 7 仍然有效。

**各来源的位号合成**

四个来源各有自己的映射表；⛔ 几张表的"格里的值"含义不同，不能互相套用：

| 来源 | 读哪一格 | 格里的值是什么 | 最终输入位号 |
|---|---|---|---|
| 键盘 | 系统键码 `0..255` → 表项 | **输入位号**（`−1` = 该键码未映射） | **格里的值**（不加 4） |
| 鼠标左右键 | 键槽映射的槽 0 / 槽 1（左右键交换设置决定哪个键用哪一槽） | **基位号** | **格里的值 + 4** |
| 第一组手柄 | 手柄按钮映射的槽 `j`（`0 ≤ j < 键总数`） | **手柄按钮编号** | **槽序号 `j` + 4**（格里的值不参与） |
| 最近一次手势 | 手势表的一格（由引擎记录的手势编号选出） | **输入位号**（`−1` = 不并入） | **格里的值**（不加 4） |

- 手柄组头的**按钮数**与键槽组头的**槽数**由输入系统初始化写成，**不是脚本指令写的**；两者的边界行为见「引擎级状态」的两条标量表。
- **键盘来源的键码表**是一张 **256 项**的表（下标 = 系统键码，格值 = 输入位号或 `−1`）：
  - **初值全 −1**；引擎构造输入对象时再写 7 项，而且这 7 项是**固定的**：

    | 系统键 | 输入位 |
    |---|---|
    | ↑ | 0 |
    | → | 1 |
    | ↓ | 2 |
    | ← | 3 |
    | Enter | 4 |
    | Space | 5 |
    | Backspace | 6 |

  - 这 7 项的系统键码不是硬编码在表里的常数，而是从另一张「逻辑键号 → 系统键码」的表取的（那张表有 **256 格**：构造时整表清 0 后写入 **93 个固定条目**，未写到的格恒为 0；**运行期没有第二个写者** —— 配置与脚本都不写它）。该表的完整条目清单、以及"查表不检查逻辑键号"的边界见「键位映射表」的「按表索引写一格」。
  - **两个脚本写者**：**按键设置（`0xfd`）**把某个槽改绑到另一个逻辑键（先解绑该槽**旧**逻辑键的键码、再登记新键），**追加按键（`0x10c`）**只登记新键、不解绑。两条的逐条合同（哪个操作数是槽号 / 逻辑键号、读序、越界抛什么）见「引擎级标量与事件」的「按表索引写一格」；这里只记它们对采样**必要**的几条后果：
  - ⇒ 键码表一格只存**一个**位号：**一个系统键只会点亮一个输入位**（后写的覆盖先写的）。两条指令的差别只在"要不要先把该槽旧逻辑键的键码解绑"。
  - ⇒ 两条都**只**检查第 1 个操作数（槽号，无符号 ≤ 31）：越界抛**显示消息型异常**、一格都不写。⛔ 不要照「引擎级状态」那两条标量表（`0x107` / `0x10b`）的"越界静默跳过"来实现它们；也⛔ 不要把"第 2 个操作数不检查"读成"它会被夹到 31"。
  - ⇒ **未执行这两条指令时，键盘映射就是上表那 7 项**（其余键码全部跳过）；⛔ 不要把它实现成"平台直接给位号"，也不要把它当成一张由配置决定的键位词表。
  - 每一次键盘采样都遍历全部 256 个键码（逐键查询一次按下状态）⇒ 一次采样对平台发出的是**若干次**查询，不是一次。

**位号只有一套**

四个来源（以及手柄的方向位）都写进**同一个 32 位输入字**的**同一套位号**；引擎不记录"这一位是谁点亮的"，脚本侧也不区分来源。

- ⇒ **多个来源可以共用同一位**：键盘的四个方向键与手柄的方向位都在 **0..3**；Enter（键盘）、鼠标左键（键槽 0）、第一组手柄的槽 0 都在 **4**；Backspace 与引擎级标志都在 **6**。这不是冲突，是引擎**有意的共用**。
- ⇒ **`0xfb` 的键编号、`0x105` 的掩码位、`0x100` / `0x104` 扫描的键号都是这套位号**，不是"某个来源的编号"：按鼠标左键会让位 4 置起 ⇒ 已登记在**键编号 4**上的回调会被 `0x100` 派发（引擎不区分"这一位来自鼠标还是 Enter"）。
- ⇒ **派发只扫到键总数为止**：`0x100` 的扫描范围是 `[扫描游标, 键总数)`、`0x104` 的上界是按键扫描上限 ⇒ 位号 **≥ 键总数** 的来源在默认键总数 **7** 下**扫不到**（例如手柄槽 3..6 点亮位 7..10）。把它们纳入派发只能靠脚本把键总数设大（`0xfe`）；引擎自己不按来源扩范围。
- **位号 ≥ 32 的落点**：写输入字的那一步是"1 左移位号"，目标机的移位只取位号的**低 5 位** ⇒ 位 **32 / 33 / 34** 实际落在 **0 / 1 / 2**（`0xfe` 把键总数限在 0..31 ⇒ 槽序号最大 **30** ⇒ 实际可达的越界位号只有 32 / 33 / 34，**35 不可达**）。这是引擎的**实际行为**，不是"被丢弃"：⛔ 不许实现成"超出 32 位就丢弃"，那样按手柄槽 28 会什么都不点亮。★ 鼠标与槽锁存并入的位号（基位号 + 4）同理：基位号 28..31 ⇒ 位号 32..35 ⇒ 落位 0..3。

**手柄的方向位（帽子 / 摇杆）落在 0..3**，与键盘的方向键**共用**这四位（⛔ 不要给它另算"槽序号 + 4"）：

- 平台给出的帽子角度按**百分之一度**记（0 = 正上）；引擎对同一个角度做**四个半平面判据**，四个判据**各自独立**：
  - 位 **0**（上）：角度 ≤ **8999** 或 ≥ **27001**；
  - 位 **1**（右）：**1** ≤ 角度 ≤ **17999**；
  - 位 **2**（下）：**9001** ≤ 角度 ≤ **26999**；
  - 位 **3**（左）：角度 ≥ **18001**。
  - 四个正方向恰只点亮一位（0° ⇒ 位 0；90° ⇒ 位 1；180° ⇒ 位 2；270° ⇒ 位 3）；**斜方向同时点亮两位**（45° ⇒ 位 0 + 位 1）。⛔ 不许实现成"取 8 个方向之一"：那会把斜方向只点亮一位。
- **帽子居中 / 设备不报"帽子可四向"**（设备能力字里那一位为 0 ⇒ 引擎一律按居中处理）时，这四位改由**摇杆轴**给出：
  - **轴序与符号**：第 1 轴是**横轴**、第 2 轴是**纵轴**；轴 1 **小于**低阈值 ⇒ **左**（位 3）、**大于**高阈值 ⇒ **右**（位 1）；轴 2 **小于**低阈值 ⇒ **上**（位 0）、**大于**高阈值 ⇒ **下**（位 2）。⇒ 小值端是"左 / 上"、大值端是"右 / 下"。
  - **比较是严格的**（轴值**等于**阈值不算命中）且按**无符号**比较。
  - **四条阈值的算式**：在引擎初始化时由「设备能力给出的轴范围」与「初始化时采到的那一个轴位置」算出 —— 低阈值 =（最小值 + 轴位置）÷ 2、高阈值 =（最大值 + 轴位置）÷ 2，除法**向零截断**。**轴位置只在初始化时采一次，运行期不重估** ⇒ 阈值此后固定：设备范围的后续变化**不会**重算阈值。
  - **采样缓存**：平台的手柄查询有 **20 毫秒**的缓存 —— 距上次查询**不超过 20 毫秒**（含边界）时这次采样复用上次那批原始轴值，不重新查询。
  - 引擎另有一格「忽略摇杆」门（构造时清 0；可获得的证据里**没有**置它的写点）：它置起时**不**用摇杆轴给方向位，但**不影响**帽子（帽子置起时方向位照旧由帽子判据给）。
- 电平采样（`0xff`）与"事件并入"（`0x101`）都写这四位；差别只在后者按上一拍状态只取**按下沿**（见「输入锁存」）。

**输入锁存**

除"当前按下状态"外，引擎还保存两个**事件锁存字**，把"按下过一次"的事件留到下一次并入：

| 锁存字 | 位的含义 | 谁写 |
|---|---|---|
| **位号锁存字** | 输入位号 | 引擎自己的窗口过程：收到一个系统键码的**按下**消息（按住产生的重复消息不算）⇒ 若该键码在键码表里有映射，把对应的输入位写进锁存字 |
| **槽锁存字** | 键槽序号 | 引擎自己的窗口过程：收到鼠标左右键消息 ⇒ 按配置 `set:ClickOnUp` 选一条（为 0 用**按下**消息、非 0 用**抬起**消息），把槽 0 / 1 写进锁存字 |

- **一次性吞并标记**：标记非 0 时，**这一条**鼠标键消息被丢掉（锁存字不写）并把标记清 0；标记为 0 时消息照常写入。引擎在一次采样之后**检查鼠标左右键**时，只要发现左键或右键正按下，就把这个标记写成 1。
- **并入规则**（只发生在引擎的「事件并入」采样（`0x101` 与 `0x72` 起播支走的就是这条）与主循环的输入处理上，**不发生在** `0xff` 的采样里）：
  1. 把**位号锁存字**整字 OR 进输入字，然后把锁存字清 0（只有走"事件并入"路径的采样做这一步）；
  2. 按组头的**槽数**（初始化为 2）逐槽 `j`：若**槽锁存字**的第 `j` 位置起，就把输入字的第 **（槽 `j` 的格值 + 4）** 位置起，并把该位清掉；槽数以外的位**原样保留**。
- 并入**不看**输入可用标志（只有电平来源才受它门控）。
- ⛔ 这两个锁存字不是输入字：输入字只在采样 / 指令的写入点变；锁存字只在"并入"时被消费。
- 那条「事件并入」路径还并进**三样**不属于上面两个锁存字的东西（★ 这三样 + 上面两个锁存字 = 「采样输入并丢弃」(`0x101`) 那句"并入"的**全集**，两处清单必须一致）：
  1. **手柄的按下沿**：对第一组手柄再采一次样（覆盖方向 / 帽子 / 按钮），把这一拍与**每设备一格的上一次结果**逐位比较，只在"上一拍没按、这一拍按下"时把位 OR 进输入字 —— **方向 / 帽子用位 0..3、按钮用位（槽序号 + 4）**（与电平采样同一组表、同一套位号）；"这一拍没按"时把那一格的状态位清掉 ⇒ **同一次按住只并入一次**（按住不放不会反复点亮）。它是**状态字**，不是"并入后整字清 0"的锁存字：⛔ 不要给它也配一条"并入即清"的整字。
  2. 一个**手势锁存**（整字 OR 后清 0）；
  3. 一个**引擎级标志**（非 0 ⇒ 输入字第 6 位置起，身份见「引擎级标量与事件」的「引擎级模式位」）。

**手势来源的合成规则**（把"最近一次手势"换成输入位的那一层）：

- 引擎只认**五种**手势编号（**3..7**）；编号 0..2（无 / 起始 / 结束）与 3..7 之外的值**一律不并入**。
- 每个编号经一张 **8 格表**（下标 = 手势编号，编号 3..7 落在表内）换成一个输入位号：格值 `< 0` ⇒ 该手势**不并入**；格值 `≥ 0` ⇒ 把 `1 << 格值` **或进手势锁存字**。
- 手势锁存字在「事件并入」采样里**整字或进输入字后清 0**（它是一次性事件，不是状态字）。
- 那张 8 格表在引擎构造时**整表写成"不并入"**，**没有第二个写者** ⇒ **发行初值下，手势来源永远不点亮任何输入位**。这是一个**可观察的结论**，不是"未实现"：⛔ 不许实现成"用手势编号当输入位号"，也⛔ 不许替这张表发明一个写者。
- 另有一条**独立**的手势信息查询通路：读出「一个索引、一个类型、两个 16 位有符号坐标」，把坐标转成客户区坐标；它与上面的位合成**互不影响**（不读也不写手势锁存字）。
- 锁存的写入发生在引擎自己的窗口过程处理触摸消息时；消费只发生在「事件并入」采样（电平采样不并入手势锁存）。输入可用标志为 0 时两处都不并入。

**可证伪**

- 只登记「无按键」表项 **7**（不登记 0），输入字 0，不执行 `0xfe`，执行 `0x100` ⇒ 必须派发到表项 7；派发 0 或完全不派发 ⇒ 初值不是 7。
- 未执行 `0xfe` 时执行 `0xff`，再按住键 6 执行 `0x104`（键总数 7 时 6 在范围内，0 时不在）⇒ 必须命中；不命中 ⇒ 按帧上限不是 7。
- `0xfe 32` / `0xfe -1` ⇒ 抛异常且键总数保持原值（初值 7 或上一次的值）；抛异常之后推进格数仍是 3。
- 不执行 `0xfd` / `0x10c`：按住 ↑ 采样 ⇒ 输入字命中第 **0** 位；按 Enter ⇒ 第 **4** 位。若 ↑ 落第 4 位 ⇒ 把"位号不加 4"写成了"加 4"。
- `0xfd` 把槽 0 改绑到逻辑键 28（默认就是 Enter）之后：按 Enter ⇒ **只有**第 **0** 位（键码表一格只存一个位号，后写的覆盖 Enter 原来的第 4 位）；按 ↑ ⇒ 输入字里**不再**有第 0 位（该槽旧逻辑键的系统键码被抹成 −1）。
- `0xfd` 与 `0x10c` 的差别看"解绑"：`0xfd(槽 7, 逻辑键 28)` 之后再 `0xfd(槽 7, 逻辑键 200)` ⇒ 按 Enter ⇒ **不得**点亮第 7 位（第 2 条 `0xfd` 把上一条绑定的 Enter 键码抹掉了）；同样两条换成 `0x10c` ⇒ 按 Enter ⇒ **仍**点亮第 7 位（`0x10c` 不解绑）。
- `0x10b` 槽 0 写 0、槽 1 写 1，左右键交换关闭：按左键 ⇒ 输入字第 **4** 位；按右键 ⇒ 第 **5** 位。
- `0xfe 1`（键总数 1）+ `0x107` 槽 0 写 0（按钮 0），手柄帽子居中、摇杆在死区内：按按钮 0 ⇒ 输入字**恰好**是第 **4** 位（不是第 0 位、也不是第 35 位）。
- 不执行 `0x107`、键总数 7、按按钮 0 ⇒ 第 **4** 到第 **10** 位**全部**置起（七格的初值都是 0 = 按钮 0）；只置第 4 位 ⇒ 把采样循环的上界当成了组头的按钮数。
- 手柄组头的按钮数为 0（没有设备 / 配置 `system:LimitJoy` = 1）：按任何按钮 ⇒ 不得点亮任何手柄位。
- 输入可用标志为 0：按住 ↑ 采样 ⇒ 键盘来源不得置位；手柄来源**仍**按组头参与（不看这个标志）。
- 让窗口过程收到一次鼠标左键消息（按 `set:ClickOnUp` 选中的那一条）、再让引擎并入一次槽锁存 ⇒ 输入字命中（槽 0 格值 + 4）；同一条消息再来一次、但中间有一次采样已经看到左右键按下 ⇒ 这一次**不得**再点亮（吞并标记生效）。
- **位号 ≥ 32 的落点**：`0xfe 29`，用 `0x107` 把槽 0..27 全指向一个**未被按下**的手柄按钮、槽 28 指向被按下的按钮 0，帽子居中、摇杆在死区内、按住按钮 0 采样 ⇒ 输入字里**恰好**是第 **0** 位（槽 28 的位号 32 落到 0）；若第 0 位不亮、只有位 4..31 亮 ⇒ 把越过 32 的位号实现成了"丢弃"。
- **位号是可共用的唯一空间**：用 `0xfb` 把**键编号 4** 登记到某段脚本，按住鼠标左键（键槽 0 的基位号 0 ⇒ 位 4）之后执行 `0x100` ⇒ 必须派发到那段脚本；派发到别的编号或完全不派发 ⇒ 把"来源自己的编号"与"输入位号"当成了两套空间。
- **帽子 = 方向位 0..3**：把第一组手柄的帽子置 **45°**、所有按钮都不按 ⇒ 输入字必须**同时**有第 **0** 位与第 **1** 位；只点亮一位 ⇒ 把帽子实现成了互斥的 8 方向枚举。再把帽子置 **0°** ⇒ 只有第 **0** 位（上）。
- **摇杆轴的轴序与严格比较**：让设备报"帽子居中"，把轴 1 设成**恰好等于**低阈值 ⇒ **不得**点亮位 3；设成低阈值 − 1 ⇒ 必须点亮位 3（等于阈值不算命中）。把轴 1 设成大于高阈值 ⇒ 位 **1**（右）；轴 2 大于高阈值 ⇒ 位 **2**（下）、小于低阈值 ⇒ 位 **0**（上）。四者与轴的对应若成对调 ⇒ 轴序或符号写错。
- **阈值不重估**：初始化之后再改设备的轴范围并重新采样，方向判定必须仍按**旧的**四条阈值；阈值跟着变 ⇒ 把"初始化采一次"实现成了"每次重估"。
- **「忽略摇杆」门只挡轴**：门置起 + 帽子居中 + 轴越界 ⇒ 四个方向位**都不得**点亮；同一时刻把帽子设为 45° ⇒ **仍然**要点亮位 0 + 位 1（门不挡帽子）。
- **手势来源在发行初值下不点亮任何位**：注入一次编号 4 的手势事件、再走一次「事件并入」采样 ⇒ 输入字**不得**置任何位（8 格表全"不并入"）；置了位 ⇒ 把格值 `< 0` 不并入实现成了"用编号当位号"。注入编号 2（结束）⇒ 同样不得置位、也不得写锁存字。连续两次同一手势事件、中间只做一次并入 ⇒ 只有第一次的锁存被消费（清 0）。

### 采样输入并丢弃（opcode 0x101）

<!-- rule: CORE-OPS-WAIT-POLL-INPUT -->

`0x101` 没有操作数。已观察到的形态是：按固定顺序做四件事：

1. 采样一次输入到引擎的输入字。这次采样走的是引擎的**事件并入**路径：它并入**两个事件锁存字**（键按下的位号锁存、鼠标点击的槽锁存）、**手柄的按下沿**与**手势锁存**，再加上一个引擎级标志（非 0 时点亮第 6 位），**不是** `0xff` 那种"键盘 / 鼠标当前按下状态"的电平采样（见「输入字与键总数」与「输入锁存」）；
2. 清状态选择字的**第 27 位**（读-改-写：只清这一位，其它位保持原值）；
3. 把输入字写成 0（**丢弃**这次采样）；
4. 把两个**等待推进的簿记格**复位：**推进请求格 ← 1**（"没有待处理的推进请求"那一侧）、**点击跳过相位 ← 0**（"空闲"）。它们是**两条不同的格**，都不参与采样、不进输入字。

★ 第 27 位是**跨条目的一位**：`0x88` 在值为 0 时清它，`0x71` 在某个条件下置它，`0xcd` 在它置起时越过时间闸。⚠ 它与等待位（第 10 位）不是同一位；把它实现成"清等待位"会让 `0x101` 变成一次放行，而引擎这里只是清这一位。

★ **第 27 位置起就挡住派发**：服务链扫到它时它的服务体把控制交回迭代头（见「位是待服务标记，清不清由服务分支决定」的位序表）⇒ 第 27 位置起时本迭代不派发、`0x101` 不会被派发 ⇒ 上面的清位是**防御性分支**。本条仍把清位写成合同，是为了让"派发到它时"的引擎数据效果唯一。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 输入已被丢弃 | 输入字 = 0 |
| 第 27 位被清 | 状态选择字第 27 位 = 0（其它位不变） |
| 两个等待推进的簿记格被复位 | 推进请求格 ← 1；点击跳过相位 ← 0 |
| 这次采样消费了哪些事件 | 两个锁存字里被并入的那几位（清 0）、手柄按下沿的每设备状态字（按这一拍比较后更新） |

**成立条件**

- 顺序固定：采样 → 清第 27 位 → 清输入字 → 复位两个**等待推进簿记格**（后三步不许调换）。
- **采样结果本身被丢弃，但这次采样不是"无副作用"的**：它**已经消费**了它并入的事件（锁存字被清、手柄按下沿的状态字被更新）⇒ 之后走同一路径的采样**看不到**这些事件。⛔ 不许把它写成"只是读一下、什么都不改"。
- 这条采样**不看**输入可用标志（并入路径不看它；只有电平来源才受它门控）。
- 两个簿记格的**身份由读者定义**，不给它们另设名字：
  - **推进请求格**的唯一读者是等待服务的**跳过分支**，而且它只与 **0** 比较：该格为 **0** ⇒ 该分支置起「等待推进挂起」标记、把输入字整字清 0、进入等待循环；该格**非 0** ⇒ 走另一条出口（本次不进入等待）。**它的初值是 0**（引擎构造把它写成 0），而且跳过分支在**确认键未按**的那条过场末尾又把它写回 0 ⇒ 0 侧是**初态**，不需要任何前置写者。⇒ `0x101` 把它写成 **1**，等于把这条分支放到"本次不进入等待"的一侧，直到下一次过场把它清回 0。
  - **点击跳过相位**的三态（0 = 空闲 / 1 = 已武装 / 2 = 已跳过一次）由同一条跳过路径读写，**初值 0**（引擎构造写的）。**"确认键"就是输入字的第 4 位**（与「等待、影片与空操作」的「输入跳过」**同一个位号**），整段受配置 `set:CancelMesSkipOnClick` 门控（该键读作 0 ⇒ 三态一个都不动）：
    - **确认键未按**且相位 ≠ 2 ⇒ 相位 ← **1**（= 已武装）；
    - 相位 = 1 且**确认键按下** ⇒ 相位 ← **2**，并清掉输入字的第 4 位；
    - 相位 = 2 且**确认键未按** ⇒ 相位 ← **0**、清掉「等待推进挂起」标记、广播一次"文本跳过"。
  - ⛔ 不许把这三态与「等待推进挂起」标记合成一格：相位是**跨迭代**的（决定下一次确认键怎么解释），标记是**本迭代**的（挡派发）。
  - ⇒ `0x101` 把两者复位成"无请求、空闲"就是**把跳过状态清干净**，不是给某条消息开绿灯。
- 这两个格**不是别的引擎标志的别名**：它们不参与采样、不进输入字，也不被 `0xff` / `0xfc` / `0x199` 碰。
- ⛔ 不许把第 27 位与等待位、影片位或睡眠位合并成一个"通用标志"。

**可证伪**

- 注入一次"键已按下"的事件（不按着物理键），执行 `0x101`，随后再走一次同一条"事件并入"采样 ⇒ 那个事件的位**不得**再出现；仍出现 ⇒ 这次采样没有消费位号锁存字（或它根本走的不是并入路径）。
- `0x101` 之前按住↑、执行 `0x101` ⇒ 输入字为 0（丢弃）；紧接着执行 `0xff` 且仍按住↑ ⇒ 第 0 位**必须**置起（`0xff` 的电平采样仍在；若 `0x101` 把键盘按下状态当成一次事件消费掉、使 `0xff` 看不到，则两条路径被混成了一条）。

### 输入回调的登记（opcode 0xcc / 0xfb）

<!-- rule: CORE-INPUT-CALLBACK-REGISTER -->

**按键回调（`0xfb`）** 有两个操作数：**键编号**、**脚本位置**。

- 键编号接受 `0` 到 `31`（**无符号比较**：`32` 及以上、`-1` 都拒绝）⇒ 抛**显示消息型异常**，不登记、不改任何引擎状态。
- 登记是**按当前帧**的：每个帧有一张「键编号 → 脚本位置」的表，初值全部是「未登记」。「没有按键」时使用**编号等于键总数**的表项；该表项是否已登记由脚本自己决定。
- 表每帧 **33 格**：编号 `0..31` 可登记，第 33 格（编号 32）**既写不进也读不到**；「无按键」那一格与"编号 = 键总数"的那个键回调是**同一格**（见「派发按键回调」）。
- 同一编号重复登记 ⇒ 后一次覆盖前一次。
- 推进格数 = 5；不改门位、不改输入字、**不切换当前帧（帧号不变）**。

**鼠标回调（`0xcc`）** 有两个操作数：**轮询间隔**、**脚本位置**。

- 间隔按**毫秒**读，**不做正负检查**：`0` 被**无条件写成 1**（唯一处理，没有别的语义分支 ⇒ "0 毫秒"与"1 毫秒"在脚本侧不可区分）；负值照写，而时间闸是**有符号**比较 ⇒ 负间隔**每次都通过**（等价于"每次到期都派发"）。
- 登记时记下四样东西：脚本位置、**轮询间隔**、**当前帧的脚本身份**（打开该脚本用的统一文件 id）、**当前时刻**（作为「上次派发时刻」的初值 —— **不是 0**）。
- **记身份的用途就是派发时的校验**：`0xcd` 把"当时的当前帧身份"与它比较，相等才允许跳转（见「定时派发鼠标回调」）⇒ 同一份文件里的两个帧可以互相派发；换一份文件就必须重新登记。⛔ 不要把身份实现成帧号或调用层数（校验失败时的异常文案把它称作「Depth」，那是文案，不是语义）。
- 脚本位置为 `-1` 表示**取消登记**：下一次派发时什么都不做（但仍会消耗一次定时）。
- 推进格数 = 5；不改门位、不改输入字、**不切换当前帧（帧号不变）**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个按键编号绑定到哪段脚本 | 当前帧的按键回调表（键编号 0..31；「无按键」使用编号等于键总数的表项） |
| 鼠标回调绑定到哪段脚本 | 引擎的一格脚本位置 |
| 鼠标回调的轮询间隔 | 引擎的一格毫秒数（0 被写成 1；负值照写、不检查） |
| 鼠标回调的所属脚本 | 登记时当前帧的脚本身份（统一文件 id） |
| 鼠标回调的上次派发时刻 | 引擎的一格时刻（登记时 = 当前时刻） |

**成立条件**

- 两张表不是同一张：按键回调按帧存，鼠标回调存引擎级一格。
- 身份是**帧记录里的脚本统一文件 id**，不是帧号、也不是调用层数；当前帧身份 ← **被装入文件的 id**。`0x3` 装入另一份文件时身份随之改变；**同一份文件内的嵌套调用不改变身份**。
- 鼠标回调的登记是**引擎级一格**：任何脚本执行 `0xcc` 都会覆盖它 ⇒ 装入了**不同文件**的子脚本登记过之后，父脚本回来必须先重新登记，否则 `0xcd` 的身份校验会失败。
- `0xfb` 的越界路径在写表**之前**返回；`0xcc` 没有范围检查（`-1` 是取消哨兵）。
- **间隔的唯一读者是 `0xcd` 的时间闸**（`已过时长 ≥ 间隔` 才派发）：因为 0 已被写成 1，**间隔恒 ≥ 1**（负值的例外见上）；`0xcc` 本身不读它、也不等它。
- 登记本身不派发；派发只发生在 `0xcd` / `0x100`。

### 定时派发鼠标回调（opcode 0xcd）

<!-- rule: CORE-INPUT-MOUSE-CALLBACK-PUMP -->

`0xcd` 没有操作数。它按**时间闸**决定这次是否把控制流交给已登记的鼠标回调。

1. 推进格数先写成 1（缺省只前进一条指令）—— 本条是 `0xcd` 的处理体，自己写推进格数。
2. 读一次当前时刻。若「当前时刻 − 上次派发时刻」**小于**登记间隔，**并且**状态选择字的第 27 位不为 1 ⇒ 直接返回（只前进一条）。★ 第 27 位置起时它自己的服务体把控制交回迭代头 ⇒ 置起即挡住派发，本条不会被派发；所以这一支只在第 27 位未置时有意义。门忙时派发仍可能发生：扫描走到表尾派发一条；第 29 位命中时则看**文本槽在用标志** —— 标志 ≠ 0（例如演示闸层开着）⇒ 每迭代派发一条，**标志 = 0**（普通打字）⇒ 本迭代零派发、直到推进器清掉第 29 位（见「门：整字为 0 直接派发；非 0 先扫服务链，扫完仍派发一条」）。
3. 否则把「上次派发时刻」更新为当前时刻，并**压入返回位置**：当前位置（dword 下标）的下一条（同一帧）。
4. 若登记的脚本位置是 `-1` ⇒ 撤销刚压入的返回位置，返回（只前进一条）。
5. 否则校验：**当前帧的脚本身份**必须等于**登记时的身份**；不等 ⇒ 抛**显示消息型异常**。
6. 校验通过 ⇒ 把当前帧的指令指针改到登记的脚本位置，推进格数写成 0（不再自动前进）。

- 这条**不读任何输入状态**、**不写任何脚本变量**；它只做时间判断与控制转移，**不切换当前帧（帧号不变）**。
- 它把控制流交给回调的方式与「同脚本调用」相同：压返回位置、跳到目标位置、由回调的返回指令回到下一条。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 距上次派发过了多久 | 当前时刻 − 上次派发时刻 |
| 这次是否派发 | 时间闸或第 27 位（「等待推进挂起」置起 ⇒ 越闸） |
| 回调返回后从哪里继续 | 当前帧的返回栈顶 ← 当前位置（dword 下标）+ 1 |
| 回调在哪个脚本里执行 | 当前帧的脚本身份（必须等于登记身份） |
| 身份不符时 | 时间闸已消费 · 返回位置留在栈上 · 指令指针不变 · 抛显示消息型异常 |

**成立条件**

- 时间闸的判据是 **`elapsed >= interval`**（含等号），不是 `>`。
- **第 27 位 = 「等待推进挂起」标记**：等待服务判定"本条消息的等待已由**外部推进**（滚轮 / 跳过）满足"时**置起**它，并把**输入字整字清 0**（这一次推进只算一次，不重复点亮）；"点击跳过"走完时**清**它。它**不是**等待位（第 10 位）、也不是影片位。置起期间有两件事：**正常派发让路**（服务链把它当"本迭代已处理"），而**本条越过时间闸**（不看到期、直接派发一条）。`0x101` 会清它（防御性分支：置起时它本来就不会被派发到）。⛔ 不许把它与等待位 / 影片位合并成一个"通用标志"。
- 身份校验发生在**目标不是 −1** 时；失败是脚本层可见的显示消息型异常，不是静默跳过。异常文本把它称作“Depth”，但比较的是脚本身份，⛔ 不要据此实现成调用层数。
- **失败路径的脚本可见态**（身份不等时，四件事同时成立）：① 时间闸**已被消费** ——「上次派发时刻」已是本次时刻，随后再来一次不会因为"还没到期"被挡；② 压入的返回位置**留在返回栈上、不回滚**；③ 指令指针**不变**、推进格数保持 **1**；④ 抛出的是**显示消息型异常**。
- 目标为 `-1`（取消）时相反：**撤销**刚压入的返回位置、只前进一条、不抛。
- 回调的返回位置是**下一条**指令；`0x100` 的按键派发不同（见下一条）。

**可证伪**

- 时间闸若写成 `>` 而不是 `>=`、返回位置若是**当前指令**而不是下一条、或目标 `-1` 仍会跳转 ⇒ 本条错。
- 同一文件 id 的两个帧（A 登记、B 派发）必须通过；换成不同文件 id 必须抛显示消息型异常。
- **失败路径消费时间闸**：构造一次身份不符、捕获异常，紧接着再派发一次（距上次不足间隔）⇒ 必须**仍被时间闸挡住**；第二次能派发 ⇒ 失败路径没有把「上次派发时刻」更新到本次。
- **失败路径不回滚返回栈**：身份不符抛异常之后，令该帧执行一次「返回」⇒ 若回到调用点**之后** ⇒ 失败路径弹掉了那一项（引擎应是**不**弹）。
- 目标 `-1`：必须只前进一条，且下一次派发仍能正常压栈（说明 `-1` 路径退了栈）。
- 第 27 位置起时派发一条，随后**清掉第 27 位**、再紧接一次派发（距上次不足间隔）⇒ 必须**不**派发（说明"越闸"没有把间隔改成 0、也没有重置「上次派发时刻」以外的量）。

### 派发按键回调（opcode 0x100）

<!-- rule: CORE-INPUT-KEY-DISPATCH -->

`0x100` 没有操作数。它按当前输入字与当前帧的扫描游标派发**一个**按键回调。

设 `limit` = **键总数**（引擎的整数格；`0xff` 把它抄进按帧上限，但本条读的是键总数本身），`cursor` = 当前帧的扫描游标。★ `0xff` 写下的按帧上限格供「按住派发按键回调」(`0x104`) 使用；本条不读它。两者的分工是**五处**：本条读**键总数**、**正向**从扫描游标起扫、查"每（帧 × 键）一个目标"的表、返回点随"有没有按键"二选一；`0x104` 读**按键扫描上限**、**反向**从上界往下扫、查"每（帧 × 键）一小组槽位"的表、返回点由**按住掩码**决定、且每条出口都推进游标。

- **输入字为 0**：考虑**编号等于 `limit` 的表项**（「无按键」表项）。
  - 该表项未登记 ⇒ 只前进一条（推进格数 1）。
  - 该表项已登记 ⇒ 压入返回位置（**当前位置（dword 下标）+ 1**），把指令指针改到表项位置，推进格数 0。
- **输入字非 0**：从 `cursor` 起，在 `[cursor, limit)` 里找**第一个置位**的编号。
  - 找不到 ⇒ 只前进一条（推进格数 1）。
  - 找到 ⇒ 把扫描游标写成「找到的编号 + 1」；然后：
    - 该编号的表项已登记 ⇒ 压入返回位置（**当前位置（dword 下标）本身**，不是下一条），把指令指针改到表项位置，推进格数 0。
      ⇒ 回调返回后会**重新执行这条指令**，因为游标已经前进，于是派发下一个置位编号；如此逐个派发完全部置位。这是**有意的重派发**，终止靠游标前进。
    - 该编号的表项未登记 ⇒ 只前进一条（推进格数 1），并**放弃本轮剩余的置位**。★ **扫描游标此刻已经前进**（它在本条**查表之前**就被写成「找到的编号 + 1」）⇒ "放弃本轮剩余"只对**这一次**执行成立：下一次执行从该编号之后继续，仍可能派发后面的置位。
- ★ **多键派发顺序 = 位号升序**：回调返回后本条被**重新执行**，于是同一个置位集合被**按位号从小到大**逐个派发。顺序**只**由位号决定 —— 与按下的先后、来源（键盘 / 鼠标 / 手柄）都无关；它**不是**优先级表，也不是"最近按下优先"。
- 这条不写脚本变量、不置门位、**不切换当前帧（帧号不变）**；帧号 / 父帧号 / 代码区不变（按帧扫描游标除外）。
- 扫描范围是**左闭右开**：包含 `cursor`，不包含 `limit`。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 这次派发哪一个按键 | 输入字里从游标起的第一个置位编号（= 该范围里位号最小的） |
| 多次派发时的先后 | 位号升序 |
| 下一次从哪里继续 | 当前帧扫描游标 ← 找到的编号 + 1 |
| 无按键时派发哪一段 | 编号等于键总数的表项 |
| 回调返回后从哪里继续 | 输入字为 0 的表项 ⇒ 下一条；按键表项 ⇒ 当前位置（重新派发） |
| 回调以「中止 / 结束脚本 / 退出脚本」收尾 | 压入的返回位置**留在栈上**（不弹、深度不回退） |

**成立条件**

- **输入字为 0** 与**输入字非 0** 的返回位置**不同**：前者是「下一条」，后者是「当前位置」。这不是笔误：后者是逐个派发的迭代器。
- 未登记的表项会让本轮扫描提前结束（不是跳过它继续找下一个），**而游标已经越过该编号** ⇒ 下一次执行不会卡在同一格。
- **按键回调表每帧 33 格**：编号 `0..31` 对应 32 个输入位号，另有一格（编号 32）**既写不进也读不到**（登记只接受 0..31，而无按键编号 = 键总数 ≤ 31）。⇒「无按键」用的那一格与"编号等于键总数"的那个键回调**是同一格**：脚本把回调登记在「编号 = 键总数」上时，它既服务于该编号的按键、也服务于无按键。
- **返回栈没有深度检查**：每次派发压一层、该帧深度计数 +1，引擎**不检查**上界。回调里再执行派发指令是合法的（再压一层）。★ 返回栈的**容量、第 257 层的落点与处置**只在「帧类指令」的「调用」那条里规定一次（本条不复述）——⛔ 不许在这里另立一套"到上限就丢弃"或"到上限就抛"的说法。
- **深度按帧隔离**：深度计数每帧一格；切帧之后是**另一个**计数。同一轮多键派发**不叠加**嵌套（一次只压一层，回调返回后弹一层）。
- **三种"非返回"收尾不清理返回栈**：回调以「中止」/「结束脚本」/「退出脚本」收尾时，它被派发时压入的返回位置**不被弹出**、深度计数**不回退**；那条栈项留在栈上，直到该帧被重新装载 / 复位（整段清 0）才消失。⇒ 这三种收尾与「返回指令」收尾在返回栈上是**不同**的（后者弹一项）。
- 回调是同一帧里的脚本调用；它写的局部池对主循环可见。
- 这条只派发**一个**回调；要派发全部，需要脚本反复执行它（引擎不在这里循环）。

**可证伪**

- 同时置起位 3 与位 5、两段脚本各自登记，反复执行本条：脚本收到的顺序必须是 **3 → 5**；5 先 ⇒ 不是升序扫描。
- 同时置起位 3 与位 5，但**先按 5、后按 3**：顺序必须**仍是** 3 → 5；变成 5 → 3 ⇒ 顺序混进了按下先后。
- 位 3 未登记、位 5 已登记、两位同时置起，连续执行两次：第一次不派发（前进一条），第二次**必须**派发位 5；第二次也不派发 ⇒ 把"游标前进"漏掉了（实现成了"整轮作废"）。
- 回调以「结束脚本」收尾：执行一次派发后，再令该帧执行一次「返回」⇒ 若回到调用点**之后** ⇒ 结束路径弹掉了那一项（本条错）。
- 回调以「返回指令」收尾：返回栈深度必须**不变**（压一项又弹一项）；深度 +1 ⇒ 返回路径没弹。
- 嵌套派发 256 层：第 256 层仍正常返回；第 257 层的落点与处置按「帧类指令」的「调用」那条判（只有那一处规定）——**不得**表现为"环形覆盖最旧一项"或"静默丢弃"（引擎不检查深度，两种替身都不是它）。
- 切帧后再派发：深度计数必须是**新帧**的（从 0 起），不是全局一个。
- 把回调登记在编号 7 上、键总数也是 7、输入字为 0 ⇒ 必须派发到那段脚本（无按键编号 = 键总数 = 7）；不派发 ⇒ 无按键编号不是键总数。
- 同上，但**不重新登记**、只把键总数改成 8、输入字为 0 ⇒ **必须不派发**（编号 8 未登记）；仍派发到编号 7 那段 ⇒ 无按键编号被实现成常量 7。
- 键编号 31 + 键总数 31 + 输入字 0 ⇒ 派发到编号 31 那段（同一格既当按键回调又当无按键回调）；若实现把两者当成两格 ⇒ 表宽写错。
- 键编号 32 登记 ⇒ 必须抛显示消息型异常（不是静默写第 33 格）。

### 取一个触点（opcode 0x2fc）

<!-- rule: CORE-INPUT-TOUCH-POINT -->

`0x2fc` 有五个操作数：**结果**、**横坐标**、**纵坐标**、**第 4 个附加字段**、**第 5 个附加字段**。

- 读取**引擎维护的触点缓冲**。它不是跨消息累积的队列：**每收到一条触摸消息，引擎把缓冲整体重建** —— 触点计数先清 0 → 释放旧缓冲 → 按**该消息携带的触点数**重新分配（每项固定 40 字节）→ 把这批触点逐个读入并把取回个数写回计数。⇒ 上一次消息的触点**全部不可见**；引擎**不设容量上限**、不排队、也不按新消息"淘汰最旧项"。"一条消息带几点"由平台决定（本版不规定）。
- **输入可用标志为 0 / 没有有效触点**：第 1 个操作数写 0；第 2 到第 5 个操作数**保持原值**（不写）。
- **有触点**：第 1 个操作数写 1；第 2 / 3 个写该触点在**引擎虚拟屏坐标系**中的横 / 纵位置 —— 平台给的是**百分之一像素**值，引擎**除以 100（向零截断）**、转客户区、再按显示模式映射（与 `0x109` **同一套**换算，见「读光标位置」）；第 4 个写该项的**标志字**（原样），第 5 个写该项的**第二个附加量**（原样）。
- **"有效"只看标志字的两位**：标志字的「抬起」位必须为 **0**、且「主触点」位必须为 **1**（两位是**与**关系）；其余标志位不参与筛选，也不影响写出的字段。
- **两个附加字段原样传递**：不做位段解释、不做符号处理、不取低 16 位 —— 任意 32 位值逐位原样写出。
- **多个有效触点**：返回缓冲顺序中**第一个**有效触点；⛔ 不按编号排序、也不保证是“最新”触点。
- **不是事件队列**：每次查询都从缓冲首项扫；同一次触点重复查询会得到同一个触点，触点不由本条“消费”。缓冲里**全部无效**时，引擎把触点计数清 0（下一次仍返回“没有触点”）。
- 推进格数 = 11；不改门位、**不切换当前帧（帧号不变）**、不写其它脚本变量。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前有没有有效触点 | 第 1 个操作数（1 / 0） |
| 触点的虚拟屏位置 | 第 2 / 3 个操作数 |
| 触点的两个附加字段 | 第 4 个 ← 该项的标志字（原样）；第 5 个 ← 该项的第二个附加量（原样） |
| 一个触点是否算"有效" | 标志字「抬起」位 = 0 **且**「主触点」位 = 1 |
| 触点缓冲里全部无效 | 触点计数 ← 0 |

**成立条件**

- **没有触点时不写坐标**：把坐标清 0 会把「没有触点」与「触点在原点」混为一谈。
- 坐标是**引擎虚拟屏坐标系**：原始值是百分之一像素 ⇒ 先 ÷100（向零截断）、再转客户区、再按显示模式映射（映射的分档与顺序见「读光标位置」的结构面合同）。
- 第 4 / 5 个附加字段是**原样搬运**：引擎不需要它们的位段语义，⛔ 不许按位段解释、⛔ 不许规范化。
- 多触点的选择是**缓冲顺序第一个有效项**；这一条与“触点编号”无关。
- **触点缓冲不是事件队列**：本条不递增读游标、不清空缓冲；只有“全部无效”才把计数清 0。缓冲的重建只由**触摸消息**触发，不由本条触发。

**可证伪**

- 构造一个「抬起位已置」的触点 ⇒ 必须被跳过（返回"没有触点"，计数可能被清 0）；它被返回 ⇒ 抬起位判据漏了。
- 构造一个「主触点位未置」的触点 ⇒ 同样跳过；两个判据是**与**、不是**或**。
- 把一个附加字段设成任意 32 位值（如 `0xFFFFFFFF`）⇒ 第 4 / 5 个操作数必须**逐位原样**得到它（不得取低 16 位、不得规范化）。
- 记录坐标 = 12345 ⇒ 写出的客户区横坐标必须是 `trunc(12345 / 100) = 123`（再经显示换算），不是 12345、也不是 124。
- 无触点时先把第 2..5 个操作数预置成非 0 哨兵：只有第 1 个变 0，其余原样。
- 先投一条带 3 个触点的触摸消息、再投一条带 1 个的：查询必须只看到**后一条**的那 1 个（计数 1）；还能查到前一条的触点 ⇒ 缓冲没有整体重建（被实现成了"追加"）。
- 投一条带 0 个触点的消息：计数必须变 0；仍返回旧触点 ⇒ 同上。
- 让平台一次给很多触点：查询必须能看到最后一个（引擎不截断、不设上限）；截断到固定容量 ⇒ 实现擅自设了上限。

### 命中查找（opcode 0x12e）

<!-- rule: CORE-INPUT-HIT-TEST-12E -->

`0x12e` 有八个操作数：**起始下标兼结果**、**补偿四元组**、**横坐标**、**纵坐标**、**框表**、**横基准平面**、**纵基准平面**、**项数**。

- 第 2 / 5 / 6 / 7 个操作数是**数组起始地址**，不是标量：第 2 个指向 4 个连续整数，第 5 个指向每项 4 个整数的框表，第 6 / 7 个各指向每项 1 个整数的基准平面。
- 第 1 / 3 / 4 / 8 个操作数按整数读。
- 令 `start` = 第 1 个操作数的整数值、`m0..m3` = 补偿四元组、`x` / `y` = 第 3 / 4 个操作数、`S[i][0..3]` = 框表第 `i` 项、`bx[i]` / `by[i]` = 两个基准平面第 `i` 项、`count` = 第 8 个操作数。
- **扫描由两个指针决定（不是索引区间）**：首项指针 = 框表基址 + (`start` + 1) × 每项字节数、末项指针 = 框表基址 + `count` × 每项字节数，两者都按 32 位回绕；**当前项指针无符号 ≥ 末项指针 ⇒ 立刻结束**，否则考察当前项、指针前进一项。⛔ 不许把它实现成"`i` 从 `start + 1` 数到 `count`"：那两套模型在**偏移回绕**与 **`count` 为负**时会给出不同结果（判据见下「成立条件」）。★ 只有在"两个乘法的偏移都不回绕"时，它才**等价于**索引区间 `[start + 1, count)` —— 那是便于阅读的特例，不是合同本身。逐项算：
  - `dx = x − bx[i]`
  - `dy = y − by[i]`
  - 命中判据是四个不等式**同时**成立：
    `m1 + dx − S[i][0] ≥ 0`、`m3 + dy − S[i][2] ≥ 0`、
    `S[i][1] − dx − m0 ≥ 0`、`S[i][3] − dy − m2 ≥ 0`。
- 第一个命中项 ⇒ 把它的下标写进第 1 个操作数并结束；扫完没有命中（含**起始项指针一开始就 ≥ 末项指针**）⇒ 第 1 个操作数写 **−1**。
- **同址门**：若第 2 个操作数指向的四元组与当前被考察的框表项**是同一块地址**（**指针相等**，不是"四个值相等"），该项被**跳过**：不算命中、**也**不终止扫描（继续考察下一项）。⛔ 不要实现成"值相等就跳过"，也⛔ 不要实现成"跳过之后终止"。
- 只写第 1 个操作数；第 2 到第 8 个操作数**只读不写**。不改变输入字、回调表、门位、游标、键总数或帧号。
- 推进格数 = **17**；没有返回值、不标脏、不发出任何外部请求。

★ 判据等价于把每项看成一个可带补偿的矩形：

```text
dx ∈ [S[i][0] − m1, S[i][1] − m0]
dy ∈ [S[i][2] − m3, S[i][3] − m2]
```

补偿四元组全 0 时，框表项就是 `[左, 右, 上, 下]`。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 从哪一项之后开始找 | 第 1 个操作数的当前值 + 1 |
| 某一项是否在命中矩形内 | 该框与补偿四元组算出的两个闭区间 |
| 这次找到哪一项 | 第 1 个操作数 ← 第一个命中项的下标 |
| 没有命中 | 第 1 个操作数 ← −1 |
| 各项的位置 | 两个基准平面的第 i 项 |

**成立条件**

- **起点是 `start + 1`，不是 `start`**：第 1 个操作数既作输入又作输出；脚本把它写成 −1 就是从 0 开始扫。
- **不环绕**：扫描**只有一个终止判据** —— **当前项指针（无符号）≥ 末项指针 ⇒ 立刻结束**；`count` 只是算末项指针的输入，⛔ 不是"扫到 `count` 个"的计数上限（见下「没有『项数』前置判据」）。起点之后的项没命中时，不会回头找起点之前的项。
- **闭区间**：四个不等式都含等号。
- **没有「项数」前置判据**：扫描范围完全由**两个指针**决定 —— 起始项指针 =（`start` + 1）× 每项字节数 + 框表基址，末项指针 = 框表基址 + `count` × 每项字节数（两者都按 32 位回绕）。**当前项指针无符号 ≥ 末项指针 ⇒ 立刻结束**；起始项指针一开始就满足 ⇒ 一项都不扫、直接写 −1（⛔ 引擎入口**不单独判** `count` 的符号或 `count ≤ 0`：`count` 只参与算末项指针）。
- **由指针判据可推出的三个端点**（不是额外规则）：① **`count` 为负** ⇒ 末项指针落在框表基址**之前**；此时**只**在**首项指针也 ≥ 它**（即 `start + 1` 那一项不更靠前）时才一项都不扫 —— **首项指针更靠前时照常扫**（`start + 1` 为负且乘出更小的偏移 ⇒ 从表前逐项扫到末项指针，读越界、命中即写回下标）。⇒ ⛔ 不许把"`count` 为负"写成"一项都不扫"：那是把末项指针的**位置**读成了 `count` 的**符号**。② **`count` = 0** ⇒ 末项指针 = 框表基址 ⇒ **`start` ≥ −1 ⇒ 一项都不扫**；**`start` ≤ −2（且偏移不回绕）⇒ 首项指针落在框表之前，会从表前逐项扫到框表基址**（读越界、内容未定义；命中即写回下标）。⛔ 不许实现成"`count` = 0 一律不扫"。③ **`count` 为正**且偏移不回绕 ⇒ 才是"从 `start + 1` 到 `count − 1`"的普通形态。
- 框表 / 两个基准平面按**同一个项下标**取值；第 5 个操作数的每项是 4 个整数。
- 四项判据用 **32 位**加减后**合并符号位**判断：溢出**回绕**（不扩宽、不饱和）。
- **三个可逐字推出的端点**：① `start` = 最大正数 ⇒ `start + 1` 回绕成 0 ⇒ 与 `start = −1` **等价**（从第 0 项起）；② `start ≤ −2` **且偏移不回绕**（`(start + 1) × 每项字节数` 仍是负值）⇒ 首项落在框表**之前**（越界读，读到的内容未定义；⛔ 不 clamp 下标、⛔ 不跳过）；★ 偏移一旦**回绕**，首项**不一定**在表前：例如 `start = −2147483646` ⇒ `(start + 1) × 16` 只留低 32 位 ⇒ 偏移 = **48** ⇒ 首项 = 表内第 **3** 项，照常往下扫（⛔ 不许写成"`start ≤ −2` 一律越界"）；③ `count` 大到使末项指针回绕到基址之前 ⇒ **首项指针 ≥ 它时立刻判"无命中"**（一项都不扫）；首项指针仍更靠前时**照常扫到那个回绕后的末项指针**（同 ① 的同一条判据，⛔ 不是"`count` 一大就无命中"）。
- **越界读的内容属未定义**：只规定"会读"，不规定读到什么；引擎**不抛**脚本可见的异常、⛔ 不补 0。
- 该条**不建**任何记录、**不写**其它状态；它只是纯计算 + 写一个结果。

**可证伪**

- 用五项框 `[0, 0x9c, 0, 0x9c]`、横基准 `[0x44e, 0x3e0, 0x365, 0x2d9, 0x453]`、纵基准 `[0x126, 0x192, 0x1e5, 0x21f, 0x22a]`、`start = −1`：光标只落在**下标 2** 的框内（例如 `(0x3c0, 0x220)`）⇒ 必须写 **2**；落在全部框外 ⇒ 必须写 **−1**。
- 同一组数据、`start = 2`：即使光标在下标 0 的框内，也必须只从下标 3 起扫；找不到时写 −1。
- `count = 0`、`start = −1` ⇒ **不读框表**、必须写 −1；仍读表 ⇒ 两个指针相等时没按"≥ 即结束"。
- `count = 0`、`start = −3`、框表**之前**两项摆成能命中的框（光标落在其中）：必须命中**表前那一项**并把它的下标写回（−2 / −1）；返回 −1 ⇒ 把"`count` = 0 一律不扫"实现了出来。
- `count = −1`、`start = −1`、框表基址是一个正常堆地址 ⇒ 必须**立刻**写 −1（一项都不扫）；开始扫描 ⇒ 把末项指针的符号当成了偏移方向。
- `count = −1`、`start = −3`、框表**之前**两项摆成能命中的框（光标落在其中）：首项指针 = 基址 − 32 < 末项指针 = 基址 − 16 ⇒ 必须**从表前扫起**、命中并写回 −2 / −1；若立刻写 −1 ⇒ 把"`count` 为负"当成了"一项都不扫"（漏掉"首项指针是否已 ≥ 末项指针"这一判）。
- 第 1 个操作数以外的七个操作数在调用前后必须**逐一不变**。
- 把 `m1` 增大 1 而其它不变：左边界必须跟着外扩 1；若左边界不动，判据写错。
- 把第 2 与第 5 个操作数指向同一数组：下标 0 = `[0,0,0,0]`、下标 1 = `[0,0x9c,0,0x9c]`，两个基准平面都为 0，`start=−1`、`count=2`、光标 `(0,0)` ⇒ 必须返回 **1**（下标 0 同址被跳过）；返回 0 = 同址门未实现。
- 第 2 个操作数指向**另一块**内存、但四个值与下标 0 的框**恰好相同** ⇒ **不得**跳过（必须能命中下标 0）；被跳过 ⇒ 把"地址相等"实现成了"值相等"。
- `start` = 最大正数、`count ≥ 2`、光标在第 0 项框内 ⇒ 必须返回 **0**（不是 −1）；返回 −1 ⇒ 把 `start + 1` 的回绕实现成了"越界即无命中"。
- `start = −2147483646`、`count ≥ 4`、光标落在第 3 项的框内 ⇒ 必须返回 **3**（偏移回绕成 48 ⇒ 首项就是第 3 项）；返回 −1、或从表外扫起 ⇒ 把端点 ② 的"偏移**不回绕时**"读成了"`start ≤ −2` 一律越界"。
- `count` 取使末项指针回绕到基址**之前**、且 `start = −1`（首项指针 = 基址 ≥ 那个末项指针）⇒ 必须**立刻**返回 −1（一项都不扫）；崩溃或长时间扫描 ⇒ 末项不是按 32 位回绕算的。同一构造下把 `start` 改成更靠前的值（首项指针 < 回绕后的末项指针）⇒ 必须**照常扫**，不是"立刻无命中"。
- 坐标与框值各取 32 位极值使差溢出 ⇒ 判据必须按**回绕后**的值比；按 64 位算 ⇒ 结果与引擎不同。
- 所有"越界"路径都**不得**抛脚本可见的异常（引擎不检查）。

### 读光标位置（opcode 0x109）

<!-- rule: CORE-INPUT-MOUSE-POS -->

`0x109` 有两个操作数：**横坐标**、**纵坐标**。

- 输入可用标志非 0 ⇒ 向平台查询当前光标位置；为 0 ⇒ **不向平台查询**。
- **输入可用标志非 0**：两个操作数分别写光标在**引擎虚拟屏坐标系**中的位置。**平台给出的客户区坐标可以在客户区外**（负 / 超界）：引擎仍按同一映射写出，不是哨兵。
- **输入可用标志为 0**：两个操作数**都写 −100000**。
- 推进格数 = 5；不改门位、**不切换当前帧（帧号不变）**、不写其它脚本变量。

**坐标换算（结构面）**

平台先给出**客户区**坐标，引擎再用**同一套**换算把它变成脚本看到的虚拟屏坐标；**触点查询（`0x2fc`）用同一套** ⇒ 同一个客户区点在两条查询里得到**同一个**虚拟屏坐标。

换算的三个输入是：

1. **基准尺寸** = **配置的客户区宽 / 高**（显示配置里那两个客户区尺寸项；引擎建立时给 640 × 480 的兜底，随后按配置覆盖）。
2. **目标矩形** —— **虚拟全屏开** ⇒ 平台报的**窗口客户区矩形**；**虚拟全屏关** ⇒ 与基准尺寸同尺寸、原点在 `(0, 0)` 的矩形。比例式里的「目标尺寸」= 该矩形的**宽 / 高**（右减左、下减上）。
3. **一对显示偏移** —— 渲染器上的两个整数；渲染器另有一个开关，**它非 0 时这对偏移按 `(0, 0)` 算**。这就是「先减 / 后减」里被减的那一对。

换算按「虚拟全屏」与「类型」分档：

- **虚拟全屏关** ⇒ **不做缩放**（这一档**不进比例式**，比例一律取 **1.0**），只把两个分量各减去对应偏移。⛔ 不许按下面两条的算式给它算比例：按类型 0 / 1 的算式，目标 = 基准时给的是 `1 + 2 × 偏移 ÷ 基准`，**偏移 ≠ 0 就不等于 1.0** —— 所以"比例恒 1.0"是**这一档的规定**（短路），不是那两条算出来的结果；
- **类型 0 / 1** ⇒ 比例 =（目标尺寸 + 2 × 偏移）÷ 基准尺寸，**先乘**比例、**后减**偏移；
- **类型 2** ⇒ **先减**偏移；比例 = 目标尺寸 ÷（基准尺寸 − 2 × 偏移）；
- 比例恰为 **1.0** 时**跳过乘法**（偏移照减）。★ 这一步**在非负坐标上**与"乘 1.0 再取整"没有差别（非负整数时 `trunc(值 × 1 + 0.5) = 值`），但**负坐标上不成立**：向零截断下 `trunc(−3 × 1 + 0.5) = −2` —— 所以"是否跳过"在负坐标上**可黑盒观察**（见下方可证伪里那条负坐标判据）；白盒路径检查只是补充。⛔ 不许把它写成"对任何输入都无差别"；
- 缩放结果一律 `trunc(值 × 比例 + 0.5)`（四舍五入、半上）；
- 另有一个「整段禁用换算」开关：它非 0 时坐标**原样**写出。

★ 「目标」与「基准」是**两个不同的量**：目标跟着**平台报的客户区**走，基准跟着**配置**走 —— ⛔ 不许把两者写成同一个来源（那样"虚拟全屏开 + 客户区与配置不同"就永远得不到非 1.0 的比例）。

★ **这里的「比例 / 偏移」与场景章那对「缩放对 / 居中偏移对」不是同一对格**（交叉引用：场景章的「绘制时怎样合成最终世界变换」；那一对缩放的算式真源在场景章的「显示适配」）：
- **偏移是同一对**：两处读的是**同一次**「取两个显示偏移」的结果（同一个渲染器对象、同一个「用固定区域尺寸」开关把它归零）；
- **比例不是同一格**：本条的**比例是每次查询现算的**（分子 / 分母是本条自己的目标尺寸与基准尺寸，且类型 0 / 1 那一档分子里含 **2 × 偏移**），引擎**不读**渲染器上那对缓存的缩放值；那对缩放值是**另一条路径按两个尺寸的比**算出来并缓存的（算式真源在场景章的「显示适配」）。
⇒ 只有「偏移 = 0」时两者可能同值（那时本条的算式退化成"目标尺寸 ÷ 基准尺寸"，与那对缓存值的形态一致）；偏移 ≠ 0 时数值一般不同。⛔ 不许把两处实现成同一格（那样会用一条未取证的等式把上面那条边界悄悄关掉），也⛔ 不许把本条的算式套到那对缓存值上。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 光标位置（虚拟屏；含出界） | 第 1 / 2 个操作数 |
| 输入可用标志 | 引擎的一格（启动置 1；清 0 路径见章首） |
| 输入可用标志为 0 | 不查询；两个操作数 ← −100000 |

**成立条件**

- 「不可用」不是「不写」：两个操作数都会被写成哨兵 −100000。
- **哨兵只由“输入可用标志为 0”触发，不是“光标出了客户区”**：窗口存在时，平台给出的客户区坐标可以在客户区外（可为负 / 超界），引擎仍按同一映射写出；把它写成 −100000 会让脚本无法区分“出窗”与“没有输入设备”。
- 第 1 个操作数是横坐标、第 2 个是纵坐标；读操作数本身的次序是 2 → 1（先取地址再按类型写），但对外语义是「写两个目标」。
- 显示模式变换（窗口 / 虚拟全屏）属引擎对平台坐标的再映射：三个输入（基准尺寸 / 目标矩形 / 一对显示偏移）与分档、顺序见上面的结构面合同；⛔ 不许把「目标矩形」实现成"按配置推出来的第二个基准"（那会让虚拟全屏开时的比例恒为 1.0）。
- **虚拟全屏关**时目标由基准**推出来**（`(0, 0, 基准宽, 基准高)`）⇒ **关档不进比例式、只减偏移**：比例按规定取 **1.0**（短路），**不是**"目标 = 基准 ⇒ 算出来 1.0" —— 按类型 0 / 1 的算式，目标 = 基准时给的是 `1 + 2 × 偏移 ÷ 基准`，偏移 ≠ 0 就不等于 1.0。⛔ 不许在这里另算一次比例（那会给"关"引入一个由偏移决定的虚假缩放）。
- 偏移在**渲染器的一个开关非 0 时按 0 算**：⛔ 不许把这个开关与「整段禁用换算」那个开关合并（前者只把偏移归零，后者整段原样输出）；那对偏移是**两个分量各自**的（横用横、纵用纵），⛔ 不许共用一个。
- **输入可用标志的清 0 路径是确定的**（空闲计时器到期 / 进入菜单循环 / 一条窗口消息）：⇒ 哨兵分支在**脚本侧可构造**，不是"只有启动那一次观察"。

**可证伪**

- 缩放 1、偏移 0、虚拟全屏关：写出的坐标必须**等于**平台给的客户区坐标（不做任何取整位移）。
- **（前提：虚拟全屏开 且 平台报的客户区与配置不同）**类型 2 与类型 1 在偏移非 0 必须给出**不同**结果（先减后乘 vs 先乘后减）；两者相同 ⇒ 减法的位置写错。★ 关档不比这一条：那一档根本不进比例式。
- **负坐标 + 比例恰为 1.0**（虚拟全屏开、目标 = 基准、偏移 0）：写 −3 ⇒ 输出必须**仍是 −3**；若得到 −2 ⇒ 乘法没被跳过（`trunc(−3 + 0.5) = −2`）。★ 这是**黑盒**判据（负坐标让"跳不跳乘法"可观察）；**（白盒插桩）**另可看执行路径：白盒观测到乘法照做 ⇒ 短路没实现。
- 同一个客户区点分别经 `0x109` 与 `0x2fc`：虚拟屏坐标**必须相同**；不同 ⇒ 两条查询用了两套换算。
- 输入可用标志为 0 时若仍向平台查询、只写一个操作数、或写的值不是 −100000 ⇒ 本条错。
- 窗口存在、光标在客户区外时若写 −100000 而不是真实坐标（可为负 / 超界）⇒ 本条错。
- **虚拟全屏关**、把**配置的客户区宽**改成另一个值（例如 800）：换算结果必须**完全不变**（这一档**不进比例式**、目标与基准一起变、只减偏移）；结果变了 ⇒ 把「目标」与「基准」取成了同一个量，或"关"那一档漏了"目标由基准推出"，或误按比例式算了一次（那会让偏移进到结果里）。
- **虚拟全屏开**、让平台报的客户区尺寸与配置尺寸不同 ⇒ 比例必须**不等于** 1.0（乘法那一步必须真的发生）；仍等于 1.0 ⇒ 目标尺寸取错（取了配置而不是平台报的客户区）。
- 把渲染器那个开关置非 0 ⇒ **只**把偏移按 (0, 0) 算（其余照旧）；若整段不再换算 ⇒ 把"偏移归零"实现成了"禁用换算"。同一个客户区点在"偏移被归零"与"偏移本来就是 0"两种状态下 ⇒ 结果必须**逐位相同**。

### 读鼠标按钮位图（opcode 0x108）

<!-- rule: CORE-INPUT-MOUSE-BUTTON -->

`0x108` 有一个操作数：**按钮位图**。

- 输入可用标志非 0 ⇒ 向平台查询当前按下的鼠标按钮；为 0 ⇒ **不向平台查询**，直接写 0。
- 位图用**引擎位 0 与位 1** 表示两个按钮；**位 2 及更高位恒为 0** —— 引擎只查左 / 右两个按钮，中键 / 侧键**不在引擎的输入面上**（不是"读到但丢弃"）。
- 设 `swap` = 平台「左右键交换」设置（0 = 关）：**左键 ⇒ 位 `swap`**、**右键 ⇒ 位 `1 − swap`**。⇒ 交换关闭时左 0 / 右 1，交换开启时两位互换；位号恒落在 `{0, 1}`。`swap` 的来源是**平台设置**（不是本引擎的配置键），本版不规定它何时改变。
- 推进格数 = 3；不改门位、**不切换当前帧（帧号不变）**、不写其它脚本变量。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前按下的鼠标按钮 | 第 1 个操作数（引擎位 0 / 位 1；左右交换设置决定左 / 右各占哪一位） |
| 位 2 及更高位 | 恒 0（中键 / 侧键不在引擎输入面上） |
| 输入可用标志为 0 | 不查询；第 1 个操作数 ← 0 |

**成立条件**

- **位 2 及以上恒为 0**：⛔ 不许把平台自己的按钮掩码整段抄进引擎位图（那会让中键 / 侧键点亮高位）。
- **平台报告的是逻辑左 / 右键，不是引擎位图**：引擎按交换设置把它们归约到固定的两位；⛔ 不许把平台自己的掩码位号直接当引擎位号（那会让右键落到别的位）。
- **不可用时整字写 0**（不是"保持上一次的值"）；这条**不**返回「这一帧新按下的键」，只返回当前状态位图；边沿判定由脚本自己做（脚本保存上一次的位图）。

### 主循环模式字（opcode 0x24e）

<!-- rule: CORE-INPUT-MODE-WORD -->

`0x24e` 有一个操作数：把它原样写进引擎的**主循环模式字**。

- ★ 这个字**就是**「场景对象表的清空」里那个**场景级状态位字**，也是「场景计时窗」的等待谓词里清的那个字 —— **同一格、三个名字**（⛔ 不许实现成两三格）。`0x24e` 是它**唯一的整字写者**；两处条件清 0（清理入口 / 等待谓词）都只看第 16 位、都清**同一个整字**（见「场景计时窗」与「场景对象表的清空」）。
- 推进格数 = 3；不改门位、**不切换当前帧（帧号不变）**、不写其它脚本变量。
- 模式字的**位 0** 被等待服务读取：**位 0 = 1 ⇒ 等待服务不把「点击」当作跳过**；位 0 = 0 时点击可以放行。**完整放行路径**（配置门、第 4 位的消费、清哪一位、取消哪个场景）的合同在「等待、影片与空操作」的「输入跳过」那一条（本节不复述，⛔ 不许在这里另立一套）。
- 模式字的**第 0 / 1 / 2 / 16 位另有读者**（第 0 位：语音压低的进入条件，见「执行与时间」的「一次迭代做哪些事」；第 1 位：**揭示支的门**，见「ADV 文本层」的「消息块开始 / 结束」—— 它与场景绘制模式一同构成揭示支的两道前置；第 2 / 16 位：见「场景计时窗」）；**其余位**（位 0 / 1 / 2 / 16 之外）在可获得的证据里**没有读者** ⇒ 写多少都不影响行为。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 模式字第 0 位 | 被等待服务读取（= 1 ⇒ **不做点击跳过**；放行路径见「等待、影片与空操作」的「输入跳过」）、也是语音压低的进入条件之一 |
| 模式字第 2 / 16 位 | 都被「场景计时窗」读取：第 2 位让带「不参与场景动画」位的绘制项照常吃「强制完成」，第 16 位在谓词没有窗内副作用时把整个字清 0（「场景对象表的清空」对**同一格**做同一条第 16 位判据） |
| 位 0 / 1 / 2 / 16 之外的位 | **无读者**：写多少都不影响任何行为 |

**成立条件**

- 这条只写模式字，不采样输入、不消费输入事件、不清等待位；写入是**整字覆盖** ⇒ 上一次的位不会残留。
- 位 0 的**取向**（= 1 ⇒ 不跳过）是合同；它的**服务实现**（放行路径）不属于本章义务，见「执行与时间」。
- ⛔ 不许为位 0 / 1 / 2 / 16 之外的位发明消费者：它们写入后没有任何读者，写多少都不改变行为。

**可证伪**

- 只写位 7（值 `0x80`）再跑一遍所有输入 / 等待路径：行为必须与写 0 **完全一致**（没有任何读者）。
- 写位 0 = 1 与写 0 各跑一次等待：位 0 = 1 时点击**不得**放行等待、位 0 = 0 时点击**必须**能放行（方向不能反）。
- 写位 1 = 0 与 1：揭示支的门必须随之改变。
- 写整字之后再执行本条写另一个值：旧位必须**全部消失**（整字覆盖，不是按位或）。

### 登记按住派发槽（opcode 0x102）

<!-- rule: CORE-INPUT-102-SLOT -->

`0x102` 有三个操作数：**键编号**、**槽号**、**目标位置**。它把"某个键的某个槽"绑定到脚本里的一个位置，供「按住派发按键回调」查询。

1. 推进格数 ← **7**（= 2 × 3 + 1）。
2. 三个操作数都**读成整型**。
3. **键编号**必须落在 **0 到 31**（含两端）；**槽号**必须落在 **0 到 9**（含两端）。两个检查**各自独立**。
   任一越界 ⇒ 抛**显示消息型异常**，并且**一个槽都不写**（表、模数、掩码、游标都不动）。
4. 通过检查 ⇒ 把**目标位置原样**写进「按住派发表」的对应格：表按**当前帧**分层，每层按**键编号**分组，每组有**固定 10 个槽**，槽号就是组内下标。
5. 本条不改门位、不改输入字、不改键总数、不改模数、不改按住掩码、不改任何游标；**不切换当前帧**。

- **目标位置完全不做检查**：它按位置（32 位字下标）原样存入。**−1 是"未登记"哨兵** ⇒ 写 −1 等于**取消**该槽的登记。
- **键编号的检查与键总数无关**：键总数只约束**派发**时的扫描范围，不约束登记 ⇒ 登记一个编号 ≥ 键总数的键是**允许的**。
- 同一（帧, 键, 槽）重复登记 ⇒ **后一次覆盖前一次**。
- 这张表与「输入回调的登记」里那张**按键回调表**（`0xfb` 写的那张）**不是同一张**：后者每（帧 × 键）只有**一个**目标。两张表在帧被释放 / 重载时都被清成"未登记"。
- 异常消息的文本只提到"第 1 个操作数"，但它**同时**用于槽号越界 ⇒ ⛔ 不许拿消息文本判断是哪个操作数错了。
- 本条**没有返回值**；尾段没有别的动作（不标脏、不建记录、不发请求）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 「某个键的某个槽」绑定到哪段脚本 | 当前帧的按住派发表：每（帧 × 键）10 个槽 ← 目标位置 |
| 某个槽未登记 | 该格 = −1 |
| 越界时 | 抛显示消息型异常；10 个槽全不变 |

**成立条件**

- 键编号 0..31 与槽号 0..9 是**引擎写死的上界**。键编号那一维与键总数**不同源**；槽号那一维与**模数**也不同源。
- 「每（帧 × 键）10 个槽」是**表的形状**：10 是**槽**的个数。⛔ 不许读成"同时最多 10 个键"。
- 两张表互不可见：把回调登记在按键回调表里，`0x104` 不会命中。
- 表是**按帧**的；帧被释放会清掉它（与按键回调表同时清）。
- 越界路径在**写表之前**返回：表内容不变（推进格数已在入口写成 7，它不影响表内容）。

**可证伪**

- 只登记（键 7, 槽 3）⇒ `0x104` 在游标 = 3 时必须命中该目标、在游标 = 4 时必须**不**命中。
- 槽号写 10 ⇒ 必须抛显示消息型异常，且槽 9 仍是原值（若被夹到 9 ⇒ 越界被静默截断）。
- 键编号写 32 ⇒ 必须抛异常；该键的任何槽都不写。
- 在帧 A 登记、切到帧 B 派发 ⇒ 必然不命中（命中 ⇒ 表不是按帧的）。
- 键总数写 2、登记键 20 ⇒ **不得**抛异常。

### 设置按住游标模数（opcode 0x103）

<!-- rule: CORE-INPUT-103-MODULUS -->

`0x103` 有一个操作数：**模数**。它决定「按住派发按键回调」的游标怎么回绕，并把**当前帧**的游标归零。

1. 推进格数 ← **3**（= 2 × 1 + 1）。
2. 把操作数读成整型，**原样**写进引擎级的**按住游标模数**格。
3. 把**当前帧**的**按住游标**写成 **0**。
4. 本条不改门位、不改输入字、不改键总数、不改按住掩码、不改按住派发表、不改按键扫描游标与按键扫描上限；**不切换当前帧**。

- **本条不做任何范围检查**：0、负数、比槽数大的数都照写、不抛。
- 模数是**引擎级一格**（所有帧共用）；按住游标是**按帧槽号**的（引擎级数组 + 当前帧号索引）⇒ 本条只清**当前帧**的游标，其它帧槽的游标保持原值（帧释放 / 重载也不复位）。
- **模数为 0 时「按住派发按键回调」的游标推进没有定义**。本条**不拦 0** ⇒ 把模数设成 0 是脚本自己制造的未定义行为；规范不提供兜底值。
- **模数与槽数没有强制对应**：槽数是 10，模数可以是任何值。模数大于槽数 ⇒ 游标会越过该（帧, 键）的 10 个槽、落进**相邻键**的槽组（很大时甚至越过整张表 ⇒ 未定义行为）；小于槽数 ⇒ 有一部分槽永远轮不到。
- 模数**没有"默认 10"这种东西**：它的初值是 **0** —— 引擎启动路径与「输入复位」都会把同一格写成 0（启动路径见「输入复位」的机器注记）⇒ 在第一次执行本条之前执行「按住派发按键回调」**必然**在游标推进处撞到除零。
- 本条**没有返回值**、**不标脏**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 按住游标怎么回绕 | 引擎级的模数格 ← 操作数（原样） |
| 下一次从哪个槽开始 | 当前帧的按住游标 ← 0 |
| 其它帧的游标 | 不变（仍受同一个模数回绕） |

**成立条件**

- 模数是**引擎级**、游标是**按帧**的：⛔ 不许把模数做成按帧，也不许把游标做成引擎级。
- 游标归零**只针对当前帧**。
- 模数 0 ⇒ **未定义行为**，⛔ 不许实现成"模数 0 就不过滤"或"用某个默认值兜底"并把它写进合同。
- **取余是向零截断余数**：`r = d − trunc(d / m) × m`，**符号随被除数**（与目标机的 `idiv` 一致，存回之前没有任何修正指令）。
  有定义时游标恒非负（`0` 或某个余数）⇒ **负模数与它的绝对值逐点不可区分**（`−7` 与 `7` 给出同一串槽号；`−1` ⇒ 槽号恒 0）。
  ⛔ 不要实现成“数学取模再调整到 `[0, |m|)`”：`5` 对 `−7` 引擎给 5、数学取模给 −2。
- 本条**不建立**初始模数：它只**写**。谁写的 0 见「输入复位」。

**可证伪**

- 模数写 7、连续执行 **7** 次「按住派发按键回调」（每次都让槽查不到）⇒ 游标必须回到 0。
- 在帧 A 设模数并清游标、切到帧 B ⇒ 帧 B 的游标必须**不变**。
- 模数写 0 时本条**不抛**；随后执行「按住派发按键回调」必须**响亮失败**。
- 执行本条前后，按住掩码、两张回调表、按键扫描上限必须逐一不变。

### 设置按住掩码（opcode 0x105）

<!-- rule: CORE-INPUT-105-MASK -->

`0x105` 有一个操作数：**按住掩码**。

1. 推进格数 ← **3**。
2. 把操作数读成整型，**原样**写进引擎级的**按住掩码**格。**不做范围检查、不归一**。
3. 本条不改任何其它引擎数据；**不切换当前帧**；**没有返回值**；**不标脏**。

- 掩码是 **32 位位集**：**第 i 位 = 编号 i 的键**（与输入字同一套编号）。
- 它是**引擎级**的（不是按帧的）：帧释放 / 重载**不清**它；「输入复位」也**不清**它。
- 初值是 **0** ⇒ 在第一次执行本条之前，「按住派发按键回调」的返回点永远是"下一条"、也不会夹上限。
- 唯一读者是「按住派发按键回调」：它用"该键号那一位置起"决定**返回点**与**是否把按键扫描上限夹到该键号**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 哪些键在派发时算"按住"（⇒ 重派发 + 夹上限） | 引擎级按住掩码的第 i 位 |
| 掩码之外 | 本版不规定（位集是 32 位，位号与输入字同一套） |

**成立条件**

- 掩码**不是**输入字：⛔ 不许用它代替输入字来判"哪个键被按住"——它只影响**返回点**与**夹上限**。
- 掩码**不是**按帧的。
- 掩码的位号与键编号同源；⛔ 不许把它解释成"槽号位图"。
- 置 0 只是让那个键**不再**重派发 / 不再夹上限，不是"取消登记"。

**可证伪**

- 掩码写 0 ⇒ 任何已登记的键被派发后，回调返回必须落到**下一条**，且按键扫描上限**不变**。
- 掩码只置第 3 位；先按住 7 派发（返回**下一条**），再**松开 7、只按住 3** 并再执行一次 ⇒ 返回点必须是**本条自身**且上限已被夹到 3。
- 掩码写全 1 照写、不抛、不截；写第 31 位也不抛。
- 写掩码前后输入字**逐位不变**。

### 按住派发按键回调（opcode 0x104）

<!-- rule: CORE-OPS-INPUT-104 -->

`0x104` 没有操作数。它按**输入字**、**当前帧的按键扫描上限**与**按住掩码**，把一个"按住的"键交给已登记的槽。

设 `limit` = 当前帧的**按键扫描上限**，`word` = **输入字**，`cursor` = 当前帧的**按住游标**，`mask` = **按住掩码**，`modulus` = **按住游标模数**。

1. 推进格数 ← **1**（缺省只前进一条）。
2. **反向找编号**：从 `limit − 1` 递减到 0，取**第一个**在 `word` 里置起的编号；`limit ≤ 0` 时**不扫描**。找不到（或没扫描）⇒ 编号 = **键总数**（"无按键"编号）。
3. **上下文闸**：这次的编号与"上一次决定游标上下文的编号"**不等** ⇒ 先把**当前帧**的按住游标清 **0**；然后把这次编号写进去。
4. **压返回点、返回栈顶 + 1**。返回点由 `mask` 决定，但**只在找到键时**：
   - 找到键、且 `mask` 里该键号那一位置起 ⇒ 返回点 = **本条指令自身**，并把 `limit` **夹到该键号**；
   - 其余情况 ⇒ 返回点 = **本条指令之后的那一格**。
5. **查表**：编号与 `cursor` 一起定位一个表项（每（帧 × 编号）10 个槽，`cursor` 就是槽号）。
   - **已登记** ⇒ 执行位置 ← 该表项的位置，推进格数 ← **0**；
   - **未登记** ⇒ **撤销**刚压的返回点（返回栈顶 −1），推进格数留在 **1**。
6. **每条出口都推进游标**：`cursor ← (cursor + 1) mod modulus`。跳与不跳、登记与未登记，全都推进。

- 本条**不改**输入字、状态选择字、存档字、入块深度、键总数、掩码、模数、两张回调表；**不切换当前帧**；**没有返回值**。
- 本条**不产生异常**（除模数为 0 的除零）；不读操作数、不做范围检查。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 这次派发哪个键 | `[0, limit)` 里**最高**的置起编号；`limit ≤ 0` ⇒ "无按键"编号（= 键总数） |
| 下一次从哪开始扫 | 按键扫描上限 ← 找到的编号（**仅**掩码该位置起时；且**不撤销**） |
| 槽位怎么轮转 | 按住游标 ← (游标 + 1) mod 模数（**每条出口**） |
| 回调返回后从哪继续 | 掩码置起 ⇒ 本条自身（重派发下一个更低的键）；否则下一条 |
| 已登记的目标 | 每（帧 × 编号）10 个槽，槽号 = 游标 |
| 未登记 | 只前进一条（不跳过它继续找下一个） |

**成立条件**

**与「派发按键回调」的分工是五处**：

| | `0x100` | `0x104` |
|---|---|---|
| 扫描上界 | **键总数** | **按键扫描上限**（`0xff` 写成的快照；本条还会把它夹下来） |
| 方向 | **正向**：从扫描游标起、递增到上界 | **反向**：从上界 − 1 起、递减到 0 |
| 游标 | 按键扫描游标：**找到时** ← 键号 + 1 | 按住游标：**每条出口** ← (游标 + 1) mod 模数 |
| 表 | 每（帧 × 键）**一个**目标 | 每（帧 × 键）**10 个槽**，游标选槽 |
| 返回点 | 输入字为 0 ⇒ 下一条；按键 ⇒ **本条自身** | **掩码**决定：该位置起且找到键 ⇒ 本条自身 **+ 夹上限**；否则下一条 |

- 两条**共用**同一个输入字、同一套"压返回点 / 返回栈顶 +1"机制、同一个"无按键编号 = 键总数"约定；但**表**与**游标**是两套。
- **掩码只在"找到键"时被判**：无按键路径固定"下一条"。
- **夹取发生在查表之前、且不撤销**：掩码置起的键即使槽**未登记**，该帧的按键扫描上限也**已经**被降到该键号。⛔ 不许把它写成"未登记时连夹取一起回滚"。
- **夹取只会降低**：找到的键号必然 `< limit`；把上限写回键总数的只有 `0xff`。
- ★ **没跑过 `0xff` 的帧上，本条没有合同**：按键扫描上限没有引擎建立的初值（构造不写那一片、分配不清零、`0xfc` / 帧装载 / 重置都不碰）⇒ 第一次 `0xff` 之前它是**未定义的残留值**，`limit` 可能大到扫不完、也可能 ≤ 0。"扫到哪个键"因此**不可判** ⇒ 这是**未定义路径**：实现必须选一个**显式的、会响的**处置（例如拒绝该次派发 / 记诊断），⛔ 不许把它当成"上限 = 0"或"上限 = 键总数"来兜底（见残差 `RES-INPUT-104-LIMIT-INIT`）。
- **反向取最高位**：同时按住多个键时先派发**编号最高**的那个。
- 游标推进**无条件**、且**没有不推进的出口**。
- **`modulus = 0` 时"游标推进"没有定义**：目标机上表现为**整数除零**，它属于宿主的结构化异常（引擎的保护区分支可忽略、也可据此结束启动 —— 见「异常的处置」）。规范**不给**兜底值；实现必须选一个**显式的、会响的**诊断，⛔ 不得把"按 0 处理"或某个默认模数写成合同。
- **按住游标没有引擎建立的初值**：启动链的 memset 覆盖到模数格之前就停了，游标数组没人清；它只被 `0x103`（清当前帧）、**上下文闸**（清当前帧）与本条（推进）写。
  但上下文闸的静态格初值是 **−1**（不等于任何合法编号）⇒ **进程里第一次 `0x104` 必然把当前帧的游标写成 0**。
  残值只在“该帧槽从启动起从没被 `0x104` 写过 + 本次编号恰等于静态格”时可达；先按再设模数只会先撞除零，看不到这个残值。
- 游标按**帧槽号**存（引擎级数组 + 当前帧号索引），**帧释放 / 重载不复位** ⇒ 重载后看到的是**定义值**（陈旧但已定义），不是未定义行为。
- **键总数 = 0 的边界**："无按键"编号与**键 0** 重合 ⇒ 键 0 的槽会被当成"无按键"表项派发。

**可证伪**

- 只用「登记按键回调」(`0xfb`) 登记过键 7 ⇒ `0x104` 必须**不**命中那个目标。
- 同时按住编号 3 与 7、上限 = 8 ⇒ 必须先派发 **7**。
- 上限 = 0、键总数 = 5、输入字里键 2 置起 ⇒ 必须走"无按键"编号（= 5）、只前进一条。
- 同一帧连续两次 `0x104`（两次都不命中）⇒ 两次的游标必须不同（按模数回绕）。
- `mask` 未置起的键 ⇒ 回调返回后**不得**重跑本条；置起 ⇒ 必须重跑，且上限已降到该键号。
- 掩码置起的键、其槽**未登记** ⇒ 执行完之后上限必须**已经**等于该键号。
- 目标只登记在槽 5、游标停在 0 ⇒ 不得命中。
- 模数 = 0 时执行 ⇒ 必须**响亮失败**。

### 输入复位（opcode 0xfc）

<!-- rule: CORE-INPUT-RESET-FC -->

`0xfc` 没有操作数。

1. 推进格数 ← **1**。
2. 把**两张回调表**（按键回调表与按住派发表）**全部**清成「未登记」（−1）。
3. 把**按住游标模数**写成 **0**。

- 本条**不**碰：输入字、门位、键总数、按住掩码、任何游标、按键扫描上限；**不切换当前帧**；**没有返回值**。
- ⇒ 执行过本条之后，必须重新执行 `0x103` 才能安全执行 `0x104`（模数为 0 = 除零）。
- ⛔ 不许漏掉"把模数写成 0"：只清两张表会留下"表空但模数仍是旧值"，与引擎不同。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 两张回调表被清空 | 每（帧 × 键）的目标 / 10 个槽 ← 未登记（−1） |
| 按住游标的回绕口径被作废 | 模数 ← 0 |

**成立条件**

- 它清的是**整张**两张表（所有帧），不是"当前帧"。
- 模数写成 0 是**有意的复位**：它让"没重新设模数就用"变成响亮的除零。
- **机器注记**：引擎**启动路径**也调用同一复位本体（把两张表写成 −1、模数写成 0）⇒ "初值 0"不是只靠脚本的 `0xfc`。
- 掩码**不**被清（引擎启动时另有一处把它写成 0）。

**可证伪**

- 先设模数 7、登记一个槽，再执行 `0xfc` ⇒ 模数必须是 **0**、两张表必须全"未登记"。
- `0xfc` 之后按住掩码必须**仍是原值**。

### 读滚轮增量并清零：opcode 0x10d

<!-- rule: CORE-INPUT-WHEEL-READ -->

引擎有一个**滚轮增量累加格**：引擎自己的窗口过程在收到滚轮消息时，把该消息的增量（可正可负）**累加**进去 —— 这是引擎代码，不是宿主代劳；增量到值的映射（刻度与符号）由平台消息给出。

`0x10d` 有一个操作数（落点）。它把累加格的当前值写进落点，并**在写落点之前**把累加格清零。

- 本条**不读**操作数的旧值：落点只写。
- 无早退、不报错、不做范围检查，没有返回值。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 自上次读取以来累计的滚轮增量 | 引擎的滚轮增量累加格 |
| 读出的增量 | 第 1 个操作数 |

**成立条件**

- **先清零、后写落点**：落点写入若因类型不符而抛操作数类型异常，累加格**已经**被清零 —— 这一支可观察，⛔ 不许交换这两步的顺序。
- 本条**不查**输入可用标志：它的结果只取决于累加格。
- 每次滚轮事件只被读到一次：没有新事件时再执行本条得 0。
- 本规则只规定"读出并清零"：一次滚轮消息加多少、符号怎么映射属于滚轮消息的输入口径（见残差）。

**可证伪**

- 先累加两次（例如 +120 与 −40）再执行 `0x10d` ⇒ 落点必须是 **80**；紧接着再执行一次 ⇒ 必须是 **0**。
- 让落点是一个不可写的操作数（类型不符）再执行 `0x10d` ⇒ 必须抛操作数类型异常，且**随后**一次 `0x10d` 读到的必须是 **0**（说明清零发生在写落点之前）。

### 等玩家推进：opcode 0x72

<!-- rule: CORE-OPS-MSG-WAIT-INPUT-72 -->

`0x72` 有一个操作数 = **消息槽**（0 = 默认槽），推进格数 = **3**。

- **起播（跳过位未置）时**把"等推进"位置起（门字第 31 位置起；第 30 位**若尚未置**也一并置起）⇒ **整字门关着**，正常派发停止，直到
  输入或"跳过"位放行；放行后从**下一条**继续（推进格数早已按 3 算过）。★ **跳过位（第 27 位）已置时整段不做**：第 31 位**不置**、第 30 位也不动（不是"无条件置起"）。
  ★ 本条之所以"等"，是因为第 31 位的服务体把控制交回迭代头 —— 派发要等它放行；门忙时另有两条派发路径（扫到表尾 / 第 29 位服务体），其中第 29 位只在**文本槽在用标志 ≠ 0**（例如演示闸层开着）时派发一条、标志 = 0（普通打字）则本迭代零派发，见「门：整字为 0 直接派发；非 0 先扫服务链，扫完仍派发一条」。
- **输入是事件锁存，不是电平**：一次"按下"只放行一次；按住不放**不会**让后续的 `0x72` 连续放行
  （引擎把按下位或进输入字、消费者读一次就清）。⛔ 按电平每帧读会让 ADV 长按连发。
- 本条**不靠"把推进格数改回 0"**阻塞；也不 `or` 门字的其它位。
- 第 30 位 = **逐格揭示活动中**（不是乱数启用）：本条在起播（跳过位未置）时与第 31 位成对置起，但它属于正文另一条
  动画（见 `CORE-OPS-TEXT-CELL-REVEAL-1CE`），本条只借用这次置位。
- **本条也写那条动画的三格**（对象 = **当前文本槽**）：
  - **跳过位未置时**：向文本子系统取一次**格数**（作为出参写进格数格）—— 它是对**当时**那个槽取的快照，之后槽变了也不重取。
  - **仅当第 30 位未置**：把它置起 **+** 当前格号清 0 **+** 节拍器相位重置（相位起点 ← 当前毫秒、节拍计数归 1；节拍长度**不变**）。
    第 30 位**已置**时这三件**一起跳过**（本条只置第 31 位）。
  - 第 30 位未置 ⇒ 三件都做；**已置时三件一起跳过**。★ 门忙时也会派发（扫到表尾），所以「已置」不只出现在打字期间 —— 在揭示动画进行中派发到本条时同样会跳过这三件。
  ⇒ 借用共享活动位的结果是：**等待期间主循环的服务支每 500 毫秒补画一格**（500 毫秒是节拍长度的初值，
  可被别的脚本指令改写；格数取自上面那份快照）。
  ⛔ 不许把本条写成"只置门位、不碰格数 / 格号 / 相位"，也不⛔ 许把三件的条件写成"无条件"。
- 起播消息（把消息槽记成当前层、按"从头"起播）发生在置位之前（**跳过位未置时**才做）。
- 起播（跳过位未置）时做一次**事件并入**（并入挂起事件 + 摇杆边沿轮询一次；它**消费**这些事件，⛔ 不是电平采样），随后把**输入字整字清 0**（丢弃）；消费者读一次就清。
- **残差** `RES-MSG-WAIT-72-LAYOUT`（unknown）：起播支里还有一次布局计算与一次子系统调用（在清输入字之后、置位之前），本版未写它们的效果；下一步：核这两次调用的入参 / 出参与当前文本槽的关系。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前消息槽 | ← 第 1 个操作数（**跳过位未置时**；已置时整段不做） |
| 等推进 | 门字第 31 位（+ 第 30 位）置起（**跳过位未置时**）⇒ 正常派发停止；第 29 位命中且**文本槽在用标志 ≠ 0**（例如演示闸层开着）时仍由它派发，标志 = 0（普通打字）则本迭代零派发（见「门」） |
| 放行 | 输入到达 ⇒ 先清第 31 位，再经共享清理清第 30 位 |

**成立条件**

- 等待期间第 31 位拦住派发（它的服务体交回迭代头）；放行前本迭代不派发。门忙时派发的两条路径见「门：整字为 0 直接派发；非 0 先扫服务链，扫完仍派发一条」。
- 放行**不改执行位置**：下一条就是 0x72 之后的那一条。
- ⛔ 不许把它实现成"跳过 / 立即放行"：那样 ADV 会一次性跑完。

**可证伪**

- 执行后（打字不在进行中）：下一拍必须**零派发**；仍派发 ⇒ 门没关。
- 注入一次左键：位必须清、并从下一条继续；不清 ⇒ 放行条件错。
- **按住不放**跨过两条 `0x72`：只许放行第一条；第二条必须等"松开再按"才放行。
  第二条也被同一次按下放行 ⇒ 输入被当成了电平。
- 事件锁存的另一面：同一个按下**不许**放行两次（一次按下最多服务一次等待）。
- **格数快照跟着槽走**：第 30 位已置（打字进行中）时，再执行一次 `0x72`、但操作数换成一个**格数不同**的文本槽：下一拍服务必须用**新槽**取到的格数画格（画格序列的长度随之改变）；仍按旧槽的格数 ⇒ 把「跳过位未置时取格数」写成了「只在第 30 位未置时取一次」。

### 光标瞬移：opcode 0x10a

<!-- rule: CORE-OPS-INPUT-SET-CURSOR-10A -->

`0x10a` 有两个操作数 = **虚拟屏坐标**的 x / y，推进格数 = **5**。

- 引擎用当前的窗口 / 显示适配参数把虚拟屏坐标换算成客户区 / 屏幕坐标，再请求平台把光标移到**换算后**的坐标。
- 换算公式（窗口句柄、缩放、客户区到屏幕）本版不规定（残差 `RES-INPUT-SET-CURSOR-SCALE`）；引擎侧不保存请求之外的状态。
- 平台调用返回值**不检查** ⇒ 失败静默；不阻塞、不置门位。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 一次把光标移到某处的请求 | 平台请求（参数 = 换算后的屏幕坐标）；引擎数据不变 |

**可证伪**

- 在缩放 1 / 窗口原点 0 且无虚拟全屏的档下：请求坐标必须等于那两个操作数；不等于 ⇒ 换算或坐标系错。
- 换一个缩放档：请求坐标必须随缩放变化；不随 ⇒ 没做换算（本版只规定"有换算"，具体公式见残差）。

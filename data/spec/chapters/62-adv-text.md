## ADV 文本层

本章回答：脚本怎样把**文本**放进一张离屏画布、画布怎样出现在场景里。它写的是「列表项与子系统写入」那一章所用**同一张层记录表（十个层槽位共用）**的另一个用途视图：那边写的是记录里的通用字段（以及 `0x70` 的其它效果），本章规定这些字段在**文本层**这一用途下的领域行为。两章是同一机器记录的两个视图，不互相覆盖。本章把 `0x70` / `0x79` / `0x213` 写的那条记录叫**层记录**（与列表章的列表项记录是同一张）；正文 / 振り仮名在画布上只以像素与字符格体现，本章不另立字符串实体。

> 本版只规定**引擎侧**的请求与状态（哪块画布、画到哪、什么时候清空 / 被消费）。字形位图、字体度量与逐像素混合属平台边界；逐位表现不进本章。

### 文本层：矩形、原点、清空与画布（opcodes 0x70 / 0x71 / 0x79 / 0x213）

<!-- rule: ADV-TEXT-LAYER -->

文本层共 **10 个槽位**（层号 0..9）。层号 **0 不是第 0 层**，而是「用默认层」（= 列表章的默认组，同一个选择子）：默认层的初值由引擎建立（初值 1），`0x80` 可改写；`0x70` / `0x71` / `0x79` / `0x6e` / `0x6f` / `0x196` 在第一个操作数为 0 时都落到它。**`0x213` 不在此列**：它把第一个操作数当**直接索引**（0 就是槽位 0），不换成默认层。

**`0x70`（五个操作数）**：第 1 个是层号，第 2 / 3 个是宽 / 高，第 4 / 5 个是左 / 上。读序是 **5 → 4 → 3 → 2 → 1**。它把层矩形写进该层记录；随后（**仅当场景绘制模式 = 1**，见下）引擎为该层建立（或按新尺寸重建）**一张离屏画布**：画布编号 = **20 + 有效层号**，尺寸 = 宽、高**各自 × 显示适配比后取整**（显示适配比见「转发到字体对象与宿主接口的入口」的「显示适配比」：字体对象上一对 视口 ÷ 配置客户区，横分量对宽、纵分量对高；⛔ 不是场景章「显示适配」的缩放对 `s`。★ 绘制项**自身位置**的缩放另见「纹理族」的 `[20, 30)` 条（那里用场景 `s`）；两比的关系见残差 `RES-ADV-TEXT-CANVAS-SCALE`。取整是**向零截断**：× 适配比后 + 0.5 再向零截断；适配比为 1.0 时就是层宽 / 层高）。重建会换掉像素缓冲；**重建本身不等价于一次显式清零**（新缓冲的内容是否为零由平台决定），清空只由 `0x71` 做。

★ 层记录的**左 / 上**两格还有一个**只搬位置**的写者：`0x198`（见 `60-ops-forward` 的「移动文本层」）。它写的就是本条的第 4 / 5 个操作数那两格；⛔ 不要为它另建一对"偏移"格 —— **回退位置**（没有对齐平移时）由**层左 / 上 + 布局字符格左上**给出；有对齐平移时还要加上该行的 Δ（见「文本绘制项的位置：逐行对齐与显示适配」）。

`0x70` 还写同一记录的其它字段、追加定位记录并置登记标记；**这些效果见「设置一个列表项：opcode 0x70」**（列表登记的内部行为就写在那一条里）。

建 / 重建纹理画布**只在场景绘制模式 = 1 时发生**。场景绘制模式的**初值取自配置 `set:DrawMode`**；运行期由脚本 `0x200` 用**它自己的操作数**覆盖，覆盖后一直生效，直到下一次复位时重新按配置写入（见「执行与时间」）。⛔ 不许实现成"每次绘制都重读配置"（配置只在初始化 / 复位时读入）；也⛔ 不许把**初值**烧死 —— **复位之后必须按（可能已被玩家改过的）配置值重设这一格**，配置改了、复位过就要生效。

层记录的**宽 / 高**与**"缩放后尺寸"那两格**的写序是合同的一部分：`0x70` 先把层宽 / 层高写进记录，并**无条件**把同一对值也写进"缩放后尺寸"两格，**随后**才按场景绘制模式分岔 —— 纹理画布路径再把这两格**覆写成缩放后的值**；旧路径不覆写 ⇒ **旧路径下这两格 = 未缩放的层宽 / 层高**（⛔ 不是"不写 / 保留旧值"）。

场景绘制模式 ≠ 1 ⇒ 引擎按**同一层矩形**配置一张**旧式精灵表面**、**不建纹理画布**。旧式精灵表面是**引擎另一张对象表里的对象**，只与画布**共用编号 `20 + 有效层号`**：编号相同不等于同一个对象 —— 配置它既**不建、不改纹理槽**，也不占用脚本纹理（`0x1f8`）那一槽；反过来，脚本给 `20 + i` 建纹理、或 `0x70` 重建画布，也不会改那张精灵表面。

★ **「精灵基色」是什么**：它是**绘制对象自己持有的一个 32 位颜色格**（不是层记录的格、也不是纹理记录的格），**不是常量**：

- **初值 0**：绘制对象**构造 / 复位时被显式写成 0**（不是"未初始化"）。
- **唯一运行期写者（触发与取值都在域内）**：引擎**建立 / 重建渲染表面**时（图形设备初始化、以及显示模式切换时的重建都会走这一步），按该表面的**像素格式**写这一格 —— 写进去的是该格式的**绿色通道满值**（32 位真彩下 = 纯绿 `0x00FF00`；后缓冲格式 = 适配器显示模式的格式，见「图形设备初始化」的「设备创建请求的实参」）。⇒ 它**不是**脚本 / 配置能设置的颜色：**没有任何指令写它**，也没有第二个写点；除「表面格式被重新确定」之外它不变。同一次写入还会派生出几个位段宽度字节（那是像素格式账，与本条无关）。
- **读**：旧路径**只读**它，当两件事的**同一个值** —— 新表面的**颜色键**（低 32 位 = 高 32 位 = 该值）、清空时的**整张填充色**（见下三条）。建表面与清空都**不写**它。
- ⇒ 实现必须真的把它实现成一格可存 32 位颜色的状态，且它的值**跟着像素格式走**（不是编译期常量：16 位与 32 位表面的绿色满值不是同一个位模式），⛔ 不许把"颜色键"与"填充色"拆成两个可独立配置的值、也⛔ 不许把它烧死成一个固定颜色。

★★ **旧路径的正面行为（场景绘制模式 ≠ 1 时的文本层）**：它不是纹理画布，而是一张**旧式精灵表面** —— **另一张对象表里的另一个对象**，只与画布**共用编号 `20 + 有效层号`**。本版规定它三条引擎侧行为：

1. **建 / 重建**：「设层矩形」为该层建立（或按新尺寸重建）这张表面，尺寸 = **未缩放**的层宽 / 层高（不乘显示适配比），并给它设一个**颜色键**，取值 = 绘制对象的「精灵基色」格；
2. **清空**：「请求文本层」把这张表面**整张填成「精灵基色」**（矩形 = 整张表面），**不**做逐像素显式清零、不建 / 不删表面；
3. **贴字**：正文按揭示游标逐字**贴到这张表面**上（位置 = 层左 / 上 + 布局字符格左上），**不读**绘制键基数 / 数量、**不建**逐字绘制条目。

★ 只剩一项是范围项：**这张表面怎样进入场景**（谁在什么绘制阶段把它画到屏幕）—— 本版不规定；位块传送的像素结果进明确舍弃。
旧路径的**否定面**仍然成立：不建纹理画布、不建逐字绘制条目、不读键基数 / 数量、不碰纹理槽。⛔ 不许把"不建纹理画布 / 不建条目"读成"旧路径照常显示"（那是两句不同的话），也⛔ 不许把纹理路径的"清成全透明"搬到旧路径上（旧路径的清空是**填充基色**，不是清零）。

**`0x79`（三个操作数）**：第 1 个是层号，第 2 / 3 个是**文本绘制原点**的 x / y（层内坐标）。读序是 **3 → 2 → 1**。它只改原点，**不建画布、不清内容**。

**`0x213`（三个操作数）**：第 1 个是层号（直接索引），第 2 / 3 个是**该层绘制键区间的基数与数量**。读序是 **3 → 2 → 1**。记录不存在时**不写该层记录**（不建记录、不改键基数 / 数量那两格）；★ 但它在**读到操作数之前**就把**当前帧的推进格数**写成 **7**（= 2 × 3 + 1，即本条自己的 `2 × 操作数个数 + 1`）—— 那一格**不是层记录里的一格**、也**不是层指令共用的标记**：**每个 handler 入口**都往它写**自己**的值（`0x212` 写 5、本条写 7、`0x1f6` 写 1），所以"记录不存在 ⇒ 什么都不发生"是错的：那条判定**不写的是层记录**（推进格数照写，因此操作数类型异常时它已经写好了）。两个格的**初值都是 0**（层记录建立时写 0）⇒「没调用过 `0x213`」与「用 0 / 0 调 `0x213`」是同一状态。

**`0x71`（一个操作数）**：第 1 个是层号（0 = 默认层）。它做四件事：

1. 把**本条指令的位置**（本条相对代码区起点按 32 位字编号的下标）写进**当前帧**的一个字段；
2. 把**文本游标复位到文本原点**（**不分模式**，任何模式都做），并在场景绘制模式 = 1 时把该层画布清成**全透明**（显式写零）；
3. 释放该层在两个键区间内的旧绘制条目：`[键基数, 键基数 + 数量)`（由 `0x213` 写）与另一组由 `0x25d` 写的键区间；
4. 释放旧绘制条目后，画布在下一次绘制路径消费时再次出现：引擎按字符逐个提交，每个字符一个条目，键 = `0x213` 写的**键基数 + 字符序号**，位置 = 层左 / 上 + 该字符的**布局字符格**左上 + 该行的**对齐平移（Δ）**（Δ 见「文本绘制项的位置：逐行对齐与显示适配」；没有 Δ 时就是前两项之和。**条目还受数量门约束**：揭示游标 < 数量才建，见本条「成立条件」）。

上述第 2 项**拆成两半**：**文本游标复位到文本原点**（连同布局字符格序列复位、揭示游标 / 块开头归零）**不分模式、任何模式都做**；**把该层画布清成全透明**只在**场景绘制模式 = 1** 时做（模式 ≠ 1 没有画布可清）。第 3、4 项（按键区间释放旧条目、逐字条目再现）只在**纹理画布路径**（场景绘制模式 = 1）执行；场景绘制模式 ≠ 1 时 `0x71` 只做中间状态复位、走旧路径 —— 没有画布，也没有逐字条目（见「成立条件」）。

`0x71` 还会改该层的定位中间状态（形状 / 读者只写到下面这一层）：
把该层的**布局字符格序列**复位成**一条起点项**（起点 = 该层矩形 / 文本原点）、清空该层的**行记录日志**（合同见下）、
向**列表登记序列**追加一条 `{层号, 条数}`（第二分量的口径见「设置一个列表项：opcode 0x70」的登记段：它是**字体对象的定位记录序列**在写入那一刻的元素条数 —— **两条序列不是同一条**，见下），并把**揭示游标归 0**、另有两格按固定值写（其中一格置 1）。
★ 布局字符格序列的读者就是本节的逐字绘制路径（它按揭示游标取该序列里的格；条目还受**数量门**约束，见本条「成立条件」）；
**行记录日志**的**追加点**是排版侧的两处（正文越界结束、段尾收尾），**读者是绘制**（**两条绘制路径**都读它 —— 哪两条、以及它们与「逐字绘制路径」的区别见下「行记录日志」）。
**列表登记序列**的**追加点**是 `0x70` / `0x71`（每条 `{层号, 条数}`），它与列表章的「列表登记序列」是**同一条**（同样的追加点、同一对游标）；**读者只有列表侧两条路**：① 按当前项发绘制请求（把第一个分量当绘制组号、第二个当**定位记录下标**）；② 按掩码移动读游标（不给量 ⇒ 读游标回到当前写游标；给正量 ⇒ 向后、给负量 ⇒ 向前，逐项跳过掩码命中的记录）。★ 第二分量取长度的**「定位记录序列」不是这条登记序列**：它是**字体对象的**定位记录序列，由「登记一条字体条目」那条脚本指令（`0x1d2`：**文本显示门放行时一条、门非 0 时一条也不加**）与**同一趟排版**的正文 / 语音记录写入（每段一条）共同追加 —— ⛔ 不许把"排版每排一行就多一条"当来源（见列表章的登记段）。⛔ 不许再把它写成"读者未定位"，⛔ 也不许把它与行记录日志、或与上述列表登记序列合成一条。
此外它还有两处整块数据拷贝、一次子系统内调用、一次入口键为「读文本跳过」的调用、以及一次**有条件的**状态位写（置状态选择字第 27 位）；这些见「文本子系统的请求」一节，不属于本条的画布合同。

**行记录日志（合同）**

每个文本层除了布局字符格序列与上面那几格定位中间状态之外，还保有一份**行记录日志**：排版每排定一行的**一截**就往里追加一条，每条记录"这一行的这一截画在哪、写什么"。

一条记录按语义携带（按领域字段列举，⛔ 不按布局）：

- 一个**矩形**（左 / 上 / 右 / 下四个整数）；
- 一个**标志字**：它决定这一条在绘制时被画、被跳过，还是"到此为止"；
- **两串文本**：第一串是这一截要画的文字；第二串抄自层自己的一个字符串状态（**用途本版不规定**，见残差）；
- 一撮从层状态**抄进来**的整数（追加那一刻的值，此后不随层状态变化）；
- 一个**行号**：同一次排版里同一行的所有记录共享它，不同行不同。

**生产者 = 排版**：追加发生在该层**已经写出这一截之后**，所以记录里的矩形与文字就是当时的排版结果，此后不会被后续排版改写。⛔ 不是"每行只留最后一条"：同一行可以有多条（换行边界、下划线、振り仮名都各占一条）。

**消费者 = 绘制**。读这条日志的是**两条绘制路径**（同一次「把该层重画一遍」里的两条遍历），按**记录自己标志字的第 2 位**分岔。★ **三处的判据分开写**：**两条绘制侧**读的是**记录自己的标志字**（记录已经存在，位就在记录上）；**追加侧**判的是**它收到的标志参数**的第 2 位（那一刻记录还没写出来）。两处读的是**同一位**，但**不是同一个对象**——⛔ 不许把追加侧写成本条记录自己的标志字（那是循环），也⛔ 不许因此认定"标志参数就是绘制模式"（那一步未取证，见 `RES-OPS-TEXT-SPAN-FLAG-1`）。置起 ⇒ 走「把段记录逐条变成绘制请求、再逐字符推进」的那条；未置起 ⇒ 走另一条（读同一序列的矩形、行跨度与第一串）。⛔ 不许只挂在其中一条上，也⛔ 不许写成"层的一格非 0"—— 它**不是**一格：它是**每条记录各自**的标志位。★ 这两条**都不是**本节的**逐字绘制路径** —— 那条读的是**布局字符格序列**（按揭示游标取格、按数量门建逐字条目），与这条日志是两条不同的序列。也⛔ 别把这里的"两条"读成「纹理画布路径 / 旧式精灵表面路径」那一对：那一对分的是**画到哪张表面**（见「文本层：矩形、原点、清空与画布」），不是"谁在读这条日志"。读法固定为：

1. 按**追加顺序**逐条走过整个日志；
2. 标志字的「**到此为止**」位置起 ⇒ **这一条与它之后的记录都不画**，本层的这一趟遍历就此结束（其它层不受影响）；
3. 标志字的「**跳过**」位置起 ⇒ 这一条不画，**其余条照旧**（含它后面那一条）；
4. 标志字的「**看下一条**」位置起 ⇒ 这一条**也不画**；并且，若它不是**最后一条**、而下一条记录标志字的**第 0 位（新段起点）**置起，则整趟遍历就此结束（后面的也不画）；否则只是跳过这一条、继续往后走（位号与位义见下「标志字的位表」）；
5. 要画的条目：用它的**矩形**与**第一串文本**发起绘制请求，并按字符逐个推进；
6. 同一「行号」的条目还要**归组**：按行号取该组条目的外接框，算该行的**对齐平移（Δ）**；模式 0 / 1 / 2 / 其它取值、两条公式、跳过掩码、两个种子与显示适配的细则见「文本绘制项的位置：逐行对齐与显示适配」。⛔ 不要把这一步写成"跨度减一再折半"——机器是 `trunc(跨度 ÷ 2)`。

**判定顺序是合同**：逐条判标志字时按「**到此为止**」→「**看下一条**」→「**跳过**」的次序判；同一条同时置起多位时按这个次序出结果（⛔ 不许换序，否则「到此为止 + 跳过」与「到此为止 + 看下一条」会给出不同结果）。

| **0** | **新段起点**：只在**下一条**记录上被测；置起 ⇒ 当前这一串到此为止 | 本条**不读自己这一位** |
| **1** | **到此为止**：这一条与它之后的条都不画 | |
| 2 | **变体选择**（暂用名）：置起 ⇒ 这一条走"用另一支字体"的变体（= 这一条走**逐字支**）；**两条绘制侧**按它分岔（读的是**记录自己的**标志字） | 追加侧另注：**同一位、另一个对象**（判的是它收到的标志参数；排版侧也按这一位换一支字体对象 —— 见本节「消费者 = 绘制」）；同时被"算行跨度"那种辅助读法的**跳过掩码**连带命中；⛔ 不许给它编 A / B 哪一支的名字 |
| 3 | **无领域义**：只被"算行跨度"那种辅助读法的**跳过掩码**连带命中 | ⛔ 不许给这一位编领域名 |
| 29 | **看下一条**：本条不画，再按下一条的位 0 决定是否结束 | 依赖后一条 |
| 30 | **跳过**：本条不画，其余照旧 | |

- ★ **读取侧不把低两位当模式，这是合同**：位 0 只作"新段起点"、位 1 只作"到此为止"。**写入侧**只把**当时收到的标志参数**原样写进记录；那个参数**是不是**绘制模式**未取证**（见残差 `RES-OPS-TEXT-SPAN-FLAG-1`）⇒ 所以⛔ 不许把"低两位 = 绘制模式"写成**任何一侧**的合同，也⛔ 不许反过来把位 0 / 位 1 写成模式位（那会让"下一条是否新段起点"变成"下一条是不是奇数模式"）。
- ★ **位 2 有两个读取者、两个对象**：**两条绘制侧**读**记录自己的**标志字（记录已经存在）；**追加侧**判的是**它收到的标志参数**的第 2 位（那一刻记录还没写出来）⇒ **同一位、另一个对象**，⛔ 不许把追加侧写成读记录自己的标志字（那是循环；见本节「消费者 = 绘制」的「三处的判据分开写」）。
- ★ **另一条序列有另一张位表**：字体对象上那条**文本记录**的标志字（位 0 = 新段起点、位 1 = 与操作数位 0 联合的跳过判据、位 2 = 用另一支字号、位 3 = 占位、位 29 = 续段、位 30 = 语音记录）见「字符串」的「画一段已排版的文本记录」条。⛔ 两条序列的标志字不许互借位义、也不许合成一张表。

**清空**：层复位时整条日志被销毁（连同它的容量），并把层上一个"已登记"格归 0。

**行记录日志的成立条件**

- 追加 / 清空 / 读取三者**互不重叠**：排版只追加，复位只清空，绘制只读。
- 日志是**逐条累积**的，不是"每行只留最后一条"（见上）。
- 日志**不进存档**：它与「按槽位编号 / 按平面编号的两张持久表」是两回事（⛔ 不许合并成一条）。
- 判决依赖**遍历次序**：第 2 / 3 / 4 三条都按追加顺序生效 ⇒ ⛔ 不许实现成"先过滤再排序"。第 4 条还依赖**后一条**的记录 ⇒ ⛔ 不许实现成"只看本条"。

**三条记录序列的身份（⛔ 不许合并；本表只在这里列一次，别处只指向本表）**

文本输出这条路上有**三条互不相同**的记录序列，名字都带"记录"，但字段与用途都不同（前两条逐条定长、第三条的"文本"是变长的）：

| 序列（本版的叫法） | 归属 | 定长？ | 串数 | 行号 | 生产者 | 消费者 |
|---|---|---|---|---|---|---|
| **行记录日志**（本节的「段记录」） | 文本层 | **定长** | **两串**（第一串 = 要画的这一截；第二串抄自层状态、用途未定） | **有**：追加时从层状态抄入；同一次排版里同一行的所有条共享它 | 排版（每排定一行的一截追加一条） | **绘制**（两条绘制路径都读；按记录标志字第 2 位分岔的两条遍历，见本节「行记录日志」） |
| **文本记录**（全串记录） | 字体对象 | 定长区 + **一条变长文本串**（无固定上限；另有一段对齐填充，**不是字段**） | **一串** | **无** | 正文追加 / 语音追加 / 「登记一条字体条目」 | **画一段已排版的文本记录**那条指令 |
| **布局字符格序列**（旧称「行记录」；`N` 取自它的条数） | 文本层 | **定长** | **无串** | **—**：每条带一个**分组键**（绘制期按它归组算行跨度；对齐按它归组，见「文本绘制项的位置：逐行对齐与显示适配」），这个键的领域义未取证 | 复位时一条**起点项**；排版每排出一个**字符格**追加一条 | **逐字绘制**（按揭示游标取格，同一序列）+ **只被数条数**（自动消息时长算式里的 `N`） |

★ 三者的可靠区分**不是名字**（都带"记录"），而是**串数**与**行号**：两串 + 有行号 ⇒ 行记录日志；一串 + 无行号 ⇒ 文本记录；无串 + 只有分组键 ⇒ 布局字符格序列。
★ `N`（自动消息的时长算式）取的是**布局字符格序列**的**条数**（复位后恰为 1 条起点项，此后每排出一个字符格 +1）；算式里那个 `−1` 是**算式自带**的（条数 − 1），不是任何一条记录里的字段。⛔ **不是行数**：行结束只把层的行计数 +1，**不**往这条序列里追加（见「文本层的正文追加与行结束」的 `0x6f` 条）⇒ 别用"行数"去回答 `N`；`−1` 是否恰好抵消那条起点项（起点项是否也占一条）见残差 `RES-AUTO-MSG-LINE-RECORD`。
★ ⛔ 不许拿一条序列的"条数"去回答另一条的问题（例：用行记录日志的条数当 `N`、或用文本记录的条数当字符格数）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某层的矩形 | 该层记录的左 / 上两格 ← `0x70` 的第 4 / 5 个值，**或** `0x198` 的第 2 / 3 个值（同一个落点）；宽 / 高两格 ← `0x70` 的第 2 / 3 个值，另有一份宽 / 高拷贝由 `0x1c1` 写（见「写列表项的一对字段」） |
| 某层的离屏画布 | 纹理槽 `20 + 有效层号`（只在场景绘制模式 = 1 时建立）；尺寸 = 宽、高各自 × 显示适配比后向零截断（见本条 `0x70` 的算式）；**纹理路径**另把缩放后的尺寸写回该层记录的一对格（旧路径下那两格保持未缩放的层宽 / 层高）；内容由 `0x71` 显式清零 |
| 某层的旧式精灵表面（场景绘制模式 ≠ 1） | **另一张对象表**里按 `20 + 有效层号` 索引的槽（与纹理槽不是同一张表）；尺寸 = **未缩放**的层宽 / 高；颜色键 ← 绘制对象的「精灵基色」格 |
| 那张表面被清空 | 整张表面 ← 「精灵基色」（不透明填充，**不是**全透明像素） |
| 该层正文落在旧路径上 | 逐字贴在精灵表面上的字形像素；位置 = 层左 / 上 + 布局字符格左上；**不建**绘制条目 |
| 某层的文本绘制原点 | 该层记录的一对坐标格 ← `0x79` 的第 2 / 3 个操作数 |
| 某层的绘制键区间 | 该层记录的一对格 ← `0x213` 的第 2 / 3 个操作数（直接索引，不换默认层）；初值都是 0 |
| 层的文本排版被复位（任何模式） | 文本游标 ← 文本原点；布局字符格序列 ← 一条起点项；揭示游标 ← 0 |
| 某层的行记录日志 | 该层记录上的一段**逐条累积的定长元素序列**（字段表见上「三条记录序列的身份」：矩形 + 标志字 + 两串 + 一撮从层状态抄来的整数 + 行号）；按追加序读；复位时整条销毁（连同容量），层上一个"已登记"格 ← 0 |
| 某一行的对齐平移（Δ） | 见「文本绘制项的位置：逐行对齐与显示适配」；只供绘制期用，**不写回**记录 |
| 层的画布被清空（仅场景绘制模式 = 1） | 画布所有像素 ← 全透明 |
| 层出现在场景里 | 该层画布被消费：每个字符一个条目，位置 = **层左 / 上 + 布局字符格左上 + 该行的对齐平移（Δ）**（Δ 见「文本绘制项的位置：逐行对齐与显示适配」；没有 Δ 时就是层左 / 上 + 布局格左上），键 = 键基数 + 字符序号，源 = 布局字符格 × 字体缩放（**数量门见「成立条件」**：揭示游标 < 数量才建条目） |
| 画布是否可见（仅场景绘制模式 = 1） | 只有「揭示游标 < 键数量」时才建逐字条目；键数量 = 0 ⇒ 一条都不建（画布不可见）。场景绘制模式 ≠ 1 时这条判据不参与：旧路径不读键基数 / 数量 |

**成立条件**

- `0x71` 的**位置写的是本条**指令的位置，不是下一条；这一格与「换脚本」写的调用点位置是同一帧记录里**相邻但不同**的两个字段，⛔ 不许共用。
- `0x71` 是**唯一**显式清空画布的指令；就画布这一面，`0x79` 只改原点、`0x213` 只改键、`0x70` 只改矩形与尺寸（重建是否得到零像素由平台决定）。
- `0x71` **不建、不删**画布：画布由 `0x70` 建 / 重建；`0x71` 只清内容并让消费从键基数重新开始。
- 画布编号只由**有效层号**决定（`20 + 有效层号`）。层号（经 `0x80` 解析后的有效层号）越界属未定义行为；本版不规定引擎的越界后果。`0x213` 直接索引时同理。
- 宽或高不大于 0 时引擎仍按给定尺寸请求建画布（0 × 0 也照样请求）；0 尺寸画布的消费后果属平台（本版不规定）。
- `0x213` 的记录不存在 ⇒ **不写层记录**（但仍会在读操作数之前把**当前帧的推进格数**写成 7，见上）；`0x71` / `0x70` 在层记录不存在时引擎**不检查**（直接解引用，未定义行为；本版不规定后果）。
- 绘制键决定该层在场景里的先后（与其它绘制请求同一套键序，见「绘制项的消费者」）。引擎按字符逐个提交：键 = 键基数 + 字符序号，源矩形 = 该字符的布局字符格 × 字体缩放（缩放为 1.0 时就是布局字符格）；本版按此规定。字符序号是**自上次 `0x71` 以来该层已提交的条目序号**（含振り仮名条目）。
- `0x213` 没写过键基数时（键基数 0、数量 0）**纹理画布路径上**画布不可见：逐字绘制条目只在**揭示游标 < 键数量**时创建；数量 = 0 ⇒ 一条都不建（画布纹理仍在槽里，但没有任何绘制条目引用它）。数量 > 0 时条目键从键基数起按字符序号递增；键与其它绘制项共用同一张表，**同键后写覆盖**。★ 这道门**只在场景绘制模式 = 1** 的路径上；模式 ≠ 1 时该层走旧路径、**不读**键基数 / 数量 ⇒「没调过 `0x213`」在那条路径上不会让该层不可见。
- **绘制键基数 / 数量的写者是 `0x213`**：这两格在层记录建立时写 0，此后只由 `0x213` 改写（层记录被整体拷贝时原样搬运，不产生新值）。
- 纹理画布路径**只在场景绘制模式 = 1 时**启用；场景绘制模式 ≠ 1 时启用**旧路径**（`0x70` 建与 `0x71` 清两处按**同一格**分岔：= 1 走画布，≠ 1 走旧路径）。旧路径的**正面行为**见上「旧式精灵表面」那三条；只剩"那张表面怎样进入场景"是范围项。
- **旧路径的成立条件**（与纹理路径相反的两处，⛔ 不许互相借用）：
  - 颜色键与清空填充色是**同一格**（精灵基色）；⛔ 不许实现成两个可独立配置的值。
  - 表面尺寸用**未缩放**的层宽 / 层高；纹理路径把"缩放后尺寸"两格覆写成缩放值，旧路径**保持**层宽 / 层高（是"不覆写"，不是"不写 / 保留旧值"）。
  - 表面的编号与纹理画布相同，但**不是同一个对象**：配置它既不建、不改纹理槽，也不占用脚本纹理那一槽；反过来，脚本给同编号建纹理也不改这张表面。
  - 旧路径**没有数量门**：即使一次都没调用过「设绘制键区间」，正文照样贴到表面上 ⇒ 该层在旧路径上**不会**因为"键数量 = 0"而不可见（不可见性由别的机制决定，本版不规定）。
  - 旧路径**没有**逐字绘制条目 ⇒ ⛔ 不许出现"键 = 键基数 + 字符序号"的条目。
  - 清空是**填充**，不是清零：⛔ 不许把纹理路径的"清成全透明"搬到旧路径上。
- 本条**不规定**画布在平台上的像素格式、混合与采样缩放；只规定「哪张画布、多大、画到哪、什么时候清空 / 被消费」。

**可证伪**

- **场景绘制模式 = 1** 时设层矩形（宽 / 高 > 0）后调 `0x71`：若纹理槽 `20 + 有效层号` 不存在、尺寸不等于「宽、高各自 × 适配比后向零截断（见本条 `0x70` 的算式）」、或画布不是全透明 ⇒ 本条错（★ 这一条**带模式前提**：模式 ≠ 1 时**不该**有这张画布，它出现反而是分岔错）。
- 先 `0x79` 设原点再调 `0x71`：若文本游标没有复位到原点 ⇒ 本条错（**场景绘制模式 = 0 时同样成立** —— 这一项不分模式）。
- 场景绘制模式 = 1 时先写正文再调 `0x71`：若画布仍有像素 ⇒ 本条错。
- 改 `0x213` 的键基数后再调 `0x71`：若绘制键仍从旧基数起 ⇒ 本条错（场景绘制模式 = 1）。
- 用层号 0 调 `0x70` / `0x71` / `0x79` / `0x6e` / `0x6f` / `0x196`：若落到的不是默认层 ⇒ 本条错。
- 用层号 0 调 `0x213`：若落到默认层而不是槽位 0 ⇒ 本条错。
- **场景绘制模式 = 1** 时不调 `0x213`、设正尺寸层矩形后调 `0x71` 再写正文：若出现任何逐字条目 ⇒ 键数量门错（初值不是 0 / 条目不看数量）。★ 同一条脚本在**场景绘制模式 ≠ 1** 下**不经过**这道门，判据是**绘制项表**而不是屏幕：模式 ≠ 1 时该层**不得**出现"键 = 键基数 + 字符序号"的逐字条目（旧路径不建条目、不读键基数 / 数量）。旧路径的字形去向见「旧式精灵表面」第 3 条（逐字贴到那张表面上），只剩"那张表面怎样进入场景"不在本版 ⇒ ⛔ 不许拿"屏幕上看得到 / 看不到字"当这条的判据。若模式 ≠ 1 下仍按数量门决定建不建条目 ⇒ 把模式 1 的门用到了旧路径上。
- 把场景绘制模式设成 0 再调 `0x70`：若**纹理槽**（脚本纹理 / 画布那一张表）`20 + 有效层号` 被建 / 被改 ⇒ 后端分岔错（旧式精灵表面是**另一张表**里的对象，只共用编号，配置它不算"改纹理槽"）。同一脚本还必须让**旧式精灵表面**被建出来、且它的**颜色键 = 精灵基色**；两者都不动 ⇒ 岔没接上。
- 场景绘制模式 = 0 时分别在 16 位与 32 位表面各走一次「设层矩形」→「请求文本层」：两次被填满的值必须分别是各自像素格式的**绿色通道满值**（不是同一个固定颜色、也不是 0）；两次填出同一个位模式 ⇒ 把基色实现成了常量，填成 0 ⇒ 把初值当成了运行值。
- 新建立的绘制对象、在引擎还没按像素格式写过这一格时读「精灵基色」：必须**恰为 0**（构造期显式写 0）；非 0 ⇒ 初值那条错。
- 场景绘制模式 = 0 时设非 1 的显示适配比再「设层矩形」：表面尺寸必须等于**未缩放**的层宽 / 高；等于缩放后的值 ⇒ 用了纹理路径的算式。
- 场景绘制模式 = 0 时不调「设绘制键区间」、只「请求文本层」再写正文：那张表面上必须出现字形；一个都不贴 ⇒ 把数量门用到了旧路径上。
- 场景绘制模式 = 0 时先给编号 `20 + i` 建脚本纹理、再调 `0x70`：脚本纹理必须**原样留在**那一槽（旧路径不碰纹理表）。
- 场景绘制模式 = 1 时脚本先给编号 `20 + i` 建纹理、再由 `0x70` 建同层画布：若槽里仍是脚本纹理 ⇒ 撞号合同错（画布不是独立对象）。
- 把配置 `set:DrawMode` 设成 0 启动（并让 `set:CreateObject` 的对应位已置，否则 `0x200` 整条不生效）、再由脚本 `0x200` 用 1 覆盖，然后调 `0x70`：必须走纹理画布（模式被覆盖了）；若仍走旧路径 ⇒ 把"运行期覆盖"写成了"只读初值"。再触发一次复位后调 `0x70`：必须回到配置值 0（走旧路径）；仍是 1 ⇒ 复位没有重读配置。
- **行记录日志**：排一段跨两行的文字后，日志条数必须**大于 2**（每行至少一条，且行号只取两种值）；恰好等于行数 ⇒ 把"每行一条"实现成了硬约束。
- 把某一条的「**跳过**」位置起：该条**不产生**绘制请求，其余条不受影响；整行都不画 ⇒ 把"跳过一条"写成了"跳过一行"。
- 把某一条的「**到此为止**」位置起：**它自己与它之后**的条目不产生绘制请求，它之前的照旧，**其它层照旧**；它自己照画 ⇒ 位义反了；其它层也被截断 ⇒ 把"一层的遍历"写成了全局。
- 把某一条的「**看下一条**」位置起（该条须不是最后一条）：该条不画；再把**下一条**标志字的**第 0 位（新段起点）**置起 ⇒ **之后的条目不画**；只把这一条置起、下一条的位 0 留空 ⇒ **只有这一条不画**。两种情形结果相同 ⇒ 没有读下一条的标志字。
- 把「看下一条」位置在**最后一条**上：遍历必须正常结束（不得读不存在的下一条）；若越界读了 ⇒ 少了"最后一条"这条判据。
- 把一条的**右界改到超出该组当前极值** +Δ（且超出文本原点）⇒ 该行跨度必须 +Δ、「对齐模式 1」的 Δ 必须 −Δ/2；不变 ⇒ 行号归组或跨度算式错。
- 只改一条的**行号**把它并进相邻组、而它的矩形落在该组既有极值内 ⇒ 跨度**不必**变（两个种子会把极值兜住）；把它当成"必须变大"⇒ 判据错。
- 绘制请求里的**文字**必须来自该条的**第一串**：把第一串改成别的串，请求里的文字必须跟着变；不变（还是第二串）⇒ 两串取反了。

**残差**

- `RES-ADV-TEXT-LAYER-STATE`（unknown）：行记录日志的**读侧已逐字取证并写进正文** —— 三条分岔（到此为止 / 看下一条 / 跳过）、标志字位表（位 0 = 新段起点、位 1 = 到此为止、**位 2 = 变体选择**、位 29 = 续段、位 30 = 跳过）、遍历次序与行跨度合成都已定；**两条绘制路径与追加侧按同一位（第 2 位）分岔**这一点也已定（它**不是**"层的一格"，而是**每条记录各自的**标志位）。仍未定的是两段（性质不同，不合并）：① **位 29 / 30 的写者可达性**：标志字是**参数**而非字面常量（抽样 3 个追加调用点，第 1 个实参取自一条排版记录的字段或调用者的寄存器）⇒ 先前"9 个调用点都不构造这两位（只扫字面常量）"**不是结论**，要沿这个参数回溯到排版记录的生产者；② 记录携带的**第二串文本**的领域义 —— 读点为零（整块拷贝的写路径存在），实现可以根本不存，但领域名仍缺。★ 第 2 位缺的是**哪一支字体**（"用另一支字体"已定）；**「变体选择」只是暂用名**；⛔ 不许按另一条序列的位表借名。

### 文本绘制项的位置：逐行对齐与显示适配

<!-- rule: ADV-TEXT-DRAW-POSITION -->

文本层的绘制项**不在排版期定最终位置**：排版期写下的布局字符格 / 段记录只给出**自己的位置**；绘制期再按层记录的「对齐模式 / 基准坐标」算一个**平移（Δ）**，叠在该位置之上，最后按显示适配比换算成屏幕坐标。

**对齐对**：层记录上有一对整数「对齐模式 / 基准坐标」（由 `0x303` 写，见「写一对字段（记录必须已存在）：opcode 0x303」）。同一对格被**三条记录序列**的读者使用，各按自己的归组单位：

| 读取的序列 | 归组单位 | 本版规定 |
|---|---|---|
| 行记录日志 | 行号（同一次排版里同一行共享） | 横向 / 纵向各有读者 |
| 布局字符格序列 | 该序列每条的分组键（领域义未取证） | 横向 / 纵向各有读者 |
| 文本记录（全串记录；列表章也叫「定位记录」） | 位 0（新段起点）为界的段 | 横向 / 纵向各有读者 |

**行记录日志的跨度**（★ 下面的掩码 / 种子**只按行记录日志的位义**定；布局字符格与文本记录的参与判据 / 位义不同，见残差 `RES-ADV-TEXT-DRAW-GROUP`）：取该组内**参与**条目（标志字命中跳过掩码 `0x6000000E`（位 1 / 2 / 3 / 29 / 30）的条目**不参与**）的矩形，按下面的**种子**初始化后取最小左 / 最大右（横向）或最小上 / 最大下（纵向）：

- 横向：最小值的初值 = 层记录的**宽拷贝**；最大值的初值 = 层记录的**文本原点 x**；
- 纵向：最小值的初值 = 层记录的**高拷贝**；最大值的初值 = 层记录的**文本原点 y**；
- 组内没有参与条目 ⇒ 本条**不产生 Δ**；条目**照常画**（掩码只把它们排除出跨度，⛔ 不是不画）。⛔ 不许拿初值差算一个 Δ 去移动别的组。

**对齐平移（Δ）**：

- 模式 = 1（居中）⇒ Δx = 基准 − trunc((最大x − 最小x) ÷ 2)；Δy = 基准 − trunc((最大y − 最小y) ÷ 2)（**向零截断**）；
- 模式 = 2（靠另一端）⇒ Δx = 基准 − 最大x + 最小x；Δy = 基准 − 最大y + 最小y；
- 模式 = 0 ⇒ **不参与**：没有 Δx / Δy（绘制项保持自己的位置）；
- 其它取值 ⇒ **参与**，但 Δx = Δy = **0**。

★ 行记录日志的 x 读者与 y 读者是**两次调用**，各自只给一个分量（另一个出参写 0）；绘制路径按需取其中一个。

★ Δx / Δy 是**平移**，不是绘制项的绝对坐标：绘制项的位置 = 它自己的位置（层左 / 上 + 该条目的矩形 / 布局格左上）**加上** Δx / Δy；**Δ 加在绘制请求的位置分量上，不改记录矩形（源矩形）、不改画布像素**。⇒ 文本绘制侧的一行中心 = 层左 + 该组的**最小左（起点）** + 基准；列表侧的布局计算输出的是**绝对左边界**（= 基准 − 半宽），同一对格在两侧是**两种应用**（文本侧平移、列表侧绝对），⛔ 不许混。⛔ 不许把 Δ 实现成"把中心设成基准"。

**显示适配**：文本绘制站的 Δx / Δy 各按方向乘**字体对象的显示适配比**（横分量对宽、纵分量对高；= 视口 ÷ 配置客户区，见「转发到字体对象与宿主接口的入口」的「显示适配比」），再加 **0.5** 后向零截断。绘制项的**位置分量（含 Δ）**由纹理消费站按「纹理族」的 `[20, 30)` 条处理（那里用的是场景章「显示适配」的 `s`）—— **不是同一个比**；两比只在窗口态 / 全屏的特定档下分别可能为 1。⛔ 不许把两个比当成一个；两者不同时画布与位置是否同倍见残差 `RES-ADV-TEXT-CANVAS-SCALE`。

**成立条件**

- 对齐只改**绘制项的位置**；不改布局字符格、不改行记录日志、不改画布像素、不写回层记录。
- 同一组的条目**一起**用这一组的 Δ；不同组**各算各的**（⛔ 不许拿整块的外接框算一个 Δ）。
- 对齐模式 / 基准坐标是**层记录**的两格；字体对象那格的「对位模式」是另一格（`0x2db` 写），⛔ 不许混用。
- 模式 0 的「不参与」是**没有 Δ**；其它取值的「参与且 Δ = 0」是**有 Δ（值为 0）**。⛔ 不许并成一个出口。
- 基准只在模式 1 / 2 被读；模式 0 与其它取值都不读它；基准**没有构造初值**（⛔ 不许假定 0）。
- `0x71` 复位**不清**这一对；对齐设置跨复位存活。
- 读者只读**本层**的记录；⛔ 不许跨层。
- 旧路径（场景绘制模式 ≠ 1）不建逐字绘制项 ⇒ 本条不适用于旧路径。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该层的对齐模式 / 基准坐标 | 层记录上的一对整数（`0x303` 写；**对齐模式初值 0、基准无构造初值**） |
| 某一组的 Δ | 绘制期由该组条目的外接框 + 对齐对算出，不写回 |
| 显示适配比（横 / 纵） | 字体对象上的一对浮点比值（视口 ÷ 配置客户区） |
| 绘制项的位置 | 自身位置（层左 / 上 + 条目矩形 / 布局格左上）+ Δx / Δy；Δ 乘字体适配比 + 0.5 取整，自身位置由纹理消费按 `s` 处理 |

**残差**

- `RES-ADV-TEXT-DRAW-GROUP`（unknown）：布局字符格序列的**分组键**的领域义（是否 = 行号）、它的参与判据 / 矩形读序；文本记录（列表章「定位记录」）的归组单位（位 0 的段边界）与参与判据；三组是否同一件事。下一步：核字符格分组键与文本记录段边界的写者 / 读者，确认三组的关系；确认不了就把三组分开写，⛔ 不借行记录日志的掩码 / 位义。
- `RES-ADV-TEXT-CANVAS-SCALE`（unknown）：画布按**字体比**预缩放、绘制项位置按**场景 s** 消费，两比是否可能同时 ≠ 1、先后顺序与取整是否叠加；以及字形 / 文本游标是否同乘一个比（决定正文只占画布一角还是铺满）。下一步：读正文绘制入口的初始游标与量度、以及纹理消费站的 s，确认两比的关系。

**可证伪**

- 模式 1：把基准 +2 ⇒ 该组绘制项的平移必须 +2（缩放后按比例）；只动 1 或不动 ⇒ 公式错。
- 模式 2：把该组右界 +1（宽 +1）⇒ 平移必须 −1；不动 ⇒「减右界」错。
- 模式 0：该组绘制项必须保持自己的位置（无平移）；出现平移 ⇒ 把「不参与」当成了「基准 0」。
- 其它取值：该组绘制项的平移必须为 0，且**有**结果；回到「不参与」⇒ 并进了模式 0。
- 行心：把基准 +100、层原点 +10 ⇒ 同一行的中心必须 +110（= 原点 + 基准）；只 +100 或只 +10 ⇒ 把 Δ 当成了绝对坐标（或漏了原点）。
- 两组宽度不同、模式 1：两组的中心都必须满足「层左 + 该组起点 + 基准」；只有整块外接框的中心满足 ⇒ 用了整块近似。
- 适配比 ≠ 1（横 1.25 / 纵 0.75）：同一组的 **Δ** 必须按自己方向的比例缩放（绘制项自身位置由纹理消费按 `s` 处理，是另一处）；两向同一个比 ⇒ 分母取错。
- 把 `0x303` 写在层 1、在层 2 上画字：层 2 不受影响。
- `0x71` 后再画：对齐模式 / 基准必须还在（不被复位清掉）。

### 文本层的正文追加与行结束（opcodes 0x6e / 0x196 / 0x6f）

<!-- rule: ADV-TEXT-APPEND -->

三条指令把正文放进文本层（**纹理画布路径 = 场景绘制模式 = 1** 时落进离屏画布；**旧路径 = 模式 ≠ 1** 时逐字贴到该层的旧式精灵表面上，见「文本层：矩形、原点、清空与画布」的旧式精灵表面条 —— ⛔ 两条路径都不是"照常显示"这种含糊说法）：

- `0x6e`（两个操作数）：第 1 个是层号（0 = 默认层），第 2 个是正文。读序是 **2 → 1**。正文为空串 ⇒ 绘制入口返回非成功值，调用方在**写当前文本槽 / 置状态位 / 登记计时之前**返回：不追加、不画、不移动游标。
- `0x196`（三个操作数）：第 1 个是层号（0 = 默认层），第 2 个是主文本，第 3 个是振り仮名。读序是 **3 → 2 → 1**。振り仮名先被截断到**上限 1023 字节**，超长静默丢弃；主文本为空串 ⇒ 整段跳过（振り仮名也不画）。
- `0x6f`（一个操作数）：第 1 个是层号（0 = 默认层），只读它。它结束当前行：文本游标的 x 复位到**文本原点**，y 前进**行距**（三支见下；未缩放且普通模式 = 字号 + 行間隙，缺省 6 + 24 = 30），该层的行计数 +1。它不改画布像素；入口的**文本显示门**（由 `0x1bb` 写；三支行为见该条；作绘制入口第 5 实参：非 0 ⇒ 抑制这一次的绘制）影响文本 run 的登记，该登记的影响本版不规定（见残差 `RES-ADV-TEXT-GATE-REGISTRATION`）；它还被「字符串」章的 `0x1d2` 当**登记守卫**用（见该条）。

正文画进画布的位置是**文本游标**（这句限定在**纹理画布路径**；模式 ≠ 1 时同一套排版仍按文本游标推进，字形逐字贴到该层的旧式精灵表面上 —— 位置 = 层左 / 上 + 布局字符格左上，见上文）；游标在 `0x71` 清空后复位到文本原点（`0x79` 写的 x / y）。★ 画布按适配比预缩放后，字形 / 游标是否同乘一个比见残差 `RES-ADV-TEXT-CANVAS-SCALE`；本版只规定画布尺寸，不把"只放大空白"写成合同。每画一个字符，游标沿 x 前进该字符的**量度宽度**；`0x196` 的振り仮名画在主文本**上方**，用**另一支字号**（`0x197` 写的那一支），**不**推进主文本游标。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 追加的正文 | 画布上从当前游标开始的字形像素；游标按字符量度推进 |
| 追加的振り仮名 | 画布上主文本上方的小字号字形（截断到 1023 字节后绘制） |
| 当前文本游标 | 该层记录里的文本游标：x 随字符量度推进，y 由行结束推进 |
| 行结束 | 游标 x ← 文本原点；游标 y ← y + **行距**（三支见下条；未缩放且模式 0 时 = 字号 + 行間隙）；该层行计数 +1 |
| 折行（超右界） | 该行已排字符格 ← 保持原坐标；游标按「行结束」推进；当前字符从新行行首开始 |
| 空正文 | 无动作（不写上面任何一项） |

**成立条件**

- 层号 0 是「用默认层」，不是第 0 层；默认层由 `0x80` 改写，初值由引擎建立（初值 1）。
- **空正文的早退在写入之前**：绘制入口对空串返回非成功值，调用方随后直接返回 ⇒ 不写当前文本槽、不置状态位、不登记计时。⛔ 不许「先记下再说」。
- `0x196` 的截断按**字节**：上限 1023 字节，超出部分静默丢弃；截断后仍要画主文本。
- 主文本用 **A 支字号**（`0x75` 写的那一格）；振り仮名用 **B 支字号**（`0x197` 写的那一格，`0x197` 同时写十个槽位的高度；见「转发到字体对象与宿主接口的入口」）。⛔ 不许把两支字号互换，也不许把振り仮名画在主文本的同一基线上。
- 颜色 / 绘制模式来自**字体对象**（`0x76` / `0x77` / `0x78`，见「渲染请求边界」的离屏文字条），不是本条的操作数。
- `0x6e` / `0x196` 都**不清空**画布：重复追加是累加，不是替换。清空只由 `0x71` 做。
- **超右界**：右界 = 层记录里**由 `0x70` 初始化、可被 `0x1c1` 覆盖的那份宽拷贝**（层内坐标、未缩放；不是建画布用的宽、不是缩放后的宽）；画布边界 = **建画布用的宽**（未缩放）× 显示适配比后的纹理矩形。**候选 x = 当前游标 x + 该字量度宽**；配置 `set:AutoLineFeed = 1` 且候选 x > 右界 ⇒ 在画下一个字符前折行（x 回文本原点、y 前进**行距**；未缩放且普通模式行距 = 字号 + 行間隙；模式 ≠ 0 / 有缩放见下条三支）；`= 0` ⇒ 不折行，超出部分按画布边界裁掉；其它值本版不规定。
- **行头禁则**：越界判定之后还要查一张**行头禁则表** —— 它是一张**字符串集合**，元素就是该字符的 1~2 字节编码：**命中 ⇒ 这个字符不在这里折行**（留在行末、可以越界，且**不**把前一个字符一起挪下去），未命中 ⇒ 按上面的规则折行。★ 本作的这张表**构造为空、全二进制没有任何写入者**（只有构造 / 析构的清零）⇒ 发行态**恒不命中** ⇒ 折行只看右界与门；因此"折行后的行首出现「。」「、」这类字符"是**正常**行为，不是缺陷。⛔ 不许把它实现成"行首禁则字符一律折行"或"把上一个字符一起挪下去"。
- **没有整行重排**：引擎不做"先量整行再整体摆"的步骤（逐字测量、逐字写坐标）。越界只**提前结束当前行**：**已经排好的字符格保持原坐标**；游标 x 回文本原点、y 前进**行距**（三支见下条）；**当前字符**成为新行的第一个字符 —— 已排好的前缀**不回填、不在新行重排**。
- 行结束的**行距** = **行間隙** + X，X 由字体对象的**行距模式格**决定（三支，判据只看这一格）：
  - **模式 = 0**（普通）⇒ X = **−行距项格**（该格建立时 = −字号，每次设字号都重写）；
  - **模式 = 1（及其它非 0 值）** ⇒ X = **字号格**；
  - **模式 = 2** ⇒ X = **字号格**（与上一支同式，但走单独一条分支）。
  ★ 没有缩放时三支数值相同（行距项格正好 = −字号，缺省 6 + 24 = 30）；**有缩放时模式 0 用的是缩放后的高度、其它模式用未缩放的字号** —— 这是三支唯一可观察的差别（缩放档上这两句的取值口径见残差 `RES-ADV-TEXT-LINE-SCALED`）。
- **收到的标志参数的第 2 位**（置起时；★ 判的是**入参**、不是本条即将写出的记录的标志字 —— 那一刻它还不存在）：追加记录走**逐字支** —— 每个字符一条记录，且**每条记录的"用另一支字体"位被置起**；
  这 N 条记录仍在**同一趟排版**里追加；打字机的"一格"就是其中**一条记录**（一个**字符格**）；
  ★ 它与 `CORE-OPS-TEXT-CELL-REVEAL-1CE` 的「格」（**等长矩形瓦片**）**不是同一个单位** —— 两者的游标、节拍与终止规则都不同；
  行结束则**不走**上面的常规路径，改走另一条入口（它同样读行距模式格，其余语义本版不规定，见残差）。
- 是否折行（而非裁掉）由 `set:AutoLineFeed = 1` 决定；其它值不规定。**对齐**：**正文 run 的排版**只有左对齐 —— 游标从左到右逐字推进、越界只提前结束当前行，**没有**在排版期把整行居中 / 贴右界的回拉（启动期配置里也没有这样的键）。**绘制期**另有一层逐行对齐：层记录的「对齐模式 / 基准坐标」由 `0x303` 写，绘制时按行组把该行平移一段（Δ），它**不改**排版游标、不改布局字符格、不改画布像素，只改绘制项的位置（见「文本绘制项的位置：逐行对齐与显示适配」）。⛔ 不许把两者混成一个（排版期回拉 vs 绘制期平移）。**字距 / 连字**仍不在本版：字距有一条额外间距格与一个"等距模式"格（`RES-ADV-TEXT-APPEND-JUSTIFY`），连字在本二进制里没有独立实现（半角只是切字用的分支，推进量仍取单字量度）。正文超出画布且不折行时按画布边界裁掉。
- **振り仮名的横向定位**（算式已定）：振り仮名被摆进**它自己那一格**（这一格的左 / 右端 = 本条主文本**最后一行**占据的范围），令 **W** = 振り仮名整串的量度宽、**格宽** = 那一格的宽、**n** = 假名数 + 1（= 间隙数，含两端边距；算式 ⌊(字节数 + 3) ÷ 2⌋）、**d** = 格宽 − W：
  - **d > 0** ⇒ **每档步进 = ⌊d ÷ n⌋**：首字 x = 格左 + 步进，此后每个假名在自身量度宽之外再各加一次步进（2 字节字加整份、1 字节字加半份）⇒ 整串**两端各留一份步进**、恰好铺满格宽（两端对齐）；
  - **d ≤ 0** ⇒ 不加步进，整串以格**中心**对齐：首字 x = 格左 − ⌊|d| ÷ 2⌋（左侧可以伸出格）。
  - 纵向 = 格顶 + 行距项（另有一个条件性 +1，条件未查清）。
  ⛔ **不是"按行比例切分"**：按比例只决定"这一行分到几个假名"（见残差），不产生每个假名的 x。★ 格宽由主文本这一行的范围给出；上式的每个量都是机械可读的。
- **逐字符显示（typewriter）**：`0x6e` / `0x196` 在**追加时一次性**写好这一段的全部布局格；文本记录也在**同一趟排版**里追加（不延迟到绘制侧）；**绘制侧每 `message:MessageSpeed` 毫秒推进一格、每帧最多一格**（未到期的帧一格都不画；按键 / 跳过时把剩余格一次抽干）。⛔ 不许实现成"追加时就画全部"，也⛔ 不许实现成"追加时只追加前 N 个字符"。
  ★ 揭示游标存在**该层的层记录**里（渲染侧另有一份缓存）；末格判据 = 游标 ≥ 本层字符格数 − 1；
  **末格只清状态选择字第 29 位，不动第 30 位**（第 30 位属于 `0x1ce` 的瓦片动画）。
  ★ **演示闸层走"重放"支**：若该层的演示闸（`0x300`）开着且参数格（每字间隔毫秒）≠ 0，推进器不按
  "整段只走一遍"收尾，而是逐格揭示 → 整段完停"期限"毫秒 → 清掉该层已排出的绘制条目、揭示游标归 0
  （闸位保持）→ **从第一格重来**，期间**不重新追加**任何文本。参数格 = 0 时该层只**抽干一次**、不重放。
  判据：一段文本 + 开着的闸 + 参数格 ≠ 0，必须出现**≥2 次**"逐格出现 → 停 → 条目全消失 → 从第一格重来"，
  且期间没有新的 `0x6e` / `0x196`；只出现一次 ⇒ 本条错。参数格 = 0 时若仍重放 ⇒ 也错。
  ★ **每一格的字形样式（字号 / 粗细 / 绘制模式 / 主色 / 副色）取"追加那一刻"的值**，不是"推进到它时字体对象的值" —— 引擎在追加时就 SelectObject + 逐字写出，之后的推进只呈现已排好版的格。判据：追加之后、这一格被推进到之前改 `0x75` / `0x2bd` / `0x76` / `0x77`，**已追加的那一段不受影响**，只有此后追加的段用新值；若一个字按新字号 / 新粗细画出、而**字宽仍是追加时量度** ⇒ 本条错。
- 字形量度、基线由平台字体与字体对象决定；本版只规定「主文本用 A 支、振り仮名用 B 支、振り仮名的横向算式、行结束按行距前进」。
- 没有可用画布（没设过正尺寸的层矩形）时，正文仍被读入并尝试绘制，但**不产生像素**（见本条前面的“宽或高不大于 0”条件）。
- 追加**成功**时的**外部写入**分两档（⛔ 不许写成"无论如何都做"）：
  - **当前文本槽 ← 本次的层号**：两档都写（空正文 / 绘制入口返回失败那一支什么都不写）。
  - **仅当** `message:MessageSpeed`（每字间隔毫秒）**≠ 0** 且**状态选择字第 27 位未置**时，才**置起状态选择字第 29 位**
    并**启动文本计时器**（间隔 = 该格、起点 = 现在）。
  - 上述条件不成立（间隔 = 0 或第 27 位已置）⇒ **旁路**：改走"立即追加 + 同帧抽干"的入口
    （不置第 29 位、不建计时器、⛔ 不留待画格）。旁路**不自己置第 27 位**；但在**同一次调用里、门判之前**
    还有一条前置支：若一条子系统查询返回非 0，就**置第 27 位**（并置一个标志格 —— ⛔ 它不是状态选择字的「等消息位」/「等待位」；含义与消费者见残差
    `RES-ADV-TEXT-APPEND-PRE27`），于是本条随后落进旁路；并且在下一次清掉第 27 位之前，**后续追加也走旁路**。
  - 空正文 / 绘制入口返回失败 ⇒ **什么都不写**（三处外部写入都不做）。
- 当前文本槽与状态选择字第 27 / 29 位、计时器属于本条的**外部写入**。第 29 位的服务者是主循环里的一个**文本推进器**
  （普通打字支在本条；演示闸支见「文本槽的演示闸与定时清除」）：它按计时器**每 D 毫秒推进一格、每帧最多一格**
  （未到期的帧一格都不画）；前进键 / 跳过 ⇒ 抽干并**清第 29 位、置第 27 位**；末格画完 ⇒ 清第 29 位。
  抽干 / 末格之后还有一次**收尾**：揭示该层全部格、判与 `0x305` 揭示支相同的**两道前置**（场景绘制模式 = 1、主循环模式字第 1 位未置），
  都满足才把消息等待三格写成 `(1,0,0)`；不满足 ⇒ 一格都不写。
  只要本轮的推进器服务里**有槽进了"参数格 ≠ 0"的闸门支**，第 29 位就保持置起（见「文本槽的演示闸与定时清除」）。
  ⛔ 不许把它实现成"每帧必画一格"，也⛔ 不许把抽干做成"画完但不动门位"。
- **残差**：`RES-ADV-TEXT-APPEND-PRE27` —— 前置支那条"子系统查询"的身份与"等消息"标记的消费者；
  `RES-ADV-TEXT-LINE-SCALED` —— 行距模式 0 在缩放档上的取值口径（行距项格是否含缩放）；
  `RES-ADV-TEXT-APPEND-RUBY` —— 振り仮名"可用宽度"实参的来源与典型取值、以及"每行分到几个假名"的比例切分（两者都已定到站点，但典型值没有运行时采样）；`RES-ADV-TEXT-APPEND-LAYOUT` 见上。
  ★ **逐字符条目的时机与节流已定**（不是残差）：追加时一次性写布局格；绘制侧按每字间隔推进、**每帧最多一格**。**揭示游标初值 = 0**（层记录建立时写 0）、每画一格 +1、到末格后**停在末格**（**无自动回绕**：显式归零来自 `0x71` 与演示闸到期，块结束则把游标回卷到「块开头」而不一定是 0）；**推进器在门的服务链里、渲染步请求在门之前** ⇒ 本帧建出的条目由**下一次**渲染步消费；**抽干按揭示游标从当前格向后逐格**进行（同一层内升序）。

**可证伪**

- 用空串调 `0x6e`：若画布像素变了、游标动了、当前文本槽被写、状态位被置、或登记了计时 ⇒ 本条错。
- 用空主文本调 `0x196`：若当前文本槽被写、状态位被置、或登记了计时 ⇒ 本条错。
- 窄画布 + 长文本（非禁则字符）：`set:AutoLineFeed = 1` 时必须出现第二行（y 前进）；`= 0` 时 y 不得前进；`= 2` 时本版不规定 ⇒ 1/0 反了即本条错。
- 第二行的第一个字符必须从**文本原点**的 x 开始（不是层内 0）；折行阈值用 **`0x1c1` 可覆盖的那份未缩放宽拷贝**（0x70 初始化；适配比 ≠ 1 时不能拿画布边界当阈值）；候选 x **等于**右界时不折行（严格大于才折）。
- `0x1c1` 把宽 / 高拷贝改小后：折行必须更早发生（阈值跟着 `0x1c1` 写的宽走）⇒ 不跟 ⇒ 本条错。
- 禁则：本作的行头禁则表**恒空**，所以"折行后的行首出现「。」「、」这类行头禁则字符"是**正确**行为；若实现让这类字符从不落在行首 ⇒ 本条错（那是把空表当成非空）。
- 对齐：**正文 run 的排版**若把整行居中 / 贴右界（游标或布局字符格被回拉）⇒ 本条错；反之，把 `0x303` 的对齐模式设成 1 / 2 后，绘制项仍完全按「层左 / 上 + 布局格左上」落位、不按行平移 ⇒ 也错（见「文本绘制项的位置：逐行对齐与显示适配」）。
- 整行重排：若同一段文本在 `set:AutoLineFeed = 1` 下的行数与"逐字超界就换行"的结果不同（例如为了凑满行把几个字符整体前移）⇒ 本条错 —— 引擎没有整行重排。

- 用空主文本 + 非空振り仮名调 `0x196`：若画布上出现振り仮名 ⇒ 本条错。

- 给振り仮名传入 1024 字节：若画布上画出的超过 1023 字节（或整段被丢弃）⇒ 本条错。
- 追加两段正文之间不调 `0x71`：若第二段覆盖第一段（而不是接在后面）⇒ 本条错。
- 行结束后：若 x 没有回到文本原点、或 y 没有前进**行距**（三支见正文；未缩放且模式 0 时 = 字号 + 行間隙）⇒ 本条错。

### 文本显示门：opcode 0x1bb

<!-- rule: ADV-TEXT-GATE-1BB -->

`0x1bb` 有一个操作数（门值），三支：

- **0** ⇒ 门 ← **最高位置起**（第 31 位，值 `0x80000000`；"抑制"态）；
- **1** ⇒ 门 ← **0**（"正常显示"态）；
- **其它**（含负数）⇒ 门**不变**（保旧值），只上报一次错误，然后照常返回。

三支都不抛异常、不改变控制流、不写操作数、不发平台请求。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 文本是否显示 | 文本显示门（0 = 正常；第 31 位已置 = 抑制） |

**成立条件**

- 门的取值只有**两个**：0，或"第 31 位已置"。判据可以写成**不等于 0**；按键重画路径按**最高位**判它 —— 因为只有这两值，两种写法等价，⛔ 不许据此把门实现成多值。
- 第三支**不写**门：⛔ 不许实现成"非法值当作 0 / 1 之一"。
- 门的读者有三类：`0x6e` / `0x196` / `0x6f` 把它当绘制入口的第 5 实参（非 0 ⇒ 抑制这一次的绘制）；
  `0x1d2` 拿它当登记守卫（非 0 ⇒ 整条跳过）；另有一条按键重画的路径按最高位读它，其触发条件与效果本版不规定（见残差 `RES-ADV-TEXT-GATE-REGISTRATION`）。
- 门的**初值是 0**（引擎启动初始化写 0）；运行期只有 `0x1bb` 的两支写它（分别写"最高位置起"与 0）；**没有任何复位路径改写它**（输入复位不碰门）。

**可证伪**

- （层存在、画布就绪、正文非空）不执行任何 `0x1bb`、直接 `0x6e` 画文本：必须画出（门 = 0）；若被抑制 ⇒ 初值不是 0（或还有别的写者）。
- 依次执行 `0x1bb 0`、`0x1bb 1`：门必须从"抑制"回到 0；若仍非 0 ⇒ 第二支没写。
- 先 `0x1bb 0`，再 `0x1bb 7`：门必须**仍**是非 0（第三支保旧值）；若变成 0 或 1 ⇒ 第三支写了门。
- `0x1bb 7` 之后：控制流必须继续（不抛、不中止）。

### 選択肢の登録：opcode 0x90

<!-- rule: ADV-CHOICE-ADD-90 -->

`0x90` 有七个操作数，把一个**选项**追加进引擎的**选项表**（与绘制项表、网格表、命令表都不是同一张）。

- 第 1 / 2 个 = 矩形的**左上**（x / y）；第 3 / 4 个 = **宽 / 高** —— 记录里存的是 `(x, y, x+宽, y+高)`。
- 第 5 / 6 / 7 个 = 该选项的三个**脚本入口**（body 内的 32 位字下标；`-1` = 没有）：第 7 个是**决定**时跳去的入口，第 5 / 6 个是光标**进入 / 离开**该矩形时跳去的入口。
- 读序 **1 → 2 → 3 → 1 → 4 → 2 → 7 → 6 → 5**（第 4、第 6 次是**重读**：再读第 1 个算**右边 = x + 宽**、再读第 2 个算**下边 = y + 高**；⛔ 不是又取了两个新操作数，操作数个数仍是 7）；推进格数 = **15**。
- 追加成功 ⇒ 记录里写下矩形、三个入口，并把**选项表级**的「当前帧深度档」单格**覆盖**成当前帧的深度档（**无索引**：每次追加都覆盖，表里只留最后一次）；随后把「选中项下标」置 **-1**、「决定标志」清 **0**、**arm 闸清 0**（下一次开窗会重新算悬停）。
- 追加**不**改变执行位置（控制流顺序前进）：决定 / 进入 / 离开的跳转发生在**消费侧**（见下）。

**容量与失败**

- 选项表的容量是 **100**（不是引擎错误文本里写的 20）。
- 已满（计数 ≥ 100）⇒ 追加**失败**、一个字段都不写，引擎抛**显示消息型异常**（消息体是「選択肢が多すぎます」那一句）；控制流不继续。
- 操作数类型非法 ⇒ 抛操作数类型异常（任一操作数，读序决定抛在哪一条）。

**消费侧（合同）**

- **决定**：若当前选中下标 `i` 在 `[0, 计数)` 内 ⇒ 执行位置 ← `body 起点 + 4 × 第 i 项的「决定入口」`；随后选中下标置 -1、决定标志清 0。选中下标越界 / 为负 ⇒ 什么都不做，继续等。
- **进入 / 离开**：光标移动时按矩形命中算出目标项，取该路径的入口；入口为 `-1` ⇒ 不跳。两条路径用的是**不同**的入口（第 5 / 第 6 个操作数），⛔ 不许合并成一条。
- **同一帧约束**：选项表**只在建表的同一帧里可被消费** —— 消费前引擎把「追加时记下的深度档」与「当前帧的深度档」比较，不等即抛显示消息型异常（消息体「Depth が不正です」）；该比较在**每个**消费入口各发生一次，每帧一次。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 选项表 | 按追加顺序的记录表：矩形四边 + 三个入口；另有**表级**「当前帧深度档」单格（无索引，追加时覆盖） |
| 表满的判据 | 计数 ≥ 100 |
| 决定后的去向 | 执行位置 ← 该项的「决定入口」（字下标） |
| 决定之后的复位 | 选中下标 ← -1、决定标志 ← 0 |

**成立条件**

- 入口是**字下标**，不是字节偏移：`执行位置 = body 起点 + 4 × 入口`。
- 容量门槛是 **100**；引擎自己的错误文本说"最大 20" —— 该文本是**一句共用常量**（两个追加路径的失败支引用同一句），里面的 20 **不参与任何比较** ⇒ 它不是行为判据，本合同只认 100。
- 追加时**不做**任何越界检查（入口越界是未定义行为，本版不规定后果）。
- 三条入口都可以是 `-1`（该路径没有入口）；`-1` 的处置是"不跳、顺序前进"，⛔ 不是"跳到 body 起点前一字"。
- **深度档是表级单格，不是每条记录一份**：追加时**覆盖**选项表上的那一格（**无索引**），所以连续追加只留最后一次的值；⛔ 不要按条目建数组。

**残差**


**可证伪**

- 连续追加 100 条：第 100 条必须成功；第 101 条必须**抛显示消息型异常**且不写任何字段（门槛按 20 实现 ⇒ 本条的 100 条会中途抛）。
- 追加后把「第 7 个操作数」改成别的值再追加一次：执行位置**必须不变**（本条不跳）；执行位置跟着变 ⇒ 把消费侧的跳转写进了追加。
- 追加 `(10, 20, 30, 40, …)`：记录里的矩形必须是 `(10, 20, 40, 60)`；存成 `(10,20,30,40)` ⇒ 宽高没有加。
- 连续追加两条、第二帧的深度档不同：表级「当前帧深度档」必须是**第二次**的值；若每条各留一份（或仍是第一次的值）⇒ 结构写错。
- 决定时选中下标越界：必须什么都不做（不跳、不清选中态）；跳到某项 ⇒ 越界判据错。

### 選択肢の付加整数：opcode 0x97

<!-- rule: ADV-CHOICE-SET-EXTRA-97 -->

`0x97` 有五个操作数：前四个是**矩形**（`x` / `y` / **宽** / **高**，与 `0x90` 同口径：存的是 `x, y, x+宽, y+高`），第五个是**一个整数**。

- 读序 **1 → 2 → 3 → 1 → 4 → 2 → 5**（第 4、第 6 次是**重读**：再读第 1 个算**右边**、再读第 2 个算**下边**，与 `0x90` 同口径；⛔ 不是又取了新操作数，操作数个数仍是 5）；推进格数 = **11**。
- 拿**四条边全等**去**选项表**里找**第一条**命中的项，把它的**附加整数格** ← 第五个操作数。
- **找不到 ⇒ 什么都不做**（不建项、不改任何项、不报错、不中止）。
- 只改**一条**（第一条命中）；同矩形的后续条目**不**被改。
- 不改变执行位置。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某项的附加整数 | 选项表里第一条矩形四边全等的项的附加整数格 ← 第 5 个操作数 |
| 没命中 | 无变化 |

**成立条件**

- 匹配是**四边全等**，不是"包含光标"、也不是"只比左上角"：差一个像素就不命中。
- 匹配**按追加顺序取第一条**：⛔ 不是"改所有同矩形项"。
- 附加整数的初值不是 0，而是 **-1**（`0x90` 追加时写 -1）；这条只覆盖写入后的值。
- 选项表为空 ⇒ 与"找不到"同一支：什么都不做。

**残差**

- `ADV-CHOICE-EXTRA-MEANING`（unknown）：附加整数的领域含义（序号？图编号？状态？）未取证；调用点把它写成 0 / 1 / 2 / 3 / 8 这类小整数。

**可证伪**

- 追加两条同矩形项，对同矩形跑 `0x97`：只有**第一条**的附加整数变；两条都变 ⇒ 取第一条错。
- 追加 `(0,0,10,10)` 后对 `(0,0,10,9)` 跑 `0x97`：必须**什么都不改**；改了 ⇒ 匹配不是四边全等。
- 追加 `(10,20,30,40)` 后对 `(10,20,30,40)` 跑 `0x97`：必须**命中**（两边都按 x+宽 / y+高 算成 `(10,20,40,60)`）；
  对 `(10,20,40,60)` 跑 `0x97`：必须**不命中**（它算成 `(10,20,50,80)`）。命中/不命中反了 ⇒ 边没按 `x+宽 / y+高` 算（没重读第 1 / 第 2 个操作数）。
- 空表跑 `0x97`：必须不抛、不建项；抛或建项 ⇒ 错误。

### 选项窗口：开窗 / 清表 / 等待（opcodes 0x93 / 0x94 / 0x91 / 0x92）

<!-- rule: ADV-CHOICE-WINDOW -->

选项表（`ADV-CHOICE-ADD-90` 建的那张）外面还有一个**窗口状态**：输入总闸、完成闩锁、一次性的 arm 闸、鼠标移动命中开关、上下键步长、悬停下标、兜底跳转目标。这四条只开关这些格；**只有 arm 那一次读平台光标**（取一次光标位置并换算成客户区坐标，用来跑一次命中），不是每帧轮询输入；`0x93` / `0x94` / `0x91` / `0x92` 本体**不读按键 / 鼠标键状态**。

- `0x93`（无操作数，推进 **1**）：先**清表**（条目数 0、选中 -1、步长 0、**兜底跳转目标 -1**、悬停 -1、移动命中开关 0、变更挂起 0 —— 七格），然后**二选一**：
  - 输入总闸 ≠ 0 ⇒ **关掉**它（不置闩锁）；
  - 输入总闸 = 0 ⇒ 置**完成闩锁**。
  ⇒ 同一个脚本片段里"第一次 0x93 = 关窗、第二次 0x93 = 放行等待者"是**正常**的，⛔ 不是幂等清表。
- `0x94`（无操作数，推进 **1**）：置**输入总闸**；做一次 **arm**（arm 闸为 0 ⇒ 置 1 并用**当前光标**跑一次矩形命中，结果写悬停下标）；置移动命中开关；**步长 ← 10000**。
  - 10000 ≥ 条目数 ⇒ 上下键翻页实际被**禁用**（选项窗是纯鼠标）。⛔ 这个 10000 **不是超时**：本族没有任何时间参数。
- `0x91`（一个操作数 = 上下键步长，推进 **3 或 0**）：
  - 闩锁已置 ⇒ 清闩锁、清移动命中开关、**不读操作数**、推进 3；
  - 否则 ⇒ arm 一次、步长 ← 操作数、置移动命中开关，并把**推进格数改回 0**。
- `0x92`（两个操作数：步长、兜底跳转目标，推进 **5 或 0**）：与 `0x91` 同构，多一条：
  - 闩锁判断在**读数之前** ⇒ 闩锁已置时**一个操作数都不读**、兜底目标也**不写**；
  - 读数序 **2 → 1**（先兜底目标，再步长）；未置闩锁时兜底目标 ← 第 2 个操作数、步长 ← 第 1 个，然后同样把推进格数改回 0。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 输入总闸 | `0x94` 置 1 / `0x93` 清 0 |
| 完成闩锁 | `0x93` 的 else 支置 1 / `0x91`·`0x92` 消费时清 0 |
| arm 闸 | 首次开窗置 1（并做一次命中） |
| 上下键步长 | `0x91`·`0x92` 的第 1 个操作数 / `0x94` 写 10000 |
| 兜底跳转目标 | `0x92` 的第 2 个操作数；`0x93` 清表把它复位成 **-1**（⛔ 不跨窗保留） |
| 悬停下标 | arm 时的命中结果（无光标 ⇒ -1） |

**成立条件**

- **推进格数 = 0 是本引擎唯一的阻塞手段**：分派器按格数推进执行位置，0 表示"本拍不前进 ⇒ 下一拍重跑同一条"。`0x91` / `0x92` 的"等待"就是这条机制，⛔ 不许实现成"睡眠 / 轮询 / 改执行位置"。
- 这条机制对**所有**指令成立（长度字恒 = `2 × 操作数个数 + 1`；`0x90` 是 15、`0x97` 是 11、这两条是 3 / 5、无操作数的是 1）——它是"长度字"的**用途**，不是本族专有。
- `0x93` / `0x94` **永远**推进 1（不阻塞）；只有 `0x91` / `0x92` 会阻塞。
- 清表是**七格复位**：条目数 0、选中 -1、步长 0、**兜底跳转目标 -1**、悬停 -1、变更挂起 0、移动命中开关 0；
  ⛔ 不是只把条目数清零，也⛔ **不是**"兜底目标跨窗保留"（清表那一格就是它，写点单独一条）。
- 失败形态：`0x91` 的操作数在**未置闩锁**那一支才被读 ⇒ 类型非法只在那一支抛；`0x92` 同理（两个操作数都不读）。

**残差**

- 选中也是**一次消费**：光标停在某条不动、或按住不放，都不该反复触发；"打开窗口的那一下点击"
  也不该被当成选中（引擎把按下位锁存、读一次清一次）。
- `ADV-CHOICE-ENTER-LEAVE-SEMANTICS`（unknown）：选项表的**进入 / 离开**两个入口（`0x90` 的第 5 / 6 个操作数）
  在帧循环里的触发条件与调用形态未取证 —— 已知消费侧会按"光标进出事件"走一条 call 支，
  但没有真实菜单的运行时 trace 钉死"何时算进入、何时算离开"。
- `ADV-CHOICE-CONSUMER`（unknown）：**消费侧的次序**未取证 —— "点中 ⇒ 换执行位置""光标进出 ⇒ 进入/离开入口""没选就关窗 ⇒ 兜底入口"这三件事在帧循环里相对命令档 / 文本推进 / 输入采样的位置，本版不规定。★ 机制已定：点中那一条时，执行位置 ← 该条的**决定入口**（`jump`，不压返回点），并清表 / 关窗 / 置闩锁。
- `ADV-CHOICE-91-92-UNUSED`（unknown）：`0x91` / `0x92` 在发行数据里**一次都没被调用**（全语料 0 处）⇒ 本条的这两支只有机制证据（写者 / 读者都在，缺一条真实调用序列）。
- `ADV-CHOICE-B-CONTROL`（unknown）：引擎里还有**第二个同形控件**（另一张选项表，带列表滚动），它的建表 / 清表 / 等待是另外几条 opcode；本版不写。

**可证伪**

- 依次 `0x94`、`0x93`：第一次 `0x93` 必须**关输入总闸**且**不置闩锁**；置了闩锁 ⇒ 两支判据反了。
- 再跑一次 `0x93`：必须置闩锁；没置 ⇒ 第二支错。
- 未置闩锁跑 `0x91`：执行位置必须**停在原地**（推进格数 0）；前进了 ⇒ 阻塞没实现。
- 置闩锁后跑 `0x91`（操作数给非法类型）：必须**不抛**且推进 3；抛了 ⇒ 闩锁支读了操作数。
- 置闩锁后跑 `0x92`：兜底目标必须**不变**（闩锁判断在读数之前）；变了 ⇒ 写序错。
- `0x94` 之后步长必须是 10000（不是 0、也不是"上次 0x91 写的值"）。
- 首次 arm（arm 闸为 0）时必须向平台取一次光标位置、并用它跑命中（悬停下标 ← 命中结果）；
  从不取 ⇒ 错（悬停下标只可能是旧值）。
- arm 闸已置时再跑 `0x94` / `0x91` / `0x92`：**不得再取光标、不得覆盖悬停下标**；若每拍都取 ⇒ 把 arm 写成了每帧轮询。
- 先摆一个非 -1 的兜底目标、再跑 `0x93`：兜底目标必须变成 **-1**；仍是旧值 ⇒ 清表漏了那一格
  （症状：上一个选项窗的兜底目标漏到下一个窗，没选就关窗时按旧下标跳转）。

### 消息等待三格：opcode 0x243

<!-- rule: CORE-OPS-MSG-WAIT-243 -->

`0x243` 无操作数，推进格数 = **1**：把三格"消息等待状态"写成 **(1, 0, 0)**（写序 = 这个顺序）。

- 整段被一道位住：该位已置 ⇒ **一格都不写**（不是"写别的值"）。
- 无调用、不置门位、不抛。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 消息等待状态 | 三格 ← (1, 0, 0) |

**成立条件**

- 写序是 (1, 0, 0)：⛔ 与"块结束"那条的 (0, 0, 1) 不是同一顺序。
- 被门位住时是**完全 no-op**，⛔ 不是"部分写"。

**可证伪**

- 门位 = 0、三格预置 7：执行后必须是 (1,0,0)。
- 门位已置：三格必须仍是 7。

### 消息块开始 / 结束：opcode 0x304 / 0x305

<!-- rule: CORE-OPS-MSG-BLOCK-304-305 -->

一对"消息块"括弧，都无操作数、推进格数 = **1**。

**`0x304`（块开始）**

- 把**消息臂位整格写 1**（顺手清掉上一块留下的"本块写过字"位）。
- 取当前消息层（层号 0 ⇒ 默认层），把该层的**揭示游标**存进"块开头"格。

**`0x305`（块结束）**

- 门 = 臂位的**第 0 位** **且** 第 16 位（第 16 位由文本追加指令 `0x6e` / `0x196` 成功追加时置）。未武装 ⇒ **只清臂位**、什么都不做。
- 武装 ⇒ **分叉之前先做两件事**（两支都做）：
  ① 揭示游标**回卷**到"块开头"格；
  ② 读 `message:ReadTextSkip` —— 非 0 且"已读"命中 ⇒ 置门字第 **27** 位（"跳过"）。★ 与文本追加指令 `0x6e` 里那一步是**同一判据、同一格**。
  这两件事都排在**分叉之前**，其中 ② 的结果**直接决定**走哪一支（⛔ 不许把它挪进任一支里）。
- 然后**二选一**：
  - **打字机支**：**每字间隔 ≠ 0**（`message:MessageSpeed`，毫秒）**且** 第 27 位**未置** ⇒ 置**打字位（第 29 位）**、按该间隔**启动文本计时器**、清臂位、返回。
    ★ **不揭示全部、不写消息等待三格** —— 余下的格由**逐帧文本泵**按该间隔一格一格推进（见「文本层的正文追加与行结束」）。
  - **揭示支**：每字间隔 = 0 **或** 第 27 位已置 ⇒ 揭示该层**全部**格（引擎在这里自旋到"该层揭示完"）；随后还有**两道前置**：
    **场景绘制模式 = 1**（这一格的初值取自配置项 `set:DrawMode`；脚本 `0x200` **用它自己的操作数直接覆盖**该格，配置 `set:CreateObject` 只作前置位图 —— 未创建 ⇒ 报错、整条不生效、连格都不写；⛔ 与字体对象那格"绘制模式"、以及配置项 `display:ScreenMode` 的"显示模式缓存"都不是同一格）**且** **主循环模式字（`0x24e` 写的那个字）的第 1 位未置**（与 `0x243` 同一道门）。
    两道都满足 ⇒ 把消息等待三格写成 **A = 1、B = 0、C = 0**（引擎写序是 B、C、A）；任一不满足 ⇒ **一格都不写**。
- 所有出口（未武装 / 打字机支 / 揭示支写了三格 / 揭示支前置不满足）**都清臂位**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 本块已开始 | 臂位 ← 1（第 0 位） |
| 本块写过字 | 臂位第 16 位 ← 1（由 `0x6e` / `0x196` 置） |
| 块首的揭示位置 | "块开头"格 ← 该层揭示游标 |
| 块结束后（打字机支） | 揭示游标 ← 块开头；打字位（第 29 位）← 1；文本计时器 ← 每字间隔；等待三格**不动**；臂位 ← 0 |
| 块结束后（揭示支） | 揭示游标 ← 块开头、该层全部格已揭示；等待三格 ← (1,0,0)（两道前置任一不满足时**不动**）；臂位 ← 0 |

**残差**

- `RES-MSG-BLOCK-READ-HIT`（unknown）：② 的"已读命中"用的是哪张已读表、键是什么、谁写；本版只规定 `message:ReadTextSkip` 非 0 这个必要条件。

**成立条件**

- 两条**不是** `0x300` / `0x301` 的镜像：那一对动的是**演示闸**（三层循环重放），这一对动的是**消息块**状态。
- 臂位是**整格写 1**（`0x304`）⇒ 上一块的第 16 位被清；⛔ 不是 `or`。
- **武装 ≠ 立即整段全出**：武装只说明"这一块结束了"。余下的字**当场**揭示还是交给推进，取决于**每字间隔**与"跳过"位；⛔ 不许把"武装 ⇒ 揭示全部 ⇒ 写三格"写成无条件序列（那会让"一按结束就整段全出"）。打字机支**不碰**等待三格。
- `0x305` 的"揭示全部"是**函数内自旋**（不是把推进格数改回 0）：它返回时推进格数仍是 1，执行位置只前进一次。
- 揭示支的两道前置排在**自旋之后**：先把该层揭示完，再判前置；前置不满足只影响等待三格（揭示照样完成）。⛔ 不许把前置提到揭示之前。
- 打字机支只**启动**推进，收尾不在本条：推进侧的收尾（走完 / 被抽干时同样"揭示全部 + 判同样两道前置 + 写三格"）由主循环的文本泵负责。
- **场景绘制模式**那一格是**引擎级**的（它的读者之一是主循环），⛔ 不要与字体对象的"绘制模式"混成一格。
- 未武装是**静默 no-op**（只有清臂位这一个可观察效果）。

**可证伪**

- 先跑 `0x304` 再跑 `0x305`（中间不追加文本）：`0x305` 必须什么都不做（揭示游标不变），只清臂位。
- 臂位预置 `0x10000` 跑 `0x304`：执行后必须是 **1**；是 `0x10001` ⇒ 用了 `or`。
- 加一个文本块（`0x6e`）再 `0x305`，且**每字间隔 = 0 或"跳过"位已置**：揭示游标必须回到块开头，且该层最终**全部揭示**。
- **打字机支**：把每字间隔设成**非 0**、执行 `0x304` → 追加一段字 → `0x305`：`0x305` 返回时该层**不许**已经全部揭示，等待三格**不许**被写成 (1,0,0)；若两者都发生 ⇒ 漏了打字机支。
- **揭示支的两道前置**：把**场景绘制模式**设成 ≠ 1（由脚本 `0x200` **用它自己的操作数直接覆盖**它；⛔ 不是切换显示模式，也不是重读配置）或把主循环模式字第 1 位置起，再走揭示支：该层仍必须**全部揭示**，但等待三格必须**一格都没被写**；三格变成了 (1,0,0) ⇒ 前置漏了；若该层反而没揭示完 ⇒ 前置被提到了揭示之前。

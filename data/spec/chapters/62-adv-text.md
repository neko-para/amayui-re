## ADV 文本层

本章回答：脚本怎样把**文本**放进一张离屏画布、画布怎样出现在场景里。它写的是「列表项与子系统写入」那一章所用**同一张层记录表（十个层槽位共用）**的另一个用途视图：那边写的是记录里的通用字段（以及 `0x70` 的其它效果），本章规定这些字段在**文本层**这一用途下的领域行为。两章是同一机器记录的两个视图，不互相覆盖。本章把 `0x70` / `0x79` / `0x213` 写的那条记录叫**层记录**（与列表章的列表项记录是同一张）；正文 / 振り仮名在画布上只以像素与字符格体现，本章不另立字符串实体。

> 本版只规定**引擎侧**的请求与状态（哪块画布、画到哪、什么时候清空 / 被消费）。字形位图、字体度量与逐像素混合属平台边界；逐位表现不进本章。

### 文本层：矩形、原点、清空与画布（opcodes 0x70 / 0x71 / 0x79 / 0x213）

<!-- rule: ADV-TEXT-LAYER -->

文本层共 **10 个槽位**（层号 0..9）。层号 **0 不是第 0 层**，而是「用默认层」（= 列表章的默认组，同一个选择子）：默认层的初值由引擎建立（初值 1），`0x80` 可改写；`0x70` / `0x71` / `0x79` / `0x6e` / `0x6f` / `0x196` 在第一个操作数为 0 时都落到它。**`0x213` 不在此列**：它把第一个操作数当**直接索引**（0 就是槽位 0），不换成默认层。

**`0x70`（五个操作数）**：第 1 个是层号，第 2 / 3 个是宽 / 高，第 4 / 5 个是左 / 上。读序是 **5 → 4 → 3 → 2 → 1**。它把层矩形写进该层记录；随后引擎为该层建立（或按新尺寸重建）**一张离屏画布**：画布编号 = **20 + 有效层号**，尺寸 = 宽、高**各自 × 显示适配比后取整**（显示适配参数见「绘制项的消费者」；取整是**半上取整**：× 适配比后 + 0.5 再向下取整；适配比为 1.0 时就是层宽 / 层高）。重建会换掉像素缓冲；**重建本身不等价于一次显式清零**（新缓冲的内容是否为零由平台决定），清空只由 `0x71` 做。

`0x70` 还写同一记录的其它字段、追加定位记录并置登记标记；**本条只覆盖画布这一面，其余效果本版不规定**。

**`0x79`（三个操作数）**：第 1 个是层号，第 2 / 3 个是**文本绘制原点**的 x / y（层内坐标）。读序是 **3 → 2 → 1**。它只改原点，**不建画布、不清内容**。

**`0x213`（三个操作数）**：第 1 个是层号（直接索引），第 2 / 3 个是**该层绘制键区间的基数与数量**。读序是 **3 → 2 → 1**。记录不存在时**什么都不做**（不建记录、不写任何状态）。

**`0x71`（一个操作数）**：第 1 个是层号（0 = 默认层）。它做四件事：

1. 把**本条指令的位置**（本条相对代码区起点按 32 位字编号的下标）写进**当前帧**的一个字段；
2. 把**文本游标复位到文本原点**，并把该层画布清成**全透明**（显式写零）；
3. 释放该层在两个键区间内的旧绘制条目：`[键基数, 键基数 + 数量)`（由 `0x213` 写）与另一组由 `0x25d` 写的键区间；
4. 释放旧绘制条目后，画布在下一次绘制路径消费时再次出现：引擎按字符逐个提交，每个字符一个条目，键 = `0x213` 写的**键基数 + 字符序号**，位置 = 层左 / 上 + 该字符的**布局字符格**左上。

`0x71` 还会改该层的定位中间状态；这些中间状态的形状与读者**本版不规定**。此外它还有两处整块数据拷贝、一次子系统内调用、一次入口键为「读文本跳过」的调用、以及一次**有条件的**状态位写（置状态选择字第 27 位）；这些见「文本子系统的请求」一节，不属于本条的画布合同。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某层的矩形 | 该层记录的左 / 上两格 ← `0x70` 的第 4 / 5 个值；宽 / 高两格 ← 第 2 / 3 个值，另有一份宽 / 高拷贝由 `0x1c1` 写（见「写列表项的一对字段」） |
| 某层的离屏画布 | 纹理槽 `20 + 有效层号`；尺寸 = 宽、高各自 × 显示适配比后半上取整；缩放后的尺寸也写回该层记录的一对格；内容由 `0x71` 显式清零 |
| 某层的文本绘制原点 | 该层记录的一对坐标格 ← `0x79` 的第 2 / 3 个操作数 |
| 某层的绘制键区间 | 该层记录的一对格 ← `0x213` 的第 2 / 3 个操作数（直接索引，不换默认层） |
| 层被清空 | 画布所有像素 ← 全透明；文本游标 ← 文本原点 |
| 层出现在场景里 | 该层画布被消费：每个字符一个条目，位置 = 层左 / 上 + 布局字符格左上，键 = 键基数 + 字符序号，源 = 布局字符格 × 字体缩放 |

**成立条件**

- `0x71` 的**位置写的是本条**指令的位置，不是下一条；这一格与「换脚本」写的调用点位置是同一帧记录里**相邻但不同**的两个字段，⛔ 不许共用。
- `0x71` 是**唯一**显式清空画布的指令；就画布这一面，`0x79` 只改原点、`0x213` 只改键、`0x70` 只改矩形与尺寸（重建是否得到零像素由平台决定）。
- `0x71` **不建、不删**画布：画布由 `0x70` 建 / 重建；`0x71` 只清内容并让消费从键基数重新开始。
- 画布编号只由**有效层号**决定（`20 + 有效层号`）。层号（经 `0x80` 解析后的有效层号）越界属未定义行为；本版不规定引擎的越界后果。`0x213` 直接索引时同理。
- 宽或高不大于 0 时引擎仍可能按 0 尺寸建画布；0 尺寸画布的消费后果本版不规定。
- `0x213` 的记录不存在 ⇒ 无动作；`0x71` 在层记录不存在时引擎**不检查**（未定义行为；本版不规定后果）。
- 绘制键决定该层在场景里的先后（与其它绘制请求同一套键序，见「绘制项的消费者」）。引擎按字符逐个提交：键 = 键基数 + 字符序号，源矩形 = 该字符的布局字符格 × 字体缩放（缩放为 1.0 时就是布局字符格）；本版按此规定。字符序号是**自上次 `0x71` 以来该层已提交的条目序号**（含振り仮名条目）。
- `0x213` 没写过键基数时，本版**不规定**画布是否可见。
- 纹理画布路径是本节的前提；引擎另有一条按层矩形直接 Blt 的旧路径，其选择条件本版不规定。
- 本条**不规定**画布在平台上的像素格式、混合与采样缩放；只规定「哪张画布、多大、画到哪、什么时候清空 / 被消费」。

**可证伪**

- 设层矩形（宽 / 高 > 0）后调 `0x71`：若纹理槽 `20 + 有效层号` 不存在、尺寸不等于「宽、高各自 × 适配比后半上取整」、或画布不是全透明 ⇒ 本条错。
- 先 `0x79` 设原点再 `0x71`：若文本游标没有复位到原点 ⇒ 本条错。
- 先写正文再 `0x71`：若画布仍有像素 ⇒ 本条错。
- 改 `0x213` 的键基数后再 `0x71`：若绘制键仍从旧基数起 ⇒ 本条错。
- 用层号 0 调 `0x70` / `0x71` / `0x79` / `0x6e` / `0x6f` / `0x196`：若落到的不是默认层 ⇒ 本条错。
- 用层号 0 调 `0x213`：若落到默认层而不是槽位 0 ⇒ 本条错。

**残差**

- `ADV-TEXT-LAYER-DRAW-KEY`（unknown）：逐字符绘制条目用的**绘制键基数**来自脚本的另一条指令；本作 ADV 的
  消息层**没有**给它，此时实现需要兜底（否则只有窗框没有字）。兜底基数是**宿主选择**，⛔ 不是引擎语义。

### 文本层的正文追加与行结束（opcodes 0x6e / 0x196 / 0x6f）

<!-- rule: ADV-TEXT-APPEND -->

三条指令把正文放进文本层画布：

- `0x6e`（两个操作数）：第 1 个是层号（0 = 默认层），第 2 个是正文。读序是 **2 → 1**。正文为空串 ⇒ 绘制入口返回非成功值，调用方在**写当前文本槽 / 置状态位 / 登记计时之前**返回：不追加、不画、不移动游标。
- `0x196`（三个操作数）：第 1 个是层号（0 = 默认层），第 2 个是主文本，第 3 个是振り仮名。读序是 **3 → 2 → 1**。振り仮名先被截断到**上限 1023 字节**，超长静默丢弃；主文本为空串 ⇒ 整段跳过（振り仮名也不画）。
- `0x6f`（一个操作数）：第 1 个是层号（0 = 默认层），只读它。它结束当前行：文本游标的 x 复位到**文本原点**，y 前进**行距**（三支见下；未缩放且普通模式 = 字号 + 行間隙，缺省 6 + 24 = 30），该层的行计数 +1。它不改画布像素；入口的**文本显示门**（由 `0x1bb` 写；三支行为见该条；作绘制入口第 5 实参：非 0 ⇒ 抑制这一次的绘制）影响文本 run 的登记，该登记的影响本版不规定；它还被「字符串」章的 `0x1d2` 当**登记守卫**用（见该条）。

正文画进画布的位置是**文本游标**；游标在 `0x71` 清空后复位到文本原点（`0x79` 写的 x / y）。每画一个字符，游标沿 x 前进该字符的**量度宽度**；`0x196` 的振り仮名画在主文本**上方**，用**另一支字号**（`0x197` 写的那一支），**不**推进主文本游标。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 追加的正文 | 画布上从当前游标开始的字形像素；游标按字符量度推进 |
| 追加的振り仮名 | 画布上主文本上方的小字号字形（截断到 1023 字节后绘制） |
| 当前文本游标 | 该层记录里的文本游标：x 随字符量度推进，y 由行结束推进 |
| 行结束 | 游标 x ← 文本原点；游标 y ← y + **行距**（三支见下条；未缩放且模式 0 时 = 字号 + 行間隙）；该层行计数 +1 |
| 折行（超右界） | 该行已排字符格 ← 保持原坐标；游标按「行结束」推进；当前字符从新行行首开始 |
| 空正文 | 无动作（不写上面任何一项） |

**成立条件**

- 层号 0 是「用默认层」，不是第 0 层；默认层由 `0x80` 改写，初值由引擎建立（初值 1）。
- **空正文的早退在写入之前**：绘制入口对空串返回非成功值，调用方随后直接返回 ⇒ 不写当前文本槽、不置状态位、不登记计时。⛔ 不许「先记下再说」。
- `0x196` 的截断按**字节**：上限 1023 字节，超出部分静默丢弃；截断后仍要画主文本。
- 主文本用 **A 支字号**（`0x75` 写的那一格）；振り仮名用 **B 支字号**（`0x197` 写的那一格，`0x197` 同时写十个槽位的高度；见「转发到字体对象与宿主接口的入口」）。⛔ 不许把两支字号互换，也不许把振り仮名画在主文本的同一基线上。
- 颜色 / 绘制模式来自**字体对象**（`0x76` / `0x77` / `0x78`，见「渲染请求边界」的离屏文字条），不是本条的操作数。
- `0x6e` / `0x196` 都**不清空**画布：重复追加是累加，不是替换。清空只由 `0x71` 做。
- **超右界**：右界 = 层记录里**由 `0x70` 初始化、可被 `0x1c1` 覆盖的那份宽拷贝**（层内坐标、未缩放；不是建画布用的宽、不是缩放后的宽）；画布边界 = **建画布用的宽**（未缩放）× 显示适配比后的纹理矩形。**候选 x = 当前游标 x + 该字量度宽**；配置 `set:AutoLineFeed = 1` 且候选 x > 右界 ⇒ 在画下一个字符前折行（x 回文本原点、y 前进**行距**；未缩放且普通模式行距 = 字号 + 行間隙；模式 ≠ 0 / 有缩放见下条三支）；`= 0` ⇒ 不折行，超出部分按画布边界裁掉；其它值本版不规定。
- **行头禁则**：越界判定之后还要查一张**行头禁则表** —— 它是一张**字符串集合**，元素就是该字符的 1~2 字节编码：**命中 ⇒ 这个字符不在这里折行**（留在行末、可以越界，且**不**把前一个字符一起挪下去），未命中 ⇒ 按上面的规则折行。★ 本作的这张表**构造为空、全二进制没有任何写入者**（只有构造 / 析构的清零）⇒ 发行态**恒不命中** ⇒ 折行只看右界与门；因此"折行后的行首出现「。」「、」这类字符"是**正常**行为，不是缺陷。⛔ 不许把它实现成"行首禁则字符一律折行"或"把上一个字符一起挪下去"。
- **没有整行重排**：引擎不做"先量整行再整体摆"的步骤（逐字测量、逐字写坐标）。越界只**提前结束当前行**：**已经排好的字符格保持原坐标**；游标 x 回文本原点、y 前进**行距**（三支见下条）；**当前字符**成为新行的第一个字符 —— 已排好的前缀**不回填、不在新行重排**。
- 行结束的**行距** = **行間隙** + X，X 由字体对象的**行距模式格**决定（三支，判据只看这一格）：
  - **模式 = 0**（普通）⇒ X = **−行距项格**（该格建立时 = −字号，每次设字号都重写）；
  - **模式 = 1（及其它非 0 值）** ⇒ X = **字号格**；
  - **模式 = 2** ⇒ X = **字号格**（与上一支同式，但走单独一条分支）。
  ★ 没有缩放时三支数值相同（行距项格正好 = −字号，缺省 6 + 24 = 30）；**有缩放时模式 0 用的是缩放后的高度、其它模式用未缩放的字号** —— 这是三支唯一可观察的差别（缩放档上这两句的取值口径见残差 `RES-ADV-TEXT-LINE-SCALED`）。
- 层的**另一个模式格**（= 1 时）：追加记录走**逐字支** —— 每个字符一条记录，且**每条记录的"用 B 支字号"位被置起**；
  这 N 条记录仍在**同一趟排版**里追加；打字机的"一格"就是其中**一条记录**；
  行结束则**不走**上面的常规路径，改走另一条入口（它同样读行距模式格，其余语义本版不规定，见残差）。
- 是否折行（而非裁掉）由 `set:AutoLineFeed = 1` 决定；其它值不规定。**对齐**：引擎只有左对齐 —— 启动期配置里没有任何对齐键、层记录 / 文本记录里没有对齐位、越界只查右界与下界，**没有任何"居中 / 右对齐"的回拉**（⛔ 不许实现居中 / 右对齐）。**字距 / 连字**仍不在本版：字距有一条额外间距格与一个"等距模式"格（`RES-ADV-TEXT-APPEND-JUSTIFY`），连字在本二进制里没有独立实现（半角只是切字用的分支，推进量仍取单字量度）。正文超出画布且不折行时按画布边界裁掉。
- **振り仮名的横向定位**（算式已定）：振り仮名被摆进**它自己那一格**（这一格的左 / 右端 = 本条主文本**最后一行**占据的范围），令 **W** = 振り仮名整串的量度宽、**格宽** = 那一格的宽、**n** = 假名数 + 1（= 间隙数，含两端边距；算式 ⌊(字节数 + 3) ÷ 2⌋）、**d** = 格宽 − W：
  - **d > 0** ⇒ **每档步进 = ⌊d ÷ n⌋**：首字 x = 格左 + 步进，此后每个假名在自身量度宽之外再各加一次步进（2 字节字加整份、1 字节字加半份）⇒ 整串**两端各留一份步进**、恰好铺满格宽（两端对齐）；
  - **d ≤ 0** ⇒ 不加步进，整串以格**中心**对齐：首字 x = 格左 − ⌊|d| ÷ 2⌋（左侧可以伸出格）。
  - 纵向 = 格顶 + 行距项（另有一个条件性 +1，条件未查清）。
  ⛔ **不是"按行比例切分"**：按比例只决定"这一行分到几个假名"（见残差），不产生每个假名的 x。★ 格宽由主文本这一行的范围给出；上式的每个量都是机械可读的。
- **逐字符显示（typewriter）**：`0x6e` / `0x196` 在**追加时一次性**写好这一段的全部布局格；文本记录也在**同一趟排版**里追加（不延迟到绘制侧）；**绘制侧每 `message:MessageSpeed` 毫秒推进一格、每帧最多一格**（未到期的帧一格都不画；按键 / 跳过时把剩余格一次抽干）。⛔ 不许实现成"追加时就画全部"，也⛔ 不许实现成"追加时只追加前 N 个字符"。
  ★ **演示闸层走"重放"支**：若该层的演示闸（`0x300`）开着且参数格（每字间隔毫秒）≠ 0，推进器不按
  "整段只走一遍"收尾，而是逐格揭示 → 整段完停"期限"毫秒 → 清掉该层已排出的绘制条目、揭示游标归 0
  （闸位保持）→ **从第一格重来**，期间**不重新追加**任何文本。参数格 = 0 时该层只**抽干一次**、不重放。
  判据：一段文本 + 开着的闸 + 参数格 ≠ 0，必须出现**≥2 次**"逐格出现 → 停 → 条目全消失 → 从第一格重来"，
  且期间没有新的 `0x6e` / `0x196`；只出现一次 ⇒ 本条错。参数格 = 0 时若仍重放 ⇒ 也错。
  ★ **每一格的字形样式（字号 / 粗细 / 绘制模式 / 主色 / 副色）取"追加那一刻"的值**，不是"推进到它时字体对象的值" —— 引擎在追加时就 SelectObject + 逐字写出，之后的推进只呈现已排好版的格。判据：追加之后、这一格被推进到之前改 `0x75` / `0x2bd` / `0x76` / `0x77`，**已追加的那一段不受影响**，只有此后追加的段用新值；若一个字按新字号 / 新粗细画出、而**字宽仍是追加时量度** ⇒ 本条错。
- 字形量度、基线由平台字体与字体对象决定；本版只规定「主文本用 A 支、振り仮名用 B 支、振り仮名的横向算式、行结束按行距前进」。
- 没有可用画布（没设过正尺寸的层矩形）时，正文仍被读入并尝试绘制，但**不产生像素**（见本条前面的“宽或高不大于 0”条件）。
- 追加**成功**时的**外部写入**分两档（⛔ 不许写成"无论如何都做"）：
  - **当前文本槽 ← 本次的层号**：两档都写（空正文 / 绘制入口返回失败那一支什么都不写）。
  - **仅当** `message:MessageSpeed`（每字间隔毫秒）**> 0** 且**状态字第 27 位未置**时，才**置起状态字第 29 位**
    并**启动文本计时器**（间隔 = 该格、起点 = 现在）。
  - 上述条件不成立（间隔 = 0 或第 27 位已置）⇒ **旁路**：改走"立即追加 + 同帧抽干"的入口
    （不置第 29 位、不建计时器、⛔ 不留待画格）。旁路**不自己置第 27 位**；但在**同一次调用里、门判之前**
    还有一条前置支：若一条子系统查询返回非 0，就**置第 27 位**（并置一个标志格 —— ⛔ 它不是状态选择字的「等消息位」/「等待位」；含义与消费者见残差
    `RES-ADV-TEXT-APPEND-PRE27`），于是本条随后落进旁路；并且在下一次清掉第 27 位之前，**后续追加也走旁路**。
  - 空正文 / 绘制入口返回失败 ⇒ **什么都不写**（三处外部写入都不做）。
- 当前文本槽与状态字第 27 / 29 位、计时器属于本条的**外部写入**。第 29 位的服务者是主循环里的一个**文本推进器**
  （普通打字支在本条；演示闸支见「文本槽的演示闸与定时清除」）：它按计时器**每 D 毫秒推进一格、每帧最多一格**
  （未到期的帧一格都不画）；前进键 / 跳过 ⇒ 抽干并**清第 29 位、置第 27 位**；末格画完 ⇒ 清第 29 位。
  只要本轮的推进器服务里**有槽进了"参数格 ≠ 0"的闸门支**，第 29 位就保持置起（见「文本槽的演示闸与定时清除」）。
  ⛔ 不许把它实现成"每帧必画一格"，也⛔ 不许把抽干做成"画完但不动门位"。
- **残差**：`RES-ADV-TEXT-APPEND-PRE27` —— 前置支那条"子系统查询"的身份与"等消息"标记的消费者；
  `RES-ADV-TEXT-LINE-SCALED` —— 行距模式 0 在缩放档上的取值口径（行距项格是否含缩放）；
  `RES-ADV-TEXT-APPEND-RUBY` —— 振り仮名"可用宽度"实参的来源与典型取值、以及"每行分到几个假名"的比例切分（两者都已定到站点，但典型值没有运行时采样）；`RES-ADV-TEXT-APPEND-LAYOUT` 见上；`RES-ADV-TEXT-LAYER-TIMING` —— 逐字符条目的**创建时机**与推进节流已定（追加时写布局格；绘制侧每 D 毫秒一格、每帧最多一格；跳过 ⇒ 抽干 + 换门位），仍未定的是"每帧那一格从哪个格号开始 / 与渲染步的先后"。

**可证伪**

- 用空串调 `0x6e`：若画布像素变了、游标动了、当前文本槽被写、状态位被置、或登记了计时 ⇒ 本条错。
- 用空主文本调 `0x196`：若当前文本槽被写、状态位被置、或登记了计时 ⇒ 本条错。
- 窄画布 + 长文本（非禁则字符）：`set:AutoLineFeed = 1` 时必须出现第二行（y 前进）；`= 0` 时 y 不得前进；`= 2` 时本版不规定 ⇒ 1/0 反了即本条错。
- 第二行的第一个字符必须从**文本原点**的 x 开始（不是层内 0）；折行阈值用 **`0x1c1` 可覆盖的那份未缩放宽拷贝**（0x70 初始化；适配比 ≠ 1 时不能拿画布边界当阈值）；候选 x **等于**右界时不折行（严格大于才折）。
- `0x1c1` 把宽 / 高拷贝改小后：折行必须更早发生（阈值跟着 `0x1c1` 写的宽走）⇒ 不跟 ⇒ 本条错。
- 禁则：本作的行头禁则表**恒空**，所以"折行后的行首出现「。」「、」这类行头禁则字符"是**正确**行为；若实现让这类字符从不落在行首 ⇒ 本条错（那是把空表当成非空）。
- 对齐：若画布上出现"居中的行"或"贴右界的行"⇒ 本条错 —— 引擎只有左对齐。
- 整行重排：若同一段文本在 `set:AutoLineFeed = 1` 下的行数与"逐字超界就换行"的结果不同（例如为了凑满行把几个字符整体前移）⇒ 本条错 —— 引擎没有整行重排。
- 折行后的字符格：若第一行已排好的字符格因折行被改坐标（或整段前缀搬到新行重排）⇒ 本条错；折行后的行首字符必须是引发越界的**那个**字符，不是前缀的第一个字符。
- 用空主文本 + 非空振り仮名调 `0x196`：若画布上出现振り仮名 ⇒ 本条错。
- 主文本与振り仮名的字号互换：若主文本变成 B 支大小、振り仮名变成 A 支大小 ⇒ 本条错。
- 给振り仮名传入 1024 字节：若画布上画出的超过 1023 字节（或整段被丢弃）⇒ 本条错。
- 追加两段正文之间不调 `0x71`：若第二段覆盖第一段（而不是接在后面）⇒ 本条错。
- 行结束后：若 x 没有回到文本原点、或 y 没有前进**行距**（三支见正文；未缩放且模式 0 时 = 字号 + 行間隙）⇒ 本条错。

### 文本显示门：opcode 0x1bb

<!-- rule: ADV-TEXT-GATE-1BB -->

`0x1bb` 有一个操作数（门值），三支：

- **0** ⇒ 门 ← **最高位置起**（第 31 位，值 `0x80000000`；"抑制"态）；
- **1** ⇒ 门 ← **0**（"正常显示"态）；
- **其它**（含负数）⇒ 门**不变**（保旧值），只上报一次错误，然后照常返回。

三支都不抛异常、不改变控制流、不写操作数、不发平台请求。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 文本是否显示 | 文本显示门（0 = 正常；第 31 位已置 = 抑制） |

**成立条件**

- 门的取值只有**两个**：0，或"第 31 位已置"；判据是**不等于 0**（⛔ 不是逐位判最高位）。
- 第三支**不写**门：⛔ 不许实现成"非法值当作 0 / 1 之一"。
- 门的读者已知两处：`0x6e` / `0x196` 把它当绘制入口的第 5 实参（非 0 ⇒ 抑制这一次的绘制）；
  `0x1d2` 拿它当登记守卫（非 0 ⇒ 整条跳过）。另有一处按位判它来挡"按键重画文本"，是否读同一格见残差。
- 门的**初值与复位**本版不规定（见残差）。

**可证伪**

- 依次执行 `0x1bb 0`、`0x1bb 1`：门必须从"抑制"回到 0；若仍非 0 ⇒ 第二支没写。
- 先 `0x1bb 0`，再 `0x1bb 7`：门必须**仍**是非 0（第三支保旧值）；若变成 0 或 1 ⇒ 第三支写了门。
- `0x1bb 7` 之后：控制流必须继续（不抛、不中止）。

### 選択肢の登録：opcode 0x90

<!-- rule: ADV-CHOICE-ADD-90 -->

`0x90` 有七个操作数，把一个**选项**追加进引擎的**选项表**（与绘制项表、网格表、命令表都不是同一张）。

- 第 1 / 2 个 = 矩形的**左上**（x / y）；第 3 / 4 个 = **宽 / 高** —— 记录里存的是 `(x, y, x+宽, y+高)`。
- 第 5 / 6 / 7 个 = 该选项的三个**脚本入口**（body 内的 32 位字下标；`-1` = 没有）：第 7 个是**决定**时跳去的入口，第 5 / 6 个是光标**进入 / 离开**该矩形时跳去的入口。
- 读序 **1 → 2 → 3 → 4 → 7 → 6 → 5**；推进格数 = **15**。
- 追加成功 ⇒ 记录里写下矩形、三个入口、以及**当前帧的深度档**；随后把「选中项下标」置 **-1**、「决定标志」清 **0**、**arm 闸清 0**（下一次开窗会重新算悬停）。
- 追加**不**改变执行位置（控制流顺序前进）：决定 / 进入 / 离开的跳转发生在**消费侧**（见下）。

**容量与失败**

- 选项表的容量是 **100**（不是引擎错误文本里写的 20）。
- 已满（计数 ≥ 100）⇒ 追加**失败**、一个字段都不写，引擎抛**显示消息型异常**（消息体是「選択肢が多すぎます」那一句）；控制流不继续。
- 操作数类型非法 ⇒ 抛操作数类型异常（任一操作数，读序决定抛在哪一条）。

**消费侧（合同）**

- **决定**：若当前选中下标 `i` 在 `[0, 计数)` 内 ⇒ 执行位置 ← `body 起点 + 4 × 第 i 项的「决定入口」`；随后选中下标置 -1、决定标志清 0。选中下标越界 / 为负 ⇒ 什么都不做，继续等。
- **进入 / 离开**：光标移动时按矩形命中算出目标项，取该路径的入口；入口为 `-1` ⇒ 不跳。两条路径用的是**不同**的入口（第 5 / 第 6 个操作数），⛔ 不许合并成一条。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 选项表 | 按追加顺序的记录表：矩形四边 + 三个入口 + 深度档 |
| 表满的判据 | 计数 ≥ 100 |
| 决定后的去向 | 执行位置 ← 该项的「决定入口」（字下标） |
| 决定之后的复位 | 选中下标 ← -1、决定标志 ← 0 |

**成立条件**

- 入口是**字下标**，不是字节偏移：`执行位置 = body 起点 + 4 × 入口`。
- 容量门槛是 **100**；引擎自己的错误文本说"最大 20"，两者不一致 —— 本版以**机械判据（比较 100）**为准，文本只当提示（见残差）。
- 追加时**不做**任何越界检查（入口越界是未定义行为，本版不规定后果）。
- 三条入口都可以是 `-1`（该路径没有入口）；`-1` 的处置是"不跳、顺序前进"，⛔ 不是"跳到 body 起点前一字"。

**残差**

- `ADV-CHOICE-CAPACITY-TEXT`（unknown）：容量 100 与错误文本"最大 20"的矛盾没有找到解释（可能是历史文本，也可能是两条不同的上限）。
- `ADV-CHOICE-DEPTH`（unknown）：记录里的"当前帧深度档"从哪来、和深度校验如何交互未取证。

**可证伪**

- 连续追加 100 条：第 100 条必须成功；第 101 条必须**抛显示消息型异常**且不写任何字段（门槛按 20 实现 ⇒ 本条的 100 条会中途抛）。
- 追加后把「第 7 个操作数」改成别的值再追加一次：执行位置**必须不变**（本条不跳）；执行位置跟着变 ⇒ 把消费侧的跳转写进了追加。
- 追加 `(10, 20, 30, 40, …)`：记录里的矩形必须是 `(10, 20, 40, 60)`；存成 `(10,20,30,40)` ⇒ 宽高没有加。
- 决定时选中下标越界：必须什么都不做（不跳、不清选中态）；跳到某项 ⇒ 越界判据错。

### 選択肢の付加整数：opcode 0x97

<!-- rule: ADV-CHOICE-SET-EXTRA-97 -->

`0x97` 有五个操作数：前四个是**矩形**（`x` / `y` / **宽** / **高**，与 `0x90` 同口径：存的是 `x, y, x+宽, y+高`），第五个是**一个整数**。

- 读序 **1 → 2 → 3 → 4 → 5**；推进格数 = **11**。
- 拿**四条边全等**去**选项表**里找**第一条**命中的项，把它的**附加整数格** ← 第五个操作数。
- **找不到 ⇒ 什么都不做**（不建项、不改任何项、不报错、不中止）。
- 只改**一条**（第一条命中）；同矩形的后续条目**不**被改。
- 不改变执行位置。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某项的附加整数 | 选项表里第一条矩形四边全等的项的附加整数格 ← 第 5 个操作数 |
| 没命中 | 无变化 |

**成立条件**

- 匹配是**四边全等**，不是"包含光标"、也不是"只比左上角"：差一个像素就不命中。
- 匹配**按追加顺序取第一条**：⛔ 不是"改所有同矩形项"。
- 附加整数的初值不是 0，而是 **-1**（`0x90` 追加时写 -1）；这条只覆盖写入后的值。
- 选项表为空 ⇒ 与"找不到"同一支：什么都不做。

**残差**

- `ADV-CHOICE-EXTRA-MEANING`（unknown）：附加整数的领域含义（序号？图编号？状态？）未取证；调用点把它写成 0 / 1 / 2 / 3 / 8 这类小整数。

**可证伪**

- 追加两条同矩形项，对同矩形跑 `0x97`：只有**第一条**的附加整数变；两条都变 ⇒ 取第一条错。
- 追加 `(0,0,10,10)` 后对 `(0,0,10,9)` 跑 `0x97`：必须**什么都不改**；改了 ⇒ 匹配不是四边全等。
- 空表跑 `0x97`：必须不抛、不建项；抛或建项 ⇒ 错误。

### 选项窗口：开窗 / 清表 / 等待（opcodes 0x93 / 0x94 / 0x91 / 0x92）

<!-- rule: ADV-CHOICE-WINDOW -->

选项表（`ADV-CHOICE-ADD-90` 建的那张）外面还有一个**窗口状态**：输入总闸、完成闩锁、一次性的 arm 闸、鼠标移动命中开关、上下键步长、悬停下标、兜底跳转目标。这四条只开关这些格；**它们一个都不直接读输入**（读输入在帧循环里）。

- `0x93`（无操作数，推进 **1**）：先**清表**（条目数 0、选中 -1、步长 0、悬停 -1、移动命中开关 0、变更挂起 0），然后**二选一**：
  - 输入总闸 ≠ 0 ⇒ **关掉**它（不置闩锁）；
  - 输入总闸 = 0 ⇒ 置**完成闩锁**。
  ⇒ 同一个脚本片段里"第一次 0x93 = 关窗、第二次 0x93 = 放行等待者"是**正常**的，⛔ 不是幂等清表。
- `0x94`（无操作数，推进 **1**）：置**输入总闸**；做一次 **arm**（arm 闸为 0 ⇒ 置 1 并用**当前光标**跑一次矩形命中，结果写悬停下标）；置移动命中开关；**步长 ← 10000**。
  - 10000 ≥ 条目数 ⇒ 上下键翻页实际被**禁用**（选项窗是纯鼠标）。⛔ 这个 10000 **不是超时**：本族没有任何时间参数。
- `0x91`（一个操作数 = 上下键步长，推进 **3 或 0**）：
  - 闩锁已置 ⇒ 清闩锁、清移动命中开关、**不读操作数**、推进 3；
  - 否则 ⇒ arm 一次、步长 ← 操作数、置移动命中开关，并把**推进格数改回 0**。
- `0x92`（两个操作数：步长、兜底跳转目标，推进 **5 或 0**）：与 `0x91` 同构，多一条：
  - 闩锁判断在**读数之前** ⇒ 闩锁已置时**一个操作数都不读**、兜底目标也**不写**；
  - 读数序 **2 → 1**（先兜底目标，再步长）；未置闩锁时兜底目标 ← 第 2 个操作数、步长 ← 第 1 个，然后同样把推进格数改回 0。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 输入总闸 | `0x94` 置 1 / `0x93` 清 0 |
| 完成闩锁 | `0x93` 的 else 支置 1 / `0x91`·`0x92` 消费时清 0 |
| arm 闸 | 首次开窗置 1（并做一次命中） |
| 上下键步长 | `0x91`·`0x92` 的第 1 个操作数 / `0x94` 写 10000 |
| 兜底跳转目标 | `0x92` 的第 2 个操作数（`0x93` 清表**不**复位，跨窗保留） |
| 悬停下标 | arm 时的命中结果（无光标 ⇒ -1） |

**成立条件**

- **推进格数 = 0 是本引擎唯一的阻塞手段**：分派器按格数推进执行位置，0 表示"本拍不前进 ⇒ 下一拍重跑同一条"。`0x91` / `0x92` 的"等待"就是这条机制，⛔ 不许实现成"睡眠 / 轮询 / 改执行位置"。
- 这条机制对**所有**指令成立（长度字恒 = `2 × 操作数个数 + 1`；`0x90` 是 15、`0x97` 是 11、这两条是 3 / 5、无操作数的是 1）——它是"长度字"的**用途**，不是本族专有。
- `0x93` / `0x94` **永远**推进 1（不阻塞）；只有 `0x91` / `0x92` 会阻塞。
- 清表是**七格复位**（含移动命中开关与变更挂起）；⛔ **不**复位兜底目标（它跨窗保留），也不是只把条目数清零。
- 失败形态：`0x91` 的操作数在**未置闩锁**那一支才被读 ⇒ 类型非法只在那一支抛；`0x92` 同理（两个操作数都不读）。

**残差**

- `ADV-CHOICE-CONSUMER`（unknown）：**消费侧**（帧循环里"点中某条 ⇒ 执行位置 ← 该条的决定入口"、"光标进出 ⇒ 进入/离开入口"、"没有选择就关窗 ⇒ 兜底入口"）本版只给出合同，未规定它在帧循环里的**次序**（与命令档、文本推进、输入采样的相对位置）。
- `ADV-CHOICE-91-92-UNUSED`（unknown）：`0x91` / `0x92` 在发行数据里**一次都没被调用**（全语料 0 处）⇒ 本条的这两支只有机制证据（写者 / 读者都在，缺一条真实调用序列）。
- `ADV-CHOICE-B-CONTROL`（unknown）：引擎里还有**第二个同形控件**（另一张选项表，带列表滚动），它的建表 / 清表 / 等待是另外几条 opcode；本版不写。

**可证伪**

- 依次 `0x94`、`0x93`：第一次 `0x93` 必须**关输入总闸**且**不置闩锁**；置了闩锁 ⇒ 两支判据反了。
- 再跑一次 `0x93`：必须置闩锁；没置 ⇒ 第二支错。
- 未置闩锁跑 `0x91`：执行位置必须**停在原地**（推进格数 0）；前进了 ⇒ 阻塞没实现。
- 置闩锁后跑 `0x91`（操作数给非法类型）：必须**不抛**且推进 3；抛了 ⇒ 闩锁支读了操作数。
- 置闩锁后跑 `0x92`：兜底目标必须**不变**（闩锁判断在读数之前）；变了 ⇒ 写序错。
- `0x94` 之后步长必须是 10000（不是 0、也不是"上次 0x91 写的值"）。

### 消息等待三格：opcode 0x243

<!-- rule: CORE-OPS-MSG-WAIT-243 -->

`0x243` 无操作数，推进格数 = **1**：把三格"消息等待状态"写成 **(1, 0, 0)**（写序 = 这个顺序）。

- 整段被一道位住：该位已置 ⇒ **一格都不写**（不是"写别的值"）。
- 无调用、不置门位、不抛。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 消息等待状态 | 三格 ← (1, 0, 0) |

**成立条件**

- 写序是 (1, 0, 0)：⛔ 与"块结束"那条的 (0, 0, 1) 不是同一顺序。
- 被门位住时是**完全 no-op**，⛔ 不是"部分写"。

**可证伪**

- 门位 = 0、三格预置 7：执行后必须是 (1,0,0)。
- 门位已置：三格必须仍是 7。

### 消息块开始 / 结束：opcode 0x304 / 0x305

<!-- rule: CORE-OPS-MSG-BLOCK-304-305 -->

一对"消息块"括弧，都无操作数、推进格数 = **1**。

**`0x304`（块开始）**

- 把**消息臂位整格写 1**（顺手清掉上一块留下的"本块写过字"位）。
- 取当前消息层（层号 0 ⇒ 默认层），把该层的**揭示游标**存进"块开头"格。

**`0x305`（块结束）**

- 门 = 臂位的**第 0 位** **且** 第 16 位（第 16 位由文本追加指令 `0x6e` / `0x196` 成功追加时置）。未武装 ⇒ **只清臂位**、什么都不做。
- 武装 ⇒ 依次：① 揭示游标**回卷**到"块开头"格；② 读 `message:ReadTextSkip`，非 0 且"已读"命中时置门字第 **27** 位；③ 揭示该层**全部**格（引擎在这里自旋到"该层揭示完"）；④ 把消息等待三格写成 **A = 1、B = 0、C = 0**（引擎写序是 B、C、A）。
- 三条出口（未武装 / 正常 / 自旋后）**都清臂位**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 本块已开始 | 臂位 ← 1（第 0 位） |
| 本块写过字 | 臂位第 16 位 ← 1（由 `0x6e` / `0x196` 置） |
| 块首的揭示位置 | "块开头"格 ← 该层揭示游标 |
| 块结束后 | 揭示游标 ← 块开头（回卷）、等待三格 ← (1,0,0)、臂位 ← 0 |

**残差**

- `RES-MSG-BLOCK-READ-HIT`（unknown）：② 的"已读命中"用的是哪张已读表、键是什么、谁写；本版只规定 `message:ReadTextSkip` 非 0 这个必要条件。

**成立条件**

- 两条**不是** `0x300` / `0x301` 的镜像：那一对动的是**演示闸**（三层循环重放），这一对动的是**消息块**状态。
- 臂位是**整格写 1**（`0x304`）⇒ 上一块的第 16 位被清；⛔ 不是 `or`。
- `0x305` 的等待是**函数内自旋**（不是把推进格数改回 0）：它返回时推进格数仍是 1，执行位置只前进一次。
- 未武装是**静默 no-op**（只有清臂位这一个可观察效果）。

**可证伪**

- 先跑 `0x304` 再跑 `0x305`（中间不追加文本）：`0x305` 必须什么都不做（揭示游标不变），只清臂位。
- 臂位预置 `0x10000` 跑 `0x304`：执行后必须是 **1**；是 `0x10001` ⇒ 用了 `or`。
- 加一个文本块（`0x6e`）再 `0x305`：揭示游标必须回到块开头，且该层最终**全部揭示**。

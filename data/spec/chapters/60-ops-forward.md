## 转发型指令

本章 7 条规则 / 11 个 opcode。

这一族都把工作交给**引擎持有的某个对象**的一个入口，由那个对象去处理。各条的入口形态各不相同，引擎数据效果也各不相同（`0x1ca` 写一个命名键、`0x324` 释放接收者持有的对象、`0x32f` 清场景光源表里的一格并让图形设备关掉那个光源），所以它们**不是同一条机制**：

1. **交给谁、交了什么**：入口的稳定标识（消息号 / 入口槽 / 入口自身的可观察行为）与实参的形态（操作数 / 常量 / 引擎里的一个字段）；
2. **引擎数据效果**：各条自己的状态对应表说的是唯一准；
3. **入口之后完全无法观察的部分**才归"本版不规定" —— ⛔ 不因为"看不见"就写成"什么都不做"：请求本身是可观察的。

★ 这一族的**类型名**在本作样本里没有（对象是由谁构造的、叫什么，没有观察）⇒ 本版用"引擎持有的对象 / 某个子系统对象"这类**稳定定位**称呼它们，⛔ 不编造类型名。

### 设一个命名键：opcode 0x1ca

<!-- rule: CORE-OPS-FORWARD-MESSAGE -->

`0x1ca` 有一个操作数。它把引擎**命名键存储**里的键 `message:ReadTextSkip` **设成该操作数**（按整型读出的值），然后返回 —— 返回值由分派器丢弃。

- 入口是那个存储的**"设置一个命名键"入口**（实参 = 键名 + 值）；
- 这是**引擎数据**：`0x71` 读的就是**同一个键** —— 它非 0 时 `0x71` 走文本侧的跳过分支。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 命名键 `message:ReadTextSkip` 的当前值 | ← 第 1 个操作数 |

**成立条件**

- 这条**不是**"无引擎数据效果"：写原值（清零）与不写看起来一样，但非 0 值会改变 `0x71` 的行为。
- 命名键存储**不是**脚本键表：脚本的配置指令用的是 `(键类型码, 键下标)` 拼成的键（见「配置」的「脚本访问」），读不到这里的命名键；而 `0x71` 读的正是**同一个命名键**。
- 该入口的返回值不写回操作数、也不进帧状态：分派器丢弃它。
- **键存储是一个引擎持有的服务对象**，对外有一张**构造期一次装好、运行期不再更换的入口表**；它内部是**两张按名字索引的映射**：一张存**整数**、一张存**字符串**。
- 入口表至少含：读整型键、读字符串键、写整型键、写字符串键、以及"这个键在不在"。**写入口只覆盖已存在的键**。
- **键不存在时两支都先上报、不静默**：引擎发**一次模态错误提示** —— 标题是一个固定常量文本 `不正なキー`、正文 = **那个键名本身**。随后 —— **读**给出 **0**（字符串那支给空串）；**写**什么也不写、返回"没写成"。
- **键集合在启动时一次定型**：由该对象的构造路径按内建默认逐条登记（各键缺省值不同），加上两段装载的直接登记面（见「配置」的「配置库」），运行期**不新增键**。⇒ 正常装载之后"键不存在"**不可达**；可达的只有白盒删键、或键名拼错。
- `0x71` 读到非 0 之后文本侧的具体行为不在本条。

### 把引擎字段里的对象交给入口：opcode 0x324

<!-- rule: CORE-OPS-FORWARD-FIELD -->

`0x324` **没有操作数**。它从引擎的一个字段里取出一个对象，把这个对象当作接收者交给一个**无参入口**（尾跳：入口的返回值直接回到分派器），然后返回。

- 入口的可观察行为是一个**复位**：**逐格判空**它自己持有的**三个**对象（非空才释放）、把这三处引用清空，再清掉它自己的一个标记；
- 改的是**接收者自己的状态**（一个引擎持有的对象），不是脚本可观察的数据。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 接收者被复位 | 它持有的三个对象被释放、引用清空；它的一个标记 ← 0 |
| 三个「待处理」引用（第 1 / 2 / 3 格） | 接收者自己的三格指针；各由**一条**指令整份替换（见下文 `0x327` / `0x326` / `0x328`），复位时三格一起释放并清空 |
| 交给该入口的请求 | 一次无参尾跳（接收者来自引擎字段） |

**成立条件**

- 它**不读任何操作数**：操作数个数为 0 是这条指令的长度依据。
- 接收者不是操作数，而是引擎里存着的一个对象指针 —— 所以"没给操作数"不等于"没有输入"。
- 入口**不带实参**：与本族的另外两条（带键名 / 带索引）不同，⛔ 不许把一条实参写成"可选的"。
- **接收者是谁**：它是**场景持有的三维特效对象** —— 门前渲染判据第 b 支读的那三个「待处理」指针格就是**它的**（见「帧步进」的「就绪判据」）。它由**引擎把渲染器挂到场景上**那一步（图形初始化路径内、用一个图形设备构造）**建立**、在**场景拆除时删除**（场景构造时那一格是 0）；**建立失败 ⇒ 启动以一条错误消息结束**，不会进入脚本执行 ⇒ 在能执行脚本的整个期间那一格**恒非空**。本条**不创建、不销毁**它，只复位。
- ⛔ 不许把"该字段只有读、没有写"当成结论：那个字段**有写点**（建立 / 拆除路径各写），本条只是不规定它们的时机与守卫。
- ★ **换成空值时入口不自查**：复位入口的第一句就按接收者的字段取址，**没有任何「接收者是否为空」的判据** ⇒ 空值 ⇒ **访问违例**（进程终止）。「为空」只出现在"还没挂渲染器"与"场景已拆"这两种**不执行脚本**的时段。⛔ 不许把它实现成"为空就跳过"，也⛔ 不许把它实现成一条静默的无动作 —— 入口的实参就是那个字段的值，「值是空」与「不要调用入口」是两件事。
- ★ 入口**逐格判空**的是**它自己持有的那三个对象**（不是接收者本身）：逐个"非空才释放"，随后清那三格与它自己的一个标记。
- 接收者的**类型身份是三维特效对象**（类型级证据见复核数据）：它与门前就绪判据第 b 支读的是**同一个对象**，那三个「待处理」格属于它自己这一族，⛔ 不许按渲染器成员去解释。
- 三个引用**各自只有一个填充例程**，且三个例程**外形相同**：**先释放该格原有的对象**（带销毁标记）、把该格**清空**，再用接收者自己持有的一份 **4×4 矩阵模板**（第 2 格那一次用**三份**模板）与**两个整数**——**接收者自己的一格整数**（建立接收者时写入）与**触发指令的第 1 个操作数（按整型读）**——构造新对象，最后**存回同一格**。★ 第 2 格那一次的构造还多收几样实参（该指令的**第 3 个操作数（浮点）**、**第 4 个操作数（整型）**、它对**第 2 个操作数选中对象**做的一次询问的结果、以及场景上的一份资源）；本版只登记**它们的来源**，不规定它们在新对象里的用途（⛔ 不许因此把第 2 格与另外两格实现成两套生命周期：释放 / 清空 / 存回三步三格同形）。⇒ 填充是"整份替换"，不是"就地改"，也不是"两个例程分工"。
- 三个填充的**触发者是三条不同的脚本指令**，各换**一格**、互不重叠（三格按机器顺序称第 1 / 2 / 3 格，与「状态对应」及门前就绪判据第 b 支读的那三格同序）：**`0x327` → 第 1 格**、**`0x326` → 第 2 格**、**`0x328` → 第 3 格**；三条都把自己的**第 1 个操作数（整型）**交给填充例程。⛔ 不许把三条实现成同一格、也不许允许互换：复位入口按格释放三个、就绪判据按格判空，三格必须彼此独立。
- 这三条指令**不是**逐帧事件、**不是**换显示资源的事件，也不是场景建立 / 拆除的一部分 ⇒ 一帧之内三格可以被改任意次，也可以一帧都不改；同一帧内改两次 ⇒ 后一次看到的模板已是前一次之后的值（模板回灌）。
- 释放旧对象**先于**填新对象，且只用"销毁标记 = 真"的那一次调用；⛔ 不许实现成"先建后放"（那会让新旧对象同时存活、多占一份资源，且在构造失败时泄漏旧对象）。
- 对某一格的**转发**（一次虚调用）在该格为空时**静默返回**（不是崩溃、不是抛错）—— 这是三个引用里**唯一**允许为空的读路径；复位入口**没有**"接收者非空"判据（它对空接收者直接解引用）。

**可证伪**

- 连续触发**同一格**的填充两次 ⇒ 必须观察到**两次**「释放 + 构造 + 存回」，且第二次构造读到的模板是第一次之后的值；只观察到一次构造、或第二次仍用第一次之前的模板 ⇒ "模板回灌"写错（看成了"只在第一次建"）。
- 白盒让某次构造失败（新对象返回空）⇒ 该格必须是**空**（已释放、未填），且随后的转发静默返回、复位入口仍会解引用它；旧对象仍被保留 ⇒ "先放后建"写错。
- 只触发上面三条指令中的**一条** ⇒ 另外两格**一格都不许变**；变了 ⇒ 三个例程被实现成了一个，或 opcode → 格的对应写错。

### 关掉场景的一个光源：opcode 0x32f

<!-- rule: CORE-OPS-FORWARD-CONTAINER -->

`0x32f` 有一个操作数，读成**光源下标**。它做两件事，顺序固定：先把**场景光源表**里该下标那格的**启用标志**清 0，再向**图形设备**发**一次**「把该下标的光源关掉」的请求（两个实参 = **该下标**与**常量「假」**）。

- 场景的光源表是**固定 10 格**：每格 = 一个**启用标志** + 一份**光源描述**。本条**只**改标志，**不改**该格的光源描述（描述仍留着，下次设同一个下标时被覆盖）。
- **下标不做范围检查**：越界 ⇒ 标志被写到表外（未定义行为），并且请求带一个越界下标（设备侧只会拒绝）。本版对此不作语义断言。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该下标光源的启用标志 | ← 0（该格的光源描述不变） |
| 交给图形设备的请求 | 一次「关光源(下标, 假)」 |

**成立条件**

- 清格是**按下标**的一格，不是整块清：别的下标不受影响。
- 下标来自脚本；**接收者是场景自己持有的那张固定表**，不是脚本给的、也不是引擎里另存的一个对象。
- 这张表还有**另外两条路径**（同一张表）：设置第 i 个光源（写完整描述、并把标志置 1）、以及「应用全部光源」（按 10 格逐个把已启用的送进设备）。⇒ 本条与它们是同一张表的三个入口，⛔ 不要各建一张。
- 这里的"光源表"与「数据池」的容器句柄（`0x8003` / `0x8009` / `0x8005` / `0x800B`）**不是同一个对象**：`0x32f` 的接收者是引擎自有的固定对象，不是池句柄容器，见「容器句柄」；本条只规定"按下标清标志"与"发一次关光源请求"两件事，不把两者合并成一条机制。
- 标志与描述是**两件事**：只建模标志清 0 不等于建模了描述。⛔ 不许把清标志实现成清描述、也不许让请求的布尔为真。
- 请求的实参是**（下标, 假）**：⛔ 不许写成无参请求，也不许把"交给光源表的下标"原样当成两个实参。

### 转发到字体对象与宿主接口的入口：opcode 0x308 / 0x75 / 0x197 / 0x1a5 / 0x2fe

<!-- rule: CORE-OPS-FORWARD-PROLOGUE -->

这五条都读**一个**操作数，把工作交给**引擎持有的某个对象**的一个入口。按本族的三句话写：**交给谁 / 实参形态 / 引擎数据效果**。五条**不是同一条机制**（接收者、入口、实参形态都不同）。

| opcode | 交给谁 | 实参形态 | 引擎数据效果 |
|---|---|---|---|
| `0x308` | 引擎持有的**宿主接口对象**的一个入口（定位：那个入口会向平台库发请求）；它在"操作数的最低位"或命名键 **`system:LimitTouch` 的最低位**（**任一为 1**）时请求**注销**、否则请求**注册**（对象 = 一个输入设备窗口；两个平台入口是触摸窗口的注册 / 注销） | 引擎级的一个槽（窗口类句柄）＋ 操作数 | 该对象的一个字段 ← 操作数（注册 / 注销两支都写，连平台库加载失败那一支也写） |
| `0x75` | **字体对象**的「设置 **A 支字号**」入口 | 操作数（整型） | 该对象的一个**字号**字段 ← 操作数（缺省 24）；两份字体描述的**高度**字段 ← **操作数的相反数**；再按该对象的**对位模式**（即 `0x2db` 写的那一格；初值 0）决定那两份描述的**下一格**怎么写：**0 支** = 「操作数的一半取负」；**非 0 支** = 由一次**平台字体度量**写回（见下「非 0 支的下一格来自度量」）；随后**重建字体**（外部请求）。★ 这一列是**入口体写的值**；重建之后还可能被改写（见下「入口体写的值 ≠ 重建后的最终值」） |
| `0x197` | 同一个字体对象的「设置 **B 支字号**」入口 | 操作数（整型） | 另一个**字号**字段 ← 操作数（缺省 8）；**那支描述的两个变体**的高度字段 ← 操作数的相反数，同两个变体的宽度字段 ← 操作数的一半取负；该对象持有的**十个**文本槽的高度字段 ← 同一个操作数（无下标、无越界检查），字重字段 ← 该对象的**粗细**格（由 `0x2bd` 写：操作数非 0 ⇒ 700、0 ⇒ 0）；随后**重建字体** |
| `0x1a5` | 字体对象里「设置一个字符串」的入口 | 操作数（**按文本读**，不是整型） | 把这一支的**两份字体描述**都改成该字面名：描述一 ← 名字**原样**，描述二 ← `'@'` 前缀 + 名字；同时把两份描述的**高度**←（**当前这一支的字号**的相反数）、**下一格**←（该字号的一半取负）；随后**请求重建字体**（★ 表里这一列是**入口体写的值**；重建之后这两格还可能被改写，见下「入口体写的值 ≠ 重建后的最终值」） |
| `0x2fe` | 同一个字体对象里**另一个**「设置一个字符串」的入口 | 同上（按文本读） | 同上，但改的是**另一支**的**另一对**描述（`0x75`/`0x1a5` 与 `0x197`/`0x2fe` 各一对，互不覆盖） |

- **实参形态是合同的一部分**：`0x1a5` / `0x2fe` 读的是**文本**（把同一个操作数按整型读会得到另一件事）；`0x308` 除操作数之外还带**一个引擎级槽**（不是脚本给的 0）。
- **两条字符串入口不许合并**：它们写的是那个对象里**两对不同的描述** —— `0x1a5` 写 **A 支那一对**（与 `0x75` 同一对），`0x2fe` 写 **B 支那一对**（与 `0x197` 同一对）。⛔ 合并成"一个设名入口"会让改 A 支名字时把 B 支的名字一起改掉。
- **每对里的两份不是副本而是两个变体**：同一对的两份**高度与下一格完全相同**，只有字面名不同 —— 一份是操作数原样，另一份是 `'@'` + 操作数。⛔ 不许把两份写成"同一份的两个拷贝"（那会丢掉 `'@'` 这一份）。
- **这条入口顺带重算这一支的派生量**：它读**这一支自己的字号**（A 支读 A 支字号、B 支读 B 支字号）重写两份描述的高与宽 ⇒ 改名字**不会**改字号，但会把描述的高宽按当前字号重算一遍。改别的支的名字不影响本支。
- **`0x308` 读的命名键是 `system:LimitTouch`**：操作数最低位与它的最低位**任一为 1** ⇒ 请求注销，否则请求注册。它只读、不写这个键；键的写者不在本族的五条里。
- **`0x75` 的下一格由对位模式选两种写法**：对位模式 = 0（初值）走"一半取负"那支；`0x2db` 把它写成非 0 之后走另一支（度量）。⇒ 先 `0x2db(非 0)` 再 `0x75(n)`、与先 `0x75(n)` 再 `0x2db(非 0)`，写下的下一格不同 —— 后者是 `0x2db` 的**尾跳入口**按当时的对位模式**重算**了两份描述的高度与下一格（同一个派生例程，见下条）。
- **入口体写的值 ≠ 重建后的最终值**（四条字号 / 设名入口都成立）：
  - **入口体一律先无条件写**：该支两份描述的**高度 ← −该支字号**、**下一格 ← −(该支字号 ÷ 2)**。这一步**不看**对位模式。
  - `0x75` / `0x197` 的入口体在写完后再**自己按对位模式分岔一次**：= 0 ⇒ 直接请求重建；≠ 0 ⇒ 对该支两份描述各跑一次**度量派生例程**（见下条），再请求重建。
  - `0x1a5` / `0x2fe` 的入口体**不分岔**，写完就请求重建（A 支与 B 支各请求**各自的**重建入口）；**但重建路径自己按对位模式分岔**：≠ 0 ⇒ 对该支两份描述跑**同一个**度量派生例程、**覆写**高度与下一格；= 0 ⇒ 不再按度量覆写这两格（A 支上已逐字核到：重建先把两份描述的高度写成 −A 支字号、然后跳过那两次派生 ⇒ 下一格保持入口体写的 −字号/2）。
  - ⇒ **对位模式 ≠ 0 时，"−字号/2"不是最终值**（下一格由度量决定）；对位模式 = 0 时它才是最终值。⛔ 不许把"设名入口总是留下 −字号/2"当合同，也⛔ 不许把"重建什么都不改"当合同 —— 两支的差别在**重建之后**读那两格才看得出来。
- **非 0 支的下一格来自度量（不是算式）**：对位模式 ≠ 0 时，`0x75` 对**两份描述**各跑一次派生例程。**每一次派生发两次平台字体度量，量的不是同一个字体**：
  - **第一次量的是常量参考字体**（不是该描述的字面名）：字面名用常量 `ＭＳ ゴシック`、高度 = −该支字号、宽度 = −该支字号 ÷ 2、粗细取该对象的粗细格、字符集 = 默认，字符固定为 `0x8C83`。这一次的结果进该对象自己的**参考量度**（离屏文字路径做纵向对位时读的上升量就取自这里）。
  - **第二次量的是该描述自己的字面名**（高度 = −该支字号、宽度 = −该支字号 ÷ 2、同一个固定字符）—— **写回那两格的是这一次的结果**，不是第一次的。
  - ★ **两次量度用的字符都是常量 `0x8C83`，但"字符码"是例程参数，不是例程里的常量**：同一个量宽例程也服务**文字绘制路径**，那条路径传的是**实际被画的字形码**（可 < `0x100`）。本条这两次派生**只**走"传常量 `0x8C83`"那一支 ⇒ 在本条的路径上字符码**恒 ≥ `0x100`**，下面的**分岔永远落全角支、半角支在本条上不可达**。⛔ 不许把"半角支在本条不可达"改写成"例程里没有半角支"（它在绘制路径上是可达的），也⛔ 不许把"字符固定"写成"分岔无关"。
  - ⛔ 不许把两次写成"同一个字体的两次量度"，也⛔ 不许拿参考字体那次的结果当写回值。以下各条都指**第二次**量度：
  - **「半格」不是字号 ÷ 2**：它 = **参考黑框宽 ÷ 2**，其中**参考黑框宽**是该字体缓存里那个**参考字形**的黑框宽度；参考字形 = **常量参考面名 + 固定字符**、按**当时的 A 支字号**量的（不是该描述的字面名，也不随描述变）。★ **这个阈值用整数右移一位算**（向下取整）。⛔ 只有在"测得行高恰好等于字号"的字体上它才与"字号 ÷ 2"数值相同。
  - **哪一档会"再缩一次"：只有对位模式 = 1 那一档**；其它非 0 档**没有**半格判据、也没有再缩这一步。写回"下一格"与高度的算式按对位模式分两档，**两档的差别有两处**：
    - **对位模式 = 1 那一档**：
      - ★ **本档先按「这次要测的那个字符的字符码」分岔**：字符码（16 位无符号，**是例程参数**）**≥ `0x100` ⇒ 全角支**，**< `0x100` ⇒ 半角支**。⛔ 不许按"字体名 / 是否 CJK 区段 / 绘制模式"判。参照片是**另一个固定参照字符**的测量结果，它**只进比值、不进分岔**。
        ★ **在本条这条路径上两问都已定**：字符码来自**调用方传的实参**，而本条（`0x75` / `0x197` 的度量派生与重建路径）两次量度传的都是**常量 `0x8C83`** ⇒ **本档在这里恒走全角支，半角支不可达**。半角支只出现在**文字绘制路径**上（那条路径传给同一个量宽例程的是**实际被画的字形码**）；本条的两次派生**都不经过它** ⇒ 对本条而言半角支是一段**为完整性保留**的合同，不是发行路径；⛔ 不许因为"本条看不到"就删掉它，也⛔ 不许把本条写成"两种字符都可达"。
      - **半角字符**（码 < `0x100`；**本条不可达**，见上，合同仍成立）：高度**一律**重算成 `trunc(字号 ÷ 测得行高 × (−字号))`（向零截断），再用重算后的高度重新取一次本字形度量；"下一格" = **−测得的平均字宽**；若**本字形黑框宽 > 半格** ⇒ **再缩一次**：`下一格 = trunc(分子 ÷ 本字形黑框宽 × (−平均字宽))`，其中 **分子 = 参考黑框宽 × 0.5**。★ **分子与上面那个阈值是两个算式，⛔ 不许合并**：阈值是**整数右移一位**（向下取整），分子是**精确的一半**（浮点 × 0.5）—— 参考黑框宽为奇数时两者差 0.5，把两者写成同一个算式会在这种字体上分岔。
      - **全角字符**：**不重算高度**（保持 −字号：不新建字体、不重取文本度量、不重取字形）；"下一格" = `trunc(较小盒宽 ÷ 较大盒宽 × (−平均字宽))`，其中两个盒宽 = **本字形盒宽**与**参照盒宽**（取二者的**较小者当分子**）。★ **方向是合同**：写成"大 ÷ 小"会让全角字宽变成倒数值（> 平均字宽）。**不做半格判据**。⛔ 这里的两个盒宽是本字形与参照的，不许换成"参考黑框宽"。
    - **其它非 0 档**：只量一次本字体；"下一格" = **−测得的平均字宽**；**测得行高 > 字号**时高度才重算成 `trunc(字号 ÷ 测得行高 × (−字号))`。**没有**半格判据、**没有**"再缩一次"。
    - ⇒ 两档差别：① **半格阈值再缩只在 = 1 档**；② **高度重算的条件**（= 1 档对半角字符无条件、其它档只在测得行高 > 字号时）。
    - ⛔ 实现不得拿"字号 ÷ 2"冒充本条的阈值。
  - **回退**（三条判据，按下序判）：配置 `display:AspectMode` ≠ 0 ⇒ **不回退**、走度量；否则 ① 该对象的**对位模式 = 0** ⇒ 回退；② 该描述**自己存着的字面名**（跳过开头一个 `@` 后）**不在字体名表里** ⇒ 回退；③ 该字面名在表里的表项**第 0 位已置**（等宽）**且**它不属于 `IPA P` 系列 ⇒ 回退。回退 ⇒ **下一格 ← 高度 ÷ 2**（高度是负的 ⇒ 数值等于 −字号/2）、高度仍 ← −字号（不缩放）。此时数值与 0 支相同，但**写入路径不同**（度量请求已经发出）。
    - ★ ① 的**可达性**：本作的每个派生例程调用点都已经先判过"对位模式 ≠ 0" ⇒ ① 在发行路径上**恒不成立**（它是例程内部的冗余判据）。②③ 可达。⇒ ⛔ 不许据此把回退写成"只看 `AspectMode` 与名字"：合同是三条都判。
  - ⇒ 这一支的写入值是**平台输入**：同一字号、不同字体 / 不同平台可以不同。本版规定"发两次度量请求、写回哪两格、取自哪个量"；⛔ 不许把非 0 支写成"恒等于 −字号/2"（那会让对位模式变成一个没有效果的开关），也⛔ 不许把它写成"从操作数算出来的"。
- **名字要先过"可选字体名一览"**：两条设名入口都先拿字面名去查引擎的**可选字体名一览**（**与字体名查询指令查的是同一张表**，见「按名字查字体表」）；名字不在表里且不是 `AGE Extend` ⇒ 写一条**警告文本**（继续执行，名字照写）。随后把名字登记进字体对象的**两张字体名表**（同一名字不重复追加）—— ⚠ 那两张是**只装名字**的名字向量（一张原样名、一张 `'@'` 前缀名），**不是**上面那张带"等宽 / 非等宽"标志的字体名一览，别混成一张。
- **名字放不下时不截断**：入口把名字交给一个**有容量上界的边界检查拷贝**，容量 = **32 字节（含结尾的 NUL ⇒ 放得下的名字最长 31 字节）**；引擎**不预检、不截断**。放不下（**长度 ≥ 32 字节**）时那个拷贝走**非法参数**处置 —— 默认后果是**立即终止进程**（不返回、不截断、也不"只丢掉长的那半"）。★ 这属**平台边界**：引擎发出的请求是"把一个 NUL 串拷进那个定长名字字段"，后果由运行库的非法参数处置决定；本版只钉"请求形态 + 容量 + 默认后果"，⛔ 不许实现成"截到容量上界减一字节"，也⛔ 不许实现成"静默跳过这次设名"。
- ★ **字体对象持有两张「已登记名字」表，它们是同一次登记的两种取向形态，不是同一张名单的两份拷贝**：一张收**原样名字**、另一张收 **`'@'` + 名字**（`'@'` 前缀是平台面名的竖排形态）。
  - **每次设名入口执行时两张都写**：各自**去重追加**（同一名字不重复追加），元素只有名字、**没有**标志字节。
  - 两张表的**第 0 项是字体对象建立时写入的默认名字**（原样那张是默认面名、`'@'` 那张是它的 `'@'` 形态）⇒ **查重与查找都从第 1 项开始，第 0 项永不参与匹配**。
  - **读者是两条文本输出路径，各读自己那一张**：它们按**当前字面名**在表里线性查找，命中的项**下标**（从 1 起算）被用来组织一次以该名字为键的查表请求。⇒ 这两张表**不参与字体选择**：改它们只改这两条路径的键，不改画字用的字体。
  - ⛔ 它们**不是**「可选字体名一览」（那张是启动时枚举系统字体填的、每项带字宽族字节、按名字查下标，见「按名字查字体表」）。
- ★ **字体对象有一个抗锯齿开关（构造期初值 0），它是可写的，不是死格**：
  - **初值来源**：启动期先读配置总闸 `set:EnableAntiFont`；**只有总闸非 0** 时，才把配置命名键 `message:UseAntiFont` 的值写进这个开关（总闸为 0 ⇒ 开关保持构造期的 0）。该键在存储里**有内建默认值 1**（构造期登记）⇒ 正常装载后它**不是"缺键读 0"**；"缺键"只在存储被白盒删掉键时出现，那时按「配置」章的读取器合同读作 0。
  - **服务入口写两处，两处的值不完全相同**：引擎对外的服务接口有一个入口，它做两件事且顺序固定 —— 先按"非 0 ⇒ 1"**归一**后把值写进配置键 `message:UseAntiFont`，再把**原值**写进这个开关。开关只在"= 0 / ≠ 0"上被读 ⇒ 两处数值不同不产生行为差别，但⛔ 不许把两处都写成归一值。另有一个带窗口句柄的初始化入口也写这个开关（它把什么值传进去**未取证**）。
  - **写它还会连带清状态**：值**变化**时（相同值不重复动作）⇒ 重建字体、清空该字体对象持有的两张文本键表、清空两段字形缓存、并做一次字形缓存重建请求。⇒ 改这个开关是**可观察的**。
  - ⇒ 「开关非 0 时绕开 A/B 两支」**可达**（配置总闸非 0、且把配置键置 1 即可），⛔ 不许再写成"唯一写者是构造期 / 疑似不可达"。
- ★ **开关非 0 时换掉的是整条文字绘制路径（不是某一处外观）**：本版把全引擎里"按这个开关是否为 0"的 **45 处**读点**逐处归了类**，全部落在下面 **8 个族**上（写者自己那一处不计入）：
  - **字形面格式**：关 ⇒ 字形位图取**单色**；开 ⇒ 取**灰阶**，位数由字体对象上的**灰阶位深档**决定（档 = 1 ⇒ **8 位**；档 = 其他值（含初值 0）⇒ **4 位**）。该档**构造期写成 0**；另有一个写点：**进程启动时的那一条"应用设置"入口**在**抗锯齿总开关 `set:EnableAntiFont` 非 0** 时把配置键 `message:AntiFontLevel` 的值**原样**写进这一格（与"抗锯齿开关"的初值抄写**同一入口、同一道闸门**，且**写在开关之后**；写这一格本身不重建字体、不清缓存）。⇒ **8 位档在发行态可达**（总开关非 0、子开关非 0、级数 = 1），灰阶支**两档都可能**。⛔ 不许把这格写成"构造期之后无写者 / 8 位档不可达"（旧文那句已被这个写点推翻）；也⛔ 不许把这一格与抗锯齿开关本身合并（两格、两个写者）。运行期设置提交**不**碰这一格 ⇒ **运行期改级数不改变本次会话的位深**（改开关则立即生效）。它与上面两个抗锯齿开关**不是同一格**，见「渲染请求边界」的「离屏文字：opcode 0x204」条）。
  - **字形框宽**：关 ⇒ 框宽**原样**；开 ⇒ 框宽**上对齐到 4 的倍数**。
  - **逐字 vs 整串（主流）**：关 ⇒ **一次整串**交给平台文本输出；开 ⇒ **逐字形**循环（再按"是否描边模式"分岔）。
  - **逐字纵向步进**：开且绘制模式 ≠ 0 时，每一个字形的**纵向步进多加一格**；关时不加。
  - **位置补偿**：**只在「开关关 且 绘制模式 = 3」**时，两个位置分量各**减去一对分量之比**（横 / 纵各用自己那一格的分母）；其它任何组合都没有补偿。那对分量是**描边对角偏移**（见下「描边对角偏移」）。
  - **字体选择**：开 ⇒ 在另一个格为 0 时，把该对象持有的一个字体选进文本绘制设备；关 ⇒ 不选。
  - **覆盖率 → 逐像素写入（覆盖率当不透明度）**：这一族与开关的关系是**只换覆盖率样本的取法**，不是"关就不做" —— 两支之后走**同一段**写入：
    - 开关**关** ⇒ 覆盖率样本 = **单色位图的那一位**，只有 0 / 1（1 即满覆盖）；
    - 开关**开** ⇒ 覆盖率样本 = **灰阶样本的整字节**，值域由下面的**灰阶位深档**决定（一档 0…16、另一档 0…64）。
    - **归一**：`覆盖值 = 原始级数 × 255 ÷ 除数`（整除、向下取整），`除数 = 该档样本上限 + 1`（0…16 那档 = **17**、0…64 那档 = **65**）；关那一支的 1 **直接就是满覆盖 255**（不除任何除数）。每通道 **4 位**的目标面（16 位表面）再把覆盖值**右移 4 位**降到 0…15，每通道 **8 位**的目标面（32 位表面）直接用归一值（0…255）。⇒ 各档的**满覆盖**分别是 **255（单色）/ 240（0…16 档）/ 251（0…64 档）**；⛔ 除数不是 2 的幂（16 / 64）—— 按 2 的幂算会把灰阶档的满覆盖抬到 255，灰度字比引擎亮一档。
    - 之后与「离屏文字」条的覆盖率合同是**同一段写入**：★ **降位在短路判据之前** —— 16 位表面先把覆盖值**算术右移 4 位**成**通道值**（0…15），再拿**通道值**判短路；32 位表面的通道值**就是**覆盖值。三条短路一律判**通道值**（⛔ 不是判覆盖值）：**通道值 = 0** ⇒ 一个字节都不写；**通道值达该面的通道满量**（16 位面 = 15、32 位面 = 255）⇒ 直写源色、**不读目标**；**读了目标之后目标的不透明度 = 0** ⇒ 直写源色。⇒ 之后**逐通道**（由低位到高位）`结果通道 = (源通道 × 通道值 + 目标通道 × (通道满值 − 通道值)) ÷ 通道满值`，**输出的不透明度 = max(目标, 通道值)**。★ 若把判据写成"覆盖值达通道满量"，16 位面上的短路 ② **永不成立**（覆盖值满量是 240 / 251，通道满量是 15）；若写成"覆盖值 = 0 才不写"，16 位面上覆盖值 15（灰阶最小非 0 级）会被错写成像素。⛔ 不许在实现里写两份（两份必然漂）。
  - **旧式绘制路径**：关 ⇒ 整串交给**旧式绘制对象**输出；开 ⇒ 走新路径（不调用旧式对象）。
  - ⇒ ⛔ 不许把这条开关实现成"只影响抗锯齿位"：45 处读点分布在 8 个族里，任一族漏掉都会让"开"与"关"在可观察请求上分不开；也⛔ 不许把"关"实现成"同一套绘制的两种外观"。
- ★ **描边对角偏移（合同）**：字体对象上有一对**整数偏移量（横 / 纵分量，初值 1 / 1，单位 = 未缩放像素）**，旧式文本路径按**对角四向**用它：
  - 绘制模式 = 0 ⇒ 不偏移，只画一遍；
  - 绘制模式 ∈ {1, 2} ⇒ 只按 (+横, +纵) 偏移，画一遍；
  - 绘制模式 = 3 ⇒ 按 (+,+) / (−,−) / (+,−) / (−,+) 四个对角**各画一遍**（这就是描边）。
  另一条（逐字 / 位图）路径上，这对偏移量被**读两处、作用不同**：**取源块**时按「绘制模式 > 0」把它加进**整数源矩形的宽 / 高**（与抗锯齿开关无关，两支都做；那对整数已经乘过适配比）；而**目标坐标**始终 = 记录给的基准点 + 记录自带的两格 —— 偏移量**从不加进目标坐标**。只有「绘制模式 = 3 且抗锯齿关」这一支才另做一次折算：偏移量各自**除以对应方向的显示适配比**，再从**目标坐标**里**减去**；其它组合都不做这项折算与扣除。⇒ 同一份记录、同一趟里，"开"与"关"两支交给绘制请求的目标坐标只差 `(−横偏移 ÷ 横比, −纵偏移 ÷ 纵比)`（横纵各用自己那一格分母）："关"把同一个字形放在比"开"更靠左上 `偏移 ÷ 比` 的位置。
  这对偏移量**不是配置项**：构造期写 1 / 1，运行期只有"从绘制设备回读"一条写路径（回读发生在它与设备不一致时）。
- ★ **显示适配比（合同）**：字体对象上有一对**浮点比值（横 / 纵）** = 当前显示尺寸 ÷ 基准尺寸（即下一条那对"宽分量 / 高分量"），1.0 = 不缩放；构造期 1.0 / 1.0。重算条件与算式见下「字号是"未缩放"的量」—— 两个分量各自与上次比、**两个都相等 ⇒ 整趟什么都不写**；重算后把同一对值**同步给全部绘制设备**（设备上另有一份副本）。它不是字体度量，⛔ 不许与"字号 / 字宽 / 行高"混为一谈；折算用的分母**必须**是对应方向的那一格（横用横、纵用纵 —— 互换 ⇒ 视频比例不为 1 时两向补偿量都不对）；⛔ 不许每帧重算（重算会连带重建字体与清缓存，是可观察的）。
- **不改脚本可观察数据**：五条都不写任何池、不写帧、不写列表记录，也不把返回值写回操作数（`0x308` 的返回值由分派器丢弃）。
- `0x75` / `0x197` 的**引擎数据效果在接收者内部**：它们不是"纯转发"。⛔ 不许把五条都写成"什么都不做"。
- ★ **两支是同一个字体对象的两套字号**：**A 支**（`0x75`，缺省 24）是**把文字画进纹理那条路径**（`0x204`）出字形时用的高度；
  **B 支**（`0x197`，缺省 8）只在「画一段已排版的文本记录」那条路径（以及与之同源的记录输出路径）被选中。两支各有缺省、能单独改、互不覆盖。
  ⛔ **不许**把 A 支当成"行高"：界面脚本里"每行前设一次行高"就会顺手改掉画字用的高度，同一页里字号会跟错格。
- **每次绘制用哪一支**：把文字画进纹理那条路径（`0x204`）**总是用 A 支**（它按 A 支的字号建字形字体）；
  普通文本那条（`0x196`）的**主文本**段也选 A 支；★ 但它在**同一条指令里画的振り仮名**走**另一条**输出路径、
  传的是"选 B 支"的那个实参 ⇒ **振り仮名用 B 支**（见「文本层的正文追加与行结束」）。
  **记录绘制那条按「被画记录自己标志的第 2 位」选支** ——
  置起 ⇒ B 支、否则 A 支。这个位**不是 `0x82` 的操作数**，而是**追加记录的那条路径**写进去的：
  **振り仮名 run**（振り仮名串非空）与**层处于另一个模式时的逐字支**（见「ADV 文本」条）会把它置起；
  **主线正文 run** 不置起（位 2 = 0）⇒ 主线正文记录按 A 支画。
  ★ 这个标志的**低两位在写入侧携带的是什么，本版不写成合同**：观察到的只是"追加器把**当时收到的标志参数**原样写进记录"（振り仮名那条把标志写成「绘制模式」后再置起第 2 位；另一条正文追加器把收到的参数原样传下去），而"那个参数**就是**绘制模式"这一步**尚未取证**（见残差 `RES-OPS-TEXT-SPAN-FLAG-1`）。⇒ 正文只把**读取侧**写死：位 0 只作「**新段起点**」（**只在下一条**记录上被测）、位 1 只作「与操作数位 0 联合的跳过判据」 —— 位号与位义只有一张表，见「字符串」的「画一段已排版的文本记录」条；⛔ 不许把"低两位 = 绘制模式"写成读侧合同，也⛔ 不许把位 0 / 位 1 写成模式位。
  ⇒ 「位 2」**不是**"用了 B 支字号"的独立开关，它是"这一记录要按振り仮名（竖排字形）画"的标记 —— 由**两次排版层追加**（振り仮名 run、层处于另一模式时的逐字支）在标志上**恒置起**，主线正文 run 不置起；
  ⛔ 不要把它实现成"绘制模式的一部分"（绘制模式本身是字体对象的一格，不是这条记录的字段）；写入侧若把 ≥ 4 的绘制模式当标志传下来，位 2 会被模式字自己带起来 —— 那是写侧的副作用，不是"用 B 支字号"的独立开关。
  ★ 记录存的是**标志不是字号**：
  真字号取字体对象的活句柄，所以"追加之后、绘制之前"改 B 支字号会让已追加的振り仮名按新字号画 ——
  但**布局格仍按追加时的量度**（改字号只改字形，不重排）。
- **字号是"未缩放"的量**，缩放乘在**建字体**那一步：`高度 ← trunc(高度 × 比例 + 0.5)`
  （`trunc` = **向零截断**。高度本身是负值（字号取相反数），所以"先加 0.5 再向零截断"在负值上等价于**向上**取整 —— ⛔ 不要实现成"四舍五入到整数"，两者在负值上差 1；加的是字面常数 0.5，不是平台默认的取整）。
  比例 = **视口高 ÷ 配置的客户区高**（配置来自 `set:WinY`），初值 1.0；
  **只在窗口态且虚拟全屏类型 = 2 时**按上面这个商重算，**其余情况一律记 1.0**
  ⇒ 视口等于客户区尺寸时恰好 1.0。**视口的实际数值是平台输入**：本版规定算式与取整，具体数值随平台。
  ★ 这一对分量就是上文「显示适配比」：高分量（纵向）乘进字号缩放，宽分量（横向）不参与字号缩放、只作为横向的折算分母与设备副本。
- 同一趟还会算出**一个宽分量**（= 视口宽 ÷ 配置的客户区宽）：它**不参与字号缩放**（缩放只乘高度），
  但会**连同高分量一起**再抄一份进十个文本槽的两格（与"绘制原点偏移"不是同一对格）。★ **哪一格放哪个分量是合同**：
  十个槽里**前一格 ← 宽分量、紧邻的下一格 ← 高分量**（与字体对象自己缓存那两个分量同一顺序：缓存也是宽在前、高在后）。
  ⛔ 不许把两者对调 —— 对调不会报错，只会让所有文本槽的横向 / 纵向比例互换。
  两个分量各自和"上次算出的那个"比，**两个都相等 ⇒ 整趟什么都不写**（不重抄槽、不重建字体）。
- 重算发生在两个时机：① 启动、字体对象建立之后一次；② 引擎**重新应用字体设置**的路径里。
  ⛔ 不要把它和「显示适配」的缩放混成一个：那一套按后缓冲与参考尺寸算，重算时机也不同。
- **每支各喂自己的那份字体描述**（每支两份）：⛔ 不要合并成"一份字体设置"；
  每支一对描述、每对两份（见上「两条字符串入口不许合并」）：**哪条设名入口写哪一对已经定死**（`0x1a5` → A 支那对、`0x2fe` → B 支那对），⛔ 不要再按字面名的写法去猜。
- 平台侧的行为（窗口是否真的注册、字形是否真的建出来）**不在本版**：它们属于平台与呈现模块。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| `0x308` | 宿主接口封装对象的一个字段 ← 操作数；一次平台请求（注册 / 注销输入设备窗口） |
| `0x75` / `0x197` | 字体对象的 **A 支字号** / **B 支字号**字段 ← 由操作数派生（两组不同的格）；一次字体重建请求（`0x197` 还会把十个文本槽的高度一起写成同一个值）。字号本身的缩放比另有一格（见上「字号是"未缩放"的量」） |
| `0x1a5` / `0x2fe` | 该支两份描述的字面名 ←（原样 / `'@'`+原样）；该支两份描述的高 ← −字号、下一格 ← −字号/2；一次字体重建请求 |
| 描边对角偏移（横 / 纵） | 字体对象上的一对整数（初值 1 / 1，单位 = 未缩放像素；运行期只从绘制设备回读） |
| 显示适配比（横 / 纵） | 字体对象上一对浮点比值（当前显示尺寸 ÷ 基准尺寸）；设备上有另一份副本 |
| 灰阶位深档 | 字体对象上的一个整数（初值 0 ⇒ 4 位档；启动期「应用设置」入口在总开关非 0 时抄入级数键 ⇒ 键 = 1 时 **8 位档**） |

**成立条件**

- 读操作数**只有一次**；`0x308` 读完之后才读那个引擎级槽。
- 这五条的操作数都**不做范围检查**。
- **重建请求之后的过程属实现侧**（引擎内部怎么重建它持有的字体、平台怎么建字形、逐位结果怎样）不在本版；可观察的是**请求发生**与**本条写下的那几格**。⛔ 不许把"内部不建模"写成"没有写"。
- 半角 / 全角的分岔**只看字符码**（16 位无符号，`0x100` 是边界）；⛔ 不许按字体名 / 区段 / 绘制模式判，也⛔ 不许让参照字符参与分岔。
- 全角支**必须**跳过"重算高度 + 重建字体 + 重取度量"这三件；做了 ⇒ 高度会被压成半角支的换算值。
- 「较小 ÷ 较大」的**方向**是合同：⛔ 不许写成"较大 ÷ 较小"（那会让全角支的宽度变成倒数）。
- 「半格」判据**只在半角支**里出现；全角支做了它 ⇒ 两支被混成一支。
- ⛔ 不许把「减」实现成"抵消之前加过的偏移"：目标坐标里**从来没有**加过那对偏移量。判据：把偏移量从 1 改成 2 再比较目标坐标，位移差必须**恰好**是 `1 ÷ 比`（一次相减）；差是它的两倍 ⇒ 有人加过一次。
- 那对偏移量在这一支里**两条路都读**（取源块 + 折减目标），但**只在一个方向上进目标坐标**（减）；⛔ 不许实现成"加进目标、也不再取源块"。
- 那对偏移量**为 0** 时，绘制模式 = 3 的两档（抗锯齿开 / 关）目标坐标必须**逐位相同**；不同 ⇒ 折算路径在 0 上不闭合（分母或符号取错）。
- 覆盖率那一族**只有一处样本取法分岔、只有一段写入**：⛔ 不许把"抗锯齿关"实现成跳过这段写入，也⛔ 不许给两支各写一份混合算式。

**可证伪**

- **本条路径上半角支不可达，所以下列三条分岔判据要白盒构造**（⛔ 发行态下它们**不可证伪** —— 本条两次量度传的都是常量 `0x8C83`）：
  - **白盒**：把派生路径传给量宽例程的实参改成半角码（如 `0x41`）⇒ 必须先按半角支重算高度再定下一格；若高度没变 ⇒ 分岔没按字符码判。同一白盒下改回 `0x8C83` ⇒ 必须走全角支。
  - **白盒**：边界两值 `0xFF` / `0x100` 必须在**同一边界**两侧分岔；若 `0xFF` 也走全角支 ⇒ 判据写成了 `> 0x7F`。
  - **白盒**：半角支里让"那一格的一半"大于本字盒宽 ⇒ 下一格宽必须**等于 −平均字宽**（不覆盖）；小于 ⇒ 必须按比值式覆盖。两种情况给出同一个值 ⇒ 附加判据没实现。
- **发行态可证伪的两条（只覆盖全角支）**：
  - 造一个"本字盒宽 < 参照盒宽"的字符与一个"本字盒宽 > 参照盒宽"的字符：两者的**下一格宽都是负值**，且**绝对值都 ≤ 平均字宽**；若其中一个的绝对值 > 平均字宽 ⇒ 比值方向反了（写成了大 ÷ 小）。⛔ 判据是**绝对值**，不是"≤ 平均字宽"（下一格是负值，逐字比较会把反号的那支也判成通过）。
  - 全角支执行前后，字体的高度参数与文本度量必须**逐字不变**；变了 ⇒ 全角支里多做了半角支的三件事。
- **（白盒插桩）**参照字符换成另一个固定字符（同一实现内改常量）：两支的**分岔结果**必须完全不变（只有比值变）；分岔结果变了 ⇒ 参照字符被拿去判半角 / 全角了。
- 把横 / 纵偏移量改成不同的值（例如 2 / 0），绘制模式 = 3 且抗锯齿关：两个方向必须**分别**按各自的适配比折算相减；若两向用同一个比值 ⇒ 分母取错。
- 同一组偏移量、绘制模式 = 3 但**抗锯齿开**：必须**不**折算、**不**扣除（只按 (+横, +纵) 平移一次、共一遍）；若仍扣除 ⇒ 把"只在关时补偿"写成了"模式 3 一律补偿"。
- 绘制模式 = 2 且抗锯齿关：必须**不**折算、只加一次；若出现四遍 ⇒ 把"只有模式 3 才四遍"写错了。
- 显示尺寸设为基准尺寸（适配比 1.0）：补偿量与"不折算"相同；不同 ⇒ 适配比没参与运算（或参与方式不是除法）。
- 让显示尺寸从基准值变一次：全部绘制设备上的那一对副本必须**同一次**更新；只有一部分变 ⇒ 适配比没有同步给设备组。
- 灰阶档：总开关非 0、子开关置 1、级数键置 1，重启后画一段文本（抗锯齿开）⇒ 字形位图必须是 **8 位灰阶**；级数键置 2 或删掉该键 ⇒ 必须是 **4 位灰阶**。恒为 4 位 ⇒ 漏了启动期把级数键抄进**灰阶位深档**这一步（旧文"8 位档不可达"已被推翻）。★ 运行期改级数键**不**改变位深（只有下次启动才生效）—— 运行期一改就变 ⇒ 把该格实现成了"每次绘制重读配置"。
- 绘制模式 = 3、偏移量 (1, 1)，把**横**偏移改成 2（纵不动、适配比不变）：目标横坐标必须**只**向左多走 `1 ÷ 横比`（纵坐标不变）；多走两倍 ⇒ 有人把偏移加进过目标坐标；纵坐标也动 ⇒ 两个方向的分母被混用。
- 偏移量置 (0, 0)、绘制模式 = 3、抗锯齿关 ⇒ 目标坐标必须与"抗锯齿开、同偏移量"逐位相同；不同 ⇒ 折算在 0 上不闭合。
- 覆盖率：抗锯齿**关**、在**每通道 8 位**的目标面上写一位"置起"的像素 ⇒ 该通道的不透明度必须是 **255**；得到 240 ⇒ 把"关"那一支也送进了灰阶归一化（单色位图没有除数）。同一像素改在**每通道 4 位**的面上写 ⇒ 该通道必须是 **15**（= 255 右移 4 位）。
- 覆盖率：灰阶档取"0…16"那一档、样本给满值（16）⇒ 覆盖值必须是 **240**（该档满覆盖）；得到 255 ⇒ 除数是 16（2 的幂），灰度字会亮一档。
- 覆盖率：灰阶档取"0…16"那一档、样本给 1（最小非 0）⇒ **每通道 8 位**的面上必须**写出**一个不透明度很小的像素（不是跳过）；跳过 ⇒ 把"通道值 = 0 才跳过"写成了"通道值很小也跳过"。★ 同一个样本在**每通道 4 位**的面上**必须跳过**（覆盖值 15 右移 4 位 = 0）—— 在 4 位面上写出了像素 ⇒ 拿覆盖值而不是降位后的通道值判了短路。

### 文本槽的绘制原点偏移：opcode 0x198

<!-- rule: CORE-OPS-FORWARD-TEXT-SLOT -->

字体对象持有**十个文本槽**，每个槽除了自己的高度（那十格由 B 支字号一起写入），还有**一对绘制原点偏移**。`0x198` 有三个操作数：
第一个是**槽下标**，第二、三个是加到这个槽的绘制原点上的**横向 / 纵向**偏移。

- 槽下标的 `0` **不是第 0 个槽**，而是"默认槽"（= 第 1 个槽）；槽 0 本身不可达。合法下标 0..9。
- 它**只**写这两个偏移：不改 A 支 / B 支字号、也**不重建字体**。
- 下标越界在引擎里**不做检查**：它会拿越界下标去索引字体对象里的**槽指针表**，取到的指针非 0 就写穿到该指针所指处 —— 这是**未定义行为**，本版不作语义断言。**建议**实现把它记为诊断（例如中止）；本作的实现选择是**直接返回、不写、不诊断**，登记为实现侧已知偏离。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个文本槽的绘制原点偏移 | 该槽的两个偏移字段 ← 第 2、3 个操作数 |

**成立条件**

- 偏移是在矩形**已经乘过显示缩放之后**才加进绘制原点的（"设计像素还是设备像素"本版未定）。
- ⛔ 不许把它写成"改字号"：它的接收者与 `0x197` 是同一个对象，但写的是**另一对格**，两条指令互不影响。

### 切换显示模式：opcode 0x2cf

<!-- rule: CORE-OPS-FORWARD-DISPLAY-MODE -->

`0x2cf` 有一个操作数，读成**目标显示模式**（0 = 窗口 / 1 = 全屏）。目标不在 {0,1} ⇒ 本条**什么都不做**（不报错、不改任何格）；否则把它交给引擎的**显示模式入口**，由那个入口决定这一次到底换不换。

入口先看引擎的**显示模式缓存**（`0x2ce` 读的就是这一格），并在两种情况下**什么都不做、一个键都不写**：

1. 命名键 `display:ForceScreen` 为 1 且缓存非 0（强制全屏）；
2. 目标等于缓存（请求已满足；"目标 0、缓存 0"也属于这一支）。

其余情况：缓存 ← 翻转值（旧值 0 ⇒ 1，否则 ⇒ 0；在"目标 ∈{0,1} 且目标 ≠ 旧值"的前提下等于"缓存 ← 目标"），随后向平台发一组窗口重建 / 分辨率请求，最后把命名键 `display:ScreenMode` 写成**归一后的**新缓存（非 0 ⇒ 1）。此外，`set:SaveWinPos` 为真且**旧缓存**非 0 时，入口还会写窗口位置两个键。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 显示模式缓存 | ← 目标（只在"目标 ≠ 旧值"且未被强制全屏吞掉时） |
| 命名键 `display:ScreenMode` | ← 归一后的新缓存（只在更换路径的尾部） |
| 窗口 / 分辨率 / 外部资源 | 一组平台请求（请求本身可观察；平台细节不在本规则） |
| 窗口位置两个键 | 条件写（`set:SaveWinPos` 且旧缓存非 0），值取自平台窗口 |

**成立条件**

- 它**读缓存、不读 `display:ScreenMode`**；键只在更换路径末端被写 ⇒ 早退之后两者可以不一致。
- 写进键的是**归一后**的值（非 0 ⇒ 1），不是目标原值；本版的缓存只取 0/1（见「配置」的「读显示模式缓存」），所以在这里两者数值相同，但写的是归一值而不是目标。
- 目标越界是**静默**的：不抛、不记日志、不改缓存、不写键。
- 平台细节（窗口重建、整窗尺寸、外部资源重载、窗口位置两键的具体取值）**不在本规则**：本版只登记"发生了这些请求"。

### 设一个命名键（点击跳过效果开关）：opcode 0x307

<!-- rule: CORE-OPS-FORWARD-NAMED-KEY -->

`0x307` 有一个操作数。它把命名键 `system:EffectSkipOnClick` **设成该操作数**（原值），然后返回 —— 返回值由分派器丢弃。`0x306` 读的是**同一个键**。

- 写入**不归一**：写 3 就存 3（不像某些开关入口那样折成 0/1）。
- 写入口只覆盖**已存在的键**：键不在存储里 ⇒ 发**一次带该键名的模态错误提示**、**不创建键**、不改任何东西、返回"没写成"（同一机制，见「设一个命名键：opcode 0x1ca」）。
- 入口与 `0x1ca` 是同一个"设置一个命名键"入口，只是键不同。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 命名键 `system:EffectSkipOnClick` 的当前值 | ← 第 1 个操作数 |

**成立条件**

- ⛔ 不许实现成"缺键即创建"：那会造出词表里没有的键，「保存」写出什么也会跟着变。
- 该键是**构造期登记的内建默认**（初值 0），不依赖发行默认表或玩家文件：正常装载后总是存在，所以本条写**不会因缺键被拒**；上面"不创建键"那一支只在存储被白盒删掉键时才可达（对照「配置」的「读点击跳过效果开关」）。
- 操作数类型不符时抛操作数类型异常，且**不写**（读在写之前）。

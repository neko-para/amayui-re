## 存档：写入 / 恢复 / 归属

本章 6 条规则。

### 槽的身份：槽号 → 一对文件

<!-- rule: FMT-SAVE-SLOT -->

存档槽由一个**整数槽号**标识。引擎按"存档目录 + 槽号"构造文件：
主数据文件名为 `SAVE<槽号>.DAT`，缩略图文件名为 `SAVE<槽号>.STH`；
槽号以**十进制、至少两位、左补 0** 写出（三位以上的槽号照写；负槽号按带符号十进制写出，其后果见残差）。
**槽号不做范围检查**：越界槽号不报错，只是构造出另一个文件名。

一个槽在"删除"与"复制"里是**一对文件**：两个文件都处理，先主数据、后缩略图；
但**写入**是两条独立指令 —— 写槽数据不产生缩略图，写缩略图也不写槽数据。
主数据写入成功之后，引擎还会顺带重写**系统数据文件**（系统容器的格式本版未成篇）与另一份运行期文件；
两者的具体格式 / 判据不在本版。删除 / 复制**不**触发这次重写。

**条件**

* 槽号来自该指令的第 2 个操作数（按整型读）。
* 另有"按名字直接打开存档"的指令变体：名字 → 路径的解析由文件子系统负责，不经过槽号。
* 目录前缀由文件子系统给出（本版不规定它的搜索规则）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 槽号 | 指令操作数（整型）；不落任何池 |
| 一个槽 | 目录下的一对文件 |

### 292 字节文件头与头部校验

<!-- rule: FMT-SAVE-HEADER -->

存档主文件以一个**固定 292 字节的头**开始；字段按字节偏移固定：

| 偏移 | 宽度 | 内容 |
|---|---|---|
| 0 | 4 | **魔数**：本作为 `S4SD`；同一引擎的另一族为 `S3SD` |
| 4 | 4 | **版本串**：4 字节，原样写入（样本里是 `460B`） |
| 8 | 232 | **游戏标题**：NUL 结尾的字节串（样本里是 `天結いキャッスルマイスター`） |
| 240 | 4 | **解压后（未变换）负载的字节数** |
| 264 | 16 | **存档时刻**：本地时间 8×u16 = 年、月、星期、日、时、分、秒、毫秒 |
| 280 | 4 | **游戏时间**（秒） |
| 284 | 4 | **存档格式版本 1** |
| 288 | 4 | **存档格式版本 2** |
| 244…259 | 16 | 保留（写 0） |
| 260 | 4 | 保留（写 0；补满 240–264 的保留区） |

**头部校验**：读回时必须**成功读满 292 字节**（负载可以更长），且魔数等于引擎期望值、第 8 字节起的标题等于引擎自己的标题串；
否则判"这个文件不是本游戏的存档"，**不恢复任何状态**。头**没有**自校验和，`+240` 也不参与边界判断
（它是负载的未变换长度，不是头部长度）。

**条件**

* 魔数取自引擎里的一个 2 字符"族标识"：族标识等于 `S4` 时魔数为 `S4SD`，否则 `S3SD`。族标识本身是数据（残差）。
* 时刻是保存当时的**本地时间**（含星期与毫秒）；游戏时间是"自本局开始累计的秒"。
* 版本字段**不在头部校验里**；它们由负载读取阶段比较（见 `FMT-SAVE-ENVELOPE`）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 存档时刻 | 头 `+264`（本地时间 8×u16） |
| 游戏时间 | 头 `+280`（秒） |
| 标题 / 版本串 / 族标识 | 引擎里的字符串状态（运行期状态；布局属机器细节） |

### 负载信封：参数块、变换、校验与版本门

<!-- rule: FMT-SAVE-ENVELOPE -->

校验和 / 变换 / 压缩算法与负载字节布局见 `FMT-SAVE-CODEC`；本节只写参数块与读取顺序。

292 字节头之后是**20 字节参数块**，按 **5 个 32 位槽**解释：
负载的 32 位字数、校验和 1、校验和 2、32 位随机种子、随机键（第 5 槽只用低 16 位；后两项保存时随机生成）。
参数块之后是**负载本体**，长度 = 参数块第 1 字 × 4 字节。

负载以**变换形式**存放（本样本里未变换 4.3 MB 的负载只占约 1 MB）。读回顺序与判据：

1. **版本门**：文件头的版本 1/2 必须等于引擎当前期望值；唯一例外是"文件版本 1 == 2 且期望版本 1 == 2"，此时**不比较**版本 2。
   通过后，文件里的两个版本回写进文件子系统的状态。
2. **两个校验和**都覆盖变换后的负载；任一不符 ⇒ 拒绝（报错）。
3. **解密**：用参数块里的种子与随机键解密；失败 ⇒ 拒绝。
4. **内层**：版本字段 1 的值 < 2 时，解密结果自带 2 字校验头，数据在校验头之后；版本字段 1 的值 ≥ 2 时，解密结果先解压，
   解压结果再带 2 字校验头。内层两个校验和都必须通过。

负载之后**允许**有一段尾段；槽读取的"普通"变体不读它，"完整"变体读它（见 `FMT-SAVE-RESTORE`）。

**条件**

* 期望版本来自两个配置键（`set:SaveVersion1` / `set:SaveVersion2`），不是来自文件。
* **密文字节数**（`4 × 参数块第 1 槽`）不得超过 `2 × (头 +240 + 24)`（超了 ⇒ 拒绝）：这是读取缓冲的边界判据。`+240` 是**解压后（未变换）**长度，不是密文长度；24 字节余量 = 12 字节压缩段前缀 + 内层 8 字节头 + 4 字节余量。
* 校验和 / 变换 / 压缩 / 内层头的算法见 `FMT-SAVE-CODEC`；本条不再把它们推给实现。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 负载长度（变换后） | 参数块第 1 字 × 4 |
| 文件版本 | 头 `+284/+288` → 文件子系统状态 |
| 随机种子 / 键 | 参数块第 4 / 第 5 个 32 位槽（保存时生成，不来自任何游戏数据） |

### 槽负载的块结构：哪些状态被持久化

<!-- rule: FMT-SAVE-BODY -->

负载块与帧记录的字节布局见 `FMT-SAVE-CODEC`；本节只写持久化字段集合与判据。

槽负载（版本字段 1 = 2 / 3 的容器）由以下部分**按序**组成（字段集合，逐格顺序见 `FMT-SAVE-CODEC`）：

1. **主体当前帧号**（负载起点 + 8 的第 1 字；不是负载第 1 字，负载前 8 字节是内层校验头）；
2. **定长副块**（40 B / 1200 B；内容本版不规定）；
3. **每帧一条记录**（按帧号索引，宽度固定）：该帧的**脚本文件索引**（脚本身份）、状态码、两个位置**下标**
   （表 A / 表 B，最后一帧的表 B 为 −1）、**返回栈中每个返回点的位置下标**；下标 −1 表示“没有这一项”；
4. **6 个块计数**与块 0..5：块 0 = **全局整型池前缀**、块 3 = **全局浮点池前缀**、块 2 = **字符串段**，
   块 1 / 4 的**内容**只在版本字段 2 ≥ 20 时写（计数仍写），块 5 写 `c5` 个 0 字。

**值的编码**：整型池以**解码后的值**落盘 —— 写侧对每个保存的整数值做一次解码变换；
读侧把整池（含容量末尾的一格）**清零后**再写入前缀，然后对全池做一次编码变换。
因此"文件里的整数是明文，内存里是编码位模式"是合同；编码键**不进文件**（每实例生成）。

**持久化判据**（不是靠字段名猜）：写入侧把它复制进块，并且读取侧要么把它复制回内存、要么用它**重建**。
按这条判据：

* **持久化**：全局池（整型前缀 / 浮点 / 字符串）、每帧的位置下标与返回栈下标、每帧的脚本身份；
  版本 2 ≥ 20 时的块 1 / 4 身份**未取证**，读侧按计数跳过、不写回任何已建模池。
* **不持久化**：配置库（另有玩家文件）、纹理 / 图像对象（只存标识）、整型编码键、任何堆地址。
* **由标识重建**：脚本体（按脚本身份重新装载）、图像对象（按文件标识重新装载）。
* **未查明**：局部池的值是否随存档持久化（本版不规定）。

**条件**

* 块内计数是"要保存的前缀长度"，不是池容量；容量由装载期决定，读侧按容量清零/编码。
* 块 / 帧记录的具体字节布局见 `FMT-SAVE-CODEC`；本节只规定字段集合与编码方向。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前帧号 | 主体第 1 字（负载起点 + 8） |
| 全局整型池的前缀 | 块计数 + 值序列（运行期计数属机器细节） |
| 整型编码键 | 运行期编码键（不落盘；位置属机器细节） |

### 恢复：重建什么、保留什么、位置怎么回来

<!-- rule: FMT-SAVE-RESTORE -->

恢复分两段：**读文件**（头部校验 → 版本门 → 参数块 → 校验 → 解密/解压，结果进引擎暂存区）与**应用**：

1. 把**已建模池**（整型 / 浮点 / 字符串）清零，再按 `c0` / `c3` / 字符串段写前缀；整型池全体重新编码。
   块 1 / 4 按 `c1` / `c4` **跳过**，不写回任何已建模池（身份未取证，见 `FMT-SAVE-BODY`）。
2. **重建**每帧记录；按存档里的脚本身份**重新装载脚本**（代码缓冲、局部池由此产生）—— 不是从存档读回代码。
3. 按存档里的**位置下标**还原执行位置：位置本身**不落盘**，恢复时用 `基址 + 4 × 位置表[下标]` 算出；
   继续位置用**表 A 下标**（`rec[259]`），**表 B 下标**（`rec[260]`）的用途本版**未取证**；
   下标为 **−1** 表示“没有这一项”，此时位置不变。
4. 若还原出的位置对应的是“换脚本”指令，引擎按该指令的**长度槽**推进（即“该指令已执行完”）；否则不自动推进。

**两个读取变体**：普通变体只读文件本体、且**不重建图像/条目对象**；完整变体在读完之后还读尾段并应用它，
并按存档里的标识重建图像/条目对象（尾段语义不在本版）。两者读的是同一份负载。

**重建 vs 读回的判据**：能从"标识 + 引擎自己的装载器"重建的，就不落盘（脚本体、图像对象）；
否则落盘（池的值、位置下标、返回栈下标）。

**条件**

* 位置的"表"是每帧自带的两张位置表（一张服务"换脚本"、一张服务另一族调用）；表的内容由脚本装载期建立。
* 返回码：打开失败 = 1；头部不合法 = −1（读变体）/ 2（只读头的变体）；成功 = 0。
  版本不符 / 校验不符 / 负载读失败**不改变**返回码（后续处置本版不规定）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前帧号 | 主体第 1 字（负载起点 + 8；运行期当前帧属机器细节） |
| 执行位置 | 帧记录的"操作数基址"格；由位置表下标算出 |
| 位置表 | 每帧两张（长度 + 指针） |

### 负载编码：校验、变换、压缩与字节布局

<!-- rule: FMT-SAVE-CODEC -->

参数块第 1 槽 = 密文的 32 位字数；第 2 槽 = 校验和 1；第 3 槽 = 校验和 2；第 4 槽 = 32 位种子；第 5 槽 = 随机键（只用低 16 位，且**必须为奇数**；偶键按**未定义行为**处置，⛔ 不许静默除零）。

**两个校验和**（都覆盖**密文全长** `4 × 第 1 槽` 字节；按字节在文件中的先后喂养；初值 `0xFFFFFFFF`、结果按 32 位小端写、末步取反）：

- **校验和 1（参数块第 2 槽）** = **非反射 CRC-32**，多项式 `0x04C11DB7`，每字节 **MSB 先**；
- **校验和 2（参数块第 3 槽）** = **反射 CRC-32**，多项式 `0xEDB88320`（与常见 CRC-32 同表）。

**变换**（不是加密；每源双字 → 两密文双字）：

```
n = 第 1 槽 / 2（源双字数；第 1 槽必须为偶数，奇数按未定义行为）
seed = 第 4 槽
k    = 第 5 槽 & 0xFFFF
for i in 0..n-1:
  x = src[i] XOR seed
  t = k & 0xFFFF
  dst[2i]   = ((x >>> 16) * t) >>> 0
  dst[2i+1] = ((x & 0xFFFF) * t) >>> 0
  seed = (seed + 0x0B0B0B0B) >>> 0
  k    = (k + 0x0B02) >>> 0
```

解密逐对做两次整除；**余数不为 0 是唯一失败判据**；两因子都 < 2^16，不溢出。

**压缩**：与「ALF 归档」的 LZSS **同一例程、同一参数**（窗口 / 初值 / 标志极性 / 匹配码装填 / 回绕与重叠见该章），本节不重复。
压缩段前缀是 `[解压后字节数][解压后字节数][压缩字节数][压缩流]`（12 字节，始终存在、位于压缩流之前）；
当**解压后字节数 == 压缩字节数**时该段不压缩、原样存放（前缀仍在）。⛔ 不许拿前缀第 1、2 字互比（它们恒等）。

**内层头**：解密 / 解压后的负载 = `[校验 1][校验 2][主体]`，两个校验覆盖**主体**，用上面同一对 CRC-32。
版本字段 1 的值 < 2 ⇒ 直接复核解密结果里的内层头；≥ 2 ⇒ 复核**解压结果**里的内层头。

**主体字节布局**（基址 = 负载起点 + 8；下列偏移都以该基址计）：

| 偏移 | 宽度 | 内容 |
|---|---|---|
| 0 | 4 | 当前帧下标 |
| 4 | 8 | 保留（写 0，读侧忽略） |
| 12 | 40 | 定长副块 1（内容本版不规定；实现可写 0，读侧不得依赖） |
| 52 | 1200 | 定长副块 2（同上） |
| 1252 | `版本字段 1 == 3 ? 20000 : 0` | 版本 1 = 3 专有副块（内容本版不规定；可写 0，读侧不得依赖） |
| `1252 + 副块长` | 1044 × (当前帧下标 + 1) | 每帧一条记录（`RECBASE`） |
| `RECBASE + 1044 × (当前帧下标 + 1)` | 24 | 6 个 32 位块计数 |

6 个计数（`c0..c5`，4 字节小端、无编码）紧跟在记录之后：
`c0` 整型池前缀字数、`c1` 块 1 字数、`c2` 字符串条数、`c3` 浮点池前缀字数、`c4` 块 4 字数、`c5` 块 5 字数。

| 计数 | 块 | 元素宽度 / 编码 | 版本条件 |
|---|---|---|---|
| `c0` | 块 0：全局整型池前缀 | u32，**文件里是解码后的明文**；写侧解码、读侧编码 | 总是写 |
| `c1` | 块 1（身份未取证；读侧跳过） | u32 raw | 内容仅 v2 ≥ 20 写 |
| `c2` | 字符串段（= 块 2） | `u32 capWords` + `capWords × 4` 字节的 **NUL 结尾字节池**；`c2` 是**字符串条数**，`capWords` 是**已用字数**（4 字节对齐），字符串连续存放、尾部填充 0、读侧忽略尾部 | 总是写 |
| `c3` | 块 3：全局浮点池前缀 | u32 raw | 总是写 |
| `c4` | 块 4（身份未取证；读侧跳过） | u32 raw | 内容仅 v2 ≥ 20 写 |
| `c5` | 块 5 | `c5` 个 u32，**写 0、读侧跳过** | 总是写 |

★ 版本字段 2 < 20 时，**计数仍无条件写**，只有块 1 / 4 的内容写入被门控 ⇒ 合法文件可以出现
“非 0 计数 + 未写空洞”。

**尾段**从
`tail = 1252 + (版本字段 1 == 3 ? 20000 : 0) + 1044 × (f + 1) + 24 + 4 × (c0 + c1 + c3 + c4 + c5 + capWords + 1)`
开始（`f` = 当前帧下标）：
值为 **740 的 u32 长度字段** + `u32 N`，随后 `N` 条**每条 2964 字节**的记录：
`+0` u32 key（升序、唯一）、`+4 .. +744` 740 字节 value（不解释字段）、`+744 .. +2964` 未写区（**内容未规定，读者不读**）。
N 条之后再跟 `2 × u32` + 740 字节（写 0）。
最后还有一段 slack：`c2 + 16463 + 3N` 个 32 位字，在最终尾块之后，**内容未规定（样本为 0），读者不读**。
（本作样本 `c2 = 3421`，因此恰好是 `19884 + 3N` 个字。）

**每帧记录**（261 个 32 位字）：`rec[0]` = 状态码（多处置 −10 / −11 / −1，**不是脚本身份**）；
`rec[1]` = **脚本文件索引**（脚本身份）；`rec[2]` = 返回点条数 **N（≤ 256）**；
`rec[3 .. 3+N)` = N 个返回点位置下标（−1 = 无；N = 256 时覆盖到 `rec[258]`）；
`rec[259]` = 表 A 下标（**最后一帧不是 −1**）；`rec[260]` = 表 B 下标（**最后一帧强制 −1**）。

## 存档：写入 / 恢复 / 归属

本章 9 条规则。

### 槽的身份：槽号 → 一对文件

<!-- rule: FMT-SAVE-SLOT -->

存档槽由一个**整数槽号**标识。引擎按"存档目录 + 槽号"构造文件：
主数据文件名为 `SAVE<槽号>.DAT`，缩略图文件名为 `SAVE<槽号>.STH`；
槽号以**十进制、至少两位、左补 0** 写出（三位以上的槽号照写；负槽号按带符号十进制写出，其后果见残差）。
**槽号不做范围检查**：越界槽号不报错，只是构造出另一个文件名。

一个槽在"删除"与"复制"里是**一对文件**：两个文件都处理，先主数据、后缩略图；
但**写入**是两条独立指令 —— 写槽数据不产生缩略图，写缩略图也不写槽数据。
主数据写入成功之后，引擎还会顺带重写**系统数据文件**（格式见「系统容器」条）与另一份运行期文件；
两者的具体格式 / 判据不在本版。删除 / 复制**不**触发这次重写。

**条件**

* 槽号来自该指令的第 2 个操作数（按整型读）。
* 另有"**按名字**"的指令变体（写一条 / 读两条 / 只读头一条）：它们**不经过槽号，也不拼存档目录** —— 第 2 个操作数是一个**字符串引用**，其值原样当作文件路径（相对路径按进程工作目录解释）。
* **槽号只用于"拼名字"**：目录前缀怎么来见下；**槽号不做范围检查**。
* **槽号可以是任何 32 位整数**：它只会被写成文件名的一部分，所以"越界"的表现是"另一个文件名"，不是错误、也不会被拒绝。写成文件名的规则是**十进制、至少两位、左补 0、负数带负号**：`0 → 00`、`7 → 07`、`42 → 42`、`100 → 100`（照写）、`-1 → -01`、`-12 → -12`。⇒ 槽号**不会让路径离开存档目录**（产物只可能多出数字与负号），也不会与另一个槽号撞名；唯一边界是整条路径的 256 字节上限（超长被**截断**，且引擎不检查这个截断）。
* **存档目录 = 根 [+ 分隔符] + `set:SavePath`**；两个分隔符各自只在"拼到此处的结果非空"时补（会出现连续分隔符，引擎不折叠）。根 = `set:UseAppDataFolder` **恰为 1** ⇒ 宿主给出的用户应用数据目录（现代 Windows 上是本地那一份，不是漫游）；其它值 ⇒ 空串（相对进程工作目录，发行态即安装目录）。相对目录取 `set:SavePath`（原样、可带子目录；**不看** `set:RegFilePath`），缺键默认 `SAVE`。
* **没有搜索顺序**：只有一个目录，不会"先安装目录、再用户目录"，也不回退。**目录按需创建**：每次槽操作（含只读）先探一次目录，不存在就递归建；探测名固定是系统数据文件名（不是当次槽名），读操作不创建任何文件。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 槽号 | 指令操作数（整型）；不落任何池 |
| 一个槽 | 目录下的一对文件 |

### 缩略图文件：BMP 容器

<!-- rule: FMT-SAVE-STH -->

一个槽的缩略图文件（`.STH`）是一份 **BMP**，由**引擎自己**组装：写侧先把 14 字节文件头、40 字节信息头与像素块填进内存，
再分三段写到文件；读侧按文件开头的两字节认格式（`BM` ⇒ 本格式），把像素解出来写进**第 3 个操作数指定的图像 / 表面对象**。存档头的族标识来自初始化文件头两字节（本作是 `S4IN` 一族，写出的魔数是 `S4SD` / 旧代 `S3SD`）；文件头里的版本串取可执行文件的版本资源、去掉第二字符后取前四字符，**读侧不比较它**；保留区写侧整块清零后不再触碰、读侧不判。
缩略图**不是**平台交回的一整份文件字节：容器由引擎按本节写 / 读，平台只提供"某张表面的像素 + 行宽 + 通道掩码"。

**本作写出的文件结构**（两段头 + 像素；无调色板、无尾段）：

- **文件头**（14 字节）：`BM`；保留字段 = 0；像素数据起始 = 54；**声明的文件长度 = 像素字节数 + 40**（比真实长度少 14；**引擎的读取器从不比较这个字段**，读到真实长度也不拿它截断 ⇒ ⛔ 实现里不要按它裁剪像素）。
- **信息头**（40 字节）：`biSize` = 40；宽、高（正数）；平面数 = 1；位深 = 24（本作样本，见条件）；
  压缩 = `BI_RGB`（0）；`biSizeImage` = 0；每米像素数 = 0；调色板计数 = 0。
- **像素**：每行字节数 = 宽 × 位深按 32 位对齐（即 4 字节对齐）；行**自下而上**（文件里第一行是画面最后一行）；
  每像素 3 字节，顺序为**蓝、绿、红**。**行末填充字节也写出**：写侧一次分配「对齐行宽 × 高」并整块写出，
  逐像素只覆写有效像素，填充字节保持分配时的初值（本作为 0）⇒ 任意宽度下的产物唯一。
  本作样本的宽度都是 4 的倍数 ⇒ 样本里没有填充字节可对（其内容未在样本上取证）。文件在像素块之后结束。

**声明的文件长度比实际短 14 字节**：引擎写的是 `40 + 像素字节数`，按上述结构算出的实际长度是 `54 + 像素字节数`
（本作四份样本：声明 172840、实际 172854）。⛔ 不许把它"修正"成 `54 + 像素字节数`：
读侧不比较这个字段，但写侧必须照写，否则产物与真机不是逐字节相同。

**读侧**只按文件开头判格式（`BM` 走本格式）；随后读 40 字节信息头，要求位深属于 {1, 4, 8, 24, 32}（16 位被拒）；
位深为 1 / 4 / 8 时再读调色板，条目数取信息头的调色板计数（0 表示 2 / 16 / 256 条），每条 4 字节；
像素字节数按"宽 × 位深按 32 位对齐 × 高"**算出**，**不读** `biSizeImage`，也**不比较**声明的文件长度、像素数据起始、
平面数与压缩字段。
**每一步只检查读取调用本身的布尔结果**（成功 / 失败），**不比较实际读到的字节数**：调用报成功就继续，
**短读**（文件比上述结构短）：读取步骤只看"读操作是否返回真"、**不比较实际字节数**（短读按成功继续）；像素缓冲与调色板是**清零分配**（短读后按 0 继续），而**两段头不做清零**（头短读后是分配残留 ⇒ 未定义）。本版只钉这个边界（见残差）。
**唯一的内容判据是位深集合**：位深不在 {1, 4, 8, 24, 32} 里 ⇒ 该指令以状态 `2` 失败；
**任一读取调用报失败同样进状态 `2`**（读不到头 / 调色板 / 像素都走这个结局，不看实际读到的字节数）。
**打开文件失败是另一个状态**（`1`，见「存档槽的文件级操作」）。

**条件**

- 宽与高**不是格式常数**：它们取自**第 3 个操作数**指定的那个对象（写侧 = 被捕捉的对象；本作样本四份都是 320 × 180）。
- 位深也取自捕捉路径：**本作生效的是屏幕捕捉（配置项 `set:DrawMode` 缺省 0，发行配置未覆盖）⇒ 恒 24 位**；纹理捕捉只在 `DrawMode == 1` 时生效。
  纹理路径的 32 位布局是**代码已定、零样本**：源表面带 alpha ⇒ 32 位，像素 **蓝 / 绿 / 红 / alpha**（alpha 按格式位宽左移），行宽 = 位深 × 宽按 32 位对齐，声明长度 = 行宽 × 高 + 40，自下而上。
- 三个通道取自被捕捉表面的通道掩码，不缩放（24 位输出）。
- **第 3 个操作数指定“装进 / 取自哪个对象”，不是槽号**：引擎有两条实现，写出的文件头取值与长度算术相同。
  **本作生效的是屏幕捕捉路径**：它把该操作数当**表面选择**，**0 / 1 / 2 被拒**（其余值继续；负数按无符号位模式不等于这三个值 ⇒ 落在接受侧），
  被拒时**不读文件内容**、写错误通道、以状态 `2` 结束（见「存档槽的文件级操作」）。
  另一条纹理捕捉路径把它当**图像对象编号**，没有这个限制。
- 读侧的 1 / 4 / 8 位调色板展开与 32bpp 像素布局**沿用共享图像装载器的 BMP 分支**（与装载纹理时是同一个读者）；
  本作的样本只有 24 位，展开细节见残差。
- 打开文件失败与内容失败是**两个状态**（见「存档槽的文件级操作」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 缩略图文件 | 该槽目录下的一份 BMP |
| 被捕捉的对象 | 第 3 个操作数指定；引擎向平台请求锁定的表面（像素 + 行宽 + 通道掩码） |
| 读入的缩略图 | 第 3 个操作数指定的图像 / 表面对象（重新建立） |

### 292 字节文件头与头部校验

<!-- rule: FMT-SAVE-HEADER -->

存档主文件以一个**固定 292 字节的头**开始；字段按字节偏移固定：

| 偏移 | 宽度 | 内容 |
|---|---|---|
| 0 | 4 | **魔数**：本作为 `S4SD`；同一引擎的另一族为 `S3SD` |
| 4 | 4 | **版本串**：4 字节，原样写入（样本里是 `460B`） |
| 8 | 232 | **游戏标题**：NUL 结尾的字节串（样本里是 `天結いキャッスルマイスター`） |
| 240 | 4 | **解压后（未变换）负载的字节数** |
| 264 | 16 | **存档时刻**：本地时间 8×u16 = 年、月、星期、日、时、分、秒、毫秒 |
| 280 | 4 | **游戏时间**（秒） |
| 284 | 4 | **存档格式版本 1** |
| 288 | 4 | **存档格式版本 2** |
| 244…259 | 16 | 保留（写 0） |
| 260 | 4 | 保留（写 0；补满 240–264 的保留区） |

**头部校验**：读回时必须**成功读满 292 字节**（负载可以更长），且魔数等于引擎期望值、第 8 字节起的标题等于引擎自己的标题串；
否则判"这个文件不是本游戏的存档"，**不恢复任何状态**。头**没有**自校验和，`+240` 也不参与边界判断
（它是负载的未变换长度，不是头部长度）。

**条件**

* 魔数取自引擎里的一个 2 字符"族标识"：族标识等于 `S4` 时魔数为 `S4SD`，否则 `S3SD`。族标识本身是数据（残差）。
* 时刻是保存当时的**本地时间**（含星期与毫秒）；游戏时间是"自本局开始累计的秒"。
* 版本字段**不在头部校验里**；它们由负载读取阶段比较（见 `FMT-SAVE-ENVELOPE`）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 存档时刻 | 头 `+264`（本地时间 8×u16） |
| 游戏时间 | 头 `+280`（秒） |
| 标题 / 版本串 / 族标识 | 引擎里的字符串状态（运行期状态；布局属机器细节） |

### 只读头读取交给脚本的七个字段

<!-- rule: FMT-SAVE-HEADER-FIELDS -->

"只读头"的存档读取（见「存档槽的读取」）成功时，把存档头的**七个整数**按固定顺序交给脚本：
**年、月、日、时、分、秒、游戏时间**。前六项各是 **16 位无符号**，最后一项是 **32 位原样**（单位：秒）。

前六项**不是**存档时刻块的前六项：时刻块的第 1、2 项是年、月，第 3 项是**星期**（**跳过**），
第 4、5、6、7 项依次是日、时、分、秒，第 8 项是**毫秒**（**跳过**）。
游戏时间取自头里的「游戏时间」字段（字段次序与宽度见 `FMT-SAVE-HEADER`）。
两个格式版本字段在游戏时间之后，**不**交给脚本。

**条件**

* **星期与毫秒没有位置**：七个值里不出现它们，它们也不挤占别的格。
* 交给脚本的是头里的值本身：不换算时区、不重排、**不把两个 16 位项拼成一个 32 位项**。
* 七个格按「年 → 游戏时间」的顺序写。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 存档时刻的年 / 月 / 日 / 时 / 分 / 秒 | 存档时刻块的第 1、2、4、5、6、7 项（各 16 位）→ 第 3..8 个操作数 |
| 游戏时间（秒） | 头里的「游戏时间」字段（32 位）→ 第 9 个操作数 |

### 负载信封：参数块、变换、校验与版本门

<!-- rule: FMT-SAVE-ENVELOPE -->

校验和 / 变换 / 压缩算法与负载字节布局见 `FMT-SAVE-CODEC`；本节只写参数块与读取顺序。

292 字节头之后是**20 字节参数块**，按 **5 个 32 位槽**解释：
负载的 32 位字数、校验和 1、校验和 2、32 位随机种子、随机键（第 5 槽只用低 16 位；后两项保存时随机生成）。
参数块之后是**负载本体**，长度 = 参数块第 1 字 × 4 字节。

负载以**变换形式**存放（本样本里未变换 4.3 MB 的负载只占约 1 MB）。读回顺序与判据：

1. **版本门**：文件头的版本 1/2 必须等于引擎当前期望值；唯一例外是"文件版本 1 == 2 且期望版本 1 == 2"，此时**不比较**版本 2。
   通过后，文件里的两个版本回写进文件子系统的状态。
2. **两个校验和**都覆盖变换后的负载；任一不符 ⇒ 拒绝（报错）。
3. **解密**：用参数块里的种子与随机键解密；失败 ⇒ 拒绝。
4. **内层**：版本字段 1 的值 < 2 时，解密结果自带 2 字校验头，数据在校验头之后；版本字段 1 的值 ≥ 2 时，解密结果先解压，
   解压结果再带 2 字校验头。内层两个校验和都必须通过。

负载之后**允许**有一段尾段；槽读取的"普通"变体不读它，"完整"变体读它（见 `FMT-SAVE-RESTORE`）。

**条件**

* 期望版本来自两个配置键（`set:SaveVersion1` / `set:SaveVersion2`），不是来自文件。
* **密文字节数**（`4 × 参数块第 1 槽`）不得超过 `2 × (头 +240 + 24)`（超了 ⇒ 拒绝）：这是读取缓冲的边界判据。`+240` 是**解压后（未变换）**长度，不是密文长度；24 字节余量 = 12 字节压缩段前缀 + 内层 8 字节头 + 4 字节余量。
* 校验和 / 变换 / 压缩 / 内层头的算法见 `FMT-SAVE-CODEC`；本条不再把它们推给实现。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 负载长度（变换后） | 参数块第 1 字 × 4 |
| 文件版本 | 头 `+284/+288` → 文件子系统状态 |
| 随机种子 / 键 | 参数块第 4 / 第 5 个 32 位槽（保存时生成，不来自任何游戏数据） |

### 槽负载的块结构：哪些状态被持久化

<!-- rule: FMT-SAVE-BODY -->

负载块与帧记录的字节布局见 `FMT-SAVE-CODEC`；本节只写持久化字段集合与判据。

槽负载（版本字段 1 = 2 / 3 的容器）由以下部分**按序**组成（字段集合，逐格顺序见 `FMT-SAVE-CODEC`）：

1. **主体当前帧号**（负载起点 + 8 的第 1 字；不是负载第 1 字，负载前 8 字节是内层校验头）；
2. **定长副块**（40 B / 1200 B；内容本版不规定）；
3. **每帧一条记录**（按帧号索引，宽度固定）：该帧的**脚本文件索引**（脚本身份）、**父帧号**、两个位置**下标**
   （表 1 / 表 2，最后一帧的表 2 下标为 −1）、**返回栈中每个返回点的位置下标**；下标 −1 表示“没有这一项”；
4. **6 个块计数**与块 0..5：块 0 = **全局整型池前缀**、块 3 = **全局浮点池前缀**、块 2 = **字符串段**，
   块 1 / 4 的**内容**只在版本字段 2 ≥ 20 时写（计数仍写），块 5 写 `c5` 个 0 字。

**值的编码**：整型池以**解码后的值**落盘 —— 写侧对每个保存的整数值做一次解码变换；
读侧把整池（含容量末尾的一格）**清零后**再写入前缀，然后对全池做一次编码变换。
因此"文件里的整数是明文，内存里是编码位模式"是合同；编码键**不进文件**（每实例生成）。

**持久化判据**（不是靠字段名猜）：写入侧把它复制进块，并且读取侧要么把它复制回内存、要么用它**重建**。
按这条判据：

* **持久化**：全局池（整型前缀 / 浮点 / 字符串）、每帧的位置下标与返回栈下标、每帧的脚本身份；
  版本 2 ≥ 20 时的块 1 / 4 身份**未取证**，读侧按计数跳过、不写回任何已建模池。
* **不持久化**：配置库（另有玩家文件）、纹理 / 图像对象（只存标识）、整型编码键、任何堆地址。
* **局部池的值不持久化**（整型 / 浮点 / 字符串与三张局部指针表）：它们属于帧，**随脚本装载重建**；文件里既没有它们的块，帧记录也只覆盖状态 / 脚本索引 / 位置表两格 / 位置 1 / 位置 2 ⇒ 存档**无法**恢复某个局部槽的当时取值。★ 恢复后是 0 还是分配残留**本版不规定**。
* **由标识重建**：脚本体（按脚本身份重新装载）、图像对象（按文件标识重新装载）。

**条件**

* 块内计数是"要保存的前缀长度"，不是池容量；容量由装载期决定，读侧按容量清零/编码。
* 块 / 帧记录的具体字节布局见 `FMT-SAVE-CODEC`；本节只规定字段集合与编码方向。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前帧号 | 主体第 1 字（负载起点 + 8） |
| 全局整型池的前缀 | 块计数 + 值序列（运行期计数属机器细节） |
| 整型编码键 | 运行期编码键（不落盘；位置属机器细节） |

### 恢复：重建什么、保留什么、位置怎么回来

<!-- rule: FMT-SAVE-RESTORE -->

恢复分两段：**读文件**（头部校验 → 版本门 → 参数块 → 校验 → 解密/解压，结果进引擎暂存区）与**应用**：

1. 把**六个全局池**（整型 / 浮点 / 字符串 / 整型引用 / 浮点引用 / 字符串引用）清零，再按 `c0` / `c1` / 字符串段 / `c3` / `c4` 写前缀（`c1` / `c4` 只在 `v2 ≥ 20` 时读内容；`c5` 只跳过 `c5` 个字）；整型池全体重新编码。局部池**不恢复**（脚本重新装载时重建）。
2. **重建**每帧记录；按存档里的脚本身份**重新装载脚本**（代码缓冲、局部池由此产生）—— 不是从存档读回代码。**执行位置本身不落盘**：恢复时用 `代码基址 + 4 × 表[下标]` 算出；`rec[260]` 优先（推进 3 字），否则 `rec[259]`（不推进），下标为 −1 时该项不变。
3. 按存档里的**位置下标**还原执行位置：位置本身**不落盘**，恢复时用 `基址 + 4 × 位置表[下标]` 算出；
   `rec[259]` 是**表 1**（消息显示指令 `0x71` 的位置族）的下标，`rec[260]` 是**表 2**（换脚本 `0x03` 的位置族）的下标；
   两者**不互斥**（同一条记录可以两个都有）；`rec[260]` 优先、恢复后推进 3 个字（= 那条换脚本指令的长度），否则 `rec[259]`、推进 0；
   下标为 **−1** 表示“没有这一项”，此时位置不变。
4. 若还原出的位置对应的是“换脚本”指令，引擎按该指令的**长度槽**推进（即“该指令已执行完”）；否则不自动推进。

**两个读取变体**：普通变体只读文件本体、且**不重建图像/条目对象**；完整变体在读完之后还读尾段并应用它，
并按存档里的标识重建图像/条目对象（尾段语义不在本版）。两者读的是同一份负载。

**重建 vs 读回的判据**：能从"标识 + 引擎自己的装载器"重建的，就不落盘（脚本体、图像对象）；
否则落盘（池的值、位置下标、返回栈下标）。

**条件**

* 位置的"表"是每帧自带的两张位置表（一张服务"换脚本"、一张服务另一族调用）；表的内容由脚本装载期建立。
* 返回码：打开失败 = 1；头部不合法 = −1（读变体）/ 2（只读头的变体）；成功 = 0。
  版本不符 / 校验不符 / 负载读失败**不改变**返回码（后续处置本版不规定）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前帧号 | 主体第 1 字（负载起点 + 8；运行期当前帧属机器细节） |
| 执行位置 | 帧记录的"操作数基址"格；由位置表下标算出 |
| 位置表 | 每帧两张（长度 + 指针） |

### 负载编码：校验、变换、压缩与字节布局

<!-- rule: FMT-SAVE-CODEC -->

参数块第 1 槽 = 密文的 32 位字数；第 2 槽 = 校验和 1；第 3 槽 = 校验和 2；第 4 槽 = 32 位种子；第 5 槽 = 随机键（只用低 16 位，且**必须为奇数**；偶键按**未定义行为**处置，⛔ 不许静默除零）。

**两个校验和**（都覆盖**密文全长** `4 × 第 1 槽` 字节；按字节在文件中的先后喂养；初值 `0xFFFFFFFF`、结果按 32 位小端写、末步取反）：

- **校验和 1（参数块第 2 槽）** = **非反射 CRC-32**，多项式 `0x04C11DB7`，每字节 **MSB 先**；
- **校验和 2（参数块第 3 槽）** = **反射 CRC-32**，多项式 `0xEDB88320`（与常见 CRC-32 同表）。

**变换**（不是加密；每源双字 → 两密文双字）：

```
n = 第 1 槽 / 2（源双字数；第 1 槽必须为偶数，奇数按未定义行为）
seed = 第 4 槽
k    = 第 5 槽 & 0xFFFF
for i in 0..n-1:
  x = src[i] XOR seed
  t = k & 0xFFFF
  dst[2i]   = ((x >>> 16) * t) >>> 0
  dst[2i+1] = ((x & 0xFFFF) * t) >>> 0
  seed = (seed + 0x0B0B0B0B) >>> 0
  k    = (k + 0x0B02) >>> 0
```

解密逐对做两次整除；**余数不为 0 是唯一失败判据**；两因子都 < 2^16，不溢出。

**压缩**：与「ALF 归档」的 LZSS **同一例程、同一参数**（窗口 / 初值 / 标志极性 / 匹配码装填 / 回绕与重叠见该章），本节不重复。
压缩段前缀是 `[解压后字节数][解压后字节数][压缩字节数][压缩流]`（12 字节，始终存在、位于压缩流之前）；
当**解压后字节数 == 压缩字节数**时该段不压缩、原样存放（前缀仍在）。⛔ 不许拿前缀第 1、2 字互比（它们恒等）。

**内层头**：解密 / 解压后的负载 = `[校验 1][校验 2][主体]`，两个校验覆盖**主体**，用上面同一对 CRC-32。
版本字段 1 的值 < 2 ⇒ 直接复核解密结果里的内层头；≥ 2 ⇒ 复核**解压结果**里的内层头。

**主体字节布局**（基址 = 负载起点 + 8；下列偏移都以该基址计）：

| 偏移 | 宽度 | 内容 |
|---|---|---|
| 0 | 4 | 当前帧下标 |
| 4 | 8 | 保留（写 0，读侧忽略） |
| 12 | 40 | 定长副块 1（内容本版不解释；**读侧会读**，⛔ 不可写 0 —— 见残差） |
| 52 | 1200 | 定长副块 2（100 × 12 字节的记录表；内容本版不解释，读侧逐项读，⛔ 不可写 0 —— 见残差） |
| 1252 | `版本字段 1 == 3 ? 20000 : 0` | **纹理记录表**（1000 × 20 字节 = 每项 5 个 32 位格：来源文件号 / 颜色键 / **恢复重建门** / 零读者标志 / 空白标记）。写侧从场景的备份表整段复制；读侧整段拷回，逐项在「门 = 1 且来源文件号 ≥ 0」时重建纹理对象（成功还会清空白标记；失败写 −1 并继续下一项）。⛔ 不要写 0：写成 0 会让恢复时一条纹理都不重建 |
| `1252 + 副块长` | 1044 × (当前帧下标 + 1) | 每帧一条记录（`RECBASE`） |
| `RECBASE + 1044 × (当前帧下标 + 1)` | 24 | 6 个 32 位块计数 |

6 个计数（`c0..c5`，4 字节小端、无编码）紧跟在记录之后：
`c0` 整型池前缀字数、`c1` 浮点池前缀字数、`c2` 字符串条数、`c3` 整型引用池前缀字数、`c4` 浮点引用池前缀字数、`c5` 字符串引用表字数。

| 计数 | 块 | 元素宽度 / 编码 | 版本条件 |
|---|---|---|---|
| `c0` | 全局**整型池**前缀 | u32，**文件里是编码后的值**（内存池里是明文）；写侧编码、读侧解码 | 总是写 |
| `c1` | 全局**浮点池**前缀 | u32 raw | 内容仅 v2 ≥ 20 写；计数与洞总是存在 |
| `c2` | 字符串段（= 全局字符串池） | `u32 capWords` + `capWords × 4` 字节的 **NUL 结尾字节池**；`c2` 是**字符串条数**，`capWords` 是**已用字数**（4 字节对齐），字符串连续存放、尾部填充 0、读侧忽略尾部 | 总是写 |
| `c3` | 全局**整型引用池**前缀 | u32 raw（元素是整型池地址） | 总是写 |
| `c4` | 全局**浮点引用池**前缀 | u32 raw | 内容仅 v2 ≥ 20 写；计数与洞总是存在 |
| `c5` | 全局**字符串引用表** | 无数据（写侧**不写**内容，读侧**只跳过** `c5` 个字） | 总是写计数 |

★ 六个块是**六个全局池**：整型 / 浮点 / 字符串三个值族，与整型引用 / 浮点引用 / 字符串引用三个引用族；**局部池不在这六块里**。
★ 版本字段 2 < 20 时，**计数仍无条件写**，只有**浮点族两块（`c1` / `c4`）的内容**写入被门控 ⇒ 合法文件可以出现
“非 0 计数 + 未写空洞”。`v1 = 2` 的容器**无论 `v2` 是多少都不写这两块内容、也不写尾部的场景表**。
★ 版本字段 2 **不只参与相等比较**：它还是块 1 / 4 内容的写入门与回填门（≥ 20 才写 / 才回填），
且在配置版本 1 == 1 时用 `== 20` 选择另一条位置还原分支。判据统一是"版本 2 与 20 比"。

**负载末尾的只写表**：从
`tail = 1252 + (版本字段 1 == 3 ? 20000 : 0) + 1044 × (f + 1) + 24 + 4 × (c0 + c1 + c3 + c4 + c5 + capWords + 1)`
开始（`f` = 当前帧下标）：
 值为 **740 的 u32 长度字段** + `u32 N`，随后 `N` 条**每条 2964 字节**的记录：
 `+0` u32 key（升序、唯一）、`+4 .. +744` 740 字节**场景记录**、`+744 .. +2964` 未写区（**内容未规定，读者不读**）。
 N 条之后再跟 `2 × u32`（场景的**键窗**：起点、计数）+ 740 字节（**场景自身记录**）。
最后还有一段 slack：`c2 + 16463 + 3N` 个 32 位字，在最终尾块之后，**内容未规定（样本为 0），读者不读**。
（本作样本 `c2 = 3421`，因此恰好是 `19884 + 3N` 个字。）
★ 这是**场景子系统的状态**（记录表 + 键窗 + 场景自身记录），**有读取路径**（恢复时按键插入、重建这三样）⇒ 它**参与恢复**；只在 `v1 = 3` 的容器里存在。⛔ 不要把它与「负载之后的尾段（文本缓冲）」混为一段：那是另一段、另一个子系统、另一个读者，位置在负载**之外**。

**尾段（消息窗口的命令日志 + 检查点）**：负载之后引擎还可能追加一段——**12 字节压缩前缀 + 压缩流**（与负载同一例程、同一形状），
解码后是 `[键值对个数 P][每对 8 字节][记录数 N][每条 44 字节][字符串字数 W][字符串区]`。
它由读侧的**完整变体**读取，且**只在文件版本 1 ≥ 2 时读**；普通变体不读。写侧只有"存到槽"的那条路径追加它
（另一条写同一格式的路径不追加）⇒ **存在性取决于写路径**，不是格式必然。段的定位是顺序的（紧随负载），不是由负载内某张表算出来的。

- **8 字节对** = `(槽号, 记录下标)`；下标指向一条**标志字第 0 位 = 1** 的"组首条"；多对可指向同一下标；**末对的下标是导航哨兵**（不是一条记录）。
- **44 字节记录**：`+0` 槽号（只写、本二进制零读者）；`+4/+8/+12/+16` = 矩形左/上/右/下；`+20/+24/+28/+32` = 族相关载荷（显示族里 `+20/+24` 可判为**颜色**；登记族 = 值/键；音声族 = 音声标识/变体/通道）；`+36` 字距（**只有显示族写**，其它族为未定义内存）；`+40` 标志（bit0 组首条、bit1 终止、bit2 绘制态、bit3 行推进、bit29 键值登记、bit30 音声）。
- **字符串区**：NUL 串按记录顺序连续、**无偏移/长度格**、**整段按 32 位字取反**；尾部 1..4 字节是**未定义内存**（合同只要求"读者不解释"，⛔ 不许写"逐字节相同"）。
- **写**：总长 = `12 + 8P + 44N + 4W`，`W = floor(Σ(len+1)/4) + 1`。
- **读**：清空 → 按文件顺序压对 / **追加**记录 → **从尾部弹出到第一条 bit0 记录（含它）为止** ⇒ **恢复后 N = 末对下标**（最后一组被丢弃）；**不恢复游标**、不校验 P/N/W，调用方也不检查返回值。
- 它与 `message:AutoMessage*` 是**同一对象的不同成员**：AutoMessage 读每槽 24 字节表算自动推进延迟，尾段存的是日志与检查点；两者互不影响。

**每帧记录**（261 个 32 位字）：`rec[0]` = **父帧号**（帧 0 为 −1，其后为压栈前的帧号；**不是状态码**）；
`rec[1]` = **脚本文件索引**（脚本身份）；`rec[2]` = 返回点条数 **N（≤ 256）**；
`rec[3 .. 3+N)` = N 个返回点位置下标（−1 = 无；N = 256 时覆盖到 `rec[258]`）；
`rec[259]` = **位置 1** 在**表 1** 里的下标（−1 = 该项不存在）；`rec[260]` = **位置 2** 在**表 2** 里的下标（**当前帧 / 最后一条记录强制 −1**）。

三张表不是"运行时扫描代码建出来的"，而是**脚本文件头自带的反查表**：头里 `[u32 n][n−4 字节 = 3×(条数, 表区偏移)]`；表体在代码区之后（`偏移` 是表体自己在 body 里的 dword 下标），每项是一个**位置**（`(PC−代码基址)>>2`），严格升序。表 1 的项指向消息显示指令（`0x71`）、表 2 指向换脚本指令（`0x03`）、表 3（返回点）指向脚本内子调用（`0x8f`）。`rec[259]/[260]` 的下标是**在该表里线性查找这个位置得到的结果**（不是"位置减表起点"）。引擎不追加 / 不去重 / 无上限。

三个下标都是"表里的序号"，不是地址、不是行号：返回点 `位置 = 代码基址 + 4 × 表3[下标]` 且**返回值 = 表3 表项 + 3 个字**；`rec[260]` 对应 `位置 = 基址 + 4 × 表2[下标]`、恢复后**推进 3 个字**（= 表项所指换脚本指令的长度）；`rec[259]` 对应 `表1[下标]`、恢复后**推进 0**。

### 系统容器（SAVE.DAT）：脚本键的持久化

<!-- rule: FMT-SAVE-SYSTEM -->

系统容器是**不带槽号**的那份存档文件：文件名 = 存档目录 + `SAVE.DAT`（先写临时名再换名，旧件转备份）。

- **什么时候写**：① 主数据（槽容器）写入**成功之后**；② **窗口关闭**且命名键 `set:NoSaveDat` 为 0 时。读档**不**触发重写。
- **什么时候读**：启动期一次 —— 把下面第 2、3 段读回并**重建**两张脚本键表。
- **负载**（前 8 字节是内层校验头，其后依次）：
  1. `[u32 n][n × u32]`：一个整型数组（段的身份见残差）；
  2. **脚本整型键表**：`[u32 c][c × (12 字节键 + u32 值)]`；
  3. **脚本字符串键表**：`[u32 m][u32 字数][m × (键 NUL 串, 值 NUL 串)]`；
  4. 版本门（主版本 > 3，或主版本 == 3 且次版本 ≥ 10）之后再多 0x400 字节块 + `[u32 k][k × u32]`；
  5. 末尾一个 0 字。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 脚本键表的全部整型项 / 字符串项 | 第 2 / 3 段各条记录里的键与值 |
| 文件里一条记录的位置 | 段首 + 元素宽度 × **它前面有多少个占用槽**（哈希槽升序、空槽跳过） |

**成立条件**

- **身份来自记录里的键**（`(键类型码, 8 位十六进制池槽下标)`：整型侧前缀 03、字符串侧前缀 05），⛔ 不从位置推断：同一组键在**不同插入历史**下文件字节可以不同、读回语义相同。
- 条数取该哈希表的**元素个数**，不是容量（容量只当扫描上界）。
- 键字段定长 12 字节 ⇒ 更长的键被静默截断；脚本键恒 9 字节，不受影响。
- 段 2 是**定长** 16 字节/条；段 3 变长（两条 NUL 串）。
- 系统容器与槽容器共用同一套外层（头 + 参数块 + 变换 / 压缩），外壳的两条规则这里不重复。

## 启动入口：入口 → 初始化 → 主循环

启动是引擎从宿主手里取得控制权、到主循环被调用之间的动作。**本章只规定以下三段**：取得索引、装载根脚本、把控制权交给主循环。**gate 判定不在本章**；**窗口 / 图形设备 / 消息泵 / 周期性定时器请求**见「启动期的平台请求」。这三段里任何一段不通，走同一条出口结束，不存在"部分成功"。

主循环内部的迭代、派发与等待属于《执行与时间》；消息泵的请求序列见「启动期的平台请求」的事件入口。本章只规定主循环被调用之前的事。

### 启动的边界：入口到主循环

<!-- rule: CORE-BOOT-ENTRY -->

启动阶段指**引擎取得控制权到主循环被调用**之间的动作。它只有一个入口：接收宿主给的实例与启动参数。成功路径的终点是**调用主循环**；失败路径走**共享出口**（见「中止形状」）。

- 启动的终点是"主循环被调用"这一件事。主循环被调用之后引擎还做什么、主循环是否会返回，本章都不规定；**主循环的退出路径**见「启动期的平台请求」的事件入口。
- 进程启动到引擎入口之间由宿主完成，不属于本章。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 在启动阶段 | 主循环尚未被调用 |
| 启动阶段结束 | 主循环已被调用 |

**成立条件**

- "只有一个入口"指引擎自己的启动过程；宿主可以在此之前做任意多的事。
- 成功路径上，入口把控制权交给主循环；主循环的出口见「启动期的平台请求」的事件入口，**入口之后是否再回到宿主，本章不规定**。失败路径不通过返回值报告（唯一例外是"第二次启动被拒"，见「中止形状」的残差），走「中止形状」的共享出口。

### 索引先行

<!-- rule: CORE-BOOT-INDEX-FIRST -->

引擎在装载任何脚本之前**先取得索引**。索引给出"统一文件 id → 条目"的映射（条目的名字、所属归档、偏移与长度）；没有它就无法按 id 取到任何脚本。

- 先按 S4 族的固定文件名（`SYS4INI.BIN`）尝试；打不开再按 S3 族（`SYS3INI.BIN`）。两族都不成 ⇒ 见「索引打不开就中止」。
- 索引成功之后、根脚本之前，配置已经可用：发行默认表随索引尾部到达（见《配置》）。索引也先于**窗口创建**（窗口请求见「启动期的平台请求」）。
- 本规则不规定"索引是不是启动的第一个文件动作"：更早的宿主阶段是否碰文件未取证。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 已有 id → 条目的映射 | 索引已装载 |
| 还没有映射 | 索引未装载 |

**成立条件**

- 先 S4 后 S3 的**回退顺序**是引擎行为，不是安装目录的偏好。
- 索引只提供映射；内容按《文件与脚本装载》的取件规则取得。

### 索引打不开就中止

<!-- rule: CORE-BOOT-INDEX-FAIL -->

两族的初始化文件都打不开 ⇒ 引擎向宿主**显示一条内建文本**（用途是告知重新安装；**文本内容本版不规定**），随后**不再前进**：不装载脚本、不建主循环、不做后续初始化。

- 这条中止**不通过返回值报告失败**：需要人看的失败用一条消息表达（见「中止形状」）。
- 中止前不留"半套"引擎状态：没有根脚本、没有主循环。
- 不重试：两族都已试过，没有"再试一次"的路径。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 启动失败（索引） | 一条显示请求；启动随即结束 |
| 启动继续 | 索引已装载，进入下一阶段 |

**成立条件**

- 文本是引擎内建的，不是脚本或配置提供的。

### 根脚本按统一文件 id

<!-- rule: CORE-BOOT-ROOT-SCRIPT -->

启动以**统一文件 id 0** 作为根脚本向装载器请求；请求时把服务窗口一并交给装载器（装载器需要它，本规则不规定用途）。

- 装载器返回"成功"标志（=1）才算装载成功；任何其它返回值 ⇒ 见「中止形状」。
- 按 id 而不是按文件名引用脚本是引擎的约定；脚本之间的相互引用也全是 id（统一 id 的两个区见《文件与脚本装载》）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 根脚本 = 统一 id 0 | 请求里的文件 id 为 0 |
| 装载成功 | 装载器返回成功标志（=1） |

**成立条件**

- 装载器对内容的合格判据（签名 / 版本 / 头部）属于《脚本与执行》；本规则只规定"按 id 请求"与"返回值怎么用"。
- 根脚本的 id 0 是引擎的起点约定，不是配置项。

### 中止形状：一条出口，没有部分成功

<!-- rule: CORE-BOOT-ABORT-SHAPE -->

启动期所有失败共享**同一条出口**：不再执行后续阶段，直接结束启动。启动没有"部分成功"——不存在"索引有了但没有根脚本、仍然进主循环"的形态。

- 中止走同一出口；**有的中止带一条消息、有的不带**，带不带不是出口的区分（两者都是"不再前进"）。
- 中止不改返回值：与索引失败走**同一出口**、同样**不通过返回值报告失败**（唯一例外是"第二次启动被拒"，见残差）。
- "结束启动"不是"返回一个错误码"：需要人看的失败用消息表达（例外：第二次启动被拒静默返回非 0，见残差）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 启动了 | 走完某阶段的正常分支，直到主循环被调用 |
| 没启动 | 走到共享出口 |

**成立条件**

- 这是可被独立实现复现的形状，不是"错误处理很弱"的评价。

**残差**

- `RES-BOOT-ABORT-RETURN`（unknown）："第二次启动被拒"是启动期唯一通过返回值报告的失败（非 0）；它在本版没有独立规则，单实例信号的语义也未成篇。下一步：把单实例信号与这条拒绝路径作为「启动前段」单独立条。

### 主循环的返回：唯一的出口段

<!-- rule: CORE-BOOT-LOOP-EXIT -->

**合同**

- 主循环用**异常**表达“退出”。本版规定的触发点有两类：
  1. 第一条消息泵**取到退出消息**；
  2. 第二条消息泵（等待之后）**取到退出消息**。
- 另有“未登记配置态下的周期性提示对话框返回终止”一类；该提示的出现条件 / 周期 / 继续分支**本版未取证**，不写成合同（见 `RES-BOOT-EXIT-NAG`）。
- 退出异常在**主循环内部**被捕获（不是由入口捕获）；捕获后直接进入**唯一的出口段**：
  1. 撤掉主循环自己装的两项宿主级处理器（结构化异常翻译器、内存不足处理器），恢复默认；
  2. 若引擎仍记着一个**服务窗口**，向它发一条**同步的关闭消息**（`WM_CLOSE`）；
  3. **返回**（无返回值）。
- 所以"取到退出消息"**不是**"主循环不返回"：主循环会正常返回，随后由入口做进程级清理（见「退出后的清理」）。
- 两类触发点在抛出**之前**先把“服务窗口”槽清空 ⇒ 这条路径上窗口早已销毁（退出消息就是它销毁时投递的），出口段**不会**再发关闭消息。未登记提示若也走出口段，其是否清空该槽本版**不规定**。
- 出口段的关闭消息是**同步**的：若窗口还在，它的关闭处理在出口段返回之前就跑完。

**成立条件**

- "唯一的出口段"是代码形状：非退出类异常经对话框选"终止"也汇到同一段（见「异常的处置」）。
- 退出消息被取出之后进程没有立即结束：入口还有一段清理与返回值。
- 出口段不碰引擎数据（不改脚本、不改帧）；它只发一条平台请求然后返回。
- 三类触发点都只表示"该结束了"，不携带原因码；原因的差别只体现在"要不要补发关闭消息"。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 取到退出消息 | 一条退出消息已从队列取出；服务窗口槽已清空；紧接着抛退出异常 |
| 对话框选终止 | 服务窗口槽保留；抛退出异常 |
| 主循环退出 | 出口段跑完并返回（无返回值） |

### 异常的处置：五类捕获与"对话框决定的出口"

<!-- rule: CORE-BOOT-LOOP-EXC -->

**合同**

- 主循环的一次迭代整体处在一个保护区内，捕获**五类**引擎异常：退出、需要显示消息、操作数类型号非法、结构化异常翻译、内存不足。
- **退出类**：直接进出口段（不显示对话框）。
- **其余四类**：组装一条内建文本 → 请求一个**选择对话框** → 按返回值分流：
  - `2` ⇒ **重试**：丢掉当前这次指令处理的现场，回到循环开头重新执行同一处；
  - `4` ⇒ **忽略并前进**：把当前帧的执行位置按"当前指令的长度"推进一条，回到循环开头；
  - 其它（含 `1`）⇒ 进出口段。
- 因此"用户在一次错误对话框里选择终止"也是主循环的出口，与退出消息走**同一段**。
- 四类之间的差别只在**文本内容**与随文本带的信息（哪一条消息、带不带类型号 / 命令号 / 深度、带不带宿主异常码）；**分流规则相同**。

**成立条件**

- 对话框返回值是**引擎的选择值**，不是平台按钮号；本规范只给 2 / 4 / 其它三档（其余值的差别未取证）。
- "重试"不重置引擎对象、不重置帧：丢的只是当前这次指令处理在现场留下的临时量。
- "忽略并前进"的步长来自当前帧的指令长度字段，不是常量。
- 类型号非法的文本里带三个数（类型号 / 命令号 / 深度）、结构化异常翻译的文本里带异常码与来源位置 —— 这些是错误报告上下文，不改变分流。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 保护区命中并捕获 | 一条内建文本 + 一次对话框请求 |
| 对话框返回 2 | 执行位置不变，继续 |
| 对话框返回 4 | 执行位置前进一条指令 |
| 其它 | 主循环结束 |
| 退出类 | 无对话框，直接结束 |

### 退出后的清理：顺序与"不释放"

<!-- rule: CORE-BOOT-EXIT-CLEANUP -->

**合同**

主循环返回之后，入口**按以下顺序**做清理，然后返回 `0`：

1. 若引擎对象存在 ⇒ 走它的虚析构（整个引擎对象释放）；
2. 关闭**单实例信号**（那个命名信号对象）；
3. 睡眠 500 毫秒；
4. 把引擎指针清空；
5. 输出一条调试文本（仅在正常清理完成时）；若第 1 步抛异常 ⇒ 只输出另一条"删除失败"的调试文本，流程**继续**；
6. COM 反初始化；
7. 释放运行期显式装载的两个系统模块（内核库、通用控件库）；
8. 销毁启动期建立的**文件句柄局部对象**（启动早期它曾在一个**存档 / 配置目录**的完整路径上以"只写"方式试写一个临时名文件、随即关闭；此刻已无打开的句柄，析构是空操作）；
9. 辅助宿主模块的包装对象析构（它会释放那个模块）；
10. 返回 `0`。

**不释放 / 不做**（同样是合同）：

- 窗口不在这里销毁：正常路径上窗口已在关闭处理里销毁；失败路径上不显式销毁（由进程退出回收）。
- 失败路径（启动期的任何中止）**不**做 5～7：不做 COM 反初始化、不释放那两个系统模块、不关单实例信号。
- 第 1～5 步包在一个保护区里，只有第 1 步可能抛；抛出时第 2～4 步**不执行**（`单实例信号` 保持打开、睡眠被跳过）。

**成立条件**

- 顺序是合同：第 1 步在第 2 步之前（引擎对象先于信号释放），第 2 步在第 3 步之前。
- 睡眠 500 毫秒是引擎常量，不是可配置项。
- 第 8 步的对象是**启动期在窗口之前**建的那个文件句柄局部对象；它的句柄在启动早期就已关闭，所以这一步实际不释放任何打开件。
- 返回 `0` 与"退出是否成功"无关：这是入口的正常返回形态（见「启动失败的返回形态」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 主循环已返回 | 引擎对象待析构；单实例信号仍打开 |
| 清理完成 | 引擎指针为空、信号已关、COM 已反初始化、两个系统模块已释放、辅助模块已卸 |
| 引擎析构抛异常 | 只输出"删除失败"调试文本，随后从第 6 步继续 |

### 启动失败的返回形态

<!-- rule: CORE-BOOT-FAIL-RETURN -->

**合同**

- 进程入口只有一个**非 0** 返回：**重复实例被拒** ⇒ 返回 `−1`。判据是启动时创建的**命名单实例信号**已存在（创建返回句柄但宿主错误码非 0）。这条路径**不做任何文件访问**、不建窗口、不装载索引。
- **其余所有启动失败都返回 `0`**，且都走同一条"不再前进"的出口（见「中止形状」）。它们的差别只在**前半段**：

| 失败点 | 显示消息 | 销毁顺序（在共享出口之前） |
|---|---|---|
| 索引（两族都失败） | 一条内建文本（用途：让人重新安装） | 命令行解析对象 → 引擎对象 |
| 窗口类注册 | **无** | 引擎对象此时还没建 |
| 建窗 | **无** | 引擎对象 → 启动期局部对象 |
| 图形初始化 | 一条内建错误文本写进引擎的错误通道 | 引擎对象 → 启动期局部对象 |
| 根脚本装载（返回值 ≠ 1） | **无** | 引擎对象 → 启动期局部对象 |
| 闸门（引擎错误标志） | 视失败点 | 多数与建窗同；有一处**跳过**引擎析构 |

- 失败路径都**不**做进程级清理（COM 反初始化 / 释放系统模块 / 关单实例信号）—— 见「退出后的清理」的"不做"清单。

**成立条件**

- "显示消息"用的是引擎自己的消息请求；文本是引擎内建资源，内容本版不规定。
- 返回值 `0` **不代表成功**：正常退出与启动失败都返回 `0`。要区分只能看"主循环有没有被调用"。
- 重复实例被拒发生在**窗口类注册之前**，因此第二条实例完全不碰文件、不碰窗口。
- "闸门"指引擎错误标志的查询；它不属于本章，本条只用到"失败就中止"。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 重复实例 | 返回 `−1`；无文件访问、无窗口 |
| 其它启动失败 | 返回 `0`；共享出口被走到 |
| 正常退出 | 返回 `0`；主循环被调用过 |

## 启动入口：入口 → 初始化 → 主循环

启动是引擎从宿主手里取得控制权、到主循环被调用之间的动作。**本版只规定以下三段**：取得索引、装载根脚本、把控制权交给主循环；**gate 判定与周期性定时器请求等动作本版不规定**（原因：判定内容与回调行为都没有取证）。这三段里任何一段不通，走同一条出口结束，不存在"部分成功"。

主循环内部的迭代、派发与等待属于《执行与时间》；本章只规定主循环被调用之前的事。

### 启动的边界：入口到主循环

<!-- rule: CORE-BOOT-ENTRY -->

启动阶段指**引擎取得控制权到主循环被调用**之间的动作。它只有一个入口：接收宿主给的实例与启动参数。成功路径的终点是**调用主循环**；失败路径走**共享出口**（见「中止形状」）。

- 启动的终点是"主循环被调用"这一件事。主循环被调用之后引擎还做什么、主循环是否会返回，本章都不规定。
- 进程启动到引擎入口之间由宿主完成，不属于本章。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 在启动阶段 | 主循环尚未被调用 |
| 启动阶段结束 | 主循环已被调用 |

**成立条件**

- "只有一个入口"指引擎自己的启动过程；宿主可以在此之前做任意多的事。
- 成功路径上，入口把控制权交给主循环；**主循环是否返回、入口之后是否再回到宿主，本版不规定**（原因：主循环的出口没有取证）。失败路径不通过返回值报告，走「中止形状」的共享出口。

### 索引先行

<!-- rule: CORE-BOOT-INDEX-FIRST -->

引擎在装载任何脚本之前**先取得索引**。索引给出"统一文件 id → 条目"的映射（条目的名字、所属归档、偏移与长度）；没有它就无法按 id 取到任何脚本。

- 先按 S4 族的固定文件名（`SYS4INI.BIN`）尝试；打不开再按 S3 族（`SYS3INI.BIN`）。两族都不成 ⇒ 见「索引打不开就中止」。
- 索引成功之后、根脚本之前，配置已经可用：发行默认表随索引尾部到达（见《配置》）。
- 本规则不规定"索引是不是启动的第一个文件动作"：更早的宿主阶段是否碰文件未取证。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 已有 id → 条目的映射 | 索引已装载 |
| 还没有映射 | 索引未装载 |

**成立条件**

- 先 S4 后 S3 的**回退顺序**是引擎行为，不是安装目录的偏好。
- 索引只提供映射；内容按《文件与脚本装载》的取件规则取得。

### 索引打不开就中止

<!-- rule: CORE-BOOT-INDEX-FAIL -->

两族的初始化文件都打不开 ⇒ 引擎向宿主**显示一条内建文本**（用途是告知重新安装；**文本内容本版不规定**），随后**不再前进**：不装载脚本、不建主循环、不做后续初始化。

- 这条中止**不通过返回值报告失败**：需要人看的失败用一条消息表达（见「中止形状」）。
- 中止前不留"半套"引擎状态：没有根脚本、没有主循环。
- 不重试：两族都已试过，没有"再试一次"的路径。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 启动失败（索引） | 一条显示请求；启动随即结束 |
| 启动继续 | 索引已装载，进入下一阶段 |

**成立条件**

- 文本是引擎内建的，不是脚本或配置提供的。

### 根脚本按统一文件 id

<!-- rule: CORE-BOOT-ROOT-SCRIPT -->

启动以**统一文件 id 0** 作为根脚本向装载器请求；请求时把服务窗口一并交给装载器（装载器需要它，本规则不规定用途）。

- 装载器返回"成功"标志（=1）才算装载成功；任何其它返回值 ⇒ 见「中止形状」。
- 按 id 而不是按文件名引用脚本是引擎的约定；脚本之间的相互引用也全是 id（统一 id 的两个区见《文件与脚本装载》）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 根脚本 = 统一 id 0 | 请求里的文件 id 为 0 |
| 装载成功 | 装载器返回成功标志（=1） |

**成立条件**

- 装载器对内容的合格判据（签名 / 版本 / 头部）属于《脚本与执行》；本规则只规定"按 id 请求"与"返回值怎么用"。
- 根脚本的 id 0 是引擎的起点约定，不是配置项。

### 中止形状：一条出口，没有部分成功

<!-- rule: CORE-BOOT-ABORT-SHAPE -->

启动期所有失败共享**同一条出口**：不再执行后续阶段，直接结束启动。启动没有"部分成功"——不存在"索引有了但没有根脚本、仍然进主循环"的形态。

- 中止不区分"用户可见的失败"与"内部失败"：两者都是"（有的带一条消息）+ 不再前进"。
- 中止不改返回值：与索引失败走**同一出口**、同样**不通过返回值报告失败**。
- "结束启动"不是"返回一个错误码"：需要人看的失败用消息表达。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 启动了 | 走完某阶段的正常分支，直到主循环被调用 |
| 没启动 | 走到共享出口 |

**成立条件**

- 这是可被独立实现复现的形状，不是"错误处理很弱"的评价。

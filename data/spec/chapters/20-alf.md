## ALF 归档

ALF 是**索引 + 数据体**的归档格式：索引文件（`*.AAI`）描述目录；数据体（`*.ALF`）按目录里的 `offset` / `length` 存放文件内容。★ 引擎里另有一个"初始化文件"加载器（头长 300、签名 `S?IN` / `S?IC`），它**不是** ALF 索引，本版不把它算进这一族。

本版把 ALF 作为**协议**描述（协议自持）；协议中已核验 / 部分 / 观察值的部分见表。

### 索引头

<!-- rule: FMT-ALF-HEADER -->

索引以一个 **268 字节定长头**开始；签名决定它是"裸目录"还是"压缩目录"：

| 族 | 签名 | 头长 | 归档记录步长 | 归档名字段 | 文件记录步长 | 文件名段 |
|---|---|---|---|---|---|---|
| S4 | `S3AI` / `S4AI` / `S3AC` / `S4AC` | `268` | `256` | `256` | `80` | `64` |

- **段**：容器中由长度界定的连续字节区。本规范用「TOC 段」指目录字节序列；AGF 的 meta / body 也是段。
- 头 `+0` 是签名；`+8` 是**标题串**（以 NUL 结束，宽度不固定）；头内其余字段本版不解释。
- 签名以 `AI` 结尾：头之后直接是**裸 TOC 段**，从 **268** 起。
- `S?IN` / `S?IC` 是**另一个加载器**（`SYS?INI.BIN` 这类初始化文件，头长 300）的签名，**不属于 ALF**。
- 更长的头 / UTF-16 文件名的变体在本作样本里**没有**，本版不规定。

### 加装档（AC）的压缩信息块

<!-- rule: FMT-ALF-ADDON -->

- 签名以 `AC` 结尾（加装档）：`[268,280)` 是 **12 字节压缩信息块**，TOC 段的压缩数据从 **280** 起，解压后与 `AI` 族的 TOC 段同布局。
- 压缩信息块 = 解压后长度 + 同一长度的第二份 + 压缩数据长度；紧随其后的是压缩数据。

### ALF 的 LZSS

<!-- rule: FMT-ALF-LZSS -->

ALF 的目录区使用 4 KiB 环形窗口的 LZSS：

- 窗口 `4096` 字节，写位置从 **4078** 开始；初始化只清零**前 4078 字节**，末尾 18 字节在对象构造时**未初始化**（解码若引用到那一段，读到的是未初始化内存，结果不可复现）；
- 最短匹配 `3`，最长匹配 `18`；
- 每个 flag 字节管 8 个单位，**低位先**；flag 位为 **1** ⇒ 字面量、为 **0** ⇒ 一个 `(位置, 长度)` 匹配（这个极性用真实 `*.AAI` 解出的 TOC 反证过：反过来解会把归档名解成 0）；
- 一个匹配占两个字节：第 1 个是位置的**低 8 位**，第 2 个的低 4 位是长度、高 4 位是位置的高 4 位；**位置是环形窗口内的绝对下标（0..4095）**，不是回退距离；**长度 = 低 4 位 + 3**（范围 3..18）；
- 拷贝从位置下标起逐字节向后推进，到 4095 后回绕到 0；匹配可以覆盖当前写位置（重叠匹配）——同一次匹配先写出的字节会被后续字节读到；
- 压缩信息块里的"解压后长度"与"压缩数据长度"**相等**时，数据原样存放（不跑解压）。

★ AGF 的 meta / body 与 ACIF 的 alpha 用的是**同一个**解压例程、**同一组参数**；ALF 与 AGF 不同的只是**容器**（压缩块放哪、解到哪），不是算法。因此"把 ALF 的解压器用于 AGF"在参数上成立，但**容器路径必须各走各的**。

### 目录区（TOC）

<!-- rule: FMT-ALF-TOC -->

解压后的目录区按顺序：

```text
u32 archive_count
archive_count × { filename[256] }        // 指向同目录的 *.ALF 数据体
u32 file_count
file_count × {
  filename[64]
  u32 archive_index
  u32 file_index
  u32 offset
  u32 length
}
```

- 两种记录都是定长：归档记录 256 字节（整条是名字字段）；文件记录 80 字节（名字字段 64 字节 + 四个 u32）。名字是 NUL 结束的字节串，NUL 之后的字节是填充（可能未初始化）。**不要**用"重新拼名字 + 补零"的方式重写（会破坏逐字节往返）。码页本版不规定。
- `file_index` 的用途**未查明**（实现注释也只写 "within archive?"）；本版只保真搬运，不解释。
- `offset` / `length` 指向对应 `.ALF` 数据体里的文件内容；载荷**原样存放**，不做二次压缩。
- 按索引取一个文件有两条路径：先按文件记录里的名字直接打开（能打开就用它）；打不开时按 `archive_index` 打开归档记录里的归档文件、定位到 `offset`、读 `length` 字节。
- 多份索引（本体 + 加装档）的叠加顺序与文件搜索路径本版不规定。

### 与 AGE 汇编格式的边界

ALF 是**容器**，不是脚本协议：它不包含 opcode / 操作数。脚本（ASM）见「脚本与执行」；AGF 图像见「AGF 图像」。

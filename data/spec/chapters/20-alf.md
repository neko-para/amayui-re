## ALF 归档

ALF 是**索引 + 数据体**的归档格式：索引文件（`*.AAI` / `SYS?INI.BIN`）描述目录；数据体（`*.ALF`）按目录里的 `offset` / `length` 存放文件内容。

本版把 ALF 作为协议描述；实现细节（`age-format`）不是来源。协议中已核验 / 待核验的部分见表。

### 索引头

索引以一个定长头开始；签名决定单字节还是 UTF-16LE 文件名：

| 族 | 签名 | 头长 | 加装档段起点 | 归档记录 | 文件名 | 文件记录 |
|---|---|---|---|---|---|---|
| S4 | `S3IC` / `S4IC` / `S3AC` / `S4AC` | `300` | `268` | `256` | `64` | `80` |
| S5 | `S5IC` / `S5AC` | `540` | `532` | `512` | `128` | `144` |

- 头的前 240 字节是标题，后 60 字节是未知区；S4 按单字节（latin1）读，S5 按 UTF-16LE 读。
- 引擎加载器还识别 `S3IN` / `S4IN`（在 `S3IC` / `S4IC` 之前比较）；实现当前只覆盖 `S3IC` / `S4IC` / `S3AC` / `S4AC`，`S3IN` / `S4IN` 的语义**待核验**。
- 签名以 `AC` 结尾表示**加装档**：段起点提前到「加装档段起点」，而不是完整头长。
- 段起点之后是 12 字节段头：
  - `u32 originalLength` —— 解压后的目录区长度；
  - `u32 originalLength2` —— 同一长度的第二份记录；
  - `u32 length` —— 紧随其后的 LZSS 压缩数据长度。
- 压缩数据解压后得到**目录区（TOC）**。

### ALF 的 LZSS

ALF 目录区使用 4 KiB 环形窗口的 LZSS：

- 窗口 `4096` 字节，最长匹配 `18` 字节，**最短匹配 3**；
- 每个 flag 字节管 8 个单位；单位可以是字面量，或 `(位置 12 位, 长度 4 位 + 3)` 的匹配；
- 位置是窗口内偏移，长度 = `(hi & 0x0F) + 3`。

★ AGF 的 LZSS 参数不同（最短匹配 3），**不能互相替代**。

### 目录区（TOC）

解压后的目录区按顺序：

```text
u32 archive_count
archive_count × { filename[arcEntry] }        // 指向同目录的 *.ALF 数据体
u32 file_count
file_count × {
  filename[filName]
  u32 archive_index
  u32 file_index
  u32 offset
  u32 length
}
```

- 归档记录的名字是定长字段；字段尾部可能含未初始化字节，**不要**用"重新拼名字 + 补零"的方式重写（会破坏逐字节往返）。
- `file_index` 的用途**未查明**（实现注释也只写 "within archive?"）；本版只保真搬运，不解释。
- `offset` / `length` 指向对应 `.ALF` 数据体里的文件内容；载荷**原样存放**，不做二次压缩。
- 因此"读索引 → 读归档 → 按 offset/length 切片"就是取文件的完整路径。

### 与 AGE 汇编格式的边界

ALF 是**容器**，不是脚本协议：它不包含 opcode / 操作数。脚本（ASM）见「脚本与执行」；AGF 图像见「AGF 图像」。

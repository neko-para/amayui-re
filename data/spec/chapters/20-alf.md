## ALF 归档

ALF 是**索引 + 数据体**的归档格式：索引文件（`*.AAI`）描述目录；数据体（`*.ALF`）按目录里的 `offset` / `length` 存放文件内容。★ 引擎里另有一个"初始化文件"加载器（头长 300、签名 `S?IN` / `S?IC`），它**不是** ALF 索引，本版不把它算进这一族。

本版把 ALF 作为协议描述；实现细节（`age-format`）不是来源。协议中已核验 / 待核验的部分见表。

### 索引头

索引以一个 **268 字节定长头**开始；签名决定它是"裸目录"还是"压缩目录"：

| 族 | 签名 | 头长 | 归档记录步长 | 文件记录步长 | 记录内文件名字段 |
|---|---|---|---|---|---|
| S4 | `S3AI` / `S4AI` / `S3AC` / `S4AC` | `268` | `256` | `80` | `64` |

- 头 `+0` 是签名；`+8` 是**标题串**（以 NUL 结束，宽度不固定）；头内其余字段本版不解释。
- 签名以 `AI` 结尾：头之后直接是**裸目录区**；以 `AC` 结尾（加装档）：头之后多一个 **12 字节压缩信息块**，目录区是 LZSS 压缩的。
- 压缩信息块 = 解压后长度 + 同一长度的第二份 + 压缩数据长度；紧随其后的是压缩数据。
- **段起点在两种情况下都是头长**（268）："加装档提前"是相对"头 + 12 字节块"而言，不是另一个偏移量。
- `S?IN` / `S?IC` 是**另一个加载器**（`SYS?INI.BIN` 这类初始化文件，头长 300）的签名，**不属于 ALF**。
- 更长的头 / UTF-16 文件名的变体在语料里**没有样本**，本版不规定。

### ALF 的 LZSS

ALF 的目录区使用 4 KiB 环形窗口的 LZSS：

- 窗口 `4096` 字节，写位置从 **4078** 开始；初始化只清零**前 4078 字节**，末尾 18 字节的初值不在本版规定（解码若引用到那一段，结果不可复现）；
- 最短匹配 `3`，最长匹配 `18`；
- 每个 flag 字节管 8 个单位，**低位先**；单位可以是字面量，或一个 `(位置, 长度)` 匹配；
- 一个匹配占两个字节：第 1 个是位置的**低 8 位**，第 2 个的低 4 位是长度、高 4 位是位置的高 4 位；长度 = 低 4 位 + 3 ⇒ 位置 12 位、长度 4 位；
- 压缩信息块里的"解压后长度"与"压缩数据长度"**相等**时，数据原样存放（不跑解压）。

★ AGF 的 meta / body 与 ACIF 的 alpha 用的是**同一个**解压例程、**同一组参数**；ALF 与 AGF 不同的只是**容器**（压缩块放哪、解到哪），不是算法。因此"把 ALF 的解压器用于 AGF"在参数上成立，但**容器路径必须各走各的**。

### 目录区（TOC）

解压后的目录区按顺序：

```text
u32 archive_count
archive_count × { filename[arcEntry] }        // 指向同目录的 *.ALF 数据体
u32 file_count
file_count × {
  filename[filName]
  u32 archive_index
  u32 file_index
  u32 offset
  u32 length
}
```

- 归档记录的名字是定长字段；字段尾部可能含未初始化字节，**不要**用"重新拼名字 + 补零"的方式重写（会破坏逐字节往返）。
- `file_index` 的用途**未查明**（实现注释也只写 "within archive?"）；本版只保真搬运，不解释。
- `offset` / `length` 指向对应 `.ALF` 数据体里的文件内容；载荷**原样存放**，不做二次压缩。
- 因此"读索引 → 读归档 → 按 offset/length 切片"就是取文件的完整路径。

### 与 AGE 汇编格式的边界

ALF 是**容器**，不是脚本协议：它不包含 opcode / 操作数。脚本（ASM）见「脚本与执行」；AGF 图像见「AGF 图像」。

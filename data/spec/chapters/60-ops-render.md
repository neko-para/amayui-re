## 渲染请求边界：目标、混合、离屏文字族、清屏与帧步进

本章的规则逐条点名它覆盖的 opcode（见各小节标题）；未列出的 opcode 本版不作断言。

本章的规则分两类：**作用在渲染路径的输入状态 / 表面内容**上的（把某个纹理槽的纹理设为当前渲染目标、设置场景混合的模式与颜色、把文本 / 数值文本画进某个纹理槽的纹理），以及**帧与画面级**的（清屏、帧步进 —— 后者定义主循环与脚本共用的**渲染步**，遍历 / 提交；清、38 贴回等见该条残差）。
它们改**引擎数据**（以及离屏文字族写入的纹理表面内容）。除 `0x33f` 外都向外部渲染模块发请求
（`0x20d` / `0x204` / `0x205` / `0x20e` / `0x20c`）；请求的形态写在每条里，平台侧的行为不在本版。
本章也把「外部请求」与「引擎数据改变」分开写：请求本身是可观察的，请求的结果不是。

### 渲染目标：opcode 0x20d

<!-- rule: CORE-OPS-RENDER-TARGET-20D -->

`0x20d` 有一个操作数：**第 1 个是纹理槽号**；读一次，按整数读，比较按**无符号**做。长度槽 ← 3。

- 操作数 **小于 1000** ⇒ 目标是该编号的**纹理槽**（纹理槽的定义见「纹理族」）：
  - 槽里没有对象 ⇒ 向**错误通道**（术语见「总览与约定」）上报一条文本（说明该纹理尚未创建）；本条**不改当前渲染目标**。
  - 槽里有对象 ⇒ 先向外部请求该纹理的**渲染表面**（一个可用于绘制的平台表面）；取不到 ⇒ 错误通道上报（说明渲染表面获取失败）；本条不改当前渲染目标。
  - 取到 ⇒ 再请求把该表面**设为渲染目标**；失败 ⇒ 错误通道上报（说明渲染目标设置失败）；本条不改当前渲染目标。
  - 成功 ⇒ **当前渲染目标 = 该槽号**。
- 操作数 **不小于 1000**（按无符号比较，因此负的整数也落在这一支）⇒ 目标是**平台后缓冲**（取后缓冲 + 设为渲染目标）：
  - 先请求平台后缓冲；取不到 ⇒ 错误通道上报（说明后缓冲获取失败）；本条不改当前渲染目标。
  - 取到 ⇒ 请求把它设为渲染目标；失败 ⇒ 错误通道上报（说明后缓冲目标设置失败）；本条不改当前渲染目标。
  - 成功 ⇒ **当前渲染目标 = 「后缓冲」哨兵**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 场景的当前渲染目标 | 场景记录里的一个整数字段 ← 纹理槽号 / 「后缓冲」哨兵 |
| 错误通道 | 一次上报（仅失败路径；文本为说明型消息，内容本版不规定） |
| 取到的渲染表面 | 一份平台侧引用：请求结束后归还（成功与失败路径都归还） |

**成立条件**

- 只有两段：**小于 1000 / 不小于 1000**。不小于 1000 **不是**"槽号越界错误"，而是"复位到后缓冲"的合法入口；正因为比较按无符号做，负数也走这一支。
- 1000 是本条的分支阈值，不是另取证的纹理容量：纹理族对编号不做范围检查（见「纹理族」的「状态模型」）。⇒ 编号 ≥ 1000 的创建是**越界写**（未定义行为；容量与后果本版不规定，见残差），不是"产生一个本条不认的合法对象"；⛔ 不许据此认为存在编号 ≥ 1000 的合法纹理对象。
- 所有失败都发生在写当前渲染目标**之前** ⇒ 失败时该字段保持原值。它的**初值是「后缓冲」哨兵**（场景建立时写入；场景建立本版不规定，见残差）。
- 成功路径**先取表面、再设目标、再归还表面**：归还发生在写当前渲染目标之前，两者次序不可交换。
- 本条**不建**纹理对象、不改纹理槽、不改绘制项、不置脏标记；它不抛引擎自己的错误（操作数类型异常仍按「数据池」的通用规则生效）。
- 错误文本可能带平台返回码的文本转写 ⇒ 内容本版不规定；实现必须**仍然上报**，不得静默。
- 平台是否真的切换了目标、后缓冲是否真的可见，属外部模块：本版只规定请求、参数与状态写入。

**残差**

- `RES-RENDER-TARGET-PLATFORM`（unknown）：平台侧是否真的切换了目标、后缓冲是否真的可见不在本版。下一步：在表现层观察 `SetRenderTarget` / `GetBackBuffer` 的返回与画面变化。
- `RES-RENDER-TARGET-SURFACE`（unknown）：取渲染表面时两个附加实参都传 0，它们的语义本版不规定。下一步：按表面请求的实参表核这两个常量。
- `RES-RENDER-TARGET-ORDER`（unknown）：本条写目标格发生在**门之后**，因此它从**下一次渲染步**（门前那次或 `0x20c` 那次）起生效；命令档在步内的切 / 恢复由 `CORE-SCENE-DRAW-ORDER` 规定。仍未定的是编号 38 的切 / 贴回 / 复位、以及平台换链 / 垂直同步的逐位行为。下一步：补 38 的实参；平台逐位表现进 discards。
- `RES-RENDER-TARGET-BOUNDS`（unknown）：编号 ≥ 1000 的创建写到纹理槽表之后，属未定义行为；本版只说明"不是合法对象"，不规定越界写的后果。下一步：按纹理族的编号上限与槽表容量取证。
- `RES-RENDER-TARGET-FIELD`（unknown）：渲染步在**步末**读它判「是否提交」；命令档在步内的切 / 恢复也读它（由场景章规定）。仍未枚举的是所有其它读者。下一步：枚举该格的读取点，确认是否还有别的分支。
- `RES-RENDER-TARGET-INIT`（unknown）：场景建立路径与目标格初值的写入点不在本版。下一步：把场景建立作为表现层 / 场景族的条目成篇。
- `RES-RENDER-TARGET-TEXT`（unknown）：三条失败路径的错误文本内容本版不规定。下一步：按错误通道的调用点枚举文本。

### 场景混合：opcode 0x33f

<!-- rule: CORE-OPS-RENDER-BLEND-33F -->

`0x33f` 有三个操作数：**1 = 混合模式**、**2 = 透明度**、**3 = 颜色**。长度槽 ← 7。
读序是 **2 → 3 →（按需）1 →（按需）1 → 1**：前两个总是先读；第 1 个只在下面两种回退发生时被读，最后写模式时再读一次。

- **归一化**：透明度 > 255 ⇒ 按 255；透明度 < 0 ⇒ 取**编号 1 指向的绘制项**（见「场景 / 颜色族」）的**当前颜色的透明度**；颜色 < 0 ⇒ 取**该绘制项的当前颜色**；其余情况取参数本身（★ 颜色的位 31–24 仍**不参与**结果，见下条「合成」）。这段归一化与「场景 / 颜色族」的共用口径**同形**（含「颜色的高 8 位永不参与」那一条），但有两处差别：**回退来源**是编号 1 指向的那条绘制项（不是"本条上次写的值"）；并且本条**不建**默认绘制项（见下）。窗进行中这里读的是**当前颜色字段**，不是这一步的插值色（插值色不是记录字段）。
- 该绘制项不存在 ⇒ 回退值取「无颜色」哨兵；本条**不建**绘制项（它只查表，不走场景族共用口径里的"取记录：查不到先建默认记录"那一步）。
- **合成**：结果 = `(透明度段 << 24) | RGB 段` —— **透明度段** = 归一化后的透明度，**RGB 段** = 归一化后**颜色的位 23–0**。位布局就是「场景 / 颜色族」共用口径的那一个（位 31–24 = 透明度，位 23–16 = 红，15–8 = 绿，7–0 = 蓝），⛔ 不是"另一套位段"。★ 颜色参数的**位 31–24 永不参与**：即使颜色 ≥ 0，进结果的也只是它的低 24 位（写成"取参数本身"会把这 8 位带进去 ⇒ 错）。
- 写两个引擎数据：**场景混合的模式 ← 第 1 个操作数原样**（不归一、不夹取、不查表）；**场景混合的颜色 ← 合成结果**。
- 本条**不发外部请求**：模式与颜色由渲染路径稍后读取；读取方怎样分支属外部模块，本版不规定。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 场景混合的模式 | 场景持有的**效应对象**上的一个整数格 ← 第 1 个操作数 |
| 场景混合的颜色 | 同一对象上的一个颜色格 ← 合成结果 |

**成立条件**

- 模式格**原样**收下操作数：取 0、取 1、取 3、取很大的值都照写；⛔ 不许 clamp 到某个模式枚举。
- 回退色读的是**绘制项**（与绘制纹理、排渐变窗用的同一张表），⛔ 不是"场景混合自己的旧颜色"：把上一趟写进颜色格的值当归一化输入，会在颜色格被改过之后得到不同结果。
- 模式与颜色是**两个格**：只写颜色不写模式、或反之，都不是本条。
- 本条**不置脏标记、不置「场景有动画」**：它不参与场景的动画推进。
- 效应对象由场景建立路径构造（初值：模式 = 0、颜色 = 「无颜色」哨兵；场景建立本版不规定，见残差）；本条**不检查**它是否存在 —— 对象不在场时解引用即未定义行为，按崩溃诊断。
- 第 1 个操作数在**两种角色**下被用：模式值、回退查表的键。两者是否同一领域概念**本版不规定**（见残差）。

**残差**

- `RES-RENDER-BLEND-OPERAND1`（unknown）：第 1 个操作数同时被当作"混合模式"写入与"绘制项查找键"使用；两个角色是否同一领域概念本版不规定。下一步：找效应对象两个格的读者，确认模式值是否与绘制项键同一空间。
- `RES-RENDER-BLEND-OBJECT`（unknown）：效应对象的构造与生命周期不在本章；本条只规定两个格的写入与回退读取。下一步：把效应对象的构造 / 释放作为表现层条目单独立条。
- `RES-RENDER-BLEND-INIT`（unknown）：效应对象的初值（模式 = 0、颜色 = 无颜色哨兵）由场景建立路径写入，该路径本版不规定。下一步：同 `RES-RENDER-TARGET-INIT`。
- `RES-RENDER-BLEND-NOCREATE`（unknown）：本条不建默认绘制项，与「场景 / 颜色族」的"取记录先建默认"不同；原因未逐字取证。下一步：核该查找路径，确认它不走到建默认记录的分支。
- `RES-RENDER-BLEND-PIXEL`（unknown）：模式与颜色如何参与像素混合属表现层。下一步：逐位表现按项目口径进 discards。

### 离屏文字：opcode 0x204

<!-- rule: CORE-OPS-RENDER-TEXT-204 -->

`0x204` 有四个操作数：**1 = 纹理槽号**、**2 = 横坐标**、**3 = 纵坐标**、**4 = 文本**。长度槽 ← 9。
读序是 **3 → 2 → 4 → 1**：第 3、2 个按整型读，第 4 个按**文本**读（先于第 1 个），第 1 个按整型读。

- 第 4 个操作数按文本读：字符串型操作数给出它的字节串；数值型操作数给出**十进制文本**（口径同「字符串」的源侧：整数无前导零、无宽度填充；浮点定点 6 位小数）；内联文本按「数据池」解码。
- 文本的字节串按 **Shift-JIS** 解释：单字节与双字节混排，**前导字节**引入一个双字节字符（两个字节合成一个字）；`0x8140`（**全角空格**）走一个**特例分支**（它的量度与落像素行为本版不规定）。**推进量不是无条件等于字形量度**：半角字符（`< 0x100`）、空白宽度配置、以及对位模式都会改变它；本版不规定逐档算法（见残差 `RES-RENDER-TEXT-ADVANCE`）。
- **入口条件**（**三条**，都在发请求**之前**判；任一不满足 ⇒ 本条什么都不做：不发请求、不改引擎数据、不报错）：
  1. 该槽里有纹理对象（纹理槽见「纹理族」）；
  2. 该纹理对象的一次**只读询问**返回非空（与「渲染目标」那条取表面用的是同一个询问）；
  3. 文本**非空**（首字节非 0）。
- **字体与颜色不是操作数**：本条**没有**字体 / 颜色实参。绘制入口自己从引擎**唯一**的字体对象读取：
  - **字体** = 该对象持有的 **A 支字体描述**里的**横排那一份**（字面名、高度、粗细、字符集）以及由它**物化**出的平台字体句柄。
    ★ **每支各两份描述**（横排一份、竖排一份；竖排那份物化时的字符走向 = 2700），两支合计**四**份 ——
    见「转发到字体对象与宿主接口的入口」。描述本身由别的 opcode 改（字号 / 粗细 / 字面名），改完请求重建；
  - **颜色** = 该对象的**主色 / 副色**两个 24 位值（主色默认**白**、副色默认**黑**）。脚本侧写进来的是 `0xRRGGBB`（高字节红、低字节蓝）；写入字体对象时按 **COLORREF 的 BGR 序**存放（低字节红、高字节蓝，最高字节不用），所以同一个数值在"脚本侧"与"存储侧"的字节顺序**不同**。★ 这不是场景混合色的颜色格序（场景颜色格的高 8 位是透明度，低 24 位才是 RGB；见「场景混合」）—— 两套字节序不要互借。
- **请求**（一次同步绘制，内部含多条平台请求）：把该文本逐字画进该槽的纹理 —— 参数 = 横坐标、纵坐标、文本。顺序：
  1. 字体对象：把**「按算出的格宽推进」开关**清 0（0 ⇒ 本条用字形步进；半角 < 0x100 走半角公式，见残差）；
  2. 若**显示记录**里的**虚拟全屏类型**格（= 配置 `display:VirtualFullScreenType` 的当前值；"虚拟全屏"关时该格为 0）等于 **2**，把该对象物化出的字体句柄**选进**绘制表面（`SelectObject`）；不等于 2 就**不选**（用绘制表面当前已经选着的那个字体）。
  3. 取一次**本次量度**（`GetTextMetrics`）；
  4. **纵向对位**：**仅当**该对象的**对位模式**等于 **1** 时，`纵坐标 ← 纵坐标 + 量度缓存里的 ascent − 本次量度的 ascent`；否则**纵坐标原样**。缓存里那个 ascent 是**上一次走「不销毁旧句柄」那套重建入口**（列表章 `0x78` / `0x2db` 条尾跳进去的那一套）时对**重建入口自己组的那份参考字体**做的那一次量度的 ascent 分量（**取自文本度量那一张**，不是字形度量那张） —— ★ **那次量度是无条件做的**：重建入口在名字非空时先写两份描述的高度，**紧接着就取一次参考字体量度**（把量度写进字体对象的**两张**量度结构 —— 一张**文本度量**、一张**字形度量**），**之后**才按对位模式是否为 0 分岔；⇒ 缓存**不是**"对位模式 ≠ 0 的分支才写"（对位模式只决定随后的**派生**跑不跑，见「列表」的 `0x78` / `0x2db` 条）。★ **另一套（重建前先销毁旧句柄的那一套）重建入口**取的量度落进**它自己那张**结构（不是上面这两张里任何一张），**不写这个缓存** ⇒ 缓存的唯一写者是**不销毁那一套**；⛔ 不许把缓存口径写成"最近一次重建（不分哪一套）的量度"。参考请求 = 字面名常量「ＭＳ ゴシック」、高度 = −字号（该字号若带缩放比，缩放乘在建字体那一步，见「转发到字体对象…」）、宽度 = −字号/2、**粗细取对象描述的粗细**、字符集 = 默认（宽度取整与字符集默认值见 `RES-RENDER-TEXT-ALIGN-REFERENCE`）；**不是对象当前字面名那份渲染字体**，也不是"上一次 `0x204` 的量度"、更不是常量 0。所以这一步的效果是"把参考字体与本次量度的基线差补回来"。
  5. 按**绘制模式**二选一进入两条绘制入口（模式 = 0 ⇒ "只画主色一遍"的那条；模式 ≠ 0 ⇒ 另一条，并把模式作为实参传进去）。两条入口内部**同形**：取该纹理的尺寸 / 描述 → **加锁**表面 → **落字前**把**纵坐标 ← 纵坐标 + 本次量度的 ascent** → 逐字取字形并写入（每字按推进量前进）→ **解锁**（⇒ 落字用**基线**，第 3 个操作数（纵坐标）是**字形格顶**）。
     **基线** = 第 3 个操作数的**原值** +（对位模式 = 1 ? 缓存 ascent : 本次 ascent）。★ **对位模式与绘制模式是两个正交的轴**：绘制模式决定走哪条入口、画几遍颜色；对位模式在**本请求的纵向对位**上决定基线用哪个 ascent（它对推进量与重建量度的作用不在本条，见本章残差与 `0x2db` 条）。
- **两条绘制入口只差一个绘制模式**（模式**不是操作数**，是字体对象的一格，默认 **1**）：

| 模式 | 效果 |
|---|---|
| 0 | 只画主色一遍 |
| 1 | 先按**投影偏移**（常量 (1, 1)，见下）画一遍**副色**，再在同一位置画**主色** |
| 2 | 主色在**同一位置**画两遍 |
| 3 | **副色**按**多趟径向**画：以两个投影偏移分量为半径、按等步长绕行取样（步长 = 360 ÷ (√(偏移纵 ＋ 偏移横) × 8)；偏移 (1,1) ⇒ 累计角度每趟 +31.82°、共 **12 趟**，累计约 1.94 圈），每趟的位移 =（round(sin(θ) × 偏移横), round(cos(θ) × 偏移纵)），θ = 累计角度 × 180 ÷ π（★ 引擎这个乘法方向就是如此，见下）⇒ 12 趟的位移收敛成 **6 个方向**（(0,±1)、(±1,0)、(1,1)、(-1,-1)）；最后画**主色** |

  ⛔ 模式不是操作数：把它从操作数里取，会把纹理槽号当成模式。
- **投影偏移**恒为 **(1, 1)**（横向、纵向各一个整数，单位 = 设备像素）：构造时置入；**本条绘制请求只读它，不调用样式应用 / 字体重建**，因此本条读取到的值不受那些入口影响。⛔ 不是资源文件的字段、⛔ 不是配置键、⛔ 也不是任何脚本操作数写进来的值；⛔ 不许实现成可配置 / 可从资源读的值。★ **其它直接调用绘制入口的路径**在**另一条应用路径**的借用期读到的是**样式值**（不是 (1, 1)）；它们是否把该值用于字形格 / 推进量，见残差 `RES-RENDER-TEXT-PROJECTION`。
- 绘制侧的用法：模式 1 的副色趟画在（横 + 偏移横, 纵 + 偏移纵）；模式 3 的径向以两个偏移分量为半径、按步长取点（累计角度从 0 起，< 360 就再画一趟 ⇒ 偏移 (1,1) 时共 12 趟、扫过约 1.94 圈；角度的三角函数实参是**累计角度 × 180 ÷ π**，本版照抄引擎的乘法方向，⛔ 不要"修正"成 × π ÷ 180 —— 那会换出 8 个方向的位移）；模式 0 / 2 不读它。
- **字形位图的请求格式**由**字体对象**的**抗锯齿开关**决定：**两者都非 0 才开；任一为 0 / 缺键 ⇒ 关 ⇒ 每像素 1 位（掩码）**。开关 = 配置的**总开关** `set:EnableAntiFont`（取值含「配置」章对 `ENABLEANTIFONT` 的平台条件改写）与**子开关** `message:UseAntiFont`；级数格 = 配置的 `message:AntiFontLevel`（= 1 ⇒ **8 位**，其余 / 缺键 ⇒ **4 位**）—— 它就是「转发到字体对象与宿主接口的入口」条里的**灰阶位深档**（**同一格**，两处口径必须一起读）。⛔ 不是平台自由：⛔ 不许无条件用平台的灰度抗锯齿，也⛔ 不许把 1 位与灰度当成同一格式。★ **两格的初值都只在启动期从配置抄进来**：字体构造时两格先清 0；之后由**进程启动时的那一条"应用设置"入口**从配置键抄入（总开关为 0 ⇒ 整块跳过、两格保持构造期的 0）；同一个入口内**顺序固定：先开关、后级数**，且**写级数这一步本身不重建字体、不清缓存**（开关那一步会重建 / 清缓存，见「转发到字体对象与宿主接口的入口」条）。运行期设置提交只把**开关**重新应用，**级数没有**对应的重应用路径 ⇒ **运行期改级数不影响本次会话**（改开关则立即生效）。⇒ **8 位档在发行态可达**（总开关非 0、子开关非 0、级数 = 1）—— ⛔ 不许把它写成"恒 4 位档"。⛔ 不许实现成"每次绘制都重读配置"。
- **级数 → 覆盖值**：字形位图里每个像素的**原始级数**按该格式的值域取值 —— **4 位灰度 0..16（17 级）**、**8 位灰度 0..64（65 级）**（0 = 无覆盖）、**1 位掩码只有 0 / 1**。引擎把它换算成**逐像素覆盖值** = **原始级数 × 255 ÷ 除数**，**除数 = 17（4 位）/ 65（8 位）**，整除（正数向下取整）⇒ 4 位的覆盖值 ∈ {0, 15, 30, …, 240}（**满覆盖 240**）；8 位的覆盖值 = ⌊原始 × 255 ÷ 65⌋ ∈ {0, 3, 7, …, 251}（**满覆盖 251**，不是连续区间）；1 位掩码的覆盖值是 0 / 255 —— **只有它的覆盖值能到 255**。⛔ 除数不是 2 的幂（16 / 64）：按 2 的幂算会把满覆盖抬到 255，抗锯齿档下的文字比引擎亮一档。⛔ 也不是把原始级数直接当覆盖值（4 位格式里原始 16 才是满覆盖，它对应 240、不是 16）。
- **覆盖值不是"像素不透明度"**：三种量必须分开 —— **覆盖值**（上一段，0..255）、**通道值**（真正写进表面某个通道的那个数）、**像素不透明度**（写完后的 alpha）。表面有 **16 位与 32 位两种**，两者通道满值不同：**32 位表面**的通道值 = 覆盖值（满值 **255**）；**16 位表面**先把覆盖值**算术右移 4 位**（向下取整）降到 4 位通道（0..15、满值 **15**），且这次降位发生在三条短路判据**之前**（判的是降位后的**通道值**，不是覆盖值）。写入后像素的不透明度 = **目标不透明度与通道值里的较大者**（不是直接等于通道值）⇒ 目标本来就更不透明时，像素不透明度可以超过**通道值**（32 位表面通道值就是覆盖值；例如目标已是 255 时，灰度字形的像素不透明度也是 255）。⛔ 别把"16 位表面上 1 位掩码的覆盖值 255"读成"像素不透明度 255"：那个表面的通道值最多 15。
- **写入：三条支路**（按**通道值**与目标像素**自身的不透明度**选，⛔ 不是"一律 alpha 混合"）：
  1. **通道值 = 0** ⇒ **一个字节都不写**（目标像素原样保留；⛔ 不是"写一个透明像素"）。16 位面上覆盖值 15（灰阶最小非 0 级）右移后就是 0 ⇒ 落在这一支。
  2. **通道值达到该表面的通道满值**（32 位表面 = 255；16 位表面 = 降位后的 15）⇒ **整像素覆写**：颜色 ← **源色原值**、不透明度 ← **通道值**，**不读目标像素**（⇒ 同一像素重复写同一字形是幂等的；**刚清空的画布上满覆盖像素的第一次写入**走这一支；半覆盖像素走下一支「读了目标之后」）。
     ★ **结果相同但触发不同的一支**：**读了目标之后**目标的**不透明度 = 0** ⇒ 也**整像素覆写**（颜色 ← 源色原值、不透明度 ← **通道值**），不做混色。这一支**必须读过目标**才知道（它与下一条共用同一次读）；⛔ 不许把两支并成"都不读目标"，也⛔ 不许把它写成"`通道值 = 0`"（那会把半量字形在空画布上的第一次写入抹掉）。
  3. 其余 ⇒ **逐通道加权**：通道 ← (源 × 通道值 + 目标 × (通道满值 − 通道值)) ÷ 通道满值；输出不透明度 ← **目标与通道值中的较大者**（⛔ 不是"等于通道值"、⛔ 不是 alpha-over）。
  ★ 三条支路共用同一个写入点。**逐通道乘除的取整顺序、位打包的实现、16 位表面降位后的实际位模式**属逐位表现，见残差。
- **加锁不是入口条件**：它发生在请求内部（请求的第 5 步）；加锁失败时，前 1–4 步已经发生的副作用**不回收**（已清的开关、可能已选的字体、已取过的量度），只是不写像素并上报错误通道。
- **特殊字形路径**：逐字写入时，若**字形码**是 `0xF042` 或 `0xF043`（私用区字形），进入特殊路径：**解锁 → 矩形操作 → 重新加锁**。`0xF043` 做**一次**、`0xF042` 做**两次**（第二次的起点再叠加一次投影横偏移与推进量）；矩形由该字形的**字框**（origin / blackbox 分量）加投影横偏移与当前推进量装配。矩形操作本身的语义（拷贝 / 填充）本版不规定（见残差）。其它字形不走这条路径。
- **回退字体**：逐字写入时，若**字形码 < 0x100**，用字体对象里那份**回退字体描述**建一个临时字体、选进绘制表面并把回退状态置 1；字形码 ≥ 0x100 时**只释放**（把**请求开始时**选着的句柄选回、删临时字体、状态清 0）。临时字体不写进描述、不持久。★ 回退字体与半角推进共用字符范围（< 0x100），但**不是同一个门**：前者建临时字体，后者改推进量。
- **引擎数据**：字体对象的字形暂存区被复用 —— 字形位图长度与两份暂存缓冲被重建（长度请求与本体请求必须同格式）；两个内部布尔开关被写（一个与本条开始清 0 的是同一个；另一个是**回退字体**的状态）。它们都不是脚本可观察的值。
- **失败**：
  - **字形取不到** ⇒ **不报错**：不写像素，只按推进量前进（见上）。
  - **加锁失败** ⇒ **不写任何像素**，并由加锁操作向**错误通道**写一条文本（内容本版不规定）。
  - **取尺寸失败**与**加锁失败**同一出口（不写像素、本函数不报错）；**取矩形失败**未定位（见残差）。
  - 操作数类型异常仍按「数据池」的通用规则抛出。
- 操作数 1 直接作为纹理槽号；本条**自己**不做 1000 阈值判断（那是 `0x20d` 的分支）。纹理族对编号**不做范围检查**：编号 ≥ 1000 或负值的越界后果本版不规定（同「渲染目标」的纹理族口径）。
- 本条**不建**纹理、不改纹理槽、不改绘制项、不置脏标记、不改池 / 帧 / 列表记录。
- **字体对象的其它维护入口**（字段清单分别落在「列表」的 0x78 / 0x2db 条与「标量」的 0x76 / 0x77 / 0x2bd 条）：`0x75` = 字号；`0x76` / `0x77` = **主色** / **副色**；`0x78` = **绘制模式**；`0x2bd` = **粗细**；`0x2db` = **对位模式**；`0x197` = **B 支字号**；字面名由两条"设置字符串"的入口分别写入两份描述（哪条写哪份见残差）。⛔ `0x203` **与文字无关**：它写的是另一族的绘制色表，不是本条的颜色来源。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个纹理槽的纹理被画上一段文本 | 该槽纹理对象的**表面内容** ← 逐字写入的字形（像素不判，见下） |
| 字体对象的字形暂存区被复用 | 两份暂存缓冲与字形位图长度格被重写（内部缓存；布局属机器细节） |
| 字体重建时量到的 ascent 被缓存 | 字体对象**文本度量那张**量度结构的 ascent 分量 ← **不销毁旧句柄的那套**重建入口在名字非空时**无条件**取的那次参考字体量度（对位模式只决定随后跑不跑派生；另一张**字形度量**不提供这个分量；**销毁旧句柄的那套**把量度落进它自己那张结构，不改这里） |
| 请求 | 一次同步绘制：清一个内部开关 →（虚拟全屏类型 = 2 时）选字体 → 取量度 → 纵向对位（仅对位模式 = 1）→ 按绘制模式进两条入口之一 → 取尺寸 / 描述 → 加锁 → **落字前纵坐标 += 本次量度的 ascent** → 逐字取字形（**格式见上**）→ 写入 → 解锁（特殊字形路径在写入中解锁 / 重锁） |

**成立条件**

- 三**条**入口条件都在请求**之前**判：不满足时纹理表面与字体对象的内部缓存**都不动**；⛔ 不许"先清开关再判"。加锁在请求内部，失败后果见「失败」，★ 不把"能不能加锁"提前成第 4 条入口条件。
- 文本为空**不是**错误：不画、不报错。文本为空判的是**首字节**，不是"去掉空白后为空"。
- 第 4 个操作数**先于**第 1 个被读：第 4 个读取抛类型异常时，第 1 个还没被读。
- 请求**同步**完成：本条不置等待位、不置影片位、不等待下一帧；分派器在本条返回后推进指令指针。
- 字体、主色 / 副色、绘制模式**都不是操作数**：⛔ 不许从操作数里取字体或颜色，也⛔ 不许把操作数当绘制模式。
- 纵向对位**只在**对位模式 = 1 时做：其它模式**不做对位修正**（不加减缓存与本次 ascent 的差），但第 5 步落字前仍会加**本次 ascent**。⛔ 不许实现成"总是修正"，也不许把缓存里的 ascent 当成"本次量度"。
- 第 3 个操作数（纵坐标）是**字形格顶**，不是基线：两条绘制入口都会在落字前加上**本次量度**的 ascent。⛔ 不许把它当基线直接落字 —— 那会把整段文字上移一个 ascent。
- 对位模式 = 1 的对位项用的是**字体重建时对参考字体**量到的 ascent 分量（不是渲染字体的 ascender），⛔ 不许把它当成常量 0 —— 那会把整段文字上移一个 ascent（在纹理上表现为文字从本行 30px 源带跨到相邻源带）；⛔ 也不许拿渲染字体的 ascender 代替它 —— 两者不保证相同，基线会偏（差多少取决于两种字体的 ascent 与字号；观测见残差）。
- **四种组合**都要对：绘制模式（0 / ≠0）× 对位模式（0 / 1）只影响"走哪条入口"与"基线用本次还是缓存的 ascent"（就本请求的纵向对位而言），两个轴**正交**；⛔ 不许把两种模式混成一个开关。
- 两条入口的**选择只看绘制模式是否为 0**：⛔ 不要说成"由另一个内部选择格二选一"（那是同一条模式格的两种说法）。
- 模式 0 与模式 1 **不是同一件事**：模式 0 只画主色，模式 1 多一遍副色（投影偏移处）。⛔ 不许把"没设过模式"实现成 0 —— 默认值是 **1**。
- **投影偏移**是**常量** **(1, 1)**：⛔ 不许把它实现成可配置 / 可从资源读的值，也⛔ 不许让其它入口改变本条读取到的值 —— 把它当配置读会引入一个引擎没有的自由度。
- 模式 3 的副色趟**只外扩一个像素**：每趟的两个位移分量都是 `round(三角函数 × 偏移分量)`，而偏移分量恒为 1 ⇒ **每个位移都落在 {-1,0,1}² 里**（12 趟收敛成 6 个位移、各出现两次）。⛔ 不许实现成"沿对角线逐级加粗"（那会把副色推到 2px 以外；真机在选项/角色设定页的副色黑边只有 1~2px）。★ 像素级后果随字形格式：1 位掩码下就是"外扩 1px"；灰度格式下位移处的半覆盖像素还会与主色混合（可见 2px 的半透明边），这是混合的结果，不是位移更大。
- 模式 3 的**累计角度从 0 起算**（角度 0 也画一趟），循环条件是"累加后仍小于 360"；偏移 (1,1) 时正好 12 趟。★ 这两条在 1 位掩码下**看不出来**（位移并集在 11/12/13 趟时相同）：可证伪的观察是"位移集合 = 那 6 个方向"（见 `RES-RENDER-TEXT-PROJECTION` 的 falsifier 与审计的请求计数档），灰度格式下还能看见重复趟的二次混色。
- 像素结果（字形长什么样、混合结果）**不在本版**：本版只规定"往哪个槽的纹理、在哪个位置、画了哪段文本、用了哪套字体状态"。
- 错误文本的**内容**本版不规定；但失败必须**仍然上报**到错误通道，不得静默。

**残差**

- `RES-RENDER-TEXT-FONT-SELECT-WHY`（unknown）：现在选不选字体的判据已定 —— **显示记录的虚拟全屏类型 == 2**；但该格的**取值集合与各档含义**、以及**为什么只有 == 2 才换字体**，本版不规定。下一步：核该配置键的取值来源，并解释"只在某一档才换字体"的理由（真机对比各档的字形表现）。
- `RES-RENDER-TEXT-FONT-FALLBACK`（unknown）：回退字体的**触发条件（字形码 < 0x100）与建 / 删次序已定**（见上）；仍未定：那份回退字体描述与 A / B 支的关系、临时字体是否复用重建入口。下一步：读回退字体描述的来源与它和 A/B 支的关系。
- `RES-RENDER-TEXT-FONT-SHARED-METRICS`（unknown）：该开关的领域身份是**「按算出的格宽推进」**（0 ⇒ 用字形步进；非 0 ⇒ 按算出的格宽），不是"共享缩放 / 度量"；写点 ≥ 20、分属多条路径，未逐一归类。下一步：读这些写点各自属于哪条路径；确认本条清 0 ⇒ 本条恒走字形步进。
- `RES-RENDER-TEXT-SPECIAL`（unknown）：特殊字形路径的**次数（F043 一次 / F042 两次）与矩形装配（字框 + 投影横偏移 + 推进量）已定**；仍未定：矩形操作本身是拷贝还是填充、以及 PUA 是否另有句柄。下一步：读矩形操作的实现入口（复核数据）的语义。
- `RES-RENDER-TEXT-LOCK`（unknown）：**加锁失败与取尺寸失败是同一个早退出口**（不写像素、本函数不报错）；**取矩形失败**未定位。下一步：读取矩形失败分支；确认错误文本是否由加锁子例程内部发。
- `RES-RENDER-TEXT-FONT-INSTANCE`（unknown）：字体对象是引擎级的**唯一实例**；它的领域名、以及**其它文字路径**是否复用同一实例（同一套主色 / 副色 / 绘制模式）本版不规定。下一步：把其它文字入口的接收者与字体状态读出来，确认是否同一实例。
- `RES-RENDER-TEXT-GLYPH-RASTER`（unknown）：字形位图由平台栅格化，逐位形状**不可还原**；本版规定**请求的位深**（本条）、**级数 → 覆盖值的换算**（见上）与**落字起点（首字）**（推进量见 `RES-RENDER-TEXT-ADVANCE`），不规定位图的逐位形状 / 位模式。下一步：按项目口径把逐位表现进 discards。
- `RES-RENDER-TEXT-SURFACE-FORMAT`（unknown）：**级数 → 覆盖值、16 位表面把覆盖值降到 4 位通道的换算（算术右移 4 位）、以及三条写入支路都已定**（见上）；**脚本侧 `0xRRGGBB` → 存储侧的字节反转（COLORREF BGR 序）也已定**（见「颜色」）。仍不规定的是**通道顺序**：源色的三个字节落到目标像素的哪三个位置、以及它们分别对应红 / 绿 / 蓝中的哪一个（两种表面格式各自确认）。下一步：按一条写入路径读源色的解包顺序并对照像素。
- `RES-RENDER-TEXT-WRITE-BITS`（discarded）：写入循环的**逐位表现**不在本版保留 —— 逐通道乘除的取整顺序（先乘后除 / 中间截断）、位打包的指令级实现、以及 16 位表面降位后的实际位模式。范围：字形写入的逐像素算术。影响：同一覆盖值下相邻像素值可能差 1；三条支路的选择、覆盖值本身、输出通道值 = max(目标, 覆盖值) 这些**结构**不受影响（它们在正文里）。⛔ 不许据此认为"像素内容随便"：结构部分可判，只有逐位不同。
- `RES-RENDER-TEXT-PUA`（unknown）：私用区字形（`0xF042` / `0xF043`）由哪一份字体描述 / 哪一个平台字体句柄画出、以及它们为什么走"解锁 + 矩形操作"路径，本版不规定；**是否另有额外句柄**未定（本版断言字体对象持有**四份**存储的描述：A / B 两支 × 横排 / 竖排各一份，各有自己物化的句柄）。下一步：把字体描述与句柄的对应关系查清，再读这两个字形的矩形操作参数。
- `RES-RENDER-TEXT-ENCODING`（unknown）：**编码本身已证**（Shift-JIS 字节串：前导字节 + 双字节合成、`0x8140` 全角空格）；**仍不规定**的是：数值型操作数 → 十进制文本的格式（符号 / 宽度 / 浮点）、字形选择与字符集（字符集格）的对应，以及 `0x8140` 的量度 / 空白宽度配置分支。下一步：按数值格式化路径取证格式串；把字体描述的字符集格与字形查找对齐；读 `0x8140` 特例的推进量来源。
- `RES-RENDER-TEXT-ALIGN`（unknown）：纵向对位的**条件式与差值形态已定**（仅对位模式 == 1，`y += 缓存 ascent − 本次 ascent`）；缓存 ascent 的来源已定 = 重建入口在名字非空时**无条件**取的那一次量度（对**参考字体**；数值见 `RES-RENDER-TEXT-ALIGN-REFERENCE`；由平台量度请求的**指针出参**写进字体对象的**文本度量**那张量度结构，同一次请求的另一张是**字形度量**、不提供这个分量；**单位与取整未取证**）。对位模式只决定**派生**跑不跑（见「列表」的 `0x78` / `0x2db` 条），**不**决定缓存写不写。仍未规定的是：**除重建入口那次 SelectObject（把参考字体选进绘制表面）之外**，还有谁在什么时候改绘制表面的当前字体。下一步：核"虚拟全屏类型 ≠ 2"时绘制表面选着哪个字体；把两张量度的单位与取整取证。
- `RES-RENDER-TEXT-ALIGN-REFERENCE`（unknown）：**参考字体**的身份已定到"重建入口的固定请求"（字面名常量、高度 = −字号、宽度 = −字号/2、粗细取对象描述、字符集默认；不是对象当前字面名），但 **宽度 −字号/2 的奇数取整**、**字符集"默认"的具体值**、以及它的 **ascent 数值**（目标平台上 20px 时是 17 还是 18）与系统字体版本 / 替换未取证。下一步：在目标平台上对该系统字体做一次量度，记录量度结果的 ascent 分量与取整，并核宽度取整 / 字符集默认值。
- `RES-RENDER-TEXT-ALIGN-BACKEND`（discarded）：**跨后端 / 跨系统字体版本**的数值差与栅格化位模式属**平台实现可替换**的部分，逐位 / 跨后端表现不在本版保留。范围：绘制路径与字体重建路径。影响：换一个平台字体后端时 ascent 可能差 1px，不保证跨后端像素一致。★ 目标平台上的取值本身不在此舍弃：由 `RES-RENDER-TEXT-ALIGN-REFERENCE` 的 next 去量（两者不重叠）。⛔ "量哪份字体"不是后端自由（见参考字体残差）。
- `RES-RENDER-TEXT-ADVANCE`（unknown）：推进量的**三分支已定位**（开关 = 0 ⇒ 字形步进；半角 < 0x100 ⇒ 字号 ÷ 半角系数 × 缩放 + 0.5 后取整（四舍五入）；其余按字形步进；空白宽度配置另有一支）；仍未定：半角系数的数值、缩放格身份、`0x8140` 特例。下一步：读半角系数与缩放格，补 `0x8140` 的推进量来源。
- `RES-RENDER-TEXT-PRESENT`（unknown）：加锁 / 写入与帧提交 / 呈现的先后关系没有取证。下一步：定位主循环的呈现点，给出相对顺序。
- `RES-RENDER-TEXT-PROJECTION`（unknown）：**本条**绘制请求读取时为 (1, 1) 已定（构造置入；本条不触发借用）。**借用期内的其它绘制路径确实会读到样式值**（借用 / 归还点已定位，多个直接绘制入口调用点与样式应用同处一个字体对象）；仍未定的是：这些路径是否把该值用于**字形格 / 推进量**，以及样式应用的每个退出路径是否都走到归还点。下一步：读借用期内直接绘制入口调用点的实参装配，并核样式应用的每个退出路径的归还。★ 绘制模式 3 的径向半径 / 趟数 / 步长**已按站点取数**，不再是残差。

### 数值文本：opcode 0x205

<!-- rule: CORE-OPS-RENDER-NUMTEXT-205 -->

`0x205` 有六个操作数：**1 = 纹理槽号**、**2 = 字段原点（横坐标）**、**3 = 纵坐标**、**4 = 值**、**5 = 格数**、**6 = 格式位**。长度槽 ← 13。
读序是 **2 → 6 → 5 → 4 →（格式化）→ 3 → 1**：先按整型读第 2、6、5、4 个，格式化之后才按整型读第 3、1 个。

- **本条 = 「把数值格式化后的文本画进纹理槽」**：绘制入口、字体 / 颜色 / 绘制模式 / 对位模式、以及三条入口条件（槽里有纹理对象、只读询问非空、文本非空）与「离屏文字」条**同一份**；本条只多出"把值格式化成文本并算出横向位置"。
- **格式化**（十进制的绝对值；不出现小数点、千分位、指数）：
  - **符号**：值为负 ⇒ `-`；值为正且置 **`0x8`** ⇒ `+`；值为零时置 **`0x10`** ⇒ `+`、置 **`0x20`** ⇒ `-`（`0x10` 优先于 `0x20`，两位可同时置）。有符号时**符号占一格**，可用数字格 = 格数 − 1。
  - **前导零**：置 **`0x1`** ⇒ 数字补零补满可用数字格；不置 ⇒ 不补（高位留空，文本只含数字与符号）。
  - **放不下**：数字位数超过可用数字格 ⇒ **丢掉高位数字**，只画低位那几格。例：2 格、不置 `0x8` / `0x10`、值 12345 ⇒ `45`；3 格、值 −1234 ⇒ `-34`。
  - **`#` 的唯一入口**：**有符号且格数 < 2**（连符号位都排不下）⇒ 整段退化成**单个 `#`**。**无符号且格数 ≤ 0** ⇒ **空串**（不画、不报错）。
  - **半角 / 全角**：置 **`0x10000`** ⇒ 文本按**半角 ASCII** 落字；不置 ⇒ 每个字符**就地扩成全角**（数字 `０`–`９`、`-`、`+`、`#` 的全角形）。
  - **未列出的格式位在本条无作用**（引擎只测上述几位）。
- **横向位置** = 第 2 个操作数 + **未用格数 × 格宽 × k**（下面的算术都是整除，向零截断）：
  - **未用格数** = **格数 − 已写字符数**（符号计入字符数；数字放不下、`#` 档与空串档一律取 0）。
  - **格数按本次模式的字符格计**：半角模式下 1 个字符占 1 个半角格，未用格数也是半角格数。
  - **k 与格宽**：右齐（缺省：格式位 `0x2` / `0x4` 都不置）⇒ 全角 `未用格数 × 格宽`、半角 `÷ 2`；居中（置 **`0x2`**）⇒ 全角 `÷ 2`、半角 `÷ 4`；左齐（置 **`0x4`** 且未置 `0x2`）⇒ 0。
  - **格宽** = 「ADV 文本」条行距里**不含行間隙**的那一项 X：行距模式 = 0 ⇒ X = **−行距项格**；模式 ≠ 0 ⇒ X = **字号格**。⛔ 不许把行間隙算进格宽，⛔ 也不许把 `X` 取成"行距项格"本身（那样右齐会整体左移）。带字体缩放时这两格的取值口径见「ADV 文本」条的行距三支 —— 本条**不另定**缩放口径。
  - 配置 **`set:BlankExtentMode = 1`** 时**格宽改为空白字符的量度宽**：全角模式取**全角空格**的量度宽，半角模式取**半角空格**量度宽的两倍（仍等于一个全角格）；**取 1 以外的值 ⇒ 仍用上面的 X**（取值集合与写入者见残差）。
  - ★ 上面这两支（**缩放档**与 **`set:BlankExtentMode = 1`**）本版**还没有落成唯一公式**（前者转引「ADV 文本」，后者只到"取空格量度宽"）⇒ 独立实现者目前只能照**默认支（未缩放、非 1）**写。缺的两支见残差 `RES-RENDER-NUMTEXT-CELLWIDTH`。
  - **本条不再乘任何缩放系数**：带字体缩放时，缩放由「ADV 文本」条的行距三支决定（模式 0 与模式 ≠ 0 的取法不同）；⛔ 不要在这里再乘一次显示适配比或字体缩放比。
- **纵坐标**与「离屏文字」条同一条对位规则：落像素的基线 = 原值 +（对位模式 = 1 ? **缓存 ascent** : **本次量度的 ascent**）。⇒ 第 3 个操作数是**字形格顶**，不是基线。
- 第 1 个操作数**直接作纹理槽号**：本条**自己**不做「渲染目标」条的 1000 阈值判断；编号越界的后果本版不规定。
- 本条**不建**纹理、**不改纹理槽表**、不改绘制项、不置脏标记、不改池 / 帧 / 列表记录；请求内部会复用字体对象的字形暂存区与两个内部布尔开关（同「离屏文字」条，都不是脚本可观察值）。
- 操作数类型异常按「数据池」的通用规则抛出：第 3 个操作数读取抛异常时，第 1 个还没被读。
- 本条**不改变**当前渲染目标：目标由第 1 个操作数指定的纹理槽给出（同「离屏文字」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个纹理槽的纹理被画上一段格式化后的数值文本 | 该槽纹理对象的表面内容 ← 该文本的字形（像素不判，同「离屏文字」条） |
| 字体对象的字形暂存区被复用 | 两份暂存缓冲与字形位图长度格被重写（内部缓存；同「离屏文字」条） |

**成立条件**

- **溢出是截断，不是提示**：`#` 只在"有符号且格数 < 2"时出现；⛔ 不许把"数字放不下"实现成 `#` —— 那会在窄字段上把 `45` 变成 `#`。
- **符号只由值的正负与格式位共同决定**：`0x10` / `0x20` 只对**零**生效（⛔ 不是"对非零也生效"），`0x8` 只对**正数**生效；负值一律 `-`（即使置了 `0x8`）。
- **`0x10000` 同时改字形与起点偏移**：置它时字符按半角落字、起点偏移也按半角格宽算；⛔ 不许只改其中一边。★ 它**不是**对逐字推进量的规定 —— 推进量属绘制入口（见「离屏文字」条的残差）。
- **未用格数含符号格**：`-7` 在 3 格里未用 1 格（不是 2 格）；`#` 档与空串档的未用格数是 0（⛔ 不是负数）。
- 本条**不置**脏标记、不发"帧级"请求：它只改该纹理槽的表面内容。

**残差**

- `RES-RENDER-NUMTEXT-BLANK`（unknown）：`set:BlankExtentMode = 1` 时"空白字符的量度宽"已定到"量当前字体的空格字符"，但该配置键的**取值集合**与**写入者**本版不规定（≠ 1 走默认支已定）。下一步：核该键的写入路径与取值集合。
- `RES-RENDER-NUMTEXT-METRIC`（unknown）：`BlankExtentMode = 1` 时量到的**空格量度宽**由平台字体给出，取整与"是否含行距项"未取证；默认支的格宽（−行距项格 / 字号格）是**引擎状态**，不在本条残差里。下一步：在同一后端上量一次空格 extent，核对取整；跨后端差异按项目口径进 discards。
- `RES-RENDER-NUMTEXT-INTMIN`（unknown）：值为最小整数时"取绝对值"在引擎侧溢出，会打印出非数字字符；本版只规定正常范围的绝对值。下一步：按该分支的除法 / 取模逐字核，补一条可观察的反例。
- `RES-RENDER-NUMTEXT-KBOTH`（unknown）：格式位 `0x2` 与 `0x4` 同时置位时按居中处理（判据先看 `0x2`）；这是否是引擎意图、以及是否有脚本会同时置两位，本版不规定。下一步：在语料里找同时置两位的站点。

### 清屏：opcode 0x20e

<!-- rule: CORE-OPS-RENDER-CLEAR-20E -->

`0x20e` **没有操作数**；长度槽 ← 1。

- **请求**：把**当前渲染目标**整面清成**透明黑**。参数：清**颜色与深度**两个缓冲区（颜色 0 = 四个通道全 0；深度 1.0）；**不清模板**（模板实参传 0，但不参与清屏）；**没有矩形** ⇒ 清整面。
- **门控支**：当**虚拟全屏类型 = 1** 且**当前渲染目标是后缓冲**时，清屏序列变成两次：**切到纹理槽 38 的渲染表面 → 清该表面 → 切回后缓冲 → 清后缓冲**。门控不成立时只清一次 —— 清的是**当前渲染目标**（它可能是后缓冲，也可能是某个纹理槽）。
  ⇒ 总计：门控成立 **2 次**（38 在前、后缓冲在后），不成立 **1 次**（⛔ 不是"先清后缓冲、再清 38、再清后缓冲"的三次）。
- **门控支的两次切换与清屏都成功时**，当前渲染目标的可观察值仍是后缓冲：门控条件本身就要求它是后缓冲，序列最后也切回它。★ 门控支的"切目标"在引擎里走的是**另一条入口**（不是「渲染目标」条的直调）；它写不写「当前渲染目标」格、以及切目标 / 清屏失败怎么上报，本版**不单独规定**（本条同步执行、期间没有别的读者）。
- 纹理槽 **38** 的身份与创建见「纹理族」的 38 档（引擎自建、虚拟全屏类型 = 1 时按显示记录的宽 / 高建出）：本条**只清它、不建它**；门控成立而 38 不存在时切目标会失败（后果见残差）。
- 本条**不建**纹理对象、不改纹理槽表、不改绘制项、不置脏标记、不改池 / 帧 / 列表记录。
- 本条与「帧步进」的清屏位是**两个入口**：后者的条件见该条正文（它与本条互不替代）；⛔ 不要用本条替代它，也不要把它当成本条的门。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前渲染目标的表面被清成透明黑 | 该表面内容 ← 透明黑（像素不判） |
| 门控支清的那一份表面 | **纹理槽 38** 的纹理表面 ← 透明黑 |
| 请求 | 一次或两次同步清屏；门控支的序列里夹一次"切到 38 / 切回后缓冲" |

**成立条件**

- 门控的**两个条件同时成立**才走门控支：只满足一个 ⇒ 只清主目标一次。⛔ 不许把"虚拟全屏"当成"总是开"或"总是关"。
- 门控支**先切到槽 38、清、再切回后缓冲、再清**：两次清屏的**顺序**是可观察的（对槽 38 的那次发生在后缓冲那次之前）；⛔ 不许实现成"只清后缓冲"或"只清槽 38"。
- 清屏**不依赖**当前场景是否脏、是否有绘制项：本条一旦派发就发请求。
- 颜色是**透明黑**（四个通道全 0），⛔ 不是不透明黑（`0xFF000000`）。

**残差**

- `RES-RENDER-CLEAR-38`（unknown）：门控支清完槽 38 之后**谁消费**这份内容、以及"清 38"与"贴回 38"的先后本版不规定（38 的身份 / 创建 / 切回时机见「纹理族」的 38 档）。下一步：读 38 的读者（绘制 / 贴回）与清屏的先后。
- `RES-RENDER-CLEAR-VFS`（unknown）：虚拟全屏类型的**取值集合**见场景章（0 / 1 / 2）；未定的是 **1 与 2 两档在"建离屏目标 / 选字体"上的分工**。本条只用 `== 1` 这条判据。下一步：读 1 / 2 两档的建 38 与选字体分支，写成条件。
- `RES-RENDER-CLEAR-FAIL`（unknown）：清屏 / 切目标的平台失败如何上报（是否写错误通道、文本内容）未取证。下一步：逐字读两个请求的失败分支。
- `RES-RENDER-CLEAR-ORDER`（unknown）：本条与同帧已排队的绘制命令 / 呈现的先后（清屏是否打断已在显示列表里的命令）未取证。下一步：核目标切换与显示列表提交的消费者。
- `RES-RENDER-CLEAR-DEPTH`（discarded）：深度 / 模板缓冲区在目标表面上的实际位模式、以及平台是否真的清了它们不在本版（本模型没有深度缓冲）。范围：本条请求的深度分量。影响：只影响依赖深度测试的绘制；颜色分量的清屏结果不受影响。下一步：平台深度行为按项目口径进 discards；⛔ 不据此声称像素逐位一致。

### 帧步进：时间戳 + 渲染一步 + 清帧标志（opcode 0x20c）

`0x20c` 没有操作数。

- 若引擎**未处于执行区间**（**区间忙标记 = 0**）：读一次当前时刻，把「引擎上一时刻」←「引擎当前时刻」，再把「引擎当前时刻」← 读数。这两格是**引擎级**的，与 `0x1f4` 写的是**同一对**（见 `CORE-OPS-RUN-BRACKET`）。
- ★ 这一对就是**场景时钟**（见「场景计时窗」）。区间内 `0x20c` **不重盖**这一对（忙门）；不忙时它先覆盖、再请求渲染步，因此**它自己那次渲染步读的是覆盖后的值**。
- 向渲染子系统发出**一次步进请求**。这条请求是「同迭代的两次渲染步」里的**指令侧一次**（见下）：它**不经过**门前判据（见「一次迭代做哪些事」的 `0x20c` 例外）；⛔ 它不是唯一的渲染入口：主循环在**门前请求判据**（见下）成立时另发一条。**场景遍历 / 绘制顺序**是引擎行为：两档顺序（命令档 + 收尾扫描）与平键序见「场景 / 颜色族」的「绘制顺序」；D3D 调用与像素输出属平台。
- 把**帧标志格**清成 0（帧标志的置 / 清 / 唯一读者见下面的「帧标志」）。
- 推进格数 = 1；不改当前帧、不改门位、不写脚本变量。

**门前请求判据（合同）**

主循环在**门之前**判定是否发出一次渲染步。判据是下列**七支必要条件的合取**（全部成立才请求），求值次序固定：

1. **场景绘制模式 = 1**。非 1 ⇒ 本段**整体不进入**：既**不搬场景时钟**、也不做后面任何判定，本迭代**直接跳到门**（服务状态位 / 派发一条指令）继续。⛔ 不许只写成"不渲染"。
2. **画面暂停闩 = 0**。
3. **刷新请求位**（脚本 `0x21b` 写进引擎状态的那个布尔，见下面「刷新请求位（合同）」）**≠ 0**，**或**状态选择字的第 10 位（等待位）/ 第 13 位（影片位）至少一位为 1。
4. 状态选择字的**第 24 位 = 0**。
5. **没有媒体对象占用**（见下「两项逐媒体对象谓词」）。
6. **不成立**「区间忙标记 ≠ 0 **且** 状态选择字第 10 位 = 0」。
7. **就绪判据 = 1**，**或**有**媒体对象到期**（见下）。

**刷新请求位（合同）**

它是一格**脚本可置、脚本可读的粘滞布尔**，语义就是「脚本主动请求过一次刷新」。★ 它**不是**状态选择字的**第 20 位**（「重绘待处理位」，见 `0x1ce` 条）：那是**另一个字里的另一格**，写点与消费点都与 `0x21b` 无关 —— 两格名称相近但**不是同一格**，⛔ 不许合并、也⛔ 不许用一个实现另一个：

- **缺省 0**（引擎建立 / 复位时清 0）。
- **写者只有 `0x21b`**，且写进去的是**归一后的真值**：操作数为 0 ⇒ 0，任何非 0（含负数）⇒ 1；除此之外本版没有写者。
- **粘滞**：它保持自己的值，直到 `0x21b` 再写一次或复位清 0。两个读者都**只读**：读它既不清它、也不改任何其它格。
- **读者有两处**：① 上面第 3 支（与状态选择字的第 10 / 13 位是「**或**」，⛔ 不是「与」）；② 脚本可以把它的值**读回成一个整数**（0 或 1）落进脚本的落点 —— 落点是脚本侧的一个值，不是引擎字段（见「薄标量写」）。
- 它**不**参与第 4～7 支，也**不**改变第 1 支的前置：它只在第 3 支里起作用。★ 引擎**不会**因为"场景脏了 / 窗口重画了"去置它 ⇒ ⛔ 不许拿「就绪判据非 0」或「脏标记」替代它（那两格分别在别的支里）。

★ **第 1、2、3 支通过之后、第 4 支之前，引擎无条件做一次场景时钟搬移**：上一时刻 ← 当前时刻、当前时刻 ← 本迭代读数。这次搬移与"是否真的发出请求"**无关** —— 第 4～7 支把请求挡掉时，时钟**也已经搬过**。

**就绪判据**是下列四条的**析取**（任一成立即为 1，全不成立为 0）—— 它回答的是**"有没有东西要画"**，⛔ 不是"渲染器忙不忙"、⛔ 不是"设备就绪"：

- a. **场景脏闩 ≠ 0**（「总览与约定」的**脏标记**）。场景的任何内容变更把它置 1；窗还在走的每一步也把它置 1（见下一条）；渲染步的步头把它清 0。★ 它**不是**「有动画」标记：两者是场景上的**两个不同的格**（「有动画」的读者闭集见「场景 / 颜色族」的 `0x202` 条；本判据读不到它）；
- b. **三维特效对象**（就是 `0x324` 复位的那**同一个**对象，见「把引擎字段里的对象交给入口」）的三个「待处理」指针格任一非 0；
- c. 场景的**动画槽表**：场景持有**固定 10 个**动画槽，每槽装**一个设备侧动画对象** —— 装载（或重建）时先把该槽清空，再把**整份文件**读进内存、用图形设备建对象后放进槽；装载失败则该槽留空；释放显示资源的路径（设备丢失恢复、渲染器初始化）会逐槽释放。绘制侧的记录里带一个**槽号**，渲染时按该槽号取用。**任一槽非空** ⇒ 本支成立。★ **释放不清槽**：逐槽释放之后槽里仍是**那个已被释放的对象引用**（与纹理槽同一形态）⇒ **槽非空**，c 支在这些释放之后**仍然成立**；⛔ 不许把释放实现成清槽（那会让 c 支在释放后凭空变 0）；
- d. **绘制项表**中任一元素的值**首字的第 2 位**（位号从 0 起，权 **4**）为 1（遍历完仍无 ⇒ 0）。这张表按**整数键**索引，值是 **740 字节**的绘制项记录。★ 渲染步的**绘制主循环**另有自己的一道闸：**命令表**（值 96 字节的那张）非空 —— ⛔ 别把这两个判据混成一个。

★ 这四支里 **b / c / d 不是"置位即脏"的标记**：它们是**表 / 计数本身非空**，置清由各自的数据结构维护。⛔ 不许把这三支写成"某个标记被置起"。
★ 本判据**没有独立的「有动画」支**：那个格**不参与**本判据。⇒ "窗还在走"经 **a 支**进入本判据（窗还在走时**场景推进**把 a 支那个格置 1，**无条件** —— 带「不参与场景动画」位的项也置；推进同一处也置「有动画」，带该位的项**除外**，但本判据只读前者 —— 见「场景计时窗」与「绘制项的消费者」4.1）；⛔ 不许为"窗还在走"另立第五支，⛔ 也不许把它实现成"不置脏也能让本判据成立"。
★ c 支的 10 个槽与 d 支的**绘制项表**是**两张不同的表**（身份见上面两支）：c 支的槽装**设备侧动画对象**、d 支的元素是 **740 字节**的绘制项记录；⛔ 不许用同一张表实现这两张，也⛔ 不许把它们与**媒体对象表**（格装播放类对象）混成一张，更⛔ 不许用"哪张非空"互相顶替。

**两项逐媒体对象谓词**（对**上一迭代存在过的**媒体对象逐个求值）：

- **媒体对象**：引擎另一张**定长对象表**里的一个对象（上限一千格，空槽跳过），本章称**媒体对象** —— ⛔ **不是**场景命令记录、⛔ 也不是绘制项。每个媒体对象带**一个通道**、**一个影片文件 id** 与**两个目标引用**；表只是容器，槽号由**填它的那条指令**按自己的操作数给出（见下「媒体对象表（合同）」）。
- **通道只有两个取值**：由**媒体文件名的格式标记**决定 —— 名字里带 `WMV` 或 `MP4` 的 ⇒ 通道 **1**，其它 ⇒ 通道 **0**；对象刚建立时是 0。⇒ 不存在第三个取值，也不存在"由脚本指令 / 配置项直接指定通道"。⛔ 不许把通道实现成"指向某个对象的指针"。
- **影片文件 id**：对象上的一格整数，就是某条指令「**取文件并配置**」那一步用过的**名字 id**（与 `0x20f` 的资源 id 同一套编码；见下「媒体对象表（合同）」与各指令条）。⇒ 它只在那一格被写过之后才有值；对象刚建立时**没有被写过**。★ 本版**没有观察到**它的读者（写它是合同；引擎读回它不在本版）。
- **两个目标引用**：通道 0 的目标是一个**媒体纹理渲染器**、通道 1 的目标是一个**媒体会话**；任一引用可为空。两个目标上各有**自己的一对格**：一个**到期标记**、一个**占用计数**（两对是**不同的格**，⛔ 不许按同一位置去读另一个目标、也⛔ 不许把两个目标合并成一个）。
- **到期**：按该对象的通道取**它那个目标**的到期标记：格非 0 ⇒ 判真，且是**消费性**的（判真时把那一格清 0）；格为 0 ⇒ 判假；**通道不属于那两个已知取值** ⇒ 该对象**一律判真**（它没有目标、也没有到期格可清 ⇒ 不存在"还没到期"这回事）。任一对象判真 ⇒ 整体为真（第 7 支成立）。
- **占用**：判据 = 该对象此刻**是否正被别处使用** —— 把它那个目标的**占用计数**自增：自增后的值 > 1 ⇒ 报告「占用中」（随即自减回去）；= 1 ⇒ 报告不占用（同样自减回去）。任一对象报告「占用中」⇒ 整体为真，且该支**否决**本迭代的请求（第 5 支不成立）。
- **判据的窗口**：到期判真时**不再问**占用；到期为假时才看占用是否 > 1。

一个存活的媒体对象都没有时，两项谓词一律为假（引擎不进行空扫描；判据是"上一迭代有没有存活对象"，⛔ 不是"表里有没有空格"）。

**媒体对象表（合同）**

表是引擎上一张**定长指针表**，**上限一千格**，空槽为空。

- **上限一千的来源**：它是**每拍扫描的循环边界**，**不是**任何一条指令选格时的判据 —— ⛔ 不许写成"指令会检查槽号 < 1000"（没有这样的检查）。槽号 ≥ 1000（或为负）时会发生什么，**本版不规定**（那是"没有检查"的直接后果，不是引擎决定的可观察行为）。
- **填**：只有**五条指令**会往表里填对象 —— 播影片（`0x20f`）一条，加 `0x236` / `0x240` / `0x241` / `0x24d` 四条。五条**都按自己的第 2 个操作数选格**；**同槽已有对象 ⇒ 不重建**（旧对象留在格里：**不释放**、也**不换成一个新对象**；该格仍是原来那个对象，与「等待、影片与空操作」的同一口径一致）。该格**为空**时才建；新对象是一条播放类对象（带一个通道、一个影片文件 id 与两个目标引用，见上）。
  ★ **`0x24d` 的同一个操作数有两重身份**：它既是本表的槽号（这一条确实**填**本表），又写进场景命令记录当**影片纹理编号**（见「场景 / 颜色族」的影片覆盖命令）⇒ **一个操作数同时选中媒体对象表的一格与一张纹理**。⛔ 不许因此把它从这五条里划掉，也⛔ 不许把它实现成"只写命令记录、不填本表"。
  ★ **判定与填表的次序**（三步、顺序固定）：① `0x24d` **先按同一编号选格填本表**（格空才建；格非空 ⇒ 保持原对象）⇒ ② **若这一步真的新建了对象，再按第 1 个操作数打开影片**（打不开 ⇒ 抛出、本条终止）⇒ ③ **再判纹理槽**（槽空 ⇒ 抛出、本条终止；**已填的那一格不回收**）。次序以「场景 / 颜色族」的影片覆盖命令为准，本条不重复。
  ★ 其中 `0x236` / `0x240` / `0x241` **整条尚未成篇**：本条只登记与本表有关的那一项副作用（按第 2 个操作数选一格、格空时建对象）。
- **清**：来源共**五条** ——
  ① **纹理族的三条写指令**（`0x1f8` / `0x1f9` / `0x1fa`）在**建立 / 释放**之前先清**自己那个编号**的一格（与「纹理族」的「共享对象槽」是**同一条**合同，本条不重复；`0x1f8` / `0x1fa` 取第 1 个操作数、`0x1f9` 取第 2 个）；
  ② **两条指令**（`0x210` / `0x249`）按自己的操作数把该格的对象释放并置空（`0x210` 取第 1 个操作数、`0x249` 取第 2 个）；★ 这两条**整条尚未成篇**，本条只登记这一项副作用；
  ③ **每一拍的扫描**：逐个非空格求值「到期 / 占用」两项谓词，并在**该对象已到结束条件**时释放对象、把格置空。结束条件 = **对象自己的两个时刻比较成立**（"已经过去 / 播完"那一对）**且** **循环位 = 0**（循环位 = 选项字的第 0 位，与「执行与时间」的影片收尾同一格同一口径）；
  ④ **另一条路径**（既不是指令效果、也不在每拍扫描里）：引擎在某个**「本拍不计入」**的判定为真时，把该格的对象**释放并置空**；判定为假 ⇒ 这一格**不动**。★ 那个判定的**领域身份**本版未取证（见残差）；
  ⑤ **退出清理指令**（`0x23d`，无操作数）：它按**槽号区间 `42..999`** 逐个槽处理，槽里的播放类对象**关闭并释放、槽置空**（槽号 0..41 **不动**；槽里**不是播放类对象 ⇒ 跳过**，同一遍历的完整合同见「空操作」的退出清理条）。它**释放的是对象**，不是整块清表、也不删表的格；同一趟里它还会处理每个槽的**纹理槽对象**（那是另一张表，见「空操作」的退出清理条）。★ 这一条**也是整表遍历**，只是**起点是 42**。
- 扫描是**逐槽**的（每槽先释放对象再置空），不是整块清；空槽静默跳过；扫描**不报错**。
- 到达扫描时，两项谓词的求值次序固定为「先到期、后占用」（见上「两项逐媒体对象谓词」）。
- ⛔ 不许把"清空整张表"当成某条指令的效果：各格生命周期互不相干。**整表遍历有两处**：③ 那一拍扫描（逐槽看状态）与 ⑤ 的退出清理（按槽号区间 `42..999`、不看状态）；⛔ 也不许把① 的服务范围说成"只影响纹理"：它清的**是同一张表的同一格**。

**场景绘制模式（合同）**

引擎有一格**整数模式**，回答"现在用哪种方式显示"：`0` = 不显示、`1` = 正常显示，**其余整数值 = 第三态**（见下）。

- **来源两个、写点四个**（⛔ 不是"只有三处"）：来源 = **配置 `set:DrawMode`** 与**脚本指令 `0x200`**；四个写点 = ① 初始化时取配置 `set:DrawMode`；② **复位块的整块清零**（只写 0、不读配置）；③ **复位时按同一配置重设**；④ 脚本的那条指令（`0x200`）**用自己给的操作数直接覆盖**它 —— 不重读配置、不校验范围、不钳上下界。④ 还要求该操作数对应的对象已被创建（前置位图来自配置 `set:CreateObject`），不成立则整条不生效、一个字节都不写。★ 复位路径上 **② 先于 ③**（先整块清零、随后按配置重设）⇒ **复位后的取值唯一 = 配置值**（⛔ 不是 0，也⛔ 不是"两种先后都可能"）。**缺省 0**。
- **读者分两类，判据不同**：一类要求**恰好 = 1**；另一类只要求 **≠ 0**。⇒ 第三态在两类读者眼里**不同**（一类当它关、一类当它开），所以**第三态的可观察后果必须按子系统分别判**，下面按读者点名。
  - **要求恰好 = 1 的读者（点名，均已成篇）**：① 门前渲染步的整段门（第 1 支）；② **画面暂停闩**的置 1 / 清 0 两个写点（它 ≠ 1 时闩**不动**）；③ 逐字绘制路径的「走新路径」门（≠ 1 ⇒ 落**旧式绘制**那条路）；④ 文本层的建 / 清画布与逐字路径分岔。⇒ 第三态对这几个子系统**等于关**：门前不请求渲染、闩保持原值、逐字路径落旧路径。
  - **只要求 ≠ 0 的读者（点名；全语料共九处站点 —— 其中两支（三处站点）已归因，其余六处未归因）**：① **纹理缩放拷贝**（`0x32`）：**= 0 走平台的位块传送、≠ 0 走引擎自己的软件缩放**（见「纹理族」的缩放拷贝条）⇒ 第三态下**照常执行，只是换了一条像素路径**（1 处站点）；② **主循环里的一处休眠/节流**：**= 0 才进休眠支、≠ 0 不进** ⇒ 第三态下**不节流**（2 处站点，同一支的两个判据点）。
  - ★ **其余 ≠ 0 站点本版未逐点归因**（六处，分布在这几条尚未成篇的指令与两处内部例程里）⇒ 本版**不**对它们下"照常 / 停用"的结论，见残差 `RES-DRAW-MODE-THIRD-STATE`。⛔ 不许把"第三态 = 部分照常、部分停用"当全体断言写（那是未逐点归因前的推广）。
- **它还兼作一份配置的位下标**：初始化时，引擎用它的值选配置 `set:CreateObject` 的一位；该位未置起就把 `set:CreateObject` 写成 **3**。⇒ 它有意义的区间是**位号**的范围；超出该范围时位号如何取，本版不规定（见残差 `RES-DRAW-MODE-BIT-INDEX`）。
- **它按整数原值被取出**：另有一条指令（`0x201`）把它的值**原样**交出去（第三态取到 `2` 就是 `2`），⛔ 不是 0 / 1 归一化的布尔。★ `0x201` **整条尚未成篇**：本条只登记「原值交出、不归一化」这一项。
- **它不参与画面暂停闩的判定**：门前判据第 1 支只判「= 1」，第 2 支读的是另一格（暂停闩）；⛔ 不许用一个标志同时实现两者。
- **暂停闩的两个写点都以它 = 1 为前提**：一个写点把闩置 1、另一个把闩清 0；它 ≠ 1 时闩**不动**（既不置、也不清）。★ 这两支不是模式的第二个角色，而是**同一个闩的两个写点**，且它们落在**两个不同的收尾例程**里（例程的调用者归属本版未取证）。

**帧标志（合同）**

引擎有一个「**欠一次渲染**」标记（同一个事实的另一种说法：「自上次渲染以来已有新的显示对象」），只使用**最低位**：

- **置 1**：**状态重建入口**在开始工作前先置 1 —— 那条路径把场景与显示对象按配置 `set:CreateObject` 重建，**存档装载与（无确认）读回共用它**（见「存档」的读写两条）。
- **清 0**：任何一条渲染步请求发出之后立即清 0（门前一条与指令侧一条各清一次）。
- **读**：只有一处读者 —— **显示模式派发**（切换显示模式之后的那段收尾，见「切换显示模式」）在已经有标记时**不再发渲染步**，而是把本字第 1 位置 1，表示「这次请求已折叠」。
- **第 1 位写而无读者**：它不参与任何判定，是纯记录位。

本标记**不是**"每次迭代开头自动归零"的格：它只在上面两类写点（置 1 / 渲染步之后清 0）之间变化，**没有**按迭代边界清点的写者 ⇒ ⛔ 不许把它实现成"迭代开始清 0"；它**不参与**「就绪判据」。

**同迭代的两次渲染步（合同）**

同一迭代可以向渲染子系统发出**两次**渲染步请求，且引擎**不去重**：

- **门前一次**：由上面「门前请求判据」触发。
- **指令侧一次**：由脚本的帧步进指令（`0x20c`）触发，**不经过**门前判据。

两次之间**没有**独立的「帧记录」：两次都读同一对场景时钟格；差别是——指令侧那次在**区间不忙**时会**重新搬一次**时钟（新读数），忙时沿用门前搬的那一对。另外，门前那次会把**场景脏闩**消费掉（渲染步步头清它），所以第二次是在「无脏」状态下照跑。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 引擎时间戳 | 引擎上一时刻 / 引擎当前时刻 |
| 渲染走了一步 | 一次步进请求 |
| 帧标志被清 | 帧标志格 = 0 |
| 画面被提交 | 一次呈现请求（仅当本步结束时目标 = 后缓冲） |
| 媒体对象表 | 引擎对象上的定长指针表（上限一千格，空槽为空指针） |
| 一个媒体对象 | 表里一格指向的对象：带一个通道、一个影片文件 id 与两个目标引用 |
| 影片文件 id | 对象上的一格整数；由「取文件并配置」那一步写，哪条指令在什么条件下写它见各指令条；本版没有观察到它的读者 |
| 通道（0 / 1） | 对象上的一个整数格；只由「媒体文件名是否带 `WMV` / `MP4` 标记」写入 |
| 两个通道的目标 | 对象上的两个指针格（通道 0 → 媒体纹理渲染器、通道 1 → 媒体会话），任一可为空 |
| 到期 / 占用 | 各目标上**自己的一对**整数格；到期是**消费性**的（读到非 0 即清 0），占用自增后 > 1 即"占用中"、随即减回 |
| 当前显示方式（0 / 1 / 第三态） | 引擎一格整数；缺省 0 |
| 它兼作的掩码位号 | 配置 `set:CreateObject` 的对应位；该位为 0 ⇒ 该配置写成 3 |
| 被取出交给脚本侧的"显示方式" | 同一格的原值（不归一化） |

**渲染步（合同边界）**

- 渲染步从**入口的当前渲染目标**开始，对当前渲染目标做场景遍历 / 绘制；命令档可在步内切到离屏目标并在出档恢复（已由 `CORE-SCENE-DRAW-ORDER` 规定）。
- **批次闸（不是第一步）**：渲染步入**开头**先做一次「清屏位」判定（该位没有置 1 来源 ⇒ 恒走"不清"，见下一条），**随后**向渲染器请求**开始一次批次**；渲染器拒绝（返回失败）时**整步立即结束、什么都不做**（不遍历、不提交、不复位目标）。⛔ 不许把"开始批次"写成渲染步的第一个动作（它前面还有那次清屏位判定，只是那一步恒不产生请求）。这道闸与「就绪判据」**不是**一件事（它判的是渲染器是否接受了这次批次，不是"有没有东西要画"），也与迭代身份无关；⛔ 不许把它实现成"设备就绪检查"。
- **批次闸拒绝的后果**：开始批次被拒绝 ⇒ 这一**整步立即结束**：**不发出**与它配对的那次「结束批次」，也不复位目标、不遍历 / 不绘制、不呈现、不清命令表、不写任何步末格。⇒ 「结束批次」**不是**无条件配对动作：它只在开始批次成功之后才发出；⛔ 不许实现成"无论成败都收尾"。
- **渲染步从不自行清屏**。脚本的清屏入口是另一条指令（`0x20e`），它直接向渲染器发清屏请求。渲染步开头确有一个「清屏位」判定，但本版里**没有任何把该位置为非 0 的来源**（该位唯一的写点是复位时清 0）⇒ 该判定恒走「不清」。⇒ 独立实现者应当实现成「渲染步不隐含清屏」；⛔ 不许把"每步先清黑"当成渲染步的固定行为，⛔ 也不许为它实现一个"某条件下自动清屏"的分支。
- **呈现请求**：呈现是渲染步里**最后一项平台绘制请求**，且只在**步末的当前渲染目标是后缓冲**时发出；目标是纹理时**不提交**。它**不是**字面意义上的"最后一步"：**批次已在它之前结束**（批次闸的配对动作在呈现之前），它**之后**还有步内收尾（复位、命令表清理、「强制完成」的清除等，见「场景计时窗」；这一段其余次序见残差）。呈现请求**不读取**绘制项表、也不读取纹理槽表 —— 两张表在遍历阶段已被消费，呈现只是把已经画好的内容交给平台；遍历与提交都在同一次同步的渲染步内完成，脚本指令不可能插进来 ⇒ 不存在「呈现读到两条指令之间中间状态」的问题。平台是否真的把后缓冲送到屏幕、以及换链 / 垂直同步的逐位行为属平台。
- **设备丢失时呈现会重试，并释放全部显示资源**：呈现调用返回「设备丢失」这一种失败时引擎进入恢复并**重试**，上限 **10** 次；超过上限即不再重试（本步照常收尾）。恢复**不重建**任何资源（重建由别的路径做，不在本节）：它做的是把引擎当前的显示资源**全部释放**、再置一个「需要重建」的标记；那次释放的收尾还会按显示状态重发一次（见下）。
  - **释放范围**：引擎的显示资源 = 若干显示对象 + **全部纹理槽里的对象** + 动画槽里的对象；释放是**逐个对象**做的。
  - ★ **纹理槽值不被清空**：释放之后槽里仍是一个（已被释放的）对象引用，而**不是**空槽 ⇒ 之后按槽号取用会取到「已被释放」这个状态。⛔ 不许把释放实现成清槽。
  - 恢复**不读**槽表来决定画什么：它不对槽表做任何取值 / 编号判断，只做「逐槽若有对象就叫它释放」 ⇒ 「呈现不读表」在恢复路径上**没有例外**（遍历释放不算"读表来画"）。
  - ★ 这条恢复流程**也走「重发」**：它在复位之后经**同一个释放入口**收尾，而那个入口的末尾就是「按显示状态重发一次」（见 `0x25b` 条的读者②）⇒ ⛔ 不许把它写成「设备丢失恢复只释放、不重发」；也不许把它算作第三条触发点（触发点仍是那两条入口，见 `0x25b` 条）。
- 渲染步**内部各请求的领域身份、参数与失败后果**本版不规定（**位置的次序与门已定**，见残差的次序表）；⛔ 不许把"步进请求交给渲染子系统"当成"遍历 / 提交顺序由平台自由选择"：遍历与提交的次序是引擎行为，只是这一段还没有完整合同。

**成立条件**

- **区间忙标记**非 0 时**不更新时间戳**；但渲染请求与清标志**照做**。该标记就是「暂停」、由 `0x1f4` / `0x1f5` 置清（见 `CORE-OPS-RUN-BRACKET`）。
- 时间戳的更新是「先搬旧、再写新」，不是只写新值。
- 这条不置门位：渲染请求是否阻塞属平台，不在本条；门只决定这一迭代派发不派发指令。
- `0x20c` **不经过门前闸门**：绘制开关、画面暂停闩、**门前请求判据**都不挡它（见「一次迭代做哪些事」的 `0x20c` 例外）。★ 这只限**门前**那道判据：渲染步**内部**还有一道**批次闸**，它对 `0x20c` 发的这一步**同样会早退**（步内早退与请求由谁发出无关）。

**可证伪**

- 刷新请求位恒 0、状态选择字第 10 / 13 位恒 0 ⇒ **若观察到门前的**一次渲染步请求，则第 3 支写错。
- 把状态选择字的**第 20 位**（重绘待处理位）置起、刷新请求位保持 0，且第 10 / 13 位都为 0 ⇒ 门前第 3 支**必须不成立**（不发渲染步）；若发出了 ⇒ 把第 20 位并进了刷新请求位（两格被实现成一格）。
- 把场景做脏（任一内容变更）而**不**触碰刷新请求位、**且**状态选择字第 10 / 13 位都为 0、绘制模式 = 0 ⇒ 若仍观察到门前的渲染步请求 ⇒ 第 1 或第 3 支写错。
- 把绘制模式置 0 ⇒ 若仍观察到场景时钟被搬移 ⇒ 第 1 支写错（本段应整体不进入）。
- 让门前判据第 4～7 支之一否决、而第 1～3 支通过 ⇒ 若观察到场景时钟**没有**被搬 ⇒ 搬移的位置写错（搬移在第 3 支之后、第 4 支之前）。
- **（白盒插桩）**制造「上一迭代有媒体对象且占用」而场景不脏、无动画 ⇒ 若仍观察到渲染步请求 ⇒ 第 5 支漏写。
- **（白盒插桩）**用扩展名是 `WMV` / `MP4` 的媒体名建立一个媒体对象 ⇒ 它的通道必须是 1；用别的格式 ⇒ 通道必须是 0；观察到**第三个取值** ⇒ 把"通道由媒体文件名的格式标记决定、空间 = {0, 1}"写错。
- **（白盒插桩）**把通道 0 目标的**到期标记**置非 0、**占用计数**置 2 ⇒ 门前判据必须判「到期」（不是「占用」），且该格同一次读后变 0；在同一对象上再问一次 ⇒ 这次才判「占用」。第一次就判「占用」⇒ 两支次序反了；到期标记读完仍非 0 ⇒ 把"消费性"写成了"粘性"。
- **（白盒插桩）**把某个媒体对象的通道改成 2（既不是 0 也不是 1）⇒ 必须判「到期」，且**不得**读写任何目标上的格（没有格可清）；访问违例 ⇒ 把"其余通道一律判到期"实现成了"按通道索引目标"。
- **（白盒插桩）**只保留通道 0 的目标（通道 1 的置空）而通道 = 0 ⇒ 判据照常工作；因此崩溃 ⇒ 把"任一引用可为空"写成了"两个都必须非空"。★ 上面**四条**（从"建一个媒体对象"那条起）都要**先造出媒体对象、再改它的内部格**（通道 / 目标 / 到期格 / 占用计数），而这四条要改的格**不是**任何一条指令能写的（填格的那五条只给槽号与资源号）⇒ 这四条**只能白盒插桩**，⛔ 不许改写成黑盒（黑盒造不出那个对象）。
- 把帧标志的第 1 位写成任意值后行为发生变化 ⇒ 「帧标志」那条错（它应为死位）；标记为 1 时仍观察到第二条渲染步发出 ⇒ 唯一读者那一支写错。
- 同一迭代里只观察到一次渲染步（例如指令侧那次被跳过）⇒ 「同迭代的两次渲染步」错；渲染步入口读到帧标志或迭代计数 ⇒ 「不去重」错。
- 在**任何**输入下，渲染步在遍历之前**都不发清屏请求**（清屏只随显式清屏指令出现）⇒ 若观察到渲染步自行清屏 ⇒ 「渲染步从不自行清屏」错，须改写成"某条件下清屏"。（★ 这是**请求序列**上的观察，不是"在语料里找出写点"那种内部检查。）
- 在遍历完成之前观察到一次呈现请求 ⇒ 呈现时机错；同一渲染步里出现**两次以上**呈现请求、或在**目标不是后缓冲**时发出呈现 ⇒ 呈现门错；呈现请求之后引擎又读了绘制项表 / 纹理槽表 ⇒ 「呈现不读表」错（★ 后半句是**实现侧检查**：读表发生在引擎内部，请求序列上看不到；★ 设备丢失恢复里「逐槽释放对象」的遍历**不算**读表 —— 它不按槽号取值决定画什么）。
- **设备丢失恢复**：恢复之后某个纹理槽变成空槽 ⇒ 释放把槽清了，恢复条错；恢复路径里出现「按槽号取纹理来画」的读取 ⇒ 「恢复不读表」错；恢复之后**没有**置「需要重建」标记、或恢复路径里**重建**了资源 ⇒ 恢复条错。
- **动画槽**：让某个动画槽装载成功（槽非空）、再走一次设备丢失恢复（或渲染器初始化）⇒ 该槽必须**仍非空**（指向那个已被释放的对象），且就绪判据 c 支**仍成立**；若槽变成空槽、或 c 支因此变 0 ⇒ 释放把槽清了（与纹理槽的合同不一致）。
- 用覆盖指令把**场景绘制模式**写成 **2**：门前渲染步**必须不发出**（第 1 支只认 1）；若发出了 ⇒ 第 1 支写成了「非 0」。
- **（白盒插桩 —— `set:CreateObject` 没有脚本可读入口）**把配置 `set:CreateObject` 写成 **2**（只有第 1 位置起）、场景绘制模式写成 **1** ⇒ 初始化**不得**改写 `set:CreateObject`；写成 **0** ⇒ 必须被改成 **3**。任一方向不符 ⇒ 位下标那一处写错（方向、位号、写值三者之一）。★ 同一事实的**黑盒代理**：把 `set:CreateObject` 写成 0 ⇒ 「按操作数要求对象已创建」的那条指令（`0x200`）必须整条不生效（用 `0x201` 读回场景绘制模式，仍是旧值）。
- **（白盒插桩 —— 媒体对象表没有脚本可读入口）**用播影片把媒体对象表的某一格填上、再让它播完 ⇒ 该格**必须**在某一拍的扫描之后变空（对象被释放）；若格仍是那个对象 ⇒ 扫描的结束条件写错。★ **黑盒代理**：该格清空之后等待谓词不再被它挡住（放行），且同一槽再播一支影片时建的是**新**对象。
- **（白盒插桩）**播影片之后**不清**任何东西、只是不再喂它 ⇒ 若该格在**同一拍**就被清 ⇒ 扫描的结束条件写宽了（把"创建"当成了"结束"）。★ 黑盒代理：同一槽紧接着再播一支影片 ⇒ 必须**复用**该格上的对象（不重建）。
- **（白盒插桩）**对同一格连填两次（第二次换一个媒体名）⇒ 该格上**仍是第一次建的那个对象**（不重建、不释放）；若观察到旧对象被释放、或该格换成了另一个对象 ⇒ 「同槽已有对象 ⇒ 不重建」写错。
- **（白盒插桩）**让**「本拍不计入」**的判定为真 ⇒ 该格上的媒体对象必须被释放且格变空；判定为假 ⇒ 该格**原样不动**（既不被释放、也不被换成新对象）。两个方向任一不符 ⇒ 清的第 ④ 条写错。
- 用纹理族的一条写指令在同一编号上建纹理 ⇒ 同一格上的播放对象**必须**先被释放（不是"共存"）。

**残差**

### 设置显示状态与图像号：opcode 0x25b

<!-- rule: CORE-OPS-RENDER-DISPLAY-STATE-25B -->

`0x25b` 有一个操作数：**图像号**。

1. 引擎的**显示状态**格 ← **2**（无条件）；
2. 引擎的**当前图像号**格 ← 图像号（无条件）；
3. **窗口态**（显示模式缓存 = 0）时再按该图像号**载入图像**（一次载入请求）；**全屏态**时**不载**。

- 不写操作数、不报错、无范围检查。
- 图像号只被"记下来"再交给载图入口：本条不校验图像是否存在。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 显示状态 | 格 ← 2 |
| 当前图像号 | 格 ← 第 1 个操作数 |
| 载图请求 | 仅窗口态发出 |

**成立条件**

- 前两步**无条件**：⛔ 不许因为"全屏"就跳过记录状态与号。
- 第三步的判据是**显示模式缓存 = 0**（窗口态），不是"有没有窗口"、也不是去查命名键。
- **显示状态的三个取值**：`2` = 当前显示的是**图像号格**指出的图像（本条写的）；`1` = 当前显示的是**外枠图像**（窗口边框画面，见下「外枠纹理」）；`0`（以及其它既非 1 也非 2 的值）= 没有要重新显示的画面（初值；两条重发路径对这类值都不做事）。★ 本条只写 `2`；写 `1` 的通常是**别的指令**（它同时写外枠编号格；那条指令尚未成篇）。**例外只有一条**：下面「图像号 < 0」的**黑底替代**支会把显示状态改成 `1`、并把外枠编号格 ← `0` —— 除这一支外本条不碰这两格。
- **这两格的读者只有"重新显示"那两处**（本版已枚举全部访问形态）：
  - ① **显示模式入口把模式切回窗口态之后**（「切换显示模式」把"外部资源重载"排除在它自己之外，这里就是那个重载）：
    - 显示状态 `2` 且**图像号 ≥ 0** ⇒ 用**图像号格**的值**重发一次载图**；
    - 显示状态 `2` 且**图像号 < 0** ⇒ 经**错误通道**写一条「外枠用ビットマップを読み込めませんでした。黒で代替します。」，然后**把显示状态改成 `1`、外枠编号格 ← `0`，再按编号 `0` 发一次外枠纹理请求**（黑底替代；⇒ 之后的重发都走 `1` 那支）；
    - 显示状态 `1` ⇒ 用**外枠编号格**的值**重发一次外枠纹理请求**；
    - 其它值 ⇒ 什么都不做。
    ★ **负号分支只挂在状态 `2` 上**：状态 `1` 支不看图像号，也**不检查**外枠编号的正负（负数照原样当请求实参传下去）。
  - ② **引擎释放自己的显示资源之后的恢复路径**（**只有两条入口**：**呈现失败后的设备丢失恢复**流程 —— 它先释放、再（必要时）复位，然后经**同一个释放入口**收尾；以及**渲染器初始化** —— 显示模式切换会重跑它）：释放完成之后**立即在同一次调用内**按同一套两支重发（`2` ⇒ 用**图像号格**重发载图；`1` ⇒ 用**外枠编号格**重发外枠纹理请求；其它值 ⇒ 什么都不做）。★ **触发点是"释放"本身，不是"下一次窗口重绘"** ⇒ 这次重发是可观察的请求，不需要等某次重绘。★ **触发点是一个闭集**：只有这两条入口会走到这次重发；设备丢失恢复**在集合里**（它调的正是那个带重发的释放入口）—— ⛔ 不许写成「恢复只释放、重发只由设备重置触发」，也⛔ 不许推广成「任何释放显示资源的路径都会重发」。
    - **窗口态判据与读者①同一条**：**显示模式缓存 ≠ 0（全屏态）时这次重发不发生** —— 那两格只被记录（与 `0x25b` 第 3 步「全屏态不载」同一口径）。
    - **「引擎自己的显示资源」** = 场景持有的那一批：若干显示对象 + **全部纹理槽里的对象** + 动画槽里的对象（与「帧步进」里设备丢失恢复释放的是**同一批**）。
    - 这条路径**不写**显示状态、也不写图像号 / 外枠编号 ⇒ 每次释放都会**再发一次同样的请求**。
    - 这条路径**没有**状态 `2` 的负号分支 ⇒ 状态 `2` 且**图像号 < 0** 时它把那个**负值原样**交给载图入口（不转外枠、不改成 −1 / 0、不做符号检查）。
    ★ 同一个负图像号在两条路径上的结局**可观察地不同**：① 走完显示状态 = `1`、外枠编号 = `0`（此后走外枠那支）；② 走完这两格**都不变**（仍是 `2` + 那个负值）。⇒ ⛔ 不许把 ② 也实现成"负数就转外枠"，也⛔ 不许把 ② 实现成"负数 ⇒ 什么都不发"。
- **外枠纹理**（显示状态 `1` 指的东西）：
  - 引擎只有**一份**外枠纹理，由引擎自己创建，**不占纹理槽编号**：⛔ 不是 `0x1f8` 那种槽里的对象，也别指望用 `0x216` 查到它。
  - **编号来源**：**外枠编号格**。写显示状态 `1` 的那条指令同时写这一格；黑底替代也写它（← `0`）。
  - **请求**：按该编号对这份纹理发一次请求 —— 三项参数依次是矩形 `(0, 0, 宽, 高)`、**该编号本身**、常量 `0xFF`。★ 它**不是**本条第 3 步那条载图请求，也**不**走绘制入口。
  - **失败**：创建 / 请求失败 ⇒ 经**错误通道**上报一条（说明外枠纹理创建失败），**不抛异常**、不改显示状态与外枠编号格。
  - **每次请求都重建**：先释放旧的外枠纹理对象，再新建并装载（⇒ 这份纹理不是"改内容"，是"换对象"；新建失败时格子里留下的是一个创建失败的对象，不是旧对象）。
  - **三项参数各当什么用（已取证）**：这份纹理的填充入口按**像素位宽**分两条支（16 位 / 24-32 位），两支都把**第 2 个实参当颜色**、把**第 3 个实参当透明度**（⛔ `0xFF` 是**透明度**，不是编号）：
    - **颜色**：24 / 32 位支取实参的**低 24 位**（`& 0xFFFFFF`，原样作像素的 RGB）；16 位支把它压成 **4:4:4** —— 红 = 位 **12–15**、绿 = 位 **8–11**、蓝 = 位 **4–7**，**位 0–3 被丢弃**（⛔ 不是 RGB565：位宽与位段都不同）⇒ 同一个编号在 16 位表面上会丢最低 4 位。
    - **透明度**：≥ 0 ⇒ 写进像素的 alpha 段；< 0 ⇒ **保留目标像素原有的 alpha 段**、只写颜色。本请求传的 `0xFF` 恒 ≥ 0 ⇒ "保留原有 alpha"那一支在这个调用点上**永远走不到**。
    - ⇒ **本条请求的实参 = 矩形 `(0, 0, 宽, 高)` + 编号（作颜色）+ `0xFF`（作透明度）**，即"不透明、编号作 RGB"。★ 这条**只规定实参**（哪份纹理、三个实参各是什么、失败怎么报）；填充**结果**的像素（位段落位、通道拼接、宿主 alpha 是否被覆写）属**表现结果**，见「总览与约定」的「本版不覆盖」——⛔ 不许把像素结果写成合同。★ 外枠编号**不是**资源索引：这个入口**没有任何资源取得**（不载入、不按编号查表、不把参数当指针或下标用过）⇒「按编号取一张位图铺进矩形」的读法**已被证伪**，⛔ 不许实现成取图。
    - **矩形的宽 / 高** = **渲染对象的目标画面区**（⛔ **不是**客户区 / 窗口区）：宽 ← **源宽**；高 ← **截断(源高 × 缩放比)**（向下截断）。**夹取**：若高 **< 源高** ⇒ 高 ← **源高**，且宽 ← **截断(源高 ÷ 缩放比)**（这一步在比较之后执行 ⇒ 夹取后的宽不再是源宽）；另有一档（**另一个显示模式格非 0**）⇒ 高 ← **源高**、宽不动。
    - ★ 上面这些**不改变**前面几条可判的部分（哪张纹理、用哪个编号、失败怎么报）。
- ⇒ **全屏态不载图时没有任何"补载"**：全屏期间这两格只被**记录**；回到窗口态（或上述恢复路径）才重发。⛔ 不要写成"下一次显示请求会补载"——没有这样的消费者。
- **窗口态的载图失败**：载图入口失败 ⇒ 抛**显示消息型异常**（**类别 7：可重试 / 忽略**），消息文本里带**解析出的图像文件名**。抛出时第 1、2 步**已经写过**（显示状态 = 2、图像号 = 操作数）、**不回滚** ⇒ 忽略之后引擎停在"状态 2 + 一个没载入的图像号"上。
- 图像号格被写成操作数**之后**才谈载入：载入用的就是同一个值（⛔ 不许读两次不同来源）。

**可证伪**

- 若外枠编号被用作任何资源查找 / 下标 / 指针 ⇒「编号并入填充色」错（那说明被实现成了取图）。
- 若填充色不是「不透明 + 编号作 RGB」（例如把 `0xFF` 当编号、或对目标像素做了混合）⇒ 本条错。
- 若外枠纹理的尺寸不等于**目标画面区**的宽 / 高（例如等于窗口客户区）⇒ 宽高身份错。
- 构造一个「高 < 源高」的缩放档 ⇒ 外枠纹理的高必须**恰为源高**、宽必须恰为 **截断(源高 ÷ 缩放比)**（不是源宽、也不是"没有下界"的算出来那个高）；只夹高不重算宽 ⇒ 夹取支写错。
- 在 **16 位位宽**的表面上请求一次，编号取 `0x0F`：颜色段必须按 **4:4:4** 落位（红 = 位 12–15、绿 = 8–11、蓝 = 4–7），**位 0–3 不参与**；若按 RGB565 落位（红 5 位 / 绿 6 位）⇒ 位宽分支写错。
- 触发一次显示资源释放（设备重置 / 渲染器初始化）后**在同一次调用内**观察请求序列：必须有那一次重发（状态 `2` ⇒ 载图、状态 `1` ⇒ 外枠）；没有 ⇒ 触发点错。若重发只在之后的窗口重绘里出现、而不在同一次释放调用内 ⇒ 时机错。

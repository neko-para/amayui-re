## 渲染请求边界：目标、混合、离屏文字族、清屏与帧步进

本章规则数以 `pnpm tools spec chapters` 现查。

本章的规则分两类：**作用在渲染路径的输入状态 / 表面内容**上的（把某个纹理槽的纹理设为当前渲染目标、设置场景混合的模式与颜色、把文本 / 数值文本画进某个纹理槽的纹理），以及**帧与画面级**的（清屏、帧步进 —— 后者定义主循环与脚本共用的**渲染步**，遍历 / 提交；清、38 贴回等见该条残差）。
它们改**引擎数据**（以及离屏文字族写入的纹理表面内容）。除 `0x33f` 外都向外部渲染模块发请求
（`0x20d` / `0x204` / `0x205` / `0x20e` / `0x20c`）；请求的形态写在每条里，平台侧的行为不在本版。
本章也把「外部请求」与「引擎数据改变」分开写：请求本身是可观察的，请求的结果不是。

### 渲染目标：opcode 0x20d

<!-- rule: CORE-OPS-RENDER-TARGET-20D -->

`0x20d` 有一个操作数：**第 1 个是纹理槽号**；读一次，按整数读，比较按**无符号**做。长度槽 ← 3。

- 操作数 **小于 1000** ⇒ 目标是该编号的**纹理槽**（纹理槽的定义见「纹理族」）：
  - 槽里没有对象 ⇒ 向**错误通道**（术语见「总览与约定」）上报一条文本（说明该纹理尚未创建）；本条**不改当前渲染目标**。
  - 槽里有对象 ⇒ 先向外部请求该纹理的**渲染表面**（一个可用于绘制的平台表面）；取不到 ⇒ 错误通道上报（说明渲染表面获取失败）；本条不改当前渲染目标。
  - 取到 ⇒ 再请求把该表面**设为渲染目标**；失败 ⇒ 错误通道上报（说明渲染目标设置失败）；本条不改当前渲染目标。
  - 成功 ⇒ **当前渲染目标 = 该槽号**。
- 操作数 **不小于 1000**（按无符号比较，因此负的整数也落在这一支）⇒ 目标是**平台后缓冲**（取后缓冲 + 设为渲染目标）：
  - 先请求平台后缓冲；取不到 ⇒ 错误通道上报（说明后缓冲获取失败）；本条不改当前渲染目标。
  - 取到 ⇒ 请求把它设为渲染目标；失败 ⇒ 错误通道上报（说明后缓冲目标设置失败）；本条不改当前渲染目标。
  - 成功 ⇒ **当前渲染目标 = 「后缓冲」哨兵**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 场景的当前渲染目标 | 场景记录里的一个整数字段 ← 纹理槽号 / 「后缓冲」哨兵 |
| 错误通道 | 一次上报（仅失败路径；文本为说明型消息，内容本版不规定） |
| 取到的渲染表面 | 一份平台侧引用：请求结束后归还（成功与失败路径都归还） |

**成立条件**

- 只有两段：**小于 1000 / 不小于 1000**。不小于 1000 **不是**"槽号越界错误"，而是"复位到后缓冲"的合法入口；正因为比较按无符号做，负数也走这一支。
- 1000 是本条的分支阈值，不是另取证的纹理容量：纹理族对编号不做范围检查（见「纹理族」的「状态模型」）。⇒ 编号 ≥ 1000 的创建是**越界写**（未定义行为；容量与后果本版不规定，见残差），不是"产生一个本条不认的合法对象"；⛔ 不许据此认为存在编号 ≥ 1000 的合法纹理对象。
- 所有失败都发生在写当前渲染目标**之前** ⇒ 失败时该字段保持原值。它的**初值是「后缓冲」哨兵**（场景建立时写入；场景建立本版不规定，见残差）。
- 成功路径**先取表面、再设目标、再归还表面**：归还发生在写当前渲染目标之前，两者次序不可交换。
- 本条**不建**纹理对象、不改纹理槽、不改绘制项、不置脏标记；它不抛引擎自己的错误（操作数类型异常仍按「数据池」的通用规则生效）。
- 错误文本可能带平台返回码的文本转写 ⇒ 内容本版不规定；实现必须**仍然上报**，不得静默。
- 平台是否真的切换了目标、后缓冲是否真的可见，属外部模块：本版只规定请求、参数与状态写入。

**残差**

- `RES-RENDER-TARGET-PLATFORM`（unknown）：平台侧是否真的切换了目标、后缓冲是否真的可见不在本版。下一步：在表现层观察 `SetRenderTarget` / `GetBackBuffer` 的返回与画面变化。
- `RES-RENDER-TARGET-SURFACE`（unknown）：取渲染表面时两个附加实参都传 0，它们的语义本版不规定。下一步：按表面请求的实参表核这两个常量。
- `RES-RENDER-TARGET-ORDER`（unknown）：本条写目标格发生在**门之后**，因此它从**下一次渲染步**（门前那次或 `0x20c` 那次）起生效；命令档在步内的切 / 恢复由 `CORE-SCENE-DRAW-ORDER` 规定。仍未定的是编号 38 的切 / 贴回 / 复位、以及平台换链 / 垂直同步的逐位行为。下一步：补 38 的实参；平台逐位表现进 discards。
- `RES-RENDER-TARGET-BOUNDS`（unknown）：编号 ≥ 1000 的创建写到纹理槽表之后，属未定义行为；本版只说明"不是合法对象"，不规定越界写的后果。下一步：按纹理族的编号上限与槽表容量取证。
- `RES-RENDER-TARGET-FIELD`（unknown）：渲染步在**步末**读它判「是否提交」；命令档在步内的切 / 恢复也读它（由场景章规定）。仍未枚举的是所有其它读者。下一步：枚举该格的读取点，确认是否还有别的分支。
- `RES-RENDER-TARGET-INIT`（unknown）：场景建立路径与目标格初值的写入点不在本版。下一步：把场景建立作为表现层 / 场景族的条目成篇。
- `RES-RENDER-TARGET-TEXT`（unknown）：三条失败路径的错误文本内容本版不规定。下一步：按错误通道的调用点枚举文本。

### 场景混合：opcode 0x33f

<!-- rule: CORE-OPS-RENDER-BLEND-33F -->

`0x33f` 有三个操作数：**1 = 混合模式**、**2 = 透明度**、**3 = 颜色**。长度槽 ← 7。
读序是 **2 → 3 →（按需）1 →（按需）1 → 1**：前两个总是先读；第 1 个只在下面两种回退发生时被读，最后写模式时再读一次。

- **归一化**：透明度 > 255 ⇒ 按 255；透明度 < 0 ⇒ 取**编号 1 指向的绘制项**（见「场景 / 颜色族」）的**当前颜色的透明度**；颜色 < 0 ⇒ 取**该绘制项的当前颜色**；其余情况用参数本身。这段归一化与「场景 / 颜色族」的共用口径同形，但有两处差别：**回退来源**是编号 1 指向的那条绘制项（不是"本条上次写的值"）；并且本条**不建**默认绘制项（见下）。窗进行中这里读的是**当前颜色字段**，不是这一步的插值色（插值色不是记录字段）。
- 该绘制项不存在 ⇒ 回退值取「无颜色」哨兵；本条**不建**绘制项（它只查表，不走场景族共用口径里的"取记录：查不到先建默认记录"那一步）。
- **合成**：结果的透明度 = 归一化后的透明度，结果的颜色 = 颜色（归一化后）；透明度是颜色值的一部分（位段细节属机器细节，本版不规定）。
- 写两个引擎数据：**场景混合的模式 ← 第 1 个操作数原样**（不归一、不夹取、不查表）；**场景混合的颜色 ← 合成结果**。
- 本条**不发外部请求**：模式与颜色由渲染路径稍后读取；读取方怎样分支属外部模块，本版不规定。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 场景混合的模式 | 场景持有的**效应对象**上的一个整数格 ← 第 1 个操作数 |
| 场景混合的颜色 | 同一对象上的一个颜色格 ← 合成结果 |

**成立条件**

- 模式格**原样**收下操作数：取 0、取 1、取 3、取很大的值都照写；⛔ 不许 clamp 到某个模式枚举。
- 回退色读的是**绘制项**（与绘制纹理、排渐变窗用的同一张表），⛔ 不是"场景混合自己的旧颜色"：把上一趟写进颜色格的值当归一化输入，会在颜色格被改过之后得到不同结果。
- 模式与颜色是**两个格**：只写颜色不写模式、或反之，都不是本条。
- 本条**不置脏标记、不置「场景有动画」**：它不参与场景的动画推进。
- 效应对象由场景建立路径构造（初值：模式 = 0、颜色 = 「无颜色」哨兵；场景建立本版不规定，见残差）；本条**不检查**它是否存在 —— 对象不在场时解引用即未定义行为，按崩溃诊断。
- 第 1 个操作数在**两种角色**下被用：模式值、回退查表的键。两者是否同一领域概念**本版不规定**（见残差）。

**残差**

- `RES-RENDER-BLEND-OPERAND1`（unknown）：第 1 个操作数同时被当作"混合模式"写入与"绘制项查找键"使用；两个角色是否同一领域概念本版不规定。下一步：找效应对象两个格的读者，确认模式值是否与绘制项键同一空间。
- `RES-RENDER-BLEND-OBJECT`（unknown）：效应对象的构造与生命周期不在本章；本条只规定两个格的写入与回退读取。下一步：把效应对象的构造 / 释放作为表现层条目单独立条。
- `RES-RENDER-BLEND-INIT`（unknown）：效应对象的初值（模式 = 0、颜色 = 无颜色哨兵）由场景建立路径写入，该路径本版不规定。下一步：同 `RES-RENDER-TARGET-INIT`。
- `RES-RENDER-BLEND-NOCREATE`（unknown）：本条不建默认绘制项，与「场景 / 颜色族」的"取记录先建默认"不同；原因未逐字取证。下一步：核该查找路径，确认它不走到建默认记录的分支。
- `RES-RENDER-BLEND-HIGHBITS`（unknown）：透明度是颜色值的一部分，但位段口径本版只记形态、不写具体位段。下一步：按颜色字段的位段取证补成唯一公式。
- `RES-RENDER-BLEND-PIXEL`（unknown）：模式与颜色如何参与像素混合属表现层。下一步：逐位表现按项目口径进 discards。

### 离屏文字：opcode 0x204

<!-- rule: CORE-OPS-RENDER-TEXT-204 -->

`0x204` 有四个操作数：**1 = 纹理槽号**、**2 = 横坐标**、**3 = 纵坐标**、**4 = 文本**。长度槽 ← 9。
读序是 **3 → 2 → 4 → 1**：第 3、2 个按整型读，第 4 个按**文本**读（先于第 1 个），第 1 个按整型读。

- 第 4 个操作数按文本读：字符串型操作数给出它的字节串；数值型操作数给出**十进制文本**（口径同「字符串」的源侧；符号、宽度、浮点格式本版不规定 —— 见残差）；内联文本按「数据池」解码。
- 文本的字节串按 **Shift-JIS** 解释：单字节与双字节混排，**前导字节**引入一个双字节字符（两个字节合成一个字）；`0x8140`（**全角空格**）走一个**特例分支**（它的量度与落像素行为本版不规定）。**推进量不是无条件等于字形量度**：半角字符（`< 0x100`）、空白宽度配置、以及对位模式都会改变它；本版不规定逐档算法（见残差 `RES-RENDER-TEXT-ADVANCE`）。
- **入口条件**（**三条**，都在发请求**之前**判；任一不满足 ⇒ 本条什么都不做：不发请求、不改引擎数据、不报错）：
  1. 该槽里有纹理对象（纹理槽见「纹理族」）；
  2. 该纹理对象的一次**只读询问**返回非空（与「渲染目标」那条取表面用的是同一个询问）；
  3. 文本**非空**（首字节非 0）。
- **字体与颜色不是操作数**：本条**没有**字体 / 颜色实参。绘制入口自己从引擎**唯一**的字体对象读取：
  - **字体** = 该对象持有的 **A 支字体描述**里的**横排那一份**（字面名、高度、粗细、字符集）以及由它**物化**出的平台字体句柄。
    ★ **每支各两份描述**（横排一份、竖排一份；竖排那份物化时的字符走向 = 2700），两支合计**四**份 ——
    见「转发到字体对象与宿主接口的入口」。描述本身由别的 opcode 改（字号 / 粗细 / 字面名），改完请求重建；
  - **颜色** = 该对象的**主色 / 副色**两个 24 位值（主色默认**白**、副色默认**黑**）。脚本侧写进来的是 `0xRRGGBB`；引擎存放时按平台颜色字节序（低字节为蓝、最高字节不用），因此同一个数值在"脚本侧"与"绘制侧"的字节顺序**不同**。
- **请求**（一次同步绘制，内部含多条平台请求）：把该文本逐字画进该槽的纹理 —— 参数 = 横坐标、纵坐标、文本。顺序：
  1. 字体对象：把一个内部布尔开关清 0；
  2. 若**显示记录**里的**虚拟全屏类型**格（= 配置 `display:VirtualFullScreenType` 的当前值；"虚拟全屏"关时该格为 0）等于 **2**，把该对象物化出的字体句柄**选进**绘制表面（`SelectObject`）；不等于 2 就**不选**（用绘制表面当前已经选着的那个字体）。
  3. 取一次**本次量度**（`GetTextMetrics`）；
  4. **纵向对位**：**仅当**该对象的**对位模式**等于 **1** 时，`纵坐标 ← 纵坐标 + 量度缓存里的 ascent − 本次量度的 ascent`；否则**纵坐标原样**。缓存里那个 ascent 是**上一次字体重建**时（对位模式 = 1 的那条重建分支）对**重建入口自己组的那份参考字体**做的那一次量度的 ascent 分量 —— 参考请求 = 字面名常量「ＭＳ ゴシック」、高度 = −字号（该字号若带缩放比，缩放乘在建字体那一步，见「转发到字体对象…」）、宽度 = −字号/2、**粗细取对象描述的粗细**、字符集 = 默认（宽度取整与字符集默认值见 `RES-RENDER-TEXT-ALIGN-REFERENCE`）；**不是对象当前字面名那份渲染字体**，也不是"上一次 `0x204` 的量度"、更不是常量 0。所以这一步的效果是"把参考字体与本次量度的基线差补回来"。★ 对位模式 ≠ 1 的重建分支本版**未建模**（见 `RES-RENDER-TEXT-ALIGN` 与 `0x2db` 条）：那里缓存里是什么，本条不规定。
  5. 按**绘制模式**二选一进入两条绘制入口（模式 = 0 ⇒ "只画主色一遍"的那条；模式 ≠ 0 ⇒ 另一条，并把模式作为实参传进去）。两条入口内部**同形**：取该纹理的尺寸 / 描述 → **加锁**表面 → **落字前**把**纵坐标 ← 纵坐标 + 本次量度的 ascent** → 逐字取字形并写入（每字按推进量前进）→ **解锁**（⇒ 落字用**基线**，第 3 个操作数（纵坐标）是**字形格顶**）。
     **基线** = 第 3 个操作数的**原值** +（对位模式 = 1 ? 缓存 ascent : 本次 ascent）。★ **对位模式与绘制模式是两个正交的轴**：绘制模式决定走哪条入口、画几遍颜色；对位模式在**本请求的纵向对位**上决定基线用哪个 ascent（它对推进量与重建量度的作用不在本条，见本章残差与 `0x2db` 条）。
- **两条绘制入口只差一个绘制模式**（模式**不是操作数**，是字体对象的一格，默认 **1**）：

| 模式 | 效果 |
|---|---|
| 0 | 只画主色一遍 |
| 1 | 先按**投影偏移**（常量 (1, 1)，见下）画一遍**副色**，再在同一位置画**主色** |
| 2 | 主色在**同一位置**画两遍 |
| 3 | **副色**按**多趟径向**画：以两个投影偏移分量为半径、按等步长绕行取样（步长 = 360 ÷ (√(偏移纵 ＋ 偏移横) × 8)；偏移 (1,1) ⇒ 累计角度每趟 +31.82°、共 **12 趟**，累计约 1.94 圈），每趟的位移 =（round(sin(θ) × 偏移横), round(cos(θ) × 偏移纵)），θ = 累计角度 × 180 ÷ π（★ 引擎这个乘法方向就是如此，见下）⇒ 12 趟的位移收敛成 **6 个方向**（(0,±1)、(±1,0)、(1,1)、(-1,-1)）；最后画**主色** |

  ⛔ 模式不是操作数：把它从操作数里取，会把纹理槽号当成模式。
- **投影偏移**恒为 **(1, 1)**（横向、纵向各一个整数，单位 = 设备像素）：构造时置入；**本条绘制请求只读它，不调用样式应用 / 字体重建**，因此本条读取到的值不受那些入口影响。⛔ 不是资源文件的字段、⛔ 不是配置键、⛔ 也不是任何脚本操作数写进来的值；⛔ 不许实现成可配置 / 可从资源读的值。★ **其它直接调用绘制入口的路径**是否会在借用期读到另一个值，见残差 `RES-RENDER-TEXT-PROJECTION`。
- 绘制侧的用法：模式 1 的副色趟画在（横 + 偏移横, 纵 + 偏移纵）；模式 3 的径向以两个偏移分量为半径、按步长取点（累计角度从 0 起，< 360 就再画一趟 ⇒ 偏移 (1,1) 时共 12 趟、扫过约 1.94 圈；角度的三角函数实参是**累计角度 × 180 ÷ π**，本版照抄引擎的乘法方向，⛔ 不要"修正"成 × π ÷ 180 —— 那会换出 8 个方向的位移）；模式 0 / 2 不读它。
- **字形位图的请求格式**由**字体对象**的**抗锯齿开关**决定：**两者都非 0 才开；任一为 0 / 缺键 ⇒ 关 ⇒ 每像素 1 位（掩码）**。开关 = 配置的**总开关** `set:EnableAntiFont`（取值含「配置」章对 `ENABLEANTIFONT` 的平台条件改写）与**子开关** `message:UseAntiFont`；级数 = `message:AntiFontLevel`（= 1 ⇒ **8 位**，其余 ⇒ **4 位**）。⛔ 不是平台自由：⛔ 不许无条件用平台的灰度抗锯齿，也⛔ 不许把 1 位与灰度当成同一格式。★ **两格什么时候从配置抄进来**：字体构造时先清 0，之后由**进程启动时的那一条"应用设置"入口**从配置键抄入（总开关为 0 时整块跳过）；运行期设置提交只把**开关**重新应用，**级数没有**对应的重应用路径 ⇒ **运行期改级数不影响本次会话**（改开关则立即生效）。⛔ 不许实现成"每次绘制都重读配置"。
- **级数 → 覆盖值**：字形位图里每个像素的**原始级数**按该格式的值域取值 —— **4 位灰度 0..16（17 级）**、**8 位灰度 0..64（65 级）**（0 = 无覆盖）、**1 位掩码只有 0 / 1**。引擎把它换算成**逐像素覆盖值** = **原始级数 × 255 ÷ 除数**，**除数 = 17（4 位）/ 65（8 位）**，整除（正数向下取整）⇒ 4 位的覆盖值 ∈ {0, 15, 30, …, 240}（**满覆盖 240**）；8 位的覆盖值 = ⌊原始 × 255 ÷ 65⌋ ∈ {0, 3, 7, …, 251}（**满覆盖 251**，不是连续区间）；1 位掩码的覆盖值是 0 / 255 —— **只有它的覆盖值能到 255**。⛔ 除数不是 2 的幂（16 / 64）：按 2 的幂算会把满覆盖抬到 255，抗锯齿档下的文字比引擎亮一档。⛔ 也不是把原始级数直接当覆盖值（4 位格式里原始 16 才是满覆盖，它对应 240、不是 16）。
- **覆盖值不是"像素不透明度"**：三种量必须分开 —— **覆盖值**（上一段，0..255）、**通道值**（真正写进表面某个通道的那个数）、**像素不透明度**（写完后的 alpha）。表面有 **16 位与 32 位两种**，两者通道满值不同：**32 位表面**的通道值 = 覆盖值（满值 **255**）；**16 位表面**先把覆盖值**算术右移 4 位**（向下取整）降到 4 位通道（0..15、满值 **15**），且这次降位发生在"覆盖值是否为 0"的判据**之前**。写入后像素的不透明度 = **目标不透明度与通道值里的较大者**（不是直接等于通道值）⇒ 目标本来就更不透明时，像素不透明度可以超过**通道值**（32 位表面通道值就是覆盖值；例如目标已是 255 时，灰度字形的像素不透明度也是 255）。⛔ 别把"16 位表面上 1 位掩码的覆盖值 255"读成"像素不透明度 255"：那个表面的通道值最多 15。
- **写入：三条支路**（按覆盖值与**目标像素自身的通道值**选，⛔ 不是"一律 alpha 混合"）：
  1. **覆盖值 = 0** ⇒ **一个字节都不写**（目标像素原样保留；⛔ 不是"写一个透明像素"）。
  2. **通道值达到该表面的通道满值**（32 位表面 = 255；16 位表面 = 降位后的 15）**或目标像素自身的通道值 = 0** ⇒ **整像素覆写**：颜色 ← **源色原值**、通道值 ← 覆盖值，**不读目标像素**（⇒ 同一像素重复写同一字形是幂等的；**刚清空的画布上每个像素的第一次写入都走这一支**）。
  3. 其余 ⇒ **逐通道加权**：通道 ← (源 × 通道值 + 目标 × (通道满值 − 通道值)) ÷ 通道满值；输出通道值 ← **目标与覆盖值中的较大者**（⛔ 不是"等于覆盖值"、⛔ 不是 alpha-over）。
  ★ 三条支路共用同一个写入点。**逐通道乘除的取整顺序、位打包的实现、16 位表面降位后的实际位模式**属逐位表现，见残差。
- **加锁不是入口条件**：它发生在请求内部（请求的第 5 步）；加锁失败时，前 1–4 步已经发生的副作用**不回收**（已清的开关、可能已选的字体、已取过的量度），只是不写像素并上报错误通道。
- **特殊字形路径**：逐字写入时，若**字形码**是 `0xF042` 或 `0xF043`（私用区字形），进入特殊路径：**解锁 → 矩形操作 → 重新加锁**（矩形操作夹在两次加锁之间；它的语义本版不规定，见残差）。其它字形不走这条路径。
- **引擎数据**：字体对象的字形暂存区被复用 —— 字形位图长度与两份暂存缓冲被重建（长度请求与本体请求必须同格式）；两个内部布尔开关被写（一个与本条开始清 0 的是同一个；另一个是**回退字体**的状态）。它们都不是脚本可观察的值。
- **失败**：
  - **字形取不到** ⇒ **不报错**：不写像素，只按推进量前进（见上）。
  - **加锁失败** ⇒ **不写任何像素**，并由加锁操作向**错误通道**写一条文本（内容本版不规定）。
  - **取尺寸 / 取矩形失败**时的行为本版**不规定**（见残差）。
  - 操作数类型异常仍按「数据池」的通用规则抛出。
- 操作数 1 直接作为纹理槽号；本条**自己**不做 1000 阈值判断（那是 `0x20d` 的分支）。纹理族对编号**不做范围检查**：编号 ≥ 1000 或负值的越界后果本版不规定（同「渲染目标」的纹理族口径）。
- 本条**不建**纹理、不改纹理槽、不改绘制项、不置脏标记、不改池 / 帧 / 列表记录。
- **字体对象的其它维护入口**（字段清单分别落在「列表」的 0x78 / 0x2db 条与「标量」的 0x76 / 0x77 / 0x2bd 条）：`0x75` = 字号；`0x76` / `0x77` = **主色** / **副色**；`0x78` = **绘制模式**；`0x2bd` = **粗细**；`0x2db` = **对位模式**；`0x197` = **B 支字号**；字面名由两条"设置字符串"的入口分别写入两份描述（哪条写哪份见残差）。⛔ `0x203` **与文字无关**：它写的是另一族的绘制色表，不是本条的颜色来源。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个纹理槽的纹理被画上一段文本 | 该槽纹理对象的**表面内容** ← 逐字写入的字形（像素不判，见下） |
| 字体对象的字形暂存区被复用 | 两份暂存缓冲与字形位图长度格被重写（内部缓存；布局属机器细节） |
| 字体重建时量到的 ascent 被缓存 | 字体对象那张量度结构的 ascent 分量 ← 重建时（对位模式 = 1 的分支）对参考字体的一次量度 |
| 请求 | 一次同步绘制：清一个内部开关 →（虚拟全屏类型 = 2 时）选字体 → 取量度 → 纵向对位（仅对位模式 = 1）→ 按绘制模式进两条入口之一 → 取尺寸 / 描述 → 加锁 → **落字前纵坐标 += 本次量度的 ascent** → 逐字取字形（**格式见上**）→ 写入 → 解锁（特殊字形路径在写入中解锁 / 重锁） |

**成立条件**

- 三**条**入口条件都在请求**之前**判：不满足时纹理表面与字体对象的内部缓存**都不动**；⛔ 不许"先清开关再判"。加锁在请求内部，失败后果见「失败」，★ 不把"能不能加锁"提前成第 4 条入口条件。
- 文本为空**不是**错误：不画、不报错。文本为空判的是**首字节**，不是"去掉空白后为空"。
- 第 4 个操作数**先于**第 1 个被读：第 4 个读取抛类型异常时，第 1 个还没被读。
- 请求**同步**完成：本条不置等待位、不置影片位、不等待下一帧；分派器在本条返回后推进指令指针。
- 字体、主色 / 副色、绘制模式**都不是操作数**：⛔ 不许从操作数里取字体或颜色，也⛔ 不许把操作数当绘制模式。
- 纵向对位**只在**对位模式 = 1 时做：其它模式**不做对位修正**（不加减缓存与本次 ascent 的差），但第 5 步落字前仍会加**本次 ascent**。⛔ 不许实现成"总是修正"，也不许把缓存里的 ascent 当成"本次量度"。
- 第 3 个操作数（纵坐标）是**字形格顶**，不是基线：两条绘制入口都会在落字前加上**本次量度**的 ascent。⛔ 不许把它当基线直接落字 —— 那会把整段文字上移一个 ascent。
- 对位模式 = 1 的对位项用的是**字体重建时对参考字体**量到的 ascent 分量（不是渲染字体的 ascender），⛔ 不许把它当成常量 0 —— 那会把整段文字上移一个 ascent（在纹理上表现为文字从本行 30px 源带跨到相邻源带）；⛔ 也不许拿渲染字体的 ascender 代替它 —— 两者不保证相同，基线会偏（差多少取决于两种字体的 ascent 与字号；观测见残差）。
- **四种组合**都要对：绘制模式（0 / ≠0）× 对位模式（0 / 1）只影响"走哪条入口"与"基线用本次还是缓存的 ascent"（就本请求的纵向对位而言），两个轴**正交**；⛔ 不许把两种模式混成一个开关。
- 两条入口的**选择只看绘制模式是否为 0**：⛔ 不要说成"由另一个内部选择格二选一"（那是同一条模式格的两种说法）。
- 模式 0 与模式 1 **不是同一件事**：模式 0 只画主色，模式 1 多一遍副色（投影偏移处）。⛔ 不许把"没设过模式"实现成 0 —— 默认值是 **1**。
- **投影偏移**是**常量** **(1, 1)**：⛔ 不许把它实现成可配置 / 可从资源读的值，也⛔ 不许让其它入口改变本条读取到的值 —— 把它当配置读会引入一个引擎没有的自由度。
- 模式 3 的副色趟**只外扩一个像素**：每趟的两个位移分量都是 `round(三角函数 × 偏移分量)`，而偏移分量恒为 1 ⇒ **每个位移都落在 {-1,0,1}² 里**（12 趟收敛成 6 个位移、各出现两次）。⛔ 不许实现成"沿对角线逐级加粗"（那会把副色推到 2px 以外；真机在选项/角色设定页的副色黑边只有 1~2px）。★ 像素级后果随字形格式：1 位掩码下就是"外扩 1px"；灰度格式下位移处的半覆盖像素还会与主色混合（可见 2px 的半透明边），这是混合的结果，不是位移更大。
- 模式 3 的**累计角度从 0 起算**（角度 0 也画一趟），循环条件是"累加后仍小于 360"；偏移 (1,1) 时正好 12 趟。★ 这两条在 1 位掩码下**看不出来**（位移并集在 11/12/13 趟时相同）：可证伪的观察是"位移集合 = 那 6 个方向"（见 `RES-RENDER-TEXT-PROJECTION` 的 falsifier 与审计的请求计数档），灰度格式下还能看见重复趟的二次混色。
- 像素结果（字形长什么样、混合结果）**不在本版**：本版只规定"往哪个槽的纹理、在哪个位置、画了哪段文本、用了哪套字体状态"。
- 错误文本的**内容**本版不规定；但失败必须**仍然上报**到错误通道，不得静默。

**残差**

- `RES-RENDER-TEXT-FONT-SELECT-WHY`（unknown）：现在选不选字体的判据已定 —— **显示记录的虚拟全屏类型 == 2**；但该格的**取值集合与各档含义**、以及**为什么只有 == 2 才换字体**，本版不规定。下一步：核该配置键的取值来源，并解释"只在某一档才换字体"的理由（真机对比各档的字形表现）。
- `RES-RENDER-TEXT-FONT-FALLBACK`（unknown）：**回退字体**的状态（本条第二个布尔开关，连同由它决定的一份"临时字体"的建 / 删）本版只登记"被写"，不规定取值与生命周期。下一步：枚举该格的读写点，确认临时字体在什么字符范围上被建立 / 释放。
- `RES-RENDER-TEXT-FONT-SHARED-METRICS`（unknown）：本条开始清 0 的那个内部开关，其领域身份（与"共享缩放 / 度量"相关）与其他写点本版不规定。下一步：枚举该格的读写点，确认它只影响字形缩放 / 量度的复用。
- `RES-RENDER-TEXT-SPECIAL`（unknown）：特殊字形路径已定到"字形码 `0xF042` / `0xF043` ⇒ 解锁 → 矩形操作 → 重锁"；**矩形操作的语义未定**（几次、覆盖哪块矩形、与字形量度的关系）。下一步：逐字读该分支的矩形参数来源，写成条件或明确舍弃。
- `RES-RENDER-TEXT-LOCK`（unknown）：**加锁失败**已定（不写像素 + 错误通道一条文本）；**取尺寸 / 取矩形失败**时的行为本版仍不规定。下一步：读取尺寸 / 取矩形那两个失败分支的判据与后果。
- `RES-RENDER-TEXT-FONT-INSTANCE`（unknown）：字体对象是引擎级的**唯一实例**；它的领域名、以及**其它文字路径**是否复用同一实例（同一套主色 / 副色 / 绘制模式）本版不规定。下一步：把其它文字入口的接收者与字体状态读出来，确认是否同一实例。
- `RES-RENDER-TEXT-GLYPH-RASTER`（unknown）：字形位图由平台栅格化，逐位形状**不可还原**；本版规定**请求的位深**（本条）、**级数 → 覆盖值的换算**（见上）与**落字起点（首字）**（推进量见 `RES-RENDER-TEXT-ADVANCE`），不规定位图的逐位形状 / 位模式。下一步：按项目口径把逐位表现进 discards。
- `RES-RENDER-TEXT-SURFACE-FORMAT`（unknown）：**级数 → 覆盖值、16 位表面把覆盖值降到 4 位通道的换算（算术右移 4 位）、以及三条写入支路都已定**（见上）；仍不规定的是**通道顺序**：源色的三个字节落到目标像素的哪三个位置、以及它们分别对应红 / 绿 / 蓝中的哪一个（两种表面格式各自确认）。下一步：按一条写入路径读源色的解包顺序并对照像素；这要先定脚本侧 `0xRRGGBB` 与"格内存放时字节反转"那条口径（见残差 `RES-RENDER-TEXT-SURFACE-FORMAT` 的取证记录）。
- `RES-RENDER-TEXT-WRITE-BITS`（discarded）：写入循环的**逐位表现**不在本版保留 —— 逐通道乘除的取整顺序（先乘后除 / 中间截断）、位打包的指令级实现、以及 16 位表面降位后的实际位模式。范围：字形写入的逐像素算术。影响：同一覆盖值下相邻像素值可能差 1；三条支路的选择、覆盖值本身、输出通道值 = max(目标, 覆盖值) 这些**结构**不受影响（它们在正文里）。⛔ 不许据此认为"像素内容随便"：结构部分可判，只有逐位不同。
- `RES-RENDER-TEXT-PUA`（unknown）：私用区字形（`0xF042` / `0xF043`）由哪一份字体描述 / 哪一个平台字体句柄画出、以及它们为什么走"解锁 + 矩形操作"路径，本版不规定；**是否另有额外句柄**未定（本版断言字体对象持有**四份**存储的描述：A / B 两支 × 横排 / 竖排各一份，各有自己物化的句柄）。下一步：把字体描述与句柄的对应关系查清，再读这两个字形的矩形操作参数。
- `RES-RENDER-TEXT-ENCODING`（unknown）：**编码本身已证**（Shift-JIS 字节串：前导字节 + 双字节合成、`0x8140` 全角空格）；**仍不规定**的是：数值型操作数 → 十进制文本的格式（符号 / 宽度 / 浮点）、字形选择与字符集（字符集格）的对应，以及 `0x8140` 的量度 / 空白宽度配置分支。下一步：按数值格式化路径取证格式串；把字体描述的字符集格与字形查找对齐；读 `0x8140` 特例的推进量来源。
- `RES-RENDER-TEXT-ALIGN`（unknown）：纵向对位的**条件式与差值形态已定**（仅对位模式 == 1，`y += 缓存 ascent − 本次 ascent`）；**对位模式 = 1 的那条重建分支**里缓存 ascent 的来源已定 = 对**参考字体**做的那一次量度的 ascent 分量（数值见 `RES-RENDER-TEXT-ALIGN-REFERENCE`；由平台量度请求的**指针出参**写进字体对象的一张量度结构；**单位与取整未取证**）。**对位模式 ≠ 1 的重建分支未建模**（它与 0x2db 尾跳入口内的分支有关，见 `RES-OPS-SET-TAIL-FIELDS`）。仍未规定的是：**除重建入口那次 SelectObject（把参考字体选进绘制表面）之外**，还有谁在什么时候改绘制表面的当前字体。下一步：核"虚拟全屏类型 ≠ 2"时绘制表面选着哪个字体；把两张量度的单位与取整取证；核 0x2db 尾跳入口在两种对位模式下的量度分支。
- `RES-RENDER-TEXT-ALIGN-REFERENCE`（unknown）：**参考字体**的身份已定到"重建入口的固定请求"（字面名常量、高度 = −字号、宽度 = −字号/2、粗细取对象描述、字符集默认；不是对象当前字面名），但 **宽度 −字号/2 的奇数取整**、**字符集"默认"的具体值**、以及它的 **ascent 数值**（目标平台上 20px 时是 17 还是 18）与系统字体版本 / 替换未取证。下一步：在目标平台上对该系统字体做一次量度，记录量度结果的 ascent 分量与取整，并核宽度取整 / 字符集默认值。
- `RES-RENDER-TEXT-ALIGN-BACKEND`（discarded）：**跨后端 / 跨系统字体版本**的数值差与栅格化位模式属**平台实现可替换**的部分，逐位 / 跨后端表现不在本版保留。范围：绘制路径与字体重建路径。影响：换一个平台字体后端时 ascent 可能差 1px，不保证跨后端像素一致。★ 目标平台上的取值本身不在此舍弃：由 `RES-RENDER-TEXT-ALIGN-REFERENCE` 的 next 去量（两者不重叠）。⛔ "量哪份字体"不是后端自由（见参考字体残差）。
- `RES-RENDER-TEXT-ADVANCE`（unknown）：推进量的逐档算法本版不规定：半角字符（`< 0x100`）、空白宽度配置、以及对位模式各自怎样改推进量都未逐字写成条件。⛔ 照"每个字符 = 自身字形量度"实现会把半角按全角排。下一步：按三条分支的站点逐档取证（半角系数 / 空白宽度表 / 对位模式）。
- `RES-RENDER-TEXT-PRESENT`（unknown）：加锁 / 写入与帧提交 / 呈现的先后关系没有取证。下一步：定位主循环的呈现点，给出相对顺序。
- `RES-RENDER-TEXT-PROJECTION`（unknown）：**本条**绘制请求读取时为 (1, 1) 已定（构造置入；本条不触发借用）。仍未定的是：**其它直接调用绘制入口的路径**是否会在样式应用 / 重建临时改这一格的期间读到另一个值（若存在此类路径），以及该值是否参与字形格 / 推进量。下一步：枚举直接调用绘制入口的路径与借用区间的重叠；若重叠，核该值是否参与字形格 / 推进量。★ 绘制模式 3 的径向半径 / 趟数 / 步长**已按站点取数**（见上表与「成立条件」），不再是残差。

### 数值文本：opcode 0x205

<!-- rule: CORE-OPS-RENDER-NUMTEXT-205 -->

`0x205` 有六个操作数：**1 = 纹理槽号**、**2 = 字段原点（横坐标）**、**3 = 纵坐标**、**4 = 值**、**5 = 格数**、**6 = 格式位**。长度槽 ← 13。
读序是 **2 → 6 → 5 → 4 →（格式化）→ 3 → 1**：先按整型读第 2、6、5、4 个，格式化之后才按整型读第 3、1 个。

- **本条 = 「把数值格式化后的文本画进纹理槽」**：绘制入口、字体 / 颜色 / 绘制模式 / 对位模式、以及三条入口条件（槽里有纹理对象、只读询问非空、文本非空）与「离屏文字」条**同一份**；本条只多出"把值格式化成文本并算出横向位置"。
- **格式化**（十进制的绝对值；不出现小数点、千分位、指数）：
  - **符号**：值为负 ⇒ `-`；值为正且置 **`0x8`** ⇒ `+`；值为零时置 **`0x10`** ⇒ `+`、置 **`0x20`** ⇒ `-`（`0x10` 优先于 `0x20`，两位可同时置）。有符号时**符号占一格**，可用数字格 = 格数 − 1。
  - **前导零**：置 **`0x1`** ⇒ 数字补零补满可用数字格；不置 ⇒ 不补（高位留空，文本只含数字与符号）。
  - **放不下**：数字位数超过可用数字格 ⇒ **丢掉高位数字**，只画低位那几格。例：2 格、不置 `0x8` / `0x10`、值 12345 ⇒ `45`；3 格、值 −1234 ⇒ `-34`。
  - **`#` 的唯一入口**：**有符号且格数 < 2**（连符号位都排不下）⇒ 整段退化成**单个 `#`**。**无符号且格数 ≤ 0** ⇒ **空串**（不画、不报错）。
  - **半角 / 全角**：置 **`0x10000`** ⇒ 文本按**半角 ASCII** 落字；不置 ⇒ 每个字符**就地扩成全角**（数字 `０`–`９`、`-`、`+`、`#` 的全角形）。
  - **未列出的格式位在本条无作用**（引擎只测上述几位）。
- **横向位置** = 第 2 个操作数 + **未用格数 × 格宽 × k**（下面的算术都是整除，向零截断）：
  - **未用格数** = **格数 − 已写字符数**（符号计入字符数；数字放不下、`#` 档与空串档一律取 0）。
  - **格数按本次模式的字符格计**：半角模式下 1 个字符占 1 个半角格，未用格数也是半角格数。
  - **k 与格宽**：右齐（缺省：格式位 `0x2` / `0x4` 都不置）⇒ 全角 `未用格数 × 格宽`、半角 `÷ 2`；居中（置 **`0x2`**）⇒ 全角 `÷ 2`、半角 `÷ 4`；左齐（置 **`0x4`** 且未置 `0x2`）⇒ 0。
  - **格宽** = 「ADV 文本」条行距里**不含行間隙**的那一项 X：行距模式 = 0 ⇒ X = **−行距项格**；模式 ≠ 0 ⇒ X = **字号格**。⛔ 不许把行間隙算进格宽，⛔ 也不许把 `X` 取成"行距项格"本身（那样右齐会整体左移）。带字体缩放时这两格的取值口径见「ADV 文本」条的行距三支 —— 本条**不另定**缩放口径。
  - 配置 **`set:BlankExtentMode = 1`** 时**格宽改为空白字符的量度宽**：全角模式取**全角空格**的量度宽，半角模式取**半角空格**量度宽的两倍（仍等于一个全角格）；**取 1 以外的值 ⇒ 仍用上面的 X**（取值集合与写入者见残差）。
  - **本条不再乘任何缩放系数**：带字体缩放时，缩放由「ADV 文本」条的行距三支决定（模式 0 与模式 ≠ 0 的取法不同）；⛔ 不要在这里再乘一次显示适配比或字体缩放比。
- **纵坐标**与「离屏文字」条同一条对位规则：落像素的基线 = 原值 +（对位模式 = 1 ? **缓存 ascent** : **本次量度的 ascent**）。⇒ 第 3 个操作数是**字形格顶**，不是基线。
- 第 1 个操作数**直接作纹理槽号**：本条**自己**不做「渲染目标」条的 1000 阈值判断；编号越界的后果本版不规定。
- 本条**不建**纹理、**不改纹理槽表**、不改绘制项、不置脏标记、不改池 / 帧 / 列表记录；请求内部会复用字体对象的字形暂存区与两个内部布尔开关（同「离屏文字」条，都不是脚本可观察值）。
- 操作数类型异常按「数据池」的通用规则抛出：第 3 个操作数读取抛异常时，第 1 个还没被读。
- 本条**不改变**当前渲染目标：目标由第 1 个操作数指定的纹理槽给出（同「离屏文字」）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 某个纹理槽的纹理被画上一段格式化后的数值文本 | 该槽纹理对象的表面内容 ← 该文本的字形（像素不判，同「离屏文字」条） |
| 字体对象的字形暂存区被复用 | 两份暂存缓冲与字形位图长度格被重写（内部缓存；同「离屏文字」条） |

**成立条件**

- **溢出是截断，不是提示**：`#` 只在"有符号且格数 < 2"时出现；⛔ 不许把"数字放不下"实现成 `#` —— 那会在窄字段上把 `45` 变成 `#`。
- **符号只由值的正负与格式位共同决定**：`0x10` / `0x20` 只对**零**生效（⛔ 不是"对非零也生效"），`0x8` 只对**正数**生效；负值一律 `-`（即使置了 `0x8`）。
- **`0x10000` 同时改字形与起点偏移**：置它时字符按半角落字、起点偏移也按半角格宽算；⛔ 不许只改其中一边。★ 它**不是**对逐字推进量的规定 —— 推进量属绘制入口（见「离屏文字」条的残差）。
- **未用格数含符号格**：`-7` 在 3 格里未用 1 格（不是 2 格）；`#` 档与空串档的未用格数是 0（⛔ 不是负数）。
- 本条**不置**脏标记、不发"帧级"请求：它只改该纹理槽的表面内容。

**残差**

- `RES-RENDER-NUMTEXT-BLANK`（unknown）：`set:BlankExtentMode = 1` 时"空白字符的量度宽"已定到"量当前字体的空格字符"，但该配置键的**取值集合**与**写入者**本版不规定（≠ 1 走默认支已定）。下一步：核该键的写入路径与取值集合。
- `RES-RENDER-NUMTEXT-METRIC`（unknown）：`BlankExtentMode = 1` 时量到的**空格量度宽**由平台字体给出，取整与"是否含行距项"未取证；默认支的格宽（−行距项格 / 字号格）是**引擎状态**，不在本条残差里。下一步：在同一后端上量一次空格 extent，核对取整；跨后端差异按项目口径进 discards。
- `RES-RENDER-NUMTEXT-INTMIN`（unknown）：值为最小整数时"取绝对值"在引擎侧溢出，会打印出非数字字符；本版只规定正常范围的绝对值。下一步：按该分支的除法 / 取模逐字核，补一条可观察的反例。
- `RES-RENDER-NUMTEXT-KBOTH`（unknown）：格式位 `0x2` 与 `0x4` 同时置位时按居中处理（判据先看 `0x2`）；这是否是引擎意图、以及是否有脚本会同时置两位，本版不规定。下一步：在语料里找同时置两位的站点。

### 清屏：opcode 0x20e

<!-- rule: CORE-OPS-RENDER-CLEAR-20E -->

`0x20e` **没有操作数**；长度槽 ← 1。

- **请求**：把**当前渲染目标**整面清成**透明黑**。参数：清**颜色与深度**两个缓冲区（颜色 0 = 四个通道全 0；深度 1.0）；**不清模板**（模板实参传 0，但不参与清屏）；**没有矩形** ⇒ 清整面。
- **门控支**：当**虚拟全屏类型 = 1** 且**当前渲染目标是后缓冲**时，清屏序列变成两次：**切到纹理槽 38 的渲染表面 → 清该表面 → 切回后缓冲 → 清后缓冲**。门控不成立时只清一次 —— 清的是**当前渲染目标**（它可能是后缓冲，也可能是某个纹理槽）。
  ⇒ 总计：门控成立 **2 次**（38 在前、后缓冲在后），不成立 **1 次**（⛔ 不是"先清后缓冲、再清 38、再清后缓冲"的三次）。
- **门控支的两次切换与清屏都成功时**，当前渲染目标的可观察值仍是后缓冲：门控条件本身就要求它是后缓冲，序列最后也切回它。★ 门控支的"切目标"在引擎里走的是**另一条入口**（不是「渲染目标」条的直调）；它写不写「当前渲染目标」格、以及切目标 / 清屏失败怎么上报，本版**不单独规定**（本条同步执行、期间没有别的读者）。
- 纹理槽 **38** 的身份与创建见「纹理族」的 38 档（引擎自建、虚拟全屏类型 = 1 时按显示记录的宽 / 高建出）：本条**只清它、不建它**；门控成立而 38 不存在时切目标会失败（后果见残差）。
- 本条**不建**纹理对象、不改纹理槽表、不改绘制项、不置脏标记、不改池 / 帧 / 列表记录。
- 本条与「帧步进」的清屏位是**两个入口**：后者的条件见该条正文（它与本条互不替代）；⛔ 不要用本条替代它，也不要把它当成本条的门。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 当前渲染目标的表面被清成透明黑 | 该表面内容 ← 透明黑（像素不判） |
| 门控支清的那一份表面 | **纹理槽 38** 的纹理表面 ← 透明黑 |
| 请求 | 一次或两次同步清屏；门控支的序列里夹一次"切到 38 / 切回后缓冲" |

**成立条件**

- 门控的**两个条件同时成立**才走门控支：只满足一个 ⇒ 只清主目标一次。⛔ 不许把"虚拟全屏"当成"总是开"或"总是关"。
- 门控支**先切到槽 38、清、再切回后缓冲、再清**：两次清屏的**顺序**是可观察的（对槽 38 的那次发生在后缓冲那次之前）；⛔ 不许实现成"只清后缓冲"或"只清槽 38"。
- 清屏**不依赖**当前场景是否脏、是否有绘制项：本条一旦派发就发请求。
- 颜色是**透明黑**（四个通道全 0），⛔ 不是不透明黑（`0xFF000000`）。

**残差**

- `RES-RENDER-CLEAR-38`（unknown）：门控支清完槽 38 之后**谁消费**这份内容、以及"清 38"与"贴回 38"的先后本版不规定（38 的身份 / 创建 / 切回时机见「纹理族」的 38 档）。下一步：读 38 的读者（绘制 / 贴回）与清屏的先后。
- `RES-RENDER-CLEAR-VFS`（unknown）：虚拟全屏类型的**取值集合**见场景章（0 / 1 / 2）；未定的是 **1 与 2 两档在"建离屏目标 / 选字体"上的分工**。本条只用 `== 1` 这条判据。下一步：读 1 / 2 两档的建 38 与选字体分支，写成条件。
- `RES-RENDER-CLEAR-FAIL`（unknown）：清屏 / 切目标的平台失败如何上报（是否写错误通道、文本内容）未取证。下一步：逐字读两个请求的失败分支。
- `RES-RENDER-CLEAR-ORDER`（unknown）：本条与同帧已排队的绘制命令 / 呈现的先后（清屏是否打断已在显示列表里的命令）未取证。下一步：核目标切换与显示列表提交的消费者。
- `RES-RENDER-CLEAR-DEPTH`（discarded）：深度 / 模板缓冲区在目标表面上的实际位模式、以及平台是否真的清了它们不在本版（本模型没有深度缓冲）。范围：本条请求的深度分量。影响：只影响依赖深度测试的绘制；颜色分量的清屏结果不受影响。下一步：平台深度行为按项目口径进 discards；⛔ 不据此声称像素逐位一致。

### 帧步进：时间戳 + 渲染一步 + 清帧标志（opcode 0x20c）

<!-- rule: CORE-OPS-RENDER-FRAME-STEP -->

`0x20c` 没有操作数。

- 若引擎**未处于执行区间**（**区间忙标记 = 0**）：读一次当前时刻，把「引擎上一时刻」←「引擎当前时刻」，再把「引擎当前时刻」← 读数。这两格是**引擎级**的，与 `0x1f4` 写的是**同一对**（见 `CORE-OPS-RUN-BRACKET`）。
- ★ 这一对就是**场景时钟**（见「场景计时窗」）。区间内 `0x20c` **不重盖**这一对（忙门）；不忙时它先覆盖、再请求渲染步，因此**它自己那次渲染步读的是覆盖后的值**。
- 向渲染子系统发出**一次步进请求**。这次请求就是主循环**门之前**那条渲染步（见「一次迭代做哪些事」的「门前渲染」）；⛔ 它不是唯一的渲染入口，主循环在场景脏 / 有动画 / 命令表在动 / 影片有新帧时也会发同一条请求（**具体判据见残差 `RES-RENDER-STEP-NEEDS-REDRAW`**，本条只登记"不止这一条请求"）。**场景遍历 / 绘制顺序**是引擎行为：两档顺序（命令档 + 收尾扫描）与平键序见「场景 / 颜色族」的「绘制顺序」；D3D 调用与像素输出属平台。
- 把**帧标志格**清成 0（谁置它、它表示什么，本版不规定，见残差）。
- 推进格数 = 1；不改当前帧、不改门位、不写脚本变量。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 引擎时间戳 | 引擎上一时刻 / 引擎当前时刻 |
| 渲染走了一步 | 一次步进请求 |
| 帧标志被清 | 帧标志格 = 0 |
| 画面被提交 | 一次呈现请求（仅当本步结束时目标 = 后缓冲） |

**渲染步（合同边界）**

- 渲染步从**入口的当前渲染目标**开始，对当前渲染目标做场景遍历 / 绘制；命令档可在步内切到离屏目标并在出档恢复（已由 `CORE-SCENE-DRAW-ORDER` 规定）。
- **渲染步默认不清屏**：只有场景的清屏位为 1 时才清（该位的写入者与缺省见残差 `RES-RENDER-STEP-CLEARFLAG`）；脚本的清屏入口是另一条指令（`0x20e`）。⛔ 不许把“每步先清黑”当成渲染步的固定行为。
- 渲染步结束时，若**步末的当前渲染目标是后缓冲**，向平台发一次**呈现请求**；目标是纹理时**不提交**。平台是否真的把后缓冲送到屏幕、以及换链 / 垂直同步的逐位行为属平台。
- 渲染步内部的**清 / 编号 38 的切与贴回 / 复位 / 收尾、各请求的参数与失败后果**本版不规定（见残差）；⛔ 不许把"步进请求交给渲染子系统"当成"遍历 / 提交顺序由平台自由选择"：遍历与提交的次序是引擎行为，只是这一段还没有完整合同。

**成立条件**

- **区间忙标记**非 0 时**不更新时间戳**；但渲染请求与清标志**照做**。该标记就是「暂停」、由 `0x1f4` / `0x1f5` 置清（见 `CORE-OPS-RUN-BRACKET`）。
- 时间戳的更新是「先搬旧、再写新」，不是只写新值。
- 这条不置门位：渲染请求是否阻塞属平台，不在本条；门只决定这一迭代派发不派发指令。
- `0x20c` **不经过门前闸门**：绘制开关、等消息位、渲染器忙都不挡它（见「一次迭代做哪些事」的 `0x20c` 例外）。

**残差**

- `RES-RENDER-STEP-NEEDS-REDRAW`（unknown）：门前闸门里「场景需要重绘」的判据（脏标记 / 有动画 / 命令表在动 / 影片新帧）及各自读取点未取证。下一步：逐条读闸门条件。
- `RES-RENDER-STEP-21B`（unknown）：`0x21b` 那个 0/1 标量的领域名、写者与“为什么它能替代等待位让主循环渲染”未取证。下一步：枚举它的写点与读者。
- `RES-RENDER-STEP-INTERNAL`（unknown）：渲染步内部的清 / 38 切与贴回 / 目标复位 / 收尾顺序、以及各请求的参数与失败后果未取证。下一步：逐段读渲染步并对齐 `60-ops-texture` 的 38 语义。
- `RES-RENDER-STEP-DOUBLE`（unknown）：同一迭代里门前渲染与 `0x20c` 都请求渲染步时，是否真的走两次、以及两次的帧记录 / 命令档「第一帧」判定如何共享本帧场景时刻，未取证。下一步：在真机 / 断点上观察同迭代双请求。
- `RES-RENDER-STEP-BUSY`（unknown）：渲染器忙的判据（谁置 / 何时清）未取证；门前闸门只把它当"为真则本迭代不渲染"。
- `RES-RENDER-STEP-DRAW-SWITCH`（unknown）：场景绘制开关的领域名、缺省值以及它与其它子系统的第二重角色未取证；本条只规定它为 1 才走门前渲染。
- `RES-RENDER-STEP-WAITBIT`（unknown）：状态选择字里「等消息」位的位号、置点与服务分支未取证；本条只规定它为 1 时门前不渲染。
- `RES-RENDER-STEP-FLAG`（unknown）：帧标志格的写者与含义未取证；本条只规定清 0。

## 总览与约定

本规范描述《天結いキャッスルマイスター》引擎在执行脚本时对外可观察的领域行为：脚本怎样编码、引擎维护哪些状态、操作数怎样访问数据池、值怎样表示。

它面向**独立实现者**：读者不需要原二进制、反汇编或本仓的复核材料。但它依赖一份**伴随格式**：AGE 汇编格式（`age-format` 包）规定脚本文本的字节布局、指令表与操作数编码；本规范规定这些字节在运行期的**含义**。两者的分工见「脚本与执行」。

### 本版覆盖

- **脚本二进制协议**（ASM）：脚本头、指令编码、操作数编码、指令表；协议中待核验的部分在「脚本与执行」标出。
- **执行模型**：指令流与当前帧。
- **ALF 归档**：索引头、段、LZSS、TOC 与载荷定位。
- **AGF 图像**：ACGF 容器、meta/body 段、可选 ACIF alpha、像素排布。
- **数据池**：全局池与局部池的族、槽、下标、访问原语、类型标签、支持集合、值编码、字符串记录、容量与越界。
- **引擎级状态**：引擎级按索引标量表。

数据池是**一个完整主题**：族、下标、访问、值表示、容量放在同一章，不再按"池 / 操作数 / 值"拆散。

### 本版不覆盖

- 对象模型、容器句柄、输入、表现边界、**文件装载的调度/搜索路径**、存档、配置、时间。
- 指令表里**逐条 opcode 的语义**：本规范只规定与操作数访问、池、值、引擎标量表相关的行为；其余 opcode 的行为不在本版断言。
- 平台 API（Win32 / D3D 等）的实现细节。

**本版没有提到的行为不等于"引擎没有该行为"**。未覆盖的领域要么另有规范，要么尚未成篇。

### 规范用语

- **必须**：实现不满足即不符合本规范。
- **应当**：除非有明确理由，否则应满足。
- **可以**：实现可自行选择。
- **未规定**：本版不作断言。

### 基本术语

- **引擎**：执行脚本、维护池与帧状态的运行时。
- **脚本**：一段按顺序排列的指令序列，是引擎执行的基本单位。
- **指令**：一个 opcode 加零个或多个**操作数**。
- **操作数**：一个**类型标签**加一个 **raw** 值；类型标签决定访问方式，raw 是该方式的操作数（通常是一个下标或立即值）。
- **帧**：一次脚本执行的上下文；局部池属于当前帧。
- **池**：一组可按整数下标访问的**槽**；槽里装一个值或一个地址。
- **值**：池槽或操作数所表示的整数、浮点数或字符串。
- **引用**：槽里装的是另一处地址；读取/写入要经过一次解引用。
- **AGE 汇编格式**：`age-format` 包里的现有实现；它仿照第三方库写成，**不是本规范的来源**。

### 表示约定

- 多字节整数按小端解释；未特别说明时，"整数"指 32 位位模式。
- "浮点数"指 IEEE-754 binary32。
- 字符串是字节序列；本规范只规定引擎如何**解释**文本（例如按十进制解析），不规定存储编码的码页。
- "下标"从 0 开始。
- "地址"是实现内部的引用。本规范只规定"槽里装地址 / 解引用"的关系，不规定地址的数值，也不规定池在内存中的位置。

### 与现有实现（`age-format`）的关系

本规范是**协议与运行期语义的定义**；`age-format` 是现有实现，不是规范的来源。

| | 现有实现（`age-format`） | 本规范 |
|---|---|---|
| 地位 | 实现（仿照第三方库写成） | 规范（定义协议与运行期语义） |
| 内容 | 脚本头 / 指令表 / 操作数编码 / 反汇编与重汇编的代码与数据 | 脚本二进制协议、执行模型、池、值、引擎标量表 |
| 依赖方向 | 实现应当向本规范对齐 | **不依赖实现**：正文与 `format/opcode-table.json` 自包含 |

★ 本规范**不引用** `age-format` 的源码位置 / 版本 / 构建方式；读者不需要它。实现里的 `instruction-set.json` 是实现副本，可能与本规范漂——以本规范为准，但本规范的协议部分当前**待核验**（见「脚本与执行」）。

### 规范与实现的关系

本规范只描述外部可观察行为；平台 API 的实现细节不在本规范。实现可以自由选择内存布局；本规范用"池 / 槽 / 帧"等术语描述逻辑结构，不要求与任何具体偏移一致。

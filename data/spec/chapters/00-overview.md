## 总览与约定

本规范描述《天結いキャッスルマイスター》引擎在执行脚本时对外可观察的领域行为：脚本怎样编码、引擎维护哪些状态、操作数怎样访问数据池、值怎样表示。

它面向**独立实现者**：读者不需要原二进制、反汇编或本仓的复核材料。它自带**伴随数据**（脚本指令表与配置键表，见「脚本与执行」「配置」）。

### 本版覆盖

- **脚本二进制协议**：脚本头、指令编码、操作数编码、指令表（伴随数据）。
- **执行模型**：帧栈（帧记录 / 当前帧 / 父帧链 / 分配与释放）、一次迭代的步骤、门与状态选择位；逐条控制转移（调用 / 返回 / 跳转 / 换脚本 / 结束 / 重置）见「帧类指令」。
- **ALF 归档**：索引头、段、LZSS、TOC 与载荷定位。
- **AGF 图像**：ACGF 容器、meta/body 段、可选 ACIF alpha、像素排布。
- **数据池**：全局池与局部池的族、槽、下标、访问原语、类型标签、支持集合、值编码、字符串记录、容量与越界。
- **引擎级状态**：引擎级按索引写的标量表（见「引擎级状态」）。**状态选择字与位规则**不在这一章，见「执行与时间」。
- **配置**：库、发行默认表、玩家文件、保存、脚本访问（键表见伴随数据）。
- **各指令族章**：逐 opcode 的引擎数据效果 —— 已写成的 opcode 见各指令族章章首的族清单与计数，以及「引擎级状态」「配置」各条点名的 opcode；未列出的 opcode 本版不作断言。
- **执行与时间**：一次迭代、门、状态位、时钟、计时窗。
- **启动期平台请求**：窗口类、窗口创建、输入法解绑 / 菜单、图形设备、消息泵、定时器（见「启动期的平台请求」）。
- **渲染请求边界**：渲染目标、场景混合、离屏文字（见「渲染请求边界」）。

数据池是**一个完整主题**：族、下标、访问、值表示、容量放在同一章，不再按"池 / 操作数 / 值"拆散。

### 本版不覆盖

- 输入的**采样形态**（键鼠 / 手柄 / 事件）：本版只登记 `0x101` 的形态（采样并丢弃、清状态选择字里的**一个位**（位号未取证）、写两个引擎级标量 A / B）；它对引擎数据的**完整效果本版不规定**（见「等待、输入、影片与空操作」）。
- 表现**结果**（平台请求是否受理、像素与声音如何）、对象模型、存档、**文件装载的调度 / 搜索路径**。★ 引擎对请求返回值的**使用**（成功 / 失败分支）属于请求边界章；本项排除的是平台侧的受理结果与表现结果。
- 容器的完整语义：本版只写容器句柄的类型标签、懒分配与读写行为；容器对象的其余语义（其余字段的用途、哪些操作用容器、注册表的消费者）不在本版。
- 平台 API（Win32 / D3D 等）的实现细节：本版只在「启动期的平台请求」「渲染请求边界」里把 API 名与请求参数当作**边界契约**引用，不解释其内部结构。
- **尚未成篇的 opcode**：本版不对它们的行为作断言（各指令族章章首逐族列出已写成的范围）。

**本版没有提到的行为不等于"引擎没有该行为"**。未覆盖的领域要么另有规范，要么尚未成篇。

### 规范用语

- **必须**：实现不满足即不符合本规范。
- **应当**：除非有明确理由，否则应满足。
- **可以**：实现可自行选择。
- **未规定**：本版不作断言（实现可以任选，不构成合同）。
- **未定义行为**：本版同样不作语义断言，但**要求实现把它记为诊断**；⛔ 不许替引擎 clamp、补 0 或跳过——那会让"越界"看起来像一条语义。
- **机器细节** / **实现细节**（同义）：本版**不规定其取值**的**引擎内存侧**内容（对象布局、内部的偏移与容量、通道映射等）；实现可以自选，但不得改变本版规定的可观察行为。
  ★ **文件协议的字段偏移不是机器细节**：容器头 / TOC / meta 的字段位置属于本版要定义的协议（见「ALF 归档」「AGF 图像」）。
  ★ **两条内存侧的量是合同、不属于本条**：数组地址算术里的**元素宽度**（整型 / 浮点 / 引用 / 指针 4 字节、字符串记录 28 字节，见「数据池」的「数组地址算术」）与字符串记录的**内联判别阈值**（见「数据池」的「字符串记录」）。实现必须照这两个量算地址与判内联；记录内部字段的布局与容量字段宽度仍属机器细节。
  ★ **行为里的硬上限也不是机器细节**：玩家配置文件**一行最多 255 字节**及其切分（见「配置」的「玩家配置文件」）是合同。

### 基本术语

- **引擎**：执行脚本、维护池与帧状态的运行时。
- **脚本**：一段按顺序排列的指令序列，是引擎执行的基本单位。
- **指令**：一个 opcode 加零个或多个**操作数**。
- **操作数**：一个**类型标签**加一个 **raw** 值；类型标签决定访问方式，raw 的形态由类型标签决定（见「数据池」的「操作数类型标签」）。
- **帧**：一次脚本执行的上下文；局部池属于当前帧。
- **帧记录**：帧在引擎内部的表示：局部池的计数与基址、父帧号、代码区起点与指令指针、长度槽、位置等。本版只规定这些字段的**行为**，不规定它们的布局。
- **操作数组数（`argc`）**：一条指令在脚本里携带的 `(type, raw)` 组数；决定指令占多少字节。
- **长度槽**：帧记录里记本条指令推进量的那一格。**直线指令**把它写成 `2 × argc + 1`；**控制转移指令**按各指令族章自己的规定写（0 表示不自动推进）。本规范里**"推进格数"**与它同义。
- **代码区**：脚本里指令字节所在的那一段；**代码区起点**是它的第一个 32 位字。位置、指令指针都以代码区起点为基。
- **池**：一组可按整数下标访问的**槽**；槽里装一个值或一个地址。（**格**是同义词。）
- **值**：池槽或操作数所表示的整数、浮点数或字符串。
- **引用**：槽里装的是另一处地址；读取/写入要经过一次解引用。
- **场景**：一批可绘制条目（绘制项 / 网格）、它们的键表、几个标记位，外加两个时间戳。本版用它说明绘制与动画挂在谁身上；场景如何创建与切换不在本版。
- **纹理槽 / 对象槽**：纹理表 / 对象表里由整数下标定位的一格；槽里装对象引用。
- **释放守卫**：每条纹理记录自带的一个计数；非 0 时释放指令**不清**纹理记录与纹理槽（只清对象槽）。本作里（观察）：它没有写入点，恒为 0。
- **空白创建**：纹理记录上的一个**独立写入位**，表示这条纹理是运行时新建的、不是从文件加载的；它**不是**"来源文件 == 无"的派生谓词（`0x1fa` 会把来源写成无而不改这一位），也不保证像素被清零（初始像素内容未定义）。
- **状态选择字**：一个 32 位字，位号从 0 起；某位置起表示"该位有工作待服务"。整字为 0 才执行指令（见「执行与时间」）。
- **列表项（记录）**：引擎里按"列表组号"取的一条记录（若干字段对 + 若干标记）；绘制与文本请求按它取。
- **组号**：本规范里有两个命名空间共用这个词 —— 语音组（`0..2`）与列表组；按上下文区分，不混用。
- **默认组**：列表组号为 0 时被替换成的那一组。它是一个引擎级选择子，**初值为 1**（子系统建立时写入），由 `0x80` 改写（见「列表项与子系统写入」的「设默认组」）。
- **子对象**：引擎对象里按固定字段挂着的子系统对象（文本 / 消息 / 声音等）。
- **无颜色**：颜色字段的哨兵值，表示"没有当前颜色"（具体数值属机器细节，本版不规定；依赖它的颜色规则因此只到形态，或写成「本版不规定」，见「场景 / 颜色族」）。
- **当前颜色 / 终色**：条目的当前颜色与颜色渐变窗的目标颜色。窗**不另存**"起色"：每一步插值时的起色就是该项**当前颜色字段在该步的值**；排窗本身不改当前颜色（见「场景 / 颜色族」）。
- **窗的派生色**：由当前颜色、终色、窗字段与该步时钟派生出的颜色，**不是**独立记录字段，也不写回当前颜色。绘制项无窗 / 延迟内 / 有窗但未推进时取当前颜色，推进中取插值，到期取终色；网格无窗时取顶点缓冲现状，窗推进时按派生色重烘（派生色落在「无颜色」时是否重烘，本版不规定，见「场景计时窗」的残差）。
- **脏标记**：场景被改动过的标记；本版只规定谁置它，不规定谁读。
- **输入字**：一次输入采样的结果存放处。
- **声音后端**：平台侧的声音接口，分"存在 / 不存在"两态。
- **错误通道 / 场景错误缓冲**：引擎把一条错误文本写进场景并上报出去的路径（与异常不同：它**不中止本条**）。本版规定触发条件；文本内容在已取证处给出，未取证处明确写"本版不规定"。缓冲的具体位置、显示方式与显示对象不在本版。
- **统一文件 id**：脚本用来指名字脚本 / 根脚本的整数标识（`0` 是根脚本）。纹理 `0x1f9` 的"文件号"也使用这同一编号空间；影片的资源 id 是否同一空间另见影片条。
- **词表**：**命名键**认可的全部键及其类型（见伴随数据 `format/config-keys.json`）；**运行期写入**可创建词表外的命名键（类型由写入方给出），但它们不参与玩家文件装载 / 保存；脚本键不走词表。
- **AGE 汇编格式（ASM）**：脚本的二进制协议本身（本版「脚本与执行」的主题）。

### 表示约定

- 多字节整数按小端解释；未特别说明时，"整数"指 32 位位模式。
- "浮点数"指 IEEE-754 binary32。
- 字符串是字节序列；本规范只规定引擎如何**解释**文本（例如按十进制解析），不规定存储编码的码页。
- "下标"从 0 开始。
- "地址"是实现内部的引用。本规范只规定"槽里装地址 / 解引用"的关系，不规定地址的数值，也不规定池在内存中的位置。

### 协议自持

本规范是**协议与运行期语义的定义**：正文与伴随数据自包含（脚本二进制协议、执行模型、池、值、引擎标量表），读者不需要任何实现的代码或数据。本规范也不引用任何实现的源码位置、版本或构建方式；协议部分当前的核验状态见「脚本与执行」。

### 规范与实现的关系

本规范只描述外部可观察行为；平台 API 的实现细节不在本规范。实现可以自由选择内存布局；本规范用"池 / 槽 / 帧"等术语描述逻辑结构，不要求与任何具体偏移一致。

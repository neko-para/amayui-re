## 对象模型：根对象 / 类行为表 / 类型身份 / 对象槽表

本章 5 条规则。

### 根对象：唯一实例、构造与发布

<!-- rule: CORE-OBJECTS-ROOT -->

引擎在启动期创建**一个**根对象，且在销毁前保持整个进程只有一个。根对象是引擎运行期状态的容器：
它拥有的子对象，其存储**是根对象存储的一部分** —— 随根对象一起构造、一起销毁，不单独发布，
也不会比根对象活得长。

根对象构造完成后立即被发布到**一个进程级全局槽**。引擎其余部分要拿根对象时都从这个槽取。
根对象被销毁时该槽被清空；此后从该槽取到的是"空"。

根对象自己的类只贡献**如何销毁**这一项行为；它的可观察功能来自它拥有的子对象，而不是它自己的方法。

退出流程**不专门扫槽表、也不逐槽销毁对象**：根析构器与退出段都没有引用槽表基址；退出前仍被占用的槽，
其对象不经行为表销毁，随进程一起结束。整表只在根对象构造时清零一次，此后只有释放路径逐格清空。
★ 这一条只说退出流程本身不逐槽销毁；⛔ 不得据此断言别处一定没有销毁这些对象的路径。

**上下文与条件**

- 创建与销毁都发生在启动 / 退出流程中：早于任何脚本执行、晚于所有脚本结束。具体时序由启动章规定。
- "按值内嵌"是可观察约束：子对象的存储由根对象的存储承载；子对象的构造在根对象构造器体内进行。
- 根对象存储的大小、子对象的数量与排列顺序属**机器细节**（见"状态对应"里的存储指针），
  不进本规范的行为条款；本条只规定"子对象的存储由根对象的存储承载、随它一起构造与销毁"。
- 全局槽的地址属**机器细节**，不进本规范的行为条款；本条只规定"发布一次、销毁时清空"。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 根对象（唯一实例） | 根对象的一整块存储（属机器细节）；启动期一次分配 + 一次构造产生 |
| 根对象发布的进程级全局槽 | 一个数据段指针格（地址属机器细节） |
| 根对象拥有的子对象 | 根对象内嵌的子对象（具体数量与排布属机器细节） |

### 对象前缀：类行为表与输出对象

<!-- rule: CORE-OBJECTS-BASE -->

由基类构造器建立的每个引擎对象都以**两个指针**开头：

1. 第一个指向它所属类的**行为表**；
2. 第二个指向引擎里**唯一**的**输出对象** —— 那是进程级的一个静态对象，不是每个实例新建的。

基类构造器负责写这两个指针。每个子类构造器**先调用基类构造器**，然后把自己的行为表指针覆盖上去。
所以"子类对象在偏移 0 处就是基类对象"，`this` 不需要调整。

基类提供三项可观察操作，它们都**作用于那个输出对象**、不改变对象自己的状态：

- **追加一段文本**：把这段字节原样交给输出对象，由它写进自己持有的日志落点；
- **按脚本位置追加文本**：若当时存在"当前脚本位置"，先写一个**位置前缀**（形如 `(<脚本名>：<行号>行目) `；脚本名与行号的取值来自脚本运行位置，其来源本版**未取证**，见残差 `RES-OBJ-LOG-PREFIX`）再追加；否则与"追加一段文本"相同；
- **报告**：先向日志落点依次写入 `\r\n致命的エラー[`、这段文本、`]\r\n`，再把这段文本交给根对象的一个错误处理入口（该入口还接收一个窗口句柄）。

输出对象的行为表有三项：**删除式析构**、以及**两个报告入口**。两个报告入口都是**致命错误报告**：
先向日志落点写入 `\r\n致命的エラー[` + 文本 + `]\r\n`，再把文本交给根对象的两个错误处理之一 ——
一个接收"窗口句柄 + 文本"，另一个接收"两个整数 + 文本"。基类操作只用到"窗口句柄"那一项。

输出对象的存储是**静态的**：它在启动期被构造、在退出期被销毁，不属于根对象，也不随任何单个对象存亡。

**上下文与条件**

- 对象前缀由基类构造器建立；绕过构造器造出来的对象、以及构造器不调用基类构造器的类，**不满足**本条。
  （本版只对 26 个调用基类构造器的类声明；其余类的对象模型不属本条。）
- **同形不同义**：不调用基类构造器的类也可能在对象开头放两个指针大小的值 —— 例如调试输出类把第二个值
  写成"未打开的句柄"哨兵；那不是"输出对象引用"，语义由各自的类决定，⛔ 不得据前缀形状把对象判进本条。
- 输出对象只有一个，所有对象共享；它的构造 / 销毁时机属启动 / 退出流程。
- 三项操作的**外部效果**是边界行为：本条规定"文本落到输出对象、由它写进自己的日志落点；
  报告一项还把文本交给根对象的错误处理"。日志的**文本组成**（固定分隔行与脚本位置前缀）属本条；
  落盘时机、缓冲与平台是否受理属**平台侧行为**（写失败不改变引擎的状态）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 对象前缀·类行为表引用 | 对象的类行为表引用（属机器细节） |
| 对象前缀·输出对象引用 | 对象的输出对象引用（属机器细节） |
| 输出对象（进程级静态） | 一段静态存储（大小属机器细节） |
| 输出对象的行为表 | 三项：删除式析构、两个致命错误报告入口（"窗口句柄 + 文本"与"两个整数 + 文本"） |
| 日志行的文本组成 | 追加：文本原样；按位置追加：`(<脚本名>：<行号>行目) ` 前缀 + 文本；报告：`\r\n致命的エラー[` + 文本 + `]\r\n`，随后把文本交给根对象的错误处理 |

### 类的可观察身份

<!-- rule: CORE-OBJECTS-TYPE-IDENTITY -->

引擎对象在运行期**没有类型编号**：对象存储里不存类名、类 ID、也不存任何类型标记。

类与类的差别只体现为对象开头那个**行为表指针**。行为表的**内容由类决定**：
根对象、基类前缀、场景子对象、以及槽里的对象，其行为表只有一项 —— **如何销毁该对象**；
另一些类（绘制 / 纹理 / 渲染等）的行为表有自己的多项行为。

但无论如何，引擎**不在运行期检验一个对象的类**：它不读类型标记、也不对引擎对象做运行期类型转换。
调用点**静态地**知道对象是什么类，行为表只用来选"该调哪个实现"。

因此"这个对象是什么类"在引擎的可观察行为里只表现为：**哪一个行为表的哪一项被执行**。
类名与继承关系保存在二进制的类型元数据里，但引擎自身的对象模型**不**把它当作运行期状态。

**上下文与条件**

- 适用于引擎自己创建并管理的对象。外部中间件对象的类型检验发生在中间件内部，不属本条。
- "行为表内容由类决定"是可证伪的断言：同一类的两个实例必须写同一张表；
  而"某个类只有销毁一项"只对**逐张核过**的那些类成立（见残差），⛔ 不许把"只有一项"推广到所有类。
- 全语料里唯一的运行期 `typeid` / `dynamic_cast` 落在渲染中间件（Live2D）里，作用于中间件自己的对象。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 对象的类 | 对象的类行为表引用（属机器细节）：对象第一个字指向它的类行为表 |
| 类行为表的表项 | 每项是该类的一个行为（根 / 基类 / 场景 / 槽对象：唯一一项 = 删除式析构函数） |
| 继承关系 | 类型元数据里的基类数组（运行期不被引擎读取） |

### 对象槽表：容量、编号、无检查

<!-- rule: CORE-OBJECTS-SLOT-TABLE -->

引擎有一张**对象槽表**：**1000 个槽**，编号 **0 … 999**。

- 每个槽要么是**空**（没有对象），要么装**一个对象引用**；一个槽最多装一个对象。
- **槽号由执行中的指令给出**（哪条指令给哪个号是游戏数据的事，不在本条）。
- 表在根对象构造时**整表清零**（1000 个槽全部为空），此后由创建 / 释放操作改变个别槽。
- 引擎对**指令给出的槽号不做任何范围检查**：直接用槽号算表项地址。
  因此槽号越界（小于 0 或大于 999）是**未定义行为** —— 不是"静默忽略"，也不是"抛异常"。
- 引擎自己的**整表遍历**（主循环与若干统计 / 清理路径）以 1000 为界逐个访问。
  那是**遍历**的界，不是对指令槽号的检查；两者不得混为一谈。

**上下文与条件**

- 编号从 0 起；"空"由空引用表示，不是另一个标志位。
- 容量 1000 是引擎常量，不从配置或脚本读入。
- 越界是未定义行为：实现应记诊断或响亮失败；⛔ 不得 clamp 到表内、⛔ 不得补 0 后继续、⛔ 不得静默跳过。
- 槽号是 32 位整数：负值同样是越界。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 对象槽表（1000 槽） | 对象槽表（1000 槽；元素宽度属机器细节） |
| 空槽 | 表项 = 0 |
| 占用槽 | 表项 = 对象引用 |

### 槽的占用与释放

<!-- rule: CORE-OBJECTS-SLOT-LIFECYCLE -->

槽只有两种状态：**空**与**占用**。状态转换由引擎操作驱动：

- **创建类操作**：目标槽为空时，引擎创建一个对象、把对象引用写进槽（空 → 占用）；
  该槽**已占用**时，引擎**复用**槽里现有的对象，**不再新建**（一个槽任何时刻最多一个对象）。
- **换用 / 释放**：同一个槽要被另一种资源使用时，引擎先对槽里的对象做一次固定清理，
  再**通过该对象的行为表销毁它**（带删除标志），最后把槽写回空（占用 → 空）。
  槽清空之后，引擎还以**同一个槽号**清掉**纹理表**里的对应项（见「一场释放，两个归属」）。
  新路径自己建立它需要的东西，本条不描述。
- **主循环扫描**：引擎按槽号顺序遍历整表。空槽跳过；占用槽在正常迭代里被"逐对象推进"一次。
  该槽的**逐对象计时**判定为"已完成"时进入**清理**（判定见「影片对象表的服务」）：引擎先对该对象做一次**收尾** ——
  收尾是**场景侧的一次固定调用**（把槽号交给场景的清理例程），**不是**对象行为表里的一项（影片对象的收尾请求见「影片对象表的服务」，其像素效果见残差 `RES-MOVIE-FILL`）——
  随后**销毁**对象并把槽清空；
  对象状态字的**低两位等于 2** 时**跳过收尾**、直接销毁并清槽 —— 两条清理分支**最终都销毁**（区别只在"是否先收尾"）。
- **一场释放，两个归属**：一个槽号同时索引**对象表**（即「对象槽表：容量、编号、无检查」那 1000 槽的表，槽号到对象的表）与**纹理表**（同一槽号空间里的纹理对象表）。释放路径先清对象表，
  再按同一槽号清纹理表；场景那一步有一个门：该槽号在**释放守卫**（一张从不被写入的门控表 ⇒ 这个门在引擎里**恒成立**）里为"非零"时跳过这次清。
  两张表里的对象**不是同一个**（槽对象与纹理对象各自销毁、各自清格）。
- 任何"占用 → 空"之后，该对象不再被引擎访问；读空槽得到"没有对象"，**不是**错误。
- 对象的销毁责任属于槽表：销毁由释放路径触发，不是由对象自己决定。

**上下文与条件**

- "创建类操作"与"换用 / 释放"是**两类不同的消费者**：本条只规定槽状态怎么变；
  消费者怎么用槽里的对象属指令语义（见 `CORE-OPS`）。
- "固定清理"是一次非虚调用，发生在销毁**之前**；它**不是**对象行为表里的一项，而是**场景侧的一次固定调用**（把槽号交给场景的清理例程）。
- "销毁"是虚调用（经行为表第 1 项），所以不同类可以有不同的析构实现。
- 清理路径里"对象状态字的低两位 = 2 ⇒ 跳过收尾"：本条只规定**存在这个判定**与它的两种后果（收尾后销毁 / 直接销毁）；
  该状态字的位语义与写入者**本版未取证**（见残差）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 空 ↔ 占用 | 对象槽表的对应表项（属机器细节） |
| 对象的销毁 | 对象行为表第 1 项（删除式析构；对象的类行为表引用（属机器细节）） |

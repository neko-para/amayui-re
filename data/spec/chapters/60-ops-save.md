## 存档槽的读写与文件级操作

本章 3 条规则 / 7 个 opcode。

### 存档槽的读取：opcode 0x1a0

<!-- rule: CORE-OPS-SAVE-READ -->

`0x1a0` 有**九个**操作数。把第 2 个读成整数 = **槽号**；用引擎的存档目录拼出该槽的存档文件名（`SAVE` + 至少两位十进制槽号 + `.DAT`），以**只读**打开：

- 打不开 ⇒ 第 1 个操作数 ← **1**，本条结束（没有合法句柄，不关闭）；
- 打开后读**存档头**（只读头，不读负载）：
  - 头合法 ⇒ **七个整数**依次写进第 3..9 个操作数，第 1 个操作数 ← **0**；
  - 头不合法（含读不满 292 字节）⇒ 第 1 个操作数 ← **2**（第 3..9 个操作数保持原值）；
- 打开成功的支路最后都关闭文件。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 存档槽号 | 第 2 个操作数（十进制，`%2.2d`） |
| 读出的七个字段 | 第 3..9 个操作数 ← 存档头里的七个整数 |
| 读取结果 | 第 1 个操作数 ← 0（成功）/ 1（打不开）/ 2（头不合法，含读不满 292 字节） |

**成立条件**

- **三种结果是三个值、不是两个**：把「头不合法」并进「失败」会让脚本无法区分「没有这个槽」与「槽坏了」。
- 第 1 个操作数**总是**被写（三条路径都写）。
- **失败的两条支路只写第 1 个操作数**：打不开 / 头不合法时第 3..9 个操作数**保持原值**（七个字段只在读成功后写）。
- 「头合法」的判据（**读满 292 字节** + 魔数与标题校验）见「存档」章的 `FMT-SAVE-HEADER`；本条只区分两种读取结果。
- 读成功时的七个整数是存档头里的字段，**它们的含义、顺序与宽度**见「存档」章的 `FMT-SAVE-HEADER-FIELDS`；本条只规定「搬进第 3..9 个操作数」。
- 槽号是**至少两位十进制**（更长的槽号照写、负号保留；见「存档」章）。
- 打开是只读（不创建、不截断）：文件不存在不是「创建空档」。
- 七个字段的写入顺序是第 3 → 第 9（次序是合同的一部分）。

### 存档槽的写入与读回：opcode 0x19e / 0x1a1

<!-- rule: CORE-OPS-SAVE-WRITE -->

两条都针对同一个存档文件（`SAVE` + 至少两位十进制槽号 + `.DAT`，槽号 = 第 2 个操作数），但**方向相反**：`0x19e` 写、`0x1a1` 读回。

- `0x19e`（**带覆写确认**）：目标已存在时，先用「存档格式读」试读一次；读不回来就向宿主弹一次**确认**；用户不同意覆写 ⇒ 第 1 个操作数 ← **1** 并结束。同意（或目标不存在 / 能读回）⇒ 以写方式打开并写，第 1 个操作数 ← 写入入口的返回值。
- `0x1a1`（**无确认的读回**）：以**只读 + 只打开已存在**的方式打开该槽的 `.DAT`；打不开 ⇒ 第 1 个操作数 ← **1** 并结束；能打开 ⇒ 读头 + 读负载（版本门 / 校验 / 解密 / 内层见「存档信封」），**读完之后**把**全局整型池**的全部槽（**计数格 + 1 格**）按引擎的编码 key **逐个重新编码**一遍（读档把整池就地解码过 ⇒ 这一步是补偿）。★ **成功路径不写第 1 个操作数**（只有"打不开"那一支写 1）——这与 `0x19f` 把读档结果写进第 1 个操作数是两条不同的合同。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该槽的存档文件 | `0x19e`：以写方式建立 / 截断并写入；`0x1a1`：只读打开并读回 |
| 第 1 个操作数 | `0x19e` ← 写入结果（另有「用户拒绝」= 1）；`0x1a1` 只在打不开时 ← 1 |
| 全局整型池 | `0x1a1` 在**读完之后**整池重编码（计数格 + 1 格） |

**成立条件**

- **确认只发生在「已存在且读不回来」时**：目标不存在、或目标能正常读回时都**不弹**。⛔ 不许把确认做成「只要已存在就弹」。
- 两条的**方向与分支都不同**：`0x19e` 写（有「用户拒绝」这一支），`0x1a1` 读回（只有"打不开"这一支写 1）。⛔ 不许合并成一条带开关的实现。
- `0x1a1` 的**池重编码是本条的一部分**，不是「帧刷新 / 定时器」：它发生在关闭文件之后、本条返回之前。
- 重编码的**范围**是计数格 + 1 格（不是「到容量上限」）。
- 两条都改第 1、2 个操作数与槽文件（以及 `0x1a1` 的整池）；主数据写成功后还可能重写系统数据文件（见「存档」章）。

### 存档槽的文件级操作：opcode 0x1ab / 0x1ac / 0x1ae / 0x1af

<!-- rule: CORE-OPS-SAVE-FILES -->

四条都不读写存档主体（`.DAT`）的内容：删除 / 拷贝只做文件级动作，缩略图写 / 读只碰 `.STH`（容器由引擎自己组装 / 解析，见「存档」章）。**状态写在第 1 个操作数**：
删除 / 拷贝是**两个文件**（顺序：先 `.DAT` 后 `.STH`）——`0` 两个都成功 / `1` 第二个成功而第一个失败 / `2` 第二个失败（不论第一个成没成；后一步覆盖前一步）；
缩略图写 / 读是**单个 `.STH`**——`0` 成功 / `1` 打开失败 / `2` 写（读）失败。

- `0x1ab`（2 个操作数，**删除**）：删该槽的 `.DAT` 与 `.STH`。
- `0x1ac`（3 个操作数，**拷贝**）：把第 2 个操作数的槽拷到第 3 个操作数的槽（`.DAT` 与 `.STH` 各一次）。
- `0x1ae`（3 个操作数，**写缩略图文件** `.STH`）：槽号 = 第 2 个，第 3 个是**被捕捉的图像对象**编号 ——
  引擎把该对象当前的画面组装成 BMP 并写盘（容器与像素布局见「存档」章的 `FMT-SAVE-STH`）。
- `0x1af`（3 个操作数，**读缩略图文件** `.STH`）：槽号 = 第 2 个，第 3 个是**装载结果落的图像 / 表面对象**编号 ——
  引擎把刚打开的文件交给图像装载器（或自己的 BMP 读取例程），由它按文件开头的字节分派格式并重建该对象；
  目标按**表面编号**的那条实现里，0 / 1 / 2 被拒（见下：不读文件内容、写错误通道、状态 2）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该槽的 `.DAT` / `.STH` | 按四条各自的动作删除 / 拷贝 / 写 / 读 |
| 动作结果 | 第 1 个操作数 ← 0 / 1 / 2（删除 / 拷贝按两个文件；缩略图按单文件） |

**成立条件**

- **两个文件都总是尝试**：第一个失败**不返回**，照旧处理第二个（`0x1ab` 删 `.STH`、`0x1ac` 拷 `.STH`）。
  ⛔ 不许在第一个失败处提前返回 —— 那会漏掉第二个文件，并把状态停在 `1`。
- **后一步覆盖前一步**：第二个失败 ⇒ `2`（不论第一个成没成）；否则第一个失败 ⇒ `1`；否则 `0`。
  ⛔ 不许把「两个都失败」归成 `1`，也不许把这两个值按严重程度重排。
- **缩略图的两条失败路径都走错误通道、都以 `2` 结束**：
  - `0x1ae`：文件在**捕捉之前**就以截断方式建立；捕捉（分配 / 表面锁定 / 读表面）或写盘失败时，
    引擎把原因写进错误通道、关闭文件，**不删除**它 ⇒ 槽目录里留下一个空 / 半截的 `.STH`。
  - `0x1af`：第 3 个操作数在「目标按表面编号」的实现上是**表面选择**：**0 / 1 / 2 被拒**
    （其余值继续；负数按无符号位模式不等于这三个值 ⇒ 落在接受侧）。被拒时引擎**不读文件内容**，
    只把一条「表面指定无效」写进错误通道 ⇒ 状态 `2`，文件仍被关闭。
- 四条都按 `SAVE` + 至少两位十进制槽号 + `.DAT` / `.STH` 拼名；拷贝的**源是第 2 个、目标是第 3 个**。
- `0x1ac` 的拷贝**会覆盖**目标（目标已存在不报错、不弹确认）：⛔ 不许顺手加「目标存在就失败」的检查 —— 那会让「复制到一个已用槽」这条路径变成失败。
- 删除 / 拷贝碰两个文件；缩略图写 / 读只碰一个 `.STH`。
- 缩略图文件（`.STH`）与存档主体（`.DAT`）是**两个独立文件**：只写 `.DAT` 不会写 `.STH`（见「存档槽的写入」）。
- 缩略图的字节是**引擎组装的**，不是平台的捕捉结果原样转存；读侧不按扩展名判断，而按文件开头的字节分派格式（本作写出的都是 BMP）。
  `.STH` 的容器、头字段与像素布局见「存档」章的 `FMT-SAVE-STH`。

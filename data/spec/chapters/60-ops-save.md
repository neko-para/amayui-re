## 存档槽的读写与文件级操作

本章 3 条规则 / 7 个 opcode。

### 存档槽的读取：opcode 0x1a0

<!-- rule: CORE-OPS-SAVE-READ -->

`0x1a0` 有**九个**操作数。把第 2 个读成整数 = **槽号**；用引擎的存档目录拼出该槽的存档文件名（`SAVE` + 至少两位十进制槽号 + `.DAT`），以**只读**打开：

- 打不开 ⇒ 第 1 个操作数 ← **1**，本条结束；
- 打开后读**存档头**（只读头，不读负载）：
  - 读成功 ⇒ **七个整数**依次写进第 3..9 个操作数，第 1 个操作数 ← **0**；
  - 内容不符 ⇒ 第 1 个操作数 ← **2**；
- 无论哪一支，最后都关闭文件。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 存档槽号 | 第 2 个操作数（十进制，`%2.2d`） |
| 读出的七个字段 | 第 3..9 个操作数 ← 存档头里的七个整数 |
| 读取结果 | 第 1 个操作数 ← 0（成功）/ 1（打不开）/ 2（内容不符） |

**成立条件**

- **三种结果是三个值、不是两个**：把「内容不符」并进「失败」会让脚本无法区分「没有这个槽」与「槽坏了」。
- 第 1 个操作数**总是**被写（三条路径都写）。
- 读成功时的七个整数是存档头里的字段，**它们的含义属存档格式**（见「存档」章）；本条只规定「搬进第 3..9 个操作数」。
- 槽号是**至少两位十进制**（更长的槽号照写、负号保留；见「存档」章）。
- 打开是只读（不创建、不截断）：文件不存在不是「创建空档」。
- 七个字段的写入顺序是第 3 → 第 9（次序是合同的一部分）。

### 存档槽的写入：opcode 0x19e / 0x1a1

<!-- rule: CORE-OPS-SAVE-WRITE -->

两条都写同一个存档文件（`SAVE` + 至少两位十进制槽号 + `.DAT`，槽号 = 第 2 个操作数），但前置条件与收尾不同：

- `0x19e`（**带覆写确认**）：目标已存在时，先用「存档格式读」试读一次；读不回来就向宿主弹一次**确认**；用户不同意覆写 ⇒ 第 1 个操作数 ← **1** 并结束。同意（或目标不存在 / 能读回）⇒ 以写方式打开并写，第 1 个操作数 ← 写入入口的返回值。
- `0x1a1`（**无确认**）：直接以写方式打开并写；第 2 个操作数（槽号）→ 写盘 → 关闭；随后把**全局整型池**的全部槽（**计数格 + 1 格**）按引擎的编码 key **逐个重新编码**一遍。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该槽的存档文件 | 以写方式建立 / 截断，并写入本次存档 |
| 第 1 个操作数 | ← 写入结果（`0x19e` 另有「用户拒绝」= 1） |
| 全局整型池 | `0x1a1` 在写完之后整池重编码（计数格 + 1 格） |

**成立条件**

- **确认只发生在「已存在且读不回来」时**：目标不存在、或目标能正常读回时都**不弹**。⛔ 不许把确认做成「只要已存在就弹」。
- 两条的**分支不同**：`0x19e` 有「用户拒绝」这一支，`0x1a1` 没有。⛔ 不许合并成一条带开关的实现（拒绝路径的返回值不同）。
- `0x1a1` 的**池重编码是本条的一部分**，不是「帧刷新 / 定时器」：它发生在关闭文件之后、本条返回之前。
- 重编码的**范围**是计数格 + 1 格（不是「到容量上限」）。
- 两条都改第 1、2 个操作数与槽文件（以及 `0x1a1` 的整池）；主数据写成功后还可能重写系统数据文件（见「存档」章）。

### 存档槽的文件级操作：opcode 0x1ab / 0x1ac / 0x1ae / 0x1af

<!-- rule: CORE-OPS-SAVE-FILES -->

四条都不解析存档内容，只做文件级动作。**状态写在第 1 个操作数**：
删除 / 拷贝是**两个文件**（顺序：先 `.DAT` 后 `.STH`）——`0` 全部成功 / `1` 第一个文件失败 / `2` 第一个成功、第二个失败；
缩略图写 / 读是**单个 `.STH`**——`0` 成功 / `1` 打开失败 / `2` 写（读）失败。

- `0x1ab`（2 个操作数，**删除**）：删该槽的 `.DAT` 与 `.STH`。
- `0x1ac`（3 个操作数，**拷贝**）：把第 2 个操作数的槽拷到第 3 个操作数的槽（`.DAT` 与 `.STH` 各一次）。
- `0x1ae`（3 个操作数，**写缩略图文件** `.STH`）：槽号 = 第 2 个，数据源 = 第 3 个。
- `0x1af`（3 个操作数，**读缩略图文件** `.STH`）：槽号 = 第 2 个，数据去处 = 第 3 个。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该槽的 `.DAT` / `.STH` | 按四条各自的动作删除 / 拷贝 / 写 / 读 |
| 动作结果 | 第 1 个操作数 ← 0 / 1 / 2（删除 / 拷贝按两个文件；缩略图按单文件） |

**成立条件**

- **两个失败是不同结果**：第一个文件失败 ⇒ `1`（不再做第二个）；第一个成功而第二个失败 ⇒ `2`。⛔ 不许把两者都归成 `1` 或都归成 `2`。
- 四条都按 `SAVE` + 至少两位十进制槽号 + `.DAT` / `.STH` 拼名；拷贝的**源是第 2 个、目标是第 3 个**。
- `0x1ac` 的拷贝**会覆盖**目标（目标已存在不报错、不弹确认）：⛔ 不许顺手加「目标存在就失败」的检查 —— 那会让「复制到一个已用槽」这条路径变成失败。
- 删除 / 拷贝碰两个文件；缩略图写 / 读只碰一个 `.STH`。
- 缩略图文件（`.STH`）与存档主体（`.DAT`）是**两个独立文件**：只写 `.DAT` 不会写 `.STH`（见「存档槽的写入」）。

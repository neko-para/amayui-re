## 字符串

本章 11 条规则 / 11 个 opcode。

### 设置一个字符串：opcode 0x192

<!-- rule: CORE-OPS-TEXT-SET -->

`0x192` 有两个操作数：**第 1 个是落点**，**第 2 个是源**。它把源**按文本读出**，写进落点那个**字符串格子**。

- **落点：本版规定类型标签 5（全局字符串池）与 11（当前帧的局部字符串池）** —— 把源文本写进那条字符串记录（见「数据池」的「字符串记录」）。其余落点**本版不规定**：8 / 14（两条"按指针取记录"的路径）、`0x8005` / `0x800B`（两个容器句柄变体）（原因：这些落点的写入路径都没有逐条取证）。落点是这些之外的类型标签（含 0 / 1 立即值）⇒ **类型异常**。
- 源侧**不是五个访问原语之一**：它按源的类型标签取**文本** —— 字符串族的记录读出字节串（见「数据池」的「字符串记录」）；**内联文本**（类型标签 2）按「数据池」的「立即值与内联字符串」解码；数值型操作数先按值读出，再由本条转成**十进制文本** —— 但**符号、宽度与浮点格式本版不规定**（原因：没有逐字取证，负数 / 大数 / 浮点源的输出字节都未观察）。
- 落点格子按「数据池」的**字符串记录**写入：容量小于内联阈值时字节就存在记录内部，否则存在记录指向的堆区；长度字段是已用字节数。
- 长度槽 ← **5**（= 2 × 2 + 1）；除长度槽与落点那一格，这条指令不改变其它引擎状态。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 落点（类型 5）那一格的字符串被替换 | 全局字符串池第 i 条记录按记录口径写入字节与长度 |
| 源被读成文本 | 串池 → 字节串；内联文本 → 解码后的字节；数值 → 十进制文本（格式未规定） |

**成立条件**

- 落点**必须先按类型标签分派**，不是"一律写全局池"：同一个下标在类型 5 与类型 11 下指向两个不同的池；type 11 的槽是**当前帧**的局部字符串池。
- 类型标签 0 / 1（立即值 / 立即浮点）**不是**合法的落点 ⇒ 类型异常；"写不进去"不是"静默丢弃"。
- 内联文本的**取反**是读的一部分（见「数据池」的口径）：不做这一步会把整段文本解成乱码，而写入本身不报错。
- 源与落点可以是同一格：先读后写，读到的仍是旧值。

### 把配置里的版本号写进字符串（opcode 0x2eb）

<!-- rule: CORE-OPS-TEXT-GAMEVERSION-2EB -->

`0x2eb` 有一个操作数：**落点**。它**不读落点的当前值**，但仍按落点的类型标签与 raw 定位；写入的是第 1 个操作数。

- 读配置命名键 `set:GameVersion`，把它的值按**字符串记录**写进第 1 个操作数。落点支持 **type 5（全局字符串池）/ 11（当前帧局部字符串池）**；type 8 / 14（两条按指针取记录的引用族）本版不规定（见残差）；其余类型 ⇒ 类型异常。
- 配置键缺失 / 配置库不存在时的行为本版**不规定**（见残差）；⛔ 不许凭记忆补一个版本号。
- 推进格数 = 3；除落点与访问原语的缓存外不改其它引擎状态。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 版本号字符串 | 第 1 个操作数那一格的字符串记录 ← 配置值 |
| 配置缺失 | 本版不规定 |

**成立条件**

- 操作数的**编号**固定是 1，不是"操作数里的值"；落点的 raw 仍用于定位，只是不读它的当前值。
- 这是**配置读取**，不是文件读取；配置库由「配置」章定义。

### 十进制文本转整数（opcode 0x2ec）

<!-- rule: CORE-OPS-TEXT-ATOI-2EC -->

`0x2ec` 有两个操作数：**第 2 个是源**（按文本读出）、**第 1 个是落点**（按整型写入）。

- 源按文本读出（口径同 `0x192` 的源侧：字符串族读字节串、内联文本解码；数值型操作数先转十进制文本，格式本版不规定，见残差）。
- 文本的解析口径与引擎的十进制解析一致：忽略前导空白，读一个可选符号与连续十进制数字；遇到第一个非数字字符停止；没有数字 ⇒ 0。
- 落点走**写整型**原语（要编码）；不受支持的落点类型 ⇒ 类型异常。
- 推进格数 = 5；除落点外不改其它引擎状态。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 十进制读数的值 | 第 1 个操作数 ← 解析结果 |
| 源 | 第 2 个操作数的文本（不写） |

**成立条件**

- 溢出的行为本版不规定（见残差）；实现不得用"夹到 32 位边界"冒充合同。
- 解析只认十进制，不认 `0x` 前缀、指数或千分位。

### 画一段已排版的文本记录：opcode 0x82

<!-- rule: CORE-OPS-TEXT-SPAN -->

`0x82` 有五个操作数，读取顺序是 **5 → 4 → 3 → 2 → 1**（读序是合同）。它把一条**已经排好版的文本记录**
按某个"文本节点"画出来；记录本身由**正文追加**（排版层）与 **`0xc4` 一族**（语音记录）追加，本条只**读**它。

- 第 2 个操作数是**记录下标**，索引那条**文本记录向量**；`0 ≤ 下标 < 条数` 不成立 ⇒
  **整条静默什么都不做**（颜色不写、请求不发、不报错）。
- 第 1 个操作数是**节点槽号**（索引一个十项的节点表）；引擎**不检查** 0..9（越界是未定义读）。
- 第 3 个操作数是**标志**：位 1 = "第 4、5 个操作数是颜色"、位 3 = "允许触发语音"。
- 第 4、5 个操作数是**主色 / 副色**（24 位）；写进色格时**字节序反转**（脚本给 `0x112233`，引擎格里是 `0x332211`）。
  ★ 这两格是**借用**的：本条**返回之前**把两格写回进入本条时的值（见下面的成立条件），所以本条**不改变**字体对象的持久颜色。
- 位 3 已置且这条记录的标志位 30 已置 ⇒ 触发一次配音（记录里带着资源号与配音槽号）。
- 记录的标志里**第 2 位**决定这次绘制用哪一支字号（置起 ⇒ 用另一支；见「转发到字体对象与宿主接口的入口」）。这一位由**追加记录的那条路径**写，不由本条的操作数决定。

**记录里还有什么**（同一批取证）。一条记录 = **44 字节定长区 + 24 字节文本串 + 4 字节对齐填充 = 72 字节**。
定长区依次是：记录槽号、绘制起点两格（x / y）、段末两格（x1 / y1）、**语音资源**、两个随播放请求一起交下去的参数、
**配音槽号**、一格间距量、**标志字**。文本串是平台的**变长字符串对象**（长度 / 容量 + 内联缓冲或堆指针），
**没有固定上限**，编码是游戏码页的单字节串。填充那 4 字节**不是字段**（任何拷贝都不搬它、消费侧也不读它）。

- **文本的写者**：正文追加那几条指令（`0x6e` / `0x7d` / `0x196`）经排版层把切出的**一段**正文写进这条记录 ⇒
  记录里的文本**非空可用**，本条画的**就是这一段**。⚠ `0xc4` 一族追加的是**语音记录**：它**没有文本实参**、
  文本串恒空，本条见到它的标志位 30 就走语音支路、**不绘制**。
- **标志字的位**（写者 → 读者）：
  - **位 30 = "语音记录"**：追加语音记录时置起。本条见到它 ⇒ 触发配音、**跳过绘制**。
  - **位 29 = "续段"**：见到它就**不画这一条**、推进到下一条。
  - **位 2 = "用另一支字号"**：由**追加记录的调用方**在 flags 实参上置起 —— 振り仮名 run 与**层处于另一个模式时的
    逐字支**（见「ADV 文本」条）会置起，**主线正文 run 不置起**（位 2 = 0）。置起 ⇒ 用 B 支字号、否则 A 支
    （见「转发到字体对象与宿主接口的入口」）。
  - **位 1**：与第 3 个操作数的**位 0** 联合使用 —— 记录的位 1 已置而操作数位 0 未置 ⇒ **跳过这条的绘制**。
  - **位 0 = "新段起点"**：只在**下一条**记录上被测（本条不读自己那条的这一位）。
  - 高位由文本框的状态透传；其中"抑制"那一位在追加时被抠掉。
- **记录槽号**格：本条的绘制路径**没有观察到**读它（它属于文本层自己的账）。
- **间距量**格：**文本记录**由排版层给定；**语音记录**的追加器**根本不写**它（搬过来的是调用方的栈残留）⇒
  语音记录里这一格是**未定义**，本版不规定它的值。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 本条这次绘制用的主色 / 副色 | 两格色格 ← 字节反转后的操作数（仅当第 3 个操作数位 1），本条**返回前恢复**成进入时的值 |
| 一次"画这段记录"的请求 | 向渲染器追加绘制命令（本版只记账） |
| 一次配音触发 | 向声音后端发一次播放请求（队列未建模，见残差） |

**成立条件**

- **早退在建界上，不在颜色上**：下标越界时连颜色都不写 —— ⛔ 不许把它写成"先写颜色再判越界"。
- **颜色是借用，不是改字体**：位 1 已置时，本条把两格改成操作数、用完**在本条返回之前**写回进入时的值（两格都要写回，不是只写回主色）。⇒ 本条返回后两格颜色与进入时**逐位相同**；⛔ 不许实现成永久改色 —— 其它绘制路径的颜色来源就是这两格，残留色会改变它们画出来的颜色。★ 借用期间"这次绘制的颜色 = 操作数"这一半在下面的"画这段记录"请求里（本条只记账）。
- 排版的度量（字形宽度 / 行高）来自宿主，本版不规定；本条只规定**读了什么、写了什么、什么时候什么都做**。
- 语音记录里那格**间距量**的值未定义：实现必须给它一个**确定的**初值（不得读未初始化内存），且**不得依赖**它的取值。
- 本条**不规定排版结果**（换行 / 对齐 / 字距）—— 那些是排版层（正文追加）的活；本条只规定
  "读哪条记录、按标志决定画不画 / 用哪支字号、借用哪两格颜色（并在返回前归还）、什么时候触发配音"。

### 登记一条字体条目：opcode 0x1d2

<!-- rule: CORE-OPS-TEXT-RECORD-REGISTER-1D2 -->

`0x1d2` 有两个操作数：**1 = key**、**2 = 值**。长度槽 ← 5。

- **守卫**：**文本显示门 ≠ 0** ⇒ **整条不读操作数、不入队**（照常推进）。守卫在读操作数**之前**。
  ★ 本版只规定该格的 **0 / 最高位已置** 两个取值，判据是"**不等于 0**"（⛔ 不是逐位判最高位）。门由 `0x1bb` 写（见「ADV 文本层」的「文本显示门」）。
- 放行：读序 **2 → 1**（先值后 key），向字体对象的**文本记录表**（= 「画一段已排版的文本记录」索引的**同一条**记录向量）尾追加一条记录：
  **列表号** = 默认列表号（**取值与写者本版不规定**，见残差；绘制路径不读它）、**值** = 第 2 个操作数、
  **key** = 第 1 个操作数、**标志** = **第 29 位（续段）**置起 +（该记录下标的**脏槽**非 0 ? **第 0 位（新段起点）** : 0），
  并**清该下标的脏槽**。
  - **脏槽是按记录下标**的一格（不是记录里的字段）；本版只规定"非 0 ⇒ 置第 0 位、并清 0"。
  - 本条写的**值 / key** 就是那条记录向量里"随播放请求一起交下去的两个参数"那两格（见「画一段已排版的文本记录」的字段表）。
- 本条**不写任何操作数**、不发外部请求、不改画布 / 绘制项；也不**触发绘制** ——
  它写的记录**第 29 位已置**，所以「画一段已排版的文本记录」见到会**跳过**；这些记录真正的读者见残差。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 文本记录表尾 +1 | 那条记录向量长度 +1（列表号 / 值 / key / 标志见上） |
| 该记录下标的脏槽 | ← 0 |

**成立条件**

- 守卫在**读操作数之前**：文本显示门 ≠ 0 ⇒ 不读操作数、不入队、**不抛**（操作数类型再坏也一样）。
- 两次读按 **2 → 1**：第 2 个读取抛异常时，第 1 个**还没被读**。
- 入队这一支**不写操作数**、不发请求、不改画布与绘制项。

**残差**

- `RES-TEXT-RECORD-REGISTER-CONSUMER`（unknown）：入队后谁消费（布局提交 / 绘制）与"默认列表号"的取值和写者。
  下一步：枚举记录表的读者（布局提交那一段）与默认列表号的写入点。
- `RES-TEXT-RECORD-REGISTER-DIRTY`（unknown）：脏槽的写者（谁把某下标标脏）与"第 0 位（新段起点）"的领域含义。
  下一步：读记录下标脏槽的写点。

**可证伪**

- 文本显示门 ≠ 0 时若仍入队、仍读操作数、或对坏类型的操作数**抛异常** ⇒ 本条错（守卫在读之后）。
- 写入的标志里"第 29 位（续段）"没有置起 ⇒ 本条错；脏槽非 0 时"第 0 位"没有置起（或没有清脏槽）⇒ 本条错。

### 按 key 查字体条目：opcode 0x1d3

<!-- rule: CORE-OPS-TEXT-RECORD-QUERY-1D3 -->

`0x1d3` 有五个操作数：**1 = 命中标志（写）**、**2 = 值（写）**、**3 = 读而不用**、**4 = 起始下标**、**5 = key**。长度槽 ← 11。

- 读序 **5 → 4 → 3**：第 3 个的值**被丢弃**，但**照样按整型读**（类型非法要报错）——⛔ 不许跳过不读。
- **查询**：起始下标 < 0 或 ≥ 记录数 ⇒ **未命中**。否则从起始下标起**顺扫**：
  - **命中判据** = 记录的**第 29 位（续段）**已置 **且** key 相等；命中 ⇒ 值 ← 该记录的值。
    ★ **命中不中断扫描**：同组里**后命中的覆盖前面的** ⇒ 取**最后一条**。
  - **组边界**：**下一条**记录的**第 0 位（新段起点）**已置 ⇒ 断组、停止扫描。
    组边界在命中测试**之后**判 ⇒ **本组最后一条**（断组点的前一条）自己的命中**保留**。
- 写：第 1 个 ← **命中 ? 1 : 0**、第 2 个 ← 值（**未命中写 0**，⛔ 不是 −1）。
- 本条不写记录、不发请求、不改画布；字体对象不变。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 命中标志 | 第 1 个操作数格 ← 1 / 0 |
| 值 | 第 2 个操作数格 ← 命中记录的值 / 0（未命中） |

**成立条件**

- 第 3 个操作数**必须读**（值丢弃、类型异常要抛）；它先于两次写。
- **两次写按第 1 个再第 2 个**：第 1 个写入抛异常时第 2 个**不写**。
- 未命中、起始下标越界都写 **0 / 0**（⛔ 不是 −1）；记录表与字体对象不变。

**残差**

- `RES-TEXT-RECORD-QUERY-OP3`（unknown）：第 3 个操作数是保留操作数还是历史残留（值被丢弃但类型要校验）。
  下一步：在语料里找非 0 / 非法的第 3 个操作数站点。
- `RES-TEXT-RECORD-QUERY-GROUP`（unknown）：组边界位（第 0 位）的领域含义，以及"同组多条同 key"在游戏里是否出现。
  下一步：按 0x1d2 的脏槽写点确认组是怎么划的。

**可证伪**

- 同一组里两条同 key、值 7 / 9，从 0 查 ⇒ 必须是 **9**；若得 7 ⇒ 命中后错误地中断了扫描。
- 跨组同 key（组 1 key = 5 值 7；组 2 key = 5 值 9），从 0 查 ⇒ 必须是 **7**；若得 9 ⇒ 没有在下一条记录的第 0 位处断组。
- 起始下标 = 记录数（或负数）⇒ 两个输出都是 **0**（不是 −1）。
- 第 3 个操作数类型非法却**不抛** ⇒ 本条错（它必须被读一次）。

### 取半个字符串长度：opcode 0x1a6

<!-- rule: CORE-OPS-TEXT-HALF-LEN-1A6 -->

`0x1a6` 有两个操作数：第 2 个是**源文本**、第 1 个是**落点**。它把源文本的**字节长度除以 2（向下取整）**写进落点。

- **源按文本读出**（与「设置一个字符串」的源侧同一口径：数值标签 ⇒ 十进制文本；内联文本 ⇒ 解码后的字节串）。
- 长度按**字节**数（到串尾为止），不是字符 / 码位。
- 不写源操作数；落点只写；无范围检查、不发平台请求。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 源文本的字节长度的一半 | 第 1 个操作数 ← `字节长度 ÷ 2`（整除，丢余数） |

**成立条件**

- 落点必须落在**写整型原语支持的操作数标签**里（见「数据池」）；不支持的标签 ⇒ 抛操作数类型异常（落点未写）。
- 除以 2 是**整除**：奇数字节长度丢掉余数（例如 7 字节 ⇒ 3）。
- 这个量的领域用途见残差；本规则只规定它等于"字节长度 / 2"。

### 取一段字节子串：opcode 0x2c7

<!-- rule: CORE-OPS-TEXT-SUBSTR-2C7 -->

`0x2c7` 有四个操作数：**源文本**（第 2）、**起点**（第 3）、**字节数**（第 4）、**落点**（第 1）。读序 **2 → 3 → 4**；起点与字节数都**按整型读出**。

1. **源按文本读出**（与 `0x1a6` 的源侧同一口径）。
2. `起点 ≥ 长度` 或 `字节数 ≤ 0` ⇒ 落点 ← **空串**（仍然写落点）。
3. 否则按字节切片 `[起点, 起点 + 字节数)`，并修正双字节字符的边界：
   - **首字节修正**：**从头逐字节扫描**（遇到首字节就跳过它的尾字节）并跟踪"下一个字节是尾字节"的状态；起点恰好落在被跳过的那个位置 ⇒ 起点 + 1、字节数 − 1，并上报一次警告。
   - **尾字节修正**：从（修正后的）起点再扫到"起点 + 字节数"；若扫描停在源串末尾之前、且最后读到的字节是**首字节**（它的尾字节落在切片之外）⇒ 字节数 − 1，并上报一次警告。
   - 两处修正**按此顺序**做：先首、后尾；尾修正用**修正后**的起点与字节数。
4. **双字节首字节的判据**（引擎的启发式，不是码页表）：`0x81..0x9F` 或 **≥ `0xE0`**；`0xA0..0xDF` 一律当单字节。
5. 修正后起点若已等于源文本长度 ⇒ 落点 ← 空串。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 落点 | ← 源文本的一段字节子串（可能被空串替换） |
| 源文本 / 起点 / 字节数 | 只读，不改 |

**成立条件**

- 计数单位是**字节**，不是字符：切多字节文本时以"削掉半个字符"为代价修正。
- 两条无效区间（`起点 ≥ 长度` / `字节数 ≤ 0`）都**写空串**，⛔ 不是"不写"。
- 起点为负**不在本版规定的行为里**（引擎不做 `< 0` 检查，直接把它当字节下标交给子串例程；见残差）；实现必须**响亮失败**，⛔ 不许静默当成 0。
- 修正只影响切片边界，不改源文本、不改落点的其它部分。
- 两次警告只上报（通道见残差），不改变控制流。

### 按名字查字体表：opcode 0x2de

<!-- rule: CORE-OPS-TEXT-FONT-NAME-2DE -->

`0x2de` 有两个操作数：第 2 个是**字体名文本**、第 1 个是**落点**。它在字体对象的**字体名表**里查这个名字，把**命中项的下标**写进落点；未命中写 **−1**。

- 查名前跳过名字**开头的一个 `@`**（只跳一个）。
- 比较**逐字节**且**长度必须相等**：先按两者较短的长度比字节，再比长度。
- 表是**线性扫描**：**命中即返回**该下标；未命中扫完整表。
- 匹配**不读**表项里的标志字节：只比名字与长度。
- 落点只写；**未命中也写 −1**（⛔ 不是不写）；不报错、不发平台请求。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 字体名 → 表项下标 | 第 1 个操作数 ← 下标（未命中 −1） |

**成立条件**

- 落点必须落在**写整型原语支持的操作数标签**里（见「数据池」）；不支持的标签 ⇒ 抛操作数类型异常（落点未写）。
- 表里的名字是**不透明字节串**：不做大小写折叠、不做码页转换、不去空白。
- 表的**填充时机**与表项里标志字节的用途见残差；本规则只规定查找结果。

### 两段文本是否相等：opcode 0x194

<!-- rule: CORE-OPS-TEXT-EQUAL-194 -->

`0x194` 有三个操作数：**落点**（第 1）、**左值**（第 2）、**右值**（第 3）。

- 读序 **3 → 2**（先右值，再左值）。
- 两者都按**"格式化成文本"**的读法：整数标签 ⇒ 十进制文本（无前导零、负数带 `-`）；文本标签 ⇒ 原字节串。
- 落点 ← **1**（两串**逐字节**相等）或 **0**（不等）。
- 不写第 2 / 3 个操作数、不记日志、不发请求、无早退。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 两段文本是否相等 | 落点 ← 1 / 0 |

**成立条件**

- 比较是**逐字节**的：不做大小写折叠、不做码页转换、也不按操作数标签区分类型 ——
  **整数 5 与文本 "5" 相等**（两者都格式化成 "5"）。
- 空串与空串相等（得 1）；空串与非空不等。
- 两条读都在写之前：任一条类型非法 ⇒ 抛操作数类型异常、落点不变。
- 落点必须落在**写整型原语支持的操作数标签**里（见「数据池」）；不支持的标签 ⇒ 抛操作数类型异常（落点未写）。
- 浮点标签的"文本形式"本版不规定（见残差）。

### 文本槽的定时释放：opcode 0x300 / 0x301

<!-- rule: CORE-OPS-TEXT-SLOT-TIMER -->

引擎有**十个文本槽**（下标 0 指"默认槽"，1..9 是普通槽）。每个槽除了自己的字体资源，还有一组**计时状态**：
**状态位**、**期限（毫秒）**、**起点时刻**。

- **`0x300`**（三个操作数：**槽下标**、**状态值**、**期限**）。读序：**槽下标 → 状态值 →（写状态位）→ 期限 →（写期限）**：
  - 状态位 ← `(旧状态 & 0x10000) | 状态值` —— **旧状态的第 16 位总被保留**（状态值带来的第 16 位也会进来；公式就是 OR）；
  - 期限 ← 期限操作数；
  - 下标与期限都不做范围检查（越界是未定义行为）。
- **`0x301`**（一个操作数：**槽下标**）：把该槽的**起点时刻清 0**，然后**释放**该槽的字体资源（下标 0 ⇒ 默认槽）。下标同样不检查。

**服务侧（主循环的**文本推进器**每次迭代一次，只服务槽 1..9；与「ADV 文本」的逐字推进是同一个推进器 ——
它在主循环里的位置见「ADV 文本」的「正文追加」条；「执行与时间」的迭代清单是概要，不重复列这一服务）**

1. 状态位非 0 ⇒ 置"有槽在用"标志。
2. 状态位**第 0 位**已置 ⇒ 置**第 16 位**；然后：
   - **参数格**（文本自动推进时长）**等于 0** ⇒ 只等该槽的字体资源**空闲**，然后继续下一个槽；
   - 否则（≠ 0，**含负数**）⇒ 记一个"在推进"计数、步进一次文本计时器（计时器返回负 ⇒ **本次服务提前结束**）、等资源空闲；
     再：起点为 0 ⇒ 起点 ← **现在**；否则 `现在 − 起点 ≥ 期限` ⇒ 起点 ← 0 并**释放**该槽的资源。
3. 否则（第 0 位未置）若**第 16 位**已置 ⇒ 等资源空闲，然后把状态位、期限、起点**全清 0**。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 该槽是否已起動 / 是否在等释放 | 状态位的第 0 位 / 第 16 位 |
| 该槽的期限与起点 | 期限格 / 起点时刻格 |
| 该槽的字体资源被释放 | 一次释放（清条目的一格 + 两段有序表的区间删除） |

**成立条件**

- 第 16 位是**粘住**位：旧值总被保留，写侧不清它；清除只发生在"第 0 位已清 + 第 16 位已置 + 资源空闲"之后。
- 服务**只走槽 1..9**：槽 0 不被服务（它的释放只靠 `0x301` 直接调用）。
- "等资源空闲"是**忙等**（同步循环）：没空闲就停在这里，不是延后到下一迭代。
- 参数格**等于 0** 时不按期限释放（只等空闲）：⛔ 不许把两支合并成"总是按期限"。★ 判据是"**等于 0**"，不是"大于 0"（负值走按期限那一支）。
- **期限 0 不是"无期限"**：起点非 0 后第一次服务就满足 `现在 − 起点 ≥ 0` ⇒ **当场释放**。
- 释放**不做对象析构**：清该条目的一格 + 删两段有序表的区间（见残差）。
- 本条的"十个文本槽"与「转发到字体对象」条的"十个文本槽"、`0x82` 的"十项节点表"**是不是同一张**，本版没有证明（见残差）；⛔ 不许默认它们可以互相索引。

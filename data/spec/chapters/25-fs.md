## 文件与脚本装载：取件 / 索引

脚本与数据资源都通过一个**统一文件 id** 取用。取件的输入是 id，输出是一个**打开件**（可读对象），不是内容本身：打开件可能指向当前目录里的松散文件，也可能指向归档里的一段切片；读内容由调用方对打开件做。**索引**（初始化文件）定义 id 与条目（名字 / 所属归档 / 偏移 / 长度）的对应关系。

归档自身的字节布局（目录区、段、压缩）属于《ALF 归档》；本章只规定"id 怎么被解释、内容从哪里来、失败怎么表现"。

### 统一文件 id 与两个 id 区

<!-- rule: CORE-FS-ID-ZONES -->

引擎用**一个 32 位统一文件 id** 引用脚本与数据资源。id 分两个区：

- **普通区**：高 8 位为 0，低 24 位是索引条目下标，必须落在 `[0, 条目数)`。
- **扩展区**：高 8 位非 0。它的**区号到 `*.AAI` 的映射本版未取证**（见 `RES-FS-AAI-KEY`），因此扩展区取件**不闭合**；本版只规定“高位非 0 不走基础索引”。

两个区的判定都发生在**取件时**，不在装载索引时。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 走普通区 | id 的高 8 位为 0 |
| 走扩展区 | id 的高 8 位非 0（具体映射未取证） |

**成立条件**

- 扩展区的装载来源、区号来源与 id 映射不在本版；本规则只规定“高位非 0 不走基础索引”。
- 普通区的上界是索引登记的文件条目数（见「索引装载」）。

### 松散文件优先

<!-- rule: CORE-FS-LOOSE-FIRST -->

**基础索引的条目**取件先在**当前目录**（见 `CORE-FS-SEARCH-ROOT`）里按**条目登记的名字**直接打开同名文件（松散文件）。打开成功 ⇒ 该打开件指向这个文件，**登记长度取文件的实际字节数**，不是索引里登记的长度。扩展索引条目的松散优先本版**不闭合**（见 `CORE-FS-INDEX-STACK` 的残差）。

- 同一个 id 在松散文件与归档里可以有**不同字节数**：这是规范的一部分，不是"两份应当一样"。
- 名字只用于定位松散文件；引擎对外的引用仍然是 id。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 取到松散文件 | 打开成功；长度 = 文件实际字节数 |
| 松散文件打不开 | 落到「归档回退」 |

**成立条件**

- 松散文件优先意味着**覆盖**：当前目录里的同名文件会盖掉归档里那份。
- 搜索根就是**当前目录**（见 `CORE-FS-SEARCH-ROOT`），不是“安装目录”；名字的码页与大小写本版不规定。

### 归档回退与切片

<!-- rule: CORE-FS-ARCHIVE-FALLBACK -->

松散文件打不开 ⇒ 若条目登记了一个**归档号**、且引擎已有归档，则：打开该归档、把读位置移到条目登记的偏移、**长度取条目登记的长度**，随后按顺序读。★ 什么值表示"**没有归档号**"，本版不规定（原因：哨兵编码没有取证）。

- 档名表以**归档号为下标**寻址，每条记录定宽 **256 字节**（布局见《ALF 归档》）。
- 条目没有归档号、或引擎一个归档都没有 ⇒ 不进入回退，直接失败（见「取件失败」）。
- 归档里的载荷**原样存放**，不做二次解压；"切片"就是定位 + 定量。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 取到归档条目 | （归档, 偏移, 登记长度）三元组 |
| 取不到 | 见「取件失败」 |

**成立条件**

- 目录区布局、文件记录宽度与压缩属于《ALF 归档》；本规则只规定怎么用目录里的三元组。

### 取件失败：三个原因，一种表现

<!-- rule: CORE-FS-FETCH-FAIL -->

取件失败有**三类可区分的原因**，表现相同：报告一条消息（带上下文：文件 id / 名字 / 宿主错误码），并**中断当前操作**。**不返回空内容、不返回短内容。**

1. **文件 id 越界**：普通区下标大于等于条目数（负值按「统一文件 id 与两个 id 区」的分区规则归入扩展档区，见第 3 类）。
2. **松散文件与归档都打不开**（消息里带宿主的错误码）。
3. **扩展档相关**：档未装载，或档内取件失败。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 取件失败 | 一条消息请求 + 当前操作中断 |

**成立条件**

- "中断当前操作"不是"返回 0 字节"：把失败折叠成空内容，上游会把它当成一份内容错的完整文件。
- 消息的具体文本是引擎内建资源，**文本内容本版不规定**；本规则只规定"带哪些上下文"。
- "中断"以**哪一类异常**表达，**本版不规定**（原因：这个失败点与三类异常的分类没有逐条对上）。

### 索引装载

<!-- rule: CORE-FS-INDEX-LOAD-FAIL -->

索引装载在三处判定失败，三者都**返回失败标志**（不抛、不中断）：签名不属于四族、读失败、内存不足。

- 签名按**四族依次比较**（S3 族两个、S4 族两个）；全不匹配 ⇒ 报"索引损坏"。
- 装载成功 ⇒ 引擎持有三张表：**条目数**、**归档名表**、**文件表**；此后 id 空间由这三张表定义。
- 失败时给出一条文本并返回失败标志；装载本身不执行"中止启动"那个动作（中止由启动阶段做，见《启动入口》）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 索引可用 | 三张表就位；返回成功标志 |
| 索引不可用 | 一条消息 + 返回失败标志 |

**成立条件**

- 与启动的分工：装载器**返回**失败，启动阶段决定"中止"并再显示一条自己的文本。
- **四族签名分别对应哪种初始化文件，本版不规定**（原因：只取证到两族的文件名 `SYS4INI.BIN` / `SYS3INI.BIN`，见《启动入口》）；本规则只规定"比较四族、全不匹配即损坏"。

### 松散文件的搜索根：只有一个

<!-- rule: CORE-FS-SEARCH-ROOT -->

**合同**

- 取件**不构造路径**：引擎把条目登记的**名字原样**交给宿主的"按名打开"请求。相对名按**进程当前目录**解析，绝对名按绝对名解析；引擎不拼前缀、不拼后缀、不改大小写、不做编码转换。
- **没有搜索根列表**：一次取件只发起一次打开；失败就进入「归档回退」。不存在“再换一个目录试一次”，也不存在“先试安装目录再试存档目录”；松散文件只在**当前目录**里按名打开。
- 当前目录在启动期**至多被设定一次**，且先于索引装载：
  - 启动参数里有 `SP` 键 ⇒ 当前目录设成**可执行文件所在目录**（盘符 + 目录，不含文件名）；
  - 否则若有 `PATH=` 键 ⇒ 设成该值；
  - 两者都没有 ⇒ 保持宿主给的当前目录。
- 扩展索引的枚举（见「索引的装载顺序」）用的是**同一个**当前目录。
- 运行期没有第二个设定当前目录的路径。

**成立条件**

- 启动参数是"斜杠分隔的键"，键的匹配不区分大小写；`SP` 与 `PATH=` 同时出现时 `SP` 优先（先判 `SP`）。
- "名字原样"指引擎不改变字节；宿主怎样把名字映射到文件（大小写、长名、路径规范化、UNC / 设备名）**不是**本规范规定的内容。
- 缺省时当前目录是宿主继承下来的值，引擎不改它。
- 松散文件与归档的优先关系由「松散文件优先」规定；本条只规定"名字相对哪里"。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 取件用相对名 | 打开的宿主对象相对**进程当前目录** |
| 取件用绝对名 | 与当前目录无关 |
| 当前目录被启动参数设定 | 一次目录设定请求（可执行文件目录 / `PATH=` 的值） |
| 打开失败 | 进入归档回退 |

### 归档路径：启动期一次成形的盘符前缀

<!-- rule: CORE-FS-ARCHIVE-ROOT -->

**合同**

- 归档**不**走"按登记名相对当前目录"：索引装载成功之后、窗口创建之前，引擎做一次**盘符判定**，把每份归档记录的路径改写成 **盘符 + 冒号 + 反斜杠 + 归档名**；此后打开归档直接用这串路径。
- 判定依据是配置里的卷标键（`set:CDLabel`）与两个校验键（`set:CheckVolume` / `set:CheckFileName`）：引擎在盘符里找第一个"卷标（及可选校验）匹配"的盘；**命中且卷标非空**才改写。
- 判定结果另存进引擎级的一格，供运行期读。
- **没命中 / 卷标为空** ⇒ 不改写：归档记录保持索引里登记的原样（于是按宿主规则解释，通常是相对当前目录）。
- 每份归档只改写一次：记录旁边有"已装载"标记的归档跳过。

**成立条件**

- 改写只发生在**索引里已经有归档表**之后；因此它只覆盖基础索引的那张归档表（扩展索引自带的归档表见残差）。
- 盘符的数量与顺序属于平台侧；引擎不规定"哪些盘存在"。
- 归档名本身（含子目录）不改写，只加前缀。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 归档可用（有盘符） | 归档记录的路径 = 盘符 + `:` + `\` + 归档名 |
| 判定失败 | 归档记录的路径 = 索引登记的原样 |
| 判定成功 | 引擎级的一格里存着盘符号 |

### 索引的装载顺序与同名优先

<!-- rule: CORE-FS-INDEX-STACK -->

**合同**

- **基础索引恰好一份**：先试 S4 族文件名；失败才试 S3 族；再失败 ⇒ 启动失败（见《启动入口》）。S4 成功就不再试 S3。
- 基础索引装载成功后，引擎在**当前目录**枚举 `*.AAI`（不递归、跳过目录），把每个文件作为**扩展索引**装载。
- ★ **扩展索引的格式身份、区号来源与“高 8 位 → 哪份 *.AAI”的映射本版未取证**（见 `RES-FS-AAI-KEY`）；因此扩展索引条目的取件**不闭合**，本版只登记“会枚举并尝试装载”。
- 扩展索引装载失败**不中止启动**：报告一条消息并跳过该文件，继续枚举下一个。
- 在**基础索引**上成立的优先规则：
  1. **松散文件 > 归档**；
  2. 高位 0 永远指基础索引；
  3. 扩展索引之间的同区号覆盖本版**不规定**（区号来源未取证）。

**成立条件**

- 枚举顺序是**宿主的目录枚举顺序**，不是字典序；因此"后枚举到"在跨机器上可能不同 —— 这是合同的直接后果，引擎没有第二条仲裁规则（不比较文件名、不比较时间）。
- 顺序是：基础索引 ⇒ 扩展索引；扩展索引的枚举发生在基础索引装载成功的同一步里，基础索引失败时一个 AAI 也不扫。
- 扩展索引之间互不合并：每份是独立的一套"归档表 + 文件表"，按区号寻址。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 基础索引已装 | id 高位 0 ⇒ 基础表；扩展表对应槽位为空 |
| 扩展索引已装 | 该区号槽位指向那份扩展索引 |
| 同区号再次装载 | 该槽位被覆盖（旧对象失去引用） |
| 基础索引两种族都失败 | 启动结束（不走扩展索引） |

### 取件产出的是"打开件"，不是内容

<!-- rule: CORE-FS-FETCH-HANDLE -->

**合同**

- 取件的输出是一个**打开件标识**（引擎的打开件表里的一个槽），**不是**字节内容。调用方拿到标识后，用「锁打开件」换到宿主文件句柄再自行读；读完用「关闭文件」把槽还回。
- **每次取件都重新打开**：引擎不缓存内容，也不按 id 复用已打开的件。同一 id 连续取两次（前一件不关）⇒ **两个不同的槽、两个独立的读位置**。
- 槽的分配是**环形**的：从上次分配的槽之后找第一个空槽；关闭只把该槽标空并释放宿主句柄，**分配位置不回退** ⇒ 即使前一件已关，下一次也不一定拿回同一个槽（只有绕一圈且中间没有别的空槽时才会）。
- 打开件表有**固定容量**（上限属机器细节）：全部占满时取件**失败**（一条消息 + 中断），不会抢用别人的槽。
- 每次成功取件还会写一次**按 id 的记账格**（一条按 id 派生的值）；这条记账**不影响**内容来源，也不改变槽的分配。
- 失败时**不返回空标识**：「锁打开件」与「关闭文件」遇到无效标识各自报一条消息；取件本身失败则中断。

**成立条件**

- 取件本身**不读内容**：因此"读失败"与"取件失败"是两回事，读失败归调用方处理。
- 打开件标识只在进程内有意义，不是文件 id：同一 id 的两次取件得到两个不同的标识。
- "长度"是取件时随标识给出的登记长度（松散文件取实际字节数、归档取登记长度，见「松散文件优先」与「归档回退」）。
- 关闭之后再拿同一个标识去「锁打开件」是错误用法：引擎会报一条"无效的打开件标识"的消息（「关闭文件」自己也会报同类消息）。

**状态对应**

| 领域状态 | 机器状态 |
|---|---|
| 取件成功 | 打开件表某槽 = 宿主句柄 + 读位置 + 长度；返回该槽号 |
| 读内容 | 调用方通过槽对应的句柄读 |
| 关闭 | 槽标空、宿主句柄关闭、读位置清零 |
| 表满 | 一条消息 + 中断 |

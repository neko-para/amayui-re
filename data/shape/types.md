# `types.json` —— 对象 shape 的**类型真源**（中心化：少数定义、多数载体）

> 同名数据文件的说明书。它是什么 / 非显然口径 / 指向 —— **schema 不复述**：
> 字段、义务、守卫、诚实项的真源是 `pnpm tools shape describe`。

`types.json` 是**全仓唯一**的类型成员表：每个类型按 id 共享一份，成员 = 偏移 + 跨度（或元素类型 + 条数）。
载体文件（`carriers.json`，**唯一一个**）**只放载体**、`typesFrom: "types.json"` 引用本文件 ——
⛔ 类型不许写进族文件（那会逼别的族文件去引用那一个族）。

## 非显然口径（踩过的坑都在这里）

* **成员有三种合法形态**：**内联值**（给 `width`）· **数组**（给 `type` + `count`，元素类型必须给 `size`）·
  **条数未观察的数组**（`type` + `count: null` + `sweep: {stride, index}`）。
  缺一半 ⇒ `G8` 红 —— 因为跨度算不出来时，判定器会把它**静默当成 1 字节槽**
  （实测：帧数组的访问会变成"不落在任何已声明成员上"的残差，而旧版一条红都没有）。
  ★ `count` **省略**与 `count: null` 是**两件事**：省略 = 声明不完整（红）；`null` = 明确声明"条数未观察"（要配 `sweep`）。
  ★ `count: null` **必须**配 `sweep`：没有条数 ⇒ 窗口**无界** ⇒ 会把窗口外的偏移也解释掉（实测形态：
  `0x5ee04` 的无界窗口一路吞到 `0xa609c` ⇒ **假解释**）。
* **`views`（可选，数组成员上）= 模型的推测**：`[{ elementDelta, label? }]`，意思是
  "这一段字节是**同一个数组**、索引差 k"。依据 `docs/02-engine/shape-census.md` §4：
  **原点表是声明的约定，不是语料事实** ⇒ 判定器只做两件机械的事：**算术自洽**
  （`成员.off + 步长·delta == 被解释的位移`）与**可证伪性**（零观察 / 多余的视图 ⇒ 单列"空话声明"）。
  报告里这类解释标 `🧩 …**推断**`，并由**守恒④**（解释 = 观测档 + 视图推测档）分开记账。
  ⛔ **不声明就如实进残差**，不许把"另一种原点"静默圆成"元素 0"。
* **`type` 在成员上有两个互不相干的意思**，按 `kind` 分岔：
  `kind:"ptr"` 时它是**被指向的类型**（下钻用，此时不该给 `count`）；否则它是**数组元素类型**（必须配 `count`）。
* **`kind` 是闭集合 `{"ptr"}`**，意思是"这个成员的值是**另一个对象的基址**"（会被解引用）。
  ⛔ 它**不是**"标量"的标记：不写 `kind` 就只是内联值/数组。反过来，**没写 `kind:"ptr"` 的成员被当基址用**
  ⇒ `G5'` 红（这就是"标量不许再被解引用"那条判据）。
  ★ 反过来"声明了 `kind:"ptr"` 却零解引用" ⇒ **G7** 单列"空话声明"（⛔ 不算通过，但**不判红**：类型是共享的）。
* **裸位移与视图窗口重叠时选谁**：规则定 —— 带索引/步长的站点优先**数组窗口**、裸位移优先**内联成员**，
  再比窗口宽窄与 `|elementDelta|`；三项全同 ⇒ 单列 `ambiguous`（⛔ 不许靠"谁先声明"决定）。
* **对象身份 = 路径**（见 `docs/02-engine/shape-census.md` §4.3）：二级对象靠"父类型的成员写
  `kind:"ptr"` + `type:"T…"`"，多跳就是"目标类型里再有一条 `kind:"ptr"` 成员"逐层套下去；
  **内嵌（按值）**写成 `{off, type:"TX", count:1}`（跨度 = `size(TX)`）。**对象层级 = 路径长度 + 1**。
  ★ 下钻上限（`DRILL_MAX_LEVEL`，默认 2）是**政策**：超过上限的站点进"超出解析深度"档（带路径 + EA），
  与"拒绝/未声明"**分开记账**。抬上限的代价现跑：`pnpm tools shape census`。
* **成员只写"观察到的"**：宽度取 `--access` 的 `w=`；⛔ 不把语义推断写成宽度。
  实测例子：`0x8` 的 3 处访问后面紧跟 `push 400h`（当 Buffer 传），而 `0x408` 恰等于 `0x8 + 0x400`
  —— 两个**独立**提案正好相邻，像是"一块 `0x400` 字节的缓冲"。但本表**只按观察写 `width: 4`**：
  把它写成 `char[0x400]` 是**语义推断**（走 `AGENTS.md` §6 的台账准入），不是形状层该下的结论。
* **别名/邻接不算证据**：`0x8` 与 `0x408` 相邻只是旁证，不是"它们是同一个成员"的判据；
  成员表按 `off` 分区，相邻即相邻。
* **匿名目标类型**（`T_aa514` 这种 id）：目标类型**给不出语义名**时，按"**被观察到的偏移**"声明即可 ——
  每个成员都要有观察（`pnpm tools shape access` 的站点），`size` 不给（未观察）、`complete: false`。
  ⛔ 不许凭印象补偏移；给不出就写 `type: null`（进**不透明桶**，⛔ 不算通过）。
  实测收益：`0xaa514` / `0x68eb0` 两条指针成员从"不透明 8 处"变成"解释 8 处"，**没有一句语义结论**。
* **原点约定**：同一批字节可能有两种写法（如 `0x5d894 + 0x78·索引` 与 `0x5d81c + 0x78·索引` 是同一族的两种原点）。
  本层**绝对位移**是判定器的坐标，原点约定写在成员表里 —— ⛔ 不许静默选一个（先例见 `docs/02-engine/shape-census.md` §4）。

## 怎么查

```bash
pnpm tools shape describe                              # 分节 / 义务 / 守卫 的真源（先看这个）
pnpm tools shape claims data/shape/types.json          # 类型真源自校验（无载体时 G6 会说"无绝对锚"）
pnpm tools shape claims data/shape/carriers.json    # 真正有判据的那一遍：载体 × 本类型表
pnpm tools shape census                                # 全表普查：每个偏移被谁碰 / 索引簇 / 各层级的站点数
pnpm tools shape bodies                                # handler 体骨架（族边界的依据）
pnpm tools mutate check --match shape                  # 守卫自检（两道守卫 + G7/G8/G9 + 守恒③④ + 路径/政策）
```

## 怎么改

1. **加/改成员**：只改本文件。每条成员都要有**观察**撑着（用 `pnpm tools shape access <sym>` 拿逐 site 记录，
   再 `pnpm tools shape verify <EA>` 独立复核）；⛔ 不许为了变绿编成员。
2. **改完跑两遍**：`claims data/shape/types.json`（类型自洽：G1/G8/G4/G6）**与**每个族文件的 claims
   （类型是共享的：G1 重叠 / G2 覆盖 / G3 步长 / G4 边界都会对**所有**引用它的族重新判）。
3. **跨度拿不准就别写数**：宁可让报告**明说**"判不了/按 1 字节处理"，也不要写一个看起来干净的假数
   （这是本目录最严重的错误）。
4. 改了判定逻辑 ⇒ 同步 `pnpm tools shape describe`（schema 真源）· `docs/02-engine/shape-census.md`（口径真源）
   · `tools/mutate-check.mjs`（守卫自检清单）。

# SO001 重放残差（多段整画布截图史，2.07% 像素）

## 现象（可观测分歧）

`SO001`（1280×1792 ADV 窗口图集）从**原始件**重放时，与生效版 `corpus/assets/ui-images/SO001-4.png`
差 **128110 个通道 / 47528 个像素**（全图 2293760 px 的 **2.07%**，最大差 252）。
差异分布：中簇 15 按钮 17207 · 右带上/下 19981 · 「操作説明」面板 10308 · **其余 32**。

**复现**：`pnpm tools ui-bake verify SO001` —— 它必须报 `逐通道不等 0` 才算这条缺陷消失。

## 根因（已定位到不可复现的那一环，不是参数没调对）

生效版是旧仓**分四段整画布截图叠加**出来的：`-1` 中簇 → `-2` 右带上下 → `-3` 面板 → `-4` 中簇下移 1px。
每一段都把**清理底图当 `<img>` 放进页面**由 Chrome 合成，于是每段都在底图上烙下一次
**premultiply 往返**（子会话实测：只画一遍底图就有 13,601 px / |ΔRGB| 99,560 / max 92 的固定噪声）；
而本链只有**一次** canvas 渲染 ⇒ 那段"散色历史"复现不了。

两条已被实测排除的路径：

1. **多段模型**：把它当四段链重放、逐段与旧仓 `SO001-1..4.png` 对照 ⇒ **stage1 就差 51826 通道**。
   原因是中间段的生成脚本已被覆盖、只剩产物 ⇒ 缺的是**中间底板与各段参数**，不是模型形态。
2. **参数/样式**：清理侧已**逐像素确证**与旧仓等价（对 15 张 `so001_cl_*.png` 0 差异）；
   第一步样式已由**0 差异证据**钉死（旧仓 `.tmp/so001_render15.html` 重渲 == `SO001-1.png`，
   2px 描边 / `.w-shd` 阴影层 / `left=x0-8` / `top=y0+24` / `93×26` / `line-height:22`），
   已逐条落进 recipe（第四步 `top+1` 用 `shift:{y:-1}`）。

## 唯一的收口路径（需裁决：会破"只从原始件重建"的口径）

把旧仓那 4 个中间底板登记为**外部只读素材**，再把本链扩成多段模型：

* `res/images/…` 之外的 `.tmp/so001_clean_full.png`（682,063 B）
* `.tmp/so001_band_clean_rgba.png`（660,434 B）
* `.tmp/so001_panel_clean.png`（721,033 B）
* `.tmp/so001_midclean.png`（720,062 B）

合计约 2.7 MB。**收益**：SO001 可望归零。**代价**：这批图不再是"纯从 ALF/AGF 构建"。
★ 在裁决之前，这条缺陷**保持 open**，并按用户口径把它当"多段/算法型图"接受较高偏差。

## 不做什么

* 不为凑数字改判据 / 改参考图 / 放宽 `verify`；
* 不把拿不到的中间参数"猜"进 recipe（`gen15.py` 的 1.5px 版曾被我误当最终版，已用 0 差异证据纠正）。

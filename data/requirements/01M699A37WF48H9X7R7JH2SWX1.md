# 实现侧对齐：把 0x1ca 的命名键存储与 0x324 的接收者复位落进参考实现（落点需裁决）

- 要收口的残差：`RES-OPS-FORWARD-MESSAGE-IMPL`、`RES-OPS-FORWARD-FIELD-IMPL`
- 所属规则：`CORE-OPS-FORWARD-MESSAGE`、`CORE-OPS-FORWARD-FIELD`
- 入口 EA：`0x420240`（0x1ca handler）、`0x41a470`（0x324 handler）、`0x453160`（接收者复位体）

## 已经知道什么（带 EA）

- `0x1ca`：把命名键 `message:ReadTextSkip` 设成操作数。写入经引擎持有的接口对象
  （`0x42024f lea esi,[ecx+0AA514h]`）的槽 `+0xC`（`0x42026a mov eax,[edi+0Ch]`），键名是静态串
  （`0x42026d push offset aMessageReadtex`）。同一个接口对象的槽 `+4` 是「读命名键」入口
  （`0x407b4b mov edx,[eax+4]`，0x308 用它读 `system:LimitTouch`）。
- `0x324`：从 `Engine+0x5B320` 取接收者（`0x41a488`），尾跳进复位体 `0x453530` → `0x453150`：
  释放接收者的 `+0x408` / `+0x40C` / `+0x410` 三个对象（`0x453160` / `0x453178` / `0x453190`），
  清 `+0x4E0`（`0x45319e`）。

## 还缺什么

- 参考实现仍按旧口径写这两条：`0x1ca` 没有命名键存储、`0x324` 只发一次请求而没有接收者对象。
- 落点需要人裁决：`apps/emulator` 与 `apps/emulator-new` 已废弃（只读遗产），
  新实现只落 `apps/emulator-cxx`（见 `repo:AGENTS.md` §11）。本单要决定：
  是把这两条语义落进 `apps/emulator-cxx` 的新实现，还是只把旧参考实现降级为「不声称覆盖」。

## 判据（什么算做完）

1. 参考实现里 `0x1ca` 写后 `0x71` 的分支**变化**（可观察），并有会红的守卫；
2. `0x324` 复位后接收者的三处引用为空、标记为 0，并有会红的守卫；
3. 若裁决为「不落实现」，把两条残差改成对**实现侧偏离**的显式登记（而不是 unknown），并写清由哪一轮接管。

## 判据（存在性 + 观测）

- 现象：CONFIG1 屏底部 ADV 预览的 **10px 注音行**（正文「天結」二字的 10px 版本）里，「天」的顶横整行缺失，屏幕读作「大」；同屏 30px 正文不裁、20px 标签不裁（20px 只抽一处，未全帧普查）。
- 读数（2026-11-18 / macOS arm64 / RelWithDebInfo / Amayui-CN_cnjp.ttf）：
  - 裁剪上沿固定 = 屏幕 y=610（含）；lift0/1/2/3 的 10px 墨迹顶 = 611 / 610 / 609（丢）/ 608（丢 2 行）
  - 被丢行数 = max(0, lift − 1)：y=609、x=446..453 的 8px 顶横 + x=470,474 的 2px AA
  - 10px「天」`bitmap_top=8`；屏幕反推的**有效行框余量 ≈1px**（`ascent≈9` 是由裁剪上沿 610 + 反推基线 619 得到，**来源未证**；host `metrics().ascent=10` 与它差 1，见 `repo:docs/03-emulator/fonts.md` §3.1 的 `<待核>`）
  - 30px：`origin_y=25`、`bitmap_top=23`；首行 625/627（default/off）不裁
- 机制：补偿只加在 `repo:apps/emulator-lift/src/runtime/font.cpp` 的 `buildMaskFromSlot`：`origin_y = bitmap_top + baseline_lift`，对所有字号一律 +2；屏幕事实是裁剪上沿固定 610、10px 墨迹顶随 lift 线性上移。**「guest 行框顶 = 基线 − ascent」是 `<待核>` 推断，不作产品判定**。
- 期望：10px 注音不裁；20/30px 的 +2 视觉不变；`0` 仍逐字节关掉补偿。

## 根因

`kBaselineLift = 2` 是按默认字号定的常量，被无条件加到每个字号。10px 行框的有效余量只有 1px，+2 越界 1px ⇒ guest 按行框顶裁掉。

## 修法（已裁决）

1. **只按像素字号查表**：`origin_y = bitmap_top + table(px)`；同一字号的所有字型位移**完全一致**。表值由 10/16/20/30px 采样确定：`≤16px → 1`，`>16px → baseline_lift`（缺省 2）。
2. ⛔ **不做逐字型的余量夹取**（用户裁决：基线一致性优先于绝对不裁；逐字型 max 会让同一行字型位移不同）。
3. `baseline_lift == 0` ⇒ 恒 0；`baseline_lift_by_size == false` ⇒ 恒 `baseline_lift`（旧行为，A/B 用）。
4. AOT 臂装回 `--baseline-lift <N>` 与 `--baseline-lift-by-size <0|1>`（随解释器退役被删，文档仍在引用）。

## 不做 / 边界

- 不动 `tmAscent` / 行高；补偿仍只在 `origin_y`。
- `--font` / `--font-engine-name` 仍缺，另开单（`REQ-01M7Q9D7NMFVKAN4PY57B5Y5MM`）。
- 真机 MS Gothic 的逐字号 `gmptGlyphOrigin.y` 未复核；判据是「10px 注音不裁 + 默认字号不变」，不是「与真机逐像素一致」。

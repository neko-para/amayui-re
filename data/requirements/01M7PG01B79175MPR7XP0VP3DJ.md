## 现象

加载 `saves/SAVE04.DAT`（第 5 槽）→ 进地图 →「要接受迷宫教程吗？」选**不接受** → wipe 里 `exit 3` +
`=== guest memory fault ===`。真实 fault 是 READ `0x00000020`（`fault ea` 行，base 0x300000000）；
旧 `access: WRITE 0x1005BA8C` 是 AOT 不更新 `g_access` 留下的最近一次 shim 侧写。

## 根因

槽 0x24（`this+0xA5D8+0x24*4 = 0x1005AB58`）的 1280×720 NormalTexture P：`ID3DXSprite::Draw` 的批次数组
从 16 条扩容到 32 条时，`GuestHeap::realloc` 移动了块，但 `reserveBatch(X86&, const State&)` 只把新 base
写回 guest 状态块，`draw()` 仍用旧 `s.batch` 写第 17 条（count=16）：`旧 base + 16*72 = P-8`。
四条 4 字节写 `{pTexture, flags=5, 0, 0}` 覆盖 P 的块头与 `[P]/[P+4]`（vtable/base=0）。

## 修复 / 守卫

`reserveBatch(State&)` 成功后 `s.batch=np; s.capacity=cap;`；`draw()` 用新 base。
守卫：`apps/emulator-lift/tests/d3dx9.cpp#d3dx9/sprite-batch-realloc-move`（Draw 17 次；修前 835/4，
修后 836/0）。`ctest -R '^(fault-report|d3dx9)$'` 2/2。

## 复现 / 验收

修前配方（`--max-frames 12000 --time-limit 900`）exit 3 + fault；修后不再 fault，plan 走到 AIM（地图）
第 2982 帧；配方尾部 `SC4000 0x10D00` 门是 fault 路径专用 ⇒ exit 5（不是 fault）。
`LIFT_WATCH='0x1005AB58:4>follow'` 修后无 P-8 写。

## 未做

win32 未跑（分支未编译）；watch follow pending 是 thread_local（跨线程会漏）；
`writeBytes/fillBytes/wr8/16/64` 的 watch 接线无正例（低风险跟进）。

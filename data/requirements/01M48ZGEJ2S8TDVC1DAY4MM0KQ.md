## 范围

`apps/emulator` 的**状态分区**与**快照 / 恢复**接缝。

★ **接缝本身已就位**（口径 = `apps/emulator/README.md` §7；可执行形式 = `src/model/pools.ts` 的 `STATE_PARTITION`
与 `snapshot()` / `restore()`；守卫 = `tools/test/emulator-state-partition.test.mjs` 与 `tools/test/emulator-snapshot.test.mjs`）。
本节点管的是**还没定下来的那几件**，以及**格式的时机** —— 不是为了"补一个快照功能"。

★ 为什么现在开这张单：快照的难点不是序列化，而是**"哪些量算状态"**。今天模型里只有池这一族有归属；
handler 一个接一个写下去之后，"有个量没回去"就会变成默认结果 —— 而这类错**不报错**，
只让"恢复后重跑到第 N 帧"与"自然跑到第 N 帧"在某处静静分叉。⇒ 先在每个量上挂"重开条件"。

## 待定项（★ 每条都写"重开条件"：到了什么地步才谈得上定它）

| # | 待定 | 什么时候定 | 重开条件（缺什么就定不了） |
|---|---|---|---|
| **D1** | 数组容器 / 外挂缓冲的**别名语义**：值语义（丢别名）还是"对象表 + 引用" | 写数组族 handler **之前**（`0x64 copy-local-array` / `0x2D8 set-array-to` / `0x6C fill-zero` / `0x61 lookup-array` / `0x63 lea`） | 需要**行为观察**：两个帧的容器会不会共享（别名是行为，不是口味）⇒ 第一条数组指令语义被核实 |
| **D2** | **非确定源的承载面**：`0x60 random` 的 `rand()` 状态 + "最多重掷 12 次"计数器（`Engine+0x69330h`） | 实现 `0x60` 之前 | 需要观察：那颗计数器是"每条指令 12 次"还是"每次取值 12 次"（现在只有 `inc` / `cmp …,0Ch` / 归零 的形态） |
| **D3** | `0x2DA` / `0x2DB` / `0x2DD` 碰的引擎字段（`+0x14D30` / `+0x313D0` / `+0x460F0`+`+0x460F4`）算不算引擎态 | 解出它们的语义时 | 语义未解 ⇒ "进不进快照"无从谈起（现在只登记"碰到了"，见 `numeric-ops.ts` 的 `TOUCHES_ENGINE_STATE`） |
| **D4** | **float 族的落槽宽度**：模型存 JS double，而引擎那格是 4 字节（`LOCAL_POOLS.float.elemBytes = 4` 已核实）⇒ 要不要 `Math.fround` | 做"恢复后重跑到第 N 帧 == 自然跑到第 N 帧"这条判据**之前** | 需要观察：引擎的**中间精度**（x87 80 位 / SSE 单精度）—— 只归一**落槽宽度**，别顺手断言运算精度 |
| **D5** | **`initZero` 的边界**：现在是 `i <= count`（初始化 count+1 个槽），**无任何守卫** | 出现第一条"引擎初始化几个槽"的观察时 | 它直接决定"快照里该有哪些槽在场"；★ 不许按名字猜 |
| **D6** | **快照文件格式与版本号** | 执行核心（`src/vm` 的 `step()`）落地、且上面那条等价判据能跑之后 | 今天没有"状态的第二个来源"（没有引擎对象、没有执行循环）⇒ 此刻定格式只能靠猜 |

★ D4 / D5 是从**批 R1 的池模型**（`REQ-01M48DJ3PK48CXQXAV1M3EEQNR`）带过来的保真问题：
它们在那边属"模型常量"，在这里属"什么算状态"⇒ **只在这里跟踪一份**，不复制节点。

## 判据

* **D1–D5 各自"定下来"的样子** = ① 台账 `data/ledger/` 里多一条**可再校验观察**（二进制 EA / 语料行区间 +
  内容摘要 / 守卫用例 id），② 结论落到 `STATE_PARTITION` 或模型里，③ 本表的对应行删掉。
  ⇒ 判据可机械检查：那几条待定项要么**在表里**（未定），要么**在台账里**（已定），不许两头都没有。
* **D6** 在执行核心落地后由本节点决定：要么定格式（含版本号与"读不到认识的版本就响亮拒绝"），
  要么拆成子节点；★ 在此之前**不许**先写格式 —— 现在写的每一条都绑不上观察。

## 为什么留这一条
`AGERC.DLL`（菜单资源）现在用**入库可信产物**：`corpus/assets/agerc/AGERC.DLL`（= 旧仓 `patch/AGERC.DLL`），
并有机械复核 —— `tools/test/agerc-artifact.test.mjs` 拿清单里 `binary/agerc-modified-install` 记的 sha256 当**唯一基准**
（旧仓在机时再做逐字节比对；这条守卫真抓过一次：有人为测「加壳 vs 不加壳」临时替换了旧仓 `install/AGERC.DLL`，
是 `pnpm tools corpus validate` 报红发现的）。

★ 本节点**不做事**，只保留「将来要不要自建链」这个可能性 —— 原工程节点 `REQ-01M411CSDXDVGTP83BPS6TNV48` 已废弃，
但**方向与判据不能丢**，故挪到这里跟踪。触发条件满足任一才值得动手。

## 触发条件
* 菜单／对话框需要**大改文案**（现有 16 个对话框基本没汉化，只 `DIALOG 3` 一个）；
* 入库可信产物**失配**（旧仓那份变了、或清单基准失效）而必须自己产出；
* 需要**摆脱 Windows GUI 依赖**（旧链用 Resource Hacker 做重序列化，产物里 7 条未改过的 DIALOG 被 +2 字节）。

## 真要做时的方向（已评估，别重新摸）
* 设计文档：`docs/01-translation/agerc-design.md`（基线取法 / 入库真源 / 纯 Node 构建 / E1·E2 探针 / §4C 五条判据）；
* **基线** = `DATA1.ALF` 里那份**脱壳原版**（`SYS4INI` id 21072，849,408 B）——
  ❌ **不能**照 `patch baseline` 的「散装优先」去取安装根那份（加壳件；26 条资源的数据不在盘上）；
* **入库真源** = 菜单文本 + `DIALOG/3` 模板 + 3 个代码内嵌串槽的新串（**存定位规则，不存偏移**）+ 2 个导入改名，
  并带 `subsSha` 指纹（对话框文本是占位码位，与字典／字体强耦合）；
* 构建**纯 Node**（摆脱 Resource Hacker）；动手前先做设计文档 §6 的两个探针：
  **E1**（`DIALOG/3` 的语言标记能否保持 `0x411` —— 不必改则目录树完全不用动）、
  **E2**（那几个串槽能否按内容定位而非硬编码偏移）；
* 另一条更大的路（设计文档 §G「凭空重建 DLL」）**未否决**，但必须先出**探针版**把可达面测成运行时清单。

## 判据（真动手时按这个收口）
* 自建产物过设计文档 **§4C 五条**：资源集合不变 · 未列出的资源与基线逐字节相同 · `.text` **0 差异** ·
  与旧产物**资源级**对账（**不要求整文件逐字节** —— 旧链掺了 Resource Hacker 的重序列化）· 带 `subsSha` 指纹；
* **一条命令**从文本真源打出产物，干净目录里可复现；
* 换成自建产物后，`tools/test/agerc-artifact.test.mjs` 的基准要**显式改判**（不是删掉它）。

## 非目标
* ❌ 不追求「把 16 个对话框全部汉化」—— 那是**内容**工作，归翻译域；
* ❌ 不在本节点动菜单／对话框的**文案**（只重建"怎么产出那份二进制"）；
* ❌ 不把带壳的安装根那份当可编辑素材（它的资源字节不在盘上）。

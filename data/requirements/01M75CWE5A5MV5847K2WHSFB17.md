## 一句话

把语音起播那一下的 **libvorbis FFT/MDCT 内核**（`sub_4E0B40` = `mdct_backward`）做成函数级 native
override：值一样（数值档容差内）、`sub_4E2A30 -> sub_4E0B40` 那 163 ms/语音不再逐条解释。

## 背景（2026-11-11 实测，窄窗口 profile）

点击播放语音时（`.tmp/test.graph` 的 `click1` 窗口，3 s / 170 帧）：

```
sub_420F70 -> sub_4BB840      899.3 ms / 1     ← 一条 VOICE 命令
  sub_4BB840 -> sub_4559C0      2.0 ms / 1     ← 打开文件（CreateFileA，便宜）
  sub_4BB840 -> sub_4B6570    219.7 ms / 1     ← new stream + new Ogg 解码器 + 建 DSound 缓冲
  sub_4BB840 -> sub_4B6020    677.6 ms / 1     ← 起播：灌 3 个环
    sub_4B6C30 -> sub_48D610  676.3 ms / 146   ← Ogg 读 146 包
      sub_48D610 -> sub_4D90C0 502.4 / 147
        sub_4D90C0 -> sub_4E2A30 499.5 / 147   ← mapping0_inverse（floor/residue/coupling）
          sub_4E2A30 -> sub_4E4370 251.7 / 147 ← Huffman / 码本解码
          sub_4E2A30 -> sub_4E0B40 163.3 / 147 ← **本单**：FFT/MDCT（含 sub_4E08D0/sub_4E0760/sub_4E09D0）
```

⇒ 卡顿的构成：**熵解码 251 ms + 每次重建解码器 220 ms + FFT/MDCT 163 ms**（其余是耦合 / 位反转 / `__ftol2` 等）。本单只收 FFT/MDCT 这一段（用户口径：先做音频可接受的这一段）。

## 做法

- 真源 = **xiph vorbis v1.0.1 `lib/mdct.c`（v1.32）**；版本判据（全部钉在 `.lst`）：
  `sub_4E0030` = `mdct_init`（`[+0]=n` / `[+4]=log2n` / `[+8]=trig` / `[+0Ch]=bitrev`）、
  `sub_4E08D0` = `mdct_butterflies`（`log2n-6` 的 `jle` + 末段 `j+=32`）、`sub_4E0760` =
  `mdct_butterfly_generic`、`sub_4E09D0` = `mdct_bitreverse`、调用点 `0x4E2EAA`（`in == out` 原地）。
- 纯核 `mdctBackwardHost`（`src/runtime/native_mdct.{h,cpp}`）：逐行照抄 `mdct_backward` 与四个蝶形 +
  `bitreverse`；中间值用 `double`（见下一条的偏差口径）、落盘 `float`。
- guest 入口只做准入：`init` / `n` ∈ [64, 8192] / 2 的幂 / `log2n` / `in` / `out` / `trig(n+n/4)` /
  `bitrev(n/4)` 逐段 `committed()`，外加 `bitrev` 值域。**9 个回退原因都在任何写之前**判掉。

## 已知偏差（登记，不是缺陷）

1. **不是逐位等价**（本仓第一项"数值容忍档"）：偏差**不来自寄存器精度**（跑这条链的是 feeder 线程，
   `audio_cpu_.fpu.reset()` 把控制字设回 0x037F = 80-bit，与夹具缺省一致；主线程 CRT 的 `_PC_53`
   被它盖掉）。真因是 guest 编译后的 **float 溢出槽**：`REG_TYPE` 是 `float`，MSVC 在 x87 上大部分
   临时量留在寄存器，一部分溢出到 32-bit 栈槽（`.lst` 0x4E02F7 / 0x4E0308 / 0x4E0626 的
   `fstp [ebp+var_*]`，`var_*` 是 `dword ptr`）；本实现用 double 走"全程寄存器"那一支、不复现溢出点
   ⇒ 实测 `max|Δ|/peak` = **1.0e-7…1.5e-7**（n=64…8192）。⛔ 不要归因为 "x87 80-bit vs double"：把夹具精度
   改成 53-bit 复测，七个用例的 `max|d|` 一个数都不变。
2. `EAX` 登记为 0：guest 结束时它是 `out` 派生指针的残留（Hex-Rays 因此猜成 `float *`），唯一调用点 0x4E2EAA 之后不读它。
3. 不复刻 x87 的 PE/UE 粘性异常位（调用链上没人读它们）。
4. 函数级 override 的**相位偏移**照旧（跳过 N 条指令少走 (N−1)×100 ns 虚拟时钟）。
5. 可用 `--native-overrides all,-sub_4E0B40` 单独隔离。

## 落地时踩到的坑（写下来防复发）

- **`bitrev` 值域判据不能凭直觉收紧**：`mdct_init` 的真表是 `((~acc)&mask)-1`，取值 **`[0, n/2-2]`**，
  而且 **`bitrev[0]` 就是最大值 `n/2-2`**。一度把准入写成 `[0, n/4)` ⇒ 生产里**每个 n 都立刻回退**
  （`all` 里这一项 `hits=0`），而夹具表刚好落在窄区间内 ⇒ 两臂差分照样全绿。边界只能按**真实读取**
  算（`x0 = out+n/2+bit` 读 `x0[0]/x0[1]` ⇒ `[-n/2, n/2-2]`），并且夹具表必须覆盖**真表的范围**。
- **数值判据要单独数 NaN/Inf**：`if (d > maxdiff)` 对 NaN 恒 false ⇒ 一个 NaN 输出能让整条 `max|Δ|` 判据静默通过（实测：纯核末尾写 `out[0]=NaN`，旧判据一位不变、全绿）。

## 判据（红了意味着什么）

- `apps/emulator-lift/tests/native_override_assets.cpp` 的 `mdct/n=64|256|256/alias|1024|2048|2048/alias`：
  同一份 `mdct_lookup` + 同一份输入，**解释器臂（真 guest 字节 = oracle）vs native 臂**逐值比，
  `max|Δ| <= 1e-6 * peak`；并要求 `hits==1 && fallbacks==0`（排除"没接管 / 每次回退"两种假绿）。
- `apps/emulator-lift/tests/native_override.cpp`：准入零写（`trig` 未提交 ⇒ `out` 一字节不变 +

  哨兵不被写、成功路径 ABI（EIP/ESP/EAX）。

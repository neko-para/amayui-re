# 裁决 RES-RENDER-TEXT-SURFACE：写入循环三条支路进合同还是进 discards

## 要裁决什么

`CORE-OPS-RENDER-TEXT-204` 的字形写入循环（`sub_46D9F0`）里，**"什么时候覆写 / 什么时候加权 / 什么时候完全不写"
是引擎用 `cmp` 自己判的三条支路**，不是平台自由。现在 spec 把它们整体留在残差 `RES-RENDER-TEXT-SURFACE`
（`kind = unhandled`），需要一次**归属裁决**：进合同，还是进 `discards`。

## 证据已读全（不用再取证）

- 覆盖值 = 0 ⇒ **一个字节都不写**（32 位支 `0x46dd5e`/`0x46dd60`；16 位支 `0x46db11`/`0x46db13`）；
- 整像素覆写有两条判据：**通道值达到该表面的通道满值**（32 位 `0x46ddc0 cmp 0FFh`；16 位 `0x46db72 cmp 0Fh`）
  或**目标像素自身不透明度 = 0**（32 位 `0x46ddd5`；16 位 `0x46db88`）⇒ 写入 `(通道值<<高位)|源RGB`，**不读目标像素**；
- 其余 ⇒ 逐通道 `(源×通道值 + 目标×(满−通道值)) ÷ 满`、输出不透明度 = `max(目标, 通道值)`
  （32 位 `0x46de01..`/`0x46dddb..`；16 位 `0x46db9d..`/`0x46db8e..`）；
- 两条支路共用同一写入点（32 位 `0x46de89`；16 位 `0x46dc39`）。

## 两个选项（都需要一次"边界"取舍）

**A. 三条支路进合同**（把"哪条支路"与"输出不透明度 = max"写成条件；逐通道取整 / MMX 位模式仍进 `discards`）
- 理由：它决定**纹理内容**（提交物）的结构 —— 同一段文本在"透明画布"与"已有内容"上写出来的像素不透明度与颜色
  不同，这是可被独立实现复现的语义，不是逐位抖动。
- 代价：正文要多一节"写入支路"，且要给它一条可证伪观察（已有素材：AA 开、空白画布 ⇒ 墨迹 RGB = 源色原值，
  不透明度 = 覆盖值；AA 关 = 1 位掩码时逐像素只有 0/255）。

**B. 整体进 `discards`**（保持现状：残差 `unhandled` → 明确舍弃）
- 理由：`project-intent` 里"像素级表现不可判 ⇒ discards"的口径；引擎的写入循环与平台表面格式耦合（16/32 位）。
- 代价：丢掉一条**引擎自己判**的行为，且"覆写 vs 加权"会把"新画布上第一次写入"与"叠加"这两类结果混为一谈。

## 为什么这一条要人裁决

它是 **spec 边界**（合同 vs 舍弃）的取舍，不是取证问题 —— 证据已经读全（EA 在上）。
按本仓口径，边界归属由证据喂养、但**拍板不能由 agent 做**（`AGENTS.md` §6 的准入门与 `docs/00-origin/project-intent.md`
的"表现层不可判"之间有一条灰带，`discards` ≠ 平台）。

## agent 的建议（供裁决时参考，不代替裁决）

倾向 **A 的窄版**：只把「三条支路的判据」+「输出不透明度 = max」写进合同（这是结构），
把「逐通道乘除的取整、MMX 位模式、16 位降位后的通道打包」明确进 `discards`（那是逐位）。
理由：`0x46dd60`（覆盖值 0 一个字节都不写）与 `0x46ddd5`（目标 α = 0 ⇒ 覆写）两条会**改变后续叠加的结果**，
属结构而不属抖动；而取整顺序只影响 ±1 的像素值。

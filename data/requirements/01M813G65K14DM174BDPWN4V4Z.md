> 挂载理由：`loadSave(slot)` 本身就是这条插件运行时线 C2c 的交付（`scripts/plugins/lib/save.js`），本单收的是它"按槽号直接算行"那个缺陷面。

## 一句话

用户要求原话：「`loadsave` 里面应该要自行判断到底是哪一页」。原来 `loadSave` 按槽号直接算行 ⇒ 槽 ≥ 10 **必然点到屏外**；现在它**读页号 → 只翻左右箭头 → 每步等页号真的变 → 等列表刷新后才点行**。

## 页机制的读数（带命令 / 日期）

- 每页 **10 行**：槽 = 页 × 10 + 行；页号 = **可读的** guest int global **`0x138e`**（0..89、**环形**）。读数（2026-11-22 / win32 / `--present headless` + `emu-ctl`）：进屏 `global-get 0x138e` = **1** 且画面 `LOAD 010..019`；右箭头 `(1235,357)` ⇒ **2**；左箭头 `(45,357)` 2→1→0→**89**（`890..899`）。
- 翻页**只用左右大箭头**：左 `(45,357)` = −1 页、右 `(1235,357)` = +1 页（±1、环形）。
- ⛔ **顶部页签不是页号的写入口**（反例）：从页 1 点页签 0（x = 606 + 42k, y = 32），`0x138e` **连 60 个读点都还是 1**（`.tmp/save10-crash/page5.log`）。此前按"页签直接改页号"实现过一版，把 `plugin-runtime` / `plugin-headless` 的 `load-save-e2e` 钉在 `page not reached`（首轮全量 135/137）。
- ⛔ **进屏前写 `0x138e` 没用**：进屏第一段（`SAVE.BIN` 第 11 行 `load-int (global-int 138e)`）会从 `SAVE.DAT` 读回 ⇒ 换起始页只能靠进屏之后的翻页（读数与 EA 口径见 `repo:docs/03-emulator/save-format.md` §加载界面的列表与翻页）。

## 判据形状（怎么翻）

- 读当前页 → 按"**更短的那一边**"逐步翻 → **每步等页号真的变**（`atReadPoint` + 回调里读 global）→ 没动满 `PAGE_STALL_LIMIT = 60` 个读点 ⇒ 重试**一次** → 再满 ⇒ `finish(5, "load-save: page not reached …")`（⛔ 不假设"点一下就到"、⛔ 不用 `wait`、⛔ 不无限重试）。
- 翻完**再等列表刷新**（`SAVE` 回调体）才点行 —— 实测翻完立刻点会被吞（`load:sbunki` 30 s 超时）。
- 行 y 表补到 0..9（0–7 = 既有配方读数、9 = 截图核对 ≈626、8 = `91+59.5×8`）；槽上限 `MAX_SLOT = 899`。⚠ 槽 ≥ 100 的文件名字形**未取证** ⇒ 不声称能打开。

## 读数（手工端到端；**无自动化守卫**）

- 真翻页（`--plugin-param slot=5`，页 1→0）：`load-save: page 1 (target 0, slot 5)` → `page 0 reached` → `reached FIELD.BIN (slot 5)` → readout `run=done`（`calls=108`）。
- 槽 0..9 的既有行为未变（2026-11-22 / win32）：`ctest` 137/137 · `pnpm test` 614/614 · `pnpm verify` 500 pass / 2 skip。

## 为什么没有守卫

- 翻页是**业务正确性**（翻到了第几页 / 载入的是不是那份存档），`AGENTS.md` §12.4 明写**业务正确性不作判据** ⇒ 端到端读数进文档（本节的读数 + `repo:docs/03-emulator/save-format.md` 的翻页段 + `repo:docs/03-emulator/defects.md` 的 BUG-39 场景），不进默认门禁。
- 失败面并不因此消失：翻页退化成点页签 ⇒ 链会停在 `page not reached` / `gate timeout`（`plugin-runtime` 与 `plugin-headless` 的 `load-save-e2e` 钉的是**不翻页**那条链形状，所以它们只保证"退路没走歪"，⛔ 不保证"翻页逻辑对"）。

## 夹具调整（两处，理由）

- `repo:apps/emulator-lift/tests/plugin_runtime.cpp`：脚本化夹具**没有"进屏"这一步** ⇒ 必须把 `0x138e` **种成目标页**（否则 `save.js` 读到的不是目标页、会去翻页，整条链的坐标/拍数全错位）；`slot 9` 现在是合法槽 ⇒ 越界边界挪到 **900**。
- `repo:apps/emulator-lift/tests/plugin_e2e.cpp`：`slot=5` → **15**（= 同一份 `SAVE05` 再放到 `SAVE15`，页 1 第 5 行 = 进屏那一页）—— `calls ∈ {6,7}` 钉的是**不翻页**那条链的形状，翻页会把 calls 抬到 100+ ⇒ 判据失去意义。

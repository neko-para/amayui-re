## 目标

把「引擎 spec」当成**正式交付物**来生产，并用一个可计量的判据代替"看起来像"：
**每一行汇编要么被 spec 解释（绝对），要么被某个投影解释了一部分并写明未覆盖部分（局部），要么被明确排除（带理由）。**

## 已经定下的口径（本单的结论，不再重复讨论）

1. **四层本体**：机器本体（shape 提供，可靠 context）· 领域本体（引擎的实体 / 状态 / 操作 / 规则）· 边界契约（外部系统）· 平台实现（可替换）。
2. **shape 的地位**：它是**逆向 context**，不是 spec。offset / 布局 / ORIGIN / stride 是实现细节；spec 只放**指向绑定层的指针**（`storage`），⛔ 不许内联。
3. **计量单位 = 指令**（不是行、不是片段、不是人造"机制"）：指令客观可枚举，是唯一不会撒谎的分母。
4. **标记（mark）**：每个投影给指令打标；mark 分**绝对**（覆盖该指令 ISA 效果全集）与**局部**（覆盖一个**声明出来的子集** + 未覆盖原因 + 自由度）。
   ★ 局部不许是布尔值 —— 否则与绝对无法区分，遗漏就藏在那里。
5. **指令级守恒**：`E(指令) = ⊎(各 mark 覆盖的效果子集) ⊎ 残差`；残差 ∈ {内部未消费 · 外部未覆盖 · 明确排除(带理由)}。
   **外部未覆盖 = 遗漏点**；内部残差必须被某个外部效果消费（否则是死计算）。
6. **两个覆盖率口径**：`至少一个 mark 覆盖（粗）` 与 `外部效果被绝对覆盖（严）`。严口径才是"真的搞懂"。
7. **替换（放电）**：抽象替换是特殊 mark，必须带**覆盖范围**（哪些机器结构/指令效果），越界即红。
   已实测的两个样例：`池指针→地址代数/索引`（换算只在 2 处调用方）· `字符串值→JS string`（值 24B 可换，池槽 28B 不可换）。
8. **边界**：spec 只写到"引擎观察到的外部行为"（请求契约 + 参数），不写 D3D/Win32 细节；平台实现只需满足被观察部分（像素/混音逐位一致进 `discards`）。
9. **独立证据只有四类**：真机观测（人工、低带宽）· 游戏数据（高带宽，可批量反驳）· 三方文档/版本 · 第二实现（cleanroom）。
   ★ **投影一致只是内部一致性，不能证明与引擎一致**（共同误解不会被它发现）—— 这条必须写进任何"可信度"声明里。
10. **排除项按"一次性计数"处理，不按假设**：CPU 平台态（`fldcw/ldmxcsr/cpuid/rdtsc/cld/std`）· 并发（`lock`/线程 API）· 内存序（二进制侧 trivial，风险只在**重实现侧**）· 时序（boundary 可见 + 一条领域规则）。

## 两条后补的机制（"一条规则覆盖多指令" 与 "顺序"）

* **实例化：存 selector，不存实例。** 一条 spec 常覆盖成百条指令（例："∀ handler 开始时步进 ip"）。
  落点 = **选择器 + 检查器**，实例集合**每次重算**（符合"能机械读出的东西不进产物"，也就永远不会漂）。
  selector 优先级：已知集合（opcode 表 / 调用图）→ 模式匹配 → 手工列举（兜底，用于不规则情形）。
  ★ **反假绿**：必须同时报 `selector 命中实例数` 与 `selector 错配率` —— 宽 selector 会把覆盖率刷满而不说明问题。
* **顺序：约束是偏序（DAG），不是全序。** spec 陈述 → 边 `A ≺ B`；conformance = 二进制实际顺序是该 DAG 的**线性扩展**。
  与引擎状态无关的指令（日志 / 对齐 / 临时量）**不在 DAG 里** ⇒ 天然自由，⛔ 不需要"允许交换"这种例外规则。
  ⛔ 不许让内存投影兼职"可移动性"：它能证"没碰领域状态"，证不了"可以移动"。

## 未定（本单要做的事）

* **A 效果词表**（闭集合）：`mem / control / io / platform-state / timing / internal`；加一类要有理由，且影响守恒式分列。
* **B mark 最小字段**：`(selector, 投影, 局部|绝对, 覆盖的效果类集合, 自由度)`；
  `自由度 ∈ {序 · 寄存器/临时量 · 存在性}`（局部 mark 必须把"哪些方面不受约束"讲清）。
* **C 三张一次性扫描**（出数字，不出形容词）：平台态指令 · 并发/线程 API · 时序调用。
* **D 条目形态的落地**：两实体已试填（`.tmp/spec-draft/`，未入库）。结论：现有字段够，**缺 `storage`**；`identity`（身份/句柄/互逆）属**正文**不属字段。
* **E 序**：spec 陈述 → 偏序 DAG；判定 = 线性扩展；**顺序违规计入遗漏**（否则"逻辑对、顺序错"会被算成覆盖）。
* **F 反假绿**：`覆盖率（粗/严）`+`偏序满足率`+`selector 错配率` 三个数一起报，缺一不可。

## 判据（本单收口时）

1. 覆盖率报告可机械生成，**粗/严两个口径都给数**；
2. `遗漏点 = 0`，或全部落在"明确排除（带理由）"里；顺序违规已计入遗漏；
3. 每条"局部"mark 都带未覆盖原因与自由度；放电 mark 越界 ⇒ 红；
4. `selector 错配率` 与 `偏序满足率` 有数、且错配率不是靠把 selector 调窄来"修"的；
5. 每条 spec 规则至少能生成一个**可被数据或观测检验的预言**（否则它只是描述）。

## 反模式

⛔ 用"投影一致"当"与引擎一致"的证据；
⛔ 用"放电 / 基础设施"吞掉越界指令（越界即红）；
⛔ 把布局 / `ORIGIN` / stride 写进 spec（那是绑定层与参数）；
⛔ 把"假设"写成散文（要么一次性扫出数字，要么进排除理由）；
⛔ 再造一份与 spec 并行的"替换记录"（替换必须落在 spec 条目字段 + 绑定层上）；
⛔ 把"可交换"写成每条规则的例外（顺序自由应当由"不在 DAG 里"表达）；
⛔ 用一条宽 selector 把覆盖率刷绿（必须同时给出错配率）。

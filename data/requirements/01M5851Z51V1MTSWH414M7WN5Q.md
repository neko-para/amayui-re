## 背景与目标

本需求回应两个核心困难，而不是预设“把散文变成脚本就能证明正确”：

1. **没有原项目总体设计。** 必须从反汇编及可获得证据重建知识，不能以尚未核验的领域模型作为权威输入。允许从局部观察提出抽象候选，逐步核验与组合，不要求先恢复原作者的设计意图。
2. **纯自顶向下的 spec 与实现会共享误解。** 用户报告旧项目反复经历“发现问题 → 发现是实现错误”；需要缩短错误暴露链，区分理解、精化、绑定、遗漏与实现违约，不能只证明 emulator 满足自己的 spec。

主交付物仍是可独立实现的领域 spec。本需求要建立方法，回答：**一条 refine（精化）论述处理 / 替换 / 明确舍弃了哪些机器行为，哪些尚未处理，下一步应补 spec、论证可省略还是继续研究？**

**覆盖系统是精化范围与残差审计，覆盖率只是摘要。** “精化为什么成立”与“精化处理了什么”分别呈现；范围闭合不证明解释正确，局部解释有依据也不证明没有遗漏。

本单仍是方法讨论：效果模型、指标、条目落点与自动检查策略未定案。允许已有有效依据支撑的局部样例，不承担全域语义清零，也不批准通用形式语言或符号执行器建设。

## 已明确的原则与保证边界

1. **两层本体与边界**：机器本体（shape）· 领域本体（spec），另有边界契约与可替换的平台实现。spec 不内联 offset / 布局 / ORIGIN / stride，引用机器绑定；项目 intent 见 `docs/00-origin/project-intent.md`。
2. **不建手工汇编转写层**：不要求先维护“完整函数伪代码 / 行为散文”才生产 spec。shape 声明是待核验模型，扫描、CFG、数据流及报告是派生视图；视图辅助理解、可重算、可追溯，不成为独立证据或第二语义真源。
3. **精化绑定属于 spec**：呈现抽象合同、适用上下文、机器范围、机器—领域状态对应关系、成立条件、核验依据与残差。`storage` 不只用于定位，还需配合状态映射解释抽象；布局引用 shape，原子结论引用 ledger，不另建替换台账。函数与领域操作可以多对多。
4. **候选不是事实**：局部核验可先得到有条件的解释；入口不变量和调用摘要需追查由谁建立 / 保持。依赖未知或失效时保留未判或降级，不把假设当成已证结论。
5. **检查器是可执行投影**：明确检查哪些属性、哪些正文未被机械核验。正负例与变异用于检查判别力，不能证明自然语言忠实度。守恒只证明归属记账，没有自动证明值、条件、对象身份或语义正确。
6. **处理状态必须可区分**：spec 处理 / 替换 · 有依据的实现内部省略 · 明确舍弃（理由、范围、影响）· 尚未处理 / 无法判定。未知不得静默变为省略或舍弃，同一指令的未处理部分必须保留。
7. **替换（放电）有范围**：声明 `preserves / discards / chosen` 与机器结构 / 行为义务范围，越界即红。不在领域顺序约束中，不等于可交换、可省略或无副作用。
8. **有限可观测边界**：spec 写到引擎观察的边界请求、参数与必要时序；不要求平台实现逐位复现像素 / 混音。项目没有运行原引擎做内存差分 / trace 的条件；局部离线指令语义核验仅是可讨论策略。
9. **证据与可信度**：独立证据四类仍是真机观测、游戏数据、三方文档 / 版本、第二实现。派生分析与投影一致只支持内部核验，不证明与原引擎等价；共同误解不能排除。
10. **结构闭合不是语义上限**：shape 的 L0 支持结构分析与债务定位，不代替直接调用摘要或领域含义。按具体精化依赖与未知影响判断，不能以函数闭合度直接换算效果覆盖率。

## 候选机制（未批准实现）

* **指令 / EA 账本 + 局部 mark + 效果守恒**：指令提供枚举与追溯底数，不是正确性的分母。mark 记录精化实际处理的子集与未处理部分；“绝对 / 局部”若保留，只能相对于明确效果模型，不可暗示已证明 ISA 效果全集。
  守恒按义务统计去重；多条 spec 可以共同解释同一义务，不强迫语义投影互斥。未知调用、隐式效果与模型外内容必须在账上，不能默认内部计算被消费或无影响。
* **selector 存规则，实例重算**：已知集合 → 模式匹配 → 显式 EA 兜底是候选策略。固定语料、分析版本、摘要、依赖状态与配置，报告命中与错配；召回缺口需独立“应适用集合”，否则报告不可测。现算不等于没有失真。
* **必要顺序用偏序表达**：明确路径条件、事件作用域与重复事件；静态检查仅在相关控制流完整、判据适用时给结论。支配关系不是通用顺序证明；违例 / 满足 / 不适用 / 不可判分列。已知违例阻断对应处理结论，未知边不能支持通过。
* **覆盖指标由处理账派生**：可讨论指令粗覆盖、已解析效果的完整处理比例、未知 / 舍弃数量、选择器与顺序指标；具体命名与公式未定。不能用一个严覆盖数字同时代表范围完整、规格充分与语义正确。

## 未定（本单要做的事）

* **A 计量与效果模型**：确定账本候选域、效果粒度、未知表示与统计去重。候选类别 `mem / control / io / platform-state / timing / internal` 不构成已批准词表；调用点摘要与被调方站点不可无说明重复计数。
* **B 范围标记**：处理子集、未处理原因、成立条件与自由度如何呈现；内部省略、明确舍弃和未知怎样防混淆；替换范围如何判越界。
* **C 边界普查**：平台态、并发 / 线程与时序可以先扫描出候选，不因扫描结果就自动排除，也不先声称它们对原实现无影响。按合同依赖决定哪些保留、舍弃或未判。
* **D 精化条目与落点**：领域合同 + 状态对应 + 机器范围 + 证据 / 核验 + 残差，和 shape / ledger 单向引用并传播依赖失效；已有草稿仅作讨论样例，不等于字段已充分或语义已接受。
* **E 核验能力**：确定 selector 适用性、局部顺序、计算关系等哪些自动检查，哪些人工核验或未判；是否试点局部离线符号执行另行裁决，不要求先建通用证明器。
* **F 报告与试点**：双向追溯、逐项残差、机器覆盖 / 检查判别力 / 符合性证据分开；确定有限试点域、输入身份、范围变更解释与后续批次比较方式，不预设全局百分比目标。

## 判据（方法单收口，不是全域内容收口）

1. 有限试点中，能从一条精化查到处理 / 替换 / 舍弃的机器范围，也能从机器站点查到对应规则或残差；绑定包含状态对应、条件与有效依据，不依赖手工转写副本。
2. 固定试点域内，**未登记义务 = 0，未解释 / 未判义务允许非零**：所有候选站点和已识别效果都被登记或列为残差，识别不出的部分仍明确报告；舍弃不能冒充解释，残差带下一步问题。不得以“全域遗漏 = 0 或全排除”验收方法。
3. 局部处理不会吸走剩余效果；放电越界、错误省略 / 舍弃、依赖失效有会红的守卫与变异；重叠解释不重复统计，调整候选域不会被误报为解释进展。
4. 检查器列明其对正文的可执行投影；有依据的正例和关键错误变体核验判别力。selector 多选 / 漏选与顺序违例不会冒充通过；缺独立适用域、未知控制流或超时等报告不可判 / 不可测，而非绿。
5. 样例规则有可证伪的核验问题或预言，注明哪些由机器侧推导 / 检查支持、哪些可由数据 / 观测反驳、哪些尚未核验。覆盖闭合但语义错误不由覆盖系统保证检出；已有检查若不能区分必须写明边界，实现合同检查也不成为原引擎 oracle。
6. 试点能展示范围审计对合同缺项、遗漏或错误定位的收益及维护成本，形成继续 / 缩小 / 替换策略的决定。后续语义批次另设内容判据，在固定输入与范围下比较残差；新发现及分析变化显式解释，不预定整族或全域严覆盖 100%。

## 反模式

* 用覆盖率、效果守恒、投影一致或第二实现一致当作“解释正确 / 与引擎等价”的证明。
* 先维护完整汇编转写再生产 spec；将派生视图当独立证据，或另建并行替换台账。
* 给函数区间贴“完成”就默认其全部效果被处理；强迫函数与高层操作一一对应。
* 用放电 / 基础设施 / 不在 DAG 吞掉越界或未知；仅因没有找到消费者就宣布死计算或可舍弃。
* 把未知条件写成已证事实，或把所有未判项塞进排除；把布局内联进 spec。
* 用宽 selector 刷覆盖、用窄 selector 降错配；没有独立集合仍宣称召回完整。
* 把“未找到反例 / 未执行 / 超时”当通过，或把本方法单收口等同于全量语义完成。

## 一句话

参考实现已跑到 `#71` 的第一条 `0x3 call-script 21080`（LOADCONFIG）。**这条不能靠猜**：它要求"多脚本"（换 body、帧号 +1、返回位置写父帧），而 `0x2 exit` / `0x9 exit-script` 到底是"整机结束"还是"子脚本返回父脚本"**没有观察**。本单是**限时设问**：取证 + 设计，产出是结论而不是代码。

## 要回答

1. `0x3` 的完整语义：操作数口径（统一文件 id？）、装载失败表现、返回位置写父帧哪一格（dword 序号/字节、是否 +3）、局部池是否隔离。
2. 子脚本结束谁还控制权：`0x2 exit` / `0x9 exit-script` 的逐字与**分叉判据**。
3. `Machine` 需要新增什么状态（脚本栈 / 父帧返回槽 / 帧号 / 池隔离），三件（`0x3`/`0x2`/`0x9`）各自实现要点，**哪些点必须留残差**。
4. 2–3 条会红的守卫草案。

## 现成证据（不重复验证）

- `0x3` handler `sub_41C6A0`：`0x41C736` 存旧帧号、`0x41C73D` 帧号 +1、`0x41C724` 返回位置写父帧 `+0x5D8F0`（不 +3）、`0x41C746` → `sub_40ED40` 装载（GlobalAlloc / ReadFile / `SYS4` 头校验）。
- `0x5 ret` 的跳转路径还会从引擎级栈 `+0x68EB0/+0x68EB4` 弹值写 `+0xAAB44`（用途未定）。
- 根脚本 `#67/#68/#70/#71` = `0x3`（21080/20931/20956/20936）；`#114` = `0x3 21089`；`#134` = `0x3 21090 = LOGO.BIN`。
- `LOADCONFIG.BIN` 末尾有一条 `0x2 exit`。

## 不做

- ⛔ 不为了推进棘轮把 `0x3` 当 no-op（那会跳过被调脚本的状态，属于静默分歧）。
- ⛔ 不在没有观察的情况下写"`0x2 exit` 一定返回父脚本"这类断言。
## 结论（取证已完成，2026-10-20）

**分派器两条规则**：`帧+0x60` = 本条长度（`2·argc+1`），handler 入口写、写 0 = 不自动推进；推进在 handler **返回之后**、用**返回后那一刻的当前帧**（`帧.ip += 4×帧+0x60`）—— 这是多脚本成立的唯一机制。

**`0x3 call-script`**（`sub_41C6A0`）：先写 `长度=3` 再查深度（`F>=39` ⇒ 报「階層が深すぎます」）；读操作数（带类型标签）；把**父帧** `+0x5C ← (ip−codeBase)>>2`（本指令自己的 dword 序号，**不是 +3**）；`[0x5D884]=F`、`F++`、调 `sub_40ED40(id)` 装载；装载失败 ⇒ `Exit(2)`。装载器给子帧**新分配并 memset 每个池**（局部池不继承）、`子帧.ip=codeBase`、`子帧+0x60=0`。★ `+0x5C` 全二进制**无读点** ⇒ 别拿它算返回。

**`0x2 exit`**（`sub_41A820`）：读 `帧+0x38`（父帧号）—— **≥0 ⇒ 子返回父**（必要时释放子帧、`[0x5D880]=父号`、父 `+0x5C = −1`）；**−1（根帧）⇒ 整个执行结束**；−10/−11 是存档专用。★ 它**一处也不写 ip**：父帧 ip 仍是调用指令起点，下一迭代用**父帧自己的长度槽（仍 3）**推 12 字节到"下一条" ⇒ 返回点是算术结果。

**`0x9 exit-script`**（`sub_428A60`）：**不是返回** —— 释放全部 40 帧、复位全局池、重读配置、以**统一文件 id 0** 重装根脚本进 0 号帧，**永不回调用者**。分叉判据：`0x2` 看帧号，`0x9` 全局重置。

**参考实现的最小增量**（下一轮照此落地）：`frames: Frame[]` + 每帧 `{body, ip, 局部池, retStack, length, parent, callSite}`；`run()` 在 handler **之后**重新取当前帧再推进；`0x3` 先写 `length=3` 再建子帧；`0x2` 回父帧并让**父帧自己的 length** 去推进；`0x9` 清空全部帧并以 id 0 重装。

**必须留残差**：`+0x5C` 的读者（无）；引擎级 `Stack<int>`（`0x68EA4`，弹出→状态字）语义；`0x9` 的领域名与可达性；`0x3` 失败后的状态残留（帧号已 +1）；深度/栈溢出边界；`0x2` 的 −10/−11（存档语义）。

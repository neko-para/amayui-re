## 补充事实（本轮查证）

- 该条**不是**文件系统的大小写问题（路径由引擎自己拼 `SYS4REG.INI`，与 FS 敏感无关），而是**两个输入通道把名字匹配到固定词表**时的比较方式：
  1. **索引尾部默认表**（`SYS4INI.BIN` 尾部那 N 对键值）：键是 ASCII **大写**名，引擎用 **`__stricmp`** 比（逐字 `.lst:004942FD` 比 `"REGROOTPATH"`、`.lst:0049439E` 比 `"REGSUBKEY"`）；emulator-new 的 `applyDefaults` 也先 `toUpperCase()` 再查。
  2. **玩家文件 `SYS4REG.INI`**：spec `:94/:109` 与 `format/config-keys.md:12` 说**字节精确**；emulator-new 的 `applyIni` 用 `${section}\\${key}` 精确查表（不做折叠）。
- 矛盾句是 `:25`：「键名按字节精确匹配；大小写不敏感只发生在"把输入里的名字匹配到固定词表"这一步」——"输入"没指明是哪一条通道，按字面可被读成玩家文件也折叠大小写。
- ★ 缺的证据：**玩家文件侧的键比较原语**。要定论，先在 `.lst` 里找 INI 解析函数对键/段名的比较（`strcmp` vs `stricmp`）；若引擎对玩家文件也用 `stricmp`，那 `:94/:109` 与 `format/config-keys.md` 才是要改的一边。

## 裁决（2026-10-21）：两个通道口径不同 —— 按实现收窄正文

源码核对（用户要求"检查 spec 对应的源码，比照实现"）：

- **索引默认表**（`SYS4INI.BIN` 尾部 N 对键值）：键名是 ASCII 大写；解析器用 **`__stricmp`** 比表项
  （逐字 `.lst:004942FD` 比 `"REGROOTPATH"`、`.lst:0049439E` 比 `"REGSUBKEY"`）⇒ **大小写不敏感**。
- **玩家文件 `SYS4REG.INI`**：读取路径先拼 `段名 + "\\" + 键名`（`sub_4957F0`），再按**字节**做映射查找
  （`sub_428F10`：`eax = eax*33 + movsx(字节)` 的哈希 + `sub_401000` 的 memcmp + 长度相等）⇒ **字节精确，大小写敏感**。

⇒ 两处说法各自只对一半：`:94/:109`（玩家文件字节精确）与引擎一致；`:25` 的"大小写不敏感"只对**索引默认表**成立。
已按实现收窄 `:25`：「键名按字节精确匹配。**只有索引默认表**的键名在匹配固定词表时折叠大小写；**玩家文件**的段名/键名按字节精确匹配（见「玩家文件」）」。

# ADR 补遗 · 地址空间区域容量：初值 0 + 按需增长（每次留痕），不先去取证全局池容量

- id: REQ-01M4B969TBWVERFCB1MXS2Q2E1
- type: decision
- status: done
- done_reason: 已裁决：区域容量 = 初值 0 + 按需增长（每次增长留痕）。依据两条已登记事实：① 引擎池读/写没有上界检查（越界是 UB，不是语义）；② 全局池容量字段（Engine+0x0AAB08 一族 / 0x5D7E8 一族）在整份 .lst 里无 store ⇒ 按"必须拿到来源"会永久卡住。不违反原 ADR 的"不编默认值"：初值 0、增长由真实访问触发且逐次留痕。后果：ADR 第②③步（池→区域、指针族）可以开工；local 池容量用头部 dword 8..13。

## 决策

**地址空间的区域容量采用「初值 0 + 按需增长、每次增长留痕」**，而不是"先去把引擎的池容量字段全部取证"。

## 为什么（两条已登记的事实，不是偏好）

1. **引擎对池的下标访问没有任何上界检查**（锚 = EA：`sub_41BF50`/`sub_42B4B0` 的全部 `cmp` 都是**类型**检查
   —— `cmp edx,8003h`/`0Dh`@`0x41BF7E/0x41BF90`、`cmp ecx,8003h`@`0x42B501`、`sub ecx,3; cmp ecx,9`@`0x42B513`；
   索引直接 `基址 + idx*4`：读 `mov edx,[eax+edx*4]`@`0x41BFE3`、写 `mov [eax+edx*4],ecx`@`0x42B555`）
   ⇒ 越界是 **OOB 访存（UB）**，**不是一种语义**。本层**不模仿 UB**（这正是地址空间"越界要响亮失败"的依据）。
2. **全局池的容量来源查不到**：`Engine+0x0AAB08/0C/10/14/18/1Ch` 与计数 `Engine+0x5D7E8..0x5D7FC`
   在整份 `.lst` 里**没有任何 store**（只有 `0x415151–0x415189` 的拷贝）⇒ 按"必须拿到来源"的口径，
   全局池会**永久卡住**，而它是 `INITCONFIG4`/`LOADCONFIG` 循环的必经之路。

叠加事实：**local 池的容量已经拿到**（头部 dword 8..13；计数槽 `帧+0x1C..0x30` —— 这一条新旧证据一致）。

## 为什么这不违反原 ADR（`REQ-01M4ARC3CPM00CC1KC4Q3HF550`）

原 ADR 的要求是「`capacity` **必填**、**本层不编一个默认值**」。本决策：
* 初值 **0**（= 不编任何常数）；
* 每次增长都由**一次真实访问**触发，并**逐次留痕**（`region.grow` 记录：池、下标、旧/新容量）；
* 增长的容量来源是**被访问的下标**（可复算），不是猜的常量。
⇒ 它满足"不编默认值"，并把"引擎那边是 UB"这件事**显式记成一条与真机的差异**，而不是假装容量已知。

## 后果

* ADR 第 ②③ 步（池存储换成区域、指针族接上）**可以开工**：local 池用头部计数当容量，global 池按需增长。
* 判据（照 ADR）：**既有守卫全绿** + 新增一条"经地址空间读到的池值 == 经池 API 读到的值"。
* ⛔ 不许把"增长"实现成静默：每次增长都要在副作用日志里看得见（否则它会变成"悄悄把越界放过去"）。
* 仍需取证的（登记着，不阻塞）：`Engine+0x0AAB08` 一族与 `0x5D7E8` 一族的**写入点**。

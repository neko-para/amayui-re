## 要查的四件（每件都写清"查什么 / 锚在哪"）

1. **`sub_42B4B0` 的 case 7（type 0xA）与 case 12（type 0xC）为什么用不同池**
   逐字线索：`+0x5D820` vs `[esi+edx*8+0x5D8C0]`。★ 判据 = 两条 case 的池基址各自被哪个**装载器**填（`sub_40ED40` 一族）—— 只有"取址原语 case 号 ↔ 装载器 store"双向对上才算查明。
2. **写侧 `0x8005`（字符串数组句柄）是否存在分支**
   对照读侧在 `0x41C0D7`。★ 判据 = 在写侧 handler 体内逐字找 type 0x8005 的比较；"没找到"要写成"在这个函数体里没有"，**不是**"引擎没有"。
3. **`sub_41C300`（float 读，全语料 57 调用方 / 165 处）与 `sub_42BA00`（float 写，15 / 31）**
   ★ 判据 = 与已取证的整型对手（`sub_42AEA0` 取址 / `sub_42B4B0` 写值）**逐指令对照**，把"同形"与"真不同"分开写。`disasm-at cases` 已确认 `jpt_42BA6F` 11 项、default 同样占 5/8/11。
4. **`sub_4034C0` / `sub_4034D0` 的内层对象类型**（`this+4` 指向什么）
   逐字线索：`0x4034C3 mov ecx,[ecx+4]` → `jmp sub_497620`；兄弟 `0x4034E0` 用 vtable 槽 `+8`、`0x4034F0` 用 `+4`。★ 判据 = 找到**装 `this+4`** 的那一侧（构造/赋值点），而不是从被调方反推类型名。

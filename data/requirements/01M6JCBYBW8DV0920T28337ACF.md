## 一句话
`guestFault` 用的 `AccessSite` 来自 `thread_local g_access`（最近一次 guest 访存）；**宿主自己**的 AV 也走同一条路，
于是诊断把宿主 bug 报成 `guest WRITE 0x…`，指向一条无关的 guest 指令。已按"异常地址归因"修复。

## 落地（2026-11-04）
- `apps/emulator-lift/src/runtime/memory.h` / `memory.cpp`：
  - 新增纯函数 `inGuestSpace(guest_base, fault_addr)`（减法判区间，`base + kSpace` 不溢出）；
  - 新增 `hostFault(fault_addr, why)`：打 `=== host fault（宿主自身的异常，不是 guest 访存）===`、host 地址、guest 区间、
    一行"最近 guest 访存（可能无关）"；**不含** `access     :` 行；`_Exit(4)`；
  - POSIX `segvHandler` / Windows `vectoredHandler` 都改为**先按异常地址归因**：guest 空间内 ⇒ 原 `guestFault`
    （EA/宽度/方向 + `_Exit(3)`，行为不回退）；空间外 ⇒ `hostFault`。Windows 不再 `return EXCEPTION_CONTINUE_SEARCH`。
- 新增 pure CTest `fault-report`（`tests/fault_report.cpp`，19 checks；Windows 的 fork 用例 `LIFT_SKIP`=77）：
  ① `inGuestSpace` 边界（base / base+kSpace-1 / base+kSpace / 0x1 / nullptr）；
  ② POSIX 子进程：先弄脏 `g_access`、再解引用 `0x1` ⇒ 有 host fault 标记、无 guest 标记、无 `access :` 行、退出码 4；
  ③ 反向：safe 模式读未提交页 ⇒ 有 `access : READ 0x20000000  size=4`、退出码 3。
- 守卫自检：把 `inGuestSpace` 改成恒 `true` ⇒ `fault-report` **红**（7 failures，`access : WRITE 0x00401000` 复活）；
  还原后 `cmp` + sha256 全文一致、重建再跑绿。`pnpm test:mutation --match fault-report` 也按预期红（CTest 退出码 8）。

## 保留 / 已知边界
- Windows 真机执行未跑（本机 macOS arm64）：Windows 分支只做了 `-D_WIN32` 的 `-fsyntax-only -Wall -Wextra -Werror` 语法检查。
- 退出码 `4` 只在代码注释与用例里（未进 `SCOPE.md`；那是"诊断口径"不是用户可见偏差）。

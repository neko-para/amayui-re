# AOT · COM trampoline 去税：SetRenderState / SetSamplerState 再砍一半

- id: REQ-01M86NP8R79FE25CSMMV86JE31
- type: req
- status: done
- parent: REQ-01M7JHSEZVMYB4XHEN32V7V6HJ
- done_reason: 主判据达标：SetRenderState 469.2→279.9 ns（配对中位 −186.3，5/5）；SetSamplerState 534.3→325.6（−206.3，5/5）；五项指纹逐位同；com-dispatch-shape 6 条 + mechanism 两条新 case，变异 1/1 红；线程不变式按 guest 令牌改写（数组裸指针、无需 atomic）。未做：userOf 第 3 次查找/第 2 把锁、C5、全量变异。
- tags: [emulator-lift, aot, shim, perf]

## 一句话

shim 固定税那一批（`200ab91`）把 `SetRenderState` 775.7→**429.4 ns/次**、`SetSamplerState` 807.3→**500.7**，
但 COM 接口调用还多付一层 `ComRegistry::dispatch`。本单把 dispatch 的固定税砍下来。

## 读数（2026-11-23 / SAVE11 8 s 窗口 / 5 趟中位）

| shim | 现在 | 目标（只作方向） |
|---|---:|---:|
| `IDirect3DDevice9::SetRenderState` | **429.4 ns** | 配对差 −120…−180 ns |
| `IDirect3DDevice9::SetSamplerState` | **500.7 ns** | 同向 |
| 窗口调用量 | `SetRenderState` **1.04–1.13 M** / `SetSamplerState` 263–303 K | — |

## 取证修正（2026-11-24 只读）

- 每次 `SetRenderState` 实际付 **2 把 `recursive_mutex` + 3 次哈希 + 2 次 `std::string` 堆拷贝**
  （16/33 字符都超 SSO）：`dispatch` 的 `methods_` / `objects_` + `method` 体内
  `deviceStateOf → userOf` 的第 3 次查找与第 2 把锁。
- `known_this` **只喂一条 Info 日志**（不改变返回值/转发）⇒ 可以按 `logVisible(Info, LogCom)` 门控。
- **没有 `com-*` 这个 CTest**；COM 语义面在 `mechanism` / `d3d9*` / `d3dx9*` / `dshow-graph`。
- `1.03 M` 是估读；窗口 `N` 实测 **1.04–1.13 M**（判据用同一趟的 N，⛔ 不混用）。
- **`recursive_mutex` 不能全局换 `shared_mutex`**：`createObject → generationOf`、`releaseImpl` 递归。
  只在 **dispatch 的读侧**免锁（`methods_` 只插不删 + 按槽数组发布后不改）。
- 「~200 ns」没有算术来源 ⇒ 判据改成**相对 429.4 的配对差 + 方向**；绝对值只作读数。

## 方案（C1–C4 + C6；锁先不动）

1. **C1**：`com.h` 加 `std::vector<const MethodEntry*> method_by_slot_`（`slot=(stub-page)>>2`，
   页外/未对齐/未登记 ⇒ 回落 `methods_.find`，照 `ShimRegistry::byStubEa` 的"快路径 + 慢路径"）。
2. **C2**：`registerSlot` 在 `emplace` 成功后写数组（首次从 `cpu.shims->stubPage()/stubSlots()` 取页参数）；
   `methods_` 从不 erase ⇒ `MethodEntry*` 稳定；⛔ 不拷贝 `MethodEntry`（含 2 个 string）。
3. **C3**：`dispatch` 只留 `const MethodEntry*`，`iface` / `name` 只在 `!known_this` 分支取。
4. **C4**：`known_this` 用 `logVisible(Info, LogCom)` 门控；`objects_` 仍走 `recursive_mutex`。
5. **C6**：`tools/test/shim-fast-shape.test.mjs` 加源码谓词（dispatch 体里没有 `iface = e.iface` /
   `name = e.name`；`known_this` 在 `logVisible` 之后）。

## 判据

- **主判据**：同一 boot/SAVE11 窗口、5 趟中位 ⇒ `SetRenderState` **配对差 ≥120 ns（方向为负）**；
  `SetSamplerState` 同向；⛔ 不把「~200 ns」写死；
- 五项指纹（`exit` / `stop @` / arena / `table misses`）逐位同；
- `ctest -R 'd3d9|d3dx9|mechanism|dshow-graph'` 绿；`ctest` / `pnpm test` / `pnpm verify` 全绿；
- 守卫：`com-dispatch-unknown-this`（`mechanism` 新 case：非本 registry 的 `this` ⇒ 仍打那条日志，
  用 stderr 捕获，⛔ 不只断言计数器）+ `com-dispatch-shape`（源码谓词）；
- 变异：把 `iface = e.iface; name = e.name;` 加回热路径 ⇒ `com-dispatch-shape` 红。

## 边界

- ⛔ 不改 COM 对外语义（vtable 槽、QI、引用计数、错误码）；⛔ 不引入运行期 override 表。
- ⛔ 不动 `createObject` / `releaseImpl` 的递归锁；`userOf` 的第 2 把锁**不在本单**（要动它是「对象状态缓存」，
  另开）。
- ⚠ `<待核>`：`com.h:34` 与 `com.h:258–260` 的线程假设自相矛盾（单线程 vs feeder 并发）；实现前先确认
  "注册是否可能发生在 feeder 线程"——这决定数组能否无锁发布，或必须 `atomic<const MethodEntry*>`。

## 结果（2026-11-25 / win32 / dev）

- **主判据（5 趟交错 A/B，SAVE11 8 s 窗口）**：`SetRenderState` 窗口表 **469.2 → 279.9 ns/次**，
  配对差 −208.6 / −212.6 / −180.6 / −178.7 / −186.3 ⇒ 中位 **−186.3 ns（5/5 负，≥120 的余量 1.55×）**；
  相对历史 429.4 ⇒ −149.5（本场 base 偏慢 ~9%，主判据取本场配对差）。`SetSamplerState`（采样表）
  **534.3 → 325.6**，配对中位 **−206.3（5/5 负）**。
- **五项指纹**（30 帧定长 boot，base/final 各 2 趟）逐位同：`exit=0` / `frames=30` /
  `stop @ 00498AE4` / arena(108595152,21,6687) / `misses=0`。
- **守卫**：`com-dispatch-shape`（6 条源码谓词）+ `com-dispatch-unknown-this`（stderr 抓那行字）+
  `com-dispatch-out-of-page-stub`（页外 stub 回 `methods_.find`）；变异 1/1 红（string 拷贝加回热路径）。
- **线程**：数组读不持 `mutex_`、写在 `createObject` 锁内；真正串行化 = **guest 令牌**
  （`invokePrepared` / feeder `invokeById` 都持令牌）⇒ 裸指针发布，无需 atomic；`com.h` 注记已按此改写。
- 门禁：`ctest -R 'd3d9|d3dx9|mechanism|dshow-graph'` 12/12；默认 141/141；`pnpm test` 627；
  `verify` 472 pass；`validate` 6/6。
- **未做**：`userOf` 第 3 次查找 / 第 2 把锁（到 ~200 ns 的剩余）、C5（写侧锁改造）、全量变异扫描。

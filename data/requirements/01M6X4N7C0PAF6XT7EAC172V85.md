# emulator-lift · 修 SetRenderTarget 的像素块生命周期：纹理作为 render target 时被销毁，流水线仍指已释放的 arena（缺语义 addRef）

## 判据（存在性 + 观测）

- 位置：`repo:apps/emulator-lift/src/runtime/d3d9_pipeline.cpp` 的 `SetRenderTarget`（锚 = `kPlColorArena`）：
  它把"当前颜色目标"的 surface 与像素块记进流水线属性。
- 判据：纹理被当作 render target 之后、**没有先换 target 就释放它** ⇒ 纹理的像素块与状态块被回收，
  但流水线属性仍指它们 ⇒ 之后任何读这两个属性的绘制（Clear(TARGET) / 回退 / 读回）都落到**已释放**的 guest 内存。
- 现状为什么不可复现：游戏的任务顺序里"换 target"总在"释放纹理"之前发生 ⇒ 没有可观测分歧；
  这是**时序前提**，不是安全性证明（顺序由游戏数据决定，不是本仓能担保的不变量）。
- 怎么验（将来）：夹具里按"绑定为 RT → 不换 target → Release 该纹理 → 再画一笔"的顺序造，
  并让 arena 复用同一地址 ⇒ 判据是"新占用者的像素不许变"。

## 为什么现在不做（guest 域后果）

- 后果落在 **guest 域**：写进已释放 / 已被别人复用的 guest 像素块，宿主不崩、也不报警，画面或后续逻辑才错 ⇒ 排查成本高。
- 修法边界（给将来的 agent）：让"被绑定为 RT"这件事对像素块产生**语义 addRef**（在换 target / 释放时成对释放）；
  ⛔ 不是在释放处把属性清零 —— 那会把仍在绑定中的 RT 静默换成后缓冲，等于改语义。

## 与别的单的关系

- 同一条生命周期线三张单：**回收路径**（`REQ-01M6WTRF0X6362NK8BNK8DHHWJ`，已收口）、
  **绑定引用**（本单）、**对象表代际**（`ComRegistry::release` 那张）。三者互不重叠。

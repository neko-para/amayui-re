## 这条要做什么

`pnpm tools ledger coverage` 把"引擎还有多少没登记"变成一张**机械可复算的工作清单**。
本节点收口从这份清单派生的取证任务：**把前沿里的函数一个个变成可再校验的台账条目**。

## 判据（每个子节点都按这个收）

1. 台账里出现一条该函数的观察，**锚 = 二进制 EA**（函数起点 + 关键分支/跳转表）；
2. 该观察**不是复述 C 体**：要能回答"它是什么 / 它碰了哪些引擎字段 / 它的调用者依赖它做什么"；
3. 若它能被机械判 ⇒ 顺手给一条**会红的守卫**（或明确写"缺哪个观察才能判"）；
4. 跑一次 `pnpm tools ledger coverage`，看该函数的桶位是否从 `unobserved` 移出，
   **并把它的 callee 里新暴露的未登记函数登记进后续节点**（前沿会滚动，这是设计的一部分）。

## 怎么挑下一个

```bash
pnpm tools ledger coverage --top 20    # 直接调用前沿（按调用方个数降序）
```

★ 前沿 = **未被登记、却被已登记函数直接调用**。排在前面的就是"最多人依赖的洞"。
★ 传递可达 413 个（1 跳 106 / 2 跳 123 / …）—— 它只是**下界**：语料里有 3000+ 个解不出目标的调用点
（`call eax` / `call dword ptr [...]`），所以"闭包完整"这句话永远只是近似。

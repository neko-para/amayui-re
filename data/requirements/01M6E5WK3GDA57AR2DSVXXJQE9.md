## 1. 纵向对齐（`sub_4573A0`）

- `sub_4573A0` 是**布局字符格序列**的纵向读者：按格 `+0x14` 归组、参与判据 `格+0 == 0`、
  矩形 = 格 `+8/+0x10`、种子 `层+0x28`（高拷贝）/ `层+0x20`（文本原点 y）；
  模式 1 Δ = 基准 − trunc(跨度/2)，模式 2 Δ = 基准 − 下界 + 上界，模式 0 不参与，其它 Δ = 0。
- **调用方只有 `sub_45B2B0`**（层记录 `+0x70 == 1` 的另一条绘制入口）；ADV 可见的逐字路径
  `sub_45BE20` 只调横向 `sub_4572A0`（锚 `0x45c1e1`）。⇒ 要落纵向，得先建模那条入口，
  不是给现有逐字条目补一个 Δy。

## 2. 120B 行记录日志

- 排版侧把行命令写进层记录 `+0xD0` 的 120 字节向量（`sub_45E870`），`0x71` 清它；
  读侧横向 `sub_4574A0` / 纵向 `sub_4575B0`。本模型只建 24B 布局字符格，未建模这条序列。
- 它与「列表侧定位记录」是两条不同的序列（见 `62-adv-text` 的「行记录日志」段）。

## 3. 改基 / 键边缘

- `0x213` 改基后旧条目仍在旧键上；再发新条目会与新基 + 序号撞键（实现面复审指出的边缘）。
  机器侧键 = 层键基数 + **揭示游标**；本模型的 `draw_index` 是「已建条目数」，空条目被夹掉时两者会错位。
- 先核 `0x213` 改基在机器上是否清零旧键区间 / 旧条目是否仍被绘制，再决定修实现还是登记残差。

## 判据（待落）

1. 纵向：若建模 `sub_45B2B0` 路径，模式 1 / 2 / 0 的 Δy 与同组上 / 下界一致；两向各用自己的比。
2. 行记录日志：若建模，`0x71` 清空后读侧一条不剩；`0x70` 追加条数与 `0x71` 清空可证伪。
3. 键边缘：`0x213` 改基后旧条目不与新建条目撞键（或按机器事实显式保留并登记残差）。

## 边界

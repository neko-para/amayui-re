# movie 族的 spec 通道归属：独立 movie 通道 / 并入 render / 维持 vm（含 8 条 A 类残差）

## 背景

`CORE-VM-MOVIE`（章节 `70-vm`）按章节文件被 `RESIDUAL_CHANNELS['70-vm'] = 'vm'` 映射到 **vm 通道**，于是它的 8 条 `[A]` 残差（正文含「不规定」）也被算作 vm 的 A 类。用户提出：影片这一块**可能应当独立成通道，或作为 renderer 的附属**；并且现在去收敛这 8 条，会**依赖尚未定的 state / render 事实**（而不是 vm 事实）。

⇒ 本批（`REQ-01M674XHSX2HSFWSKDWZV2C63D` 第 1 批）**跳过**这 8 条，不裁决；本单负责裁决与后续落地。

## 已取证（可复核；锚只锚 EA）

| 段 | 机器落点 | 归属判断 |
|---|---|---|
| ① 门前扫描 / 逐槽计时 | 主循环 prologue：`0x41252F`、`0x4125CC`、计时 `0x41261B`；门在 `0x41280C` | 物理在主循环，语义是 **renderer 对象生命周期轮询**（不碰帧 / 池 / 指令指针） |
| ② 影片位服务（`0x2000`） | `0x412B7C`–`0x412D42`（`0x412B8E` 判位、`0x412CBD` 清、`0x412D32` 再置） | **真状态机**（本族 21 个站点里只有这 4 个） |
| ③ 收尾「填纹理」 | `0x4126FA call sub_4A4C70`；**同一例程就是 `0x20b` 的实现**（`0x42374C`，全语料 20 个调用点） | **渲染 / 纹理子系统** |
| ④ 后端查询 | `0x408153` / `0x4080D3` 走 vtable 转外部；RTTI `CMovieTextureRenderer : CBaseVideoRenderer : … : CUnknown` | **平台 / 媒体模块**（DirectShow） |

8 条残差的未定依赖 **不是 vm 事实**：
- **已可定**：`RES-MOVIE-PAUSE` —— 忙标记只挡 `0x41261B`（逐槽计时）与 `0x412B7C`（位服务），**不挡**扫描入口与收尾 / 填充 / 销毁。
- **依赖 state / shape 事实**：`RES-MOVIE-FAILED-OBJECT`（扫描槽体**没有**「已启动」读点；正文「未启动 ⇒ 跳过」是**无机器站点的边界选择**）、`RES-MOVIE-NEW-FRAME`（对象字段语义 + 渲染步「需要重绘」残差）、`RES-MOVIE-FILL`（纹理槽生命周期 + vtable 语义）、`RES-MOVIE-BINDING-LIFETIME`（服务链**不读**纹理绑定）、`RES-MOVIE-DRAW-ORDER`（呈现次序）、`RES-MOVIE-POLL-FAIL`（只有「未知类 ⇒ 0.0」可判）。
- **依赖别的章还没成篇**：`RES-MOVIE-WINDOW-FAMILY`（`0x1c0` / `0x1c6` 的合同未成篇；两个服务点 `0x4128E6` / `0x412B99` 的先后）。

## 三个选项与代价（取证结论，未裁决）

- **a 独立通道**（新章 `72-movie` + 通道名 `movie`）：要动 4 处登记（`spec.json`、`audit.chapters`、`RESIDUAL_CHANNELS`、`chapters/README.md`）；漏登记 ⇒ `spec validate` #2 / #11 / #12 红、少通道 ⇒ `tools/test/spec-residuals.test.mjs` 红。计数会从 vm A33 变 vm A25 + 新通道 A8（正文仍「不规定」时）。
- **b 并入 render**（搬进 `60-ops-render`）：**零登记改动、`validate` 保持绿**；A 从 render 97 变 105。代价：把「非请求的位服务」塞进「请求边界」章。
- **c 维持 vm**：零机器改动；vm 继续背 8 条 A 类，且「未启动 ⇒ 跳过」这条与 `0x412D29`（只判槽非空）矛盾的说法留着。

★ 一致性提醒：`0x1c0` / `0x1c6` **不在** `60-ops-texture` 的任何规则里（只作为 `GAP-OPS-0100-01FF.ops` 存在）；现状已是 **3 章 + 1 gap**（`0x20f` 处理器在 `60-ops-wait`、服务在 `70-vm`、填纹理原语在 `60-ops-texture`）。只搬 `CORE-VM-MOVIE` 会变成 **4 章 + 1 gap**，合不上任何「两半」。

## 需要裁决（人是唯一能拍的）

**影片这一族（`0x20f` 对象表服务 + `0x23d` 清理 + `0x1c0` / `0x1c6` 窗口影片）是否整体从 `70-vm` 迁出？若迁，落独立通道 `movie`（新章 `72-movie`）还是并入 `render`（`60-ops-render`）？**
> **裁决（2026-10-31，用户）**：**影片这一族视为 renderer 的一部分**（即选项 **b**：归 `render` 通道）。
> **本轮暂不处理**：不迁章节、不改 `RESIDUAL_CHANNELS`、不动 `0x1c0` / `0x1c6` 的 gap，也不裁决这 8 条残差
> （它们依赖的 state / render 事实还没有成篇）。⇒ 本轮把这 8 条按「已在别处跟踪」跳过；
> 后果是 vm 通道的 A 类计数仍含这 8 条（**预期噪声**，不是遗漏）。

证据倾向：**位服务留 vm、表服务（扫描 + 收尾）整块迁出**，并与 `0x20f` / `0x23d` 同批处理。

## 收口判据

1. 归属裁决写下（a / b / c 之一，含理由），并落到 `RESIDUAL_CHANNELS` + 章节登记（若选 a / b）。
2. 8 条 movie 残差按 `REQ-01M674XHSX2HSFWSKDWZV2C63D` 的同一套归宿口径（合同 / `discarded` / S1·S2 的 `unknown`）逐条收口。
3. 顺带修掉「未启动 ⇒ 跳过」这条**无机器站点**的正文断言（要么补站点，要么改成引擎实际行为：失败残留按槽体会走收尾 + 填纹理）。
4. `pnpm tools spec validate` 全绿 + `pnpm test` 绿。

★ 另有第二条同源断言：影片位服务对**任意非空槽**再置位（0x412D29–0x412D32 只判槽非空），现行正文「已启动才维持影片位」与它不一致 —— 与「未启动 ⇒ 跳过」一起裁。

## 本轮处置（2026-10-31）

- 归属已裁决：**renderer（`render` 通道）**；落地方式按选项 **b**（搬进 `60-ops-render`），零登记改动、`spec validate` 保持绿。

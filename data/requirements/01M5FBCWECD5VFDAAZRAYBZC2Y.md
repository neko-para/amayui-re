# spec：配置键依赖地址差 vs 总览"地址数值不规定"——键的语义层级必须定死

- tags: [spec, config, address, review]

## 问题

`55-config.md:150-151`：引用/指针族的配置键下标 =（引用槽里的地址 − 该族全局池起点）/ 元素宽；而 `00-overview.md:79` 声明"不规定地址的数值，也不规定池在内存中的位置"。⇒ 键是**脚本可观察**的（命中/碰撞），却依赖未规定的布局：两个独立实现只要池基址/窗口不同，就会给出不同的键；`:151` 还把"指向局部池的指针 ≠ 局部池下标"写成可观察结论。

实证：启动链到 LOGO 入口写出的 3038 个脚本键全部是**池下标量级**（≤0xA9CE）——即实际只有"指向全局池"的指针被用作键；局部池指针当键的情形在已走路径上**没有出现**。

## 要裁决/要做的

1. 选一条：
   - **A（语义合同）**：键下标 = 被引用槽的**池身份**（全局池 = 池下标；否则按"未规定"处理并禁止依赖），把 `55-config` 的公式改成"等价于全局池下标；其它情形不规定"。
   - **B（实现产物）**：保留地址差公式，但明确"键值依赖宿主布局 ⇒ 本版只规定全局池指针的键"，并把 `:151` 的"不等于局部池下标"降为注释。
2. 同步 `00-overview:79` 的措辞（"地址数值不规定"仍成立，但要说明**哪些差值是合同的**）。
3. 判据：`spec validate` 13/13；若选 A，加一条守卫（模拟：把全局池基址改掉，全局指针键必须不变）。

## 出处

第四轮 spec 复核 S1-④；相关分析见 `docs/02-engine/spec-review-4.md`。

## 补充事实（本轮查证）

**具体是哪四条指令、键怎么来**：`load-int(0x1a3)` / `save-int(0x1a2)` / `load-string(0x1aa)` / `save-string(0x1a9)`。
键 = **类型码字节 + 8 位十六进制下标**；下标按操作数族取：

| 操作数类型 | 下标来源 | 逐字 |
|---|---|---|
| 3（全局整型）/ 5（全局字符串） | 操作数自带的**池下标** | `sub_418A30` case 3：直接返回 raw |
| 6（全局整型引用）/ 12（局部整型指针） | **指针槽里的地址 − 全局整型池基址**，再 `/4` | `sub_418A30`：`[5D818/5D8C0 + raw*4]` → `sub [5D800]` → `sar 2` |
| 8（全局字符串引用）/ 14（局部字符串指针） | 同上，换成**全局字符串池基址**与 `/28` | 字符串版原语 `sub_418AE0` 同形 |

⇒ **指向全局整型池第 i 槽的指针**（无论 type 6 还是 12）与"global-int i"给出**同一个键 i**（确定性）；
但**指向局部池的指针**给出的是 `(局部地址 − 全局基址)/宽`，这个数取决于局部池被分配在哪 —— 规范 `:151` 自己也写了"不等于局部池下标"。

**矛盾点**：`00-overview:79` 声明"不规定地址的数值，也不规定池在内存中的位置"。若键可以依赖地址差，那么"同一份脚本 + 不同实现"就会得到不同的键（可观察：命中/碰撞/持久化行），独立实现无法唯一复现。

**实测（启动链到 LOGO 入口，96196 步）**：写出的 **3038 个**脚本键全部是**池下标量级**（≤ `0xA9CE`），**没有**一个落在"局部池指针换算"的量级（约 `0x0Cxxxxxx`）⇒ 已走路径上只用到"值族 / 指向全局池的指针"这一半，局部指针当键的情形**未出现**。

**两个选项的实际差别**：
- **A（语义合同：键 = 被引用槽的池身份）**：全局指针键 = 池下标；局部指针当键要么定义成"局部池下标 + 池标识"，要么明说"不规定"。实现与布局解耦，独立实现可复现。
- **B（实现产物：保留地址差公式）**：只需把合同缩到"指向全局池的指针"，并明说局部类键是机器相关的地址序号。改动最小，但这类脚本在跨实现时**不可复现**（且我们无法知道语料里有没有这种脚本）。

## 裁决（2026-10-21）：按 **UB** 落地

用户裁决：局部池与全局池基址之间的数值是**任意偏移**，所以"用指向局部池的指针去换算配置键"**不是引擎的预期场景** ⇒ 规范里直接把它定为 **UB**。

已落地：

- **正文**（`55-config.md` 的「脚本访问」）：键下标只在"地址落在该族**全局**池内"时才有定义（= 该全局池的槽下标）；否则 **键没有定义（UB）**，并写明引擎只做减法与除法、**没有范围检查**（所以那是一个取决于分配布局的数，不是槽的身份）；实现必须响亮失败或记诊断。
- **源码核对**（用户要求"检查 spec 对应的源码"）：
  - 整型键原语 `sub_418A30`：type 3 → raw；type 6/12 → `[引用池 + raw*4] − [0x5D800]`，`sar 2`；其余 → 抛类型异常。
  - 字符串键原语 `sub_418AE0`：type 5 → raw；type 8 → `[0x5D828]`、type 14 → `[帧+0x5D8C8]`，取地址后 `− [0x5D810]`，再按 28 做除法（magic `92492493h` + `sar 4`）；其余 → 抛类型异常。
  - 两者都**没有检查地址是否落在全局池**；⇒ 规范把它定为 UB 与实现的"不检查"一致。
- **audit**：`RES-CONFIG-LOCAL-POINTER-KEY` 从 `unknown` 改为 **`discarded`**（impact/reason/range = `sub_418A30` / `sub_418AE0`）。
- **实现**（`apps/emulator-new`）：`configKey` 现在解析引用地址并要求它落在**该族全局池**，否则**响亮失败**（"未定义行为"），不再算出一个布局相关的键。
- **守卫**：`tools/test/emulator-new-pointer.test.mjs` 新增"指针不落在该族全局池 ⇒ UB"；**变异** 1 条（去掉该检查），1/1 红。

## 目标与界限

把 spec 的**弃权（A）与"有写无读"（B）**分批收敛，让"表现不对"能被判成 **spec 没定 / 我们没读 / 实现偏**。
★ 不追求全局清零，但**本批处理过的每一条**都要收到界限上——不许"因为当前路径不走"就留 `unknown`。

★ 界限不是"谁走到"，而是"**证据是否已在手**"：这一轮已经把函数读了，却因"眼下没人走"不收口，
下次要**从头再读一遍**。

**R1 上下文闭包**：本轮已装载的上下文（当前函数 + 已在栈上的被调方 + 已读字段）能判的，一律判完。

**R2 只有三种情形允许停**（其余一律收口）

- **S1 跨出已装载的调用链** ⇒ `unknown`，`next` 写死"读 `<函数或格>` 的写者/消费者"（⛔ 不许"待定"）。
- **S2 需要新资产**（脚本/存档/真机）⇒ `unknown`，`next` 写死"采什么、采到后改哪条合同"。
- **S3 判完了但没有可观察后果** ⇒ **最危险的一档**，再分三档（下节）；只有 S3a 允许 `discarded`。

## S3 再分三档（"写了个没人读的格" ≠ 死格）

- **S3a 结构性死格**：全语料**没有任何读者**，且不被整块拷贝 / 交给平台 / 进存档 ⇒ `discarded`（reason/range/impact + 否定证明）。
- **S3b 消费者已知、本版不覆盖**：读者是我们**明确跳过**的子系统（顶部菜单 / 音频输出…）⇒ ⛔ **不是死格**：写"该格由 X 读；X 的行为未成篇/不在本版"，挂到 X 的 gap 或残差，`kind` 保持 `unknown`。
- **S3c 读者未定位**：找不到读者但排除不了下面的形态 ⇒ `unknown`，`next` = 找读者 **+ 写明这次搜过哪些形态**。

**S3a 的否定证明**（缺一条不许写"没有读者"）：① 字面搜该偏移的**所有形态**（`[reg+off]` / `[reg+reg*n+off]` / 立即数）；
② 所在对象被 `lea` 取过址的**全部站点**（取址即可间接读）；③ 所在记录是否被**整块拷贝**（`rep movsd` / `memcpy` / 指针传给 vtable）；
④ 是否作为**出参/指针交给平台或外部**（IAT 调用、存档序列化）。★ `0x1ce` 那次"停用支不可达"就是入口没枚举完（只看了派发点 ①）。

**R3 先估规模再裁决**：`disasm-fn callees`（扇出）/ `impact --down`（闭包）/ `show`（行数）就能估，不必读全文。
预算（可调）：**闭包 ≤ 约 3 个新函数或 ≤ 约 200 行 ⇒ 同一轮做完**；超过 ⇒ 拆子单，**把入口 EA 写进单**。

**R4 "复杂度低" = 不需要新概念**：要引入新的领域概念/类型/子系统 ⇒ 按 S1 拆单。

**R5 收口只有三种形态**：写进合同 / `discarded` / 正文"本版不规定"。`unknown` **只**留给 S1、S2。

## 批次与顺序（2026-10-31 定）

| 批 | 通道 | 为什么在这个位置 |
|---|---|---|
| 1 | **vm** | A **高外溢**（门/时序窗/影片表/循环）；四个未收口缺陷正挂在窗与时钟上 ⇒ 先解锁 |
| 2 | **state** | A **低外溢**（池越界/地址算术/对象槽生命周期/数组边界/转发 prologue），多条可直接 `discarded` |
| 3 | **render + text** | 合成一批，**按根问题排**（见下），不按章节排 |
| 4 | **input** | 一半边界（坐标映射/按键高位/模式位），一半**派发与锁存**（`CORE-INPUT-WORD`/`WAIT-POLL-INPUT`）；输入评估的前置 |
| — | audio | **不排批、不改处置**：以后会做、短期来不及 ⇒ 保持 `unknown` **就是正确**，⛔ 不许改 `discarded`/范围声明 |

## 第 3 批的三条跨通道根（各裁一次）

1. **「无颜色」哨兵 → 终色唯一性**：`SCENE-202/203/322/323` + texture 消费端（SN0000 渐变就是这条）。
2. **脏标记的消费者**：`RES-SCENE3D-DIRTY-CONSUMERS` / `-XFORM-DIRTY2` / `CORE-OPS-RENDER-FRAME-STEP`。
3. **文本层画布键基数/撞号**：`RES-ADV-TEXT-LAYER-KEY` + `RES-TEX-LAYER-CANVAS-COLLIDE`。

## audio（**不是**范围外）

以后会做、短期来不及 ⇒ 保持 `unknown`；⛔ 不许改 `discarded`、⛔ 不许写"本版不覆盖音频"（那是把**待办伪装成不做**）。
判据：`--channel audio` 的数字**保持不动**即正确；矩阵里的那批是**预期噪声**。

## 每批收口判据

1. `--channel <该批>` 的 A 逐条有归宿：收紧成合同 / `discarded`（带理由）；B 逐条补消费者或 `discarded`。⛔ 不为清零删证据。
2. `pnpm tools spec validate` 全绿；正文 falsifier 能推翻该条。
3. 改到实现边界 ⇒ 补**会红**的守卫 + `mutate-check` 一条（只落 `apps/emulator-cxx`）。
4. 收口时追加一行「批 N 完成 · 裁决 n 条 · discarded n 条 · 新增合同 n 条」。

## 不要做

- ⛔ 不把 C 类当本批目标（按场景临时取证）。⛔ 不动 `apps/emulator-new`。⛔ 不为清零删残差。
- ⛔ 不把"弃权"（正文「未规定」）与"残差"（`audit.json`）混写。

## 交接

新会话从第 1 批（vm）开始：先 `pnpm tools spec residuals --channel vm` 拿当前分母。

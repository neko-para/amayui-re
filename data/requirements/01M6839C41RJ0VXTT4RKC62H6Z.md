## 仍缺（已登记，不是静默省略）

1. **`0x9` 的三项落不下去**（本实现没有对应结构 / 宿主接口，spec 也明说"效果见各自章"）：① 两个文本子系统 + 数据子系统的复位入口（站点 `sub_403EF0` / `sub_437440`，与现有 `text_layer_state_` / 字体 / 存档状态无已取证映射）；② 四组向量格（`0x428c73`–`0x428d23`，本实现无该四组格与消费者）；③ `0x1400` 私有消息（`0x428bdb`，无窗口消息钩子、模式格未建模）。⇒ 需先补 spec 各子系统复位效果或取证映射。
2. **语音槽「低两位 = 3 ⇒ 重排 + 启动下一段」**：spec 的「音频」章没有该判据且与"3 = 完成/跳过"互斥 ⇒ 实现不做（这类槽不参与交付）。
3. `0xc8` **负值**（按无符号 ⇒ 极长阻塞）未建模，留残差。
4. `begin_text_typing_or_drain` 的"闸开 ⇒ 置 29"不看每字间隔（`0x7d` / `0x196` / `0x305` 都带间隔前置）。
5. 文件白名单偏差两处已按证据接受：`vm_ops_render.cpp` 才是 `0x20c`/`0x23c` 落点；`vm_ops_io.cpp` 3 处是 D 类"spec 对、实现偏"的修正。

## 收口判据

1. 上面「仍缺」1–2 需要 spec 侧补正文（各子系统复位效果 / 音频排队判据）后才能继续；3–4 是登记在案的实现残差。
2. 新合同都有会红的守卫（`ctest` + `mutate-check` 43 条），且断言引 spec 句而不是"当前实现的取值"。
3. 每次改实现后 `ctest` 全绿 + `pnpm test` 绿，树不许留红。

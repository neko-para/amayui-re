- done_reason: 已按用户口径落地：① 字符串元素 = 不透明的 JS 字符串（数据留在池的 Map，不做 28 字节 SSO）；② 但字符串池**进地址空间**（区域 elemBytes=28，与引擎步长一致）只为**发地址** —— 因为实测 0xe（local string-ptr）在 104 份脚本里用了 1446 次，解引用必须能定位元素；③ readOperand/writeOperand 实现 0x8/0xe（取地址 → 定位元素 → 返回 JS 字符串；指向非字符串区域或未对齐 ⇒ 响亮失败）；④ 按字节访问这一族的指令仍一律抛。判据：守卫 9 例（包含"区域里格是空的""0xe 读回同一个字符串""两处响亮失败"）。0x6/0x7/0xd 在语料里出现 0 次 ⇒ 不实现（已登记）。

## 裁决（用户口径）

> "string 应该不存在混合普通地址用法，将其当作**不透明的字符串元素**，直接映射到 js 的 string 应该就可以了"

⇒ **不做** 28 字节 `std::string` 的字节级映射（不模拟 SSO / 不模拟长串的堆指针）。
字符串元素 = **JS 字符串**，池的 Map 就是它的真源。

## 但这不等于"字符串与地址无关"（实测）

对 104 份 `.BIN` 做操作数普查：

| type | 次数 | 结论 |
|---|---|---|
| `0xc` local-ptr | 77170 | 已实现（读=解引用+DEC） |
| **`0xe` local-string-ptr** | **1446** | ★ **用到了**（`0x61` / `0x192` / `0x193` / `0x195` / `0x1c8` / `0x204` / `0x2c5`…） |
| `0x6` / `0x7` / `0x8` / `0xd` | **0** | 本语料**完全没出现** ⇒ 不实现（登记在此） |

`0xe` 的语义是"**指向一个字符串元素**的指针"（`sub_41BF50` 的 case 14：取格 → 解引用 →
按 28 字节格取文本）。⇒ 字符串元素**必须能被地址指到**，否则 `0xe` 只能抛。

## 因此的做法（在"不透明"前提下最小）

* 字符串池**也进地址空间**：区域 `elemBytes = 28`（**与引擎的元素步长一致**，`base + 28*idx` 才对得上），
  窗口/按需增长与其它池同规格。
* **但格内容不写 28 字节的 `std::string`**：数据仍然只在 **Map** 里（`下标 → JS 字符串`）。
  区域在这个池上的职责只有两条：**发地址** + **让地址落在已增长的范围内**。
* ⇒ `0xe` 读：指针格 → 地址 → 按**窗口**定位到字符串区域 → `idx = (addr − base) / 28` → 取 Map 里的字符串。
* ⇒ 快照：字符串池**从 Map 取**（不经过区域）—— 因为区域里没有它的数据。
* ⛔ 明确否掉的做法：把 JS 字符串**编进** 28 字节格（那样"格内容"与真机不同，
  而任何按字节读这一格的地方 —— `copy-local-array`、`fill-zero` —— 都会得到"看起来正常"的错值）。
  按字节访问这一族的指令**一律抛**，并在错误里写明"字符串元素按裁决是不透明的"。

## 判据

1. 写一个字符串 → 取它的地址 → 经 `0xe` 读回来**是同一个字符串**；
2. 快照与 Map 版**逐值相同**（字符串池的口径不变）；
3. 若有人真去按字节读一个字符串元素 ⇒ **响亮失败**，不许静默给个东西。

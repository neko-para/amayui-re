# ADR · lift 的浮点模型：x87 按 double 建模（CW 的 PC=53 使四则保真），超越函数站点与 80 位值域带单列

- id: REQ-01M7CHE9T4NKHGKY2TQGVX6WK3
- type: decision
- status: done
- done_reason: 已裁决：lift 的浮点模型 = double。理由是**一致性**（arm64 上没有 x87，fp80 只能软实现 ⇒ 同一份 .ll 会得两套数值），不是效率；OBS-20261114-14 让这个选择零代价（二进制把 CW 的 PC 固定成 53 位且从不改 ⇒ 四则本来就按 53 位舍入，退化是保真）。三条边界（超越函数站点 / 80 位指数值域带 / REAL4 按 float）与重开条件见正文。
- tags: [lift, x87]

## 决策

lift 的浮点模型：**x87 按 `double` 建模**（IR 里用 `double`，不用 `x86_fp80`）。

**理由是一致性，不是效率**（用户 2026-11-14 口径）：arm64 上没有 x87，`x86_fp80` 只能**软实现**
（`__addxf3` 一类），而 x86-64 宿主上是原生类型 ⇒ 同一份 `.ll` 在两个后端会得到**两套不同的数值**。
把模型钉成 `double`（IEEE-754 binary64，两个后端都原生）就消除了这个分叉。

★ `OBS-20261114-14` 让这个选择**零代价**：这个二进制把 x87 的 precision control 固定成 53 位且从不改，
所以真机上 x87 的 `+ - * /` 本来就按 53 位舍入 ⇒ 退化成 `double` 是**保真**，不是近似。
（arm64 顺带更快，但那是副产品，不是决策依据。）

## 三条边界（不是"全都 double"）

1. **超越函数站点单列**：`fsin`@`0x4CCC80`/`0x4CCC84`、`fcos`@`0x4C8D2E`、`fpatan`@`0x4CF1A1`/`0x4CF1AC`。
   x87 与 libm 的近似本来就不同（`fsin(1.0)`：`3FFED76A…` vs `3FEAED54…`）⇒ 与 fp80→double 决策**无关**，
   属既有偏差；lift 时要么保留 fp80 站点、要么接受。
2. **80 位指数值域带**：`1e200*1e200` 在 80 位有限、`double` = inf（随机 `(x*y)/z` 16,344/200,000 不同）。
   这是唯一"默认 double + 少数站点 fp80"能覆盖的真风险 ⇒ 真出现不可解释的溢出/次正规症状时先怀疑这里。
3. **内存里的 `REAL4` 槽位按 `float` 建模**（`fstp dword` 1209 站）。⛔ 不把 `REAL4` 升成 `double`：
   那比 fp80→double 的差异**大得多**。

## 必须复现的机器性质

- 那 47 个 `or reg,0C00h` 站点的 **RC = 向零**：`(int)` / `fptosi` 天然满足；`fadd` 后紧跟 `fistp` 的写法要
  显式 `fptosi`，⛔ 不许用 `llvm.round` 一类（那是就近舍入）。
- ⛔ 绝不能把 PC 当 64 位（否则四则的"保真"全部失效，36.8% 位差）。
- `fild qword` 在本二进制 0 站、`fistp qword` 6 站（输入已是 53 位）⇒ 没有 `>2^53` 的整数边界。
- 浮点**相等比较**在本二进制 0 处（`fnstsw` 掩码只有 `41h`/`44h`）⇒ 这条风险面为空。

## 重开条件

出现下列任一 ⇒ 新增一条 ADR `supersedes` 本条，并在超越函数/值域带上改混合策略：
① 真实场景 A/B 出现 `double` 臂与 `fp80` 臂的**存档字节**差异；② 有消费者读 `fistp` 之前的 80 位中间值
并靠 64 位指数区分（语料里 `tbyte` 只出现在 CRT 自己）；③ arm64 上 NaN payload 出现可见差异。

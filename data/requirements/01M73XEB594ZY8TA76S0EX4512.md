# emulator-lift · Clear(ZBUFFER) 先 arm 后 flush ⇒ CLEAR 落在含更早 draw 的 pass 开头（窄窗不对称）

- status: open
- parent: REQ-01M6H6G6DSRG1ZRD810Z0HTH8V

- severity: S3
- tags: [emulator-lift gpu depth ordering]

## 一句话
`d3d9.cpp::clear` 在 `Clear(ZBUFFER)` 时**先**向 GPU 后端 arm 一次"该清深度"、**后**才 flush 队列 ⇒
若此刻队列里已经有更早的 draw，那条 CLEAR 会落到**包含它们的那一个 render pass 的开头**，
而之后的段用 `LOAD` 读旧深度 ⇒ GPU 的深度时间线与 CPU 镜像（`clearDepth` 在那些 draw **之后**才刷 1.0）**不对称**。

## 已核（变更复审实测，`.tmp/reveq/REQ-01M73P3GXW22Y467YGYPQSM571/report-probe.md`）
- 第一帧实测到 `arm=clear seq=0 queue=1` ⇒ **窄窗真实存在**（不是理论）。
- 本场景那条队列里的 draw 是 `d3dx9_sprite.cpp::gs_state` 的 sprite（`depth_test/write=false`）⇒ **无后果**。
- 同一族：`bounded` 语义是"一次 arm 清一次"，而 `rasterFlush` 只在**真录过 pass** 时清标志 ⇒ arm 落在空队列与落在有队列的 pass 开头，结果不同。

## 修法（二选一，需裁决）
1. **有序屏障**（推荐）：`clear(ZBUFFER)` 先 flush 当前队列（或记下"本段边界"），arm 之后新开一段 ⇒ CLEAR 只影响它之后录的 draw。
2. **把清深度改成"按 draw 序号"的记账**（更重）：每段记录 `clear_at_seq`，后端按序号在 pass 内插 CLEAR——多半不值得。

## 守卫
- pure（`MockRaster`）：队列**非空**时 `Clear(ZBUFFER)` ⇒ 必须先 flush（或产生新段），再让 CLEAR 生效；
  断言"含更早 draw 的那一段 `load_op != CLEAR`"。修前该用例红（现在是 CLEAR 落在含旧 draw 的段上）。

## 未做
- 不改 `Clear` 的其它掩码语义（TARGET 位已由既有用例覆盖）。
- 不为它编造真实触发场景：**目前只有理论 + 一条 sprite 的窄窗实测**，严重度按"潜在"记。

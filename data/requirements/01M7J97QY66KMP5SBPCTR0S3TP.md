# 第三条门：await global / await local（读 guest 全局槽 / 局部槽；需与 guest 同一份解码寻址）

## 一句话

给配方加**第三条门**：`await global <addr|slot> <value>` 与 `await local …` —— 读 guest 的**全局槽 / 局部槽**并比一个值。
用户口径（2026-11-16）："取 global 可以后续安排，这里后面可以统一看支持取 global 和取 local，
**需要一些特殊的内存运算/解码逻辑**"。

## 为什么（不是锦上添花）

- **加载存档屏与保存屏共用 `SAVE.BIN`** ⇒ 位置门**区分不了**这两屏（`SAVE.BIN.txt:901` `ロードしますか？` vs
  `:954` `セーブしますか？`），真正的区分量是 `:898`/`:951` 的 **`global a9cb` 位**。
- 更一般地：**"处在哪个屏"并不总等于"PC 在哪个区间"**。同一个脚本按模式（load/save/调试）走不同分支、
  却共用同一段循环的情况会不断出现 ⇒ 位置门之外需要一条"读 guest 状态"的门。
- 今天要绕开它只能靠"配方自己知道刚才点的是 Load 还是 Save"这种隐含约定 —— 那不能当判据（换个顺序就失效）。

## 判据（每条能红）

1. `await global a9cb 1` 在**加载**路径成立、在**保存**路径不成立（同一条配方、同一屏、只换入口）⇒ 门能区分两屏。
2. `await local <槽号> <值>` 在脚本局部变量上同样成立；槽号越界 / 类型不符 ⇒ **exit 2 且点名行号**（⛔ 不静默当"没命中"）。
3. 门未满足 ⇒ 停在原步、`pending≠0`、`timeout` 到期后 **exit 5 并点名**（与 `await position` 同一套失败语义）。
4. `global` / `local` 的读数**必须来自执行中的 guest 状态**（⛔ 不读宿主缓存、⛔ 不读 `.lst` 静态表）。

## 已知的难点（用户点出的"特殊内存运算/解码"）

- **全局槽的寻址不是"一个绝对地址"**：AGE 的 global 走**槽号 → 池基址 → 元素偏移**，中间有解码/加密步骤
  （`ENC(key,0)` 那一类）。⇒ 门要接受的是**脚本侧的坐标（槽号）**，宿主要用与 guest 相同的解码路径把它变成地址。
- **必须与 guest 用同一份语义**：⛔ 不许在控制层/配方驱动器里另写一份解码（那是第二套语义实现，`AGENTS.md` §12.8 的精神）。
  ⇒ 实现落点应是**共享 runtime 的一个只读取址原语**，`await global` 与（将来的）控制层 `sample` 都用它。

## 落点（预计）

`src/runtime/recipe.{h,cpp}` 的 StepKind 加一种门 + `input_plan` 的读点评估 + 一个"按槽号读 global/local"的
**只读取址原语**（放在 runtime 内核里，与 guest 侧共用一个实现）。

## 未做 / 边界

- 本条只做**门**（只读）；⛔ 不做"写 global"（那是改 guest 状态，另立单）。
- `--input-plan` 的语法要不要多一条指令，**先裁决再动**（用户 2026-11-16 把 DSL 收到过 3 条指令）。
- 与 `click` 的立即队列无关；但两条门都属于"同一套失败语义"（exit 5 + 点名）。

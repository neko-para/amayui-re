## 背景

问题：**能不能检查"A 把 reg/local 传给 B 的 reg/arg"两侧引用的是不是同一个类型？只有一侧有类型时能不能发现？**

## 结论：**现在能了（新加 `pnpm tools shape calls`），但被调方几乎全没声明 ⇒ 目前检查结果 199 对全是"单侧"**

判据三步：①调用点上该寄存器的**来源**（`this` / 内指向量 / 读出的指针路径 / 未知）；②用 `types` 沿路径解析成类型；
③取被调方在该槽位的 `kind:"arg"` 载体声明；两者比 ⇒ `一致` / **`不一致`** / **单侧缺声明**。

首次实测：**199 对槽位，全部是"被调方没有类型"**（`sub_41BF50` / `sub_40ED40` / `sub_40F750` … 都不在任何族里）。
⇒ 这不是"检查通过"，是"检查的前提缺失"。

## 本单要做的

1. **给被调方补载体**（这是瓶颈）：优先 `sub_41BF50`（被多个 handler 调用，且助手注释里已有证据：
   它的 `[ecx+5EC8Ch]`（`0x41BFB6`）与 `[ecx+5D800h]`（`0x41BFDD`）都是 obj0 相对偏移 ⇒ 它的 `ecx` 就是 obj0）。
   每补一个，那批槽位就从"单侧"变成"能判一致/不一致"的真检查。
2. 补完再跑 `shape calls`：出现 `mismatch` = 某处声明错了，**必须**当场查（这正是这条判据的价值）。
3. 覆盖扩展（**要先证明约定，不许猜**）：
   * 栈上传参（`push` 的顺序 ↔ 参数位）—— 需要 ABI 证据；
   * 间接调用（`call eax`）—— 目标未知，属闭合度那单（S1j）；
   * `local` 载体（`{kind:"local"}`）作为实参来源 —— 现在只解析 `this` / 内指向量 / 指针路径。

## 纪律

* ⛔ **不拿"偏移相同"顶替类型**（`.lst` 与 `.c` 无准确映射；同偏移≠同指令）；
* ⛔ 两侧都解不出时**不入账**（不是"一致"）；
* 判据必须**会翻**：`★⑭` 用例断言 same / mismatch / 单侧 三态，并把被调方声明改一下就要求判定翻转；
  变异清单一条（对账不再区分不一致 ⇒ 用例当场红，17/17）。

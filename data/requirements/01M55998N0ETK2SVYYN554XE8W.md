# S2e · `[全局+K]` 站点：把"经数据段符号的访问"落成**符号相对站点**（可从根对象成员表判定）

现状：`shapeOf` 没有 `glob` 分支 ⇒ `mov eax, ds:dword_55E1BC` 之后再 `[eax+K]` 的访问一律进
**未解析基址**桶（守恒③ 的 `unresolvedBase`），既不判也不解释。而 S2c 已声明
`dword_55E1BC : T0*`（store 证据 0x4baa3a），所以 `[dword_55E1BC + K]` 在形状上**就是** `T0+K`。

## 要做的事（判据）

1. `shapeOf` 增加 `glob` 分支：基址值来自已声明的全局符号时，输出 `baseKind:"globalbase"` +
   `sym` + `absDisp = K`（K 与 `obj0` 同一个偏移空间）。
2. 守恒③ 增加一桶（或把这一类从 `unresolvedBase` 移出并**显式**计数）—— ⛔ 不许静默消失。
3. claims：对这些站点跑**全局载体声明的类型**的成员表（与 G2 同一条判据），并给解释/残差两档。
4. 只有**声明过**的全局才这么做；没声明的全局仍进未解析基址（⛔ 不猜）。

## 为什么值得做

- 它把"根对象"的成员表**用 90 来个函数**去压（这些函数本身没有对象根约定，`this` 未知），
  是 S2d（构造器成员表）最好的交叉检验。
- 每个站点都有一条 EA 级证据链（store witness → 全局类型 → 成员偏移）。

## 前置

S2c（已完成）· S2d（构造器成员表；先有成员表才有东西可判）。

## 复现

`pnpm tools shape claims data/shape/carriers.json` 的守恒③ 行（看 `未解析基址` 的数目与样例 EA）·
`pnpm tools shape access <fn>`（看 `[eax+K]` 当前的 `obj` 与 `problems`）。

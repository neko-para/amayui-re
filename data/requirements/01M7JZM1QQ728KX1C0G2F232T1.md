## 一句话

把 AOT 臂的音频从"整条关着"接到"能听见"：S0 定档谓词 → S1 参数面 → S2 生命周期 → S3 泵 → S4 出声。
S0–S2 已落地（`--audio sdl` 能 `device=ok`）；S3/S4 未做。

## 为什么单独立这一节点

AOT 臂把音频 `configure(AudioMode::Off,"",false)` 且**一次都不调** `begin/pump/end`（`aot_host.cpp` / `aot_run.cpp`），
`--audio sdl` 与 `--audio-dump` 在参数校验里直接 `exit 2` ⇒ 整个臂没有声音、也没有任何音频读数。
普查（`.tmp/audio-integration/assessment.md`，只读、已裁决）的结论：**离"听见"还差 6 件，全是接线，
没有一件需要新的音频能力** —— 音频引擎（设备模型 / 混音 / 逐缓冲格式 / 音量 / underrun）在共用 runtime 里是完整的。

★ **不需要 feeder 线程**（这一条改写了早先 A/B/C 的选路）：AOT 的 `cpu_.machine == nullptr` 注定
`setupFeederContext` 失败 ⇒ thread 档**结构上不可达** ⇒ 只剩**主线程 D 泵**；而 D 泵要的
（`pump()` 走 `startNestedGuestCall`、续延点 `0x7FFEF008`、`afterGuestCall()`）AOT 里**已经存在**。

## 落地（2026-11-17 / main `b18b887`）：S0–S2

| 步 | 做了什么 | 判据 |
|---|---|---|
| S0 | `audioThreadMode(mode, real_time, has_machine)` 纯谓词（`runtime/audio_policy.h`）；`begin()` 是唯一调用点 | 只有三者全真才进 thread 档；AOT 恒 false ⇒ **从第一刻就是 D 泵**，⛔ 不再靠 `setupFeederContext` 失败回退 |
| S1 | `parseAudioMode` 纯解析（只认 off/virtual/sdl，大小写敏感）；`--audio-dump` 接通；`--sound` 真的接进 `mute_` | 非法值仍 `exit 2` 并点名合法值；⛔ 不放宽成"认不出就当 off" |
| S2 | `begin()` @ run 入口 / `end()` @ 收口（单出口）；摘要加 `audio     : mode=… device=… muted=… notify=… dump=…` | `--audio sdl --sound` ⇒ **`device=ok`**；`--audio virtual` ⇒ WAV 44 B 合法头 |

守卫：顶层 `add_test(NAME aot-audio-flags)`（pure，S0 真值表 + S1 解析）；`cli-aot-flags` 补 3 段；
另有**配置期 opt-in** 的 `audio-sdl-device`（`LIFT_AUDIO_SDL_DEVICE`，探不到设备时 `SKIP 77`，
探得到而引擎没开 ⇒ **红**，⛔ 不把坏掉的 `openSdl` 伪装成"没声卡"）。

**默认档逐字不变**：同 argv 两份 stdout 都 58 行，只差 `probe`/`insns`/`dispatch`/`table`/`lastHash`（§12.6 排除项）。

## 还没做（按依赖排序）

1. **S3 泵**：`audio_.pump()` 要插在**执行循环块边界**（`Suspended ⇒ syncRegs/continue`、`Error ⇒ Unimplemented`）
   并补 `fill_bytes` 记账 —— 动的是执行路径与 penalty，需单独一步判据。判"通知真被消费" = `fills>0`。
2. **S4 出声**：`pushed_bytes>0` / `played_bytes` 增长；结构上依赖 S3 ⇒ 现在不可达，⛔ 不假装。
3. **D 泵的 `fill_bytes`**：pump 回调只 `++fills`（`feederEvent` 那条才记字节）⇒ "喂了多少字节"在唯一可达档恒 0。
4. **AOT 摘要补音频读数**（b-5）：`fills/pushed` 仍是 0，S3 之后才有意义。
5. **宿主主音量**：`mixerSetControlDetails` 恒成功但不作用（引擎两处在调 ⇒ 游戏音量设置无效）。
6. **DSound `SetVolume`/`SetPan` 越界**应返 `DSERR_INVALIDPARAM`（现在返 `DS_OK`）。
7. **24/32-bit PCM 缓冲不许静默丢弃**（`audio.cpp` 里现在无告警无计数）；引擎实测只用 16-bit ⇒ 不挡听，是静默洞。
8. **winmm 音频面收口**：证据 + "不实现"声明（waveOut/midiOut/DirectMusic/MCI 播 MIDI 全 0 命中，已排除）。

## `<待核>`（缺什么才能判）

`--audio virtual` 在 AOT 的**确定性**（时钟恒 realTime ⇒ WAV 随墙钟变；要拿 WAV 当判据得先裁决是否给 AOT 加虚拟时钟档）·
本机有无可用音频设备（opt-in 用例探得到就算有）· 引擎缓冲格式全集（音频在 `.ALF` 里）· AOT 主线程 prefill 是否真执行（要看 IR 覆盖）。

## 判据

1. 每一步的验收必须是**机械读数**（`device=ok` / `fills>0` / `pushed_bytes>0`），⛔ 不接受"没崩"。
2. ⛔ 不改 guest 可见语义：默认档 stdout 逐字不变（§12.6 排除项除外）；`insns`/`stop @`/arena/`misses` 逐位不变。
3. ⛔ 不为了出声改 `AGENTS.md §12.8`（不需要 native override / 第三条语义实现）。
4. 每条新增判据都要能红（变异条目），opt-in 用例必须在缺设备时 **skip 77**、⛔ 不许恒绿。

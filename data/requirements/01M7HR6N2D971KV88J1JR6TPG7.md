# 🐞S2 AOT 闭包不含 00513B90（guest 退出对话框路径）⇒ 走到那里 decode-error + exit 2；quit 只能宿主侧收口

## 一句话

AOT 臂的闭包**不含 `00513B90`**（guest 的退出对话框 / 停机路径）：`WM_QUIT` 之后 guest 走到那里 ⇒ **decode-error + exit 2**。
`quit` 指令因此只能靠 `postQuit(0)` + `stop_requested`（宿主侧收口）绕开，而不是让 guest 自己走完停机路径。

## 证据（实测，写在代码注释里）

- `src/aot/aot_host.h:128` / `src/aot/aot_run.cpp:486`：WM_QUIT 之后停在 `00513B90` ⇒ decode-error、exit 2。
- 同一 EA 也出现在 `OBS-20261116-04`：`ESC`（VK `0x1B`）在 TITLE 上两侧都落到 `00513B90` / 同一条 `agerc!_ShowDialog`。

## 影响

- **用户按 ESC → 引擎自己走退出对话框**这条路径，在 AOT 臂上必然失败（解释器臂正常）。
- 任何"让游戏自己退出"的自动化（配方里 `quit` 是宿主收口，不是 guest 收口）都会被这条掩盖：
  配方"成功退出"不等于"guest 的退出路径跑通了"。⛔ 别把两者混为一谈。

## 判据（收口时）

- 闭包包含 `00513B90`（或说明它为什么**不可能**被收进闭包，并给等价方案）。
- 一条能红的用例：AOT 臂上触发 guest 自己的退出路径（ESC / 退出对话框）⇒ 不再 decode-error。
- 反向：`quit` 指令仍按宿主收口工作（`stop: stopped — input-plan: quit`），两者不互相替代。

## 未做

不改闭包（那是构建期决定）；本单先登记缺口与重开条件。

## 结论

已按「**40 槽定长数组 + 当前帧号 `cur`**」重写 `apps/emulator-new` 的帧模型（原先是 LIFO 栈 `frames.push/pop`，**根本没有"帧号"**）。下面 6 条守卫专门构造"父帧号 ≠ 栈顶下一格 / 帧号被当数用 / 槽复用"的情形 —— 栈实现在这些用例上**必错**，所以它们（以及 6 条变异）就是本缺陷"分歧消失"的判据。

## 做了什么

- `Machine.frames: ScriptFrame[]` → **`slots: (ScriptFrame|null)[]` + `cur`**（根帧占 0 号槽；空槽是显式 `null`）。`body` / `ip` / `frame` / `operandCount` 改成**槽 `cur` 那条记录的访问器**（单一真源，不再有"副本 + 同步"）。
- `ScriptFrame` = `{ body, ip, frame, parent, length }`：`parent` = 父帧号（引擎记录里的 caller 格），`length` = **该帧自己**的「操作数个数」槽。
- `enterScript`（`0x3`）：在「`cur` + 1」号槽建子帧并切过去；**深度按槽号判**（`slot ≥ 40`），不是按"已有几帧"。
- `returnToCaller`（`0x2`）：当前帧号 ← **父帧号** + **有条件释放**（只有「父号 + 1 == 当前号」才清槽）+ **从父号向下跳过空槽**；没有父帧 ⇒ 整个执行结束。
- `loadFrameAt`（`0x6`）：往**任意槽**写记录，**`cur` 一动不动**；父帧号 ← 装载时正在执行的帧号；槽号 ≥ 40 ⇒ 报错（文本照抄引擎）。
- `callFrameAt`（`0x8`）：切到**已装载**槽；父帧号 ← **切进来的那一帧**、ip ← 0、长度槽 ← 0（**返回栈 / 局部池不清**）；目标槽未装载 ⇒ 报错（文本含帧号）。
- `0x9`：释放全部帧，只留 0 号槽的根帧。
- 分派器：长度槽从"全局一格"改成**每帧一份**（`operandCount` 只是当前帧那一格的访问器）。

## 没做的（在残差 / 其它节点）

- 存档的 `−10` / `−11` 两个负值父帧号分支（本层仍只实现"根帧结束"与"回父帧"两支）——归存档章；
- `0x6` / `0x8` 的失败路径：本层按引擎文本**响亮失败**，不模拟"主循环接住异常后继续"（那一步没有取证）；
- `0x6` 装载的记录里，局部池**未预填**（"每个池填多少、填哪几格"未取证）——与 `apps/emulator` 的口径一致。

## 现象（2026-11-13 实测 `.tmp/out`）

非 profile 的一次 window 运行：**121 行 / 8174 B**（`2>&1` 合并），其中
**启动回声 + 静态清单 = 81 行（66.9%）**，真正的运行读数 23 行，**结论只有 2 行**（`stop`/`detail`），而且位于全文第 51% 处。
用户口径："噪音过多，难以关注到真正出问题的情况。"

三块结构性噪音（不是文案）：
1. **native-ovr 表打两遍**（启动一次 + 摘要一次，身份三元组逐字重复）= **44 行 / 36.4%**；
2. **缺口 14 行无条件打**（`main.cpp` 每次 run 结束都调 `reportBaseGaps`）；
3. 重复：skip-logo / recovery 各打两次；`raster` 行的 `（sink …）` 逐字复述 `present` 行。

## 被淹没的真读数（同一份日志）

- `fill_max_ms=777.80`（= `fill_slow` 门槛 1000 ms 的 78%，却**零告警**；在 428 B 的行里第 20/27 字段）；
- `tokenwait waits=40 / 1357.8 ms / avg 33946us`（主线程纯等令牌 1.36 s）；
- `present-tail tail_insns=12782972 tail_wall_ms=293.2`；
- 4 条 native override `hits=0`（开了不命中）。

## 根因（机制早就有、从没接上）

`--log-level` 的 Warn 默认生效，但只拦 `logAt`/`logV` 的 47 个调用点；这 121 行**全走裸 `printf`**
（`machine.cpp` 178 处 / `main.cpp` 109 处 / `audio.cpp` 19 处），日志里 `[warn]` 前缀出现 **0 次**。
`LogCat::LogReport` / `LogCat::LogNative`（`src/runtime/log.h`）在 `src/` 里 **0 个使用点**。

## 判据（目标形状，默认 ≤25 行）

默认只留三段（本轮应 5–6 行）：
`=== run 结论 ===`（stop / detail / insns / present-tail）→ `=== 异常 ===`（非零的 fallback/skipped/underrun/violation + 具名 unsupported 位 + 非预期停的最近 3 条指令）→ `=== 读数摘要 ===`（1 行 `read :`）。
- 缺口清单：默认 `gap: 13` 一行；明细进 `--report` / `--verbose`；
- native-ovr per-entry：只在 `hits==0 || fallbacks!=0 || declines!=0` 时打（`--profile/--verbose/--report` 全打）；
- 启动回声 / 节表：合并（约 -14 行）；
- 良性恒定量（`bit11=MIPFILTER`、`fill_overlapped`、`muted=1`、全 0 的 token/window 行）默认不出现，进"已知良性"登记；
- `stop`/`detail` 提到最前；`present-tail` 仍**恰好 1 行**（3 个测试按字面消费）。

## 不要误伤（按字面被 CTest 消费，列名/次数不能动）

`stop      : `（6 个测试）、`detail    : `（5 个）、`insns     : `、`present-tail: `（恰好 1 行 + 字段名）、
`token     : violations=0 max-concurrent=1`、无 override 时 `native-ovr` 必须 **0 行**。
折叠 per-entry 的唯一不破测试挂法：全打挂 `--profile`（`tests/native_override_e2e.cpp` 已带 `--profile`）。

## 顺序

P0 缺口降级 + native-ovr 折叠（-52 行 / 43%）→ P1 `SummaryMode` 门控（默认 ≤25 行）+ 回声合并 → P2 结论提前 / 消重 →
P3 异常清单非零才打 + 打印点接 `LogReport` → P4 `--report` 变纯清单模式。
细节与逐行改法：`.tmp/log-noise/analysis.md`（313 行）。

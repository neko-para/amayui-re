## 目标

按用户澄清的"**真线程入口**"落地音频：`sub_4B5AA0` 不再由主线程协程泵执行，而是
**真宿主 feeder 线程**（自己的 `X86` / guest 栈 / 私有块缓存）直接跑 `sub_4B6C30`；
另有独立 mixer 线程按设备游标读 guest 环并推 SDL3。宿主实现 DirectSound 设备模型
（游标 / 4 个位置通知 / 状态机 / 逐缓冲格式 / 混音）。验收：TITLE BGM 连续可听；
SE（含 hover）延迟 ≈ 100 ms；主线程不被 fill 阻塞。

## 实现

- **方案 C（真线程，默认 `--audio=sdl` + `--real-time`）**：
  - feeder 线程：`X86` / 专用 guest 栈（0x6FD00000..0x6FE00000）/ 私有 `BlockCache`+`Decoder`，
    直接执行 `sub_4B6C30`；私有 `NativeOverrideTable` 让 `_memcpy/_memset` 仍走 native。
  - mixer 线程：每 ~5 ms 推进设备游标 / 混音 / 投递通知；主线程 Present/长 shim 不再断音频。
  - 同步：guest 每槽 `CRITICAL_SECTION` → `CriticalSectionTable` 的宿主 per-EA 递归锁；
    `ComRegistry` / `ShimRegistry` 宿主表加锁（fn 在锁外执行）；设备模型 `AudioEngine::mutex_`。
  - join：`SetEvent(quit)` + 真 `std::thread::join()`；join 前 `releaseAll` 主线程 CS。
- **方案 D 回退**：`--audio=virtual` 或无 `--real-time` 时用主线程块边界泵（确定性；CTest 用）。
- **新增/改动**：`src/runtime/audio.{h,cpp}`、`critical_sections.{h,cpp}`、`sync_guest.h`、
  `dsound.cpp`、`kernel32_sync.cpp`、`com.{h,cpp}`、`shims.{h,cpp}`、`machine.{h,cpp}`、
  `tests/audio.cpp`、`main.cpp`（`--audio off|sdl|virtual`、`--audio-dump`）。

## 验收（机械 + 实跑）

- `ctest -R audio-device`：90 checks / 0 fail（通知次序 / 2.5 s 大推进排序 / dump 逐字节 /
  44.1k mono 插值 / 泵上下文还原 / CS 与在飞计数）。
- 全量 CTest：**59/59 passed**。
- 实时真线程（RelWithDebInfo，`--skip-logo --native-overrides all --real-time --audio sdl`）：
  30 s `fills=52 / notify=52 / underruns=0`；feeder fill 381–462 ms；lead 100 ms；
  dump 4–29 s 连续、RMS 4.5k–6.4k、无 2 s 周期。窗口模式（GPU direct3d12）10 s
  `fills=12 / underruns=0`。
- 偏差 / 未做：61 个 guest 通知事件不 SetEvent；`fs_base`/TLS 仍主线程；不做通用 TSO；
  重采样线性；音频只开 feeder+mixer 两条线程，游戏 VM 仍单线程。详见报告。

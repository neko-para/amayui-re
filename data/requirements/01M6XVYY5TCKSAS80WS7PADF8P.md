## 要换掉的是什么

现在的"脚本"是**定时器时间线**：`at frame N` / `at guest_ms T` 到点就发动作，发完不管有没有生效。它已经证明不可靠 —— 点击被静默漏掉时下游照样跑，于是两轮优化基于假数据。

要换的是**交互模型**：识别 → 操作 → 再识别。只读设计（含 Maa 对照与取舍）在 `.tmp/interact-design.md`（**不入库**；拿不到就按本节判据做，不补实现细节）。

## 节点语义（本单的合同，逐条要能写成代码）

| 字段 | 语义 | 为什么要它 |
|---|---|---|
| 识别 | **两个一等公民源**：① 引擎脚本 / 帧身份（子单 B）② 渲染画面特征 | 两者失效方式互补：帧会停（房间里稳定后不再 Present）⇒ 画面源失明；画面可以不换脚本 ⇒ 脚本源失明 |
| 动作 | 与"识别"解耦：命中哪个节点就执行它的动作 | 现在动作绑在"到期"上，无法表达"看到才点" |
| next | **有序**候选列表，按序识别、第一个命中即前进 | 同一画面可能有多种合法去向，顺序本身就是知识 |
| 超时 | 单节点语义：只约束"等 next 里出现一个"；识别失败**不是错误**，超时才是 | 识别失败要能继续轮询，否则一次噪声就红 |
| 动作后必须变化 | ★ 动作执行后**必须**观测到变化，否则**响亮失败** | 反面教材：Maa 的 `wait_freezes` 失败被静默放过 ⇒ 正是我们踩的坑 |
| trace | 每次识别 / 动作 / 跳转可 diff（事件流落文件） | 故障要能对着两个版本 diff，不靠人肉复述 |

## 迁移路径（⛔ 不一夜全红）

1. 状态机与现有 `input-script` **并存**：时间线仍可用，新脚本用新模型；
2. 先只换两条路径：**进 / 出 Eushully-chan Room**（现有时间线脚本已在 `.tmp/room/`）；
3. 同一目标各有旧 / 新脚本 ⇒ 比"到达的终态"，不比中间时序；
4. 旧路径只有在同一路径连续 N 次稳定后，才删该路径的旧脚本（删一条记一条）。

## 判据

- **第一步必须覆盖进 / 出 Eushully-chan Room**：两条脚本都在**不依赖帧号**的前提下到达同一终态（进、出各一次，重复 N 次全绿）。
- 动作后无变化 ⇒ 该次运行**非 0 退出**，并指出是哪个节点、等的是什么、等了多久。
- 节点图 + 识别器可在 **pure CTest** 里用合成输入（假识别源 + 假动作）跑：节点跳转 / 超时 / 顺序候选 / 动作后变化 各至少一条用例。
- trace 可 diff：同一条路径两次运行的事件流逐行相同（时间戳除外）。
- ⛔ 不以"帧号到 X"当判据（房间里帧号不推进）。

## 不做

- ⛔ 不在此单重新设计 profiler / 吞吐（各有单）。
- ⛔ 不把画面识别做成通用 CV 框架：只做本作需要的几种特征（模板 / 颜色块 / 区域哈希），够用即止。
- ⛔ 不用 OCR / 泛化模型：不可复现、不可 diff。

## 简化裁决（相对 MaaFramework）

Maa 的用例是"用很多节点 + 很保守的策略去做**一个**任务"；我们的场景相反 —— 后续大概率会**成批生成**任务（每条任务的节点数少、路径近似线性）。所以：**参考它的思路，但按我们的实际情况简化**，不照抄它的保守策略。

具体简化（每条都要在执行时能判"做/不做"）：

1. **不做候选轮询**：`next` 就是单个节点 id（或极少量的线性链），不做"按顺序逐个识别、第一个命中即前进"的并行候选表。
2. **不做 `on_error` 图**：任何失败 = 整条任务失败（非 0 退出 + 存图 + 打出最后状态与全部候选）；不做错误分支跳转。
3. **不做 `rate_limit` / 采样间隔策略**：识别只在帧/块边界采样，采样策略固定、可解释。
4. **不做点击抖动**：Maa 默认点框中心 + 高斯采样（`Actuator.cpp:145-176`），我们必须**确定性**，点击点 = 框中心或固定点。
5. **超时必填且有默认值，失败必须响亮**：Maa 的 `wait_freezes` 失败被静默放过（`ActionHelper.cpp:78-100` 被 `TaskBase.cpp:202-211` 忽略），我们**反着做** —— 动作后画面没变就是失败。
6. **不做 `[JumpBack]` 回跳**（Maa 有，我们暂不需要）。
7. **为"生成"而设计**：schema 必须能被程序批量生成（JSON/结构化、**无自由文本、id 稳定**），并且一条命令能把任务转成**可 diff 的 trace**。

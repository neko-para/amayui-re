## 判据（已达到）

`apps/emulator-new` 的**启动入口**不再是"直接读某个脚本文件"，而是真实引擎的那条：

1. **索引**：`Install.open(安装目录)` 读 `SYS4INI.BIN`（`S4IC`），解出 8 个归档 / 21109 条目；条目 0 = `SYSTEM4.BIN`，
   `0x5262` = `LOGO.BIN`（统一文件 id == TOC 条目下标）。
2. **取件**：安装根下的**松散文件优先**（根脚本 12012 字节，TOC 登记 11992），否则按 `(archive, offset, length)`
   从 `DATA*.ALF` 切片；`LOGO.BIN` 从归档切片（长度 1508 / sha256 钉住）。
3. **启动**：以 **id 0** 为根脚本执行；当前执行掉 `0x1a7` / `0x1a8`（空操作）后停在 `0x2f6`（第 2 条 / 偏移 16）。
4. **守卫**：`emulator-new-alf`（pure：LZSS / 索引 / 松散优先 / id 映射）、`emulator-new-noop`（pure）、
   `emulator-new-boot.assets`（真实索引 + 启动棘轮）、`emulator-new-logo.assets`（改走同一入口取 LOGO）；隔离守卫改成
   "`spec.ts` 读规范 / `host.ts` 读安装目录，其余零 fs"；变异清单 3 条（松散优先 / id 偏移 / 0x202 门）。
5. **门禁**：`pnpm test` / `pnpm tools spec validate` / `pnpm tools requirements validate` / `pnpm typecheck` 全绿。

## 非目标

- **完整启动链**不在本单：`SYSTEM4.BIN` 的启动前段（`0x2f6` / `0x149` / `0x21b` / `0x88` / …）仍是缺口。
- `CORE-FS` / `CORE-BOOT` 的 **spec 规则**尚未成篇（`core/README.md` §1.1 的显式延后）：本单只落**实现 + 守卫**，
  规则成篇是后续单（要把"松散优先 / 根脚本 id 0"写成带锚的合同）。
- 不实现 `APPEND*.AAI` 的叠加索引（本作启动只读 `SYS4INI.BIN`；需要时另开单）。

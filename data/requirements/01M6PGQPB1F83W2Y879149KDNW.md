## 现象

用户实测：启用全部 native override 后**渲染坏掉**；只关掉 `sub_48B090` 就恢复正常。
已复现为可观测分歧，不是视觉错觉：同一 boot、同一虚拟时钟、300 帧：

- 关闭 `sub_48B090`：300/300 帧 hash 与 no-override 基线完全一致。
- 注册 `sub_48B090` 的 native 8bpp→32bpp fast path：第 **2** 帧起出现 hash 分歧
  （`0x765FC242A26FBA6B` vs `0x0C41812AF9164191`；后续 49/300 帧不同）。
- 另一次启用 8/24bpp 的变体在第 **47** 帧出现 RGB `max=1` 的 698,877 像素差异
  （BMP 的 RGB 只差 1，但 `Present` hash 不同，说明纹理/alpha 状态被改写）。
- 后续实测还看到：纹理能出来，但中间有**很多局部黑斑**；这不是时钟相位的典型形态。
- macOS 侧未复现上述纹理异常；Windows 侧仍可能是独立问题，继续排查。

## 当前处置

- `sub_48B090` 已作为 **stable 项进入 `all`**：`--native-overrides all` 会启用它。
- 新增 `-名字` 排除：`all,-sub_48B090` 与 `-sub_48B090,all` 等价；排除项优先于启用项。
- **时间补偿明确不做**（用户裁决）：native 省掉的 guest 虚拟时间保持现状；窗口/`--real-time`
  下没有这个欠账，headless A4 不以该 override 作逐字节基线。
- 非时钟缺陷已修（2026-11-06，见下节）；4/1bpp 源、16bpp 目标、色键≠0 仍显式回退。
- 原型代码保留；默认关闭（不给 `--native-overrides` 时全关）。

## 2026-11-06 修复与复核

- 已修：alpha 目标行序（`alpha[row*cols+col]`）；24bpp / 32bpp 源（32bpp 用第 4 字节 alpha）；
  锁改走 `d3d9::lockRect`/`unlockRect`（pitch/pBits/locks/已锁拒绝同一份语义）；
  失败路径不留锁/半状态；`cols=w` + `pitch>=4*w`；目标格式从虚拟显示状态判断（不再硬编码
  `0x5518C0`）；目标函数从 `[[self]+0xC]` 取并校验 `.lst`；bpp/src 在 Create 之后重读；
  嵌套 this 的 ECX 进 `GuestCallStack::Frame`；定时器打断保存/恢复整份通用寄存器。
- 仍显式回退：4/1bpp 源、16bpp 目标、色键≠0（无证据级语义，不猜）。
- 测试：`native-override` 196 checks、`guest-call` 27 checks；含真纹理 arena 逐字节、
  已锁拒绝、16bpp 目标拒绝、alpha 2×2 + 3×2 非方阵。全量 ctest 49/49。
- 3 帧 A/B 仍复现虚拟时钟相位偏移；这是**未补偿的预期差异**，不是本单的非时钟缺陷。

## 重开/验收

1. 非时钟缺陷：8bpp（alpha 0/非 0）、24bpp、32bpp 已有 pure fixture；4/1/16bpp 与色键仍然回退。
2. 在 **纹理 arena** 上逐字节比对（`pitch*height`），不要只看 BMP/hash。
3. CLI 守卫：`all` 包含 `sub_48B090`；`all,-sub_48B090` 不包含；排除项拼错必须报错。
4. 时间补偿**不在本单**；不要以 headless 300 帧 hash 0 当作验收，改用 arena/非时间敏感 fixture，
   或只在 real-time/窗口下比较。

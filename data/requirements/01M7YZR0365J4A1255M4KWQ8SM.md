# 插件运行时 · 拆分 loadSave：boot→TITLE 独立成链 + 自动关闭「战斗中的帮助界面」

## 一句话

把"启动 → TITLE"从 `loadSave(slot)` 里**拆出来**（独立链），并让场景能**自动**把"战斗中的帮助界面"关掉 ——
目标是"新场景只写它真正关心的那几步"，不再每次重抄载入前缀、也不用手点关帮助。

## 现状（已核）

- `scripts/plugins/lib/save.js` 的 `loadSave(slot)` 第一道门就是
  `afterPosition TITLE [0x0460,0x0520)`（`save.js` 的 `TITLE_POS_LO/HI`）—— 也就是说它**把"启动到 TITLE"和
  "TITLE → 载入 → FIELD"两件事捆在一起**。想在 TITLE 上做点事（改选项、看设置）就得改这个库。
- 本单要拆的边界：**boot→TITLE**（一道门）vs **TITLE→载入完成**（现有其余部分）。
- ⚠ 界面上有"战斗中的帮助界面"，它会在战斗开始时弹出并**吃掉点击**；本仓目前**没有任何**关于它开关的记录
  （`rg 'ヘルプ|帮助|チュートリアル|tutorial' docs/ data/requirements/ src/runtime/config*` 零命中）
  ⇒ 这是**待取证**的引擎语义，⛔ 不许按猜测写死。

## 要做

1. **拆分**：新增 `bootToTitle()`（或等价命名）链 —— 只等 TITLE 的输入回调门；`loadSave` 改成**从"已在 TITLE"开始**
   （不在 TITLE ⇒ 门超时 = 响亮失败，⛔ 不自己再等一轮）。组合由 `chains.js` 的 `route` 完成（与 `withLoadSave` 同一套）。
2. **自动配置"不展示战斗中的帮助界面"**：先取证它是什么（优先级从高到低）：
   - ① **配置文件键**（`SYS4INI.BIN` / `config` 的哪个键 = 关掉帮助）；
   - ② **guest global**（哪个 `T_*` / global 槽、取值语义）；
   - ③ 只能在**选项屏**里点（那就做成一条"进 OPTION → 关帮助 → 回 TITLE"的链）。
   取证要按 `AGENTS.md §6` 绑可再校验观察（EA / 语料行区间 / 守卫用例 id），⛔ 不许凭记忆写。
   实现上优先选"**不改 guest 可见语义、也不是每次点一遍 UI**"的方式（配置键 > global > UI 链）；
   若只能走 UI，就写成一条链并让 `bootToTitle` 之后的组合把它串起来。
3. **落地形态**：`scripts/plugins/lib/` 下新增/改的文件 + 一个样例场景（可复用现有 save07 场景）。

## 判据（收口）

- 拆分后：`plugin/load-save-e2e` 与 `plugin-runtime` 的既有用例仍绿（不给它们加时间等待）；
- 新样例：`bootToTitle → （自动关帮助）→ loadSave(槽位) → 场景` 能跑到目标屏，**日志/截图证明帮助界面没出现**；
- `tools/test/recipe-wait-policy.test.mjs` 仍绿（新链里 ⛔ 不加 `wait`）；
- 若帮助开关走的是配置键/global：加一条会红的守卫（配置被写回默认 ⇒ 红）。

## 未做 / 边界

- ⛔ 不在本单改 `.plan`（配方是冻结的文本格式；拆分只影响插件侧）。
- ⛔ 不碰 `saves/**`；⛔ 不把"关帮助"做成改 `saves` 或改安装树的副作用。
- 帮助界面的**存在性**若最终无法可靠判定（例如它只在特定战斗形态出现），就把判据降为
  "该开关已按取证的方式设置 + 一次固定战斗的截图对照"，并在此写明理由。

## 要做的（每条写清"查什么 / 锚在哪"）

1. **存档写入侧：`table_2`/`table_3` 的下标从哪来**

   （恢复：表项 `+3` 后压进 `Engine+0x5EEA4`）与 `sub_4192F0`（恢复：`PC = 记录+0x00 + 4*表项`）两类，
   **没有**像 `table_1` 的 `sub_48E870` 那样的"位置 → 下标"查找例程 ⇒ 存档里那两个下标的**写侧**未查明。
   ★ 判据 = 在存档写入侧找到填这两个字段的 store（或明确证明"没有"）。
2. **恢复路径的调用者与存档字段**
   `sub_40F750` 的 4 个 `0x410xxx` 调用点、`exit`（`0x2`）的记录 `+0x38`（旧记法 `帧+0x4C`）`== −11 / −10` 两个分支、

3. **记录 `+0x04`（旧记法 `帧+0x18`）的叫法复核**
   已登记的两条把它叫「操作数基址」（`Engine+0x5D880/frame-fields` 与 `…/local-pool-bases` 一族），
   而同一批记录里的算式只在「记录 `+0x04` = 本条指令的 **opcode 地址**」下自洽：
   `sub_41BF50` 的 type 落点 `[PC + 8·i − 4]`（i=1 ⇒ PC+4，正是紧跟 opcode 之后的 type 字）、

   ⇒ "操作数基址"这个叫法与算式**不能同时成立**。★ 判据 = 找一条能区分两者的观察（例如装载器填该字段的 store）。

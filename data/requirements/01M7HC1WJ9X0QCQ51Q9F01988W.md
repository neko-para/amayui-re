## 一句话

让 agent 能**逐步操作** AOT 二进制（停住 → 看画面/读状态 → 投递一条输入 → 继续），而不是"跑完 → 看末帧 → 改 graph → 从头重跑"。
形态参考 `node --inspect`：二进制暴露一个**可发现的本地控制端点**，由**一个 DSH tool**连上去发指令。

## 为什么（用户口径，2026-11-16）

> 之前 agent 在尝试构造 graph 路径时，需要不断地"执行到结尾 → 看最终截图 → 编辑 graph → 从头执行"。
> shim 的存在允许我们完全控制整个二进制的执行，比如"请求截图""投递输入"，这样 agent 就可以逐步操作，
> 最后汇总 graph，而不需要不断尝试。

⇒ 现在 `--interaction-graph` / `--input-plan` 都是**启动前一次性装配**，探索成本 = 每改一次配方就重跑一遍完整 boot。

## 口径（已裁决）

- ★ **先做 CLI，且 CLI 是独立进程**（用户 2026-11-16）：控制面 = 一个**独立的控制客户端进程**（第二个可执行 / 脚本），
  连到常驻的 AOT 进程；DSH tool 只是后续薄包装。"不需要非常精确的时间 ⇒ CLI 足够" ⇒ 允许粗粒度
  （命令在**下一个宿主汇点**生效），但每条命令的生效点要写死。
- ★ **除截图外必须有 `sample`（采样当前执行点）= 脚本位置**：`TITLE.BIN:<offset>`，⛔ 不是进程 / CPU 状态。
  偏移 = **绝对字节偏移、4 字节对齐**，与 `dist/views/data/TITLE.BIN.txt` 的 `label_%08x` **同一坐标系**
  （`packages/age-format/src/asm/assemble.mts:16`：`label = headerLen + 指令序号*4`）⇒ 指令序号与清单行都能机械映射。
- **AOT 臂是唯一目标**：它已基本完全覆盖解释器版本；解释器只作验证 ⇒ 设计**不必兼顾**解释器侧。
- 控制层发的是**宿主侧动作**（停 / 截图 / 读状态 / 投递），⛔ 不是"在 guest 执行循环里插桩"。
- 两个子课题各自独立取证，最后合成一个项目计划：
  - 控制层本身（CLI 命令集 / 停继续语义 / 动态投递 / `sample` 字段）
  - **脚本内位置识别**（`ScreenHash`/`ScreenRect` 不可读；要"当前在哪个脚本的哪条指令/哪个区间"）

## 硬约束（设计必须绕开，不是"最好避开"）

- `AGENTS.md` §5.1：受限沙箱里**捕获子进程输出 = 命名管道 = `spawn EPERM`** ⇒ "控制层走子进程 stdout 管道"要先判定是否可行。
- `AGENTS.md` §12.8 / `docs/03-emulator/input-plan.md`：⛔ **不许出现块边界 pump**（推进只能在 guest 读点）；控制层不能变成在执行循环里的第二套 pump。
- DSH 插件在 `$DSH_HOME`、装它要提权、**宿主插件代码不热重载**（改了要重启）⇒ 迭代速度要算进设计。

## 传输（用户裁决 2026-11-16，推翻上一版设计）

- 控制层走 **WebSocket**（`ws://127.0.0.1:<port>`）；server 侧**允许引入依赖**（`boost::asio` / `boost::beast` 一类）。
  用户原话："传输还是考虑采用 ws, 作为 server 层库可以考虑引入 boost asio, 没有必要为了节省依赖而复杂化/使用奇怪的协议"。
- ⛔ 不要为"省依赖 / 避端口"设计奇怪协议（上一版推荐的控制文件+轮询**已作废**）。
- 客户端仍是**独立进程**（CLI 优先）；DSH tool 只是后续薄包装。

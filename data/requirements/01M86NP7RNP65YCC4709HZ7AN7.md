# AOT · VFS 正解析缓存 / 安装树目录索引（`CreateFileA` 从 ~100 µs 再压一档）

## 一句话

只读内容缓存（`e0c8e6e`）把 `CreateFileA` 从 **~190 µs** 降到**命中 88–114 µs**（命中率 83.8%），但
命中仍要 **2–3 次 resolve stat + 1 次校验 stat**，而本机**一次 stat 就是 13–26 µs**；另外每次跑还有
**388 次整目录枚举 = 121.5 ms**（385 条不同的失败探测各一次）。本单把这两笔消掉。

## 读数（2026-11-23 / dev / `LIFT_VFS_TIMING=1`）

| 段 | 占比 | 单价 |
|---|---:|---:|
| 真正的 `CreateFileW` | 45.7% | 首次 0.9–1.1 ms（AV）/ 重复 40–50 µs |
| `resolve`（逐段 stat + 目录枚举） | 43.0% | 成功 61 µs / 失败 **192 µs**；**388 次整目录枚举 = 121.5 ms** |
| stat / share / 句柄表 | 其余 | **一次 stat 13–26 µs** |

## 方案

1. **正解析缓存**：键 = 已折叠的**段序列**（与负缓存同一把键 + `must_exist`/`resolve_case`），
   值 = 解析后的宿主路径；失效口径沿用 `invalidatePathCache()` 的**代（generation）**，写覆盖层一启用就
   按现有规则停用/换代。⚠ 正缓存依赖"安装树运行期只读"这条既有显式假设（`vfs.h` 已写明）——
   要在注释里把这条依赖再写一次。
2. **安装树目录索引**：一次性遍历 `--game-dir`（几千项），建 `大小写折叠键 → 真实名` 的索引；
   `lookupSegment` 查索引而不是"精确 stat + 失败后整目录枚举"。目录枚举次数应从 388 降到 ~1（建索引那次）。
   ⛔ 索引必须只读、大小写折叠规则与现行 `lookupSegment` **同一份**（不许两套）。
3. **命中后的 stat 校验**：内容缓存现在每次命中做一次 size+mtime 校验；有了索引/正缓存后，校验仍保留
   （它是"安装树变了就重读"的兜底），但**从 3 次降到 1 次**。

## 判据

- **读数**：`CreateFileA` 命中 ns/次（现在 88–114 µs，目标 **< 40 µs**）；目录枚举次数（388 → ~1）；
  FIELD 装载帧的 `CreateFileA` 桶；点击窗口的 `[profile-window]` 桶；
- **语义**：现有 `file-io / vfs-read-cache-parity`（528 条断言：命中 vs `--vfs-cache-mb 0` 在字节/大小/
  定位/EOF/错误码 5、2 上逐位一致；改写安装树后必须 stale）必须仍绿；五项指纹逐位同；
- **新守卫**：正缓存/索引命中与"关掉缓存（`--vfs-cache-mb 0` 或参照实现）"返回**同一宿主路径**；
  索引与"逐段 stat"在同一份探针集合上结论一致；变异：让索引漏一个段 ⇒ 该用例红。
- `ctest` / `pnpm test` / `pnpm verify` 全绿。

## 边界

- ⛔ 不按文件名/扩展名/目录名开特判；判据只能是上面的性质。
- ⛔ 安装树绝不写；写路径仍走 `--appdata` 影子。
- `FindFirstFile` 的目录枚举语义不在本单（索引只服务路径解析）。

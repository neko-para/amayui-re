# AOT · VFS 正解析缓存 / 安装树目录索引（CreateFileA 从 ~100 µs 再压一档）

## 一句话

只读内容缓存（`e0c8e6e`）把 `CreateFileA` 从 **~190 µs** 降到**命中 88–114 µs**（命中率 83.8%），但
命中仍要 2–3 次 resolve stat + 1 次校验 stat，而本机一次 stat 是 13–26 µs；另外每次跑还有
388 次整目录枚举 = 121.5 ms。本单把这两笔消掉。

## 读数（2026-11-23/24 / dev / `LIFT_VFS_TIMING=1`）

| 段 | 占比 | 单价 |
|---|---:|---:|
| 真正的 `CreateFileW` | 45.7% | 首次 0.9–1.1 ms（AV）/ 重复 40–50 µs |
| `resolve`（逐段 stat + 目录枚举） | 43.0% | 成功 61 µs / 失败 **192 µs**；388 次枚举 = 121.5 ms |
| stat / share / 句柄表 | 其余 | 一次 stat 13–26 µs |

## 取证修正（2026-11-24 只读）

- 安装树实测 **542 文件 / 0 子目录**（不是「几千项」）⇒ 索引 = 根目录一次遍历，内存 ~50–80 KB。
- 「388 → ~1」方向对，但计数器是**全进程**的（`find()` 也走 `lookupSegment`）⇒ 落地后预期 **3–4**；
  判据写成 **≤5**，并在报告里注明口径。
- 只做索引 ≈ **48 µs**（resolve 53→10–15，校验 23 + 插入 11 仍在）；**必须同时做正缓存**才到 ~36 µs（<40）。
- `frames` **不是**稳定量（墙钟插件链）⇒ 语义判据 = `exit` / `stop @` / arena / `table misses` 逐位同 +
  「缓存开↔关」逐位同，⛔ 不把 `frames` 写进判据。
- 点击窗口 `[profile-window]` 里**没有**具名 `CreateFileA` 行（落在 `shim:(rest)`）⇒ 该判据改看
  「点击帧的 shim 桶」，不在本单。
- **顺序裁决**：**先做目录索引**（无失效语义风险，直接消 113–122 ms 失败探测）→ 再做正缓存
  （收益更大但写后读风险在它身上）。

## 方案（两步，各自带守卫）

1. **安装树目录索引**：`vfs.h` 加 `install_dir_index_`（`折叠键 → {真名, is_dir}`，同键多候选保留
   vector 以复现 `[ambiguous]`）+ `lookupSegmentIndexed`；`vfs.cpp` 的 `installPathForSegments` 换查表；
   `setGameDir` 清索引；`--vfs-dir-index 0|1`（缺省 1，0 供 A/B 与守卫）。**懒建**（首次 lookup 的目录）。
2. **正解析缓存**：`PositiveEntry{gen, host}` + `lookupPositive/rememberPositive`，与负缓存**同一把键、
   同一代**（`invalidatePathCache` 只换代）；成功（影子命中 + 安装树成功）才存；`must_exist=false` 的
   解析结果也安全；**校验 stat 保留**（3 次 → 1 次）。
3. `cacheable = writeOverlayEnabled() && ...` 不动：没有 `--appdata` ⇒ 两张表都不查不写。

## 判据

- **读数**：`CreateFileA` 命中 ns/次 **< 40 µs**；目录枚举 **≤5**（现在 388）；FIELD 装载帧的
  `CreateFileA` 桶、点击窗口的 shim 桶；
- **语义**：`file-io` / `vfs-read-cache-parity` 绿（命中 vs `--vfs-cache-mb 0` 的字节/大小/定位/EOF/
  错误码逐位一致；改写安装树 ⇒ stale）；五项指纹逐位同；`ctest` / `pnpm test` / `pnpm verify` 全绿；
- **新守卫**（都挂 `file-io` 的新 case，不新增 CTest 名）：
  - `vfs-dir-index-parity`：索引开/关，`ok/host/error` 三元组逐字节同；探针含「中间段是文件」与歧义；
  - `vfs-resolve-cache-parity`：正缓存开/关同；**写后读**（影子新建/删除后必须换代）；
- **变异**（2 条，`--match` 单跑）：索引隔一项建表 / 删 `invalidatePathCache` 的换代 ⇒ 对应用例红。

## 边界

- ⛔ 不按文件名 / 扩展名 / 目录名开特判；判据只能是上面的性质。
- ⛔ 安装树绝不写；写路径仍走 `--appdata` 影子。
- `FindFirstFile` 的目录枚举语义不在本单（索引只服务路径解析）。
- ⛔ 不改内容缓存（`readCacheLookup` 的 stat 校验一行不动）。

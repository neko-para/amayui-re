用户 2026-11-05 裁决「**确认需要实现 D3D 接口**」后的落地：`d3d9!Direct3DCreate9` 从 stub 变**真实现**
（返回 guest 可见 COM 对象 = vtable EA + refcount 在 guest 堆上），并按取证把 IDirect3D9 / IDirect3DDevice9
的槽填上真语义。boot 因此越过 `Direct3DCreate9`，一路跑到 **CreateDevice 成功 → SetDialogBoxMode →
GetDeviceCaps → CheckDeviceFormat → Clear（第一次渲染动作）**，停在 **`d3dx9_43!D3DXCreateSprite`**。
路线裁决见 `REQ-01M6KTYX5ZYENMPFHHNQTET254`（本安装 `set:CreateObject=2` ⇒ 走 D3D9）。

## 实测（本树 · 2026-11-05 · `--max-insns 600000000`）
- 基线：`unimplemented @ eip=7FFE00AC d3d9!Direct3DCreate9`，`insns=102,917,289`
- 现在：`unimplemented @ eip=7FFE009C d3dx9_43!D3DXCreateSprite`，`insns=103,059,311`（+142,022）
  · 返回地址 `0x004A2BD5`；调用点 `0x4A2BD0`（`sub_4A2BA0`：`push &[esi+0A5D4h]` / `push [esi+744h]→[+410h]`）
  · `eax = 0x101C68A8` = **我们建的 IDirect3DDevice9 对象** ⇒ 引擎确实把设备交给了 D3DX
- 设备：1280×720 / D3DFMT_X8R8G8B8(22) / 32bpp / pitch 5120；DeviceType=1(HAL) + BehaviorFlags=`0x44`
  **第一个重试组合就成功**（1/2 × 0x44/0x84/0x24 的重试未触发）；present params 的 `Windowed=0`
- 模式枚举：`GetAdapterModeCount(0,22)=15` 被调 16 次、`EnumAdapterModes` 15 次（引擎的"解像度一覧"日志）
- Clear(0,NULL,3,0,1.0f,0)：921600 像素清成 `0x00000000`（**第一次渲染动作**）
- boot 墙钟 ≈ 34.7 s（同一份二进制两次跑 insns / 地址 / 哈希全同 ⇒ 确定性）
- **未到 Present**（#17）⇒ 没有帧号 / 帧哈希

## 实现了哪些槽（槽号 = 偏移/4；★ = `.lst` 站点实测）
IDirect3D9（17 槽；最后一个方法 CreateDevice 在 +0x40）
- #0/1/2 QI/AddRef/Release（QI 认 IID_IDirect3D9 + IID_IUnknown，其余 E_NOINTERFACE）
- #4 +0x10 GetAdapterCount → 1（只有一台虚拟显示设备）
- #6 +0x18 GetAdapterModeCount ★0x498462 · #7 +0x1C EnumAdapterModes ★0x498486（越界 ⇒ D3DERR_INVALIDCALL）
- #8 +0x20 GetAdapterDisplayMode ★0x498D44（与 DDraw **同一份**虚拟显示器；桌面 32bpp ⇒ X8R8G8B8）
- #10 +0x28 CheckDeviceFormat ★0x49918D（一律 S_OK + **记录问了什么**：诊断环形 + 一行日志）
- #16 +0x40 CreateDevice ★0x497F47
IDirect3DDevice9（119 槽）
- #0/1/2 IUnknown · #7 +0x1C GetDeviceCaps ★0x499126 · #20 +0x50 SetDialogBoxMode ★0x4990C8
- #43 +0xAC Clear ★0x498B82（后缓冲用 `SurfaceArena` 的 **guest 像素**；D3DRECT 也真清）· #17 +0x44 Present ★
其余槽 = **loud trap**（`comUnsupported` 打印 iface+偏移+寄存器后停机器，⛔ 不静默返回 0）。
⚠ vtable 用一条 `fn=nullptr` 的哨兵撑到接口真实大小（119 槽）：否则 +0xB0 之后的调用会**读 vtable 之外的堆字节**
（变异 D 实测：去掉哨兵 ⇒ +0xE4 不再是 trap，机器一路跑飞）。

## 结构偏移表（实测 = 有 `.lst` 站点；推断 = 按 d3d9.h）
- `D3DDISPLAYMODE` **16 B**（⛔ 不是 plan 文档写的 12 B）：Width +0 / Height +4 / RefreshRate +8 / **Format +0xC**
  · Format@+0xC 实测 `0x498C71`（当 D3DFORMAT 打印并传给 GetAdapterModeCount）；宽高实测 `0x498EEC`/`0x498F5C`
- `D3DPRESENT_PARAMETERS` **56 B**（memset `0x38` @`0x498F0A` 实测 + 逐字段站点全部对上）：
  +0 宽 / +4 高 / +8 格式 / +0xC BackBufferCount / +0x10 MultiSampleType / +0x18 SwapEffect /
  +0x1C hDeviceWindow ★`0x498F9E` / +0x20 Windowed / +0x24 EnableAutoDepthStencil ★`0x498F88`=1 /
  +0x28 AutoDepthStencilFormat ★`0x498F8E`=75 / +0x2C Flags ★`0x498F98`=1 / +0x34 PresentationInterval ★`0x498FBF`
- `D3DCAPS9` **0xD4 B**：**MaxTextureWidth +0x58 / MaxTextureHeight +0x5C 实测**（`0x499128`/`0x49912E`），
  其余按 d3d9.h 推断；整块 0xD4 字节**全部写成确定值**（夹具用两块 0x00/0xFF 初值的缓冲验证逐字节相同）；
  shader 版本报 **0**（本线没有 shader，⛔ 不谎称 vs_3_0 让引擎走进没实现的路径）

## 范围
把 patch 变成**能用的工作界面**。机械视图与编辑回路**已交付**；剩下的只有**旧式注释层**。

## 已交付
### ① 机械视图（`pnpm tools patch view`）——★ 持久侧只放"依赖不可变输入"的东西
* `data` = 基线 BIN 的反汇编（`--view` 的**缺省**）；`src` = 基线 + patch 的反汇编（字符串取 patch 里的中文）；
* 两者**同构**（同一套行形状、同样的**真实地址**）⇒ 可并排读；
  ★ 但**行数会不同**（`insert-after` / `delete` 正是 patch 的内容）⇒ 配对要锚在**基线行序**上、不按行号；
* ★ **`src` 不常驻**：`src` = `base 行 ∖ {被 replace/delete} ∪ op 载荷`（而 op 载荷就是中文）⇒ 查询时按锚现算
  （merge on read）；只有"用编辑器整篇改"才按支物化一支草稿。落盘清单见 `REQ-01M45AGK4JAGCX4KMZA6KRGBR1`；
* 规模与耗时**不手抄**：跑一次它就自己报。本节点曾记「223 个脚本 / 446 个文件」——
  那是**旧范围**下的数字，成因见 🐞 `REQ-01M43Y83BPG8E93NP0ESPB7N7S`。
* ★ 为什么 `src` 不直接用"重建 BIN 的反汇编"：BIN 里存的是**占位写法**（简体字多半编不进 cp932），
  BIN→中文**不可逆** ⇒ 中文只能从 patch 的载荷里取（重放两次：一次汇编用、一次展示用）。

### ② 编辑回路（两条路，判据同一条）
* **按锚直改**：`find --edits` **生成清单** → 人逐条审 → `set` 直改 op（改载荷 / `insert-after` / `delete`）；
  不渲染、不重跑 diff（`REQ-01M43YPP863JQW6JJQD6GK6BCQ`）；
* **整篇 / 折行**：`view --kind src --name X --out` 物化一支草稿 → 编辑器改 → `edit` 反解；
* 两条都：锚永远在**基线行序**上（`extractEntry` 是唯一的对齐实现，两边共用）；
  任何一处不过 ⇒ **一个字都不写**；写后回读复验，不绿回滚；
* 实测往返：改一处中文 ⇒ 反解 ⇒ 重新生成 `src` ⇒ 与改过的那份**逐字节相同**；
  改回原样 ⇒ 操作集与 `resultSha` **都回到原值**。

## 剩下的判据：旧式注释层（贴在机械视图之上，**不改指令流**）
1. **页边界**：只能由"连续文本类指令段"判（实测 `wait-for-input` **不是**边界：30 067 条里
   下一条 100% 是文本类指令、是 ADV 的 0%）；
2. `// FROM: <id> <名>`：实测 **100.0000% 可再算**（30 271 / 30 271 页）；
3. `// 输入原文：`：实测 **100% 冗余**（55.1% 与正文完全相同、44.9% 仅折行差异）⇒ 由 reflow 规则反向排版可得；
4. **原文存档块**（被译掉的日文）：逐字节能在基线反汇编里找到（30 145 / 30 145）；
5. `NAME_OVERRIDES` **5 行**（`b`/`c`/`81`/`138`/`170`）是唯一旁挂的人工数据；
6. 注释层必须是**可再算**的：`src` 视图里的注释一律由基线 + patch 现算，**不进 patch**。

## 范围口径：三个范围**互不相等**（这一条被混过两次）
* **注释层的范围** = 旧管线真正**标注过**的那批：说话人只对 `SC`/`SP` 做。代码里叫 `SPEAKER_FILTER`。
  **不要外推**：`SG`/`SN`/`CONFIG`/… 一条 `// FROM:` 都没有，按同一规则外推会凭空多出 180 个"页"。
* **patch 的范围** = 基线根里全部能反汇编的脚本，**由"产物 ≠ 基线"定，不许按名字筛**（`patch-design.md` §2.3）。
  ★ 一句话：**"没有 `// FROM:`" 只说明没做过页标注，不说明没有译文。**
* **落盘缓存的范围** = 基线根里全部能反汇编的脚本；而且现在**名单与逐支指纹取自基线索引**
  （键 = 基线指纹 + **codec 指纹**）⇒ "某个只覆盖一部分脚本的清单缩小检索范围"这件事从源头不成立。
* ⇒ **两个过滤器各自只在自己那一层用**：把注释层的过滤器用到视图生成上，就是 🐞 `REQ-01M43Y83BPG8E93NP0ESPB7N7S`。

## 已知要带上的口径
* `data`/`src` 用的是旧命名（如 `i20d`），与当前指令表不同 ⇒ 注释层做名字映射，**别改基线锚**；
* 视图头部 4 行**不许改**（`extractEntry` 会因头部不同而抛 —— 那是本方案能表达的范围之外）；
* **codec 指纹**（汇编器 / 反汇编器 / 指令表）是"BIN 是文本的可逆像"的证人：改了它要 `patch index --write`，
  并重跑 `patch verify`（旧译文的重建字节可能变了）；
* 别直接拿 `rg dist/views` 的结论当证据：`src` 根本不落盘（`find` 才是可信来源）。

## 非目标
* 不改 patch 的格式与锚（那是父节点的事；`extractEntry` 是唯一的对齐实现，两边共用）；
* 不做"文案怎么改"的业务（`REQ-01M3TCENZ0BCBBFEEDJNMDR75K`）；
* 不把视图落库（生成物一律 gitignore）。

## 目标

把"**指令表里每一个有 handler 的 opcode** 以什么形状碰了 `obj0` 的哪个偏移"变成**可复现的产物 + 命令**，
而不是一份跑完就丢的一次性输出。

## 为什么值得单独做

* 单族（`numeric-handlers.json` / `control-flow-handlers.json`）只能回答"这一族碰了什么"；
  **族边界本身要有依据** —— 例如"数值族"的边界是"被指令表命名为算数/比较的那一段"，
  而**体形相同**的 handler 远多于那一段。没有全表普查，族边界就只能靠印象。
* 未解析三类（`base=absolute` / `base=unresolved` / `index` / `width=unknown`）在**全表**口径下的报数，
  决定了"形状层当前能覆盖多少"——这是"下一轮该做什么"的唯一诚实来源（`docs/02-engine/shape-census.md` §7）。

## 判据

* 新增一个**只读**操作（候选：`pnpm tools shape census [--match <子串>]`），从
  `pnpm tools opcodes handlers` 的判据取 handler 集合，**一次载入语料**（⛔ 不要 543 次重载 `.lst`），
  产出：① 每个 handler 的对象根寄存器与站点分类计数；② `obj0` 偏移 → 命中它的 handler 列表（带站点 EA）；
  ③ 未解析三类的计数与样例 EA。
* **底数必须能与 `pnpm tools opcodes handlers` 对上**（赋值行数 = 有 handler 的 opcode 数；唯一符号数另报，
  因为存在**多 opcode 共用一个 handler** 的情形）。
* 产物落 `.tmp/`（派生、不入库）**或**按时入库 —— 但"入库"必须配同名 `.md` 与一条会红的守卫，
  否则就是一份 Markdown（`AGENTS.md` §8）。
* 与 `tools/lib/shape-access.mjs` 的 `census()` 的关系：那个是**全语料**口径（含非 handler 函数），
  本单是 **handler 子集** 口径，两者都要报（数字不同不是矛盾，是口径不同）。

## 已实测（一次性，需由上面的命令复现后才算入库结论）

* `pnpm tools opcodes handlers` 的赋值行 ⇒ 544 个有 handler 的 opcode / **543 个唯一符号**
  （`sub_419690` 被两个 opcode 共用）。
* 对象根寄存器分组：`ecx` 540 · 无根 3（`sub_418E60` / `sub_421EA0` / `sub_426FC0` ⇒ **不可检查**）。
* 两个"全表最热"的偏移形态：`0x5d880`（读为主、无索引）与 `0x5d8f4`（**全部**带 `stride=120` 索引、
  **全部是写**）—— 后者是"handler 把立即数写进记录数组同一个元素内偏移"的那个落点。
* 未解析（handler 子集）：`base=absolute` 178 site / 76 handler · `base=unresolved` 752 / 130 ·
  `index` 310 / 110 · `width=unknown` 4 / 4。
  ★ **订正（独立重测，2026-10）**：`index` **不是** `base=unresolved` 的子集 —— 实测 310 = 同时缺基址 128
  + **基址已解出、只是索引没解出 175** + 其它基址 7。后一类最容易变成**假观察**（位移少了索引那一项，
  却被当成"偏移 0/N"的观察）：已由 `offsetUnusable()` 从 `obj0` 偏移里剔出，另计一档。
  这条订正的来路 = 把"三类未解析各自报数"落成**可复现命令**时，两边数字对不上 ⇒ 回语料重数。
  ⇒ 教训与 `AGENTS.md` §6 同形：**一次性脚本的结论在重测之前只是假设**（哪怕它出自另一个 agent）。

## 还缺什么

「存档」章对**布局 1**（主版本 1 / 次版本 20）的容器只覆盖到"按两张表还原位置、推进 3 / 0"；**暂存块**与两张位置表在容器里的字段与下标语义没有成篇。`0xae` 本方的那一段已判清（见下），缺的是读入侧 / 装帧侧。

对应残差：`RES-OPS-SAVE-VERSION-AE-LAYOUT1`（保持 `unknown`，指向本单）。

## 入口 EA

- `0x4192F0`：opcode `0xae` 的处理体（读 `set:SaveVersion1` / `set:SaveVersion2`、按主 / 次版本分派）
- `0x40F750`：按 (主版本, 次版本) 应用一套布局（`(1,10)` 与 `(1,20)` 各一条子支；布局 2 / 3 也走它）
- `0x40ED40`：由**暂存块**重建帧（布局 1 的两次调用各传一个下标）
- `0x410160`：存档读入 / 装帧（`0x4105C8` 处是一次 `cmp …, 14h`）

## 已经知道什么

- `0x4192F0`：主版本 ≠ 1 ⇒ 走布局 2 / 布局 3，次版本原样传下去；主版本 = 1 时**只有次版本 = 20**（`cmp edi, 14h` @`0x419353`）才应用，否则直接返回。
- 布局 1 的两族位置表：第一族取 `[帧记录 +0x5D8E0 处的表][下标]`，第二族取 `[帧记录 +0x5D8D8 处的表][下标]`；指令指针 = 代码基址（`+0x5D894`）+ 4 × 位置值（`0x419381`..`0x419393`）；第一族命中 ⇒ 推进格数写 **3**（`0x4193A6`），第二族 ⇒ 写 **0**，两个下标都 < 0 ⇒ 位置不动。
- `0x40F750` 的 `(1,20)` 子支：先按暂存块重建帧（转 `0x40ED40`），再按两张表还原位置；布局 2 / 3 还会把位置写回位置格，布局 1 不写。

## 还缺什么（具体）

- `0x40ED40` 的入参块（暂存块）的字段：块号从哪来、块内是"整帧快照"还是"增量"、与每帧记录的关系；
- 两张位置表在容器里的元素与下标语义（位置值是代码区里的 dword 下标？下表是哪个池）；
- 版本 1 的容器头（版本 2 / 3 的容器已在「存档」章）。

## 判据（什么算做完）

- 能按字段写出布局 1 的容器（暂存块 + 两张位置表）并说明每个下标的含义；
- 用一个 (1,20) 存档验证「换脚本位置族优先 / 否则回退族 / 下标 −1 不动」三支与推进量 3 / 0；
- 结论并进「存档」章的版本 1 条，并把本条残差从 `CORE-OPS-SAVE-VERSION-AE` 删掉。

## 为什么拆单

`0x410160` 是 1500+ 行、`0x40ED40` 另有闭包 ⇒ 超出单轮预算（约 3 个新函数 / 200 行），且要引入"容器格式"这一层概念（R4）。

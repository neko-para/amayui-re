* **帧记录（per-cur 对象）基址 = `Engine+0x5D894`；记录大小 = 索引步长 = `0x78`（120 B）。**
* 判据 = 全语料机械普查，**只认以 cur 索引**的形态 `[reg+reg*8+5D8xxxh]`（`reg = 15·cur` ⇒ 净 `120·cur`）：
  命中的绝对地址**恰好落在 `[0x5D894, 0x5D908]`**（最小 = 基址、最大 = 基址 + `0x74`）；
  区间 `0x5D870..0x5D893` 与 `0x5D90C` 以上**零处** ⇒ 记录大小 = `0x74 + 4 = 0x78`，与下一条记录的 `+0x00` 严丝合缝。
* 关键否定观察：`0x5D880/0x5D884/0x5D88C/0x5D890` 全语料**一个 `*8` 形态都没有**（只有绝对形态）⇒
  它们是 **Engine 级标量**（`0x5D880` = 当前帧号 `cur`：装载器 `sub_40ED40` 体内 `.text:0040EDD0` 一族
  拿它算 `120*cur` 做记录索引；`0x40FC7B` 装载前写 `0x25`），**不是记录字段**。

### 第 1 项：记录真实大小 ⇒ **`0x78`**（不是 `0x8C`/`0x90`/更大）
原先那条「下界 ≥ `0x8C`」是把记录基址取成 `0x5D880` 算出来的**假偏移**：`0x40F63B` / `0x40F678` 写的
`0x5D904` / `0x5D908` 相对**真基址**是 `+0x70` / `+0x74`（都在 `0x78` 之内）⇒ 索引步长与记录大小**是同一个量**。

★ **诚实登记（任务指定的形态没有）**：语料里**不存在**「Size 直接等于记录大小」的指令 ——
`sub_40ED40` / `sub_40EA00` / `sub_405640` 里出现的 size 常量只有 `0x84` / `0x528`
（**另两块** per-cur 状态块的 `Size == 步长` 形态，落点 `Engine+0x69334` / `Engine+0x6A7D4`）、
`v30+1`（文件长度）与指针数组长度；记录本身由 `sub_405640` **逐字段**重置
（`+0x00/+0x20/+0x24/…/+0x74`，18 处），**没有**整条 `memset` / `operator new`。
⇒ 记录大小是**由"基址 + 最大字段偏移 + 不重叠"夹出来**的，不是由一条 size 常量给出的（这条"没找到"本身是产物）。

### 第 2 项：三格归属 ⇒ **帧内三格**（不是独立数组）
`0x5D8F8` / `0x5D8FC` / `0x5D900` = 记录内 `+0x64` / `+0x68` / `+0x6C`（同一 `120·cur` 索引口径；
与记录字段落在同一个 `[0x5D894, 0x5D908]` 区间内）⇒「`+0x78` 区是下一帧的 `+0x00`」那条读法**不成立**。

### 旁证（不单独当判据）
`0x5D894 + 40*0x78 = 0x5EB54` 正好是帧区之后那个成员（全语料 94 处引用）；而 `0x5EB54 − 0x5D880`
**不是** `0x78` 的整数倍。★ 反向判据（本轮补）：旧算术的 `0x5D880 + 40*0x78 = 0x5EB40` 在 `.text` 里**零处**引用。

# emulator-lift · overlay PROFILE 按钮：点击定界区间 profile，结束写剪贴板

## 目标 / 用户面

overlay 上提供一个**通用 Button**承载 **PROFILE** 功能：第一次点击开始一段区间 profile，再次点击结束；结束时把**结论文本**写入系统剪贴板，并在 HUD 上给一行状态（开始 / 已复制 / 失败 / INVALID）。

## 已裁决（2026-11-18，用户）

1. **结论范围**：只保证现有 AOT profile 能力（`AotWindowProf` 的桶 + shim 具名行）；不做函数 / 块级新仪器，不引入解释器 `WindowProfiler`。
2. **通用 button + JS 组件库**：C++ 只做原语（display list / resolved-rect 命中 / capture / `game.click|hover|active`）；按钮外观、布局、状态、主题放 JS 侧的 `scripts/ui/kit.js`。⛔ 不做 C++ `ui.button`，也不做独立 `ui.hit`；`key` 挂在 `ui.rect` 上（画出的 rect 即命中区，零换算漂移）。
3. **短窗口**：`sampled==0` / `unaccounted` 超限时文本保留 `INVALID`，**仍复制**（不拒绝）。
4. **验收档位**：e2e / 剪贴板用手动验收，**不进默认 CTest**（overlay 是业务功能；默认档只保纯逻辑）。
5. **默认 overlay 必须自带 PROFILE 按钮**（不能要求用户改脚本）⇒ 默认 `hud.js` 通过 `// @include kit.js` 使用组件库；`kit.js` / `hud.js` 一起发行，缺 kit 与缺 hud 同属**硬失败**（由发行打包保证）。`--ui` 仍是单路径，用户的脚本可用同一 `@include` 引组件库。

## 现状（2026-11-18 评估，只读）

- **profiler**：AOT 有 `AotWindowProf`（`src/aot/window_prof.h:52`），`AotHost::beginWindow(label)` / `endWindow()`（`aot_host.cpp:1236/1279`）已是全部接口；`endWindow` 直接 `printf`。配方 `profile_begin/end` 走同一对函数。
- **overlay**：`UiBuilder` 只有 Rect / Text，`Element` 无 `interactive`；`SdlWindow::handleEvent`（`present_sdl.cpp:556`）把四类鼠标事件**无条件**转给 guest；`mapMouse` 不能复用到 overlay。
- **脚本加载**：`UiScript::load` 单份源码、`JS_EVAL_FLAG_STRICT` 经典脚本；**无 module loader**，`import` 编译期失败；入口 `globalThis.render`；`--ui` 单路径（重复给会静默覆盖）。**新增 `@include` = 同一 context 按序多次 `JS_Eval`**（约 50–80 行；错误按文件行号）。
- **剪贴板**：全仓零实现；SDL3 有 `SDL_SetClipboardText`（UTF-8、bool、主线程），**不需要** user32 shim。
- **旧口径**：`input_plan.h:41` 的「本臂没有区间 profiler」已过时（AOT 2026-11-17 已有）。

## 设计（待实施）

1. **报告文本化（先做，可独立测）**：把 `endWindow()` 的打印体抽成 `formatWindowReportText(const AotWindowProf&, ShimNameFn, top=8)`，放 `src/aot/window_prof.cpp`（runtime lib，pure 可测）；`endWindow` 改为 `fputs` ⇒ stdout 逐字不变。≤20 行：label / wall / iter / sampled / insns / frames、lift / boundary / shim / instrument / unaccounted / coverage、Top-8 shim + `(rest)`、verdict、lift_dyn。⛔ 不含 `.lst` 函数名。
2. **宿主桥**：`AotHost` 增 `endWindowText(std::string*)` 与 `profileOpen()`；已开时 `beginWindow` 返回 false（⛔ 不再静默 `reset()`）；未闭合在 run 收口打一行 warn。
3. **C++ 命中原语**：`Element` 加 `std::string key`；`ui.rect({key,...})` 的 resolved rect 即命中区（不另存 hit 数组、不 clamp 到画布）。按**上一帧成功 present** 的绘制序逆序命中；`game.click` 一次性 `{key,x,y}`，`game.hover` / `game.active` 只读 key。
4. **事件边界**：左键 down 命中 ⇒ 吞 + capture；up 无条件吞，抬起点在同一 key 的 rect 内才发 click；motion / wheel / 右键放行；拖出取消；关闭 / 失焦 / 新 down 清 capture。⛔ 不在 `handleEvent` 里跑 JS / 开 profile / 写剪贴板（它可能在 guest `GetMessageA` shim 内）——只记 pending，下一帧由脚本消费。
5. **JS 组件库**：`scripts/ui/kit.js` 用 `ui.rect/text/measure` + `game.click/hover/active` 实现 Button（外观 / 三态 / 主题）；`scripts/ui/hud.js` 首行 `// @include kit.js` 并组合出 PROFILE 按钮。`kit.js` 必须是**纯 JS**（不碰 QuickJS 宿主 API，除 `ui` / `game`）；`kit.d.ts` 跟随 `ui.d.ts` 分发。
6. **接线**：`host.profileBegin(label)` / `host.profileEnd()`（返回 `{ok,text,error}`）+ `SDL_SetClipboardText` + 一行 stderr；HUD 状态失败 / INVALID 都要可见。
7. **平台**：macOS 高密度屏确认 `presentGeometry`（像素）与 SDL 事件（点）的 ratio；headless 下 `--overlay` 已拒；`--present auto` 隐藏回退可复制但不可点击。

## 切片

1. 报告文本化 + `aot-window-report-text`（pure）+ `aot-window-state`（double begin / cancel / unclosed）。
2. C++ 命中/捕获 + `ui.rect.key` + `game.click/hover/active` + `ui-hit` / `ui-click-router`（pure）；`@include` 多文件加载 + `kit.js` + `ui-kit-script`。
3. 接线 `AotHost` 桥 + `host.profile*` + SDL 剪贴板 + HUD 状态；`hud.js` 用 kit 画 PROFILE 按钮。
4. **手动验收**（不进 CTest）：CONFIG 里点开始/结束，剪贴板文本含 wall/Top/INVALID，命中点击没到 guest。

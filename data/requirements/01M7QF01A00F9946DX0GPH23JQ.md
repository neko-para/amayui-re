# emulator-lift · overlay PROFILE 按钮：点击定界区间 profile，结束写剪贴板

## 目标 / 用户面

overlay 上提供一个**通用 Button**承载 **PROFILE** 功能：第一次点击开始一段区间 profile，再次点击结束；结束时把**结论文本**写入系统剪贴板，并在 HUD 上给一行状态（开始 / 已复制 / 失败 / INVALID）。

## 已裁决（2026-11-18）

1. **结论范围**：只保证现有 AOT profile 能力（`AotWindowProf` 的桶 + shim 具名行）；不做函数 / 块级新仪器。
2. **通用 button + JS 组件库**：C++ 只做原语（display list / resolved-rect 命中 / capture / `game.click|hover|active`）；按钮外观、布局、状态、主题放 JS 侧 `scripts/ui/kit.js`。⛔ 不做 C++ `ui.button`，也不做独立 `ui.hit`；`key` 挂在 `ui.rect` 上。
3. **短窗口**：`sampled==0` / `unaccounted` 超限时文本保留 `INVALID`，**仍复制**。
4. **验收档位**：e2e / 剪贴板手动验收，**不进默认 CTest**（overlay 是业务功能）。
5. **默认 overlay 自带按钮**：`hud.js` 用 `import { Button } from './kit.js'`；kit/hud 一起发行，缺 kit 与缺 hud 同属硬失败；`--ui` 用户脚本可用同一 import。

## 现状（2026-11-18 评估）

- **profiler**：AOT 有 `AotWindowProf`；`AotHost::beginWindow/endWindow` 是全部接口，`endWindow` 直接 `printf`。配方 `profile_begin/end` 走同一对函数。
- **overlay**：只有 Rect/Text，`Element` 无 interactive；`handleEvent` 把四类鼠标事件无条件转给 guest；`mapMouse` 不能复用。
- **模块**：QuickJS-ng 能力**完整**（`JS_EVAL_TYPE_MODULE`、`JS_SetModuleLoaderFunc`、Promise、TLA、动态 import）；宿主只是**没接** loader。上一版 `@include` 是错误取舍（把"宿主没接"当成"引擎没有"）。探针：`import` 可用；`JS_Eval(MODULE)` 返回 **Promise**，必须 `JS_AddIntrinsicPromise`；入口仍可 `globalThis.render = ...`。
- **执行点**：`drawOverlay` 只在 guest **Present** 时调（`submitFrame`/`submitDirect`，≤1 次/提交），不是每个宿主帧；两次 Present 之间 / 叠层失败时 0 次是常态。单次 render 远低于 1 ms。
- **剪贴板**：零实现；SDL3 `SDL_SetClipboardText` 可用，不需要 user32 shim。

## 设计

1. **报告文本化（先做）**：`endWindow()` 的打印体抽成 `formatWindowReportText(const AotWindowProf&, ShimNameFn, top=8)`，放 `src/aot/window_prof.cpp`（pure）；`endWindow` 改 `fputs`，stdout 逐字不变。≤20 行：wall/iter/sampled/insns/frames、lift/boundary/shim/instrument/unaccounted/coverage、Top-8 + `(rest)`、verdict、lift_dyn。
2. **宿主桥**：`AotHost` 增 `endWindowText(std::string*)` 与 `profileOpen()`；已开时 `beginWindow` 返回 false（⛔ 不再静默 reset）；未闭合在 run 收口打一行 warn。
3. **C++ 命中原语**：`Element` 加 `std::string key`；`ui.rect({key,...})` 的 resolved rect 即命中区；按上一帧成功 present 的绘制序逆序命中；`game.click` 一次性 `{key,x,y}`，`game.hover/active` 只读 key。
4. **事件边界**：左键 down 命中 ⇒ 吞 + capture；up 无条件吞，抬起点在同一 key 的 rect 内才发 click；motion / wheel / 右键放行；拖出取消；关闭 / 失焦 / 新 down 清 capture。⛔ 不在 `handleEvent` 里跑 JS / 开 profile / 写剪贴板；只记 pending，下一次 render 消费。
5. **模块加载**：`JS_DetectModule` 自动选 classic/module（保留 `--ui` 经典语义）；module loader 160–220 行（relative resolve / 读文件 / 缓存 / 拒绝 bare、absolute、`data:` 与 `..` 逃逸）；`JS_AddIntrinsicPromise` + 删 `globalThis.Promise`；module eval 返回 Promise ⇒ drain `JS_ExecutePendingJob` + 检查 rejection；`--ui` 顶层 `function render(){}` 的旧语义不变（classic 仍走现有路径）。`@include` 只作"不加 Promise"的退路。
6. **接线**：`host.profileBegin(label)` / `host.profileEnd()`（返回 `{ok,text,error}`）+ `SDL_SetClipboardText` + 一行 stderr；HUD 状态失败 / INVALID 可见。
7. **平台**：确认 `presentGeometry`（像素）与 SDL 事件（点）的 ratio；headless 下 `--overlay` 已拒；`--present auto` 隐藏回退可复制但不可点击。

## 执行模型（本单不改，只留扩展点）

- 当前 = 每次 guest Present 一次 `render`，不是定时器；`script.pos` **尚未暴露**（`UiFrameInfo` 无 pos；`EngineFrameSource` 未读 `+0x04`）。最小改动 40–60 行：`UiFrameInfo.pos_ok/pos`，公式同 `await position`（`0x3C + pc−base`）；只有 `top` 帧是当前执行点。
- "执行到 pos 之后的下一次调用" = **下一次 Present 的 render**，天然满足；要晚一帧用 `game.frame + 1`。
- 未来异步 = `game.when({script,posFrom,posTo}, id)` 在 `drawOverlay` 里 C++ cheap 判 + `game.event` one-shot；**不**引入 Promise 协程（与现有"无跨帧控件树"冲突），也⛔不在 `handleEvent` 里跑。
- 风险：pending click 依赖下一次 Present；guest 阻塞在 `GetMessageA` 且不再 Present 时可能活锁 ⇒ 需要宿主主动 request redraw（本单待核）。

## 待核

- 一次 render 失败即**永久关闭叠层**（代码是一枪；文档说 3 次）——影响长跑稳定性。
- AOT 的 `UiReadings` 尚未接线（`game.script` / `game.worst` 在 AOT 下可能 undefined）。
- `--input-plan` 的 click 不过 `handleEvent`，不能用来验证 overlay 命中。
- DPI 点 vs 像素；`kit.js` / `kit.d.ts` / `hud.js` 的发行打包（`release/` 无复制规则）。
- `@include` 的路径/循环/错误行号（仅退路）；M1 宿主布局落地时 JS 布局不能长成第二套引擎。

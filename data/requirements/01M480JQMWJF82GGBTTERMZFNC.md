## 背景（为什么是单独一张单）
M3 只落了台账的**记录 schema 与四条不变量**，分类维度只有 `kind`（台账的结构分类：claim/observation/note）。
**知识本身的域分类（音频系统 / 渲染系统…）在 M3 里没有落** —— 这是框架里漏掉的一维，不是数据没填。

旧仓实测：分类**存在但不同构**，且**无法 join**：

| 层 | 字段 | 取值 |
|---|---|---|
| `analysis/engine-capabilities.json` | `subsystem` | 12 个**中文粗**标签（消息窗 / 渲染 / 帧循环 / 3D / 资源 / 声音 / Live2D / 输入 / 转场 / 存档槽 / AGERC / ScriptContext） |
| `analysis/fields.json` | `scope` | 18 个**英文细**标识（`Engine` / `Font` / `SoundDriver` / `PCM` / `Scene` …） |
| `analysis/functions.json` · `scripts.json` | — | **无任何分类字段** |

实测交叉：146 条 capability 里 141 条能通过 `reads` 反查到 `scope`，但**方向单向** ——
`subsystem = 声音` 的三条读的都是 `Engine` 字段，而显然属于声音的 `SoundDriver` / `Device` / `PCM`
在 capability 层看不出归属 ⇒ **两套词表之间的映射表不存在**，而它本身就是**待产出的知识**。

## 范围（★ 只落机制，**不填任何值**）
1. 记录 schema 增**必填** `system`（域）：与 `kind` 并列，但 `kind` 是**台账机制**的分类，`system` 是**知识**的分类。
2. 词汇表与旧仓同构的形态：**域词汇表 = 台账里 `kind=domain` 的记录**（同一套 append-only 纪律、同一套锚点要求），
   不另造第二个真源、也不新增第二套读写路径。
3. **处置声明**（闭集合 `disposition`）+ **别名链**：让"历史行里写过的值"永远可解释。
4. 一条新不变量：**记录里的 `system` 值必须能沿别名链追到当前词表**；追不到 ⇒ 红（= 该值待裁决，不许静默过）。
5. 派生 DB 加 `system` 列与 `domain` 投影表；CLI 加查询入口。
6. ★ **词汇表本轮留空**：归一到哪 ~15 个域、旧仓两套词表怎么合，是 **K1 的活**（要摊开旧仓实测取证），
   本节点只保证"机制在场、空词表下一切照常绿"。

## 为什么不是"直接编辑的词表"
词表的读者有两个：人（读当前态）与**校验器**（要判断**已经写下的历史行**合不合法）。
直接编辑的代价是历史行的值**悬空**：一改名就让全部历史记录变红，或只能放宽校验（等于没校验）。
需求单可以"就地编辑"是因为**没人需要重放它的历史**；词表恰好相反。（口径与外部依据见 `decisions.md` §8.1。）

## 为什么"拆分"决定性地压倒了"直接编辑"
- **改名 / 归并**：含义没变、只是叫法归一 ⇒ **别名可解析**，历史行**一个字节都不用动**。
- **拆分 / 重定义**：含义变了 ⇒ `渲染` 被拆成 A/B 之后，一条历史记录写 `system=渲染` **永远分不出该归谁**，
  只有那条记录自己的 `claim` 与 `anchor` 能回答 ⇒ 必须走**追加更正记录**（台账已有的 `replaces`），
  **不许**用词表悄悄改结论的含义。
- 本仓实测先例：`script-dsl` 的职责被重划进 `age-format`（`git log` 可查），旧名字在数据里没留痕迹 ——
  正是"重定义"这一类。

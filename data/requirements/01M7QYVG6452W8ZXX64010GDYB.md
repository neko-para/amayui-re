## 目标（架构单，短期不排期）

把**引擎自身的逻辑（内存布局 + 语义）**与**模拟器**之间划出一条显式边界，并把"引擎层"当成**可替换的一层**：

- **模拟器核心（项目无关）**：地址空间与执行、shim 接口的 ABI 转发、呈现后端、控制层传输协议（JSON / WS）、
  以及"**读 / 写 guest 内存的裸原语**"。它**不认识**具体引擎的字段与语义。
- **引擎层（AGE 专属，可替换）**：script global 的**池布局 / 类型族 / ENC-DEC**、帧与槽的读数、script 位置语义、
  dshow / DDraw 的 COM 对象字段与虚表槽序……
- **天結 专属**：脚本、资源、配置、界面知识（例如哪个 global 的哪一位控制哪张覆盖图）。

★ **不要把"typed global 读写"当成"通用能力"**：它**就是引擎逻辑**。其它 AGE 引擎是否采用同一套 global
池 / 类型 / 编码策略，是**待证明**的问题（要第二部 AGE 作品的二进制或脚本来证），
⛔ 不能因为"看起来会复用"就把它写进模拟器核心的承诺里 —— 它属于**引擎层**，只是**放在可替换的位置**上。

## 为什么现在登记

近期几件事已经把"模拟器"与"天結 的引擎细节"焊在一起了（都是可再校验的锚）：

- script global 的**寻址与编码**：`rd32(Engine+0x5D800) + 4*id`、`int` 过 `ENC/DEC`（key `0x5EC8C`）、
  `0x6d` 会交换 `5D800↔5D804` —— 这些是**引擎实现细节**，不是"模拟器"的一部分。
- **QJS 绑定**里已经在查引擎的帧/槽/读数（`game.*` 的 getter 直接读 guest 布局）。
- shim 侧同类：dshow 的 `[filter+0x34]` / `[renderer+0x6C]`、`CBaseFilter` 的虚表槽序等。
- 目标是天結，但**后续不排除给其它应用适配**：那时若这些常量散落在核心路径里，第二个应用就得改模拟器核心，
  而不是"换一层适配"。

## 与 SCOPE「不实现 shim」的区别（用户 2026-11-19 明确）

- SCOPE 那条是**模拟器层面的通用策略**：Menu / Reg 相关 shim 不做。它是**项目无关的 tradeoff**，
  即使哪天实现了，也**不破坏天結的语义**。
- 本条是**架构分层**问题：同一个引擎知识写在哪里、谁依赖谁。两者**不同层、不冲突**，⛔ 不要互相引用成判据。

## 达成判据（将来收口时用）

1. 模拟器核心路径里**不再出现**天結专属常量 / 偏移 / 语义（可用 grep 类守卫钉住禁用词表）；
2. 这些知识集中在**引擎层**，**换引擎 = 换引擎层、换应用 = 只换应用层**（都不需要改核心）；
   ⚠ "同属 AGE 的其它作品能不能直接复用引擎层"是**要证明的**（不是设计承诺）。
3. **不改变 guest 可见语义**：迁移前后语义指纹逐位相同（`exit` + `frames` + `stop @` + arena + `table misses`）。

## 不做 / 边界

- ⛔ 现在**不排期、不重构**（只是登记要点）。
- ⛔ 不拿它当"引擎知识可以先写死"的挡箭牌：新知识仍要走 `AGENTS.md` §6 的准入门（锚 EA / 守卫用例 id）。
- ⛔ 不为了"分层好看"改变任何**现有**行为；任何迁移必须**语义指纹不变**。

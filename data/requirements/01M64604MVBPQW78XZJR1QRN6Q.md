# 🐞设置界面下方 ADV 示例文本只展示一次（预期按推进速度循环重放）

- id: REQ-01M64604MVBPQW78XZJR1QRN6Q

- status: done
- parent: REQ-01M5BK8QMQYK7XQG707YVMQ202
- verify: apps/emulator-cxx/tests/core_selftest.cpp#演示闸没有循环
- repro: apps/emulator-cxx/tests/core_selftest.cpp#演示闸没有循环
- severity: S2

## 现象（用户口径 2026-10-29）

设置界面下方那段 ADV 示例文本，预期是**不断重复刷新展示**的（让用户能看到文字推进速度）；
实际只展示一次，之后纹理完全不变。（用户补充："我怀疑是部分逻辑丢失了"。）

## 根因（已定位）

- 真机**确实循环，但循环不在脚本里**：脚本 52（`CONFIG.BIN`）在 clock 2720ms 只做
  `0x300 9 1 1000` → `0x71 9` → `0x196` / `0x6e` → `0x6f`，之后**不再追加**。
- 循环由**引擎文本泵**（EA `0x409400`）的 `0x300` 服务支完成：每 `message:MessageSpeed` 毫秒从层记录的
  揭示游标揭示一格（EA `0x45BE20`）；整段揭示完记起点，`现在−起点 ≥ 期限` 时清掉该层两段绘制键区间、
  把揭示游标归 0，**闸位保持**（EA `0x404F80`）⇒ 从第一格重来，无限重复。
  ★ 第 29 位的保持判据是"本轮**有槽进了节奏支**（第 0 位置起且参数格 ≠ 0）"（EA `0x409454` 的计数 +
  `0x4094E5`），⛔ 不是"第 16 位有槽在用"；参数格 = 0 时抽干后**跳过**记起点 / 期限清除（EA `0x409452`）
  ⇒ 只揭示一次、**不重放**。
- 我们的 `0x300` / `0x301` 是**空壳**：只写三张没人读的 map（`font_slot_state_` / `font_slot_deadline_` /
  `font_slot_start_`），文本泵只服务普通打字队列、末格清 29 ⇒ 播一遍就停。
- **spec 也错了**：`CORE-OPS-TEXT-SLOT-TIMER` 把同一机制写成"定时**释放字体资源**"、服务支写成
  "参数格=0 ⇒ 只等空闲"，且漏了逐格揭示、清绘制条目重放、以及第 29 位的保持判据。

## 修法

1. **spec**：重写 `CORE-OPS-TEXT-SLOT-TIMER`（槽 = 十个文本层记录；`0x301` = 清起点 + 清该层绘制条目 +
   揭示游标归 0；服务支 = 逐格揭示 / 到期清 + 重放 / 节奏支保持第 29 位 / 参数格 = 0 是"抽干且不重放"）；
   `62-adv-text` 的逐字符条补"演示闸层走重放支"与判据；`40-pools` / audit 里两条被证伪的残差同步更正
   （槽表有写者；旧格释放不止 `0x71`）。
2. **实现**：每层保留**字符格**（沿用 `PendingGlyph` 的样式快照）与**揭示游标**；`service_text_layers`
   先服务闸门层（只走槽 1..9）；`0x301` 清该层绘制条目 + 游标归 0，**不清像素、不删字符格**；
   闸门层不进入普通打字队列（否则同一条文本有两个推进者）。

## 验证

- CTest `emulator-core-text-gate-replay`：一段文本 + 开着的闸，必须出现 ≥2 次
  "逐格揭示 → 停「期限」→ 条目全消失 → 从第一格重来"，期间没有新的 `0x6e` / `0x196`；
  `0x301` 只清条目 + 游标，像素与字符格必须还在；节奏支里第 29 位保持；
  参数格 = 0 时一次揭示完、`cycles = 0`、第 29 位被清。
  **变异实测**：把闸门服务关掉（循环上界写成 1）⇒ 当场红（"闸门层一个像素都没落"）。
- CTest `emulator-core-config-sample-text`（游戏安装档）：在真实设置界面上断言
  `text-gate slot=9 cells=22 cycles>0`。**实测 19 秒内重放 9 轮**（修前 `cycles=0`，且 19s 与 169s 的
  纹理 29 逐字节相同）。

## 归因

**spec 错 + spec 缺失**：`0x300` / `0x301` 是"照错 spec 实现的空壳"，不是脚本解释少了一条指令，
也不是绘制侧丢重绘（绘制条目与像素都在，缺的是"清 + 重放"这一歩）。

## 仍欠

- 真机"揭示完停 1000ms"的墙钟表现没有采样（本次是静态读码 + 端到端 cycles 计数）。
- 多槽共用同一个毫秒计时器的后果：引擎"未到期就结束整轮服务"（`0x409464`）⇒ 两个活动闸层时只有最低
  槽号那层推进；本实现按每层各自到期时刻推进。**已知实现选择**，见残差 `RES-OPS-300-SERVICE-INTERFACE`。
- 槽号 / `0x1d2` 列表号 / 字体对象十项槽表的同一性仍未证（残差 `RES-OPS-300-SLOT-TABLES`）。

# data/ledger/ — 台账真源（append-only 文本日志）

## 1. 本目录将来放什么

**台账的真源**：append-only 的文本日志（一条记录一行）。派生 SQLite 查询层**不在这里** ——
它由 `packages/ledger` 生成到 `.cache/`（gitignore），且**永不入库**。

## 2. 本轮状态：**没有任何条目（有意为之）**

旧仓的知识资产（`analysis/` `tickets/` `docs-new/`）**一律不迁移**：它们需要清理 / 校验 / 重分类。
见 `docs/00-origin/knowledge-rebuild.md`。**K3 通过前，任何知识条目不得进这里。**

## 3. 格式草案（M3 定稿；此处只立方向）

| 约束 | 口径 |
|---|---|
| 记录 | **一条记录一行**，自带 `ULID` 或 `时间戳+计数器` ⇒ 顺序不依赖文件位置 |
| 分片 | 按 key 前缀或按月 ⇒ 把并发追加的冲突窗口降到接近 0 |
| 合并 | 两台设备各自**追加不同行** ⇒ git 三路合并天然干净 |
| 问责 | 每条结论都有 `git log -L` 可追的链条 |
| compact | 周期性产出 canonical 排序的 snapshot —— **仍然是文本** |
| DB | 派生只读查询层；**删除本地 DB 后必须能用一条命令确定性重建（同输入同字节）** |

## 4. 为什么不能反过来（反模式）

把 `.sqlite` 提交进 git / 用 LFS 存 DB（LFS 不解决合并）/ 把 DB 当唯一存储 /
用 `sqlite3 .dump` 当文本真源 / 让 DB 参与写事务再"导出"成文本。

## 5. 迁移批次

**M3**：`packages/ledger` 的文本日志格式落地 + 派生 SQLite 构建 + "DB 可删可重建"守卫。
**只落格式与守卫，不含任何旧条目**（前置：本草案定稿）。

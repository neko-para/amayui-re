# 落笔约定（在 `src` 视图的**指令行**上）

> 来源：旧仓 `amayui-script-translate/references/conventions.md` 的**纯约定**部分，已按本仓的
> 「指令行视图 + patch 叠加层」重写。**与旧仓具体工具/路径绑死的东西一律没带过来**（见 §10）。
> 凡本仓**没有复核过**的旧结论都显式标了「未复核」。

## 0. 改什么、不改什么

| | |
|---|---|
| **可改** | 字符串字面量（双引号内的**中文**） |
| **不可改** | 助记符、操作数、label 名与 label 定义行、头部 4 行（`==Binary Information - do not edit==` 那块） |
| **可增删** | **文本类指令行**（折行/合并时加删 `show-text` / `end-text-line`）—— `patch edit` 会把它表达成 `insert-after` / `delete` |

★ 旧仓的两种语法在本仓**不存在**，不要用（实测本仓视图里 `|` 0 命中）：

* ~~`set-string "原文\|译文"` 对语法~~ —— 视图里**已经是最终中文**，改就是改；
* ~~`@"译文"` 中文标记~~ —— 同上。

★ 改完**必须**过判据，而且**每处都有人看过**：`pnpm tools patch find '<旧串>' --edits e.txt [--to '<新串>']`
**生成清单**（一条记录一处，头行是 `<脚本> <锚>[+<k>]`，带"期望的当前内容"）→ 逐条审 `e.txt` →
`pnpm tools patch set --edits e.txt`（dry-run 逐条打「- 现在 / + 改后」）→ `--write` 一次写盘 →
`pnpm tools patch verify`。**折行拆分 / 合并**（行数变化）走 `patch view --kind src --name X --out` + `patch edit`。
不要手工去动 `data/translations/patch.json`。
★ **`src` 投影不常驻**：它是 base 与 patch 的 join 结果（按锚现算）；只有"用编辑器整篇翻译"才物化一支草稿。
★ **不要"一条命令全库替换"**：机械替换会误伤同形词（实测 `赫塔→废柴雷斯` 得到"废柴雷斯雷斯"），
所以替代口径只有"生成清单 + 逐条应用"（用户口径）。

## 1. 折行

* **≤ 25 中文字 / 视觉行**（ASCII 按半字计）；
* 行与行之间 `end-text-line 0`；**页面最后一行不加**；
* **行尾不得是『** —— 会出现就把『移到下一行行首；
* 单行放得下 ⇒ 一条 `show-text`，不加 `end-text-line`；
* `write` 显式换行：多段页（如系统提示的「技能名行 + 说明行」）用两条 `show-text` + `end-text-line` 分段；
* ★ **本仓没有 reflow 工具**（旧仓的 `reflow.js` / `reflow-apply.js` 不在本仓）：
  拆行要**手工**做（加一条 `show-text` + 一条 `end-text-line`），宽度自己数。别照旧仓文档敲 `node reflow-apply.js`。

## 2. 注音（`display-furigana`）

`display-furigana 0 "主词" "注音/释义"` —— **两个字符串都是文本**，都可改。

* **释义 / 称号类**（第二参数是释义或称号）⇒ 保留在注音位，**中文释义作注音**；
* **纯读音（假名）类** ⇒ 只作存档，译文不写注音。

## 3. 停顿符 / 外字（旧仓口径，★ **本仓未复核**）

旧仓 2026-08-12 定案：外字 `U+E000` → 「……」；`U+E001~U+E003` → 「——」；原文侧保留原字符。

实测本仓 `data` 视图里这些码位**确实存在**（SC0000 单脚本 132 处）⇒ 落笔时一定会遇到。
按上面的映射处理，但把它当**旧仓口径**用（不是本仓已登记的结论；要登记得走 `AGENTS.md` §6）。

## 4. `concat`（镜像行）

* **只有原文该页本来就有 `concat`** 时才动它（镜像行 = 紧随其前的 `show-text` 段译文，保持段边界）；
* 原文没有的一律**不新增**。

## 5. `draw-string`（参数化控件文本）

`draw-string <纹理> <x> <y> <文本>`

* 前 3 个操作数是**绘制参数**（纹理 / x / y）⇒ **不动**；
* 尾参是**字面量** ⇒ 可译；
* 尾参是寄存器（`(local-string …)` / `(local-string-ptr …)`）或 `(global-string …)` 引用 ⇒ **不译**
  （内容来自已翻译的源表，如单位名 / 道具名）；
* 固定控件文本**不受 §1 的 25 字规则约束**，但受控件绘制宽度约束：超宽要精简或用更短同义词。

## 6. 术语

优先级从上到下，**先用上面的**：

1. `docs/01-translation/ref/assets/keywords/keywords-术语词典.md` 里标 **`全工程定稿` / `已确认`** 的条目
   （该文件**首列是日文**）；
2. `docs/01-translation/ref/assets/glossary-draft.md` 头部的「**已确认术语**」三条
   （`Elf → 仙灵`（绝不作"精灵"）· `ディル＝リフィーナ → 迪尔-利菲娜` · `天結いキャッスルマイスター → 天结神缘`）；
3. 其余 `ref/assets/keywords/keywords-*.md` 词表（**首列中文**，与 1 互为反向索引）；
4. 工程**既有译法**：`pnpm tools patch find '<日文或中文>'`（先例优先；日文侧命中会连中文侧一起打出来）。

* 拿不准 ⇒ **保留日文原文**，并把该词作为**待定条目登记到需求树**（`pnpm tools requirements add`），
  **不许自创一版**、也不许只在会话里提一句。
* 同一角色 / 术语**跨脚本、跨页不得漂移**。
* ★ 这些文档里的「出现 N 处 / 已回改 / 待统一」都是**旧仓当时的观察**，用前必须在当前译文上核实
  （命令见 `lookup.md` §3）。

### 6.1 同根词：**日文同根 ⇒ 中文也得同根**（★ 最容易丢语义的一类）

日语里常见「同一个词根派生出一串名字」：词根当**普通词**用（难度档 / 称号 / 攻击名 / 设施），
同一词根又派生**专名**（人名 / 地名 / 迷宫名 / 种族名）。两种处理都成立，但必须**显式选一种**：

| 做法 | 什么时候对 | 风险 |
|---|---|---|
| **统一语义**（专名也走词根的意思） | 词根本来就是**玩笑 / 双关 / 主题**命名（游戏自己在玩这个梗） ⇒ 语义丢了就是丢信息 | 生僻派生名可能**无从意译**；"名"的形态变弱 |
| **词 / 名分流**（专名音译、普通词意译） | 专名已经**脱离词根独立**（玩家认的是这个名字本身），或没有像样的意译 | ★ **中文侧凭空裂成两个不相干的词**；日文侧的同根关系在中文里消失 |
| **音义折中**（保留名字后缀，把词根换成语义） | 想同时保住"像名字"和"看得懂梗" | 名字读起来偏"梗"（若原本就是玩笑命名，这反而是对的） |

★ **落笔要求**：分流必须**成对登记**（普通词一个译法、专名家族一个译法），并在需求树节点里写清
"为什么分流 / 分流的判据是什么"；**不许**同一个词根在中文里出现第三种写法。
★ 试金石：**同一块 UI 里会不会并排出现两种写法**（如设施列表里 `【设施：X】` 与 `X的证明`）——会，就是丢语义了。
★ 要**推翻**已有的分流决定（旧仓 `archive/prob/**` 里写死过的那种）⇒ 走 C 模式：
`references/consistency-review.md`（先清点全库、再取决策史、候选带代价、**未裁决不动笔**）。

## 7. 角色语气一致性

* **定说话人**（视图里没有 `// FROM:` 行）：向上找最近的 `mov (global-int 3f37) <十六进制 id>`，
  再按 id 查角色语气文档 —— 完整做法见 `lookup.md` §2；
* 条目 = `# <hex id> <角色名>（角色语气）`，条内四节：`## 角色信息` / `## 日文表达风格` /
  `## 中文译文风格` / `## 翻译一致性注意事项`；
* 按条目保持一致：自称与称呼（含对他人称呼）、敬语层级与亲疏、句尾语气助词、口头禅与惯用句、
  拟声拟态与笑声、专名与固定译法；
* 角色**未收录** ⇒ 按上下文与同类型角色推断，并把它作为待办登记（别只留在会话里）。

## 8. 质量优先级

1. **语义准确与完整**（否定、数量、人物关系、语气）；
2. **行结构 + 术语一致**；
3. 可编码 + **每行 ≤25 中文字**；
4. **风格自然**（口语化、角色声线 —— 落笔前按 §7 查语气条目）。

## 9. 编码与字体（本仓现状，一句话）

* 视图里**写中文**；落到 BIN 时的 cp932「日文写法占位」是**构建时的机械派生**
  （`canEncodeCp932` 优先 → 简→日写法字典 `data/translations/subs-cn-jp.json` → 全角空格）；
  ⇒ **BIN 反推不回中文**，改文案永远改视图/patch 里的中文（见 `data/translations/README.md`）。
* ★ 旧仓有一条**载体字事故**的教训：载体字劫持了译文/原文里本来要正常使用的字 ⇒ 文本渲染错
  （旧仓已改掉三个）。若将来要动那份字典，判据里必须加一条「该载体字不会被当正常字使用」。
  本仓**尚未复核**，这里只作线索（要落成规则得走 `AGENTS.md` §6）。

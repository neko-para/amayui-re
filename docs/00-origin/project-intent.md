# 项目本体：spec 与 emulator 的定位

> 本文件只写**不变的口径**（交付什么、什么算做对、边界在哪）。进度与状态不在这里 —— 见 `pnpm tools requirements plan`。
> "如何把汇编整理成 spec"的**方法**真源是需求树里那张 spec 层单（指令标记 / 效果守恒 / selector / 偏序），本文件**不复述**它。

## 1. 交付物

- 主交付物是 **spec（引擎规范）**：它能告诉别人这个引擎如何工作、有哪些能力，并能据此在其它平台重新实现。
- **emulator 是示范与测试项目**（cleanroom rewrite；类比 Wine，但差一处：Wine 的界面是**有文档的** ABI，这里的界面是未文档化的私有语义 ⇒ 理解不是可选项，而是唯一路径）。
- 推论：**emulator 不许成为 spec 的真源**；spec 也不许依赖 emulator 的实现细节（shape 已按此守：`⛔ 不读 apps/emulator`）。

## 2. 什么算"做对"

- **等价性不可证**：目标二进制带壳、无法 trace；人工观测只是采样。⇒ 追求**可审计**：无已知矛盾 · 每条有依据（锚 = EA 或用例 id）· 未解释处被计数。
- 措辞纪律：说"我们的 spec 与所有可获得的独立证据不矛盾，且能被独立实现"，⛔ 不说"与真机等价"。

## 3. 两层本体 + 一条边界

- **机器本体**（shape）：可靠 context —— 对象 / 偏移 / 宽度 / 数组 / 载体 / 闭合度。它是**实现细节**。
- **领域本体**（spec）：引擎的实体 / 状态 / 操作 / 规则。
- 两者之间只允许**指针**：spec 条目带 `storage`（→ 机器绑定），⛔ 不许内联 offset / 布局 / 池基点 / 步长。
- **边界契约**：平台 API（Win32 / D3D / DSound / 文件 / 计时）。spec 只写到"**引擎观察到的外部行为**"（请求 + 参数 + 时序），⛔ 不写到平台细节；平台实现可替换，逐位一致进 `discards`。

## 4. 证据（独立性的唯一来源）

四类，按独立性排序：**真机观测**（人工、低带宽）· **游戏数据**（脚本 / 容器 / 存档，可批量反驳）· **三方文档/版本** · **第二实现**（cleanroom）。

★ **投影一致 ≠ 与引擎一致**：多路推导只能发现内部矛盾与遗漏，发现不了"共同误解"。任何"可信度"声明都必须带上这句。

## 5. 替换与放电

抽象替换 = 数据精化：必须声明 `preserves / discards / chosen` 与**覆盖范围**（哪些机器结构 / 哪些指令效果）；**越界即红**。
⛔ 不许另建一份"替换记录"（那会变成第二份 spec）；替换只落在 spec 条目字段 + 机器绑定层 + 证据指针上。

## 6. 范围

- **单作 spec**（只这一作）；不做跨作品 diff。
- 三方（Live2D 等）只写**接口 + 不变量 + source binding**（版本 + 完整细节出处），不写内部语义。
- **表现层不可判**（像素 / 混音逐位）：spec 只覆盖"提交了什么"，不覆盖"看起来如何"；这类进 `discards` 并单列。

## 7. 现场地图（能力在哪一层）

| 层 | 回答什么 | 真源 |
|---|---|---|
| 语料 / 素材 | 从哪来、到哪去、入没入库 | `corpus/assets.json` · `corpus/fixtures/` |
| 定位 | 某 EA 在哪、谁调它、这个全局谁写 | `pnpm tools disasm-at` · `disasm-fn`（只读） |
| 格式 | 容器/脚本字节结构、能否原样重打包 | `packages/age-format` · 指令表 |
| 机器本体（shape） | 这个 offset 属谁、多宽、是否数组、函数分析完没有 | `data/shape/types.json` · `carriers.json` |
| 领域本体（spec） | 引擎有什么实体/操作/规则、边界请求是什么 | `data/spec/`（`pnpm tools spec`；方法单见需求树） |
| 记录（台账） | 结论有没有证人、锚还活着吗 | `data/ledger/` |
| 待办 / 进度 | 还要做什么、这单能不能关 | `data/requirements/` |

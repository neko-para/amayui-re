> 每条给坐标与引文；`[待核]` = 证据不足以定性、需要裁决或补证据；未标的 = 文内即可判定的冲突/缺口。

## 总览（条数 / 严重度分布 / 一句话结论）

- **39 条**：**S1 = 5** · **S2 = 15** · **S3 = 19**（另单列"正文里的机器细节" 8 项）。
- 机械层是**绿**的：`validate` 13 条全过；90 条规则在 markdown / bindings / audit 三处按 id 一一对应；`format/opcode-table.json` 的 574 / 544 / 30 与 `10-format` 正文数字一致；正文引用的 55 个 opcode 的 `argc` 与正文声明的操作数个数**逐条相等**（本次复核脚本核对，0 处不符）。
- 一句话结论：**结构闭合，语义未闭合**——最要紧的是 5 处必须裁决的矛盾：①`10-format` 说装载帧/换帧"尚未成篇"而 `15-frame`/`60-ops` 已写；②玩家文件词表匹配"大小写不敏感 vs 字节精确"两说；③`40-pools` 的**单密钥** vs `60-ops` 的**两格密钥**；④配置键下标由**地址差**决定，而 `00-overview` 声明地址数值不规定；⑤约 **489 个有处理函数的 opcode 仍"尚未成篇"**，却只记在章级残差里，`report` 仍打印 `unhandled=0` / `审计缺口 0`。
- 其余 S2 集中在两类：**同一可观察量在两章口径不同**（raw / 容器元素 / 0x8005 落点 / 默认组 / 状态位）与**状态词与断言强度不匹配**（"已核验/部分" vs 正文断言、`handled` vs 核心量"本版不规定"）。

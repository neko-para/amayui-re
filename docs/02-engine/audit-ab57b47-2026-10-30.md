## C 类逐条展开

### C-1 `0x93` 清表**不复位**兜底目标 —— 与 `.lst` 直接矛盾

```cpp
// apps/emulator-cxx/src/core/vm_ops_io.cpp:403-416（ab57b47）
// ★ 引擎**不**在这里复位兜底目标（`[0CA84h]` 不在这 7 格内）⇒ 兜底跨窗保留，⛔ 不是 -1。
choice_window_.step = 0;
choice_window_.hover = -1;
choice_window_.move_hit = false;   // ← 顶替掉原来的 fallback = -1
choice_window_.pending = false;
```

- **语料**：清表原语 `sub_403EF0` 一共 **7 条 store**：`+408h←0`、`+0EFCh←-1`、`+0F00h←0`、**`+74ACh←-1`**、`+74B0h←-1`、`+74A8h←0`、`+74A0h←0`（`0x403EF5`…`0x403F19`）。
  而 `0x93` 的调用点是 `0x4191F5 lea ecx,[esi+55D8h]` ⇒ `[ecx+74ACh]` = **绝对 `[esi+0CA84h]`**（`0x55D8+0x74AC = 0xCA84`）。
- **同一条 `0xCA84` 就是兜底目标**：`0x92` 写它（`sub_4207D0`：先 `push 2` 读、`0x420830 mov [esi+0CA84h],eax`），消费侧读它当跳转下标（`0x4099EC mov edi,[esi+0CA84h]; cmp edi,-1; jz 跳过`）。
- **判 C 的理由**：注释的两句话（"不在这 7 格内"）可被上面 3 个 EA **逐条否证**；被拿来顶替的 `move_hit` 的格身份，本提交自己在 `REQ-01M65JT8TYEHQPPNKT1RW747V0` 第 6 条登记为**未取证**（"置的格与清的格不是同一格"）。⇒ 用未取证的格换掉已取证的格，是"让行为看起来合理的逻辑"。
- **可观察后果**：一次"没选就关窗"之后，`0x92` 的兜底目标跨窗残留 ⇒ 下一窗的关窗会跳到**上一窗**的入口（`cmp edi,-1` 不再短路）。
- **正确做法**：`reset_choice_table()` 里恢复 `fallback = -1`（`b013648` 已按此改回并在 `vm.h:637-638` 写明 EA）；`move_hit` 若要清，按它自己的写点另行取证（别混进"清表的 7 格"叙事）。
- 附带：`62-adv-text.md:314` 说"七格复位"却只列 6 项 —— 同一处两个数字对不上，是这处判断被仓促改过的指纹。

### C-2 文本层 `key_base_set` 门把宿主兜底挡死（行为回归）

```cpp
// vm_ops_engine.cpp:810（ab57b47）—— 兜底写 f68，但**不**置 key_base_set
if (!record.key_base_set) record.f68 = kTextLayerFallbackBase + group * 1000;
// vm_ops_text.cpp:232（ab57b47）
if (!rec.key_base_set) return;   // ← 于是兜底永远进不来
// vm_ops_text.cpp:262
if (rec.key_base_set) { …erase… }
```

- **判 C 的理由**：`0x213` 是记录 `+0x68` 的**唯一**写者，脚本不调它 ⇒ `key_base_set` 恒 false ⇒ `create_text_layer_item` **一次都不建条目**。这不是"更严格"，而是把 `op_70` 里那段兜底变成**死代码**（两条各自"看起来合理"，合起来互相取消）。
- **可观察后果**：**不调 `0x213` 的层**（本作 ADV 的消息层正是这种层）"窗框有、字没有"；`0x71` 清层也清不掉（erase 同一门）⇒ 旧条目残留。
- **正确做法**：把"基数可用"与"脚本写过"分开（`b013648` 的 `key_base_ready() = key_base_set || key_base_fallback`，`op_70` 同时置 `key_base_fallback`）。
- 附：本提交的 `check_msg_block` ⑥（`:3925-3945`）只用"`0x213` 写过基数 0"这一支 ⇒ **恰好绕开**被打死的兜底支，所以守卫全绿而回归不可见（`b013648` 补了 `repro/adv-message-text-invisible.md` 与 `key_base_ready()`）。

### C-3 `0x242` "只在建记录时标脏" —— 凭空补的分支

```cpp
// vm_ops_scene.cpp:275-287（ab57b47）
if (created) scene_dirty_ = true;
// ★ 「本条不标脏」是观察事实；只有上面「建默认记录」那一步会标脏。
```

- **语料**：`0x242` 的全部路径是 `sub_4251A0 → sub_4AD9A0 → {sub_4AAA50, sub_4AAD40, sub_4AAC00, sub_4AAEC0}`；`grep 0B5ACh` 在这五个函数体里**一条都没有**（最近的两处是 `0x4AD984` 与 `0x4ADEC5`，都在别的函数里）。
- **判 C 的理由**："不标脏"这半句有证据（写点缺席）；"建记录那一步会标脏"这半句**没有任何写点支持**，是把"建了东西大概要重绘"的直觉写成了合同，还配了一条守卫（`core_selftest.cpp:3800-3815` 断言第二次执行 `dirty == false`）把它钉住。
- **正确做法**：`0x242` 一律不置 `scene_dirty_`（若担心"值变了消费者看不到"，那条该落到 `field_2d0` 的消费者残差里，不是偷偷标脏）。
- 附带：`vm.cpp` 把 `0x242` 从 `is_scene_mutating` 白名单删掉是与 C-3 配套的**另一半**改动 —— 前半步对（旧的"无条件标脏"也错），后半步错（换成"建记录标脏"）。

### C-4 假守卫：把实现值抄进断言（`0x93` 兜底）

- **判 C 的理由**：这条用例的期望值不是从 `.lst`/spec 推出来的，而是从**改动后的实现**抄出来的；它的"红"只会在有人**按语料**把 `fallback = -1` 改回去时发生 —— 也就是说，**这条守卫保护的是错误**。
- **正确做法**：期望写 `-1`（锚 `0x403F07 [ecx+74ACh]=-1`，且 `0x55D8+0x74AC=0xCA84` 与 `0x420830`/`0x4099EC` 对上）。`mt-1`/变异清单里对应条目也要改期望，不是改断言目标。

### C-5 `0x305` 注释"bit27 没有服务者" —— 理由与事实不符

```cpp
// vm_ops_text.cpp:951（ab57b47）
//   ⛔ 不许因此把 bit27 置起：模型里它没有服务者，会让主循环 gate-stalled。
```

- **语料**：`0x41B22D` 起是 `message:ReadTextSkip != 0` **且** `sub_48F000(...)` 命中 ⇒ `0x41B292 or dword ptr [esi+0AAB44h],8000000h`（bit27）+ `[0x7789C]=1`。模型里 bit27 的服务者是 `0x88`（`vm_ops_engine.cpp:555-566` 清它；`0x71` 自己也会置它，`:938`）。
- **判 C 的理由**：**行为**上"不置位"是可接受的保守缺口（`RES-MSG-BLOCK-READ-HIT` 已登记"已读表未建模"），但**理由写错了**：不是"没有服务者"，而是"已读命中的那张表没有模型"。理由错会让下一个人按错的前提到处补 `kServicedGateBits`。
- **正确做法**：注释改成"已读表未建模 ⇒ 只实现必要条件；bit27 由 `0x88` 服务，但本模型不置它以免与未建模的跳过态耦合"；并在 `70-vm.md` 的 `kServicedGateBits` 处把 bit27 列成"有意不服务"。

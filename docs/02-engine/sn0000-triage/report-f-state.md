### 3.1 `RES-LEA-ALIAS-LIFETIME`（CORE-OPS-POOL-LEA-63）— **covered**

**依据（正文原句）**：`60-ops-array.md:172`「…**元素地址不搬移**；翻页只切换"当前组"的基址选择；引用槽里存的是**绝对地址**…**全局池在启动期分配一次、局部池在该帧装载时分配一次**；容器对象在创建后也不搬…」

**本轮指令级核对（把残差剩的那半答掉）**：
- 三个基址格 `+0x5D800`/`+0x5D808`/`+0x5D810` 的**字面**写入只有 3 条：`0x41AB03`/`0x41AB1B`/`0x41AB27`，而与它们成对的是 `+0x5D804`/`+0x5D80C`/`+0x5D814`（`0x41AAD9` 起 `mov eax,[esi+5D800h]` / `mov ecx,[esi+5D804h]` … 对调）⇒ **翻页只换"当前/备用"两份已分配缓冲**。
- 残差点名的两处取址：`0x415B8C lea eax,[esi+5D808h]` 之后是 `0x415B94` 起逐格 `mov [eax-8],edi` / `[eax],edi` / `[eax+8],edi`…（启动构造段的整块初始化，**这里会写基址格**）；`0x428AB3 lea edi,[esi+5D808h]`（复位段）之后是 `0x428AD0 mov edx,[edi-8]` → `mov [edx+eax*4],ecx` 与 `0x428AEE` 起的 `_memset` —— **复位段只透过基址清内容，没有重写基址本身**。
⇒ 结论：**不存在运行期重新分配池的路径**（启动期写完基址后再没有换基址的写点），引用槽里的地址不会因重置/翻页失效（内容可能被清零，地址不变）。

**处置建议**：**删** `RES-LEA-ALIAS-LIFETIME`。正文不必改；若想加一句钉子，建议在 `60-ops-array.md:172` 末尾补：
> 「运行期唯一的基址写入是翻页把当前组与备用组对调；复位 / 重置只透过基址清内容，不换基址。」（三对缓冲的槽位进 `bindings.storage`，正文不写偏移）

**`<待核>`**：`0x415B8C` 所在函数是否**只**被启动路径调用一次（本轮没有查它的调用方；若它也在运行期被调，结论要重判）。另：本轮只按 `+偏移h` 字面枚举，经取址/计算得到的基址写入查不到（未做 `globals --who` 全量交叉）。

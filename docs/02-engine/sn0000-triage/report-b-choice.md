### 3. `ADV-CHOICE-EXTRA-MEANING`（SET-EXTRA-97）— **real-gap**（可立即补）

**依据**

- 写点：`0x403D61` `mov [ecx+edx*4+7304h], eax`（`arg_4` = 0x97 的第 5 个操作数）；`0x90` 追加时同格写 `-1`（`0x403BA2`）。
- 读点只有一个：`0x403D70` 起（唯一调用方 `0x411BF1`，`sub_411BC0` 内），循环体：
  `0x403D90` `mov ecx, [edx]`（取该条附加整数）→ `0x403D92` `test ecx, ecx` / `0x403D94` `js`（**负数跳过**）
  → `0x403D96` `mov ebx, 1` / `0x403D9B` `shl ebx, cl`（**1 << 附加整数**）
  → `0x403DA0` `test [ecx], ebx`（`ecx` = 传入的位掩码指针）→ 命中则 `0x403DB6` `mov eax, [edi+eax*4+72Ch]`（该条的**决定入口**）。
- 传入的掩码：`0x411BC9` `lea ebx, [esi+0AAB48h]` → `0x411BEE push ebx`。同一格在本函数里被当作**按键位集合**用
  （`0x411CF4` 之前 `test [ebx], edx`，其中 `edx = 1 << "set:WheelKeyDown"`），且按下后会被**消费清零**
  （`0x411AD3` `and eax, 0FFFFFFEFh` 清 bit 0x10）。
- 命中后走的是和"点中"同一套出口：`0x411C02` 深度校验 → `0x411CA0` `lea ecx, [edx+eax*4]` / `0x411CA3` `mov [esi+5D898h], ecx`
  （执行位置 ← body 起点 + 4 × 入口）。
- 该扫描**只在输入总闸开着时**发生：`0x411BDB` `cmp dword ptr [esi+0CA74h], 0` / `jz`。

**结论**：附加整数 = **一个输入位序号**（热键位），不是序号 / 图编号 / 状态；`-1` = 该条没有热键。
按下该位 ⇒ 等价于"点中这一条"（取其决定入口）。这是**领域行为**（谁触发、触发什么），不是内容数据。

**处置草案（正文 0x97 段末加）**

> 附加整数是**一个输入位序号**（`-1` = 该条没有热键）：它把"某个按键位"绑到这一条上。
> 选项窗口开着时，引擎每帧按追加顺序扫一遍：第一条"附加整数 ≥ 0 且对应输入位已按下"的项 ⇒
> 按**点中它**处理（执行位置 ← 该条的决定入口）；同一位绑给多条 ⇒ 只有追加在前的第一条生效。

**新反例**

- 两条都绑同一位、该位按下 ⇒ 必须只有**第一条**被选中；两条都被处理 ⇒ 扫描没在第一条停。
- 把某条的附加整数从 `-1` 改成某位、按下该位 ⇒ 必须选中它；仍是"没有热键"⇒ 读点没在判负值。
- 该位按下但窗口输入总闸 = 0 ⇒ 必须**不**选中；选中了 ⇒ 扫在闸门之前。

**`<待核>`**：附加整数 ≥ 32 时 `shl ebx, cl` 只取 `cl` 低 5 位（x86 语义）—— 是否有意未判；
位号 ↔ 具体物理键的映射由键位配置决定，那属数据，不进本条。

### 4. `ADV-CHOICE-ENTER-LEAVE-SEMANTICS`（WINDOW）— **real-gap**（可立即补，`next` 要改）

**依据**：`sub_403E70` 就是那个"进入/离开"事件解析器（`ecx` = 选项表，无参数，返回一个入口下标或 `-1`）：

```
0x403E70  cmp dword ptr [ecx+74A8h], 0      ; 74A8 = 挂起位
0x403E77  mov eax, [ecx+74B0h]              ; 74B0 = 悬停下标
0x403E7D  jz  0x403E9C
  ; —— 挂起支（上一拍留下了"离开"）
0x403E7F  mov eax, [ecx+0EFCh]              ; 0EFC = 已跟踪悬停项
0x403E85  mov dword ptr [ecx+74A8h], 0      ; 清挂起
0x403E8F  cmp eax, -1 / jz 0x403EE4         ; 已跟踪项为"无" ⇒ 返回 -1
0x403E94  mov eax, [ecx+eax*4+40Ch]         ; 否则返回**它的进入入口**（40C = 第 5 个操作数）
  ; —— 常态支
0x403E9C  mov edx, [ecx+0EFCh]              ; 旧项
0x403EA2  cmp eax, edx / jz 0x403EDA        ; 没变化 ⇒ 挂起 0、返回 -1
0x403EA6  mov [ecx+0EFCh], eax              ; 已跟踪 ← 新项
0x403EAC  cmp edx, -1 / jz 0x403EC3
0x403EB1  mov dword ptr [ecx+74A8h], 1      ; 旧项存在 ⇒ 置挂起
0x403EBB  mov eax, [ecx+edx*4+59Ch]         ; 返回**旧项的离开入口**（59C = 第 6 个操作数）
0x403EC3  cmp eax, -1 / jz 0x403EE4         ; 新项为"无" ⇒ 返回 -1
0x403ED2  mov eax, [ecx+eax*4+40Ch]         ; 否则返回**新项的进入入口**
```

调用方 4 个（`sub_411590` `0x41182A`、`sub_411900` `0x411B67`、`sub_411BC0` `0x411E91`、`sub_4098E0` `0x40990D`），
每个每帧调用一次。取到入口后：深度校验 → `0x411EC8` `lea ecx, [edx+ebx*4]` / `0x411ECB` `mov [eax+5D898h], ecx`（改执行位置）。

**结论**：进入/离开的触发条件**不需要运行时 trace** —— 它是"已跟踪悬停项"与"本帧命中项"的比较，且
**从 A 移到 B 一定分两拍**（先返回 A 的离开入口，下一次调用才返回 B 的进入入口）。现状正文只写"光标移动时按矩形命中算出目标项"，
**漏了这条两拍协议与那个挂起位**。

**处置草案（正文 0x90「消费侧」的"进入 / 离开"那条改写）**

> 进入 / 离开是**两拍**：引擎维护"已跟踪项"与"挂起"两格。每次读：
> ① 挂起已置 ⇒ 清挂起，返回**已跟踪项**的进入入口（已跟踪项为"无" ⇒ 返回没有入口）；
> ② 否则比较本帧命中的项与已跟踪项：相同 ⇒ 没有事件；不同 ⇒ 已跟踪项 ← 新项，
>    旧项存在 ⇒ 置挂起并返回**旧项**的离开入口（下一次读就会返回新项的进入入口）；旧项为"无" ⇒ 直接返回**新项**的进入入口。
> ⇒ 从 A 移到 B 一定是"先离开 A、后进入 B"两个事件，⛔ 不是一次调用里两个都发；从"无"进 ⇒ 一次；移到"无" ⇒ 一次离开 + 一次"没有事件"。

**新反例**：把悬停从 A 移到 B，连续读两次 ⇒ 第一次必须是 A 的离开入口、第二次必须是 B 的进入入口；一次就跳到 B ⇒ 两拍被合成一拍。

**`<待核>`**：① 挂起只有一格 ⇒ 若两拍之间又换了项，中间项的进入事件会被吞掉（`0x403EA6` 直接覆盖）—— 是否需要写进合同，取决于是否允许"一帧内多次改命中"；
② `0x403E7F` 支在"离开到无"时第二次调用返回 `-1`，与"无事"不可区分 —— 是否需要区分未判。

### 3.1 `RES-TEX-CREATE-BLANK-PIXELS` — covered

### 3.2 `RES-TEX-CREATE-INVALID` — covered（可闭合成机器事实）

- **依据**：
  - 正文已写 `:85`「创建失败 ⇒ 对象仍留在槽里，但它的尺寸 / 可用性未定义（实现必须诊断…）」
  - **本轮新增**：对象**先入槽、后发请求**（`0x4A2CDF mov [esi+edi*4+0A5D8h],eax` → `0x4A2CF0 call eax`，虚表槽 `+0xC`）；请求失败支（`0x4A2CF2 test eax,eax` / `0x4A2CF4 jz loc_4A2D34`）走 `0x4A2D03..0x4A2D19`：拼 `"関数：CTexture エラー：テクスチャ作成に失敗． TEXTURE=%d"` + `sub_49F770` 取 HRESULT 文本 → `sub_4034C0`（错误通道），**不回滚槽**。
  - 「尺寸未定义」的**原因**也钉死了：构造器 `0x48AB5F..0x48AB89` 初始化 `+0x408/+0x40C/+0x438/+0x43C/+0x440/+0x444/+0x448/+0x44C`，**唯独不写 `+0x410`/`+0x414`**；这两格只在成功支 `0x48AD30`/`0x48AD36` 写（= 宽 / 高，正是 `0x208` 读的两格，`0x49ED81`/`0x49ED93`）。⇒ 失败后"逻辑尺寸"是 `operator new` 的残留。
- **处置**：转 `discarded`（比 `unknown` 准确），并改 `what`：

  > what（新）：创建失败 ⇒ 对象仍留在槽里；它的**尺寸两格（对象自身状态，读法见 0x208）既没有构造初值、也没有被失败路径写过** ⇒ 尺寸 / 可用性来自未初始化内存，本版不规定。错误通道有一条上报（文本内容不在本版）。
  > next（新）：无（要规定只能改实现侧「响亮诊断」口径，不再向二进制取证）。
  > `range:["0x4a2c9e","0x48ab5f"]`；`reason`：读未初始化内存不是引擎决定的行为；`impact`：只影响失败样本上的后续查询 / 绘制；⛔ 不许把"槽里有对象"当"纹理可用"。

- **`<待核>`**：0x1f8 的 handler（`0x422C20`）在拿到 `sub_4A2C10` 的 0 返回后是否另有上报（本轮只读到 `0x4A2D31 retn 10h`，未读 `0x422C90` 之后的收尾）。

### 3.3 `RES-TEX-CREATE-KIND-PARAMS` — covered（**本轮取证收口**，建议直接补正文）

- **依据（EA + 指令原文）**：创建路径把 `kind` 原样交给对象，真正的请求参数在对象的 create 方法里 ——
  - `0x4A2CE6 mov eax,[ecx]` / `0x4A2CE8 mov eax,[eax+0Ch]` / `0x4A2CF0 call eax` ⇒ 虚表槽 `+0xC`；

  - 参数装配（`sub_48AC40`，`arg_0`=宽、`arg_4`=高、`arg_8`=种类）：
    - `0x48AC5F lea edi,[esi+40Ch]` / `0x48AC65 push edi` = 输出表面指针（最后一个实参）；
    - `0x48AC66 cmp eax,1` / `0x48AC69 jnz` ⇒ **种类 = 1** 支（`0x48AC7A push 0` / `0x48AC7F push eax` / `0x48AC80 push 1`）；

    - `0x48ACD9` 起 = **其它种类**支（`0x48ACE8 push 1` / `0x48ACED push eax` / `0x48ACEE push 0`）；
    - 公共尾 `0x48AD02 push 1`（MipLevels）/ `0x48AD04 push ebx`(高) / `0x48AD05 push edx`(宽) / `0x48AD06 push ecx`(设备) / `0x48AD07 call j_D3DXCreateTexture`；
    - 格式两档的来源是 **`ds:dword_5518C0`**（`0x48AC6B`/`0x48ACDE`/`0x48ACA5` 三处读；写点是 `0x406B14 mov ds:dword_5518C0,eax`，紧接 `0x406B07 push offset "display:TextureBit"`）⇒ **与「加载纹理像素」同一格**。
  - ⇒ 三分支的请求参数（值写在下面草案里）：种类 1 / 种类 2 / 其它；**MipLevels 恒 1**；格式 = `TextureBit==16 ? A4R4G4B4 : A8R8G8B8`（种类 2 的"渲染器 `+0x464` 非 0"子支改用无 alpha 变体 `X4R4G4B4 / X8R8G8B8`）。
- **处置**：**补正文（草案，加在 0x1f8 条「成立条件」之后）+ 删残差**。草案（正文不写偏移 / 枚举数值，只写领域请求；偏移与数值进 `bindings`）：

  > **底层创建请求的参数（合同）**
  > 建立空白纹理时向平台发出的请求携带：**宽 / 高**（本条的 2 / 3）、**只有一级（不要 mipmap）**、**一个像素格式**、**一个"是否可作渲染目标"的用法标记**、**一个资源池档**，以及**输出表面**。
  > - **像素格式**由显示配置 `display:TextureBit` 决定（与「加载纹理像素」**同一格**、同一读时）：**= 16 ⇒ 每通道 4 位的带 alpha 格式**；**其它值 ⇒ 每通道 8 位的带 alpha 格式**。★ 与上传条不同：**上传**对"非 16 / 非 32"是失败，**创建**不是（创建把任何非 16 的值都当 8 位档）。
  > - **种类 = 1** ⇒ 用法标记 = **可作渲染目标**、资源池 = **非托管（默认池）**。
  > - **种类 = 2** ⇒ 与种类 1 **相同**；但若渲染器侧那一个标志（`storage` 指针）非 0 ⇒ **格式换成不带 alpha 的对应档**（16 ⇒ 每通道 4 位无 A；其它 ⇒ 每通道 8 位无 A）。
  > - **种类 = 3** 走**分割纹理对象的**创建方法，不在本条（见 `RES-TEX-CREATE-DIVIDED`）。
  > - **其它种类（含 0）** ⇒ 用法标记 = **不可作渲染目标**、资源池 = **托管池**，格式同上面第一档。
  > - ⛔ 平台枚举名与数值、池 / 用法的实际内存行为进 `discards`；⛔ 不许把"种类 2 的无 alpha 子支"写成第二个种类。

- **`<待核>`**：`[渲染器+0x464]` 的**领域名**（谁写、表示什么）；本报告只把它当"一个渲染器侧标志"。（另：`dword_5518C0` 在 spec 里被称作"显示状态"的一部分，本轮只证明它与 `display:TextureBit` 同格，未核它在 spec 的那一格名。）

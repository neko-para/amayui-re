### P0-2 `0x214` 三处与 `.lst` 矛盾（spec 与实现同错）

## 2. P1（实现偏离 / spec 缺口 / 守卫缺失）

### 2.1 实现面（全部有 `.lst` 或代码级依据）

1. **`0x72` 槽号不校验 ⇒ 越界**：`vm_ops_texture.cpp:775-776` 直接 `current_text_slot_ = slot`；
   `vm_ops_text.cpp:912-913` 经 `resolve_text_layer` 后按 `text_layer_state_[slot]` 索引 `std::array<TextLayerState,10>`
   （`vm.h:440-442`、`vm.h:1422`，无边界检查）。`0x72 0x40000000; 0x304` 即大范围越界；修好 P0-1 后 `reveal_all_text_layer_cells` 是**写**越界。
   引擎侧同样不检查（spec 把越界归 UB），但本仓对同类 UB 的既定口径是“响亮失败”（`0x216` / `0x258` 先例）。
2. **`0x7a` 的槽 0 落错**：`vm_ops_text.cpp:852` `resolved = slot == 0 ? 0 : slot`，而其它文本指令走
   `resolve_text_layer`（0 → `default_group_`，初值 1）。引擎 `sub_45A910` 在 `slot==0` 时读默认槽。
   测试只用槽 3（`core_selftest.cpp:3040-3053`）⇒ 抓不到。
3. **`0x1ca` 与 `0x1cb` 不是同一存储**：`0x1ca` 写 `named_message_read_text_skip_`（`vm_ops_engine.cpp:817`），
   `0x1cb` 读 `config_.get_int("message:ReadTextSkip")`（`:944`）；`0x1ca 1; 0x1cb dst` 得 0，直接踩
   `CORE-OPS-CONFIG-READ-1CB` 的 falsifier「设成 1 再执行必须是 1」。测试只测缺键⇒0（`:3055-3066`）。
4. **`0x229` 的消费者只做了一半**：CPU 光栅加了平移（`scene_raster.cpp:180-184`），窗口 GPU 路径
   `gpu_scene.cpp:293 build_scene_vertices` 没有读 `scene_self_transform()`；命令档「按区间 A 起点跳过」也没实现
   （`paint_interval` 逐键调 `draw_item`，`draw_item` 没有 skip 形参）。测试只用 `rasterize_scene` ⇒ 绿的是 CPU 路径。
5. **`0x20a` 是只标脏的近似**：`vm_ops_text.cpp:876-879` `(void)layer; scene_dirty_ = true;`；
   「贴已揭示的格」与「位 30 置起时再读一次层号并补画一格」都没做。
6. **`0x2e9` 的读者没接**：实现只写 `cell_2e9_`（`vm_ops_engine.cpp:1026-1032`），而该格在引擎里是
   `[esi+77980h]`，有 6 处读（`0x409187` / `0x4091E5` / `0x41209F` / `0x412162` / `0x41F118` / `0x41F1A6`），
   上下文是 `message:AutoMessagePitch0/1`、`AutoMessageTime` 的时长计算 ⇒ 「读者未取证」不成立，实现也没接消费者。
7. **`0x90` 不复位 arm 闸**：引擎每次追加都写 `[74A4h]=0`（`sub_403B30` 的 `0x403BBE`）；
   实现 `vm_ops_io.cpp:347-375` 只改 `choice_index_`，于是第二次开窗不会重算悬停。`ADV-CHOICE-ARM-RESET` 其实可收敛。
8. **选项消费侧整段缺失**：`choice_index_` 只被写成 -1，`choices_` 没有“点中 ⇒ 执行位置 = body + 4×decide”的读者；
   spec `ADV-CHOICE-ADD-90` 的「消费侧（合同）」在实现里不存在 ⇒ 菜单选中永不发生。route 只断言到达脚本，碰不到菜单。
9. **`0x93` / `0x94` / `0x91` / `0x92` 的格对不上**（证据面实测）：`0x94` 置的格与 `0x91/92` 清的格不是同一格；

   ⇒ 正文「0x93 清表时复位 -1」被反驳，实现的 `reset_choice_table()` 也跟着错。
10. **文本层绘制不请求渲染**：`create_text_layer_item` / `reveal_text_layer_cell` / `draw_text_layer_text` 都不置

   （`vm.cpp:440`）。于是 speed>0 的逐字揭示在“没有别的动画”时不产生新帧（打字机被跳过）。

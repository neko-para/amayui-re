# TITLE → Option → CONFIG.BIN 路径的指令取证记录（2026-10）

只读取证记录（`amayui-re-engine` 口径）：**锚只有 EA**（`.lst` 行号只作定位，不当锚）。
这份文件**不是** spec、**不是**知识台账：它记录"看到了什么 + 还没看到什么"，供写 spec 条目与实现时用。
⛔ 任何一条在进 `data/spec` 之前都必须再过一遍准入门（`AGENTS.md` §6）。

## 0. 共用机制（几条结论都依赖它）

- 帧 `fr = Engine + 0x5D880 + 120*Engine[0x5D880]`；`fr+0x18` = 指令指针；`fr+0x74` = **本条宽度（dword 数）**，
  由 handler **最先无条件写**；派发处 `0x411A7E–0x411A8C` 做 `IP += (fr+0x74)*4`。
- 操作数是 **2 dword 一对**（type 在 `IP+8i-4`、值在 `IP+8i`）；读 `sub_41BF50`（EA `0x41BF50`）、
  写 `sub_42B4B0`（EA `0x42B4B0`）。宽度 = 1+2×argc，与 `opcode-table.json` 独立互证。
- 可读 type 0–13（另 `0x8003`/`0x8009` 等）；可写只有 3/4/6/7/9/10/12（写文本 5/8/11 是**另一条**路径）。
  非法 type ⇒ `Command_Type_Exception`。
- 文本读原语 `sub_41B640`（EA `0x41B640`）→ `char*`：标签 0–14 除 **7 / 13**；数值标签先 itoa 成十进制；
  内联文本逐字节取反解码。**`0x192` 用的是另一个子例程 `sub_42A420`**（EA `0x42A420`），⛔ 不要混为同一条。

- 实现状态：**已实现**（`apps/emulator-cxx/src/core/vm_ops_engine.cpp` 的 `op_c0`），selftest 断言长度槽 3 与写回值。

## 2. Font 侧「条目登记表」三条：`0x1D0` / `0x1D2` / `0x1D3`

三条都作用在 **`Engine+0x14D30` 的 Font 对象**（构造点 `0x41570E` → `sub_464FD0`，vftable `Font::vftable` @ `0x465007`）。
共用数据层（不是共用子例程：三个工作子例程各只有 1 个调用点）：

- `Font+0xD24` 起是 **72 字节记录表**（std::vector）：`+0x00` 列表号 · `+0x14` 值 · `+0x18` key ·
  `+0x28` flags · `+0x2C` 空 `std::string` · `+0x44..0x47` 无人写（步长 72 是 8 对齐的结果）。
- `Font+0xD34` 起是 **8 字节对表**（每项 = 一对 dword），光标 `Font+0xD70`；
  `Font+0xD44 + 4*idx` 是每记录的脏槽。

### `0x1D2` — `sub_420380`（EA `0x420380`，`.lst` 48143–48168）

- **守卫**：`Engine[0x5EC7C] != 0` ⇒ **整条跳过**（宽度仍已写：不读操作数、不抛）。
  该槽由 `0x1BB`（`sub_420000`）写 0 / `0x80000000`，报错串「SetTBの引数が不正です」。
- 放行后读序 **op2 → op1**，**不写任何操作数**；向 `Font+0xD24` 入队一条 72 字节记录：
  `+0x00` = `Engine[0x4CC]`（默认列表号）· `+0x14` = op2 · `+0x18` = op1 ·
  `+0x28` = `0x20000000 | (Font+0xD44+4*idx != 0 ? 1 : 0)`（后者同时清槽）。
- **无外部请求**（纯内存入队，本帧不触发绘制）。推进 **5 格**。
- 未解：入队后谁消费（`Font+0xD24` 在 `0x4577xx–0x457Exx` 有大量读者）；`+0x28` 位 0 / 位 29 的领域名。

### `0x1D3` — `sub_42D4A0`（EA `0x42D4A0`，`.lst` 69907–69953）

- 读序 **op5 → op4 → op3**（降序）。★ `sub_457960` 的 `.lst` 只声明三个栈参但 `retn 10h` 吃四个：
  `[+8]`=&out · `[+0Ch]`=op3 · `[+10h]`=op4（起始下标）· `[+14h]`=op5（key）。**`[ebp+0Ch]` 函数体零引用**
  ⇒ op3 被读、值丢弃，但 type 非法照样抛。
- 查询：`count = (Font[0xD28]-Font[0xD24])/72`；`op4 < 0 || op4 >= count` ⇒ 未命中；
  否则从 op4 顺扫，命中 `(rec+0x28 & 0x20000000) != 0 && *(rec+0x18) == op5` ⇒ 取 `*(rec+0x14)`。
  **组边界**：`72*idx+0x70 & 1` 落在**下一条**记录的 `+0x28`（步长 0x48 < 0x70，字节事实）⇒
  "下一条 flags 低位 = 组头 ⇒ 断组"属**推断**。
- 写：op1 ← (命中 ? 1 : 0)、op2 ← 值（**未命中写 0，不是 −1**）。推进 **11 格**。
- 未解：op3 是保留操作数还是历史残留；组边界的领域含义。

### `0x1D0` — `sub_42D440`（EA `0x42D440`，`.lst` 69859–69899）

- 只读 **op3**（op1/op2 从不读）。走 `Font+0xD34` 对表：从光标 `Font+0xD70` 起 ±op3 步，
  跳过"指向的记录 `flags & 2`"的项；成功 `op1 ← pair[v].first`、`op2 ← pair[v].second`（顺序 1 再 2），
  越界/哨兵 ⇒ 两个都 `−1`，返回值被丢弃（不抛）。
- 无外部请求。推进 **7 格**。
- 未解：`pair.first` 的语义；`flags & 2` 在整张指令表里**无人置位**（`20000002h` 全语料 0 处）⇒ 跳过支不可达。

## 3. 文本族四条：`0x6E` / `0x6F` / `0x196` / `0x1A6`

四条都**先写当前帧长度槽、再读操作数**；文本读全部走 `sub_41B640`（与 `0x204` 同一条路径 ⇒
C++ 的 `read_text` 可直接用）。

### `0x6E` show-text — `sub_41EB20`（EA `0x41EB20`，`.lst` 45867–46004）

- 宽度 **5**（argc 2）；读序 **op2（文本）→ op1（整型）**；`46CBF0` 那一支是 **op1 → op2 → op1**。
- 写：`Engine[0x7780C] ← op1`；非跳过支 `Engine[0xAAB44] |= 0x20000000`（位 29）+ 计时队列 `0x691EC`
  登记（时长 = `Engine[0x15290]`）；跳过支 `|= 0x8000000`（位 27，与 `0x71` 同一位）+ `0x7795C ← 1`。
- 消息窗口记录 `[0x14D30 + 4*op1 + 1044]` 追加一段文本（`op1 == 0` ⇒ 引擎默认槽 `[0x14D30+1228]`）。
- **外部请求**：文本量度 + 光栅（`sub_46BE30`：`SelectObject` / `GetTextExtentPoint32A` / 逐字写出），
  实参 = (窗口记录, op1, 文本, **0**, `Engine[0x5EC7C]`)。**空串 ⇒ 不发请求、不写上面三格**。
- 分支：`Engine[0x77A04] & 1`；否则查命名键 `message:ReadTextSkip`（与 `0x1ca` 同一个键）。
  **跨指令**：跳过支把帧字段「文本请求位置」（`0x71` 写的那一格）当 `sub_48E870` 的实参。
- 未解：`0x77A04` 位 0/16、`0xAAB44` 位 27/29、`0x7795C`、`0x5EC68` 的领域名；
  `0x15290` 已证为时间量但名未定；窗口记录里"一段文本"的格内结构。

### `0x6F` end-text-line — `sub_41ECE0`（EA `0x41ECE0`，`.lst` 46011–46029）

- 宽度 **3**（argc 1）；只读 op1。`sub_46AF90(0x14D30, op1, Engine[0x5EC7C])` 定稿行结束三格
  （`*(rec[12]-20) ← rec[7]`、`*(rec[12]-16) += 行距`、`++*(rec[12]-4)`、`++rec[71]`）。
- **无外部请求**（闭包里没有任何 GDI / 光栅入口）。未解：行结束三格与 `rec[28]` 的领域名。

### `0x196` display-furigana — `sub_41FC20`（EA `0x41FC20`，`.lst` 47416–47567）

- 宽度 **7**（argc 3）；读序 **op3（文本，无条件最先）→ op2（文本）→ op1（整型）→（追加成功后）op1**。
- op3 先 `strncpy` 式拷进 1024 字节缓冲：**上限 1023 字节 + NUL**，超长静默截断、不报错。
- 写：`Engine[0x7780C] ← op1`；`0x77A04 |= 0x10000`（直接追加）或 `0xAAB44 |= 0x8000000`（跳过）/`0x20000000`；
  文本记录追加 **op2**，截断后的 **op3** 作为**第二文本**传给绘制入口（`0x6E` 处该实参是常量 0）。
- **有外部请求**，与 `0x6E` 同一入口。**不查** `ReadTextSkip`。未解：op2/op3 谁是主文本谁是振り仮名。

### `0x1A6` halve-strlen — `sub_42D110`（EA `0x42D110`，`.lst` 69515–69541）

- 宽度 **5**（argc 2）；读序 **op2（文本）→ 写 op1**（唯一一支）。`op1 ← strlen(文本) >> 1`（按**字节**）。
- 落点是**整型**（写原语的标签集）：落点给 5/11（字符串池）⇒ 类型异常。**无外部请求**。
- 未解：`strlen/2` 的领域用途（可能是排版半宽）。

## 4. 四条"标量 / 槽位"指令：`0x142` / `0x1BB` / `0x300` / `0x301`

★ 操作数位置核对：仓库里 `dist/install/CONFIG.BIN` 与统一文件 id 52 的**文件 dword 下标差 15**（60 B 头）；
CONFIG 里的实际实参全是类型标签 0（立即整数）。

### `0x142` — `sub_422930`（EA `0x422930`，`.lst` 51837–51851）

- 宽度 **3**（argc 1）；读 op1 → `Engine[0xAAB70] ← 值`。无外部请求、无分支、无检查；无类型校验（非法 type 由读原语抛）。
- 唯一读者 `sub_4765C0`（EA `0x4765C0`）：`return Engine[0xAAB70] != 0`；初值 1（两处启动初始化 `0x40DF7B` / `0x415AEC`）。
- 未解：`0xAAB70` 的领域名（只知"非 0"这一语义）。

### `0x1BB` — `sub_420000`（EA `0x420000`，`.lst` 47802–47843）

- 宽度 **3**（argc 1）；**同一个操作数读两次**（`0x42001F`、`0x420038`）。三分支写 `Engine[0x5EC7C]`：
  arg1 = 0 ⇒ `0x80000000`；arg1 = 1 ⇒ `0`；**其余 ⇒ 不写**（保旧值）+ 记一行日志
  （`"SetTBの引数が不正です．\r\n"`，经 `sub_408050` → `0x4976A0` 加 `"(<脚本>：<行>行目) "` 前缀 → `WriteFile`）。
  **三支都不抛**，控制流不变。
- `0x5EC7C` 的语义（三个读者）：`0x426788` 判 `== 0` 才画字；`0x411DCA` 用 bit31 挡 `set:ReDrawTextOnKey`；
  `0x41EB44` 把它当第 5 实参传给 `sub_46BE30` ⇒ **0 = 正常显示，bit31 = 抑制**。
- 未解："TB" 的字数 / 窗口身份。

### `0x300` — `sub_426990`（EA `0x426990`，`.lst` 58352–58379）

- 宽度 **7**（argc 3）；读序 **#1 → #2 → #3**（#1 作下标；`A[idx]` 在 #3 之前就写）：
  `A[+0x77988][idx] ← op2 | (A[idx] & 0x10000)`（**bit16 粘住**）、`B[+0x779B0][idx] ← op3`。
  无外部请求、无分支、**idx 无范围检查**。
- 数据面：A / B / C（`+0x77988` / `+0x779B0` / `+0x779D8`）是三个**各 10 条**的 dword 数组；
  每帧更新 `sub_409400` 只走 idx 1..9：`A&1` ⇒ 置 bit16；`timeGetTime() - C[idx] >= B[idx]` ⇒
  `C[idx]=0` 且 `sub_404F80(font, idx)`（与 `0x301` 同一个释放）；`A&1 == 0` 但 bit16 在 ⇒ 等 font 空闲后清 A/B/C。
  ⇒ **A = 状态位（bit0 起動 / bit16 粘住）· B = 期限 ms · C = 起点时刻**。
- CONFIG 里两次调用是 `(9, 1, 1000)` 与 `(9, 0, 0)`。未解：数组 / 槽的领域名。

### `0x301` — `sub_4269F0`（EA `0x4269F0`，`.lst` 58386–58403）

- 宽度 **3**（argc 1）；读 op1，同一值用两次：`C[+0x779D8][idx] ← 0`，再 `sub_404F80(font, idx)` 释放该字体槽
  （idx == 0 ⇒ 换成 `font+0x4CC` 缺省槽；槽项非空 ⇒ 项+132 ← 0 + 两段 map 删除 + 载荷 `[vtbl+8]` 后 `delete`）。
  无分支，idx 无范围检查。未解：条目 +104/+108 与 +276/+280 两段区间的语义、槽号 9 为何固定、
  `[vtbl+8]` 内部是否释放图形资源（下界）。

### 成对判断

- `0x142` + `0x1BB` **不是一对**：目标格不同、读写者不重叠、无共用 helper；CONFIG 里两处相邻且同值（0,0 / 1,1）
  只是"两个无关布尔量被同一处赋同值" ⇒ 不能共用实现。
- `0x300` + `0x301` **是同一条数据面上的两面**（同表、同一个释放入口），但**不是开/关对称**
  （arity 7 vs 3、写 A/B vs 只清 C）⇒ 只可共用"取 idx / 槽址 / 释放"三个小 helper。

## 6. 参数格（`Engine+0x15290`）的初值 = 配置键 `message:MessageSpeed`

spec 条目 `CORE-OPS-PARAM-74-7F` 有一条残差 `RES-PARAM-21668-INIT`：「参数格的初值没有观察」。
实测**有确定写点**：

```
35403  .text:00417EAB mov     [esi+15290h], eax      ; ← 启动期写这一格
35399  .text:00417E98 push    offset aMessageMessage ; "message:MessageSpeed"
35401  .text:00417EA3 call    eax                    ; 配置取值
```

`0x41FF00`（`sub_41FED0`）也会把同一格写成 `message:MessageSpeed`（另一条路径）。
⇒ 初值**不是分配残留**，而是配置值；CONFIG.BIN 第一次 `0x7f` 读它时该配置是缺省 0，
这解释了为什么 `0x7f` 在 CONFIG.BIN 早期可执行（实现此前把它当"未初始化 ⇒ 响亮失败"）。
★ 这条可用来降级 spec 的 `RES-PARAM-21668-INIT`（待回填）。

## 7. `0x12F` — `sub_42F560`（EA `0x42F560`，`.lst` 73203–73380）

排序置换：op1/op2/op3 = **三个数组的基址**（A 被写、B/C 只读），op4 = 元素个数 N。

- 读序：op1 → op2 → op3（地址型，`sub_42AEA0`）→ op4（整型，`sub_41BF50`）；**op4 每轮重求值**（2N+1 次）。
- 写：① `A[0] := 0`（**无条件**，N=0 也写；存原始下标）② `N≥2` 插入排序，键 = `dec(B[i]) + dec(C[i])`
  （32 位回绕、**有符号**比较、升序；`jle` 落位 ⇒ 相等不交换）③ 收尾 `A[i] := enc(A[i])`。
- 无外部请求；**零界检查**（N 超长 ⇒ 静默越界，⛔ 不许替它加检查）；推进 **9**。
- 用途（游戏层）未取证。已实现（`vm_ops_numeric.cpp` 的 `op_12f`）。
- 派发锚：`0x415DF6`（表基 `0xA509C`）+ `0x411A66`（分派）。

## 9. `0x82`（文本排版）与 `0xC2`（音乐转移）—— 已取证、**未实现**

- `0x82`（`sub_41F720`，argc 5，推进 11）：读序 **5→4→3→2→1**，五个值交给文本布局管理器
  （`ecx = Engine+0x14D30`）的 `sub_466000`；节点下标越界 ⇒ **静默**；op1 槽**零界检查**；

## 10. 文本读原语支持指针族（`type 8 / 14`）

## 三、本轮处置（按类型）

- E1：三处例子统一改成**正值**（`0x7F000000`），并写明「最高位为 1 的颜色实参按有符号是负数」。
- E2：撤回「三个名字同一个格」，改回**两个格**（脏闩 / 有动画）并写清各自读者；`0x344` 条目表按 `.lst` 定为**场景对象**的辅助表 A。
- E3：`0x25b` 16 位支改 **4:4:4**；外枠实参序按 `push` 反向定案（矩形、编号、`0xFF`）；`0x48b0f5` 锚点改 `0x48b0f7`。
- E4：删「唯一读者」→ 写读者闭集；「第一步是批次闸」→「批次闸不是第一步」；矩阵初值降成残差；`FORWARD-FIELD` 的"零写点"按别名写点改正。
- E5：阈值（整数右移）与分子（精确 ×0.5）、分母（本字形黑框宽）三式分开写；实现同步（`vm_ops_text.cpp`）。
- E6：残差摘要去 EA/行数；「以函数名开头」→「固定文本，内容本版不规定」；五章章首去本仓命令。
- E7：代码注释里四处悬空 id 指向现行条目；正文的 `RES-216-SAVE-RESTORE` 改指真实条目。
- E8：`RES-VM-RENDERSTEP-FIRSTFRAME` / `RES-RENDER-STEP-INTERNAL` 收窄成"验收式 next"。

## 四、棘轮（同一缺陷不得重复出现）

以下三条已由工具/守卫接管，下次 review 先问它们是否仍然成立：

1. **颜色归一化**：无颜色 = 32 位全 1、A 参与、透明度只供 A、颜色只供 RGB 低 24 位。
   若再出现"只比低 24 位"或"`0xFF000000` 是黑"，说明这条又退化了。
2. **半格三式**：阈值 = 参考黑框宽整数右移；分子 = 参考黑框宽 × 0.5（精确）；分母 = 本字形黑框宽。
   三者任一被合并或互换，`spec_text_container_font_names` 必须红。
3. **纹理键必有值**：`display:TextureBit` 由配置对象**构造期**写入 32，读取端**不自造缺省**。
   若再出现"缺键 ⇒ 32"，`texture_bit_default_source` 必须红。

## 六、第二轮复审新增的错误类型（同一批，续）

第一轮收口之后，对**新写的合同**再跑复审，又暴露五类**生成式**错误 —— 它们不是"读错指令"，而是"写合同时把结构搞混"：

| # | 类型 | 实例 | 判据 |
|---|---|---|---|
| F1 | **同一位号/同一格的多套语义** | 标志字"最低位"一处当停止、一处当新段起点、一处说"低两位=绘制模式"；`+0x420` 同时是日志标志 / 渲染器标记 / map 大小 | 同一格在多章出现时，逐处列出"谁写、谁读、什么义"，不一致就红 |
| F2 | **公式方向写反** | 全角字宽"大 ÷ 小"（应为"小 ÷ 大"，否则宽 > 平均字宽）；半格缩的"分子 = 字号 ÷ 2"（应为参考盒宽 × 0.5） | 把公式代一个具体例子，看结果是否落在可观察区间内 |
| F3 | **两套模型并存** | 命中扫描同时写"索引区间 `[start+1, count)`"与"两个指针比较"；`count ≤ 0 ⇒ 不扫`（引擎只比指针） | 同一段只留一套判据，另一套若只是"不回绕时的特例"必须标明 |
| F4 | **全称否定不可证伪** | "只由 `0xcd` 派发"、"唯一读者是存档写出"（越界支还有一个）、"本序列没有写者" | 全称否定必须给穷举口径；给不出就降成"已知的下界 + 残差" |
| F5 | **报告的两条结论互斥** | 同一份取证稿里"清零不改存档副本"与 EA 的"两块一起清"；"绘制后记录逐字节不变"与"②回灌 + 标量写回" | 两份报告冲突时以 `.lst` 逐字为准，并在正文写明哪条被推翻 |

处置口径（与第一轮相同）：**能落合同就落合同**（附可证伪条件）；落不了的进残差（`next` 写死"读哪个 EA"）；
"恒零 / 不可达 / 没有写者"这类否定式必须凑齐四条现场，否则降成窄 `unknown`。
本轮新增的残差里有 3 条属于"精确到一段代码"的续读任务（`RES-OPS-FORWARD-COVERAGE-BLEND`、
`RES-SCENE-TRANSFORM-RECORD-KIND-WRITERS`、`RES-OPS-FORWARD-PROLOGUE-GRAYLEVEL-KEY`）。

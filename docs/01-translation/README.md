## 3. 待定（M5 前必须拍板，本轮有意不定）

### 3.0 已落定的资源（先于数据模型拍板，因为它们是数据模型的**输入**）

* **字体已入位**：`corpus/assets/fonts/`（分发字体 `Amayui-CN_cnjp{,-Bold}.ttf` + 上游基底 Sarasa 7z）。
  它是"BIN 内嵌中日文"这条路的前提 —— 没有它连渲染都跑不起来。
* **简→日写法占位字典已入位**：`data/translations/subs-cn-jp.json`（旧仓 `res/subs_cn_jp.json`）。
  它决定"文本层写哪个码位"，与上面字体的 cmap 替换**成对**（见 `../../data/translations/README.md`）。
* **UI 图片已入位**（生效版 + 版本表）：`corpus/assets/ui-images/`；中文 UI 不落在这套数据模型里，
  它是**烘焙产物**（AGF overlay），见 `../02-engine/README.md` §6。

### 3.1 数据模型：双份合并，还是保留两份？

| 备选 | 形态 | 代价 |
|---|---|---|
| **A 单份 + 机读修改点标记语法** | 一份文本真源，译文以**机读标记**表达（替代现在用注释承担、不稳定的做法） | 需要设计标记语法 + 守卫；但消除了"两份必须同构"的隐式约束 |
| **B 保留 `data/` + `src/` 双份** | 沿用旧仓模型（日文基线只读 + 译文并列同构） | 迁移最省事；但"同构"只能靠约定，且 diff 里混着两种关注点 |
| C 单份 + 侧车**（未展开）** | 真源一份，译文存侧车文件 | 两份仍然存在，只是不同目录 —— 未消除同构约束 |

**用户的前瞻意向**：在 BIN 里**同时嵌入中日文**，让 emulator 运行时切换 —— 这会反过来约束这个数据模型
（若最终形态是"双语内嵌"，那么"单份 + 标记"可能比"双份同构"更接近最终产物）。

### 3.2 其它待定

* **BIN 内嵌中日文的前瞻**：编码、切换时机、与 `packages/age-format` 的关系（M2 之后才有容器层结论）。
* **字体**：`res/fonts/` 里 CN/JP 合并字体与 `.ttf` 的 LFS 口径（旧仓走 LFS）；落点尚未定（`corpus/` 只登记）。
* **`install/`（7.7 GB）**：用户口径"先保留、后续重新设计" ⇒ 本轮不参与。

# 模拟器的地址空间（设计）

> 这份文档是**设计记录**（决策 + 形状 + 不变量 + 迁移计划），**不是进度**。
> 进度与"还要做什么"看 `pnpm tools requirements plan`；可执行形式看代码与守卫。

## 1. 决策

**模拟器里要有统一地址空间。** 依据是用户口径：

> 这个模拟器预期应该能像真正的引擎一样驱动游戏，因此**只要确实涉及到的能力都是要支持的**。

⇒ **不允许**留"永久不支持"。某一项暂时不实现，只能是一个**已登记的、会收口的**节点，
不能是一句"这是边界"。

## 2. 为什么"按语义槽建模"表达不出指针

引擎的机器模型里，**指针**是实打实的内存地址。取证（锚 = EA，见 `data/ledger/`）逐字给出形态：

```
global-ptr 读：mov edx,[ecx+5D818h] / mov eax,[edx+eax*4] / mov edx,[eax]
                └─ 池基址 ─────────┘ └─ 取第 idx 格 = 一个地址 ─┘ └─ 解引用 ─┘
create-mesh ：mov eax,[ecx]     ; ★ 第 i 个顶点 = 操作数解出的**地址** + 4*i
```

"池里那一格装的是**地址**、值在 `[地址]` 里"这句话，要求模型里**存在地址**这个概念。
`type 6/7/8/c/d/e` 之所以一直响亮失败，就是因为没有它。

## 3. 形状：**扁平 + 合成 + 稀疏**

| 选 | 含义 | 为什么 |
|---|---|---|
| ✅ **扁平** | `区域 = [base, base + capacity*elemBytes)`，`地址 = base + elemBytes*index` | 引擎的 `base + 4*i`、`lea`、指针加减**原样成立** —— 它们本来就是地址算术 |
| ✅ **合成** | 地址由本层自己发（`ORIGIN` 起、按分配顺序 bump），**不是**宿主真地址 | 真地址取决于宿主分配器 ⇒ 两次运行不同 ⇒ 快照不可比、日志不可 diff |
| ✅ **稀疏** | 一个区域的格子按需出现（`cells: Map<偏移, 字节>`） | 池的容量**至今没有逐字取证**；稀疏 ⇒ 现在就能建、能寻址、能解引用，而不必先编一个容量出来 |

**被否掉的两条**（写在代码头注里，免得下次有人再提）：

* ❌ **结构化指针**（`{池名, 下标}`）：脚本一旦对地址做算术（`地址 ± 常数`、
  取结构体中间某个字段的地址），"这是哪个池的第几格"就没有唯一答案 ⇒ 要么在算术处失败，要么猜。
* ❌ **继续不支持**：与用户口径直接冲突。

## 4. 不变量（每条都有会红的守卫：`tools/test/emulator-address-space.test.mjs`）

1. **同一分配序列 ⇒ 同一批基址**（不依赖宿主、不依赖时刻）。
2. **`addressOf(i)` → `resolve` 必须回到同一格**；区域末地址之后**不是**本区域。
3. **解引用链成立**：`池[idx]` 装地址，值在 `[地址]`；"不解除引用"会得到地址本身（类型对、值错）。
4. **三种失败分得开**：`unmapped` / `misaligned` ⇒ **抛**（带地址）；`unwritten` ⇒ `null`（**不是 0**）。
   —— 引擎在越界时**没有边界检查**（它会安静地读到相邻内存），那是 UB，本层不模仿。
5. **快照**：同状态 ⇒ 逐值相同；恢复后**不许重发**已用过的地址（重发 = 两块数据别名）。
6. **本层只管字节**：不认 DEC/ENC、不认 SSO、不认容器 —— 引擎的取址原语**不解码**
   （取证：`sub_42AEA0` 的 case 3 是 `mov ecx,[eax]` / `lea eax,[edx+ecx*4]`，没有任何位运算）。

## 5. 它顺手逼出来的三件事（都要收口，登记在需求树）

1. **区域的容量从哪来**：`alloc` 的 `capacity` **必填**（本层不编默认值）。
   它来自装载器写进记录 `+0x08..+0x1C`（绝对 `0x5D89C..0x5D8B0`）的六个计数。
   ★ **"计数槽 → 哪个池"这条曾在这里被登记为"未逐字取证"，2026-10 已取证**（原先的说法保留一句在下面作沿革）：
   装载器 `sub_40ED40` 的形态是 **"读计数 → `operator new[]` → 写基址"**，而基址一侧的身份由取址原语
   `sub_42AEA0` 的 **case 号（= operand type）** 钉死 ⇒ 相邻性 + case 号两件事一起把六对配光：
   记录 `+0x08`(local_integer_1)↔`+0x20`=int · `+0x0C`(local_floats)↔`+0x24`=float ·
   `+0x10`(local_strings_1)↔`+0x28`=string · `+0x14`(local_integer_2)↔`+0x2C`=ptr ·
   `+0x18`(unknown_data)↔`+0x30`=floatPtr · `+0x1C`(local_strings_2)↔`+0x34`=stringPtr。
   ★ 记录基址 = `Engine+0x5D894`（`layout.mts` 的 `FRAME_LAYOUT`）；旧基址（`0x5D880`）记法要 **+0x14**。
   逐字与三次订正的经过见 `packages/age-format/src/engine/layout.mts` 的 `LOCAL_POOL_SLOTS` 头注。
   ★ 剩下的只是"**调用方还没把容量传进来**"（实现进度，见需求树）—— 不是"不知道它从哪来"。
   沿革：采用地址空间这件事，把一条"未取证"从"可以绕开"变成了"必须解决"，于是它被解决了。
2. **`*_alt` 池（memflip）**：`Engine+0x5D804/0x5D80C/…` 那六对是**同一批数据的两个区域**
   （取证：`.text:0041AAD9..0041AB66` 六对交换，开关是配置键 `set:EnableMemFlip`）。
   本层能表达（两个区域 + 一次交换），但"何时交换"未取证 ⇒ 不实现。
3. **容器句柄（`0x8003/0x8005/0x8009/0x800B`）**：它们要"懒分配 + 登记"
   （`Engine+0x5D860/0x5D870`、`Engine+0x5D904/0x5D908`（= 记录 `+0x70/+0x74`），句柄在 int 侧是 ENC 指针、
   在 string 侧是**十进制文本**）。本层提供存储与地址，登记表与懒分配在容器层。

## 6. 迁移计划（**本批只立接缝，不动池**）

池层现在的存储是 `Map<池名, Map<下标, 值>>` —— 它没有地址概念，所以"池里的值"与
"地址空间里的字节"目前是**两份**。迁移的目标是**一份**：池 = 地址空间里的一个区域，池层只保留语义
（DEC/ENC、未写过的 `null`、越界留痕）。

分三步，每步都能独立验收：

1. **本批（已做）**：地址空间独立可测（11 条守卫）+ 参与状态分区（`AddressSpace` / `Region`）+ 3 条变异条目。
2. **下一步**：池的存储换成区域（`LocalPools` / `GlobalPools` 的内部表示），
   判据 = **既有守卫全绿** + 新增一条"通过地址空间读到的池值 == 通过池 API 读到的值"。
3. **再下一步**：`type 6/7/8/c/d/e` 与 `0x800x` 接上本层，删掉 `unimplementedPointerType`。

★ 迁移**不改语义层的外部形状**：`read(tag, idx)` / `write(tag, idx, v)` / `snapshot()` / `restore()`
一个都不变 —— 换的只是"值存在哪"。

## 7. 随机源（同一轮的用户决定）

`0x60 random` 是纯数值族里**唯一的非确定源**，语料里出现 **22 次** ⇒ 游戏确实用到。
而"非确定性"与两条硬口径直接冲突（快照逐字节可比、日志能当回归基准）。

⇒ 做法：**随机源是注入的服务**（`src/host/random.ts`），种子由前端给
（`--rng-seed` / `AMAYUI_RNG_SEED`，默认是一个**显式常量**，不是时刻）。
没有随机源时那条指令**响亮失败** —— 不许退回 `Math.random()`（那会让"同种子同日志"变成假象）。
每次取数都发一条 `system.random.draw`：**取数次数本身**就是复现性判据
（同种子却给出不同次数 ⇒ 控制流在更早的地方就分叉了）。

★ 未实现并显式登记：`0x60` 体内那个**上限 12 的重掷计数器**（`Engine+0x69330`）——
已登记的语义只到 `rand() % op2`，"在什么条件下重掷"没有取证。实现一个猜出来的重试循环
比不实现更糟：它会让取数次数错，而那正是上面那条判据。

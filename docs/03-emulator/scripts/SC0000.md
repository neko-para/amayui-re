   判据只能是"`pos` 落在上面那个块里"。
3. **动画形态**：**纯渲染**（`create-mesh` / `set-vertex-color` / `draw-texture` / `set-draw-color-alpha` + `i238`/`wait` 定时），

## 第 2/3 步评估（2026-11-17 / macOS 只读）

完整评估在 `.tmp/sc0000/assessment-mac.md`（390 行；含证据链与待核）；本机 `links/install` 是**另一个修订版**
（`SC0000.BIN` 504,312 B ≠ 票据 511,688 B；`label_00006b90` 偏移 +0x20、`label_00071120` −0x1C），
⇒ ⛔ 不能拿它校验 `label_` 或位置门，只能确认资产在不在。

- **最可能的下一个缺口**仍是 `d3dx9_43!D3DXLoadSurfaceFromSurface` 本身（同一导出、第 1 步拒绝的臂）：
  5 个站点 `ColorKey` 恒 0、`Filter∈{1,-1}` ⇒ 只剩「矩形不等 ⇒ 缩放」与「16↔32 / 不同 16bpp 格式对」。
- `0x4B4D6E`（截屏/缩略图）可静态排除：同函数 `0x4B4C5F` 先调未登记的 `+0x70 CreateRenderTarget`。

  本线 caps 报 0 ⇒ 当前不可达。⚠ 补 shader 版本 caps 会立刻点亮它（语义 = 执行 FX 二进制，不在本单）。
- `i238` 是 AGE 脚本 opcode（0x238/argc 1，handler `sub_4248C0`），**不是 lift 的缺口**：lift 执行 guest 机器码。
- 第 2 步先决 = **一次读数 run**；`--import-gaps` 不存在，等价读数是 `LIFT_AOT_SHIM_TRACE=1`
  （`[aot-shim] … ret=` 即 callsite）。本机用 `links/install` 跑 `load01.plan` 未到达 SC0000（脚本修订版/门），
  ⇒ 第 2 步仍等原版安装树或一次可对齐的读数。
- 候选实现单元 A-1（格式对）/ A-2（缩放）都附了判据、顶层 pure CTest 与能红的变异；两者都**与第 1 步
  「只做 1:1 / 不猜转换语义」的裁决冲突** ⇒ 要么只钉"已拒绝"的守卫（不冲突），要么先在需求单写新裁决。

## 第 2 轮读数（2026-11-17 / macOS arm64 / `--game-dir links/raw`）

**原版脚本在 `links/raw`，不在 `links/install`**（后者是汉化修订版）。字节级核对：

```bash

# 1369ea20…  links/install/SC0000.BIN  504,312 B   ← 汉化修订版
xxd -s 0x6AB4 -l 8 links/raw/SC0000.BIN      # 8f 00 … 39c4 0100 ⇒ 目标 0x3C+0x1C439*4 = 0x71120 ✅
xxd -s 0x6AB4 -l 8 links/install/SC0000.BIN  # 8f 00 … 32c4 0100 ⇒ 0x71104（−0x1C）
```

配方要三处修正（**只改了 `.tmp/sc0000/` 的副本**，读数见 `.tmp/sc0000/read2.md`）：

1. 第一道门用**位置门** `await position TITLE 0x0460 0x0520`：`--skip-logo` 下纯身份门 + click 会把点击
   投在 boot（raw1：SAVE 门 30 s 不成立）；换位置门后进加载屏。
2. appdata 副本里**删掉 `SAVE.DAT` / `SAVE.BAK` / `RT.DAT`**：有它们时加载屏第一页是 `110..119`（全空），
   删掉才是 `000..009`；`click 300 140` 命中槽 001，缩略图台词逐字 = SC0000 第一句
   （`.tmp/sc0000/shots/loadscreen-page000-save001-confirm.png`）。⇒ 这是**数据面偏差**，`frames` 不能与未删的 run 横比。
3. 确认框要按**位置门**压在一个输入读段上，`wait` 不行（落点随机）。

**卡点（本轮没到 SC0000）**：加载确认框 `SBUNKI.BIN`「ロードしますか？」的 `はい` 点不动 ——
注入点击的 `fired/released` 递增、`SBUNKI` 的回调也跑了，但确认动作块 `[0x30AC,0x32E8)` 从未执行
（`await position SBUNKI 0x30AC 0x32E8` 8 s 到期；稳态 `pos ∈ {0x30A4, 0x09A4, 0x09C4}`）。6 种门/坐标全试过。

⚠ 顺带发现：**`SBUNKI.BIN` 不是 `links/raw` / `links/install` 里的松散文件**（只在
`../amayui-cn/raw-parts/DATA1/SBUNKI.BIN`），但引擎确实加载并执行了它（`script=SBUNKI.BIN`、`pos=0x30A4`）

## 第 3 轮：SC0000 到达（可用配方，2026-11-17 / macOS arm64）

**确认框已过**：卡点不是坐标、不是 gate 数据、也不是 `i2fc`，而是**输入计划的施加形状**——
`InputPlan::atPoint` 的 while 会在**同一个读点**里把相邻两条 `click` 都消费掉；按下只活约 17 个读点
（`kForceReleaseReads=16` 兜底），在脚本自己的 `read-mouse-pos/button`（`0xAF8/0xB0C`）之前就抬起了
⇒ SBUNKI 的 3979 次 `GetAsyncKeyState(VK_LBUTTON)` 全返回 0，`(local b)` 只到 4（bit2），从未到 5（bit0+bit2）
⇒ `0x0DA8` 的 `b & 1` 恒 0 ⇒ 跳 `0x1040`，`0x0F60` 从未进入。诊断取样见 `.tmp/sc0000/diag-locals.md`。

**形状必须是三次回调**：① 一拍无按键（置 `b` bit2、`9=0`）→ ② 一拍按下（置 `b` bit0，`b=5`）→
③ 一拍抬起（`b&1` 清、`b&4` 过 ⇒ `0x0F60`）。可用配方 `.tmp/sc0000/load24.plan`：

```plan
await position TITLE 0x0460 0x0520 timeout 30000
click 1070 480
await position SAVE 0x1104 0x11C4 timeout 30000
click 300 140
await position SBUNKI 0x09F8 0x0B18 timeout 30000
click 600 323
wait 300
await position SBUNKI 0x0AF8 0x0B18 timeout 8000
click 690 323
await position SBUNKI 0x0F60 0x1040 timeout 8000
await position SBUNKI 0x30AC 0x32E8 timeout 8000
await script SC0000 timeout 90000
```

读数（`--present headless --skip-logo --audio off --game-dir links/raw --appdata <新副本>`，副本里删
`SAVE.DAT/SAVE.BAK/RT.DAT`）：

- `load24`：`rc=0` · `steps=12 fired=4 pending=0 released=4` · 确认后 `script=SC0000.BIN`（id 0x73）。
- 到 SC0000 后（`load24` + 两次中心点击 + `wait 20000`，`--time-limit 300`）：`frames=3371`、
  `steps=17 fired=6 pending=0`、`pos` 采样到 `0x6B28`（第一句块内）与 `0xC68`；
  **没有 `unimplemented` 停点**（headless 下 3371 帧未撞 `D3DXLoadSurfaceFromSurface`）。
  ⇒ 与 win32 那次 `frames=523` 停在 D3DX **不同形**；是"这台/这一支的渲染路径没走到那 5 个站点之一"，
  还是"headless 分支不经过"，**未定**（⛔ 不要当等价性判据）。

⇒ `## 位置区间` 仍为空：`[0x6AB4,0x6B90)` 现在有"`pos` 采样到 `0x6B28`"这一条，但**没有一次
`await position` 门命中**的读数；下一步是把门挂上去。

⚠ 附带读数（**2026-11-17 已修**）：`local 9c` 曾经是 **6**（"はい"的 `_mbstrlen` 按**字节**数）⇒ 按钮宽 334
（字符口径 247）。根因见 `defects.md` 的 BUG-27（`bt` 内存形位偏移被截成低位 ⇒ 客侧 `_strcspn` 把
`"japanese"` 切成 `"japa"` ⇒ `setlocale` 失败）与 BUG-28（`CPINFO::LeadByte` 写到 +4）；修后 `9c=3`、
按钮宽 247（三种口径都 −87）。命中矩形按字符口径 = `[517,764]×[300,347]`、按字节口径 `[473,807]` ——
600/690 两个坐标都在两者之内。

用户口径："之前能执行到 SC0000，但渲染一直是黑的 ⇒ 部分 shim 实现了但功能错"。**HEAD 上不复现持续黑**：

- 黑段约 **0.3 s**（guest ≈24.3 fps，8 帧），白段约 12 s、淡入约 25 s。
- 两条读路径同源：`--dump-frame` 与 `emu-ctl screenshot` 同帧 BMP 的 sha256 前 16 位相同；
  `--present window` 的窗口回读与 guest 后缓冲前 5 色/唯一色数逐项相同。

  随后 **3.94e9 条 guest 指令零 shim 调用**（入口就在这段里）⇒ **`Clear` 之后没有任何 `Draw*`**，
  不是"画了但画成黑"。白段同理（每帧 hash 恒定、只有 1–2 色）。
- 该窗口的 shim 普查（430 万次 / 715 个名字，`LIFT_AOT_SHIM_TRACE=1` 边跑边聚合、不落大日志）：

  `GetRenderTarget`/`CreateRenderTarget`/`StretchRect`/`ColorFill`/`gdi32!GetDC`/`BitBlt` **全 0**。

# 脚本级分析 · `docs/03-emulator/scripts/`

> 这个目录回答一个问题：**"在 `<SCRIPT>` 里，哪段区间是哪个屏 / 哪段吃输入？"**
> 一份脚本一份 `.md`，文件名与 `<NAME>.BIN` **同名**（全大写，含 `.BIN` 前缀部分，例 `TITLE.md`）。
> 目录里有哪些脚本已有分析 ⇒ **看目录本身**（⛔ 不在这里列清单，那会过期）。

## 为什么单独一个目录（§12.9 的来源）

配方要按**脚本内位置**下门：`await position <SCRIPT> <lo> <hi>`。区间是
**绝对字节偏移、4 字节对齐**，与 `dist/views/data/<NAME>.BIN.txt` 的 `label_%08x` 同一坐标系。

⚠ **行号 → 地址不是 `0x3C + 4×行号`**：清单里每行占 `1 + 2×操作数个数` 个字
（`(…)` / `[…]` / `"…"` 各算 1 个操作数；头 4 行不是指令），首条指令 @ `0x3C`，
`label = 0x3C + 字序号×4`。只有"序数 = 字序号"时两者才重合 —— 拿行号直接乘 4 会**静默算错**。
（实测：用这条规则算 5 份清单共 1491 个 `label`，零偏差。）这类结论**会被反复重新取证**，所以：

- 留在 `.tmp/` ⇒ 下次从零重做；
- 写进需求单正文 ⇒ 挤爆 80 行预算；
- 写进 README ⇒ 那是"状态"，§10 禁止。

## 一份文件长什么样（四节，缺一不可）

```markdown
# <NAME>.BIN

## 身份
- 清单：`corpus/...`（或 `dist/views/data/<NAME>.BIN.txt`，N 行）
- 加载后的 `script` 身份名怎么来的（哪个 dword / 哪条身份来源）
- 这份脚本在**游戏的哪一步**被装载（只写机制：谁 call-script 它，不写剧情）

## 位置区间
| 区间 `[lo,hi)` | 是什么 | 复现命令 | 读数日期 |
|---|---|---|---|
| `[0x0460,0x0520)` | 回调体的输入段（**吃 click 的窗口**） | `node tools/emu-ctl.mjs pause && … sample` | 2026-11-16 |

## 输入点
- 哪段吃 click / 哪段是轮询（点不动的区间也要写，它是"假阳性"的来源）
- 每个 click 的参考坐标（1280×720）与它触发的转移

## 待核
- 没有读数支撑的候选区间、互相矛盾的读数、`<待核>` 的假设
```

## 怎么查（复现一条区间）

```bash
# 1) 控制层停在脚本读点，看当前位置（绝对偏移 + 脚本身份）
node tools/emu-ctl.mjs sample --json            # ⇒ { script: "TITLE.BIN", pos: 0x460, … }

# 2) 让 guest 走一段，再看一次（区间就是这么"两头夹"出来的）
node tools/emu-ctl.mjs resume --for-ms 200 && node tools/emu-ctl.mjs sample --json

# 3) 或者一次性跑一份配方，用 position 门当探针（门没等到 ⇒ exit 5，且会点名卡在哪一步）
apps/emulator-lift/out/emulator-lift-aot --input-plan apps/emulator-lift/scripts/recipes/<x>.plan …
```

## 怎么改

- **只有带读数的区间能进 `## 位置区间` 表**（§10：文档必须带命令与读数）。没有读数 ⇒ `## 待核`。
- 读数过期（换了执行源 / 脚本被改）**不删**，标 `stale` 并保留原命令（§6 第 3 条：冲突要显式化，⛔ 不静默改写）。
- ⛔ 不写剧情、进度、"当前到哪一屏"；⛔ 不把"读了清单推出来的"写成结论 —— 语义结论走 §6 准入门（锚 EA 或守卫用例 id）。
